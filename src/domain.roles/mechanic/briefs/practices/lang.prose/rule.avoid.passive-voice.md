# rule.avoid.passive-voice

## .what

no passive voice. name the actor, then the act. `guard handles errors.`, not
`errors are handled by the guard.`

## .scope

- code: comments, jsdoc headers
- docs: markdown, briefs, plans, readmes
- comms: commit messages, pr descriptions
- logs: error strings, debug lines

exempt: verbatim quotes, code blocks, human-chat tone.

## .why

- **passive hides the actor** — "the record is validated" drops *who* validates. active names it.
- **passive adds words** — "is handled by" costs three words; "handles" costs one.
- **active reads direct** — actor → act → object maps to how the reader models the system.
- **ste rule** — active voice is a core ste write-rule.

## .the test

does the sentence say *who* acts? passive drops the actor or trails it behind "by". rewrite: actor first.

## .how

- find `is`/`are`/`was`/`were` + a past participle (`handled`, `generated`, `sent`).
- name the actor. put it first. `X handles Y.`
- no known actor? recast to an imperative: `handle Y.` — still active.

## .examples

### 👎 bad — passive

```ts
// the invoice is generated by the orchestrator after the customer is charged
```

### 👍 good — active

```ts
// orchestrator generates invoice after it charges customer
```

## .enforcement

- passive voice (be-verb + past participle) where active would serve = **nitpick**
- an act whose actor stays hidden or trails behind "by" = **nitpick**
