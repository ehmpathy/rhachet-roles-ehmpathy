# catalog.of=pattern.transaction.bound=contract.trait=idempotency.pattern=idempotency-key

a member of `catalog.of=pattern.transaction._` · bound `contract` · trait `idempotency` · verdict `require` · tier `root`.

## .keeps

a retried external call charges, sends, or emits once.

## .the move

mint a key for the act before the first attempt, persist it with the intent, and send the same key on every retry. the receiver records each key with its result and answers a repeat with the first result. the key names the act, so it is stable: a hash of the desired shape, or the task's own unique key.

## .in our tools

`rule.prefer.declastruct` (mechanic) sends a hash of the desired shape as the key on each create; an async task's unique key is the natural key for its call (`pattern=async-task`). where the receiver owns a natural key, `pattern=supplied-exid` serves instead.

## .the failure it prevents

a timeout after a charge succeeds, then a retry, then a second charge.

## .source

> "An idempotency key is a unique value generated by the client which the resource uses to recognize subsequent retries of the same request." — jena, dalal & tishkin 2026, "the idempotency-key http header field", ietf internet-draft draft-ietf-httpapi-idempotency-key-header-09 (not yet an rfc) ✅

> "If the above Stripe request fails due to a network connection error, you can safely retry it with the same idempotency key, and the customer is charged only once." — stripe, "designing robust and predictable apis with idempotency", https://stripe.com/blog/idempotency ✅
