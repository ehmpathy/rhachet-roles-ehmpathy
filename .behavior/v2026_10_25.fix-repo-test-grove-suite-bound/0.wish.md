# wish: git.repo.test bounds full suites per machine

closes ehmpathy/rhachet-roles-ehmpathy#1154 (kin: #1126).

## the outcome

many crew trees share one box. each one's full suite runs under a per-machine bound, so the box never saturates and a sound change never reads red for load.

- a suite that finds the bound full waits for a slot and says so (which slot holders, which trees). it never runs past the bound and never fails for the wait.
- the bound spans every tree and repo on the machine: its state lives in the user's home, not in a repo.
- the default slot count derives from the core count; an env var or flag overrides it.
- a slot frees on exit, crash, or kill. a holder whose pid is gone is reaped, so no slot leaks.
- a small scoped unit run may bypass the bound; the bound is for the full and thorough runs.
