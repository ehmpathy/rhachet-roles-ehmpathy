| `nested` | 📝 itemized · happy · alter — bypass (`nested in a held slot`): a run spawned inside a run that holds a slot, via `GIT_REPO_TEST_GROVE_HELD` | 📝 itemized · happy · alter — each child of a nested `--what all` bypasses the same way |

- `nested` surfaced in execution: this repo's own skill tests spawn `git.repo.test` from inside a
  suite that holds a slot. on a box with a bound of 1, the inner run would wait on its own parent
  forever. the outer slot already counts that load, so the inner run bypasses. alterpath: only a
  repo whose tests spawn the skill meets it. clamped at `git.repo.test.grove.integration.test.ts`
  `[case4]`
- `nested` with a lost marker (surfaced in execution, peer i006): a child whose env was scrubbed
  (`env -i`, an explicit spawn env) has no `GIT_REPO_TEST_GROVE_HELD`, so it would queue on the
  slot its own ancestor holds and wait forever. ⛔ **forbidden** — refused at once: `✋
  ConstraintError: this run waits on its own ancestor`, exit 2, both streams, names the marker.
  clamped `[case6] [t9]`

- `scoped --thorough` and `scoped name://` (surfaced in execution, F3; itemized at 5.3 peer i001):
  `--thorough` asks for the full load, and a `name://` scope alone runs jest over every file, so
  neither bypasses. alterpath: the commonest scoped call is a path scope with no `--thorough`.
  clamped `git.repo.test.grove.integration.test.ts` `[case4]` ("a name:// scope alone is bounded,
  and waits", "a scoped run with --thorough is bounded, and waits", "the name-only wait names the
  fast lane"); the scope suite runs every case `--thorough`, so its renders show a claimed slot
- test isolation is scaffold, not an experience: the skill's own suites call `setGroveIsolation`
  (a private pool per suite file) so a test run never queues on the box's pool. no caller meets it
- `thorough × multi`: the parent loops children (`git.repo.test.sh:1450-1479`); each child claims
  and frees its own slot. `case=6` `[t3]` names it
- `non-jest × single` is **critipath** by `freq × cost`: `types`, `lint`, `format` are the
  commonest calls a clone makes (pre-approved at `init.claude.permissions.jsonc:294-296`). a
  wrongly bounded 10s lint queued behind a 10m suite taxes every clone many times an hour — high
  freq × real cost. the skill also supports `--when hook.onStop` (`git.repo.test.sh:1008`); no
  hook in this repo registers it, but a consumer that does gets the same bypass
- `non-jest`: `tsc` and `biome` are single-process; the wish names jest workers as the load. a
  bound on them is out of scope

## .stage 2 — the wait (slots on arrival × holder fate), bounded cells only = 10 cells

| slots ↓ / holder fate → | exits | terminated | terminated, kill refused | sigkilled | lingers |
|---|---|---|---|---|---|
| `free` | 🎬 demoed `case=1`, `case=6` `[t0]` · happy · **criti** (no holder to wait on) | 🚫 **impossible** — no holder to terminate | 🚫 **impossible** — no holder to terminate | 🚫 **impossible** — no holder to kill | 🚫 **impossible** — no holder to linger |
| `full` | 🎬 demoed `case=2` `[t1]`, `case=6` `[t1]` · sharp · **criti** | 🎬 demoed `case=3` `[t3]`, `case=6` `[t2]` · sharp · **criti** — the trap kills the jest tree, then the slot frees | 📝 itemized · sharp · alter — the holder cannot stop its tree; it says so (`💥 MalfunctionError: could not stop the test tree`, the `kill -KILL` fix, `may still run`), exits, and its slot frees while the tree runs on. clamped `[case3] [t8]` | 🎬 demoed `case=3` `[t0]` · sharp · **criti** — slot frees; orphans may run on (residual, see note) | 🎬 demoed `case=2` `[t2]` · sharp · **criti** |

- `terminated` spans each trapped signal, and each stop line names the one sent: sigterm (exit
  143, `[case3] [t3]`), ctrl-c (sigint, exit 130, `[case3] [t9]`), a closed session (sighup, exit
  129, `[t6]`). a `--what all` child, stopped by TERM since a background job ignores sigint, still
  names the parent's signal and exit (`[case3] [t10]`, `[case6] [t8]`)
- `terminated, kill refused` (surfaced at 5.3 peer i004): rare — the tree must belong to another
  user or sit under a policy that refuses the kill. the stop line must not claim the tree is down
- a stale holder of another user (surfaced at 5.3 peer i004): the hint names the owner to run the
  kill as (`kill <pid> (as <owner>, its owner)`). clamped `[case2] [t6]`

- `sigkilled` carries a residual: no trap can run, so the dead holder's jest tree may finish as
  orphans while its slot is reused — one suite over the bound, for the rest of that suite. it is
  rare (an oom kill or a `kill -9`), the commoner kills (`terminated`) leave no orphans, and the
  alternative — let orphans inherit the lock — would let any stray daemon a test spawned hold a
  slot forever, the leak the wish forbids. fulcrum F2 records it

- `full × exits` at a handover (surfaced in execution, peer i007): a holder writes its record just
  after its claim and its last act is to exit, so a waiter can list in either gap. the waiter
  retries its claim for up to 5s until each held slot shows a live record, then prints that same
  snapshot — never a second read — so it names the holders, or claims the slot that freed.
  critipath: a burst start on a busy grove is the wish's own scene, and `?` holders steer a
  clone to a false diagnosis. clamped `[case2] [t5]` (record lands 1s after the lock), `[t0]`
- `lingers` is not a failure: the waiter waits as long as it takes and prints a heartbeat, so it
  never reads as hung. the wish forbids a fail for the wait
- `lingers` past 30m (a hung holder) is demoed at `case=2` `[t3]`: the heartbeat names the stale
  holder and prints `kill <pid>`; the waiter never kills it. without this, "never fail for the
  wait" plus one hung jest run would stall a tree forever with no hint

### the waiter's own fate (axis H, walked only over `full`) = 2 new cells

H has no value on a `free` arrival — no wait exists to interrupt or to time — just as C has none.

| waiter fate | verdict |
|---|---|
| `claims` | 🎬 demoed `case=2` `[t1]` — the `full × exits` cell above; counted there, not again |
| `interrupted` | 🎬 demoed `case=3` `[t2]` · sharp · **criti** — ctrl-c mid-wait exits 130, holds no slot, leaves no record, prints no partial status |
| `timeout-set` | 📝 itemized · happy · alter — `--timeout` clocks the test run only, from claim; the wait never trips it (`[case3] [t7]`); a `--what all` run passes it to each child (`[case6] [t10]`) |

- `interrupted` is critipath: a human who sees a wait for minutes is the most likely actor to hit
  ctrl-c, and a leaked slot or stray holder record on that path would poison every later run

## .stage 4 — the host (lock primitive × slot pool dir) = 8 cells, + 2 for the group launch

| lock ↓ / pool dir → | writable | absent (after reboot) | unwritable | slot file unreadable |
|---|---|---|---|---|
| `flock` present | 🎬 demoed `case=1` `[t0]` · happy · **criti** | 🎬 demoed `case=1` `[t1]` · happy · **criti** — created `1777`, then claimed | 📝 itemized · sharp · alter — `💥 MalfunctionError`, exit 1, names the path and `GIT_REPO_TEST_SLOTS_DIR` | 📝 itemized · sharp · alter — `💥 MalfunctionError: grove slot file is not readable`, exit 1, names the file and the fix. clamped `[case6] [t3]` |
| `flock` absent | 📝 itemized · sharp · alter — runs unbounded, says so (`grove: ⚠️ unbounded (flock not found; install it to bound suites: util-linux on linux, brew install flock on macos)`); exit 0, no pool dir. clamped `[case7] [t1]` | 📝 itemized · sharp · alter — folds to `flock` absent; dir never created | 📝 itemized · sharp · alter — folds to `flock` absent; dir never touched | 📝 itemized · sharp · alter — folds to `flock` absent; no slot file opened |

- a slot file another user made is read-only to this user under `fs.protected_regular` (the ubuntu
  default); it sits in the `writable` cell, since a read-only open locks it. clamped `[case6] [t4]`

| group launch | verdict |
|---|---|
| `setsid` present | 🎬 demoed `case=3` `[t3]` · sharp · **criti** — the test tree leads its own session; a stop reaches the whole group |
| `setsid` absent (stock macos) | 📝 itemized · sharp · alter — job control (`set -m`) gives the tree its own group; a stop still reaches the grandchild. clamped `[case7] [t0]` (F9) |

- `flock present × absent` is critipath: tmpfs `/run/lock` empties on every reboot, so the first
  bounded run after each boot meets it. if that path failed, every grove would refuse all full
  suites after a restart

- `absent` degrades loud rather than fails: a mac clone with no grove load must still test. the
  line names the cause so a grove operator who sees it knows the bound is off
- `unwritable` fails loud rather than bypass: a silent bypass would let every tree run unbounded
  on a grove whose pool dir broke — the exact saturation the wish forbids, with no signal

| concurrency | verdict |
|---|---|
| `sole` | 🎬 demoed `case=2` `[t1]` · happy · **criti** |
| `race` | 🎬 demoed `case=2` `[t4]` · sharp · **criti** — two waiters, one freed slot: exactly one claims, the other waits on and names the new holder. the box never runs N+1 |

🎯 `case=6` is centered: `--what all` is the commonest full-suite call, and one walk crosses the
gate, the wait, a holder's death, and the child handoff. its highest-risk seam is `[t1]→[t2]`:
a slot freed by a death must reach the waiter child, though another child of the same run just
released one. `case=2` is the spotlight for the wait itself — the
experience the wish was filed to deliver: a suite that once read red for load now waits, names
who it waits on, then runs.
