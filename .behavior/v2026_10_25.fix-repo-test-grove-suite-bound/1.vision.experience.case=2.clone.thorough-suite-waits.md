# case=2 — clone · thorough suite · grove full

**feel:** sharp · **care:** critipath · **cells:** stage 1 `thorough × single`; stage 2 `full × exits`, `full × lingers`; stage 6 `sole`, `race`

## .narrative

13:14 on the grove. two trees already run full suites, 6 jest workers each on 12 cores. before
this change, a third and fourth clone's runs would start anyway — the incident's 17 workers and
load 56 — and timeout-bound tests would read red on a sound change.

now the third clone's run finds both slots held. it does not start. it prints who holds
each slot — tree, test type, pid, age — so the clone knows the wait is load, not a hang. every
30s it prints a heartbeat. when the bhrain tree's unit suite exits, its slot frees; the clone
claims it, names the wait, and runs. the suite passes on its merits.

the aha: the clone never sees a red row it must explain. it sees a queue.

## .bdd

```
given('[case2] a grove with 1 slot, held by another suite')
  when('[t0] a thorough suite starts')
    then('it does not start jest while the slot is held')
    then('stdout names the holder: tree, test type, pid, age')
  when('[t1] the holder exits')
    then('the waiter claims the freed slot')
    then('stdout names the slot and the wait duration')
    then('the waiter runs only after the holder ended — never overlapped')
  when('[t2] the holder lingers past 30s')
    then('the waiter prints a heartbeat, so it never reads as hung')
    then('the waiter never exits non-zero for the wait')
  when('[t3] a holder's age passes 30m — longer than any sound suite runs')
    then('the heartbeat names that holder as stale, with its pid and tree')
    then('it prints the command that frees the slot: kill <pid>')
    then('the waiter never kills the holder itself')
  when('[t4] two waiters from two trees poll when one slot frees')
    then('exactly one claims it; flock -n is atomic')
    then('the other waits on, and its next heartbeat names the new holder')
    then('the box never runs more suites than the bound')
```

## .the race

kai and jo both wait on a full grove. jo's tree and kai's tree poll every second, and when
slot.0 frees they try it in the same tick. the kernel grants the lock to one; the other's
`flock -n` fails, so it keeps its wait and, on the next heartbeat, lists the winner as the
holder. the box holds at the bound — the wish's clamp ("N+1 suites against a bound of N")
exercises exactly this.

## .the stale holder

a jest run with an open handle can hang with its slot held. the waiter cannot tell a slow suite
from a hung one, so it never kills; but past 30m it says what it sees and hands over the fix.
