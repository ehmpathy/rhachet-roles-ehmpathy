# case=3 — clone · slot holder killed mid-run

**feel:** sharp · **care:** critipath · **cells:** stage 2 `full × sigkilled`, `full × terminated`; waiter `interrupted`

## .narrative

a 12-core grove, bound 2 slots, both held: tree A's integration suite and tree C's unit suite.
tree B waits.

tree A's session dies mid-suite. two kinds of death, two outcomes:

- **terminated** — the human hits ctrl-c, the session closes, or the harness times the command
  out (SIGINT, SIGHUP, SIGTERM). the skill's trap kills its own process group — npm, jest, every
  jest worker — then exits. the kernel drops the lock with the last descriptor. no orphan keeps
  the cpu busy
- **sigkilled** — the box oom-kills the shell, or a `kill -9` lands. no trap can run. the kernel
  still drops the lock the instant the skill dies, so the slot cannot leak. but the jest tree may
  run on as orphans until its suite ends

either way, tree B's next poll sees slot.0 free and claims it. no reaper, no cleanup pass, no
stale ledger to trust. with a pid-file ledger instead, a SIGKILL would leak the slot, and after
two such deaths the grove would wait forever.

the holder record (tree, type, pid, since) is display text beside the lock. it is never the truth
of who holds the slot — the lock is. a stale record behind a free lock is overwritten on the next
claim.

## .bdd

```
given('[case3] a grove with 2 slots, both held by suites')
  when('[t0] a holder is sent SIGKILL mid-run')
    then('its slot frees with no trap and no cleanup')
    then('a waiter claims it within one poll interval')
    then('the waiter runs to completion')
  when('[t1] a stale holder record remains beside a free lock')
    then('the next claim ignores the record and overwrites it')
  when('[t2] a waiter is sent SIGINT (ctrl-c) mid-wait')
    then('it exits 130 at once, with no jest started')
    then('it holds no slot and wrote no holder record')
    then('the holders it waited on run on, unaffected')
  when('[t3] a holder is sent SIGTERM mid-run')
    then('its trap kills its own process group: no jest process of that run survives')
    then('its slot frees, and a waiter claims it within one poll interval')
```

## .the waiter's side

the same grove, one seat back. a human sees "⏳ 2 of 2 slots held" for four minutes and hits
ctrl-c. the waiter never claimed, so it owns no lock and wrote no record; the exit trap stops the
heartbeat and exits. the next run sees the pool exactly as before.

## .note — the sigkill residual

the slot keys to the skill's own pid: the skill closes the lock descriptor for its children, as
the wish asks ("a holder whose pid is gone is reaped"). on `terminated`, the trap also takes the
jest tree down, so slot and load free together. on `sigkilled`, they part: the slot frees at
once, while orphaned jest workers may finish their suite. for that window the box carries one
suite over the bound.

why accept it: SIGKILL is the rare death (oom, `kill -9`); the common ones are trappable. the
alternative — let jest inherit the lock so the slot frees only when the last orphan exits — closes
the window but lets any stray daemon a test spawned hold a slot forever, which is the leak the
wish forbids. fulcrum F2 records the choice.
