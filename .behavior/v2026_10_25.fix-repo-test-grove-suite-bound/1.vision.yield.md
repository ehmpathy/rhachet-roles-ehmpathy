# 1.vision — git.repo.test bounds full suites per machine

## .the outcome world

many crew trees share one grove. each full suite takes a slot from a per-machine pool before
jest starts. when the pool is full, the suite waits, names who holds each slot, prints a
heartbeat, then claims a freed slot and runs. a slot frees the instant its holder dies, however
it dies. small scoped runs skip the pool, so the tight feedback loop stays instant.

### before / after

| | before | after |
|---|---|---|
| 17 jest worker pools on 12 cores | all start; load 56; timeout-bound tests read red | at most N start; the rest queue |
| a red row on a sound change | the clone diagnoses load as a defect, or halts | does not occur for load |
| a full suite on a busy box | runs at once, slow and flaky | waits, says why and on whom, then runs at normal speed |
| a scoped unit loop | runs at once | runs at once (unchanged) |
| a killed run | n/a | its slot frees with no cleanup |

### the aha

the clone sees a queue with names in it, not a red row it must explain. `nice` lowered each
suite's priority; the slot pool bounds how many share the box.

### a day in the life

09:00 a clone runs `--what all` to close a stone: lint runs, unit claims a slot. 09:04 three
other trees hold every slot; the integration child waits 2m and names them. 09:06 a slot frees;
it runs green. 11:30 a human ctrl-c's a stuck suite in another tree; its slot frees on the spot.
all day, scoped `--scope invoice` loops never wait.

## .the contract

| aspect | contract |
|---|---|
| bounded runs | `--mode apply`, `--what unit\|integration\|acceptance`, and (no `--scope` or `--thorough`) |
| bypass | `plan` mode · `types` · `format` · `lint` · scoped runs without `--thorough` |
| slot pool | `/run/lock/rhachet/git.repo.test/slot.$i.lock` — one pool per machine, shared by every user, tree, and repo (director, F7). `/run/lock` is tmpfs, mode `1777`: any user may create, none may delete another's, and a reboot clears it. the skill creates the pool dir `1777` and each slot file `0666`, so every user can open and lock every slot. `GIT_REPO_TEST_SLOTS_DIR` points it elsewhere (hermetic tests) |
| slot primitive | kernel `flock -n` on a descriptor the skill holds for its life; the descriptor is closed for children |
| holder record | `slot.$i.holder` beside the lock: tree, test type, pid, since. display only — the lock is the truth |
| default N | `max(1, cores ÷ 6)` via `nproc` (2 on a 12-core grove) |
| override | `GIT_REPO_TEST_SLOTS=N` beats default; children of `--what all` inherit it; invalid → `ConstraintError`, exit 2. named in `--help` and in the `bound` line |
| stale holder | a holder older than 30m is named in the heartbeat as possibly hung, with `kill <pid>` as the fix. the waiter never kills it |
| wait | poll every 1s; print holders once, a heartbeat every 30s, then `🎫 slot.$i claimed after $t`. never fails for the wait; `--timeout` counts the test run only |
| no `flock` | run unbounded; print `grove: unbounded — flock absent` |
| output | a `grove` branch in the extant tree, after `keyrack`, before `scope` / `status` |

### why `max(1, cores ÷ 6)`

ehmpathy jest configs set `maxWorkers: '50%'` (`jest.unit.config.ts:41`,
`jest.integration.config.ts:59`, `jest.acceptance.config.ts:35`). so one suite runs `cores ÷ 2`
workers, and N suites run `N × cores ÷ 2`. the incident's 17 workers on 12 cores is ~3 suites.
⇒ a bound of 3 would NOT have prevented it. 2 suites = 12 workers = the core count, the most the
box holds before workers contend. `÷ 6` yields 2 on the 12-core grove. see F1.

## .mental model

- to a friend: "the test skill takes a number at the deli counter. there are only so many
  counters per machine. a scoped run is the express lane."
- analogy: a semaphore across processes; a car lot with N spaces, where a towed car frees its
  space on the spot
- their words → our words: "queue" / "wait your turn" → `slot`, `bound`, `claim`. we use `slot`
  (a seat in the pool) and `bound` (the pool size). we avoid `lock` in output: to a reader it
  implies exclusive, and the pool admits N

## .evaluation

| goal (from the wish) | met by |
|---|---|
| never saturate the box | at most N bounded suites at once, across every tree |
| a sound change never reads red for load | queued suites start only when a slot frees |
| wait says so, names holders and trees | `⏳` branch lists slot, tree, type, pid, age |
| never runs past the bound, never fails for the wait | poll until claimed; exit code untouched by wait |
| state outside any repo, one pool per box | `/run/lock/rhachet/git.repo.test/` (the wish said "the user's home"; the director ruled per machine, so three users cannot run three times the bound) |
| default from cores; env or flag override | `nproc ÷ 6`; `GIT_REPO_TEST_SLOTS` (the wish's "or": one path, not two) |
| slot frees on exit, crash, kill | kernel releases `flock` on process death; a trap on INT/TERM/HUP also takes the jest tree down |
| scoped unit run may bypass | scoped runs without `--thorough` bypass |

pros: zero daemons, zero reapers; release is the kernel's job, so no leak path exists. state is
a handful of zero-byte lock files. bypass keeps the dev loop instant.

cons: bounds count, not size — a tiny unscoped suite costs a whole slot. integration suites
spawn subprocesses beyond their jest workers, so 2 slots can still exceed the core count (#1126
owns worker counts). on a much larger box, `cores ÷ 6` admits more suites than `maxWorkers: 50%`
strictly fits (64 cores → 10 suites × 32 workers); the wish asks the default derive from cores,
and the override covers that box. linux-first: stock macOS lacks `flock`.

### edgecases and the pit of success

| edge | behavior |
|---|---|
| holder terminated (SIGINT, SIGTERM, SIGHUP) | its trap kills its own process group, then exits; slot and load free together |
| holder SIGKILLed (oom, `kill -9`) | kernel frees the slot; next poll claims it. the orphaned jest tree may finish its suite: one suite over the bound for that window (F2) |
| bound lowered while slots above N are held | holders of `slot.5` finish; new claims only try `slot.0..N-1` |
| bound raised | new claims see more slots at once |
| two trees race for one free slot | `flock -n` is atomic; one wins, the other polls on |
| `--what all` | parent holds none; each child claims and frees its own |
| `GIT_REPO_TEST_SLOTS=0` / `abc` | `ConstraintError`, exit 2, names the fix |
| a holder hangs (jest open handle) | waiter keeps its wait; past 30m names the holder and `kill <pid>` |
| pool dir absent (every reboot empties tmpfs `/run/lock`) | created `1777` by the first run, which then claims as usual (`case=1` `[t1]`) |
| pool dir uncreatable (no `/run/lock`, read-only, full) | `MalfunctionError`, exit 1, names the path and `GIT_REPO_TEST_SLOTS_DIR` as the fix (failloud, not a silent bypass) |
| a slot file created by another user | opened and locked as any other: files are `0666`; the sticky dir stops deletes, not writes |
| waiter ctrl-c'd mid-wait | exits 130, holds no slot, wrote no record |
| `--timeout 600` while it waits | the clock starts at claim; the wait never trips it |
| `--what types\|lint\|format` (incl. `--when hook.onStop`) | bypass; a quick check or a hook never waits |

## .open questions & assumptions

assumptions:
- `flock(1)` from util-linux is on PATH on every grove (confirmed here: `/usr/bin/flock`) and on
  ci (`.github/workflows/.test.yml` runs on `ubuntu-24.04`, which ships util-linux)
- the kernel releases a `flock` lock when the last descriptor on its open file description
  closes, which process death does. premise from `flock(2)`, NOT yet observed on this box (a
  prototype probe was refused by the permission guard); the case=3 clamp must prove it
- other ehmpathy repos share the `maxWorkers: '50%'` config — confirmed: declapract best practice
- **trees on one box may run under several unix users** (`/home/camper`, `/home/ground`,
  `/home/ubuntu` here). the wish's words ("the user's home") and its goal ("spans every tree and
  repo on the machine") diverge for >1 user. the director ruled for the goal (F7): one pool per
  machine in `/run/lock`. local: `/run/lock` is `drwxrwxrwt root` on tmpfs
- 🔴 **the bound covers only trees whose installed skill has it.** each tree pins its own
  `rhachet-roles-ehmpathy` (`package.json:108`). a tree on 1.39.9 or older never takes a slot, so
  the pool reads "2/2 held" while that tree adds load unseen. the bound reaches full strength only
  once the crew's trees upgrade
- **every heavy run goes through the skill.** a direct `npm run test:integration` bypasses the
  pool. the mechanic briefs steer clones to `rhx git.repo.test`; a human at a shell may not use it
- jest workers are the load that matters; `tsc` and `biome` are not bounded

## .groundwork

### external research

- `flock(1)` / `flock(2)` (util-linux, linux man-pages): `flock -n FILE cmd` and `flock -n FD`
  take an advisory lock without a wait and exit 1 if held. locks belong to the open file
  description; children that inherit the descriptor share it, so the skill closes it for
  children (`9>&-`). release on close, and so on process death. local: `/usr/bin/flock` present
- `nproc` (coreutils) reports usable cores. local: `/usr/bin/nproc` and `/usr/bin/getconf`
  present; the skill falls back to `getconf _NPROCESSORS_ONLN`, then to 1
- jest `maxWorkers` accepts a percent of cores; the repo pins `'50%'` (see above)

### internal research

- `git.repo.test.sh:1256-1271` — `run_single_test` wraps `npm run` in `nice -n 5`; the slot
  claim goes just before this, the descriptor close on these four invocations
- `git.repo.test.sh:1443-1482` — multi-mode loops `bash "$SCRIPT_PATH" ... --_multi-child`; each
  child walks the gate alone and inherits the env, so the parent needs no change
- `git.repo.test.sh:1566-1616` — apply-mode tree: header, `keyrack`, scope preview, then
  `start_timer`. the `grove` branch lands after `keyrack`
- `git.repo.test.sh:634-661` — `--help`; it gains a line for `GIT_REPO_TEST_SLOTS`
- `git.commit.operations.sh:41`, `git.release.sh:262` — the per-user state convention
  (`$HOME/.rhachet/storage/...`). the slot pool departs from it on purpose: per-user state fits a
  commit quota, not a box-wide load bound (F7)
- `git.repo.test.nice.integration.test.ts` — the test pattern to reuse: temp git repo, fake
  `npm` on PATH, mocked `jest --listTests`. the clamp sets `GIT_REPO_TEST_SLOTS_DIR` to a temp dir so the slot pool
  is hermetic
- `claude.tools/output.sh` — `print_tree_branch` and kin for the `grove` branch
- vocab: `ConstraintError` / `MalfunctionError` headers (`rule.require.qualified-error-headers`)

## .what is awkward?

- the bound counts suites, not cpu. a 3-file unscoped run and a 300-file thorough run cost one
  slot each. honest, simple, and coarse
- an unscoped non-thorough run is "full" to the skill, yet `--changedSince` may shrink it to a
  few files. it still waits. a clone may read that as friction; `--scope` is the escape
- a long wait with no end time. the heartbeat proves liveness, but the clone cannot see when a
  slot will free. holder ages are the best hint we can give
- after a SIGKILL (oom, `kill -9`), orphaned jest children keep load on the box while their slot
  is already reused: one suite over the bound until they finish. trappable deaths take the jest
  tree down with them. F2 records the choice
- the pool is cooperative, not enforced. a tree on an older skill, a direct `npm run`, or a
  second unix user adds load the pool cannot see. the `⏳` list then names fewer holders than
  the load implies — a clone who sees "2/2 held" at load 40 should suspect an unseen runner
