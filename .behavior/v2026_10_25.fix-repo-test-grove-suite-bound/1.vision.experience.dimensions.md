# 1.vision.experience.dimensions

## .what

the axes of the experience space for a per-machine bound on `git.repo.test` suites: ten axes,
A–J, in the table below — run kind, slots on arrival, holder fate, bound source, caller shape,
lock primitive, slot pool dir, waiter fate, actor, concurrency at claim. each axis varies on its
own unless a fold below says otherwise; the inventory (`1.vision.experience.case=_.md`) walks
their product.

## .the axes

| id | axis | values | why orthogonal |
|---|---|---|---|
| A | run kind | `non-jest` (`--what types` · `format` · `lint`, any mode) · `plan` (a jest type, `--mode plan`) · `nested` (a jest type, apply, spawned inside a run that holds a slot) · `thorough` (a jest type, apply, `--thorough`) · `scoped` (a jest type, apply, `--scope`, no `--thorough`) · `full` (a jest type, apply, neither flag) | decides WHETHER the bound applies; independent of box state. one partition: the values are read in that order, first match wins |
| B | slots on arrival | `free` · `full` | box state; independent of what the caller asked |
| C | holder fate | `exits` (pass or fail) · `terminated` (SIGINT, SIGTERM, SIGHUP — ctrl-c, a closed session, a harness timeout) · `sigkilled` (SIGKILL, oom kill — untrappable) · `lingers` (holds past the waiter's patience) | how a slot comes free. over B = `free` only `exits` occurs (the run's own exit frees the slot it claimed); the other three need a holder ahead of the waiter, so need B = `full` |
| D | bound source | `default` (from core count) · `env` (`GIT_REPO_TEST_SLOTS`) · `invalid` (`0`, `-1`, `abc`) · `mixed` (concurrent runs that read different N against one pool) | how N is chosen; independent of A–C |
| E | caller shape | `single` (one `--what`) · `multi` (`--what all` or a comma list) | multi spawns one child per type; each child is its own suite |
| F | lock primitive | `present` (`flock` on PATH) · `absent` (macOS stock, minimal image) | a host property; independent of all above |
| G | slot pool dir | `writable` (present) · `absent` (creatable — every reboot clears tmpfs `/run/lock`) · `unwritable` (uncreatable: no `/run/lock`, read-only, full) | a host property; varies the verdict only when F = `present` (see the F × G fold) |
| H | waiter fate | `claims` · `interrupted` (ctrl-c or SIGTERM mid-wait) · `timeout-set` (`--timeout` passed while it waits) | what befalls the waiter itself; walked only over B = `full` — a `free` arrival has no wait to befall |
| I | actor | `clone` · `human` (at a terminal) · `system` (a hook or cron that calls the skill unattended) | who invokes, and who reads the output; independent of box state |
| J | concurrency at claim | `sole` (one waiter sees the slot free) · `race` (two or more trees poll the same free slot in one tick) · `pool-init-race` (two runs create the pool dir at once) | how many claimants meet one free slot; independent of who they are |

## .the product

- stage 1 — gate: `A × E` = 6 × 2 = 12 cells. decides bounded vs bypass
- stage 2 — wait: `B × C` = 2 × 4 = 8 cells, plus `H` over `full` = 2 new cells (`claims` is
  the C walk) → 10 cells. 3 of the 10 carry the verdict `impossible` (a `free` slot has no holder
  to be terminated, sigkilled, or to linger); an impossible cell is still a walked cell
- stage 3 — config: `D` = 4 cells, applied to any bounded cell
- stage 4 — host: `F × G` = 2 × 3 = 6 cells, applied to any bounded cell
- stage 5 — actor: `I` = 3 cells, over bounded cells
- stage 6 — concurrency: `J` = 3 cells, over bounded cells

total walked: 12 + 10 + 4 + 6 + 3 + 3 = 38 cells, each with one verdict (21 demoed, 13
itemized, 1 forbidden, 3 impossible). the stages fold because each later axis only has a value
inside the `bounded` half of stage 1: a bypass run never reads N, never waits, never takes a lock.

## .why the folds hold

- **A is one partition by precedence.** `--mode plan` does not apply to `types` / `format` /
  `lint` — the skill forces them to apply (`git.repo.test.sh:1489-1491`) — so a `--mode plan
  --what lint` run is `non-jest`, not `plan`. read the values in table order; first match wins,
  so every run lands in exactly one row
- **C over `free` is `exits` alone.** a free slot is claimed at once, so no holder stands ahead
  to be terminated, sigkilled, or to linger; those three cells are impossible. `free × exits` is
  the arrival's own run, which ends and frees its slot (`case=1`)
- **C splits kills by whether they can be trapped.** on `terminated`, the skill's trap kills its
  own process group, so the slot frees AND the jest tree dies — no orphan load. on `sigkilled`,
  no trap runs: the kernel frees the slot, but the jest tree may run on as orphans. the two
  differ in load, so they are two values
- **D `mixed` resolves per run.** each run reads its own N and tries only `slot.0..N-1`. a run
  with a lower N never claims a higher slot; a holder of a higher slot finishes undisturbed. the
  box holds at most the largest N any live run read
- **D folds out of B × C.** N changes how soon a slot is full, never what a wait looks like
- **F folds out of B × C.** with no `flock`, no lock exists, so no wait can occur; stage 4 is one
  verdict per value, not a box
- **H is orthogonal to C.** C is how the holder's slot frees; H is what befalls the waiter while
  it waits. a waiter can be interrupted whatever its holder does
- **F × G: G depends on F.** with `flock` absent, every G value folds to the `flock`-absent
  verdict — the skill never touches the dir when it cannot lock. G varies the verdict only under
  `flock` present, which is why stage 4 walks them as a product rather than apart
- **G `absent` resolves into `writable`.** an absent but creatable dir is created (`mkdir -p`,
  mode `1777`), then the run claims a slot as in `case=1`. only an uncreatable dir is
  `unwritable` → `MalfunctionError`
- **the operator is not an actor value.** a grove operator is a `human` who sets
  `GIT_REPO_TEST_SLOTS`; what is distinct about that act is the bound source, which axis D already
  holds (`env`). so the operator's experience is walked at D, not at I
- **I folds out of A–H, except at two cells.** the lock and the gate read no caller identity, so
  every verdict above holds for any actor. actor matters only where a person must act: a
  `human` can interrupt a wait (H), and a `system` caller has no one to read a stale-holder hint
  or hit ctrl-c. stage 5 walks I alone for that reason
- **J folds out of I.** `flock -n` is atomic in the kernel; a race resolves the same whoever
  the claimants are. J walks alone over bounded cells
- **E folds into A per child.** `--what all` runs each type as its own child process
  (`git.repo.test.sh:1470`), so each child walks stage 1 alone; the parent holds no slot
