# 1.vision.experience.dimensions

the experience space of one `rhx git.pull.comment.set` run, once the hint exists.

## .the dimensions

| # | dimension | values (closed) | why orthogonal |
|---|---|---|---|
| D1 | set outcome | posted · edited · no-op (apply) · plan · refused before write · write malfunction | what the set itself did |
| D2 | candidate's thread state | open · resolved | graphql resolution; independent of who wrote or replied |
| D3 | candidate's author | human (not pr author) · robot · pr author · app bot | who wrote the comment under test; any value can meet any D2 or D4 value |
| D4 | last later reply in the candidate's thread | none · robot · pr author · another human · app bot | the rule's core boundary; independent of D3 (a robot reply can follow a human or a bot) |
| D5 | the hint read | ok · fails (gh error, rate limit, auth refusal) | a second call; may fail while the write held |
| D6 | output | tree · json | contract shape |
| D7 | the set's target | key (top-level) · thread (reply) · id (edit) | which comment the set touched |
| D8 | time / read consistency | list current · list lags the just-posted reply · a comment lands mid-read · a concurrent set races · an edit lands mid-read | the read runs after the write, in a round where humans and other runs act at once |
| D9 | actor role | set-runner · hint-consumer | does the actor run a set, or only live its effect? |
| D9a | set-runner | robot in a reply round · human via as-human | crossed with the run (below) |
| D9b | hint-consumer | reviewer (lives it through the replies it prompts) · future release gate (calls the shared read, not set) | crossed with the rule, never with the run |

**derived, not a dimension: the await population.** which comments await is the rule's output, a function of D2 × D3 × D4 across every candidate. it is never an independent axis. its closed value set, used only to shape the hint body: none · review rows only · issue rows only · both.

## .the walked product

### the rule (D2 × D3 × D4, per candidate)

D3 first: a candidate by the robot, the pr author, or an app bot never awaits, whatever D2 or D4 hold. that is 3 × 2 × 5 = 30 cells, all "no", each by one reason. a human candidate (D3 = human) walks D2 × D4:

| thread | last later reply by | awaits? | why |
|---|---|---|---|
| open | none | yes | no answer yet |
| open | another human | yes | a third party is no answer |
| open | app bot | yes | a status note is no answer (F9) |
| open | robot | no | answered |
| open | pr author | no | answered |
| resolved | any of 5 | no | a resolved thread awaits naught |

issue (top-level) candidates have no D2. the top-level conversation is one thread, so D4 reads as "the last later top-level comment" (F11).

### the run (D1 × D5 × D6)

| D1 outcome | D5 ok, tree | D5 ok, json | D5 fails, tree | D5 fails, json |
|---|---|---|---|---|
| posted | hint | json unchanged | ⚠️ line on stdout + stderr, exit 0 | json unchanged on stdout; ⚠️ line on stderr only; exit 0 |
| edited | hint | json unchanged | as posted | as posted |
| no-op (apply) | hint | json unchanged | as posted | as posted |
| plan | no hint; plan's own 🥥 | plan json, no hint | impossible: plan makes no hint read | impossible: plan makes no hint read |
| refused before write | refusal only (exit 2) | refusal json (exit 2) | impossible: the refusal exits before any hint read | impossible: same |
| write malfunction | malfunction only (exit 1) | malfunction json (exit 1) | impossible: exits before any hint read | impossible: same |

json × fails: the warn goes to stderr only, so stdout stays one parseable json object. tree × fails: `emit_both`, as the extant warn does.

### time / read consistency (D8, on an apply)

| D8 | verdict | outcome |
|---|---|---|
| list current | the norm | hint exact |
| list lags the just-posted reply | itemized, sharp alterpath | the answered thread shows once; the next set or get clears it. Q12 probes it |
| a comment lands mid-read (a human posts between the pages, or between the rest list and the graphql read) | itemized, sharp alterpath | a new comment absent from the thread map reads "open" (extant default), so it shows; a comment absent from the list is missed until the next read. the hint is a snapshot, never a gate |
| a concurrent set races (two runs post at once) | itemized, sharp alterpath | each hint is a snapshot after its own write; one may list a thread the other just answered. the next run converges. the write keeps its extant twin hazard (`set.sh:198-201`) |
| an edit lands mid-read | itemized, happy alterpath | an edit leaves creation time alone, so membership holds; only the first-words text may be one version stale |

### set-runner × run (D9a × D5 × D6, on an apply)

| set-runner | ok, tree | ok, json | fails, tree | fails, json |
|---|---|---|---|---|
| robot in a reply round | demoed (case=1, 2, 6) | itemized (json unchanged) | demoed (case=3) | demoed (case=3 t2, stderr warn) |
| human via as-human | itemized: same render, commands carry `--auth as-human` | itemized | itemized: same warn | itemized |

### hint-consumer × rule (D9b)

| hint-consumer | lives | verdict |
|---|---|---|
| reviewer | each comment shows until answered or resolved; a "+1" or app-bot note does not hide it | demoed (case=4) |
| future release gate | the same membership, via the shared read | demoed as the clamp hint == get (case=4 t1, case=6 t2); the gate itself is out of scope |

### target × outcome (D7 × D1)

| target | posted | edited | no-op | plan | refused | malfunction |
|---|---|---|---|---|---|---|
| key | yes (absent key) | yes (own key, body differs) | yes | yes | yes | yes |
| thread | yes (absent key in thread) | yes (own key in thread, body differs) | yes | yes | yes | yes |
| id | impossible: an id names an extant comment, so set PATCHes, never POSTs | yes | yes | yes | yes | yes |

a keyed target can edit: `set.sh:209-215` PATCHes an own match. so only `id × posted` cannot occur. every possible cell renders the same hint, since D7 never changes the read.

### the hint body (derived population × D7)

D7 does not change the body: every target reads the whole pr after the write.

| population | body |
|---|---|
| none | one line: naught awaits a reply |
| review rows only | one row per thread: author, path:line, first words, id, then `--reply-to <id> --key answer-<id>` |
| issue rows only | one row per comment: author, `top-level`, first words, id, then a top-level `--key answer-<id>` |
| both | one row each, oldest first |
