# case=3 — the hint read fails, the set still holds

feel: sharp · care: critipath

## .narrative

the robot posts an answer. the write lands and reads back. then the hint's read of every comment hits a rate limit. the set must not lie that it failed: the comment is live. one warn line says the hint could not read, names the cause, and names the command that reads the same list by hand. the set exits 0. a retry loop that keys on the exit code never re-posts.

## .the render (sketch, tail only)

```
   └─ verdict: posted, read back, hash matches
      ├─ id: 5101
      ├─ url: https://github.com/ehmpathy/surf-demo/pull/7#discussion_r5101
      └─ read-back sha256: 9f2c…

⚠️  could not read the comments that await a reply (gh api failed: API rate limit exceeded); run rhx git.pull.comment.get --pr 7 --in ehmpathy/surf-demo --unanswered
```

one line, as the wish asks. under `--output tree` it goes to stdout and stderr via `emit_both`, the shape of the extant warn in `git.repo.get.operations.sh:1143` (`emit_both "   ⚠️  $slug — fetch failed; …"`). under `--output json` it goes to stderr only, so stdout stays one parseable json object.

## .bdd

```
given('[case3] a pr where the write succeeds and the next list call fails')
  when('[t0] set --mode apply')
    then('the set exits 0')
    then('the set result tree shows posted, read back, hash matches')
    then('stdout ends with one warn line that names the cause and the get --unanswered command')
    then('no 💥 MalfunctionError or ✋ ConstraintError header renders, on either stream')
  when('[t1] set --mode apply; the hint read hits an auth refusal (a 401)')
    then('still exit 0, still one warn line: the family refusal render is muted')
  when('[t2] set --mode apply --output json; the hint read fails')
    then('stdout parses as the set json, unchanged')
    then('the warn line is on stderr only; exit 0')
```
