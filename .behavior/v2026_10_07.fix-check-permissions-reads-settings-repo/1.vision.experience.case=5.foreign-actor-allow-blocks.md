# case=5 — split layout, hash actor, another actor's allow does not count

cell #20 · sharp · critipath

## .narrative

the repo actor's `settings.repo.json` (at `<repo>/.claude`) allows `Bash(npm run build:*)`. a clone
of actor `hash=810671c1` does not hold that allow. claude, launched with
`--settings <actor>/settings.repo.json`, would prompt. before: the walk landed on `<repo>/.claude`
and checked the hash clone against the repo actor's list. after: the config dir comes from the env;
the walk-up dir contributes only `settings.json` + `settings.local.json` (the project scope claude
loads), never its `settings.repo.json`. the hook blocks and lists the clone's OWN allows. the message also names the config dir it read, so a
human who means the allow to apply knows which actor's `settings.repo.json` to grant it in.

## .bdd sketch

```ts
given('[case5] a hash actor; the command is allowed only in the repo actor settings.repo.json', () => {
  // <tmp>/actor/.claude/settings.repo.json   allow: Bash(rhx review:*)
  // <tmp>/.claude/settings.repo.json         allow: Bash(npm run build:*)
  // env: CLAUDE_CONFIG_DIR=<tmp>/actor/.claude, cwd=<tmp>
  when('[t0] the clone runs npm run build', () => {
    then('exit 2', () => {});
    then('stderr lists rhx review, not npm run build', () => {});
    then('stderr names the config dir it read: <tmp>/actor/.claude', () => {});
  });
});
```
