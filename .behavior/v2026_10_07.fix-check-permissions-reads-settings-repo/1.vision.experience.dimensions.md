# 1.vision.experience.dimensions

## .actor

two actors:
- a **mechanic clone** whose Bash call passes through `pretooluse.check-permissions.sh` before
  claude's own permission check, then through `permissionrequest.decide-permissions.sh` if claude
  would prompt. it reads the boot list from `sessionstart.notify-permissions.sh`
- a **human** who runs `rhx init` to write the repo's permissions, and who feels the clone's
  result second-hand: a clone that stalls on its own allowed commands, or one that runs clean

## .the dirs and files the hook reads

```
walk-up dir = first <ancestor>/.claude above $PWD
config dir  = $CLAUDE_CONFIG_DIR, else the walk-up dir
user dir    = $CLAUDE_CONFIG_DIR, else $HOME/.claude
```

| source | file | claude loads it as |
|--------|------|--------------------|
| `actor-repo` | `<config dir>/settings.repo.json` | `--settings` (rhachet convention) |
| `actor-local` | `<config dir>/settings.local.json` | project local when config dir = walk-up dir; else not loaded (over-allow, fails safe) |
| `user` | `<user dir>/settings.json` | user scope |
| `project` | `<walk-up dir>/settings.json` | project scope |
| `project-local` | `<walk-up dir>/settings.local.json` | project local scope |

## .the axes

| dim | name | values |
|-----|------|--------|
| A | config dir source | `walk` = `$CLAUDE_CONFIG_DIR` unset · `ccd` = set (a hash actor's brain dir) |
| B | layout | `split` = allows in `settings.repo.json`; `settings.json → grove → ~/.claude/settings.json` · `old` = allows in a real `settings.json`; no `settings.repo.json` |
| C | command source: the ONE file that lists the command | `actor-repo` · `actor-local` · `user` · `project` · `project-local` · `foreign` (another actor's `settings.repo.json`, i.e. the walk-up dir's, read by no rule) · `none` |
| D | file state of the layers | `ok` = no layer is corrupt (each file that exists is valid, any may be absent) AND at least one layer holds a Bash allow · `link-broken` = a `settings.json` link with no target · `malformed` = one file is invalid json · `all-absent` = no layer is corrupt AND no layer holds a Bash allow |

D partitions on two tests:
- is a layer corrupt? `link-broken` or `malformed`
- if none is, does any layer hold a Bash allow? `ok` if yes, `all-absent` if no

each state maps to exactly one value.

C's values map one-to-one onto the five files the contract reads, plus `foreign` (the file it must NOT read) and `none`.

## .orthogonality, and the known implications

each axis varies independently in the real world:
- A is set by how the clone launched
- B by the rhachet version a repo runs
- C by where a human put the allow
- D by disk state

four combinations are void by definition. they are surfaced here, not left implicit:

| implication | why | cells it voids |
|---|---|---|
| `C = foreign` ⇒ `A = ccd` and `B = split` | a foreign file exists only when the config dir differs from the walk-up dir, and only the split layout writes `settings.repo.json` | `walk × foreign`, `old × foreign` |
| `C = actor-repo` ⇒ `B = split` | the old layout holds no `settings.repo.json` | `old × actor-repo` |
| `A = walk` ⇒ `actor-local ≡ project-local` | the config dir IS the walk-up dir, so both name one file | `walk × actor-local` folds into `walk × project-local` |
| `D = all-absent` ⇒ `C = none` | no list can list the command | all-absent × any C except none |
| `A = walk ∧ B = split` ⇒ `user ≡ project` | under `walk` the user file is `$HOME/.claude/settings.json`; under `split` the project `settings.json` links through the grove to that same file | `walk × split × project` folds into `walk × split × user` |
| `D = link-broken` ⇒ `B = split` | only the split layout makes `settings.json` a link; the old layout's is a real file | `link-broken × old` |

the latent dimension behind the first three is **"is the config dir the walk-up dir?"**. A carries
it: `walk` ⇒ same dir, `ccd` ⇒ a different dir (rhachet's actor dirs never coincide with
`<repo>/.claude` for a hash actor).

## .axis E — the surface

four mechanic surfaces touch the allowlist (#895, F2). the three readers share one layer rule, so
A × B × C × D holds for each by construction. the writer has its own axes.

| E | surface | role | what it reads or writes |
|---|---|---|---|
| `check` | `pretooluse.check-permissions.sh` | gate: block once, or pass | the five allow layers |
| `decide` | `permissionrequest.decide-permissions.sh` | auto-approve a compound, or lift to the prompt | the five layers, for allow AND deny; the audit log in the config dir |
| `notify` | `sessionstart.notify-permissions.sh` | boot list of pre-approved commands | the five allow layers |
| `init` | `init.claude.sh` + `init.claude.permissions.sh` | write the repo's permissions | one file in `<repo>/.claude`, by layout |

**why the readers need not re-walk A × B × C × D:** each reader calls the one layer rule, so a
cell's file set is the same for all three. only the outcome's shape differs (block / lift / list).
so `decide` and `notify` walk the cells where their shape is new: the deny union, the foreign file,
the absent list, and the audit log. the `check` table stands in for the rest.

**the init axes:**

| dim | name | values |
|---|---|---|
| B | layout (same as above) | `split` = `settings.json` is a link, or `settings.repo.json` exists · `old` = otherwise |
| F | prior state of the target file | `absent` · `stale` (permissions differ) · `current` (permissions match) |
| G | `settings.json` link state (split only) | `intact` · `broken` |

init product: B × F, with G walked under `split` = 3 (old) + 3 × 2 (split) = 9 combinations. they
fold to six cells by outcome:
- the three `current` combinations write no file and make no backup → one cell
- `split × absent × broken` and `split × stale × broken` share one outcome (write `settings.repo.json`, leave the link as found) → one cell
- the other four stand alone

## .the walked product

- **main table** (`check`): A × B × C at `D = ok` = 2 × 2 × 7 = 28 cells
- **file-state table** (`check`): D's other three values, walked against the outcome they change = 4 cells (`all-absent` splits by A, since its message differs)
- **reader table** (`decide`, `notify`): the cells whose shape is new = 8 cells
- **init table**: B × F × G by outcome = 6 cells
- **total**: 28 + 4 + 8 + 6 = 46 cells
