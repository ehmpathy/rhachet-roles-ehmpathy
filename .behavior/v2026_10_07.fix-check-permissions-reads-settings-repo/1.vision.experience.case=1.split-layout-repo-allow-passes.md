# case=1 — split layout, repo actor, repo allow passes

cells #1, #3 · happy · critipath

## .narrative

a clone of the repo actor runs `rhx git.repo.test --what types`. no `$CLAUDE_CONFIG_DIR`, so the hook
walks up to `<repo>/.claude`. there, `settings.repo.json` lists `Bash(rhx git.repo.test:*)`;
`settings.json` links to the human's home defaults, which do not. before: the hook read only
`settings.json`, saw the home list, blocked. after: the hook reads `settings.repo.json` too, matches
the prefix, exits 0. the clone never sees the hook.

next the clone runs `ls`, which only the human's home defaults allow. it reaches them through the
project link (`<repo>/.claude/settings.json → grove → ~/.claude/settings.json`), the same file as the
user layer (cell #3). the hook still reads that layer, so `ls` passes too. the fix adds the repo's
allows without a loss of the home ones.
