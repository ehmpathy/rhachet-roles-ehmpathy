## .what

in `ehmpathy/rhachet-roles-ehmpathy`, close issue #895: the mechanic's
`pretooluse.check-permissions.sh` hook must read the allowlist claude actually runs on —
`settings.repo.json` — from the config dir of the clone that actually runs the command.

## .the defect

a rhachet change split a repo's `.claude/` config:

- the repo's permissions now live in `settings.repo.json`, which claude loads via `--settings`
- `settings.json` is now a link chain: `settings.json → settings.grove.json → ~/.claude/settings.json`,
  the human's home defaults

the hook still reads `settings.json` (plus `settings.local.json`) by name, so it now reads the
home allowlist — which holds almost none of the repo's Bash allows. claude itself still knows the
repo's allows, but the hook runs first and blocks the call anyway, with "not covered by
pre-approved permissions" and an empty pattern list.

a second, quieter defect: the hook finds the config dir by a walk up from `$PWD`, which always
lands on `<repo>/.claude` — the repo actor's dir. a clone of another actor is checked against the
repo actor's allowlist, not its own.

## .the outcome

- the hook reads `settings.repo.json` (and `settings.local.json` beside it) — the same allowlist
  claude loads
- the hook finds the config dir from `$CLAUDE_CONFIG_DIR` when set, and falls back to the walk up
  only when it is not, so every clone is checked against its own actor's allowlist
- a repo on the old layout (allows in a real `settings.json`) still works — the hook reads the
  allowlist from wherever it actually lives, and never blocks a command claude would allow
- a hook that finds no allowlist at all says so, and names the files it looked for, rather than
  report an empty pattern list as though the list were empty
- tests prove: the split layout passes a repo allow, the old layout still passes, an actor's
  `$CLAUDE_CONFIG_DIR` is honored over the walk up, and a truly unlisted command is still blocked

## .why now

every mechanic clone on the split layout has its own repo's allowed commands blocked by its own
hook — the hook and claude disagree about what is allowed, and the hook wins. the package ships its
hooks read-only, and an in-repo pnpm patch did not apply, so the fix must land here, upstream. a
workaround on the rhachet side would put the repo's allows back into `settings.json` — exactly the
blend of repo and home config the split removed.
