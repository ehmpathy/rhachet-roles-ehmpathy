# 1.vision — the hook reads the allowlist claude reads

## .the outcome world

a mechanic clone runs `rhx git.repo.test --what types`. the hook passes it in silence, because the
hook now reads the same layers claude merges: the actor's `settings.repo.json`, the user's
`settings.json`, the project's `settings.json`, and each `settings.local.json`. the hook and claude
agree on what is allowed. the hook only nudges where claude would prompt.

| | before | after |
|---|---|---|
| split layout, repo allow | blocked; the list shows home defaults only | passes |
| hash actor clone | checked against the repo actor's list | checked against its own actor's list |
| old layout | passes | passes |
| no allowlist anywhere | "🛑 BLOCKED" over an empty list; clones give up | "no pre-approved Bash permissions were found", plus each path read |
| a repo-allowed compound at the prompt | decide hook lifts it to a human | decide hook approves it; the human's denies still win |
| boot list | the home defaults only | the same union the gate checks |
| `rhx init`, split layout | `mv` replaces the grove link; rhachet repairs it later; two backups | writes `settings.repo.json` by name; the link stays; one backup or none |

**the aha:** the hooks are a mirror of claude's allowlist, not a second opinion. once all read the
same layers, a block means "claude would prompt you". it never means "the hook looked in the wrong
file". and the init writes the file the hooks read.

## .the contract

the hook resolves three dirs, then unions Bash allows across five files:

```
walk-up dir = first <ancestor>/.claude above $PWD (as today)
config dir  = $CLAUDE_CONFIG_DIR, else the walk-up dir     (the actor's brain dir)
user dir    = $CLAUDE_CONFIG_DIR, else $HOME/.claude       (claude's user scope)

actor   : <config dir>/settings.repo.json   + <config dir>/settings.local.json
user    : <user dir>/settings.json
project : <walk-up dir>/settings.json        + <walk-up dir>/settings.local.json
```

- duplicates collapse; one path read twice is harmless (the dirs often coincide)
- the user dir mirrors claude's own rule. without `$HOME/.claude`, a human's home allow (which claude honors) would still be blocked under the old layout. the hook has always had that gap; this wish's "never block what claude allows" closes it
- the walk-up dir's `settings.repo.json` is read ONLY when it IS the config dir; another actor's file never counts
- zero Bash allows across all five → the "no allowlist found" message names each path and its state (absent / N allows)
- no config dir and no walk-up dir → exit 0, as today
- when the config dir differs from the walk-up dir, a block message names the config dir it read (one line, above the pattern list). the old-layout message stays byte-identical, so extant snapshots do not churn
- `permission.nudges.local.json` lives in the config dir

### the peer surfaces (all of #895, per F2)

| surface | change |
|---|---|
| `permissionrequest.decide-permissions.sh` | reads the same five layers for `permissions.allow` AND `permissions.deny`. a deny in any read layer vetoes an allow in any other. zero allows → lift, never approve, and name each path on stderr. the audit log `permission.decisions.local.log` lives in the config dir |
| `sessionstart.notify-permissions.sh` | the boot list is the union of the same five layers. zero allows → one line that says so and names each path (today: silent). never blocks the session |
| `init.claude.permissions.sh` | writes `<repo>/.claude/settings.repo.json` when the layout is split (`settings.json` is a link, or `settings.repo.json` exists); else `settings.json`, as today. temp file in the same dir + rename. never writes through, or replaces, the `settings.json` link. backs up only a prior file whose permissions change |
| `init.claude.sh` | no backup of its own; the writer's one backup is the only one |

the three readers share one layer rule (one place, not three copies), so they cannot drift apart again.

## .mental model

a clone would put it this way: "the bouncer now checks the same guest list as the door". the old
hook checked a list on the wrong clipboard. in the human's words, the actor dir is "the clone's own
settings", and the walk-up dir is "the repo's `.claude`".

## .evaluation

**pros**
- closes #895's defect at its root: the hook reads the file claude reads
- one rule covers both layouts; no layout detection, no version sniff
- the actor boundary holds (case=5) without a loss to the old layout (case=4)
- an absent list now shows up as a config fault; it no longer reads as an empty toolkit

**cons**
- `settings.repo.json` in `$CLAUDE_CONFIG_DIR` is a rhachet convention. the hook cannot see claude's actual `--settings` path. if rhachet passes another file, the hook drifts again
- five reads where there were two, a fixed cost of three more jq forks. `[case23]` bounds only the 500-vs-250-rule ratio (`MAX_SCALE_FACTOR = 3`) and an absolute 30s (`integration.test.ts:1099,1107`); a fixed cost moves neither. the hook's own failfast is 4s (`check-permissions.sh:39`)

**edge cases kept in the pit of success**
- tests inherit `CLAUDE_CONFIG_DIR` and `HOME` from the session that runs them. every test must set or scrub `CLAUDE_CONFIG_DIR` and point `HOME` at a temp dir. otherwise the suite reads the runner's real allowlist, and a `[case7]`-style "blocked" assertion flips green on a dev box (hermetic tests)
- `$CLAUDE_CONFIG_DIR` set to a dir that does not exist → its layers read as `absent`; the walk-up project layer still counts
- `settings.json` as a broken link (grove absent) → treat as absent, never a crash
- malformed json in one layer → that layer yields no allows; the others still count (today's `2>/dev/null` stance)

## .groundwork

### external research

- `https://code.claude.com/docs/en/settings.md`:
  - user scope = `$CLAUDE_CONFIG_DIR/settings.json` when set
  - project `.claude/settings.json` + `settings.local.json` still load under `CLAUDE_CONFIG_DIR`
  - precedence: managed > `--settings` > project local > project > user
- `https://code.claude.com/docs/en/auto-mode-config.md`: "entries from each scope are combined … the combination is additive"
  - ⚠️ that quote concerns the auto-mode classifier lists, not `permissions.allow` directly
  - so the union across scopes is supported, not proven; verify it in execution
  - if it is wrong, the hook over-allows, which fails safe: claude still prompts

## .what is awkward

- the hook must guess claude's `--settings` path from a name convention. a hook input or env var that named the active settings files would end the guess; no such input exists today
- the bhrain twins (driver `init.claude.status-line.sh`, `init.claude.permissions.route.sh`; achiever `init.claude.sh`) live in `rhachet-roles-bhrain`, filed there per #895. until they follow, a bhrain init on the split layout still replaces the grove link
- the mechanic rule `rule.require.qualified-error-headers` argues for `✋ ConstraintError:` over `🛑 BLOCKED:`. a header change would churn every extant snapshot, so it stays out of scope here
