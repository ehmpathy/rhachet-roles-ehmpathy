# case=11 — decide reads the same layers as check

cells #33, #34, #35, #36, #37 · critipath (#33, #34) + alterpaths

## .narrative

a clone runs `rhx git.repo.test --what types | tail -5`. claude would prompt on the compound, so
`permissionrequest.decide-permissions.sh` judges it segment by segment. today it reads
`<walk-up>/.claude/settings.json`, which under the split layout is the human's home list. that list
holds `tail` but not `rhx git.repo.test`, so the hook lifts to a prompt. after: it reads the same
five layers as the check hook. both segments are allowed, so it approves (#33).

the human's deny list still wins. if `settings.repo.json` denies `rhx git.commit.uses set` and the
home list allows `rhx`, the segment is denied, and the compound lifts (#34). a deny from any read
layer vetoes an allow from any other.

a hash actor's clone gets no help from the repo actor's `settings.repo.json`; that file is foreign,
so its allows never approve (#35). with no allows anywhere, the hook lifts to the prompt and names
each path it sought on stderr (#36). every decision lands in the audit log of the clone's own config
dir (#37), so a reviewer reads one actor's decisions in one place.
