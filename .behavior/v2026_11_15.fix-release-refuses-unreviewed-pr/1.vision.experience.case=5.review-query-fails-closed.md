# case=5 — review query fails, the gate fails closed

## .narrative

the clone runs `rhx git.release --into main --apply` on pr #42. the reviews call to github fails
(a 5xx past the retries, or a token without pull-request read). the skill cannot tell whether a
human approved. it does not guess: it prints `💥 MalfunctionError`, names pr #42 and the failed
call, and exits 1. automerge is never enabled.

if an earlier run had already turned automerge on, an unread review is no approval, so the skill
disables that automerge before it exits 1, and says so. if the disable fails too, it says
automerge is still on, so the clone escalates at once.

## .bdd

```
given('[case5] feature pr #42, open, no automerge; gh api .../pulls/42/reviews exits 1')
  when('[t0] git.release --into main --apply')
    then('exit 1')
    then('stdout + stderr: 💥 MalfunctionError, names pr #42, says the review read failed, hints a retry')
    then('gh pr merge never called')
  when('[t1] git.release --into main (plan)')
    then('exit 0; status as today — plan never reads reviews, so the fault cannot block it')
given('[case5b] pr #42 open, automerge already on; reviews read exits 1')
  when('[t0] git.release --into main --apply')
    then('gh pr merge --disable-auto called on #42')
    then('exit 1; 💥 MalfunctionError says the review read failed and automerge was disabled')
given('[case5c] same as case5b, and --disable-auto exits 1 too')
  when('[t0] git.release --into main --apply')
    then('exit 1; 💥 MalfunctionError says automerge is still on, names pr #42')
```
