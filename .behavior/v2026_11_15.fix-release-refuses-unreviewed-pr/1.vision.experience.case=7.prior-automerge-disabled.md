# case=7 — prior automerge disabled, then refused

## .narrative

before this change shipped, the clone ran `rhx git.release --apply` on pr #42; automerge went on.
no human has reviewed #42. checks still run. the clone runs `--apply` again, now under the gate.
the skill reads the reviews: none. it sees automerge on, disables it, confirms it is off, then
refuses with exit 2. when checks pass, github has no automerge to act on; #42 stays open.

if the disable call itself fails, the skill cannot promise "naught merged". it reports
`💥 MalfunctionError` that names the pr and says automerge is still on, and exits 1, so the clone
escalates at once rather than walk away from a pr that will merge.

## .bdd

```
given('[case7] pr #42 open, checks inflight, automerge on, no reviews')
  when('[t0] git.release --into main --apply')
    then('gh pr merge --disable-auto called on #42')
    then('exit 2; refusal names pr #42; says automerge was disabled')
    then('gh pr merge --auto / --squash never called')
given('[case7b] same, but gh pr merge --disable-auto exits 1')
  when('[t0] git.release --into main --apply')
    then('exit 1; 💥 MalfunctionError names pr #42 and says automerge is still on')
given('[case7c] pr #42 open, automerge on, latest human (MEMBER) review APPROVED')
  when('[t0] git.release --into main --apply')
    then('no disable call; watch proceeds as today')
```
