# 1.vision.experience.dimensions

## .dimensions

| # | dimension | values (closed) | orthogonal because |
|---|---|---|---|
| D1 | goal | `--into main` · `--into prod` (from feat) · `--from main --into prod` | decides which transports run; says naught about reviews or mode |
| D2 | mode | plan · `--watch` · `--apply` · `--apply --watch` · `--mode apply` | how far the caller asks the skill to go; any goal pairs with any mode |
| D3a | reviewer kind (per review) | human with authority (OWNER / MEMBER / COLLABORATOR) · outsider human (NONE / CONTRIBUTOR) · bot (`[bot]` or `type: Bot`) · robot (seaturtle roster login) · deleted account (`user: null`, no login; E19) | who wrote a review; any kind can submit any state |
| D3b | review history of the feature pr, over authorized humans | none · one APPROVED · CHANGES_REQUESTED only (no prior approval) · APPROVED then CHANGES_REQUESTED (same human) · APPROVED then DISMISSED · COMMENTED only · human-a APPROVED + human-b COMMENTED · human-a APPROVED + human-b CHANGES_REQUESTED | the decisive-review outcome; reviews from non-authorized kinds (D3a) are filtered out first, so D3b ranges over what is left |
| D3c | approval freshness | on the head · on an older commit (stale) | which commit an APPROVED covers; any history in D3b can sit on either commit |
| D3d | head between gate and merge | still · moved (a push landed) | a race against the run; independent of what the reviews say |
| D4 | lift flag present | no · yes (`--dirty allow`, `--retry`, `--from <branch>`, `--why`: every flag the skill parses beyond mode and goal) | the gate reads no flag, so presence cannot correlate with the verdict by construction |
| D5 | pr state | open, no automerge · open, automerge already on · already merged · unfound | github-side state, set before this run |
| D6 | review query outcome | read ok · reviews read failed · head read failed | a network/auth fact, independent of what the reviews say |
| D7 | caller | clone (no tty) · human at a terminal, pr authored by a robot · human at a terminal, pr authored by that human | who runs the skill; the gate reads no caller signal (F4) |
| D8 | transport | feature pr · release pr (release-please) · tag | which merge the step makes; only the feature pr carries the code a human reviews, so only it is gated and pinned (F1) |
| D9 | apply-watch event after the arm | none (merges) · head moves · approval lost (changes requested · dismissed · reviews gone) · checks red · rebase needed · timeout · gh fault · a trappable signal (INT · TERM · HUP) · SIGKILL | what ends the watch short of a merge; a process fact, independent of the gate's verdict at arm time |

review identity and review decision are two concepts, so two axes: D3a filters, D3b decides.

## .the walked product

the gate keys on D2 × D3a × D3b × D3c × D5 × D6; the merge pin keys on D3d; the automerge lease
keys on D9. D8 decides which transport the gate and pin bind (the feature pr only). D1 decides only whether a feature pr exists. D4 and D7
never change the verdict (no flag lifts the gate; no caller is exempt — F4). D7's self-authored
human row matters only because github forbids self-approval, so that human always meets the
refusal unless a peer approves (E14).

"approved" below = D3b yields APPROVED after D3a's filter.
