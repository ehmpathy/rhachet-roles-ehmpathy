# case=9 — `--into prod` gates the feature pr, never the release pr

## .narrative

the human approves pr #42. the clone runs `--into prod --apply`. the gate reads the reviews of #42,
finds the approval on its head, and arms automerge pinned to that head. #42 merges.

release-please opens pr #100, `chore(release): v1.3.0`. no human reviews it, and none needs to: it
holds a version bump and a changelog built from commits a human already approved. the skill arms
automerge on #100 with no review read and no head pin. it merges, the tag is cut, publish runs.

a gate on #100 would read zero reviews and refuse every prod release. the code a human must see is
in #42; that is where the gate sits.

## .bdd

```
given('[case9] feature pr #42 approved; release pr #100 with zero reviews')
  when('[t0] git.release --into prod --apply')
    then('exit 0; merges through to publish')
    then('the reviews of #42 are read; the reviews of #100 are never read')
    then('the #42 merge carries --match-head-commit; the #100 merge does not')
```
