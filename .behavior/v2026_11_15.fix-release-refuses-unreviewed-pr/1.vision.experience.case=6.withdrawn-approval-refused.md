# case=6 — a withdrawn or vetoed approval is no approval

## .narrative

the human approved pr #42 yesterday. today they spot a defect and submit "request changes". the
clone, unaware, runs `--apply`. the skill reads each authorized human's latest decisive review:
changes requested. refused, exit 2, same refusal as case=1. a repo rule may also dismiss an
approval when new commits land; a dismissed approval reads the same as none. and when one human
approves while another requests changes, the request wins.

## .bdd

```
given('[case6a] pr #42 reviews: human-a APPROVED, then human-a CHANGES_REQUESTED')
  when('[t0] git.release --into main --apply')
    then('exit 2; gh pr merge never called')
given('[case6b] pr #42 reviews: human-a DISMISSED (was APPROVED)')
  when('[t0] git.release --into main --apply')
    then('exit 2; gh pr merge never called')
given('[case6c] pr #42 reviews: human-a APPROVED, human-b COMMENTED')
  when('[t0] git.release --into main --apply')
    then('proceeds; COMMENTED is not decisive')
given('[case6d] pr #42 reviews: human-a APPROVED, human-b CHANGES_REQUESTED')
  when('[t0] git.release --into main --apply')
    then('exit 2; gh pr merge never called (veto, F2)')
given('[case6e] pr #42 reviews: human-a COMMENTED only')
  when('[t0] git.release --into main --apply')
    then('exit 2; gh pr merge never called')
```
