# case 2: no charter, uses out — the extant fix stays

feel: sharp · care: critipath (regression guard for C1)

## .narrative

i work in my own tree, no director in sight. i granted my mechanic three commits at dawn, and now
it stops: no commit uses left, ask your human to grant more. that is me, and the line it shows is
the one i know — `git.commit.uses set`. i run it, and my mechanic carries on. it names no director,
and that is right: i have none.

## .bdd sketch

```
given('[case2] a tree no director charter governs, quota spent (uses = 0)')
  when('[t0] git.commit.set --mode apply')
    then('exit 2')
    then('stdout names "no commit uses left"')
    then('stdout names "ask your human to grant more" + `git.commit.uses set --quant N --push allow|block`')
    then('stdout does NOT name git.crew.grant or a director')
    then('snapshot unchanged from main')
  when('[t1] git.branch.rebase begin --mode apply')
    then('exit 1')
    then('stdout names "error: no commit uses left"')
    then('stdout names "ask your human to grant more:" + `$ rhx git.commit.uses set --quant N --push allow`')
    then('stdout does NOT name git.crew.grant or a director')
    then('stdout matches a NEW snapshot')  # no test reaches this guard on main, so no baseline exists
  when('[t2] git.release --mode apply')
    then('exit 2')
    then('stdout names "✋ blocked: no commit uses left"')
    then('stdout names "ask your human to grant more:" + `$ git.commit.uses set --quant N --push allow`')
    then('stdout does NOT name git.crew.grant or a director')
```
