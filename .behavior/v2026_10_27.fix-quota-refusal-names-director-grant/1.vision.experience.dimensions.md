# experience dimensions: a quota refusal names the director grant

## .the dimensions

| # | dimension | values |
|---|---|---|
| D1 | governance — who holds the grant for this tree | `charter` (a director charter governs the tree) · `none` (no charter) · `unreadable` (a charter is present but cannot be read) |
| D2 | refusal — the meter's state | `uses-out` (`uses` = 0, push allowed) · `uses-out+push-blocked` (`uses` = 0 and `push` ≠ allow) · `quota-absent` (no quota file) · `push-blocked` (`uses` > 0, `push` ≠ allow) · `quota-corrupt` (file unreadable) · `global-or-org-block` (commits blocked above the tree) |
| D3 | surface — which skill met the refusal | `git.commit.set` · `git.branch.rebase begin` · `git.release --mode apply` · `git.commit.push` · `git.commit.uses get` (a hint, never a refusal) |
| D4 | mode | `plan` · `apply` |
| D5 | reader — who meets the refusal first | `driver` (a clone) · `human` (in a terminal) · `system` (a cron or ci job) |
| D6 | granter reach — can the reader reach whoever holds the grant? | `reachable` · `unreachable` (the director or human never answers) |
| D7 | concurrency — how many readers share the tree's one quota file | `one` · `many` (two drivers both hit the refusal and both relay) |
| D8 | git past the guards — what the rebase meets once every quota guard passes (`git.branch.rebase begin`) | `clean` · `conflict` · `up-to-date` · `pull-refused` (the pull exits non-zero and leaves no rebase, e.g. a pre-rebase hook) · `no-origin` |
| D9 | pr title content — the commit subject `git.commit.push --output json` carries as `pr_title` | `plain` · `escape-laden` (a backslash or a quote) · `dash-led` (opens with `-`) |

## .orthogonality, per axis

- D1 governance: a fact about the tree, set by whoever charters it; no meter state, surface, mode, or
  reader implies it.
- D2 refusal: a fact about the quota file (two fields + presence + readability) and the blocks above
  it; set by grants, independent of who reads or which skill runs.
- D3 surface: the skill a reader chose. it interacts with D2 by guard order (below) — an
  interaction, not a correlation: every D2 value can meet every D3 value; only the render differs.
- D4 mode: a flag on the call. not every surface takes one: `git.commit.uses get` has no mode
  (n/a), and `git.release` checks the meter only under apply. so D4 applies per surface (walked
  below), not across all of D3.
- D5 reader: any reader can meet any governance. a charter tree is usually driven, but a human may
  run a command there too; a no-charter tree may hold a lone clone.
- D6 reach: whether the granter answers is a fact about people and channels, not the tree. a
  director may be offline; a human may be away. it does not follow from D1.
- D7 concurrency: how many clones work one tree; set by crew boot, independent of the meter.
- D8 git past the guards: a fact about the repo and its remote, met only after every D2 refusal
  passes. so it never co-occurs with a live refusal; it varies on its own, outside the wish's
  quota scope (found at verification, C18–C20).
- D9 pr title content: a fact about the commit subject, independent of the meter and the tree.
  outside the wish's quota scope (found at verification, C21).

D2 spans four facts: the file's presence, its readability, its two fields (`uses`, `push`), and any
block above the tree. compounds of these collapse by guard order, except one:

- a block above the tree + a local state: `git.commit.set` checks global/org first (`:725`,
  `:751`, before `:762`), as do push (`:278`, `:331`) and release (`:272`), so the block renders
  (C8). rebase checks no block, so there the local state renders (its own cell).
- absent + a local state: no file, so no fields to read; renders absent (C3 / C6).
- corrupt + a local state: unreadable, so no fields to read; renders corrupt (C7).
- `uses-out` + `push-blocked`: both fields read, order differs by surface. this is the one compound
  that needs its own value.

so the co-occurrence `uses-out+push-blocked` is its own value: the guards fire in order (push before uses on rebase, `begin.sh:87` before `:98`),
so on rebase the combined state renders the push refusal, not the uses refusal. `git.commit.set`
checks uses first (`:789` before `:800`), and `git.release` checks no push at all, so there the
combined state renders the uses refusal. one meter state, two different refusals by surface.

the director is not a D5 value: it never meets the refusal, it receives the relay. its experience
is C10, downstream of C1.

## .the walked product

### D4 × D3 — which refusals fire in plan mode

plan mode skips only the uses check. the push and quota-absent guards carry no mode test, so they
fire in plan too.

| D3 surface | uses-out in plan | quota-absent in plan | push-blocked in plan |
|---|---|---|---|
| `git.commit.set` | impossible C9 (`:789` tests `MODE != plan`) | itemized C3 / C6 — fires (`:762`, no mode test) | itemized C4 / C6 — fires if `--push` (`:800`, no mode test) |
| `git.branch.rebase begin` | impossible C9 (`:98` tests `MODE == apply`) | itemized C3 / C6 — fires (`:72`) | itemized C4 / C6 / C14 — fires (`:87`) |
| `git.release` | impossible C9 (meter checked only under apply) | impossible (meter unread in plan) | impossible (meter unread in plan) |
| `git.commit.push` | n/a (spends no use) | itemized C3 / C6 — push refusal fires (`:360`) | itemized C4 / C6 — fires (`:360`) |
| `git.commit.uses get` | n/a (no mode) | n/a | n/a |

⇒ the plan-mode refusals that fire are the quota-absent and push ones: the same renders as their
apply cells (C3, C4, C6, C14), in scope by F2's verdict. the uses-out refusal never fires in plan.
