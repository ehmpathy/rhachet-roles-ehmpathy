# case=6 — a hook maintainer re-adds a fork, and the clamp goes red

**actor** hook-maintainer · **feel** sharp · **care** critipath
**cell** `hook-maintainer × trips-gerunds × healthy`
**demoed** `[t0] [t1] [t2] [t3]` + 🔴 `[t4]` (lever B — the gate is reached)

acceptance #6: *"a count that is only measured in a yield drifts back on the next edit to the
file."* this case is the guard against that drift, and the only case whose actor is a future
mechanic rather than a present one.

## .the narrative

six months out, a mechanic adds a term category to the hook. the natural shape is a loop with a
`jq` inside it — the same shape the loop we removed had, because it is the shape bash makes easy.

**without a clamp.** the tests are green. the terms still block, the retries still pass, every
message matches its snapshot. the fork count doubled and not one assertion noticed, because the
count was recorded in a yield file that no test reads. six months after that, the wish is filed
again.

**with a clamp.** the same edit turns one test red:

```
● forbid-terms · fork budget · a clean Write forks under 10 processes

  expect(received).toBeLessThan(expected)
  Expected: < 10
  Received: 23

  execs observed:
    jq   × 14
    grep ×  6
    sed  ×  3
```

the mechanic reads the breakdown, sees `jq × 14` where the budget allows a handful, and either
hoists the call out of the loop or argues the budget up on purpose. **either outcome is fine.**
what the clamp forbids is the third one — a fork storm that returns unnoticed.

**the aha.** the clamp does not name a number as sacred. it makes a change to the number a
**decision** rather than an accident.

## 🔴 .the bar and the ratchet are two different numbers

acceptance #1 sets a **bar**: *under 10 processes*. acceptance #6 demands a **ratchet**: a count
that cannot drift back. **a budget set at the bar does not ratchet.**

if the post-fix count is 4 and the clamp asserts `< 10`, then a regression to 9 — more than
double the cost — passes green. the clamp would guard the wish's upper limit while the wish's
actual win leaked away beneath it.

| number | what it is | who sets it |
|---|---|---|
| **10** | the wish's bar — the pass/fail line acceptance #1 states | the wisher |
| **measured + small headroom** | the clamp's value — the ratchet acceptance #6 needs | the execution stone, from the measurement |

⇒ **the clamp asserts the ratchet, and a second assertion pins the bar.** two `then` blocks, not
one:

```
then('the exec tally is under the wish bar of 10', ...);            // acceptance #1
then('the exec tally is under the ratchet of <measured + 2>', ...); // acceptance #6
```

⚠️ **a deliberate raise of the ratchet is fine** — that is the decision the clamp exists to force.
what it forbids is a raise nobody noticed. so the ratchet lives in a **named constant with a
comment** that states the measured value it came from, never as a bare literal.

## .the instrument

a PATH shim at the head of `PATH`, one small wrapper per external tool, each of which appends its
own name to a tally file and then `exec`s the real binary by absolute path.

| property | why it holds |
|---|---|
| **behavior-neutral** | the shim `exec`s the real tool, so the hook's verdict cannot shift |
| **fork-neutral** | `exec` replaces the process, so the shim adds no fork of its own |
| **deterministic** | it counts discrete events, never elapsed time — no flake under load |
| **portable** | plain bash + a temp dir; no `strace`, no privilege, no `/proc` |
| **precedented** | the repo already does PATH injection (`howto.mock-cli-via-path`) and already spawns hooks from jest (`pretooluse.forbid-tmp-writes.integration.test.ts:24`) |

⚠️ **its bound, stated plainly.** the shim counts external command **execs**. a bare bash subshell
(`$( )` around a pure-bash function) forks without an exec and stays invisible to it. execs are the
dominant cost — each pays a fork, an exec, a binary load, and a dynamic link — and the wish's own
tally is in `jq` and `echo | tr` calls, which are all execs. the residue is named here rather than
papered over. see the yield's fulcrum on the instrument.

## .the bdd sketch

```
given('[case6] a fork budget clamps the hook', () => {

  when('[t0] the hook runs against clean content, under the shim', () => {
    then('the exec tally is under 10', ...);              // acceptance #1
    then('the tally breakdown is snapshotted, per tool', ...);  // shows WHERE the forks go
  });

  when('[t1] the hook runs against content that trips a term', () => {
    then('the exec tally is under its own stated budget', ...);
  });

  when('[t2] the fix is deliberately reverted to the per-term jq loop', () => {
    then('the clean-content clamp goes RED', ...);        // 🔴 acceptance #5, #6 — it bites
  });

  when('[t3] the shim is in place but the hook is unmodified', () => {
    then('the verdict equals the verdict without the shim', ...);  // the shim is neutral
  });

  when('[t4] settings.json is read and each hook command is resolved', () => {
    then('every command path exists on disk', ...);           // 🔴 lever B — the gate is REACHED
    then('every path is executable, and runs under bash', ...);
    then('a deliberately broken path turns this RED', ...);   // the clamp bites here too
  });
});
```

## 🔴 .`[t4]` — lever B's hazard, and the only failure here that is SILENT

added when the wisher took **F7** (drop the `rhachet run --init` wrapper). every other failure in
this case is loud: a fork count rises, a test goes red, a mechanic reads a breakdown. `[t4]` guards
a failure that makes **no sound at all.**

| | today, through the wrapper | after lever B |
|---|---|---|
| a bad hook reference | `rhachet run --init` **fails loud** — *"no init X found; available inits: …"* | 🔴 `bash <bad path>` exits non-zero with a bare shell error — and claude code's hook contract reads a **non-2** exit as *"not blocked"* |
| what a human sees | an error naming the fix | ⚠️ **the write simply lands** |

⇒ **a gate that is never invoked is a gate that never gates.** and the wrapper's dynamic resolution
was the thing that made a wrong reference loud — so lever B removes not only the cost but also the
safety net that cost bought.

🔴 **and no extant test would notice.** `blocklist.test.sh:71` invokes `bash "$HOOK"` by path
directly; the jest harnesses spawn the hook the same way. **every one of them passes whether or not
`settings.json` points at anything real.** the config is the one artifact under test that no test
covers.

⚠️ **the blast radius is seven hooks × every consumer repo, from one bad string** in a generated
file. that is why `[t4]` reads `settings.json` itself rather than trusting the path it was handed —
it is the only assertion in this case whose subject is the **config**, never the hook.

⇒ the fork clamp answers *"is the gate cheap?"*. `[t4]` answers the question that has to come
first: **"is the gate there at all?"**

## 🔴 .`[t2]` is the whole case

per `rule.require.clamp-edge-cases`, a clamp never seen to fail is a guess. the execution stone
owes the three-step proof: land the fix and see green · revert **only** the fix and see red ·
restore and see green again. a budget that passes under the un-fixed hook guards no defect at all.
