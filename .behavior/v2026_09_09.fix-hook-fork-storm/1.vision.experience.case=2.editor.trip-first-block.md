# case=2 — editor trips a term, first attempt

**actor** editor · **feel** sharp · **care** critipath
**cell** `editor × {trips-gerunds, trips-blocklist, trips-both} × healthy`, nudge `first`

the sharp path. the gate must still refuse, still name the term, still teach the alternative, and
still leave a nudge record of the exact extant shape.

> ⚠️ this file names blocked vocabulary on purpose — a demo of a refusal cannot omit the word it
> refuses. it was itself blocked on first write and landed on retry, which is the mechanism this
> case documents.

## .the narrative

kai's clone writes `const existingUser = getUser();`.

**today.** two refusals arrive. the gerunds hook detects `existing` and offers `found, prior,
current`. the blocklist hook detects `existing` and offers `extant, current, found, prior,
present`, with the rationale from `terms.blocklist.jsonc:27`. both exit 2. both stamp a record
under a sha256 of the file path. the clone reads the alternatives, picks `userFound`, moves on.
the refusal cost roughly a second of wall clock, and the clone paid for it twice — once per hook,
each with its own runner boot.

**after.** the same two refusals arrive, with the same two term names, the same two alternative
lists, the same rationale line. what changed is beneath: the parse of the word list happened
**because** a cheap pre-scan said a term was plausible, rather than ahead of that knowledge — and
the per-term triple `jq` loop at `blocklist.sh:116-119` collapsed to one read.

**the aha.** the refusal reads identically. that is the acceptance criterion, not a side effect —
a human who diffs the two block messages must find no difference in substance.

## .how it fails safe

| property | how |
|---|---|
| **fast** | exit 2 ahead of any file write; the tool call never runs |
| **loud** | stderr, not stdout; the clone cannot miss it |
| **teaches the fix** | per-term `why` + `alt`, straight from the list, plus the retry escape hatch |

## 🔴 .the trap: two nudge namespaces must stay two

today the two hooks stamp **two separate files** — `terms.gerunds.nudges.local.json` and
`terms.blocklist.nudges.local.json` (`gerunds.sh:126`, `blocklist.sh:97`). the key in each is
`sha256(file_path)`, so the two clocks are independent.

⇒ **if a merge folds them into one record, the override leaks.** a clone blocked on a gerund would
then retry and find its blocklist clock already stamped, and a forbidden term would land with no
refusal at all. one record cannot carry two independent overrides for one path.

⇒ so a merged hook keeps **two clocks**, whether or not it keeps two files. this constraint is a
direct output of the walk, and it is the first item the merge fulcrum must answer.
