# case=4 — a maintainer lands a new term, and the next edit honors it

**actor** list-maintainer · **feel** sharp · **care** critipath
**cell** `list-maintainer × trips-blocklist × healthy`
**boundary density** rank 2 (B1 B2 B3 B4 = 4) — policy, cost, and freshness all meet in one act

the cell the wish did not name, and the one any optimization can silently break.

## 🔴 .what this case actually requires — freshness, never a cache

> **the requirement is: a list change binds on the very next edit.**
> **a cache is one candidate mechanism for the cost problem, and it is probably a poor one.**

the first draft of this case read as though "the cache must be correct" were the requirement. it
is not, and the conflation matters:

| | |
|---|---|
| **the invariant** | a term added binds at once; a term retired stops to bind at once |
| **who set it** | nobody — it is a property the extant hooks hold *by accident*, because their wasteful unconditional read makes freshness free |
| **why it survives anyway** | acceptance #2 (*"every term either hook blocks today, it still blocks"*) makes it a requirement whether or not anyone wrote it down |
| **the cache** | a **means** the wish never asked for, invented at the vision, and graded at 65% in fulcrum F3 — where it may well collapse |

⇒ **this case earns its center even if the cache is dropped**, because the invariant outlives the
mechanism. any future optimization — a cache, a pre-scan over a precomputed index, a merged
process that hoists a read — can break it the same way. the case clamps the *property*, and the
clamp does not care which mechanism threatened it.

⚠️ **and if F3 collapses, this case gets easier, never moot.** with no cache, `[t1]`/`[t2]` pass by
construction — which is precisely the argument for **no cache** as the default.

## .the narrative

ana maintains the vocabulary. a review turned up a term worth a ban, so she opens
`terms.blocklist.jsonc` and adds an entry with its `why` and its `alt` list.

**her write is refused.** of course it is — the file she edits **is** the list of forbidden words,
so her addition contains the word she just forbade. she reads the refusal, agrees with it, and
retries. the entry lands. this is extant behavior and it must survive the change intact.

**then the part that matters.** ana switches to a source file and writes the new term into it,
to check the gate took. today the answer is guaranteed: both hooks re-read and re-parse the list
from disk on **every** invocation (`blocklist.sh:72`, `gerunds.sh:68-70`). freshness is free
because the wasteful read is unconditional.

**that unconditional read is exactly what the wish asks us to cut.** so the cheap shape and the
correct shape pull against each other, and this cell is where they collide.

## 🔴 .what SHIPPED — no cache, so the paragraphs below describe a design that was REJECTED

> ⚠️ **the two paragraphs directly below narrate a witness-keyed cache as though it shipped. it
> did NOT.** F3 leans reject, and the execution built no cache: **both hooks re-read and re-parse
> their list on every invocation, exactly as they do today.** raised by peers i010-r008 and
> i010-r010.
>
> they are kept rather than deleted because the hazard they describe is the reason the cache was
> refused, and a reader who meets only the verdict cannot reconstruct the argument. ⇒ read them as
> **the case against the mechanism**, never as a description of the hook.
>
> ⇒ the shipped freshness guarantee is the one in the paragraph ABOVE: unconditional re-read. so
> `[t1]`, `[t2]`, `[t3]`, `[t4]`, and `[t5]` all hold **by construction** — which is precisely the
> argument that retired the cache.

**after (the REJECTED shape).** ana's next edit is refused by the new term, same as today. the
hook did not re-parse the list to know that — it compared the list's mtime and size against what
it had cached, saw a change, and re-parsed. one `stat` costs far less than a `sed | jq`, and it is
exact enough: a list edit changes the mtime.

**the aha (of the REJECTED shape).** the fix is not "cache the list". it is "cache the list, keyed
on a cheap witness of the list's identity". drop the witness and you have shipped a silent policy
revert dressed as a speed win.

🔴 **and the aha that outlived it:** the wish asked us to cut the unconditional read, and that read
turned out to BE the whole freshness guarantee. ⇒ **the four free levers met acceptance #1 and left
it in place**, so the mechanism whose correctness this case was written to police was never built.
**the cheapest fix for a hazard is to leave unbuilt the mechanism that carries it.**

## 🔴 .the defect this case exists to forbid

> a stale cache **reverts a policy change**, with no error, no log line, and no failed test.

it breaks acceptance #2 — *"every term either hook blocks today, it still blocks"* — and it breaks
it **later**, on a machine other than the one the change was tested on. it is the worst failure
shape available to this wish: silent, delayed, and caused by the fix.

## .the bdd sketch

```
given('[case4] a maintainer changes a word list', () => {

  when('[t0] the maintainer writes the new term into terms.blocklist.jsonc', () => {
    then('the write is refused — the list holds the words it forbids', ...);
    then('the retry lands', ...);                        // extant behavior, preserved
  });

  when('[t1] an editor then writes the NEW term into a source file', () => {
    then('the hook exits 2 — the new term binds at once', ...);   // 🔴 acceptance #2
    then('stderr names the new term, with ITS why and alt', ...);
  });

  when('[t2] an editor writes a term the maintainer REMOVED', () => {
    then('the hook exits 0 — the retirement binds at once', ...); // the inverse
  });

  // 🔴 [t3]-[t5] were written to police a CACHE. no cache shipped (F3), so each
  //    holds by construction — the hook re-reads its list every time. they are
  //    kept as the contract any FUTURE cache must satisfy (peer i010-r008).
  when('[t3] the list is untouched across two edits', () => {
    then('the second edit forks no more than the first', ...);
    // ⚠️ the sibling assertion here read 'the second edit re-parses no list' —
    //    a claim that is FALSE of the shipped hook, which re-parses both times.
    //    struck rather than reworded: it asserted the cache's benefit, and the
    //    cache is what was refused.
  });

  when('[t4] the list is rewritten with identical bytes', () => {
    then('the verdict is unchanged', ...);   // trivially true with no cache
  });

  when('[t5] the list is restored with an OLDER mtime — cp -p, rsync -a, tar -xp', () => {
    then('the restored list governs — its terms bind', ...);  // 🔴 the hazard a cache would have carried
  });

  when('[t6] the maintainer\'s own edit trips the GERUNDS gate', () => {
    then('the write is refused, then lands on retry — same as any editor', ...);
    then('the nudge key is the file path, never the author', ...);   // why stage 2 folds
  });
});
```

## .`[t6]` — the maintainer is not a special actor, and that is the point

added at peer review r2, which noted this row was itemized with no render. it is also the demo that
**grounds the stage-2 fold**: the nudge key is `sha256(file_path)` (`blocklist.sh:97`,
`gerunds.sh:126`) and no branch in either hook reads who wrote the content. ⇒ the maintainer's
refuse-then-retry is bit-identical to an editor's, which is why the `nudge × load` box is walked
once rather than three times.

## 🔴 .`[t5]` is the hazard, and it was absent until review r5

the risk was written as *"does mtime change on every meaningful list edit?"* — which points at edits
that **fail to advance** the clock. that read let a wrong example stand in three artifacts:

| the named worry | verdict |
|---|---|
| a **git checkout** could defeat the witness | 🔴 **false, and backwards.** git stores no mtimes — a checkout writes the file fresh, so its mtime advances to *now*. the cache correctly invalidates. checkout is the **safe** direction |
| a **same-second rewrite** of equal size | ✅ real, and narrow |
| 🔴 **an mtime that moves BACKWARDS** — `cp -p`, `rsync -a`, `tar -xp`, `touch -r` | ✅ **the real hazard, and it was never named.** the restored list is *older* than the cache, so the cache reads as fresh forever — a stale policy that no later edit clears |

⇒ **the two failure shapes are not the same size.** a same-second collision heals itself: the next
edit advances the clock and the cache recovers. a backwards mtime is **permanent** — no later edit
restores truth; only a delete of the cache file does. the sharper witness is not *"did it change?"*
but **"is the cache strictly newer than the list?"**, which `[[ list -nt cache ]]` asks natively and
which fails **safe** on a tie.

## ⚠️ .why `[t4]` is the safe direction

a cache that invalidates **too often** costs a parse. a cache that invalidates **too rarely**
costs the policy. the two errors are not symmetric, so the witness must err toward re-parse.

⇒ if no witness is cheap enough to be exact, **carry no cache at all** and take the smaller win
from the other levers. a correct hook that saves eight forks beats a fast hook that lies.

## .how it fails safe

this is a **sharp critipath**, so it owes a fail-safe. its shape is unusual, and worth a plain
statement: **the fail-safe here is prevention, not a good error message.**

a stale cache produces *no* symptom — no exception, no exit code, no log line. there is not one
thing for a message to say, and not one thing for a human to read. so the ladder of
`rule.prefer.prevent-over-correct` must be climbed at its top rung:

| rung | how this case takes it |
|---|---|
| **1 · make it impossible** | ✅ the witness is checked on **every** invocation, never on a timer. there is no interval in which a stale answer can be served — so no ttl, ever |
| **2 · make it hard** | ✅ the witness errs toward re-parse: a false invalidation costs a parse, and is safe (`[t4]`) |
| **3 · catch it early** | ⚠️ **unavailable** — a stale cache has no boundary at which to fail loud |
| **4 · report it well** | ⚠️ **unavailable** — a silent wrong answer has no report |

⇒ because rungs 3 and 4 are genuinely unreachable, **rungs 1 and 2 carry the whole safety
obligation**, and the clamp (`[t1]`, `[t2]`) is what keeps them honest over time.

🔴 **the declared fallback is itself the fail-safe.** if no witness turns out cheap enough to be
exact (see fulcrum F3), the instruction is **carry no cache** — which restores freshness by
construction. the design's safe state is its *simplest* state, which is the pit of success:
the easy path and the correct path are the same path.
