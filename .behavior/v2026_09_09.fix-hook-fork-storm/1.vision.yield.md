# 1.vision.yield — cut the fork storm from the two forbid-terms hooks

## .the outcome world

### a day in the life

kai drives a mechanic clone on a grove of ~17 peers over 4 cores. the clone edits files all day —
that is the job. every Write and every Edit passes a gate of seven PreToolUse hooks, two of which
decide whether a word is allowed.

**after this wish, kai stops to notice those two.** most edits trip no term, and a gate with no
verdict to render should cost close to zero. it now does. the edits that *do* trip still stop,
still name the term, still teach the alternative, still permit the deliberate retry — with the
same words in the same shape. what changed is the price of the answer, never the answer.

### before / after

| | today | after |
|---|---|---|
| a clean edit — **gerunds** | full allowlist read + parse, then "none matched" | ✅ a list-free pre-scan (`grep -qE '[a-zA-Z]+ing'`) exits **without any list read** |
| a clean edit — **blocklist** | `27` `jq` for detail it then discards | 🔴 **no pre-scan is possible** — you cannot scan for unknown terms. the win is a *collapsed* parse: one `jq`, one alternation `grep`, detail read only for terms that matched |
| a tripped edit | 3 `jq` per term, in a loop over every term | one read of the list, one walk |
| a retry inside the window | full detect, then the clock overrides it all | 🔴 **UNCHANGED — the early clock read did NOT ship.** it would cost the CLEAN path a `sha256` + a nudge read on every write, which breaches acceptance #1. the clean path is nearly every path ⇒ a net loss. `case=3` and the 5.1 yield carry the arithmetic (peer i005-r008) |
| the word list | re-read and re-parsed on every invocation | ⚠️ **unchanged, most likely** — a cache is the one lever that leans **reject** (F3); the four free levers clear acceptance #1 alone |
| the fork count | recorded in no test; free to drift | clamped in ci; a regression goes red |
| under load | cost grows with the runqueue | the removed cost was the load-sensitive cost |
| 🔴 **the two hooks** | two processes, two runner boots | ✅ **still two processes, ZERO runner boots.** the merge was weighed, recommended, and **rejected** (F1); the wrapper-drop (F7) captures the boot win without it |
| 🔴 **how a hook is invoked** | `rhachet run --init …` → readlink loop → bun boot → `bash -c` → the hook | ✅ **`bash <path>`, direct.** ruled 2026-09-10 — see `.the three levers` |
| 🔴 **stdout, per hook, per edit** | 3 lines (`💪 init role …` + two blanks), emitted **even on a pass** | ✅ **zero.** ~21 lines per edit the model no longer reads |

### the aha

> **the hooks were not slow at arithmetic. they were blocked on forks — and they paid the fork
> bill ahead of the moment they learned there was no bill to pay.**

`pcpu 8%` reads backwards until you see it: 8% cputime over elapsed means ~92% of the wall clock
sat **blocked**, not busy. so the fix is not a faster algorithm. it is **fewer processes**, and
the order they run in.

🔴 **and the second aha, found later and larger:** the biggest fork bill was never inside the
hooks. it belonged to the **wrapper that reaches them** — ~10 forks plus a bun boot, to answer a
question whose answer is a static path.

## 🔴 .the three levers

three independent ways to make a hook cheaper. they were conflated once, at cost, so they are
parted here and each is verdicted.

| | lever | what it changes | scope | verdict |
|---|---|---|---|---|
| **A** | **leaf-trim** | fewer execs *inside* each hook | our 2 hooks | ✅ **take** — this wish's original scope |
| **B** | **wrapper-drop** | fewer processes *ahead of* each hook | **all 7 hooks** | ✅ **take** — ruled 2026-09-10 (F7) |
| **C** | **compile to a binary** | each process starts faster | per hook | 🔴 **reject** — net-negative once A lands (Q12) |

### lever A — the leaf-trim

the two hooks get **different** levers, and the asymmetry is structural:

| hook | today | after |
|---|---|---|
| **gerunds** | reads + parses the allowlist on every invocation, then scans | a list-free pre-scan `grep -qE '[a-zA-Z]+ing'` runs first — no `-ing` word ⇒ **exit 0, list never read** |
| **blocklist** | `27 jq + 9 grep` — three `jq` per term for `why`/`alt`, read ahead of any match | **one** `jq` emits one alternation · **one** `grep -iqE "\b(a\|b\|c…)\b"` · detail read **only** for terms that matched |

⚠️ **no pre-scan is possible for the blocklist** — you cannot scan for terms you have not read. so
its win is a *collapsed* parse rather than a skipped one, and that is a property of the problem, not
a shortfall in the design.

### 🔴 lever B — the wrapper-drop

```jsonc
// today
"command": "./node_modules/.bin/rhachet run --repo ehmpathy --role mechanic --init claude.hooks/pretooluse.forbid-terms.gerunds"

// after
"command": "bash .agent/repo=ehmpathy/role=mechanic/inits/claude.hooks/pretooluse.forbid-terms.gerunds.sh"
```

**zero code change.** `gerunds.sh:62` resolves `SCRIPT_DIR` from `${BASH_SOURCE[0]}`, so each hook
finds its own `.jsonc` from wherever it is invoked. the ported tree already holds every hook **and**
its data files — verified.

### lever C — the binary, and why it loses

published startup figures — **not measured on this box**:

| | startup |
|---|---|
| bash, non-interactive | ~3ms |
| bun compiled binary | ~10ms |
| node | ~35ms |

⇒ **a compiled binary starts slower than bash.** what it buys is zero execs inside — which is
exactly what lever A already delivers. so you would trade ~36ms of execs for ~7ms of extra boot
**that lever A already paid down**:

| blocklist variant | boot | execs | total |
|---|---|---|---|
| today | bash ~3ms | 27 `jq` + 9 `grep` ≈ 36ms | **~39ms** |
| after lever A | bash ~3ms | ~3 ≈ 3ms | **~6ms** |
| compiled binary | bun ~10ms | 0 | **~10ms** |

⚠️ **and levers B and C were conflated once, at cost.** lever C never required a merge — two
separate binaries would have been fine. they would simply have been **slower than trimmed bash**.
⇒ the conflation hid the real objection behind a false one, which is the more expensive kind of
error: a reader who refutes the false one concludes the lever is sound.

### the arithmetic, per edit

| lever | saves | scope |
|---|---|---|
| **A** | ~48ms | our 2 hooks |
| 🔴 **B** | ~175ms | **all 7 hooks** that match `Write\|Edit` |
| C | −7ms | (negative) |

#### ✅ .execution widened B's scope from 7 to 14 — corrected 2026-09-10

every "seven" in this yield counts the hooks that match `Write|Edit`, and each is right in that
frame. **the role registers 14 init hooks in total**, and every one paid the same wrapper:

| where | hooks |
|---|---|
| `onBoot` | `sessionstart.notify-permissions`, `postcompact.trust-but-verify` |
| `onTool`, matches `Write\|Edit` | the 7 counted throughout this yield |
| `onTool`, other matchers | `Bash` ×4, `Read`, `EnterPlanMode`, `WebFetch` |

⇒ all 14 swapped. **a Bash call paid the wrapper 4 times over**, which no read of this yield would
have predicted — it counts the `Write|Edit` gate, because that is what the wish measured.

⚠️ **two commands were deliberately left wrapped**: `rhachet roles boot --repo .this --role any`
and `… --repo ehmpathy --role mechanic`. those are not init hooks; they run real TS through the
runner, which is what the runner exists for. the unit clamp encodes both shapes so the line
between them cannot erode — `asWrappedCommands` keys on `rhachet run` **together with** `--init`,
and a boot command carries no `--init`.

🔴 **this said "three" until verification r4 counted it.** `getMechanicRole.ts` holds 14
`asHookCommand` calls and exactly **2** `rhachet roles boot` literals (`:74-75`, `:79-80`), and
the snapshot diff is 14 lines changed with 2 left alone. neither the role, the snapshot, nor
`settings.json` yields three under any count. the **14** beside it is correct and was verified in
the same pass — ⇒ a wrong number sat one line below a right one, in the same paragraph, for three
stones.

⇒ **B is the biggest lever by ~3.6×, and it is the one that needs no code change at all.**

⚠️ **every number here is estimated, never measured.** a `hyperfine` on one invocation settles all
of it, and this round has already caught two inherited-arithmetic errors (see `.the magnitude claim`
below). the estimates set the **order**; they do not stand as the yield's evidence.

## 🔴 .the larger cost the wish's own data holds, one line above its target

the wish's roll-up leads with `71.4% cpu · n=8 run.bun.rhachet-run.bc`. that is not a peer of the
two hook lines — it is their **parent**.

`.claude/settings.json:140,146` register both hooks as
`./node_modules/.bin/rhachet run --repo ehmpathy --role mechanic --init claude.hooks/…`, and
rhachet's `bin` is a bun-compiled binary (`rhachet/package.json:50-53,75`). so the chain per hook
is `sh -c` → **a bun runner boot** → `bash -c` → `bash hook.sh` → the leaf forks the wish counted.

⇒ **the two hooks pay two runner boots per edit**, and five more hooks pay five more. the wish's
boundary forbids a rewrite into node *"because node would pay an interpreter boot per invocation"*
— and that boot is already paid, **seven times**, by the layer beneath the hooks.

### ✅ this is now lever B, ruled 2026-09-10

it read *"context, never plan"* until the wisher ruled:

> **rhachet installs the hooks exactly as they are written in the role's hook command, so it is
> totally fine to churn that and drop the wrapper.**

⇒ that answers the one objection the dream had raised against it — *"the `--init` indirection is
what resolves an init through the symlinked `.agent/` tree; a direct path would harden every
consumer repo against a layout that is meant to move."* **the layout does not move independently:
the command string and the ported path are generated from the same role definition, so they move
together.** the objection was real, and it was answered by a fact only the wisher held.

🔴 **and F1 stays rejected — now doubly so.** the merge's headline argument was *"it removes one
runner boot per Write/Edit."* the wrapper-drop removes **all seven**, at lower churn and with no
hook merged. ⇒ **the merge was rejected on churn, and its benefit has since been captured by a
cheaper lever.** a rejected design whose sole advantage is later delivered elsewhere is the
cleanest kind of rejection there is.

✅ **read from source, not inferred** — the full chain is traced below under
`.the wrapper chain, now read in full`. what remains unmeasured is the boot's *duration*, never its
existence. that was **Q1**, and it is settled.

### 🔴 .what the wrapper does that a direct `bash` does not — read, and it is not zero

`executeInit.ts:64-69` is the whole of it:

```ts
spawnSync(command, [], {
  cwd: process.cwd(),
  stdio: [process.stdin, process.stdout, 'pipe'],   // ← stderr is BUFFERED, not inherited
  shell: '/bin/bash',                                // ← an EXTRA bash -c layer
  encoding: 'utf-8',
});
```

| the wrapper | on a drop |
|---|---|
| **no `env:` option** ⇒ the child inherits `process.env` | ✅ **no delta** — a direct `bash` inherits the identical env |
| `cwd: process.cwd()` | ✅ **no delta** — claude code already invokes hooks from the project dir |
| `shell: '/bin/bash'` with a string command ⇒ **an extra `bash -c`** | ✅ **one fork removed**, uncounted until now |
| `invokeRun.ts:43-47` logs `💪 init role …` **plus two blank lines**, on **every** invocation | 🔴 **3 stdout lines × 7 hooks = ~21 lines per edit, gone.** a token win nobody had counted |
| stderr buffered, then re-framed by `InitExecutionError` → the `💪 init role … └─ ✋ blocked by constraints` header | ⚠️ **a visible delta.** see below |

#### ⚠️ the one real behavior delta, and it touches acceptance #4

today a block message a human reads is composed of **two** parts:

```
💪 init role repo=ehmpathy/role=mechanic/init=claude.hooks/pretooluse.forbid-terms.gerunds   ← the WRAPPER
   └─ ✋ blocked by constraints                                                                ← the WRAPPER

🛑 BLOCKED: gerund(s) detected in file write                                                  ← the HOOK
detected gerunds:  ⛔ <term> → consider: <alt>                                                ← the HOOK
```

drop the wrapper and the first two lines vanish. **acceptance #4 says the messages must be
"unchanged in substance: the same detected terms, the same per-term alternatives, the same
rationale line"** — and every one of those is the hook's own output, untouched. ⇒ **the substance
holds; the frame changes.**

⚠️ **it must be declared rather than assumed benign**, for two reasons: it changes what a human
sees, and it is the exact class of delta the wish calls *"a behavior change smuggled into a cost
change."* raised as **Q13**. ⇒ if the frame turns out to be load-bearing, the hook can print its
own — a cost of one `echo`.

✅ **and the two `.test.sh` harnesses are unaffected** — `blocklist.test.sh:71` invokes
`bash "$HOOK"` **directly** today, so they already exercise the wrapperless path. the extant
baseline for acceptance #2 and #5 needs no change at all.

## 🔴 .the magnitude claim we inherited, and should not have repeated

the wish reads `8.0% + 7.0%` as *"15% of a 4-core box"*. **`ps` reports `%CPU` normalized to one
core**, so that sum is `15%` of **one** core — roughly **3.75%** of a four-core box. `n=1` for each
hook corroborates: across ~17 clones, one instance of each was alive at sample time. these are
transient processes, not a sustained draw.

⇒ **the wish's premise survives; its headline number probably does not.** the fork storm is real
and derivable from source (27 `jq` calls per invocation). the load-sensitive **latency** cost is
real. what is over-stated is the box-level cpu reclaim.

⚠️ **so the benefit that leads is latency per edit, never cpu reclaimed.** an operator who expects
15% of a box back will measure a small delta and conclude the work failed. raised as **Q8**.

### 🔴 four constraints the walk produced that the wish did not name

1. **two nudge clocks must stay two.** one merged record would leak a gerund override into a
   blocklist permit, so a forbidden term would land unrefused (`case=2`).
2. **two config paths must stay two.** an absent blocklist makes its hook *inert*; an absent
   allowlist makes its hook *stricter*. one shared "config absent" guard would retire the gerund
   gate (`case=5`).
3. **a cache needs a cheap witness of list identity.** freshness is free today only because the
   wasteful read is unconditional — the very read the wish cuts (`case=4`).
4. 🔴 **the collapse must part grep's exit 1 from its exit 2.** nine per-term greps fold into one
   alternation, so a term that does not compile stops to be a hole of size one and becomes a hole
   of size nine — every term permits, silently (`case=5` `[t5]`, **Q11**).

⚠️ **constraints 1–3 were written to bound the merge; constraint 4 bounds the COLLAPSE.** ⇒ the
first three came from the grid as drawn; the fourth came from an axis value the grid lacked until
review r5, and it is the only one of the four that describes a defect **this fix would author**
rather than one it must preserve.

### 🔴 the merge was rejected, and ALL FOUR still bind

the obvious read of the verdict is that 1–3 retire with the merge. **they do not**, and this is the
sharpest trap the ruling leaves behind:

| constraint | why it survives a rejection |
|---|---|
| two nudge clocks | a shared record was never merge-specific — any refactor that unifies the clock read breaks it |
| two config paths | 🔴 **the live risk.** the blocklist's collapse touches the term-read path. a trim that folds both hooks' list reads into one shared parse breaks this **with no merge at all** |
| both refusals reported | acceptance #4 binds every shape of this fix |
| part exit 1 from exit 2 | 🔴 **now the most load-bearing of the four** — it governs the collapse, which is the whole plan |

⇒ **a constraint discovered while one design was on the table does not belong to that design.** all
four were derived from the *behavior*, and the behavior did not change when the plan did.

## 🔴 .the merge — weighed, recommended, and REJECTED by the council (2026-09-10)

the wish asked us to weigh it and say so either way. **we recommended it. the wisher ruled against
it.** the plan is **lever A + lever B** — the leaf-trim, plus the wrapper-drop that captures the
merge's own headline benefit without merging a thing.

⇒ the record below is kept as the wisher asked for it — *"say why either way"* — and it is a
recommendation that lost, not the plan.

### 🔴 why the rejection reads BETTER an hour later, not worse

the merge was rejected for `settings.json` churn. lever B then churned `settings.json` **harder** —
all seven command strings rather than two. that looks like an inconsistency and is not:

| | the merge (F1) | the wrapper-drop (F7) |
|---|---|---|
| what churns | two commands **plus** a matcher restructure **plus** `getMechanicRole.ts` **plus** a snapshot | seven command **strings**. that is all |
| what it costs behavior | two nudge clocks, two config paths, two message sets — each a silent-failure seam to build | ✅ **zero code change.** the hooks are byte-identical |
| what it buys | **1 of 7** runner boots | 🔴 **7 of 7** |
| reversibility | dirty — consumers harden against one merged hook | clean — a string swap, revertible in one commit |

⇒ **the merge paid the most and bought the least.** its rejection was never a verdict against the
runner-boot cost; it was a verdict against the *instrument*, and a better instrument arrived.

⚠️ **this is the reversal to watch for in review.** a reader who finds *"churn rejected"* beside
*"churn accepted"* has found a real tension, and the table above is the whole answer to it: the two
churns differ in kind, not merely in size.

### what the leaf-trim is, now that it is the whole wish

| hook | today | after |
|---|---|---|
| **blocklist** | `27 jq + 9 grep` — three `jq` per term for `why`/`alt` detail, read ahead of any match | **one** `jq` emits one alternation · **one** `grep -iqE "\b(a\|b\|c…)\b"` · detail read only for terms that matched |
| **gerunds** | the allowlist is read on every invocation | a list-free pre-scan `grep -qE '[a-zA-Z]+ing'` first — no `-ing` word ⇒ **exit 0 with the list never read** |

⚠️ **the two hooks get two different levers, and that asymmetry is structural** — you cannot
pre-scan for terms you have not read, so the blocklist's win is a *collapsed* parse rather than a
skipped one.

### 🔴 the three seams survive the rejection, and they are the trap

they read as merge-only constraints. they are not:

> **a collapse that folds both hooks' term reads into one shared parse breaks seam 2 with no merge
> at all.**

⇒ two nudge clocks stay two · two config paths stay two · two message sets stay two. **the leaf-trim
must preserve every seam the merge would have had to build.**

### why it was recommended, for the record

- it removes one runner boot per Write/Edit — the single largest per-invocation cost, and one no
  leaf-fork trim can reach
- it shares the fixed bash cost: one `cat` of stdin, one `jq` over the payload, one `find_claude_dir`,
  one `date`, one stale sweep — today every one of those is paid twice
- the two hooks already share ~60 lines of near-identical preamble
  (`gerunds.sh:22-59` vs `blocklist.sh:23-60`), so the merge also retires a duplicate

**why it is the largest blast radius**

- `getMechanicRole.ts:78,84` registers the two inits; `__snapshots__/getMechanicRole.test.ts.snap:70,78`
  pins both commands verbatim — both must change together
- `.claude/settings.json` is regenerated from that role, and **every consumer repo regenerates too**
- ⚠️ `getRoleRegistry.test.ts:8` names `forbid-terms.gerunds` in a `.why` comment **only** — it
  asserts against `forbid-cross-repo-access` alone (`:24,26,45,62`). so it is a stale-comment fix,
  never a broken test. graded down from the first read
- the three seams above are each a silent-failure mode if the merge is done carelessly

### 🔴 why the verdict is coherent — and why our own evidence could not settle it

F1 named the one condition that would void the merge: *"if Q1 measures the runner boot as cheap,
the merge's headline reason evaporates."*

⚠️ **Q1 was never measured — it was READ**, and the read cut the other way. the wrapper is ~10 forks
plus a bun boot, ×7 per edit. **the merge's case grew stronger, and it was still rejected.**

⇒ that is not a contradiction. it means the question that decides was always **Q2** — *is the
cross-repo churn acceptable?* — and no read of **this** repo discloses another repo's appetite for
churn. **our evidence could only ever strengthen one side of a two-sided ledger.**

### 🔴 and then the ledger was settled from the OTHER side

an hour later the wisher accepted **seven** command-string swaps (F7) — strictly more `settings.json`
churn than the merge asked for.

⇒ **the merge did not lose to churn. it lost to its ratio.** it paid a matcher restructure, a code
merge, a pinned snapshot, and three silent-failure seams, and bought **1 of 7** runner boots. lever
B pays seven strings, changes no code, and buys **7 of 7**.

✅ **so the loss costs the wish naught.** the merge's entire headline benefit was delivered by a
cheaper lever, every acceptance line is met, and the route's rework grade stays **clean** — no dirty
fulcrum is left anywhere in it.

⚠️ **the lesson is about the evidence, never the verdict.** we spent six review rounds to strengthen
the merge's case, on a ledger whose deciding column we could not read. **the read that would have
mattered was of `executeInit.ts`** — 79 lines, in a repo we could reach the whole time. it would
have surfaced lever B on day one and retired the merge question outright.

⇒ the wrapper-chain evidence did **not** merely survive the rejection — it became the plan. its
dream is `v2026_09_09.fix.seven-runner-boots-per-write-edit`, now marked **TAKEN**.

## .mental model

**how a human would describe it to a friend**

> "we had two doormen. each one walked back to the office, pulled the whole guest list out of the
> cabinet, read it top to bottom, and *then* looked at your face. now they look at your face
> first, and only walk to the cabinet if you might be on the list — and when they do go, they take
> the whole list in one trip instead of one name at a time.
>
> **and it turned out the doormen weren't even the slow part.** to reach each one you first had to
> ring a receptionist, who looked up which door the doorman was standing at, walked over, and
> tapped him on the shoulder. seven doors, seven receptionists, every single time. we found out the
> door numbers never change — so now we just knock."

⚠️ **this read *"also, we merged the two doormen into one"* until the council rejected the merge.**
⇒ a metaphor is a claim about the design, so it goes stale with the design — and it is the last
place anyone re-reads. **the two doormen stay two; the receptionists are gone.**

**the analogy that fits best**

a toll booth on a bridge you cross a hundred times a day. the toll is small. the **queue** is not,
and the queue is longest exactly when the bridge is busiest.

**terms: theirs vs ours**

| they say | we say |
|---|---|
| "the hook is slow" | fork latency under runqueue contention |
| "it lags when the grove is busy" | the cost is load-sensitive by construction |
| "just make it faster" | fewer external command execs, in a cheaper order |
| "cache the list" | cache the list, keyed on a cheap witness of its identity |

### 🔴 how lever B re-reads acceptance #1

*"under 10 processes total, per hook"* was written against a chain that boots a runner. lever B

| | what "per hook" counted | the budget |
|---|---|---|
| **before lever B** | wrapper (~10 forks + a bun boot) **+** the hook's own leaf forks | the bar is unreachable at the chain level, and only ever plausible if you count the leaf alone |

### pros

- the common case gets cheap, and the common case is nearly all cases
- the removed cost is precisely the **load-sensitive** cost, so the win grows with grove pressure
- the fork budget becomes a reviewable number rather than folklore
- the two hooks finally gain jest coverage (`rule.require.jest-tests-for-skills`), which they lack today
- 🔴 **lever B carries the whole gate, not merely our two hooks** — all seven get cheaper, from a
  seven-string diff and no code change at all
- 🔴 **~21 stdout lines per edit stop being emitted**, so every Write/Edit costs the model fewer
  tokens to read. a benefit nobody set out to buy
- ✅ **every call is reversible.** lever A lives inside two files; lever B is a string swap

### cons

- a cache introduces a freshness defect class that does not exist today (`case=4`) — which is why
  F3 leans reject
- an exec tally clamps execs, never bare subshell forks — a stated residue, not a total
- 🔴 **lever B changes what a human sees on a block.** the wrapper's two frame lines vanish. the
  substance holds and the frame does not, and that is a real delta declared rather than absorbed
  (**Q13**)
- 🔴 **lever B regenerates `settings.json` in every consumer repo.** the wisher ruled the churn
  acceptable, and it is still churn — a bad string lands in seven places at once
- ⚠️ **lever B touches five hooks this wish never intended to open.** the wish's own escape clause
  permits it — *"unless a shared-cost fix genuinely lands there too"* — and the clause demands we
  *"say so plainly rather than expand the diff quietly"*, which is what this bullet is

⚠️ **three former cons retired across two rulings.** *"one hook named for two concerns"* and
*"ripples into consumer repos"* went with the merge; *"the largest single win is left on the table"*
went with lever B. ⇒ **a rejected design takes its costs with it, and its benefits too** — and a

### edge cases, and how the contract keeps a human in the pit of success

| edge | the guard |
|---|---|
| pre-scan disagrees with the real scan | the pre-scan must **over**-approximate: "maybe" where truth is "no" is safe; "no" where truth is "yes" is a silent policy hole (`case=1`) |
| cache goes stale after a list edit | a cheap witness (mtime + size); a false invalidation costs a parse, a missed one costs the policy — err toward re-parse (`case=4`) |
| no witness is cheap enough to be exact | **carry no cache**; take the smaller win. a correct hook that saves 8 forks beats a fast hook that lies (`case=4`) |
| 🔴 **any refactor shares a nudge record** | it must not — two clocks (`case=2`). ⚠️ **written for the merge; it survives the merge's rejection**, because a shared clock read is not merge-specific |
| 🔴 **any refactor shares a config guard** | it must not — two config paths (`case=5`). ⚠️ **the live one:** the blocklist's collapse touches the term-read path, so a trim that folds both hooks' list reads into one parse breaks this with no merge at all |
| word list is malformed | extant failhide, preserved deliberately; caught as a dream, not repaired here (`case=5`) |
| 🔴 **list parses, one term is not a valid regex** | today one grep errors and the other eight guard; the collapse folds them into **one** grep, so the same term would permit all nine. ⇒ part grep's **exit 1** (no match) from **exit 2** (bad pattern), fail loud on 2 (`case=5` `[t5]`, **Q11**) |
| the fork budget drifts back | the ci clamp, proven to bite by a deliberate revert (`case=6`) |
| 🔴 **lever B's path is wrong, or the tree moves** | the hook never runs, and a PreToolUse hook that never runs is a gate that never gates — **silently**. ⇒ the clamp must assert the hook is **reached**, never merely that it is cheap (`case=6`). one bad string lands in seven repos at once |
| ⚠️ **lever B's frame lines vanish from a block** | substance is the hook's own `>&2` output and is untouched (**Q13**); if the frame proves load-bearing, the hook prints its own for one `echo` |

⚠️ **two rows here are unlike the rest.** every other edge guards behavior that exists today; the
bad-regex row and the lever-B path row guard against holes **this fix would open**. ⇒ a
pit-of-success table that only catalogues inherited edges will not catch the edges a change
introduces, and those are the ones a reviewer cannot find by a read of the current code.

🔴 **and the lever-B row is the most dangerous edge in this wish, despite being the cheapest fix.**
every other failure here is loud or bounded; a hook that is never invoked fails **open, silently, in

## .what is awkward

1. 🔴 **the wish forbids an interpreter boot, and the invocation already paid seven.** *"do not
   rewrite in node — node would pay an interpreter boot per invocation"* is sound reason, and the
   hook was already reached *through* a bun binary boot, seven times per edit. ⇒ **the boundary
   fenced off the cost it was written to prevent.** ✅ lever B now removes it — which means the
   wish's most restrictive clause was, in effect, protecting the very thing it forbade.
2. **a cost test feels wrong.** tests assert behavior; a fork budget asserts a bill. it works only
   because we count **discrete events** rather than elapsed time. count time and it flakes on a
   busy grove — the exact condition the wish exists for.
3. ✅ ~~**the merged hook's name.**~~ **retired by the F1 verdict** — the merge was rejected, so
   there is no one hook named for two concerns and no `rule.require.ubiqlang` cost to pay. ⚠️ **the
   awkwardness it replaced is worse, and it is item 9 below:** the wish now leaves its largest
   single win untaken, on purpose.
4. **the cache is the one place where cheap and correct pull apart.** everywhere else the fix is
   free: the same answer, fewer processes. the cache trades a freshness guarantee we hold today for
   two execs. it is the only line where a reviewer should push hard. ⚠️ **and r5 made it more
   awkward, not less** — the witness turned out nearly free (Q9), so the *price* argument against
   the cache collapsed while the *nobody-asked-for-it* argument stood alone. a lever that got
   cheaper and stayed rejected is an uncomfortable thing to write down, which is why it is here.
5. **we preserve a failhide on purpose, and now by explicit verdict.** `case=5`'s malformed-config
   path silently opens the gate, we can see it, and we leave it. ✅ **the wisher ruled A8 on
   2026-09-10: acceptance #2's "policy" covers degraded mode**, so the repair is out of scope. ⚠️
   **a peer reviewer graded this a blocker and was correct to** — the vision demonstrates a sharp
   critipath that does not fail safe. it took a human to close, because only a human could rule that
   a repo rule yields to the wish's boundary. it still reads as negligence until you read why.
6. **this vision's own artifacts were blocked by the very hooks they describe.** five of the seven
   files needed a HARDNUDGE retry. that is the mechanism at work, not a defect — and it made the
   `case=2` narrative first-hand rather than hypothetical.
7. 🔴 **we must keep a bug on purpose, and it is not the one we already flagged.** the gerunds hook
   detects `-ing` **words**, never gerunds — its allowlist holds one entry, so `sibling`, `ceiling`,
   `during`, and `sting` are all "gerunds" to it. acceptance #2 forbids a policy change *either*
   direction, so the fix must stay wrong in exactly the way it is wrong today. ⚠️ **the most
   attractive collapse is the forbidden one:** swap the `-ing` regex for a real-gerund dictionary
   and you get fewer forks, better correctness, and a breach. **Q10**.
8. 🔴 **the fix's headline lever opens a hole the code does not have.** nine per-term greps folded
   into one alternation turns a term that fails to compile from a one-term hole into a nine-term
   hole. it is guardable in one line (part exit 1 from exit 2), and it is uncomfortable because
   **every other risk in this wish is inherited** — this one would be ours. **Q11**.
9. 🔴 **the churn we rejected at 14:00 we accepted at 15:00, and the yield holds both verdicts.**
   the merge was refused for `settings.json` churn; lever B churns the same file harder. the two
   differ in **kind** — a matcher restructure plus a code merge versus seven string swaps — and the
   table under `.the merge` is the whole defense. ⚠️ **it sits badly regardless**, because a reader
   who scans headings finds *"churn rejected"* and *"churn accepted"* and has to read the body to
   learn they are consistent.
10. 🔴 **the wish's largest win came from outside the wish.** every lever the wish named is a leaf
   trim; the biggest lever is a config string in a file the wish told us not to touch. ⇒ we take it
   under the wish's own escape clause, said plainly. ⚠️ **and the finding was available on day one**
   — it sits in the first line of the wish's own roll-up, above the two lines it filed against.
   nobody read the parent.
11. 🔴 **three of the four walk-produced constraints were written to bound a design that was then
   rejected — and all four still bind.** the most natural read of the F1 verdict is that the merge
   seams retire with the merge. they do not: a leaf-trim that folds both hooks' list reads into one
   shared parse breaks the two-config-paths seam with no merge anywhere in sight. ⇒ **a constraint
   discovered under one design does not belong to that design**, and no part of the artifact's
   shape says so — it has to be written down, which is why it is here and in the constraint list.
