# 1.vision — standardized english for mechanics & architects

> style note: this doc self-demonstrates the telegraphic overlay. prose drops articles + copulas, holds one instruction per sentence, stays brief. verbatim quotes and code blocks stay exempt. the two "bad example" quotes below keep their gerunds on purpose — they show what the rule catches.

## wish, distilled

entrain **ASD-STE100** (simplified technical english) into mechanic + architect via rules. technical prose — comments, plans, docs — then gains:
- higher signal:noise. one word per concept. no synonym sprawl.
- lower verbosity. short sentences. no filler.
- legibility for any-language readers.
- fewer tokens.

move fast. move clear.

> note: this doc tripped the extant `forbid.term-*` and `forbid.gerunds` hooks many times mid-write. direct proof: enforcement path works. STE rules compose with what we ship.

---

## wisher decisions (resolved 2026-08-14)

four fulcrums, settled, now load-critical:

1. **drop articles + copulas — telegraphic overlay.** terseness beats STE's article mandate. `remove filter from case.`, not `Remove the filter from the case.` inverts STE add-articles rule. strengthens fewer-tokens goal. resolves q1.
2. **one dialect everywhere — long-form too.** short-sentence + brevity rules govern ALL technical prose. procedural and long-form alike. long-form draws more readers, so gains more, not less. a brief wants many short composed sentences, not long ones. **exempt only: verbatim quotes + code blocks.** kills the two-dialect worry.
3. **require brevity — simplicity proven via brevity.** the core principle, not a style nicety. rambles hide complexity via obscurity. length lets a half-grasped idea slip past. per feynman, true simplicity demands thoroughness — so brevity proves grasp. cannot say it briefly? you do not yet grasp it. `require.brevity` makes brevity a correctness signal.
4. **forbid rambles — peer of require.brevity.** positive rule names the target. negative rule names the smell. `forbid.rambles` flags the run-on, the restatement, the hedge, the throat-clear. a reviewer then points at obscurity-by-length as a violation, not a missed ideal. the pair works: `require.brevity` pulls to the goal, `forbid.rambles` pushes off the anti-pattern.

## outcome world

### day-in-the-life

a mechanic writes a jsdoc header. today, maybe:

> `.what = this function is responsible for handling the reshaping of incoming customer records before they get persisted`

after the rule entrains:

> `.what = reshape each customer record, then persist it`

second reads shorter. one verb per action. no gerund-nouns. no vague "is responsible for". no "get persisted" passive. a spanish-first or mandarin-first reader parses it in one pass. token count drops hard.

### before / after

| axis | before | after |
|------|--------|-------|
| synonyms | check / verify / validate / ensure, swapped freely | one approved verb per concept |
| voice | passive ("is handled by") | active ("guard handles X") |
| sentence length | run-on, multi-clause | one instruction per sentence |
| gerund-nouns | "the reshaping of", "error handling" | "reshape", "handle errors" |
| tense | "will have been generated" | simple present/past |
| tokens | baseline | fewer |

### the aha

value clicks when a reviewer reads a diff and every comment reads the **same way**. same verbs. same shapes. the reviewer stops decode of *phrases*, reads only the *sense*. prose turns into a clear pane, not stained glass. second aha: non-native readers — human or the many-language LLM — stop the guess over which of five synonyms someone meant.

## user experience

### who & what

| user | usecase | goal |
|------|---------|------|
| mechanic | write comments, commit msgs, error strings | max legibility per token |
| architect | write briefs, plans, domain docs | unambiguous shared vocab |
| reviewer | grade prose against the rule | catch synonym/verbose drift |
| downstream reader (human/robot, any L1) | read the prose | one-pass comprehension |

### contract they leverage

contract = a **rule brief**. extant format under `lang.terms/` and `lang.tones/`. no new CLI.

- **input** = prose a mechanic/architect writes (comment, brief, plan)
- **output** = prose conformant to the entrained rules
- **enforcement** = the reviewer (`review.by`) + boot-loaded briefs that shape output at write-time

leverage: rule sits in role boot context. robot writes conformant prose by default. reviewer flags residual drift as blocker/nitpick.

### timeline

```
author intends a comment
  └─ boot-loaded STE rule shapes the phrasing at generation time
       └─ prose emitted already conformant
            └─ reviewer (review.rubric=...) grades residual drift
                 └─ blocker/nitpick surfaced, author converges
```

no new command. the rule rides the same path every other `lang.*` rule rides.

## evaluation

### fit to goals

| goal | fit | note |
|------|-----|------|
| signal:noise | strong | STE core = disambiguation. on-target. |
| less verbosity | strong | short-sentence + no-filler rules cut length |
| any-language legibility | strong | STE original purpose |
| fewer tokens | strong | telegraphic overlay drops articles/copulas — no STE article-tax, since wisher decision 1 removed it |

### pros

- rides extant machinery: rule-brief format, boot-load, reviewer. no new infra.
- compounds with rules we hold: `forbid.gerunds`, `require.ubiqlang`, `forbid.buzzwords`, `prefer.lowercase`.
- STE = real, stable, cited standard (jan 2025 edition). not invented here.
- prior art exists (a public claude-code STE skill). de-risks feasibility.

### cons

- STE full form = **53 rules + ~900-word dictionary**. wholesale adoption runs heavy, fights domain vocab.
- STE default add-articles rule clashes with house terseness. wisher decision 1 settles it: we drop articles, invert STE.
- over-constraint risk: a 900-word dictionary cannot name `IsoPriceWords` or `findsert`. domain terms need exemption as "technical names".

### edgecases & pit-of-success

| edgecase | how the contract keeps success |
|----------|--------------------------------|
| domain term absent from STE dictionary (`findsert`, `dobj`) | rule declares domain ubiqlang terms approved as "technical names" — exempt |
| STE says "use articles"; house drops them | **resolved: drop articles.** telegraphic overlay wins (decision 1) |
| STE targets procedures; our prose runs descriptive | **resolved: one dialect** — brevity + short-sentences govern descriptive prose too (decision 2) |
| verbatim quote or code block inside a brief | exempt — we cannot rewrite a cited quote or code. only the prose around it obeys. |
| emoji + tone rules (seaturtle vibes) vs STE plainness | tone rules govern human-chat. STE governs technical prose. lanes stay separate. |

## groundwork

### external research

wish references an external standard (ASD-STE100). verified: real, matches the wish premise.

- **what**: international standard for clear, unambiguous technical english. origin = european aerospace (AECMA, 1980s) for aircraft-maintenance docs that non-native english speakers read cleanly. maps exactly to the "any-language legibility" goal.
- **shape**: two parts. (1) **53 write-rules** across 9 sections — grammar, style, sentence structure, word choice. (2) a **controlled dictionary** ~900 approved words (one meaning, one part of speech) + ~1200 unapproved words with alternatives.
- **current edition**: january 2025.
- **prior art**: a public claude-code skill repurposes the STE rules to rewrite english aimed at agents (`danyuchn/asd-ste100-skill`). confirms feasibility of STE as rules for robots.
- **key constraint**: ASD licenses the standard text. we derive/cite the *rules*. we do not reproduce the copyrighted dictionary verbatim.

sources checked:
- https://www.asd-ste100.org/
- https://en.wikipedia.org/wiki/Simplified_Technical_English
- https://www.asd-europe.org/standards-specifications/simplified-technical-english/
- https://github.com/danyuchn/asd-ste100-skill (prior-art skill + rules summary)

### internal research

wish extends extant behavior (role rules for language). verified the machinery and the target spot.

- **rule-brief format** — confirmed via `src/domain.roles/mechanic/briefs/practices/lang.terms/rule.forbid.gerunds.md`. sections `.what / .scope / .why / .enforcement / .examples`. severity via directive (`forbid`/`require` = blocker; `avoid`/`prefer` = nitpick — per `define.directives.terms=forbid_avoid_prefer_require.md`).
- **strong overlap with extant rules** (STE composes, does not duplicate):
  - `lang.terms/rule.forbid.gerunds.md` — STE also bans -ing nouns
  - `lang.terms/rule.require.ubiqlang.md` — STE one-word-one-meaning, for code names
  - `lang.terms/rule.forbid.term=*.md` — per-term bans on overloaded verbs. same spirit as STE's unapproved-word list. this doc hit one.
  - `lang.tones/rule.forbid.buzzwords.md`, `rule.prefer.lowercase.md`, `rule.forbid.shouts.md` — style neighbors
- **placement**:
  - mechanic → `src/domain.roles/mechanic/briefs/practices/lang.terms/` (or a new `lang.prose/` cluster)
  - architect → `src/domain.roles/architect/briefs/practices/ubiqlang/` (neighbors `rule.forbid.term.addition.synonym.md`, `rule.prefer.symmetric-term-pairs.md`)
- **build path** — per `.agent/repo=.this/role=any/briefs/repo.structure.md`. edit in `src/domain.roles/`, run `npm run build` → `dist/`, runtime symlinks `dist/`. so the rule = a source-brief edit + build.
- **reviewer path** — mechanic already ships `review.rubric=mech-*` skills. a prose rubric follows that pattern. out of scope for vision, noted for execution.

no contract signatures or CLI stdouts to conform to. brief-only change.

## what is awkward?

1. ~~**token goal vs STE fidelity**~~ — **resolved by decision 1.** we drop articles, invert STE's add-articles rule. no residual tension. terseness and clarity now align.

2. ~~**STE procedural vs our descriptive prose**~~ — **resolved by decision 2.** one dialect governs both. brevity and short-sentences serve descriptive prose too — a long-form brief wants many short composed sentences.

3. **the dictionary trap** — wholesale ~900 approved words would forbid our own domain vocab. we invert STE's default: domain ubiqlang terms auto-approve as technical names. STE governs only the connective grammar. deliberate divergence from the standard. state it loud, so a reviewer never "corrects" `findsert` into "find or create".

4. ~~**two roles, two dialects**~~ — **resolved by decision 2: one dialect everywhere.** the earlier worry ran wrong. one dialect for all technical prose reads simpler and correct. exempt only quotes + code.

5. **slight irony** — we encode a *human* controlled-language standard mainly to make *robot* output cheaper and steadier. it works. but the standard's stated purpose (non-native human readers) rides as a side benefit here, not the driver. name it, so we do not over-index on aerospace-manual conventions that fit only physical procedures.
