# case=12 — a control character in the bind never reaches a trailer (sharp)

## .narrative

the commit builds its trailer by interpolation: `Co-authored-by: $NAME <$EMAIL>`. a bind file
hand-edited so its name holds a newline turns one trailer into two — the second one chosen by
whoever edited the file, and credited by github on its own. `sponsor set` strips control
characters, so it never writes such a file; the reader now refuses one as damage. the payload
never renders, and no commit lands.

## .timeline

```
given .meter/git.commit.sponsor.jsonc whose name is "Ada\nCo-authored-by: Mal <mal@x.dev>"
when [t0] the clone runs rhx git.commit.set -m @stdin --mode apply
then exit 1
  and stdout + stderr:
    🐢 bummer dude...

    🐚 git.commit.set
       └─ 💥 MalfunctionError: sponsor state file corrupt

       the file that names this tree's sponsor cannot be read:
         .meter/git.commit.sponsor.jsonc

    inspect it, or clear the bind and set it afresh:
      $ cat .meter/git.commit.sponsor.jsonc
      $ rhx git.commit.sponsor del
      $ printf 'Name <email>' | rhx git.commit.sponsor set --who @stdin
      $ rhx git.commit.sponsor set --who "Name <email>"
  and "mal@x.dev" appears nowhere in the output
  and no commit was written

given the bind's email holds a carriage return: "ada@example.com\rOVERWRITE"
when [t1] the clone commits
then the same refusal, exit 1
  and the output holds no "\r" and no "OVERWRITE" — a stray CR would silently overwrite the line
```

## .proof

`git.commit.set` `[case48]` [t0] (newline in name) · [t1] (carriage return in email).
