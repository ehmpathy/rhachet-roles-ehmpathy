# 1.vision — fix git sponsor

## the outcome world

a human opens a worktree on their own machine, grants a commit quota, and takes no other step. the
clone commits, and the trailer names the human — read from `git config`, the same `Name <email>` on
the human's own commits:

```
🐚 git.commit.set --mode plan
   ├─ commit
   │  ├─ author
   │  │  └─ name: seaturtle[bot]
   │  ├─ sponsor
   │  │  ├─ name: Kai Nalu
   │  │  ├─ email: kai@example.com
   │  │  └─ from: git config (this machine)
```

a human binds a sponsor only on purpose: to sponsor someone else's work, or on the clone's own
machine. a bind always wins over git config.

| | before | after |
|---|---|---|
| sponsor on the human's own machine | refuse until a human binds one, at a real terminal | git config, automatically — no bind |
| sponsor precedence | the bind, else refuse | the bind → else git config (if a human's) → else refuse |
| the clone's machine | refuse until a bind | refuse until a bind — git config names a clone, so it cannot answer |
| how "the clone's machine" is known | inferred from gh's session | git config names a roster identity |
| gh | the identity source for `@me` | never read, on any sponsor path |
| flag | `--who @me` | `--who @self` (documented) · `@me` still works, never mentioned |
| a bind run through claude's `!` | "only humans can run this command" — told a human they are not one | "no terminal on this command … run it from your own terminal" |
| the quota-grant tip on a human's machine | "no sponsor is bound, so commits will refuse" | "commits will name <you>, from git config" |
| session boot | six "Write(...) is not matched" warns | quiet |

**the aha:** the human never names themselves. their own machine already does.

## mental model

- human, to a friend: "on my laptop the bot's commits just credit me — same name as my own commits.
  if i want to credit someone else, i bind them."
- analogy: a house account. purchases on your card default to you; a signed note can charge
  someone else; a stranger's card at the till is refused.
- terms: the human says "me" or "my git name"; we say "sponsor", `from: git config (this
  machine)`, `from: bound (this tree)`.

## evaluation

| goal (from the wish) | met by |
|---|---|
| detect a real human on this machine | the human's own git config names them, and the commit uses it with no bind (case=1). the wisher's `!` failure no longer arises in the common flow; where a bind is still needed, the refusal names its true cause (case=8) |
| rename `@me` → `@self` | `@self` is the one documented form; `@me` aliases it silently |
| pull from git config, never gh | git config is the only identity source; no gh command runs on any sponsor path |
| fix the permission warns | delete six `Write(...)` rules; each `Edit(...)` twin already carries the rule |

pros
- zero steps on the common path: grant a quota, and commits name you
- the sponsor matches the human's own authorship
- no gh, no network, no timeout: a local read
- one rule for "whose machine": the git config says
- the human-only bind, and its tty problem, move off the critical path

cons
- git config is a host-wide value, not a proof of who asked for the change. on a human's machine
  the owner answers for every commit the clone makes there, unless they bind someone else.
- a bind through claude's `!` still cannot work (case=8): no marker tells it from the clone.

edgecases → pit of success
- git config names a seaturtle bot or clone → the clone's machine → the commit refuses and asks for a bind (case=3)
- git config unset, or one half absent → refuse, name the absent half and its `git config` fix, or a bind; never guess (case=4)
- git config email fails the shape → refuse; the lead reads "this machine's git config reads:" (M2)
- a bind file that will not read → the extant corrupt refusal; never fall back to git config (case=9 [t3])
- `del` on a human's machine → commits fall back to git config (case=9 [t2])
- stale `@me` in muscle memory → works; no render teaches it (case=5)
- stale sponsor file with `source: me` → the reader maps it to `self`

## what is awkward?

- this reverses the prior route's core premise — "a sponsor is bound by a human act, so no host
  config can stand in for a decision nobody made". the wisher's definition answers the danger that
  premise guarded against (the clone's machine names a clone, and refuses), but the reversal touches
  a large body of tests and comments built on the old premise.
- on a human's machine, the machine's owner answers for every commit the clone makes there, even
  for work someone else requested — unless they bind that person. the default is right for a
  personal laptop; on a shared human-owned box it credits whoever's git config it holds.
- a hand-set git config on the clone's machine that names a human makes that machine a human's, by
  definition, and its commits name that human with no bind. the actor guard no longer stands on
  this path — a commit needs no terminal.
- `@self` becomes a niche form: it pins today's git config as a bind, which the implicit path
  already does live. it earns its place only as a snapshot that later git config edits cannot move.
