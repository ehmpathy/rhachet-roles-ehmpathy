# case=6 — a human opens a session and the boot banner is quiet

## .narrative

kai opens a new claude session in a mechanic-enrolled repo. today the first screen shows six
lines like `Write(.meter/*) is not matched by file permission checks — only Edit(path) rules
are`. he did not write those rules and cannot act on them, so he learns to skim past the boot
banner — and one day skims past a notice that matters.

after the cleanup, he opens the session and the banner holds only what he needs. no noise to
skim, so the next real notice gets read.

behind it: each `Write(...)` rule in the mechanic role's permissions already had an `Edit(...)`
twin that carries the rule, so the six `Write` lines were dead weight.

## .timeline

```
given kai upgrades to the release with the cleanup
when [t0] kai opens a new claude session in the repo
then the boot banner shows no "is not matched by file permission checks" line
when [t1] kai asks the clone to edit .meter/git.commit.uses.jsonc
then the harness still refuses the edit — the Edit(.meter/*) deny holds
```

## .sharp twin — the guard must not weaken

the deny list shields the quota meter and the bind dir from the clone. a cleanup that dropped an
`Edit` twin by mistake would open the meter. [t1] is the actor's view of that guarantee; the repo
pins it on a claim it can test — in the built permissions file, no rule opens with `Write(`, and
every path the six `Write` rules named still appears in an `Edit(` rule in the same list. that
Claude Code applies `Edit(path)` to its Write tool is the harness's own contract, quoted in its
boot text.
