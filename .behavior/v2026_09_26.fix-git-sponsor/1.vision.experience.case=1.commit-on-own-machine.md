# case=1 — the clone commits on the human's own machine, no bind 🎯

## .narrative

kai opens a worktree on his laptop and asks his clone for a change. he grants a commit quota and
takes no other step — no sponsor command at all. the clone commits. `git.commit.set` finds no bind
in this worktree, reads git config, finds kai there — a human's identity, so this is kai's machine
— and names him in the trailer. it is the same `Name <email>` git already stamps on kai's own
commits, and on the clone's commits as committer. gh is never touched.

before: the commit refused ("no sponsor is bound to this tree … you cannot fix this yourself"), and
kai had to run a human-only bind at a real terminal. when he tried it through claude's `!`, it
refused him as though he were the clone.

## .timeline

```
given kai's laptop, git config user.name = "Kai Nalu", user.email = "kai@example.com"
  and no sponsor bound in this worktree
  and a commit quota granted
when [t0] the clone runs: echo "$MSG" | rhx git.commit.set -m @stdin --mode plan
then exit 0
  and the plan tree shows:
       ├─ sponsor
       │  ├─ name: Kai Nalu
       │  ├─ email: kai@example.com
       │  └─ from: git config (this machine)
when [t1] the clone runs the same with --mode apply
then the commit lands, author seaturtle[bot]
  and the trailer reads: Co-authored-by: Kai Nalu <kai@example.com>
  and no gh command ran
  and no sponsor file was written — the next commit reads git config afresh
```

## .the aha

the human never names themselves. their own machine already does, and the clone's commit carries
the same author line as the human's own commits.
