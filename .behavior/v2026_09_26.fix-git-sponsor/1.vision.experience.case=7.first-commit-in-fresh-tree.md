# case=7 — first commit in a fresh worktree, end to end 🎯 (densest)

crosses two skills (`git.commit.uses` → `git.commit.set`), two actors (human, clone), and the bind +
git config + roster boundaries in one walk.

## .narrative

kai spins up a worktree for his clone. he grants a commit quota. the grant succeeds, and — because
this worktree has no bind but git config names kai — it tells him commits will name him, with no
warn that they will refuse. he takes no other step. the clone commits, and the trailer names kai
exactly as his own commits name him.

before: the grant printed a coconut — "no sponsor is bound to this tree, so commits will refuse" —
and listed bind commands, one of them `--who @me`, which bound a gh display name and a noreply
address. kai had to run one before the clone could commit.

## .timeline

```
given a fresh worktree on kai's laptop, no sponsor bound
  and git config user.name = "Kai Nalu", user.email = "kai@example.com"
when [t0] kai runs rhx git.commit.uses set --quant 3 --push allow
then exit 0
  and the grant tree shows the quota
  and it reads: commits will name Kai Nalu <kai@example.com>, from git config
  and no "commits will refuse" coconut renders
  and the output does not contain "@me"
when [t1] the clone runs echo "$MSG" | rhx git.commit.set -m @stdin --mode apply
then the commit lands, author seaturtle[bot]
  and the trailer reads: Co-authored-by: Kai Nalu <kai@example.com>
  and the plan tree shows from: git config (this machine)
```

## .sharp twin — the same journey on the clone's machine

```
given the clone's machine: git config names seaturtle[bot], no bind
when [t0] a human grants a quota
then the coconut reads "commits will refuse: git config names a clone — the clone's machine"
  and lists the portable bind forms, and `@self` is not among them — it refuses here
when [t1] the clone commits
then exit 2 (case=3)
```
