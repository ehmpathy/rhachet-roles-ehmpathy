# case=10 — the quota file is damaged (sharp)

## .narrative

a write to `.meter/git.commit.uses.jsonc` stops midway — a crash, a full disk. the next time the
clone commits, the quota the human granted cannot be read. it once died on jq's own parse error: no
class, no file named, no fix. now every surface that reads the quota — `commit`, `push`, `nudge` —
refuses by name, names the file, and names the reset. it never guesses a quota, and never treats a
damaged file as "no grant" or as "unlimited".

## .timeline

```
given a worktree whose .meter/git.commit.uses.jsonc is truncated mid-write
when [t0] the clone runs rhx git.commit.set -m @stdin --mode apply
then exit 1
  and stdout + stderr:
    🐢 bummer dude...

    🐚 git.commit.set
       └─ 💥 MalfunctionError: commit quota file corrupt

       the file that holds this tree's commit quota cannot be read:
         .meter/git.commit.uses.jsonc

    ask your human to reset the quota, then grant again:
      $ git.commit.uses del
      $ git.commit.uses set --quant N --push allow|block
  and jq's raw parse error never reaches the human

given the file parses, but uses is not a count — or the file is empty
when [t1] the clone commits
then the same refusal by name, exit 1

when [t2] the clone runs rhx git.commit.push --mode apply
then the same refusal, under 🐚 git.commit.push, exit 1

when [t3] the human runs rhx git.commit.uses get
then the same refusal, under 🐚 git.commit.uses, exit 1

when [t4] the human runs the printed fix, rhx git.commit.uses del
then exit 0 — the remedy works on the damaged file
```

## .proof

`git.commit.set` `[case53]` [t0]–[t2] · `git.commit.push` `[case14c]` · `git.commit.uses`
`[caseLocalMeterDamaged]` [t0] (`get`) + [t1] (`del`, the remedy).
