# 1.vision.experience.dimensions

the experience space the wish touches: who a commit names as sponsor, how a human binds one on
purpose, the surfaces that advertise the bind, and the session boot the permissions cleanup changes.

## .the wisher's verdicts that shape the space

- **gh is never read for a sponsor** — not as an identity source, not as a clone check. only
  `git config`.
- **a clone's machine is defined by its git config.** git config names a roster identity (a
  seaturtle clone or bot) → the clone's machine. git config names a human → a human's machine.
  there is no separate "who owns the host" to detect.
- **on a human's machine, no bind is needed.** the commit takes its sponsor from git config.
- **an explicit bind wins** over git config, so a human can sponsor work on someone else's behalf.
- **the wisher's own failure was a `!` command** inside a claude session — so how the human
  invokes a bind is a real axis.

## .why each axis is orthogonal to the rest

- **D0 surface** — any actor on any channel under any config and bind state can reach any surface.
  the surface decides which render they meet.
- **D1 actor** — who types. a human may type on any channel; a clone reaches only `harness`. that
  one constraint is an impossible-cell rule, not a dependence of the axis.
- **D2 channel** — a property of the process, set by how it was launched. the actor guard reads
  only this axis (`-t` on the three streams). a human on `bang` looks, to a tty test, exactly like a
  clone on `harness` — measured: the two carry identical claude env markers (Q8).
- **D3 form** — the flag typed, independent of all else. `@stdin` and literal never read D4.
- **D4 git config** — settable on any host by anyone with shell access. no value of D1–D3 or D5
  implies a value of D4.
- **D5 bind** — the `.meter/` file this worktree holds, written by an earlier human act. any bind
  state can meet any config: a human may bind on their own machine (to sponsor someone else), and a
  clone's machine may carry a bind a human made for it.

### why the grove is not an axis

a grove axis inferred from signals that only correlate with the host's owner would hide cells. the
wisher's verdict removes the inference: "clone machine vs human machine = is the git config a clone
or human". the grove is a **name for a D4 value**, not a separate fact to detect.

## .the walked product — D0=commit (the primary surface)

the clone runs `git.commit.set`; D1=clone and D2=harness are fixed here, and the commit needs no
human at the moment of the commit — the human answered earlier, either by a bind (D5) or by the
identity they configured on their own machine (D4). precedence: **bind → git config → refuse**.

| D5 \ D4 | human | malformed | unset | clone | placeholder |
|---|---|---|---|---|---|
| unbound | M1 **sponsor = git config** ✅ | M2 refuse — fix git config, or bind | M3 refuse — set git config, or bind | M4 refuse — the clone's machine; a human binds | M5 refuse — placeholder; fix git config, or bind |
| bound | M6 **sponsor = the bind** ✅ (wins over git config) | M7 = M6 | M8 = M6 | M9 = M6 | M10 = M6 |
| corrupt | M11 refuse — corrupt file (extant render); **never** fall back to git config | M12 = M11 | M13 = M11 | M14 = M11 | M15 = M11 |

why corrupt never falls back: a damaged bind means a human meant to name someone. to silently use
git config instead would name a human the bind may have replaced — a failhide that invents an
answer (rule.forbid.failhide).

## .the walked product — D0=set (a deliberate bind)

a bind is now the exception path: sponsor someone else's work, or bind on the clone's machine.
`D1=clone` implies `D2=harness`; the actor guard refuses before D3–D4 are read (C1).
`D3 ∈ {@stdin, literal}` never read D4 (H9). `D3=@me` routes to the `@self` arm (H8).

for `D1=human · D3=@self`, walked over D2 × D4:

| D4 \ D2 | terminal | bang |
|---|---|---|
| human | S1 bind (a pinned snapshot of the implicit sponsor) | B1 refuse at actor guard — "no terminal" |
| malformed | S2 refuse — shape | B2 = B1 |
| unset | S3 refuse — set git config | B3 = B1 |
| clone | S4 refuse — the clone's machine | B4 = B1 |
| placeholder | S5 refuse — placeholder | B5 = B1 |

for `D1=human · D3 ∈ {@stdin, literal}`: `terminal` → bind the named human (E1); `bang` → refuse at
the actor guard, as B1 (E2).

### why D6 and D7 are orthogonal

- **D6 permission meters** — files a write may leave damaged on any host, under any bind or
  config. they gate `commit`, `push`, and `nudge` before any sponsor axis is read. a damaged meter
  never reads as "no grant" or "not blocked" — damage is not absence.
- **D7 flag shape** — what the caller typed, independent of every file and config.
