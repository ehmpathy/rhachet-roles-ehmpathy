# case=2 — a clone tries to bind itself (sharp)

## .narrative

a clone reads "no sponsor bound" and reaches for `@self`, in hope to derive a sponsor from git
config. the actor guard refuses before any identity is read: the command has no terminal. the
refusal is the same one a human's `!` command meets (case=8) — the guard cannot tell the two apart
— so it speaks to both readers: the clone learns that a better name will not help, and to hand off
to its human; a human learns to use their own terminal.

## .timeline

```
given a clone under a tool harness (no tty on any stream)
when [t0] rhx git.commit.sponsor set --who @self
then exit 2
  and stdout + stderr:
    🐢 bummer dude...
    🐚 git.commit.sponsor set
       └─ ✋ ConstraintError: no terminal on this command

       a sponsor bind needs a human at a real terminal, and this command
       has none. a clone's tool call has none, and neither does a claude
       `!` command, so the two cannot be told apart here.

       if you are a clone: this holds even for a real human's name. to
       name a human who did not act is a fabrication, and it reads as
       authorized. hand this to your human.

    run it from your own terminal, in this tree:
      $ printf 'Name <email>' | rhx git.commit.sponsor set --who @stdin
      $ rhx git.commit.sponsor set --who "Name <email>"
  and no git config read and no gh call was made
  and .meter/git.commit.sponsor.jsonc is absent
```

fast (refused before any read) · loud (both streams) · teaches the fix (the handoff, with the
commands a human runs). the remedy lists only the two portable forms — `@self` refuses on the
clone's machine, so a mandatory remedy never names it.

the `del` arm keeps its own remedy (`rhx git.commit.sponsor del`) and omits the fabrication
paragraph, as today.
