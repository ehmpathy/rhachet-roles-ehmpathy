# case=9 — an explicit bind wins over git config (happy + sharp twin)

## .narrative

kai's laptop, but the change is jo's request — jo should answer for it. kai binds jo, in his own
terminal. from then on the clone's commits in this worktree name jo, not kai: the bind wins over
git config. when the work is done, kai clears the bind, and commits name him again.

if the bind file is ever damaged, the commit refuses rather than quietly fall back to kai — a
damaged bind means someone meant a sponsor other than git config, and to substitute git config
would invent the answer.

## .timeline

```
given kai's laptop, git config names kai
when [t0] kai, in his own terminal, runs:
      printf 'Jo Rivera <jo@example.com>' | rhx git.commit.sponsor set --who @stdin
then exit 0, bound: name Jo Rivera, email jo@example.com, source: supplied
when [t1] the clone commits
then the trailer reads: Co-authored-by: Jo Rivera <jo@example.com>
  and the plan tree shows from: bound (this tree)
  and git config was not read for the sponsor

when [t2] kai runs rhx git.commit.sponsor del, and the clone commits again
then the trailer reads: Co-authored-by: Kai Nalu <kai@example.com>
  and the plan tree shows from: git config (this machine)

given the bind file is corrupt
when [t3] the clone commits
then exit 1, the extant corrupt-file refusal (inspect, or del and re-bind)
  and the commit does NOT fall back to git config

when [t4] kai runs rhx git.commit.sponsor set --who @self
then exit 0, bound: kai from git config, source: self
  ⇒ a pinned snapshot: later changes to git config no longer move the sponsor
```
