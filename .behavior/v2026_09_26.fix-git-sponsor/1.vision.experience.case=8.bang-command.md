# case=8 — a human runs a bind through claude's `!` (sharp alterpath)

the wisher's own failure: "git.sponsor right now doesnt detect a real human, e.g., me from this machine".

⇒ on the human's own machine this case no longer arises in the common flow — commits take the
sponsor from git config with no bind (case=1). a `!` bind remains possible only for the exception
paths: sponsor someone else (case=9), or bind on the clone's machine (case=3).

## .narrative

kai is mid-session with his clone. it says no sponsor is bound. he types `! rhx git.commit.sponsor
set --who @self` straight into claude. a `!` command runs without a terminal on any stream — to the
skill's tty test it is indistinguishable from the clone's own tool call. today the refusal reads
"only humans can run this command", which tells kai, a human, that he is not one.

after: the refusal still holds (the guard cannot tell kai from the clone on this channel), but it
names the channel as the cause, and the one move that works — his own terminal. it is the same
render the clone meets (case=2); the guard sees one channel, so it speaks once, to both readers.

```
      $ printf 'Name <email>' | rhx git.commit.sponsor set --who @stdin

  and no git config was read, no sponsor is bound
when [t1] kai runs `rhx git.commit.sponsor set --who @self` in his own terminal

```

the remedy names the portable forms, not `@self`, because the same render reaches a clone on its
own machine, where `@self` refuses. kai's own terminal is a human's machine, so `@self` works
there, as the optional coconuts already advertise.

## .why `!` cannot be told apart from the clone (Q8, answered)

measured 2026-09-26: the wisher's `! env | grep -i claude` and the clone's tool shell carry the same
claude markers with the same values — `CLAUDECODE=1`, `CLAUDE_CODE_ENTRYPOINT=cli`,
`AI_AGENT=claude-code_2-1-280_agent`, `CLAUDE_CODE_SESSION_ATTENDED=1`,
`CLAUDE_CODE_CHILD_SESSION=1`, and the same session id, pid, and socket. and a marker counts only
if the clone cannot set it; any env var is one the clone could export. so the refusal above is the
fix: it names the true cause and the one move that works.
