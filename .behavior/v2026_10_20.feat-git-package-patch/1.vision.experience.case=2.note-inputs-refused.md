# case=2 — a patch with no why or no upstream is refused

feel = sharp · care = critipath · covers c2, c20

## .narrative

kai has his edits in the dir and is in a hurry. he runs `commit` with only the issue link — he
forgot `--why`. the verb stops him before it touches the tree and says `--why` is required.
he adds it, and in his rush leaves off `--upstream`; same stop, and the hint shows the shape it
wants: an issue or pr url. he types `--upstream later`, half in jest; it is refused too — a link,
not a promise. each time his edits sit untouched, so the fix is one flag away. the third attempt
lands. a patch with no upstream ref is a fork nobody knows to retire; kai never got to make one.

later, a fresh ci box with no git identity runs the same commit, flags all correct. it stops at
once: the note needs a "who", and `user.name` is unset. the message hands back the two
`git config` lines to run; once set, the commit lands with a real name in the note.

## .timeline

  when [t0] commit --package rhachet --upstream https://github.com/ehmpathy/rhachet/issues/580 --mode apply

    then exit 2: ✋ ConstraintError: --upstream is required
    then the hint names the shape: an issue or pr url
  when [t2] commit --package rhachet --why 'enroll hook leaks' --upstream 'later' --mode apply
    then exit 2: ✋ ConstraintError: --upstream must be an http(s) link
    then the edit dir is still intact
given the same open edit dir, in a tree whose git config has no user.name
  when [t3] commit --package rhachet --why 'enroll hook leaks' --upstream https://github.com/ehmpathy/rhachet/issues/580 --mode apply
    then exit 2: ✋ ConstraintError: git identity absent; the note needs a who
    then the fix names: git config user.name '<name>' and git config user.email '<email>'
    then pnpm patch-commit never ran; the edit dir is intact
