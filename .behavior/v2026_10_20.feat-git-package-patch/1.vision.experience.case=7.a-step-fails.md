# case=7 — a step fails under the verb: loud, the tree recoverable, the rerun named

feel = sharp · care = critipath (a failed seal must never leave a half-state the crew cannot see) · covers c26, c26b, c26c, c26d

## .narrative

a clone patches `is-number`. pnpm, not the verb, is what breaks: once because the package sits on
disk but pnpm never installed it, once because a stray file squats where the patches dir belongs,
once because the reinstall after the seal cannot fetch a dependency, and once because the note
path is blocked.

each time the clone gets the same shape of answer: `💥 MalfunctionError`, exit 1, on both streams —
so it knows the verb did not refuse its input; a step under it failed. pnpm's own words sit under
`detail`. the tree is left in a state a rerun can finish: the edit dir still open after a failed seal, the patch kept when pnpm already recorded its
entry, so the manifest never points at an absent file. the hint names the rerun. the clone fixes
the cause and pastes the same command; the seal lands.

## .timeline

```
given a pnpm repo with is-number@7.0.0 installed
  when [t0] begin --package reef-ghost --mode apply   (on disk, never installed by pnpm)
    then exit 1: 💥 MalfunctionError: pnpm patch failed, on stdout and stderr
    then pnpm's words sit under └─ detail
  when [t1] commit --mode apply, while ./patches is a file
    then exit 1: 💥 MalfunctionError: pnpm patch-commit failed
    then no note is written; the edit dir stays open
  when [t2] commit --mode apply, while the reinstall cannot fetch a dependency
    then exit 1: the patch is kept so the entry holds; "then rerun this commit"
  when [t3] commit --mode apply, while the note path is blocked
    then exit 1: the patch landed but its note could not be written; rerun this commit to write it
  when [t4] the cause is cleared, and the same commit reruns
    then exit 0: the patch is re-sealed and the note written
```

proven by `[case6]` `[t0]`, `[t1]`, `[t4]`, `[t5]` and `[case7]` `[t0]` in the integration suite.
