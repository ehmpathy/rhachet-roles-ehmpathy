wish =

# wish: git.package.patch — a crew patches a dependency through one paved rhx verb

## .the one home

ehmpathy/rhachet-roles-ehmpathy#926 — `git.package.patch`, to entool the pnpm patch lifecycle. this
wish delivers #926 and closes the asks that duplicate it: #772 (set.package.patch). #1014 (allow raw
pnpm patch in permissions) is adjacent: the paved verb makes the raw allow unneeded, so say in the PR
whether #1014 should close.

## .the defect

the commander: "we expect and encourage patches." yet on 2026-10-20 a crew's raw
`pnpm patch rhachet@1.48.1` was refused by the auto-mode classifier, which read it as a security
control weakened, and the crew sat until a director authorized it by hand. a patch has no paved
verb, so each one is a novel shell command the harness must judge fresh.

## .the want

a `role=mechanic` skill, `rhx git.package.patch`, that:

1. runs `pnpm patch` and `pnpm patch-commit` for a named dependency, inside the crew's own tree only
2. requires `--why` and an upstream issue link; refuses without either
3. writes the LOCAL PATCH note (who, when, why, where the upstream fix is queued)
4. refuses any path outside the tree — never the shared pnpm store, never a global install
5. runs plan first, apply on `--mode apply`, and is idempotent on re-run
6. is pre-approved in the mechanic permissions, so a crew calls it with no harness prompt

proven by tests: a patch inside the tree lands with its note; a path outside the tree is refused; an
absent `--why` or issue link is refused.

## .bounds

- PR + `rhx git.release --watch`. never `--apply`, never merge; the commander releases
- size: nano unless the crew shows why not, and then it asks before it grows
