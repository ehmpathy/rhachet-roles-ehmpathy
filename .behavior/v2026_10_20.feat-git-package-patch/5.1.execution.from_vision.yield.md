## .the contract, as built

| phase | flags | writes |
|---|---|---|
| `begin` | `--package <name>[@<version>]`, `--edit-dir <dir>`, `--mode plan\|apply` | `node_modules/.pnpm_patches/<name>@<version>/` (default) |
| `commit` | the above + `--why '<why>'`, `--upstream <url>` | `patches/<name>@<version>.patch`, `patches/<name>@<version>.patch.note.md`, the `patchedDependencies` entry |

plan is the default for both phases. both are idempotent:

- `begin` reuses an open edit dir and never re-runs pnpm over it
- `commit` with no open dir, where the patch and a note with the same why + upstream already exist, is a no-op (exit 0)

## .found in execution

- `useBeforeAll` hands back a proxy object, so a fixture returns `{ dir }` and cases read `scene.dir`
- `tee /dev/stderr` fails where stderr is a socket, as node's `spawn` gives a child. under `set -e` that turned every exit 2 into exit 1. `output.sh` now writes the rendered block to fd 1 and fd 2 directly
- pnpm 10 behaves as the vision assumed: `--edit-dir` opens the copy, `patch-commit` writes the patch and records the patched dependency
- `shift 2` with one arg left fails under `set -e`, so a flag with no value exited 1 in silence. each parse now shifts only what is there, and the empty value reaches its "is required" refusal
- `commit` refuses an open `--edit-dir` whose `package.json` names another package or version than `--package`. a seal never lands under a version the crew did not ask for
- the two bound-check calls take named args (`get_real_path --path --from`, `is_inside_tree --path --root`), the shape of their producer `is_path_within_repo_root`, so a swap cannot invert the bound in silence
