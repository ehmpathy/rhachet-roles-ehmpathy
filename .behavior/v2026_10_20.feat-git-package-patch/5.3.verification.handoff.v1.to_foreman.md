# 5.3.verification handoff v1 — to foreman

## .the ask, as one command

```sh
rhx git.commit.uses allow --global
```

with it, the clone stages by path (never the F6 files), commits `cont(git.package.patch): ...` to
#1020, pushes, and runs `rhx git.release --watch`. CI then runs `blackbox/git.package.patch.acceptance.test.ts`
on the pinned rhachet, which is the one proof this gate still lacks.

## .what was tried

1. **acceptance locally** — `rhx git.repo.test --what acceptance --against local --env test --scope 'path://git.package.patch' --mode apply`.
   the build step refuses: rhachet 1.51.0 `repo introspect` rejects roles that boot via hooks
   (architect, ergonomist, mechanic). the tree carries rhachet 1.51.0 from the F6 bump; HEAD and CI
   pin 1.48.1.
2. **roll the tree back to the pinned deps** — refused by the clone: the same bump moves
   `rhachet-roles-bhrain` 0.39.3 → 0.42.1, which drives this route, and the bump is the human's
   in-flight work (fulcrum F6), not the clone's to revert.
3. **a pinned worktree at HEAD + this change** — `git worktree add` and `pnpm` are both unpaved here
   (`rhx permissions.get --head pnpm` → none), so each call would prompt a human anyway.
4. **push, so CI proves it** — `rhx git.stage.add …` exits 2: "a human has blocked all mechanic
   operations"; `rhx git.commit.uses get --global` → `global: blocked`.

## .why it needs the foreman

the global commit block is a human-only lever, and every other path to a pinned-rhachet run either
reverts the human's work or prompts the human. one grant opens the push, and CI runs acceptance
with no further ask.

## .what already holds

types, format, biome, the verb's 122 integration cases, the permissions hook's 372 of 373 cases,
and the mechanic boot.yml consistency checks. the one red permissions case, `case58`, times the whole
hook on a host at load 40 / 12 cpus; it is fulcrum F13. see `5.3.verification.yield.md`.

## .also owed, once the grant lands

origin/main is at v1.42.0, three releases past this branch's base, and both sides edit
`commands.alternatives.jsonc` and the permissions suite. the clone runs
`rhx git.branch.rebase begin --mode apply` before the push; that rewrites commits, so it rides the
same grant.
