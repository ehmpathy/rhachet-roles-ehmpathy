# case=6 — several versions installed: no picker, a named choice

feel = sharp → happy · care = critipath (the stall #926 records) · covers c7b, c6, c18

## .narrative

a clone on the crew needs to patch `rhachet`, and the repo holds two copies: `1.48.1` at the top
and `1.47.0` under a peer dep. last time, raw `pnpm patch rhachet` opened a picker — and a clone
has no hand on stdin, so it sat, then hand-wrote diff hunks to get around it.

this time it runs `begin --package rhachet` and gets an answer within a second: two versions are
installed, here they are, and here is the exact command for each. no prompt waits on it. it
copies the `rhachet@1.48.1` line and runs it; the dir for that version opens. at commit it names
the same version, and the patch seals against `1.48.1` — the one the defect lives in. the note
beside it names the clone itself as the author, since that is who the tree's git config says
made it.

## .timeline

```
given a pnpm repo where rhachet@1.48.1 and rhachet@1.47.0 are both installed
  when [t0] begin --package rhachet --mode apply
    then exit 2 fast: ✋ ConstraintError: several versions of rhachet are installed
    then it lists 1.48.1 and 1.47.0
    then the fix names: begin --package rhachet@1.48.1
    then no pnpm process waits on stdin; no edit dir is made
  when [t1] begin --package rhachet@1.48.1 --mode apply
    then the edit dir node_modules/.pnpm_patches/rhachet@1.48.1 opens
  when [t2] the clone edits, then: commit --package rhachet@1.48.1 --why '...' --upstream <url> --mode apply
    then patches/rhachet@1.48.1.patch and its note land; 1.47.0 is untouched
    then the note's who = the clone's git identity, e.g. seaturtle[bot] <seaturtle@ehmpath.com>
```
