# 1.vision.experience.dimensions

the experience space of `rhx git.package.patch`, factored into orthogonal axes.

## .actors

- **crew.human** — a human at a terminal, inside its own worktree
- **crew.clone** — a mechanic clone (bot) inside its own worktree. a system actor: no stdin to
  answer a prompt, no hand to click a modal; `git config` names the bot, so the note's "who" is the bot
- **reviewer** — the commander who reads the pr, and later decides when the patch can retire

the harness classifier is not an actor; it is the obstacle this verb removes. the permission hook
is a boundary the crew crosses (axis I).

## .the axes

| # | axis | values |
|---|------|--------|
| A | phase | `begin` (open an edit dir) · `commit` (seal the patch + note) |
| B | mode | `plan` (default, preview) · `apply` |
| C | package spec | bare name, one version installed · `name@version` · bare name, several versions installed · not installed |
| D | edit dir state | absent · present, no edits · present, edited |
| E | edit dir location | inside the tree (default) · outside the tree (literal path, `..`, or a symlink that points out) |
| F | note inputs (commit only) | `--why` + `--upstream` · `--why` absent · `--upstream` absent · `--upstream` not a link |
| G | prior patch for this package@version | none · extant (an amend) |
| H | repo shape | pnpm · npm lockfile · pnpm with `node-linker=hoisted` |
| I | entry | the paved verb · a raw `pnpm patch` / `pnpm patch-commit` call |
| J | time | sequential (first run, or a re-run) · concurrent (two sessions on one package in one tree) |
| K | actor | crew.human · crew.clone · reviewer |
| L | git identity (the note's "who") | set · absent (`user.name` or `user.email` unset) |
| M | package root | git root (single package, or a pnpm workspace rooted at the git root) · a workspace rooted below the git root |

## .how the product is walked — the gate order

the verb validates in one fixed order, and the **first failed gate wins**:

```
1. entry (I)      raw pnpm call → the hook redirects; the verb never runs
2. flags          unknown flag (e.g. -g) → refused
3. repo shape (H) npm lockfile → refused
4. location (E)   --edit-dir escapes the tree → refused
5. inputs (F, L)  commit only: --why / --upstream absent or not a link → refused;
                  then git identity absent → refused
6. spec (C)       begin: not installed / several versions with a bare name → refused
                  commit: not installed → refused; a bare name resolves to the one open edit
                  dir for that name, and zero or several open dirs → refused
7. state (D, G)   decides the action: open, reuse, seal, no-op, or "no edits"
8. mode (B)       plan prints the action; apply performs it
```

so every cell where an earlier gate fails collapses to that gate's refusal, whatever the later
axes hold. this is a conditioned product, stated so it can be checked: the inventory gives each
gate's refusal a cell **per phase** where the gate applies in both phases, then walks D × G × B
per phase for the cells that pass every gate. H=hoisted passes gate 3, then bites twice: at begin
only the top-level copy is visible, so gate 6 sees one version; at commit pnpm's own apply may
fail. J, K, and M vary the experience, not the gate outcome, and get their own cells.

every cell of that walk lands in `1.vision.experience.case=_.md` with a verdict.
