# 1.vision.experience.dimensions

the experience space of `rhx git.package.patch`, factored into orthogonal axes.

## .actors

- **crew.human** — a human at a terminal, inside its own worktree
- **crew.clone** — a mechanic clone (bot) inside its own worktree. a system actor: no stdin to
  answer a prompt, no hand to click a modal; `git config` names the bot, so the note's "who" is the bot
- **reviewer** — the commander who reads the pr, and later decides when the patch can retire

the harness classifier is not an actor; it is the obstacle this verb removes. the permission hook
is a boundary the crew crosses (axis I).

## .the axes

| # | axis | values |
|---|------|--------|
| A | phase | `begin` (open an edit dir) · `commit` (seal the patch + note) · `help` (the verb's or a subcommand's usage) · no subcommand · an unknown subcommand |
| B | mode | `plan` (default, preview) · `apply` · any other value |
| C | package spec | bare name, one version installed · `name@version` · `name@version`, that version not installed · bare name, several versions installed (a prerelease among them) · `@scope/name` · not installed, undeclared · not installed, but declared in the manifest · `--package` absent or bare |
| D | edit dir state | absent · present, no edits · present, edited · present, holds another package or version |
| E | edit dir location | inside the tree (default) · a custom in-tree `--edit-dir` · outside the tree (literal path, `..`, or a symlink that points out) · the default base symlinked out of the tree · the live install, the patches dir, or a broken link |
| F | note inputs (commit only) | `--why` + `--upstream` · `--why` absent · `--upstream` absent · `--upstream` not a link |
| G | prior patch for this package@version | none · extant (an amend) · extant, but its manifest entry or lockfile record lost (a rebase dropped it) |
| H | repo shape | pnpm · a foreign lockfile (npm, yarn, bun) · pnpm with `node-linker=hoisted` · not inside a git repo |
| I | entry | the paved verb via `rhx` (the rhachet seam) · the paved verb with the rhx selectors (`--skill`, `--repo`, `--role`) in its argv · a raw `pnpm patch` / `pnpm patch-commit` call |
| J | time | sequential (first run, or a re-run) · concurrent (two sessions on one package in one tree) |
| K | actor | crew.human · crew.clone · reviewer |
| L | git identity (the note's "who") | set · absent (`user.name` or `user.email` unset) · hostile (spans several lines) |
| M | package root | git root (single package, or a pnpm workspace rooted at the git root) · a workspace rooted below the git root |
| N | step outcome | every step succeeds · a step fails under the verb (pnpm fails, a file is malformed, a write is blocked, pnpm writes no lockfile) |
| O | string trust | the strings read from disk and argv are clean · hostile (a newline or a command in a manifest value, shell metachars in a path) |

## .how the product is walked — the gate order

the verb validates in one fixed order, and the **first failed gate wins**:

```
0. dispatch (A)   no subcommand or an unknown one → refused, subcommands named; help → usage
1. entry (I)      raw pnpm call → the hook redirects; the verb never runs.
                  the rhx selectors in argv are stripped, never refused
2. flags (B, C)   unknown flag (e.g. -g), a flag with no value, --package absent,
                  or --mode neither plan nor apply → refused
3. repo shape (H) not inside a git repo, a foreign lockfile, or node-linker=hoisted → refused
4. location (E)   --edit-dir escapes the tree, or is the live install, the patches dir, or a
                  broken link → refused; the default base symlinked out → refused at gate 7
5. inputs (F, L)  commit only: --why / --upstream absent or not a link → refused;
                  then git identity absent → refused
6. spec (C)       begin: not installed / several versions with a bare name → refused
                  commit: not installed → refused; a bare name resolves to the one open edit
                  dir for that name, and zero or several open dirs → refused
7. state (D, G)   decides the action: open, reuse, seal, no-op, or "no edits";
                  a prior patch whose record was lost → refused, the restore named
8. mode (B)       plan prints the action; apply performs it
```

so every cell where an earlier gate fails collapses to that gate's refusal, whatever the later
axes hold. this is a conditioned product, stated so it can be checked: the inventory gives each
gate's refusal a cell **per phase** where the gate applies in both phases, then walks D × G × B
per phase for the cells that pass every gate. H=hoisted fails gate 3: pnpm cannot apply a patch
under that linker, so the verb refuses before pnpm runs (c12h). J, K, and M vary the experience,
not the gate outcome, and get their own cells.

N and O cut across the gates rather than sit in the order. N=fails can strike at any read or
write the verb makes, from gate 6 on: each such step is a malfunction (`💥`, exit 1) that leaves
the tree recoverable and names the rerun. O=hostile is checked where the string is read: a
manifest value is shape-checked before it is printed, and a path is quoted before it is pasted.

every cell of that walk lands in `1.vision.experience.case=_.md` with a verdict.
