## what shipped

### the production hook

`permissionrequest.decide-permissions.sh` — the default-deny, quote-aware decider proven in the
spike, promoted to a production hook with full what/why headers:

1. reads hook json from stdin, extracts `tool_input.command`
2. strips BOTH single- and double-quoted spans (backslash-escape aware) to get the
   shell-active **residue** (quoted metachars are inert data, not chains) — via the
   extracted transformer `compute_active_residue`, which also reports `RESIDUE_BALANCED`
   so an unbalanced/unterminated quote can never auto-approve
3. **DENY** when the residue holds an unquoted command-chain operator: `;`, `&` (covers
   `&&`), `||`, or a literal newline/carriage-return — it smuggles a second command
4. **APPROVE** a single clean `rhx` / `npx rhachet` call whose residue holds no other
   shell-active metachar (`| < > ( ) $` backtick) — safe by design, already past the
   permissions nudge
5. **LIFT** the rest — emit no stdout, so claude-cli falls back to the human prompt
   (a brain decides: human today, an inline haiku later)

verdicts emit the **nested** `decision.behavior` schema — the shape proven to suppress the
prompt on claude-cli 2.1.87 (the flat `permissionDecision` shape does NOT; that was the
root cause of prior "allow does not stick" reports).

### the test

`permissionrequest.decide-permissions.integration.test.ts` — 34 cases, jest given/when/then:

- **case1** clean rhx auto-approves (quoted parens, quoted pipe, `npx rhachet`, nested-schema shape)
- **case2** unquoted chains auto-deny (`&&`, bare `&`, `;`, `||`, literal newline)
- **case3** unprovable commands lift (pipe-to-shell, redirect, non-rhx, `rhxfoo`, `sudo rhx`)
- **case4** edge cases (empty / absent command lift with exit 0)
- **case5** redteam invariant — 14 adversarial payloads, each asserted to **never**
  `AUTO_APPROVE` (deny or lift only)
- **case6** the audit trail (G3) — an allow/deny writes one recorded line; a lift writes none

### the audit trail (G3 — auditable gate)

each auto-decision is recorded to `.claude/permission.decisions.local.log` (jsonl:
`{at, verdict, reason, command}`), which mirrors the peer `.local` convention and is
gitignored via `*.log`. only allow/deny are logged — a lift makes no decision (the human's own
choice is claude-cli's record). this concretely delivers the vision's G3 ("the verdicts are
recorded") rather than a lean on claude-cli's transcript. never fails the hook (best-effort
append).

### the edge case the clamp caught (and fixed)

the first test run found a real inconsistency: `rhx foo || rm -rf ~` **lifted** instead of a
deny. the deny branch caught `&` (so `&&` denies) but `||` contains only `|`, which fell
through to the rhx-clean check and lifted. safe (the redteam invariant held — never
auto-approved) but inconsistent: `&&` and `||` are both command-chains. **fixed the decider**
(added `||` to the deny branch), not the test — `||` genuinely smuggles a second command.
re-run: 31/31 green. (`rule.require.clamp-edge-cases`.)

## peer-review convergence (iteration i002)

the first peer gate (once the reviewer brain was restored) caught a **real, critical security
defect** plus several genuine gaps. all blockers fixed; convergence recorded in the per-reviewer
`.taken.by_self` files. the fixes:

- **the security bypass (r1/r2/r4 blocker) — FIXED**: the residue parser was single-quote-only,
  so `rhx foo --arg "it's a test" ; rm -rf ~` flipped `in_single` on the apostrophe, stripped
  the real `; rm -rf ~`, and AUTO_APPROVED a destructive chain. the parser now models BOTH quote
  kinds + backslash escapes (`compute_active_residue`), tracks quote balance, and the bypass
  now DENIES. the twin false-deny (`&` inside double quotes hard-denied a safe url) now APPROVES.
- **decode-friction / decomposability (r3 blockers, r4 nitpick) — FIXED**: the inline residue
  state machine and the inline classify globs are extracted into named operations —
  `compute_active_residue`, `is_command_chain`, `is_clean_rhx_call` — so the orchestrator reads
  as narrative and the phase-2 haiku swap has a clean seam behind LIFT.
- **fork drift (r2 blocker, r1/r4 nitpick) — RESOLVED**: the drifted probe fork
  `permissionrequest.auto-approve-rhx.sh` + its clamp + snapshot are deleted. the permanent
  redteam guarantee (now incl. the bypass class) lives in the shipped `src/` test against the
  real hook; the composition order is proven-once spike evidence in `findings.md`.
- **audit failhide (r2 nitpick) — FIXED**: a failed audit write now emits a one-line stderr
  note instead of a silent vanish (`|| true` → `|| printf ... >&2`), fail-safe preserved.
- **snapshot coverage (r1/r4 nitpick) — FIXED**: `toMatchSnapshot()` pins the emitted nested
  allow JSON as a schema-drift early-warn.
- **suite grew 34 → 47, all green**; the redteam invariant now covers the apostrophe-bypass class.

### the exec bit — RESOLVED (human-set) and now clamped

- **exec bit 100644 → 100755**: the shipped hook is now `100755` (the human ran the `chmod +x`
  after the driver hit the in-session `chmod` gate wall). the yield previously claimed "no
  current path is broken" — that UNDERSTATED the risk: rhachet's real registration
  (`executeInit`) bare-path-spawns the hook (`spawnSync(command, { shell: '/bin/bash' })` with
  the raw file path), which genuinely NEEDS the +x bit; without it every PermissionRequest
  silently reverts to the human prompt.
- **now regression-clamped (case7)**: a test asserts `fs.statSync(scriptPath).mode & 0o111`
  is non-zero on the shipped hook. the rest of the suite invokes via `bash [scriptPath]` (which
  ignores the +x bit), so this is the ONE case that bites if a future `Write` re-creates the
  file at 644 — it clamps the exact defect that cost five review rounds.

### the composed control stack — now covered in `src/` (r10 blocker)

- the delete of the drifted probe clamp removed the ONLY composition coverage. replaced with a
  slim `permissionrequest.compose.integration.test.ts` in `src/` that runs the REAL shipped
