# 1.vision — auto-decide claude-cli suspicious permission prompts in the hook itself

## .what

paint the world where claude-cli's suspicious permission prompts are auto-decided **inside
the hook itself** — no human in the loop for the obvious cases. the decider is *pluggable*
behind the `PermissionRequest` seam: a static allow/deny ruleset for the known
false-positive syntax, an **inline haiku call** for the novel tail, and escalate-to-human
for any unsure case. a warm reviewer clone is a later, optional latency swap — **not** a
phase-1 requirement.

> ⚠️ this is a **spike-shaped** wish. the primary deliverable is *proven knowledge* — can
> the hook API decide/suppress a suspicious prompt **at all** on claude-cli **2.1.87** (does
> the hook fire? does `allow` stick? which json schema?) — proven first with a trivial
> **'always approve'** probe, before any decider logic is wired. the decider choice (static /
> haiku / clone) is downstream of that proof.

> ✅ **PROVEN (2026-08-14, claude-cli 2.1.87)** — the spike is done. the hook fires for
> suspicious commands; an `allow` **suppresses the prompt** with the **nested**
> `decision.behavior` schema (the flat `permissionDecision` shape does NOT — that is why
> prior tests failed). a deterministic in-hook decider + composite clamp test (50/50,
> redteam-clean) are built. evidence: `probe/findings.md`; decider:
> `probe/permissionrequest.auto-approve-rhx.sh`; clamp:
> `probe/permissionrequest.clamp.integration.test.ts`. only the race (Q4) awaits a human read.

## the decision — in-hook decider, clone deferred (settled with the wisher 2026-08-14)

**question**: do we need the reviewer clone, or can the hook handle suspicious prompts
itself?

**answer**: the hook handles it **itself**. the clone is not needed for phase 1.

the hook process is ours — it can decide however we want. three candidate deciders sit
behind the same seam:

| decider | judgment | latency | dependency |
|---------|----------|---------|------------|
| static ruleset (bash/jq match) | none | ~0ms | none — self-contained |
| **inline haiku call** (the chosen decider) | full | cold, but haiku is fast (~sub-second) | none — self-contained |
| clone say/get (warm reviewer) | full | warm | the peer-worktree transport |

**why in-hook wins for phase 1**:

- the confirmed suspicious triggers (`&&`, `$()`, backticks, `|`-in-regex, quoted flags,
  process substitution) are **static and enumerable** (`research.claude-code-suspicious-syntax.md`)
  — a ruleset kills the bulk of the pain with zero latency and zero dependency.
- for the genuinely-novel tail a static list can't classify, an **inline haiku call**
  renders judgment without any external transport. haiku is the fastest model, so a single
  classify call typically lands sub-second — inside the ~2s race budget *if* the race is even
  real (Q4).
- for any command the haiku is unsure of → **escalate to the human**, which is the correct
  G4 answer on novel danger, not a regression.
- the clone's *only* edge over an inline haiku call is **warmth** (a dodge of cold-start
  against an unproven race). its cost is a whole external transport + lifecycle. that trade
  does not pay for phase 1. the clone stays a phase-3 swap behind the same seam, *only if* an
  inline call proves too slow against a **proven** race.

**the immediate deliverable** (per the wisher): a trivial **'always approve'** hook — the
static-allow probe — to prove the seam (Q0/Q1) *before* any decider logic. the haiku decider
is phase 2, wired only once `allow` is proven to stick.

## the outcome world

### day-in-the-life

a human runs a supervised claude clone on a long build task. claude reaches for a bash
command that trips claude-cli's suspicious heuristic — a `$(...)` substitution, a `&&`
compound, a `|` inside a regex (all confirmed false-positive-heavy triggers, see
groundwork). today that command **stalls**: a permission dialog pops, the clone freezes,
and the run waits — sometimes for hours — until a human wanders back to click "allow".

in the outcome world, that same command hits the `PermissionRequest` hook seam. the hook
runs a **deterministic decider** — no model, no network, no clone:

1. it strips quoted spans and reads the shell-active residue, in single-digit ms.
2. a clean single `rhx` / `npx rhachet` call (safe by design, already past the permissions
   nudge) → emits `allow` (nested schema); the clone never even notices a pause.
3. an unquoted chain (`; & && ||` newline) that smuggles a second command → emits `deny`.
4. every other case → emits **no output** → lifts to a brain (the human today, an inline
   haiku later); the fail-safe default.

the clone drives on. the human's attention is spent only on the genuinely novel — not on
the hundredth safe-but-flagged `rhx` false positive.

### before / after

| dimension | before (today) | after (outcome world) |
|-----------|----------------|------------------------|
| suspicious command | stalls the run, waits for a human | auto-decided in <2s, or escalated |
| human attention | spent on every false positive | spent only on novel/dangerous |
| unattended runs | die at the first prompt | run to completion |
| the decision | a human's gut, un-recorded | the decider's verdict, logged & auditable |
| safe `rhx` calls the classifier flags | interrupt constantly | auto-allowed in-hook (~ms) |

### the "aha" moment

the value clicks the first time a human walks away from a long unattended run, comes back
an hour later, and finds it **finished** — not frozen on prompt #3. the prompts that used
to be a human-shaped bottleneck became a decider-shaped gate that never sleeps.

the second "aha": the verdicts are *recorded*. "why did the clone run that command?"
now has an answer — the decider's logged reason — instead of a shrug.

## user experience

### usecases / goals

- **G1 — unattended autonomy**: run a supervised clone unattended and have it survive
  suspicious-classified false positives without a human babysitter.
- **G2 — attention conservation**: stop paying human attention on the same
  `&&`/`$()`/`|` false positives over and over.
- **G3 — auditable gating**: keep a recorded, reviewable trail of *why* each borderline
  command was allowed or denied.
- **G4 — safety retained**: never let the auto-gate become a rubber stamp — genuinely
  dangerous or novel commands still reach a human.

### the contract (shipped)

the seam is a **`PermissionRequest` hook**, registered in `.claude/settings.json`
alongside the extant `PreToolUse` family, invoked the same way as every other hook in
this repo. it is named `permissionrequest.decide-permissions` to complete the extant
`{verb}-permissions` family (`sessionstart.notify-permissions`,
`pretooluse.check-permissions`, now `permissionrequest.decide-permissions`):

```jsonc
// .claude/settings.json → hooks.PermissionRequest
{
  "matcher": "Bash",
  "hooks": [
    {
      "type": "command",
      "command": "./node_modules/.bin/rhachet run --repo ehmpathy --role mechanic --init claude.hooks/permissionrequest.decide-permissions",
      "timeout": 5,   // matches the peer fast pattern-match hooks; a phase-2 brain would raise this
      "author": "repo=ehmpathy/role=mechanic"
    }
  ]
}
```

**hook input** (stdin json, confirmed by docs):

```jsonc
{
  "session_id": "abc123",
  "hook_event_name": "PermissionRequest",
  "tool_name": "Bash",
  "tool_input": { "command": "git status && echo '---' && pwd", "description": "..." },
  "tool_use_id": "toolu_01...",
  "permission_mode": "default",
  "cwd": "/home/vlad/git/..."
}
```

**hook output** (stdout json — the shape is now **PROVEN**). the **nested** schema
suppresses the prompt on 2.1.87; the flat `permissionDecision` shape does NOT:

```jsonc
// ✅ proven-good on 2.1.87
{
  "hookSpecificOutput": {
    "hookEventName": "PermissionRequest",
    "decision": { "behavior": "allow" },   // | "deny"
    "reasoning": "single clean rhx call, safe by design"
  }
}
```

```jsonc
// ❌ proven-broken on 2.1.87 (the wish's + research brief's proposed shape) — prompt STILL fires
{ "hookSpecificOutput": { "hookEventName": "PermissionRequest", "permissionDecision": "allow" } }
```

**LIFT** (escalate to a brain) = emit **no output**; claude-cli falls back to the human prompt.

**the decider** (shipped at
`src/domain.roles/mechanic/inits/claude.hooks/permissionrequest.decide-permissions.sh`;
default-deny): strip BOTH single- and double-quoted spans (backslash-escape aware) to get the
shell-active residue, then —

- unquoted chain (`; & && ||` newline) → **deny**
- clean single `rhx` / `npx rhachet` call, no residue metachar → **allow**
- every other case → **lift** (a brain: human now, haiku later)

**G3 audit trail**: each auto-decision (allow/deny) appends one jsonl line —
`{at, verdict, reason, command}` — to `.claude/permission.decisions.local.log` (gitignored,
best-effort). a lift makes no decision, so it writes no line. this is the recorded, reviewable
trail G3 promises.

### what it looks like in use — a testdrive (proven, from the composite clamp)

**case 1 — auto-approve (safe rhx, no consult)**

```
claude wants: Bash(rhx sedreplace --old 'foo(bar)' --new 'baz' --glob 'src/**/*.ts')
  └─ PermissionRequest hook fires   (parens tripped the classifier, proven)
       ├─ decider: single clean rhx call, parens are quoted data
       └─ emits { decision: { behavior: "allow" } }   (~ms)
  ↳ command runs, no dialog   → harness: "Allowed by PermissionRequest hook"
```

**case 2 — auto-deny (an unquoted chain smuggles a 2nd command)**

```
claude wants: Bash(rhx foo && rm -rf ~)
  └─ PermissionRequest hook fires
       ├─ decider: unquoted && chains a second command → deny
       └─ emits { decision: { behavior: "deny" }, ... }
  ↳ fail-safe by design (NOT yet live-traced): the emit is proven-safe, not
     proven-silent-block. a DENY can never DOWNGRADE to auto-approve, so the
     worst case is a fall-back to the human prompt (the "before" state). whether
     the deny SUPPRESSES the prompt or defers to the human on 2.1.87 is an open
     empirical item — see probe/findings.md "DENY live behavior" (Q13) and the
     question register below. contrast case 1 (allow), which IS live-traced.
```

**case 3 — hard-block upstream (injection form, never reaches the seam)**

```
claude wants: Bash(rhx foo $(rm -rf ~))
  └─ PreToolUse forbid-suspicious-shell-syntax fires FIRST → exit 2
  ↳ blocked before PermissionRequest is ever reached
```

> caveat (see edgecase table): the forbid hook's own parser is single-quote-only, so an
> earlier unpaired `'` (e.g. `rhx foo --arg "it's a test" $(rm -rf ~)`) can slip the `$(`
> past it to the seam. THIS decider's both-quote-aware residue still keeps the `$(` active
> and **lifts** it (never auto-approves) — the auto-approve invariant holds; only
> defense-in-depth degrades (hard-block → human prompt). flagged for a forbid-hook pass.

**case 4 — lift to a brain (fail-safe default)**

```
claude wants: Bash(rhx foo | bash)   (pipe to a shell — not a clean single rhx call)
  └─ PermissionRequest hook fires
       ├─ decider: residue has a pipe → not clean → lift
       └─ emits no output → claude-cli falls back to the human prompt
  ↳ human decides today; an inline haiku decides later
```

**case 5 — settings-deny (blocked before any hook)**

```
claude wants: Bash(grep foo file.txt)
  └─ matches permissions.deny "Bash(grep:*)" → blocked at the settings layer
  ↳ never reaches a hook at all
```

### the composed control stack (proven order)

```
settings.deny  →  PreToolUse forbid  →  PermissionRequest decider  →  settings allow/ask/default
(grep, ls,        ($() backtick <(       (clean rhx = allow;           (rhx:* = allow,
 git commit)       > redirect = block)     chain = deny; else = lift)    chmod = ask)
```

### timelines

- **decider verdict**: single-digit ms — a bash pattern match, no model, no network.
- **lift**: whatever the human takes, same as today.
- **the race (Q4)**: only relevant to a *future* inline-haiku decider (~1-2s). the static
  decider is far under any threshold; whether haiku is too slow awaits the `slow`-mode read.

## mental model

### how a human describes it to a friend

> "you know how claude keeps stopping to ask 'are you sure?' on commands that are totally
> fine? i wired up a bouncer with a rulebook that answers those for me. safe stuff it waves
> through, sketchy stuff it stops, and weird stuff it still kicks up to me (a smarter
> bouncer comes later)."

### analogies

- **a bouncer with a rulebook** — obvious regulars walk in (clean `rhx` → allow), a smuggled
  second command gets turned away (chain → deny), and when the rulebook can't classify, the
  bouncer calls the manager (lift to a brain — human now, haiku later).
- **a spam filter for permission prompts** — the inbox (human attention) only sees what
  the filter couldn't confidently auto-sort.
- **a code-review bot for runtime actions** — instead of a review of a diff before merge, it
  reviews a *command* before execution.

### their words vs our words

| human says | we say |
|------------|--------|
| "the are-you-sure popup" | `PermissionRequest` prompt / suspicious-classified tool call |
| "the bouncer" | in-hook decider (deterministic now; a brain later) |
| "wave it through" | `decision.behavior: "allow"` (nested schema) |
| "turn it away" | `decision.behavior: "deny"` |
| "kick it to me" | lift — emit no output, fall back to the human prompt |
| "the safe list" | clean single `rhx` / `npx rhachet` call, no unquoted chain |
| "a smarter bouncer" | phase-2 inline haiku, phase-3 warm clone (both deferred) |
| "don't let it review itself" | (phase-3, clone only) loop-guard on `RHACHET_CLONE_SERIAL` |

## evaluation

### how well it solves the goals

| goal | verdict | note |
|------|---------|------|
| G1 unattended autonomy | **strong — seam proven** | `allow` sticks on 2.1.87 (nested schema); clean `rhx` auto-approves |
| G2 attention conservation | **strong** | the deterministic decider alone kills the bulk of false positives |
| G3 auditable gating | **strong** | decider verdicts are logged by construction |
| G4 safety retained | **strong** | default-deny; phase 1 auto-approves ONLY clean `rhx`, everything else denies or lifts |

### pros

- **fail-safe by construction**: any hook failure (bad json, timeout, non-zero exit) →
  fall back to the human prompt. the easy failure path is the *safe* path (pit of success).
- **rides extant infra**: hook registration, `rhachet run --init` invocation, and
  `.integration.test.ts` testing all already exist — only the `PermissionRequest` event
  type and the decider are new.
- **zero external dependency**: the phase-1 decider is a bash pattern match — no model, no
  socket, no clone. it delivers value standalone; a brain is a later, optional swap.
- **the brain is behind the same seam**: phase 2 (inline haiku) and phase 3 (warm clone)
  drop in behind the decider without a contract change.

### cons

- **phase-1 autonomy is deliberately narrow** — only a clean single `rhx` auto-approves, so
  many flagged commands still lift to a human until the brain lands. that is the safe trade,
  not a bug, but G1 is only *partly* delivered until phase 2.
- **the race (Q4) bounds the future brain, not phase 1** — a haiku/clone verdict (~1-2s)
  *could* exceed the race budget; the deterministic decider (single-digit ms) cannot. so the
  race is a phase-2 gate, still un-read (see Q4), not a phase-1 risk.
- **auto-approval is a security surface** — phase 1 caps the blast radius by auto-approving
  ONLY clean single `rhx` calls (safe by design); a future brain widens the surface and must
  stay conservative, keeping novel/dangerous cases lifted.
- **schema drift across versions** — a shape that works on 2.1.87 may break on the next
  claude-cli bump. this hook is coupled to an undocumented/unstable contract; the
  `.integration.test.ts` snapshot is the early-warning.

### edgecases & pit-of-success

| edgecase | how the contract keeps us safe |
|----------|-------------------------------|
| safe `rhx` call the classifier flagged | decider auto-approves in-hook (~ms) — clean single call, quoted metachars are inert data |
| unquoted chain smuggles a 2nd command | decider denies (`; & && ||` newline in the residue) |
| injection form (`$()` backtick `<()` `>`) | hard-blocked upstream by `PreToolUse forbid-suspicious-shell-syntax` (exit 2) — never reaches the seam. **caveat**: the forbid hook's `appears_executable` parser is single-quote-only, so an earlier unpaired `'` (e.g. `"it's a test"`) can throw off its parity and let a `$(` reach the seam — where THIS decider's both-quote-aware residue keeps the `$(` active and **lifts** (never auto-approves). so the auto-approve invariant holds even on the forbid parser's blind spot; the loss is a defense-in-depth downgrade (hard-block → human prompt), flagged for a dedicated pass to harden the forbid hook (a shared `compute_active_residue` lib sourced by both hooks). |
| decider can't classify (pipe, odd shape) | lifts to a brain — emit no output → human prompt today, haiku later |
| hook itself errors (bad json, non-zero exit, timeout) | claude-cli falls back to the human prompt (fail-safe) |
| tool already in `permissions.allow` | hook **never fires** (confirmed) — the settings allowlist wins upstream |
| claude-cli version bump changes schema | `.integration.test.ts` snapshot catches the drift; fail-safe still lifts meanwhile |
| (phase-3, brain) brain slower than the race threshold | decision lost → dialog fires → human decides (no worse than today) |
| (phase-3, clone) reviewer reviews its own command | `RHACHET_CLONE_SERIAL` loop-guard → immediate exit, normal flow |

## open questions & assumptions

### the load-bearing unknown (the blocker) — ✅ RESOLVED

**Q0 — does an `allow` decision actually suppress the prompt on 2.1.87?** → **YES, proven**
— but only with the **nested** `decision.behavior` schema. the flat `permissionDecision`
shape (this wish's original proposal) does NOT suppress, which is exactly why prior tests
reported "no." the oracle was the harness line `Allowed by PermissionRequest hook`, not "the
command ran" (see the measurement trap in `probe/findings.md`). **Q1** (does it fire?) and
**Q2** (which schema?) are likewise resolved. only **Q4** (the race) remains — see below.

### assumptions we've made

- **A1** (phase 1, **PROVEN**): `PermissionRequest` (not `PreToolUse`) is the event that
  reaches suspicious-classified prompts. the probe confirmed the hook fires for a suspicious
  command. (contrast: hard auto-mode *denials* fire a separate `PermissionDenied` event —
  not our seam.)
- **A2** (phase-2/3, deferred): a brain can render a verdict inside the race budget. **not
  required for phase 1** — the deterministic decider is single-digit ms. gated on Q4 before
  an inline haiku is trusted.
- **A3** (phase-3, deferred): `RHACHET_CLONE_SERIAL` is injected into every spawned clone's
  env. **currently false** — not found in the codebase; only relevant once the clone swap is
  wired.
- **A4** (phase-3, deferred): the clone `say`/`get` socket transport will exist. **currently
  false** — no `clone say`/`clone get`, no `@:reviewer`, no socket in the repo today. not a

## groundwork

sanity check against reality — not exhaustive, just enough to know the vision isn't built
on false assumptions.

### external research

verified against official docs + the repo's own research brief:

- **`PermissionRequest` hook exists and fires at the human-prompt seam.**
  cited: [claude hooks docs](https://code.claude.com/docs/en/hooks). stdin carries
  `tool_name`, `tool_input`, `session_id`, `permission_mode`, `cwd`, `tool_use_id`.
- **schema drift is real and unresolved.** the repo's research brief
  (`.agent/repo=.this/role=any/briefs/research.claude-code-suspicious-syntax.md:117-147`)
  and the wish both use the flat `{ hookSpecificOutput: { permissionDecision: "allow" } }`
  shape (community workaround, issue #30435, *not officially documented*). newer docs
  (v2.1.222) show a nested `{ decision: { behavior: "allow"|"deny"|"escalate" }, reasoning }`
  shape. **the 2.1.87 target sits between these two — which one it honors is unproven.**
- **fail-safe default confirmed**: invalid json, non-zero exit, or timeout → escalate to
  normal permission flow. good for pit-of-success.
- **allowlist bypass confirmed**: a tool matching `permissions.allow` is auto-approved and
  the `PermissionRequest` hook **does not fire** — so the in-hook decider is a *distinct*
  mechanism from `settings.json` allow (the decider only ever sees what settings did not
  already approve).
- **the race (#12176)**: official docs claim a clean timeout (default 600s, recommend <5s)
  with no race; the community issue claims a ~2s dialog-fires-anyway race. **contradiction
  → must validate empirically on 2.1.87.** the wish flags this and the probe plan isolates
  it (static allow first, then add `sleep 3`).
- **caveat carried from the wish**: issue numbers (#12176, #19298, #18312, #36168) came
  from web search — verify version ranges via `gh issue view` if a design decision hinges
  on them. not yet independently verified in this pass.

  `src/domain.roles/{role}/inits/claude.hooks/{hookType}.{name}.sh`, register in
  `.claude/settings.json` (`hooks.PreToolUse`, etc.), invoke via
  `rhachet run --repo X --role Y --init claude.hooks/NAME`, and test via
  `.integration.test.ts`. the new hook conforms to this pattern exactly.
- **`.claude/settings.json` has no `PermissionRequest` section yet** — only `SessionStart`,
  `PreToolUse`, `Stop`, `PostCompact`. adding one is net-new but structurally trivial
  (`.claude/settings.json:2-227`).
- **closest analog is present**: `pretooluse.check-permissions.sh` already reads stdin json,
  matches on `tool_input.command`, and gates — but it exits `2` to block and does **not**
  emit `hookSpecificOutput` today. the auto-review hook is a sibling that *does* emit the
  decision json.
- **vocab / patterns to reuse**: `permissionDecision` / `hookSpecificOutput` /
  `hookEventName` (from the research brief), the `type/command/timeout/author` hook-entry
  shape, the `ConstraintError`/`MalfunctionError` exit-code semantics (2 = constraint,
  1 = malfunction) for the hook's own failures.

## what is awkward?

- **the load-bearing fact is now proven — but phase 1 is deliberately small.** the seam
  works (Q0), so the outcome world is no longer contingent. the honest caveat now: phase 1
  auto-approves only clean `rhx`, so the rich "never frozen again" world only fully arrives
  once the brain lands. phase 1 is the beachhead, not the whole beach.
- **the phased split is clean, but the payoff is staged.** the deterministic decider (phase
  1) needs no clone, no socket, no race budget — a cheap, certain win. the brain (phase 2/3)
  carries the judgment for the novel tail but also the cost and the race. the value is real
  at phase 1 and grows with each phase; the risk is a reader mistakes phase-1 breadth for the
  whole vision.
- **the race budget fights the *future* brain, not phase 1.** a real brain rendering judgment
  over a call is exactly what could blow a 2s budget — but that tension lives entirely in
  phase 2/3. the phase-1 decider is a sub-ms pattern match, so the tension is deferred, not
  erased.
- **auto-removing the human from a security decision is philosophically uncomfortable.** the
  feature's value *is* its risk: the more prompts it silences, the more it becomes the thing
  that could silence a dangerous one. phase 1 caps this to clean `rhx` only; the discomfort
  grows exactly as the brain widens the surface.
- **we're coupled to an undocumented, drifting contract.** the proven schema is a community
  workaround on an unstable surface; a claude-cli bump can silently break it. the
  `.integration.test.ts` snapshot is our early-warning, but we build on sand the vendor can
  shift.
