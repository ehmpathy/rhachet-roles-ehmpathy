# 1.vision — fix: ban yeller readme

> illustrate the vision implied in the wish: stop clones from ignoring `readme.md` and
> from spawning redundant shouted `README.md` files. do it two ways — a ref-level rule
> that teaches, and a hook that enforces.

---

## the outcome world

### day-in-the-life

a clone lands in a repo, needs orientation. instinct says "read the README".

**before** — the clone runs `Read README.md`. the file is absent (the repo uses
`readme.md`). the clone concludes "there's no readme here" and either:
- proceeds blind, missing the repo's own house rules, or
- worse, "helpfully" runs `Write README.md` to create one — now the repo has two
  readmes, a shouted duplicate that drifts from the real `readme.md`. sad. 😢

**after** — the clone runs `Read README.md`. the hook catches it *before* the read
executes and redirects:

```
🛑 BLOCKED: Read to README.md

this repo uses readme.md (lowercase) — README.md does not belong here.

  Read readme.md

why: shouted filenames (README.md) violate rule.forbid.shouts.
     one canonical readme per repo, always lowercase.
```

the clone reads `readme.md`, gets oriented, never creates a duplicate. the repo stays
clean with exactly one readme.

### before/after contrast

| moment | before | after |
|--------|--------|-------|
| clone looks for readme | reads `README.md`, finds no file, gives up | redirected to `readme.md`, finds it |
| clone wants to add a readme | writes `README.md`, spawns a duplicate | blocked, told to use `readme.md` |
| repo readme count | drifts to 2 (`README.md` + `readme.md`) | stays 1 (`readme.md`) |
| the rule | buried as one row in `rule.forbid.shouts` | dedicated ref brief, discoverable by name |

### the "aha" moment

the value clicks the first time a clone *would have* created `README.md` and instead
gets nudged to the file that was there all along. the hook converts a silent failure
("no readme here") into a loud, self-correcting redirect. the clone doesn't just
avoid the mistake — it learns where the real readme lives.

## user experience

the "user" here is a **clone** (an agent operating in the repo). the human is a
secondary beneficiary — they stop finding stray `README.md` files in diffs.

### usecases / goals

1. **orient in a repo** — clone wants to read the readme; must land on `readme.md`
2. **author a readme** — clone wants to write a readme; must write `readme.md`
3. **not pollute** — clone must never leave a shouted `README.md` behind

### contract inputs & outputs

two contracts, layered (teach + enforce):

#### contract 1 — the ref rule (teaches)

- **input**: a clone reading briefs, or a reviewer checking a filename
- **output**: `rule.forbid.shouted-readme` (ref-level brief) — explains *why* `readme.md`
  over `README.md`, with the redirect guidance
- **leverage**: loaded on demand (ref, not say — no context bloat); cited by the hook
  and by reviewers when a `README.md` slips into a diff

#### contract 2 — the pretooluse hook (enforces)

- **input**: a `PreToolUse` json payload for `Read` / `Write` / `Edit` whose
  `file_path` basename is `README.md`
- **output**: exit `2` with a redirect message to stderr, pointing at `readme.md` and
  citing the rule
- **leverage**: the clone cannot bypass it — the read/write is blocked *before* it runs

### what it looks like to leverage them

```
# clone attempts:
Read  README.md          → blocked, redirected to readme.md
Write README.md          → blocked, redirected to readme.md
Edit  README.md          → blocked, redirected to readme.md
Read  readme.md          → allowed ✓
Read  docs/README.md     → blocked, redirected to docs/readme.md (nested repo-local)
Read  node_modules/x/README.md → allowed ✓ (third-party, not ours)
```

### timeline

instant. the hook fires synchronously on the tool call; the clone gets the redirect in
the same turn and retries against `readme.md`.

> and points you at `readme.md`. so you can't accidentally make a second one."

|----------|--------|

## evaluation

### how well it solves the goals

- **stops redundant `README.md` creation** — hook blocks `Write`/`Edit` outright ✓
- **stops "readme is absent" false conclusions** — hook redirects `Read` to the
  real file ✓
- **teaches, not just blocks** — the ref rule gives the *why*; the hook cites it ✓

### pros

- **two layers**: the rule teaches (durable, cited), the hook enforces (unbypassable)
- **reuses the proven hook pattern** (`pretooluse.forbid-tmp-writes.sh`) — low risk
- **ref-level rule = zero context cost** until needed
- **self-correcting**: the redirect makes the fix obvious in the same turn

### cons

- **another hook** to maintain + register in `.claude/settings.json`
- **potential overlap** with extant `rule.forbid.shouts` (which already lists
  `README.md`) — risk of two rules saying near the same thing
- **scope nuance**: node_modules and nested `docs/README.md` need careful handling or
  the hook creates false-positive friction

### edgecases & pit-of-success

| edgecase | pit-of-success handling |
|----------|-------------------------|
| `node_modules/**/README.md` | **allow** — third-party readmes are not ours; `get.package.docs` reads them legitimately |
| `README.md` at repo root | **block + redirect** — this is the core case |
| `docs/README.md` or any nested repo-local | **block + redirect** (wisher-confirmed) — the ban is repo-wide, any repo-local `README.md` is caught, not just root |
| `.git/**` or other vendored dirs | allow — not authored by us |
| case-insensitive filesystems (macos) | `readme.md` and `README.md` collide on disk; the hook still guides the clone to type the lowercase form |
| clone reads `readme.md` correctly | allow silently — no friction on the happy path |

## open questions & assumptions

### assumptions

1. the hook is hosted in the **mechanic** role (`mechanic/inits/claude.hooks/`),
   alongside the extant forbid-* hooks — that's where the pattern and registration live
2. "ref level" means a **ref brief** (path-only in boot, fetched on demand), not a
   `say` brief loaded fully into context
3. the rule applies **repo-wide to any clone**, not just mechanic-role work
4. `readme.md` (lowercase) is the established canonical form (confirmed: extant
   `rule.forbid.shouts` already prescribes it)

### open questions (triaged)

1. **[answered] scope of the ban** — *any* repo-local `README.md`, but **not** those under
   `node_modules/**` or vendored dirs (`.git`, `dist` mirrors of packages). answered by
   logic + reality: a Glob found hundreds of `README.md`/`readme.md` under `node_modules`,
   so a blanket ban would break third-party doc reads and `get.package.docs`. repo-local
   scope is mandatory, not optional.
2. **[answered] relationship to `rule.forbid.shouts`** — the new ref rule **cross-references
   `shouts` as parent** and earns its place with a delta `shouts` lacks: the
   *redirect-to-`readme.md`* behavior + status as the hook's cited authority. this avoids
   the synonym trap (architect's `rule.forbid.term.addition.synonym`).
3. **[answered] which role hosts it** — **mechanic** (pragmatic — the forbid-* hook
   pattern and registration already live there). runtime coverage is universal regardless
   of host, because `.claude/settings.json` hooks fire by matcher, not by active role
   (verified). the only real tradeoff is src ownership; mechanic is the low-friction call.
4. **[answered — wisher-confirmed] readme-only** — the ban covers `README.md` only, no
   `CHANGELOG.md`/`LICENSE`/`TODO.md`. wisher decided "only readme's for now"
   (2026-07-18). the broader shouted-doc class (e.g. the extant `LICENSE` duplicate)
   is out of scope for this behavior; `rule.forbid.shouts` still covers it advisorily.
5. **[research] github lowercase readme** — confirm github shows a lowercase `readme.md` as
   the repo/dir front page (case-insensitive match). i hold this as known and the repo
   already runs on `readme.md`, but a 30-second web check in the research phase closes it
   fully. low risk.

## groundwork

### external research

none — no external apis, services, or docs. this is entirely internal tooling
(claude-code pretooluse hooks + role briefs).

### internal research

extant behavior this extends — verified:

- **hook pattern** — `src/domain.roles/mechanic/inits/claude.hooks/pretooluse.forbid-tmp-writes.sh`
  (read in full). confirmed contract: reads json from stdin, extracts `.tool_name`,
  short-circuits unless `Write`/`Edit`/`Read`/`Bash`, extracts
  `.tool_input.file_path`, blocks with stderr message + `exit 2`. this is the template
  the readme hook will follow.
- **stdout/redirect format** — the tmp-writes hook emits a `🛑 BLOCKED: <Tool> to <path>`
  header, blank line, guidance, then the alternative. the readme hook mirrors this.
- **extant rule** — `src/domain.roles/mechanic/briefs/practices/lang.tones/rule.forbid.shouts.md`
  (read in full). already prescribes `README.md → readme.md` (line 69) and
  `CHANGELOG.md`, `LICENSE`, `TODO.md`. the new rule is a **focused, hook-cited**
  extension, not a contradiction. relationship must be declared (open question 2).
- **rule naming convention** — `rule.{directive}.{topic}.md` with directive ∈
  {require, prefer, avoid, forbid} (per enroller `rule.require.rule-directive-prefix`).
  proposed: `rule.forbid.shouted-readme.md`.
- **test convention** — `rule.require.jest-tests-for-skills` forbids `.test.sh`, mandates
  `.integration.test.ts`. despite extant `.test.sh` files (e.g.
  `pretooluse.forbid-terms.gerunds.test.sh`), the new hook gets a jest
  `.integration.test.ts` with snapshots.
- **registration** — hooks wire into `.claude/settings.json` under `hooks.PreToolUse`;
  `.claude/settings.json` is already modified on this branch.
- **src → dist → .agent flow** — edit in `src/`, run `npm run build`, runtime symlinks
  `.agent/` to `dist/` (per `repo.structure` brief).

### the term "yeller"

the branch/wish calls it "yeller readme" (shouted). our vocabulary already uses
**"shouts"** (`rule.forbid.shouts`). for the rule filename, prefer alignment with the
established term: `shouted-readme` reads truer to our ubiqlang than `yeller-readme`.
flag for the wisher (open question, minor).

## what is awkward?

- **duplication risk with `rule.forbid.shouts`** — that rule *already* bans `README.md`.
  a second rule that says "don't shout the readme" feels redundant unless it earns its
  place by (a) being the hook's cited authority and (b) adding the *redirect-to-readme*
  behavior that shouts doesn't cover. the framing must make the delta explicit, or it
  smells like a synonym rule.
- **role placement tension** — the behavior is universal ("any clone"), but the hook
  machinery lives in mechanic. hosting a universal rule inside one role is a slight
  mismatch between scope and home.
- **node_modules exclusion** — the happy-path hook is trivial; the *correctness* lives
  entirely in the exclusion logic. get it wrong and we either leak (`README.md` slips
  through in nested dirs) or over-block (`get.package.docs` breaks on third-party
  readmes). the awkwardness is that the edgecase handling is the whole game.
- **"yeller" vs "shouts"** — introducing "yeller" as a near-synonym for our established
  "shouts" would itself lightly violate the ubiqlang synonym rule. prefer to land on
  "shouted".
