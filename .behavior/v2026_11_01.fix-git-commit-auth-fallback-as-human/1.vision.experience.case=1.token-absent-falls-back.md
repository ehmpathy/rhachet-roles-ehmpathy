# case=1 — bot token absent, default auth, falls back to as-human

cell g2 (render r3 in json) · happy · critipath · clamp caseA

## .narrative

a clone already holds a seaturtle commit on its branch, on a seat with no ehmpath keyrack. it runs `git.commit.push --mode apply`, no `--auth`. it sees the push land, then the pr open, and reads why on the `opened:` line: the bot token was unavailable, so the seat's own gh login opened it. exit 0. it moves on to `git.release --watch`. it never had to remember `--auth as-human`, and no human reads a guide. (the composed `git.commit.set --push` walk is `case=7`.)

## .bdd

```
given('[caseA] bot token absent from the keyrack, default auth')
  when('[t0] git.commit.push --mode apply')
    then('exit 0')
    then('gh pr list and gh pr create run with no GH_TOKEN')
    then('the opened line names as-human and the cause: token unavailable')
  when('[t1] the keyrack call times out (EXTERNAL_CALL_TIMEOUT) instead')
    then('the same fallback; detail names the timeout')
  when('[t2] git.commit.push --mode apply --output json')
    then('stdout json: auth = as-human, auth_fallback.cause = token-unavailable; exit 0')
```
