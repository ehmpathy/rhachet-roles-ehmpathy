# case=3 — bot auth works, no fallback

cell g1 (and g5, same walk) · happy · critipath · clamp caseC

## .narrative

a clone finishes a fix in a repo where the ehmpath app is installed and its keyrack is unlocked. it runs `git.commit.push --mode apply`, no `--auth`. it watches the tree come back and sees the pr open under the seaturtle bot: `opened: as-ehmpath (ehmpath keyrack)`. it reads no fallback note, because none happened. the tree looks exactly like yesterday's. the clone moves straight to `git.release --watch`.

## .sketch

```
   ├─ pr: pr #42 (created)
   ├─ opened: as-ehmpath (ehmpath keyrack)
```

## .bdd

```
given('[caseC] bot token present and accepted, default auth')
  when('[t0] git.commit.push --mode apply')
    then('every gh pr op carries GH_TOKEN')
    then('exit 0; the opened line reads as-ehmpath; no fallback text')
  when('[t1] the same, with explicit --auth as-ehmpath')
    then('identical walk and render')
  when('[t2] git.commit.push --mode apply --output json')
    then('stdout json: auth = as-ehmpath, auth_fallback = null; exit 0')
```
