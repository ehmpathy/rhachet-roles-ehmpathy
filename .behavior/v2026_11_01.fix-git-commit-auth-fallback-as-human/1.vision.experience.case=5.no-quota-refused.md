# case=5 — no push quota, refused as today

cell t1p (t1s on set: same refusal, before the commit) · sharp · critipath · clamp caseE

## .narrative

a clone whose human granted commits but not pushes runs `git.commit.push --mode apply`, default auth, on a seat with no keyrack token. it sees `bummer dude`, `push not allowed`, and a hint to ask its human for `--push allow`, exactly as yesterday. no fallback line appears, because the run never got as far as a pr. the fallback moves identity; it never opens a gate.

the same clone, in its usual flow, runs `git.commit.set -m @stdin --mode apply --push` instead. set refuses before it makes a commit: `push not allowed in current grant`. its staged files stay staged, its commit quota stays whole, and it asks its human for the grant.

## .bdd

```
given('[caseE] push not allowed in .meter, bot token absent, default auth')
  when('[t0] git.commit.push --mode apply')
    then('exit 2; "push not allowed"; the grant hint names git.commit.uses')
    then('no git push, no gh call, no fallback text')
  when('[t1] git.commit.set -m @stdin --mode apply --push')
    then('exit 2; "push not allowed in current grant" (git.commit.set.sh:800)')
    then('no commit made; quota unchanged; no keyrack fetch, no gh call, no fallback text')
```
