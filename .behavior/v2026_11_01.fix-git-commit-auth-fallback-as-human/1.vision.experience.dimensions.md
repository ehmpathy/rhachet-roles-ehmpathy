# 1.vision.experience.dimensions

the experience space of a pr-open after `git.commit.set --push` or `git.commit.push --mode apply`.

## .dimensions

| # | dimension | values (closed) | orthogonal because |
|---|---|---|---|
| A | actor | clone at its seat · human direct at its seat · headless seat (a cron or ci job, gh logged in as a service account) · human who reviews the pr later | who lives the walk. the first three drive D1–D8 the same way; the headless seat differs only in that no one reads a guide live (its exit code is the signal). the last only reads the result |
| D1 | auth source | default (no `--auth`) · explicit `as-ehmpath` · explicit `as-human` | set by the caller's args alone |
| D2 | bot token state | accepted · accepted with a foreign bot id (an app token whose live identity ≠ the roster, `assert_token_identity_in_sync`) · unavailable (absent key, keyrack timeout, keyrack failure — `fetch_github_token` returns empty for all three) · refused (401 / 403 / not accessible by integration) | set by the keyrack and the target org alone. **consulted only when D1 ≠ explicit as-human** (see .the D1 × D2 relation) |
| D3 | seat gh login | usable · absent | set by the seat's `gh auth login` alone |
| D8 | gh op result, once a credential is accepted | success · non-auth failure (protected branch, rate limit, no commits between) | set by the repo and github state, not by who asks. it splits from D2 so a token state never hides an op failure |
| D4 | gates | all open · push quota absent · global block · org block · sponsor absent (set only) · author guard · branch guard · open-hours (outside this repo) | set by `.meter` files, the sponsor bind, and git state, all independent of auth |
| D5 | entry | `git.commit.push` standalone · `git.commit.set --push` composed | set by which skill the actor calls |
| D6 | output | tree · json | set by push's `--output` alone. the set entry exposes no `--output`, so `set × json` is impossible by nature (r9): a latent "does the entry offer json?" sub-axis, which only push answers yes |
| D7 | mode | apply · plan | set by `--mode` |

## .the D1 × D2 relation

D2 is a real axis, but push.sh reads the token only when D1 asks for the bot. so `explicit as-human × D2` is **impossible by nature**: no token is fetched, so no token state exists to vary. those cells are verdicted `impossible`, not hidden as `n/a`. D3 still varies under explicit as-human, since that mode IS a seat-login attempt. every other pair varies freely.

## .the walked product

**core grid** — D1 × D2 × D3, with A = clone, D4 = all open, D5 = standalone, D6 = tree, D7 = apply:

| D1 \ D2 | accepted | accepted, foreign bot id | unavailable | refused |
|---|---|---|---|---|
| default | as-ehmpath, no fallback line | hard stop, exit 2 (F4) | fallback as-human, named | one retry as-human, named |
| explicit as-ehmpath | as-ehmpath | hard stop, exit 2 | guide + exit 2 (today) | `pr creation failed` + exit 2 (today) |
| explicit as-human | impossible | impossible | impossible | impossible |

D3 splits three rows of cells:
- default × unavailable / refused: usable → the fallback opens the pr; absent → the as-human attempt fails too → the two-fix guide, exit 2.
- explicit as-human (no D2): usable → the pr opens as-human; absent → the two-fix guide, exit 2.
- every bot-path cell (accepted, foreign id, explicit as-ehmpath): D3 is not read. the bot opens the pr, or the run stops before any seat-login attempt.

the foreign-bot-id column stops on the extant guards (`git.commit.push.sh:536,573`), whichever D1 read the token.

**op-result walk** — D8 = non-auth failure, crossed with each auth that reaches a gh op:

| auth that reached the op | D8 non-auth failure → |
|---|---|
| bot (default or explicit, token accepted) | real cause as `pr creation failed: …`, exit 2, no retry (extant path) |
| as-human after a fallback (D3 usable) | real cause, exit 2; the `opened:` line still names the fallback; no two-fix guide, since the login works |
| explicit as-human | real cause, exit 2 (extant push case27) |

**gate walk** — each D4 refusal value × D5 entry × any D1/D2/D3: refused at its guard before the token is read. one verdict per (gate, entry). where each gate lives:

| gate | `git.commit.push` standalone | `git.commit.set --push` |
|---|---|---|
| push quota | push.sh `:353-366` | set.sh `:800`, before the commit |
| global / org block | push.sh `:268-342` | set.sh `:709,737` |
| sponsor | impossible (nature) — push authors no commit, reads no sponsor | set.sh `:850-985`, above the fetch |
| author guard | push.sh `:369-385` | always passes — set authors as seaturtle itself, then push.sh runs the guard |
| branch guard | push.sh `:387-403` | set.sh `:611-623` refuses on the base branch before any commit |
| open-hours | outside this repo | outside this repo |

**render walk** — each default-auth critipath outcome × D5 × D6. D7 = plan collapses: plan reads no token and calls no gh, so every D2 value renders the same plan.

| outcome \ (D5, D6) | push, tree | push, json | set, tree | set, json |
|---|---|---|---|---|
| no fallback (accepted) | `opened: as-ehmpath …` | `auth: as-ehmpath`, `auth_fallback: null` | set relays `opened:` | impossible — set has no `--output json` |
| fallback, unavailable | `opened: as-human (fallback: … unavailable)` | `auth: as-human`, `auth_fallback.cause: token-unavailable` | set relays the same line | impossible |
| fallback, refused | `opened: as-human (fallback: … refused — http 403)` | `auth: as-human`, `auth_fallback.cause: token-refused` | set relays the same line | impossible |
| both auths fail | two-fix guide, exit 2 | `{status: error}` on stdout, guide on stderr, exit 2 | set replays the guide, `push: ✋ ConstraintError`, exit 2 | impossible |

`set, json` is impossible by nature: `git.commit.set` takes no `--output` flag. the push json is set's internal seam, and the `push, json` column already covers it.

explicit-auth outcomes on the set entry: set forwards the explicit `--auth` to push.sh unchanged (F1), so each explicit cell of the core grid renders on set as push renders it, replayed through set's tree.
