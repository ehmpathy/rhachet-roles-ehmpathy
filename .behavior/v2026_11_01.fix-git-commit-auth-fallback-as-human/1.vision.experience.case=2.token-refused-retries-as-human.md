# case=2 — bot token refused by gh, default auth, one retry as-human

cell g3 (render r5 in json) · happy · critipath · clamp caseB

## .narrative

a clone pushes to an org where the ehmpath app is not installed. the keyrack hands over a token. gh refuses it: `HTTP 403: Resource not accessible by integration`. the skill retries the pr op once, as-human. the pr opens. the `opened:` line names the refusal. exit 0.

## .sketch

```
   ├─ pr: pr #42 (created)
   ├─ opened: as-human (fallback: ehmpath bot refused — http 403)
```

## .bdd

```
given('[caseB] bot token present, gh refuses it with 403 / not accessible by integration')
  when('[t0] git.commit.push --mode apply, default auth')
    then('the first gh pr op carries GH_TOKEN; the retry carries none')
    then('exactly one retry')
    then('exit 0; the opened line names as-human and the refusal')
  when('[t1] gh refuses at pr create, after pr list succeeded under the bot')
    then('only pr create retries as-human; same render')
  when('[t2] the as-human retry hits a non-auth failure (protected branch)')
    then('exit 2; the real gh cause is shown as pr creation failed')
    then('the opened line still names the fallback')
    then('no two-fix guide: the seat login worked, so re-auth is no fix')
    then('no second retry')
  when('[t3] git.commit.push --mode apply --output json, refused as in [t0]')
    then('stdout json: auth = as-human, auth_fallback.cause = token-refused, detail = "http 403"; exit 0')
```

## .boundaries

- refusal = gh's auth signatures (401, bad credentials) plus the access signatures (403, not accessible by integration)
- a non-auth gh failure (protected branch, no commits, rate limit) never triggers the retry
- the retry runs on whichever op the bot was refused at: `pr list` or `pr create`
