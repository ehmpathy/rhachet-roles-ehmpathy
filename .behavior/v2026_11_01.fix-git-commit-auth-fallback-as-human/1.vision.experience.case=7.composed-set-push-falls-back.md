# case=7 — `git.commit.set --push`, default auth, token absent, falls back through the composer

cell r4 · happy · critipath · clamp caseA (on set) · densest cell

## .narrative

the common call. a clone finishes a fix on a seat with no ehmpath keyrack and runs `git.commit.set -m @stdin --mode apply --push`, the way it always does. no `--auth` to remember. a heads-up flashes on stderr: the keyrack token wasn't fetched, so the commit authors as the default seaturtle. then the tree lands with `cowabunga!`: its commit under seaturtle[bot], the push ✓, pr #42 created, and one line that tells it why the pr reads differently today: `opened: as-human (fallback: ehmpath bot token unavailable)`. its meter dropped by one, as on any shipped push. it follows the release-watch hint and moves on. yesterday this same call ended in a guide and an exit 2.

## .boundaries

the walk crosses: set arg parse → keyrack miss → commit author pick → token thread (`SEATURTLE_PR_TOKEN_PREFETCHED=1`, value `""`) → push.sh reads no `--auth` (F1), so the default → fallback → gh as-human → json `auth: as-human` + `auth_fallback` → set relays the `opened:` line.

the stderr heads-up is extant (`git.commit.set.sh:1035-1038`). it names the author consequence; the `opened:` line names the pr consequence. two facts, one cause, on two streams. the note stays as-is. set arg parse → keyrack miss → commit author pick → token thread (`SEATURTLE_PR_TOKEN_PREFETCHED`) → push.sh default detection → fallback → gh as-human → json contract → set render.
