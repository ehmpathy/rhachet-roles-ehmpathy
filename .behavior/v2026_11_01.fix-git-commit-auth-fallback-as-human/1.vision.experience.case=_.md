## .forbidden (rejection invariants)

| cell | what | kind | why |
|---|---|---|---|
| f1 | explicit `as-human` falls back to as-ehmpath | nurture — the code could, the contract rejects it | the fallback runs one way, bot → human. an explicit mode keeps its mode |
| f2 | explicit `as-ehmpath` falls back to as-human | nurture | a caller who asked for the bot must not get a silent swap (caseD) |
| f3 | a fallback that lifts a gate | nurture | identity moves, gates hold. every guard runs before the token read (caseE) |
| f4 | more than one as-human retry | nurture | a second retry buys no new credential |
| f5 | an as-human retry after a non-auth gh failure | nurture | the credential worked; the repo or github refused. a retry would hide the real cause (F3) |
| f6 | a fallback on a foreign bot id | nurture | a wrong identity is a defect a human must see, not an auth gap (F4) |
