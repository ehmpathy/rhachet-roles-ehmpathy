# experience dimensions: git.branch.cutover

## .the shape of the experience

one invocation runs a fixed pipeline: **preflight → cut base → replay picks → carry tree → report**.
a halted replay opens a second entry: **settle** (continue or abort). each axis below varies one
stage. the walked product lives in `1.vision.experience.case=_.md`.

## .the axes

| # | axis | values (closed) | stage it varies |
|---|------|-----------------|-----------------|
| D1 | mode | `plan` · `apply` | all — plan mutates naught |
| D2 | preflight | `pass` · `into-extant-local` · `into-extant-origin` · `sha-unknown` · `sha-merge-commit` · `fetch-fails` · `op-in-progress` · `quota-absent` · `untracked-collision` · `from-absent` · `from-unknown` · `pick-with-tree` | preflight |
| D3 | pick load | `0` · `1` · `many` | replay picks |
| D4 | tree load | `clean` · `dirty` | carry tree |
| D5 | replay outcome | `clean` · `pick-conflict` · `pick-empty` · `carry-conflict` | replay + carry |
| D6 | settle entry | `none` · `continue-settled` · `continue-unsettled` · `abort` | settle |
| D7 | actor | `mechanic` · `human` | all |
| D8 | source kind | `feature branch` · `main` · `detached HEAD` | report only — collapsed |
| D9 | base (`--from`) | `@main` · `branch` · `@tree` | cut — where the new branch starts |

### .value notes

- **D2 `quota-absent`** — no `git.branch.uses` quota granted (wisher, q3). refuses in apply; plan
  reports it.
- **D2 `untracked-collision`** — an untracked file sits at a path the new base or a pick tracks. a
  switch would overwrite it, so cutover refuses and names each path. untracked work is never at risk.
- **D2 `from-absent`** — no `--from`. there is no default; the refusal names the three forms.
- **D2 `from-unknown`** — `--from <branch>` names a branch that is not on origin after the fetch.
- **D2 `pick-with-tree`** — `--pick` with `--from @tree`. HEAD already holds every commit, so a
  pick could only come back empty; refused rather than silently a no-op.
- **D9 `@main` · `branch`** — a fresh base after a fetch. one mechanism: `branch` only swaps which
  origin ref is cut; `@main` resolves to `origin/main`, else `origin/master` (a5).
- **D9 `@tree`** — a stacked branch at HEAD. the cut changes no file, so D5 collapses to `clean`
  (no pick to conflict or empty, no carry to conflict) and D2 `untracked-collision` cannot arise.
- **D2 `op-in-progress`** — a rebase, merge, cherry-pick, or prior cutover is mid-flight in this
  worktree.
- **D5 `pick-empty`** — the pick's change is already on `origin/main`. three causes, one outcome:
  the sha is an ancestor of `origin/main`; its change arrived by squash; or the same sha was named
  twice. each is dropped and reported. the ancestor and duplicate causes are visible before any
  mutation, so plan marks them "will drop"; the squash cause shows only on replay.
- **D5 `carry-conflict`** — the tracked edits do not apply cleanly onto the new base + picks.
  untracked files never enter the carry, so they never conflict.
- **D7 actor** — the skill behaves identically for both. the axis exists because the *motive*
  differs: for a mechanic, every raw git step is a permission prompt; for a human it is toil.

## .orthogonality

| pair | why independent |
|------|-----------------|
| D1 × all | any input can be previewed or executed |
| D2 × D3/D4 | refusal reasons are properties of the repo and `--into`, not of the load — except the two `sha-*` values, which need D3 ≥ 1 (recorded as impossible cells: one value per axis, not a whole row) |
| D3 × D4 | committed work and uncommitted work vary freely |
| D5 × D3/D4 | outcome depends on content. two values need a load to exist: `pick-*` needs D3 ≥ 1, `carry-conflict` needs D4 = dirty (impossible cells, with reasons) |
| D6 × D5 | settle only exists after a halt: D6 ≠ none needs D5 ∈ {pick-conflict, carry-conflict}. the settle entry is a second invocation, so it is a separate stage, not a hidden dimension |
| D7 × all | the contract has no actor branch |
| D8 × all | the source is only read, never written; every source kind admits every load and outcome |
| D9 × D3/D5 | `@main` and `branch` admit every pick load and outcome. `@tree` admits picks 0 only (picks ≥ 1 is D2 `pick-with-tree`) and outcome `clean` only (impossible cells, with reasons) |
| D9 × D4 | the tree carries under every base; under `@tree` it never leaves the worktree |

## .collapses (why the product shrinks)

- **D2 ≠ pass** halts before any mutation → D3/D4/D5/D6 do not vary its outcome. one cell per
  refusal × mode.
- **D1 = plan** never replays → D5/D6 are impossible under plan (nature: no git mutation runs).
- **D7** is behavior-identical → walked once; actor noted per case.
- **D9 `branch`** shares `@main`'s pipeline → blocks A–D are walked at `@main`; `branch` adds only
  the `from-unknown` refusal. **D9 `@tree`** collapses D5 → walked in its own small block (E).
- **D8** is behavior-identical → walked once (feature branch); one inventory row per value states
  the collapse reason. cutover reads `HEAD` and never writes the source ref, so the source kind
  changes only the report's `source:` line.

## .absent-axis check

- **concurrency** — a second session in the same worktree mid-cutover is D2 `op-in-progress`. a
  second worktree is isolated by git; its stash stack is not touched (the carry uses no stash).
- **resource-absent** — no network = D2 `fetch-fails`. no `origin/main` = D2 `fetch-fails` (the
  base is unreachable; same fix).
- **actor = system** — no hook or daemon invokes cutover. impossible by nature today.
- **source kind** — surfaced by this check and promoted to D8 (a closed, collapsed axis).
