# case=10: a pick whose change is already on main

**cell** C6 squash cause (+ C9, C13, C16) · C6a ancestor cause · C6b duplicate cause · sharp × alterpath (chosen — the exact trap of the motive incident)
**actor** mechanic

## .narrative

the mechanic names three shas, and one of them is the `feat` that already squash-merged. that sha
is not an ancestor of `origin/main` — the squash made a new commit — so preflight cannot catch it.
its change, though, is already there. the replay produces no diff.

raw `git cherry-pick` would halt here and ask the human to commit an empty pick or skip it. the
skill drops it instead, moves on, and says so plainly in the report: which sha, and why it carried
naught. the other picks land. a commit that carries no change never lands on the branch.

## .sketch output

```
$ rhx git.branch.cutover begin --from @main --into turtle/wave-report-v2 --pick 0f0f0f0 --pick a1b2c3d --pick e4f5a6b --mode apply

🐢 righteous!

🐚 git.branch.cutover begin --mode apply
   ├─ into: turtle/wave-report-v2 (checked out, no upstream)
   └─ picks (3, in order)
      ├─ 1. 0f0f0f0 feat(report): add wave report — dropped, already on origin/main
      ├─ 2. a1b2c3d → 1e1e1e1 cont(report): add swell period ✓
      └─ 3. e4f5a6b → 2d2d2d2 cont(report): add tide column ✓
```

exit `0` — the cutover succeeded; the drop is reported, not hidden.

## .bdd

```
given('[case10] a pick whose change is already in origin/main via squash', () => {
  when('[t0] cutover runs in apply mode', () => {
    then('the empty pick adds no commit');
    then('the report marks it dropped, with the reason');
    then('the other picks land in order');
    then('exit 0');
  });
});
given('[case10b] one pick is already an ancestor of origin/main, and another sha is named twice', () => {
  when('[t1] cutover runs in plan mode', () => {
    then('the ancestor pick is listed with "will drop — already on origin/main"');
    then('the second copy of the repeated sha is listed with "will drop — named twice"');
    then('no ref, index, or file changes; exit 0');
  });
  when('[t2] cutover runs in apply mode', () => {
    then('neither the ancestor pick nor the repeat adds a commit');
    then('the report marks each dropped, with its reason');
  });
});
```
