# case=11: a git operation is already in flight

**cell** A6 `op-in-progress` · sharp × critipath
**actor** mechanic

## .narrative

the mechanic hit a pick conflict an hour ago (case 6), wandered into other work, and forgot. now it
runs a fresh cutover, maybe with a corrected sha list. a second cutover on top of a half-done one
would tangle two sequencers and could strand the uncommitted tree held in the private ref.

the skill refuses before any mutation. it names what is in flight — the halted cutover, its target
branch, the pick it stopped on — and the two ways out. the same refusal fires for a rebase, merge,
or raw cherry-pick in flight; for those it names their own settle commands
(`rhx git.branch.rebase continue` / `abort` for a rebase).

## .sketch output

```
$ rhx git.branch.cutover begin --into turtle/swell-v3 --cherry-pick 1a1a1a1 --mode apply

🐢 bummer dude...

🐚 git.branch.cutover
   └─ ✋ ConstraintError: a cutover is already in flight
      ├─ into: turtle/swell-v2
      ├─ halted on: 2b2b2b2 cont(swell): add period bands
      ├─ tree: held aside, safe
      └─ fix: finish or undo it first
         ├─ rhx git.branch.cutover continue
         └─ rhx git.branch.cutover abort
```

output rides stdout and stderr; exit `2`.

## .bdd

```
given('[case11] a cutover halted on a pick conflict', () => {
  when('[t0] a new cutover runs, plan or apply', () => {
    then('it refuses with ConstraintError: a cutover is already in flight');
    then('it names the halted target, the stopped pick, and both settle commands');
    then('the halted state, the private tree ref, and every branch are unchanged');
    then('exit 2');
  });
});
given('[case11b] a rebase is in flight', () => {
  when('[t0] a cutover runs', () => {
    then('it refuses and names rhx git.branch.rebase continue / abort');
    then('exit 2');
  });
});
```
