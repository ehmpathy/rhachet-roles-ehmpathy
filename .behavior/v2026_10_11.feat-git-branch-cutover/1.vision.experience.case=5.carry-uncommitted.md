# case=5: carry uncommitted work, no picks

**cell** C2 · apply · picks 0 · tree dirty · outcome clean · happy × critipath
**actor** human

## .narrative

a human started a new feature on top of a branch that already shipped. none of its commits matter
now — only the edits in the tree. they want those edits on a fresh branch from main, still
uncommitted, so their first commit there can be a `feat`.

they name only the new branch. the skill parks the modified files in a private ref, checks the
park matches the worktree byte for byte, cuts the branch from fresh `origin/main`, and lays the
edits back down. the two untracked files are never touched — they sit on disk the whole time.
`git status` on the new branch shows the same modified and untracked files as before. the old
branch is exactly where it was.

had main rewritten one of the modified files, the carry would not lay down clean. the human would
get a halt instead, with the original edits parked safe and both exits named — the recovery case 9
walks. had main added a file at an untracked path, cutover would have refused before any move
(case 12).

## .bdd

```
given('[case5] a dirty tree of modified and untracked files, no picks', () => {
  when('[t0] cutover runs in apply mode', () => {
    then('HEAD is on the new branch at the fetched origin/main');
    then('each modified file holds the same content as before');
    then('each untracked file is present, still untracked, and its inode + mtime unchanged — never rewritten');
    then('the index is clean: no file is staged');
    then('the old branch ref is unchanged');
    then('no entry is added to, or removed from, the shared stash stack');
  });
});
given('[case5b] the same carry, but a carried file was rewritten on origin/main', () => {
  when('[t1] cutover runs in apply mode', () => {
    then('it halts on the carry conflict, the original tracked edits parked in a private ref — exit 2');
    then('the untracked files stay on disk, untouched');
    then('`continue` (settled) or `abort` (restore on the source branch) recovers it; see case 9 t3 / t4');
  });
});
```
