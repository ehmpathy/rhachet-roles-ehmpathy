# 1.vision — the pr-watch daemon ends dead watches and holds its token

## what this builds

four repairs. each one ends a process that is born today for no alert.

| # | repair | today | after |
|---|---|---|---|
| 1 | **a 404 ends the watch.** a pull endpoint that answers 404 ends its watch, with one note that names the token that got the 404, both readings (gone, or hidden from this token), and the rewatch | a 404 is a plain read fault: the watch never primes, never idles, and lives forever | the watch ends; the daemon exits once its last watch ends |
| 2 | **a dark watch idles out.** with no good read, the idle clock starts at the pr's first failed read, and a `set` restarts it; each failed read doubles the poll gap, as a quiet read does | the idle clock and the poll gap start only at the first good read; a watch with none reads every tick, forever | one end path for quiet and dark prs: the 1-week ttl and its note |
| 3 | **the token is read once and held.** read only when a due read needs one and none is held; held until github refuses it. a 401 drops it, re-reads keyrack (the seaturtle key, then the grove key), and retries once before any pause. while paused, a tick counts as a quiet read of each due pr, so the extant poll gap doubles (cap 30 min), and the extant cadence reset in `set` snaps it back | `rhachet keyrack get` runs at the top of every tick, a tick with no due pr included. about an hour after each unlock, keyrack purges the seaturtle grant, and each tick then makes two reads: the seaturtle key, refused, then the grove key | about two keyrack reads per daemon life in the common case: the seaturtle token, then, at its death, the grove token |
| 4 | **no spawn for records no daemon will serve.** one predicate answers "would a daemon of this key serve this record?"; the SessionStart hook counts with it, and the steal acts on it | the hook counts every older-key record of the clone, ended or gone or on another key. it spawns a daemon whose first tick steals none of them, then exits. this repeats at every session start, for every clone, forever | an ended older-key record is stolen with its end mark and its note delivered; a gone root is reaped; another key's record waits for that key |

why it works: each repair closes a loop at its cause, not at its symptom. a watch can now end from every state it can reach (open, merged, closed, gone, dark). a daemon is spawned only when it has a record to serve, so "spawn, find naught, exit" cannot recur. the token read moves from "per tick" to "per refusal", so a quiet or idle tick costs no keyrack birth.

## the outcome world

**before.** a seat upgrades on monday. its old-key dir keeps an ended record and a record whose worktree was removed. each session start of each clone on the box spawns a daemon that exits one tick later. elsewhere a watch on a deleted repo answers 404 forever: each minute it births a keyrack read, a clone list read, and a `gh` call. every live daemon reads keyrack once a minute, twice a minute once the seaturtle grant has lapsed.

**after.** the deleted repo's watch ends at its first 404, and the clone hears `#1221 answers 404 (gone, or this token cannot see it); watch ended`, with the rewatch command. the stale old-key records are settled at the next spawn that has real work; later session starts spawn naught. a live daemon reads keyrack at its first due read, and once more when the seaturtle token dies at its hour and the grove token takes over. then it reads keyrack no more while github accepts the grove token.

**the aha.** the daemon is idle most of the time, and an idle tick now births no node process at all for the token.

### births per daemon, by a code read (not a measurement)

| source of a birth | today, per 60s tick | after |
|---|---|---|
| token: `rhachet keyrack get` | 1 while the seaturtle grant lives; 2 once keyrack has purged it (seaturtle refused, then grove), every tick, due pr or not | ~2 per daemon life; while paused, 1 per due tick on a gap that doubles to 30 min |
| clone probe: `rhachet clone list` per repo root | 1 per root | unchanged (out of scope: F6, caught as a dream) |
| github: `gh api` per endpoint of each due pr | 5–6 per due pr | unchanged per read; a dead watch stops its reads |
| respawn: hook → `bash daemon.sh` + its first tick, for orphan records | 1 daemon life per session start | 0 |

at one tick a minute, the token row is up to ~2,880 keyrack births a day per daemon today, and ~2 after. the director's laptop count after release turns this table into a measurement.

## mental model

- a clone would say: "a watch stops when its pr is done or gone, and the watcher stops when no watch is left."
- analogy: a mail carrier who returns undeliverable mail once, instead of a knock at an empty house every minute; and who keeps the key in a pocket, back to the key box only when a lock refuses it.
- our terms vs theirs: we say `ended`, `servable record`, `held token`; a clone says "it stopped", "no watch left", "it remembers the token".

## evaluation

- goals:
  - 404 / merged / closed ends and stays ended → repairs 1 and 4 (merged and closed already end under their own key; an ended record left under an older key is what the hook respawns for)
  - a live watch reads its token once per daemon life → repair 3: one read, plus one more when the hourly seaturtle token dies and the grove token takes over
  - a clamp per case → the clamps above
- pros: each repair is local to one function, with no change to the watch record schema or the `set`/`get`/`del` contracts. the hook and the steal share one predicate, so they cannot drift apart again
- cons: a held grove token serves past keyrack's ~9h unlock, for the rest of the daemon life (F1). the extant `health [t2]` test pins "a 404 sends no note; its text waits on the commander", so it flips on purpose, since the wish now answers it
- edge cases and their pit of success:
  - a 404 from a token that cannot see the pr → the note names the token, both readings, and the fix before a rewatch (case=2, E15, E31)
  - the hourly seaturtle token dies → one re-read and one retry, no note (E26)
  - a closure note a DEAF clone will not take → the record waits for it (F6 of the daemon holds), but reads no github and no token while it waits (E14)

## open questions and assumptions

- **[wisher]** a held grove token serves past keyrack's unlock lapse (F1). a human who lets keyrack lapse to stop all github reads would see the daemon read on until its last watch ends. trade the ~48 reads a day of a 30-minute recheck for that bound, or hold until a 401 as the wish words it?
- **[wisher]** "stuck" is read as "no good read for the 1-week idle ttl" (F3). does the wisher want a shorter bound for a watch that has never read ok?
- **[wisher]** a paused daemon whose human unlocks with no push resumes within the 30-minute cap (F4). acceptable, or should an unlock alone wake it sooner?
- **[answered]** does keyrack's `--json` reply say when the token dies? no. `get` rebuilds the grant without `expiresAt` (`rhachet` `getKeyrackKeyGrant.js:53`–`60`), though keyrack's own cache holds one. so the daemon learns of a dead token from github's 401. caught as a reseed dream for rhachet
- **[answered]** is one 404 enough to end a watch? yes, by logic (F2): the token is held, so a re-read with it gives the same answer; a false end costs one rewatch, which the note names, and a grove-token 404 names the seaturtle fix (E31)
- **[answered]** does the daemon hold "one process per watch", as the wish says? no: one daemon per machine per key (`gen_watch_daemon`, `git.pull.watch.operations.sh:757`), shared by every watch of that key
- **[answered]** does a respawn read the token, as the wish says? no: a daemon with zero records exits at `git.pull.watch.daemon.sh:872`, before the token read at `:883`. the respawn's cost is the daemon birth itself, which repair 4 removes
- **[research]** does a renamed repo's old name redirect under `gh api`, as github's rename docs say? if not, a rename reads as a 404 and ends the watch with the rewatch named. one live call in the blueprint settles it
- **[research]** the births table is a code read. the director's laptop count after release is the measurement; the clamps measure keyrack and `gh` calls per tick in the scene

## groundwork

### external research

none beyond the rename check above. `get_watch_github_resource` reads the status from the reply's first line, so a 404 is already told apart from a 5xx or a 401 (`git.pull.watch.github.sh:151`, `:194`). the seaturtle token's one-hour life is github's rule for an app installation token, recorded in `.behavior/v2026_05_14.auth-github-app-seaturtle/1.vision.yield.md:153`.

### internal research

- the tick: `run_watch_tick` (`git.pull.watch.daemon.sh:868`). the token read sits at line 883, before the per-pr loop and its `is_watch_pr_due` check (line 917), so it runs on every tick
- the token read: `get_watch_token` and `get_watch_token_ambient` (`git.pull.watch.token.sh:54`, `:77`), each one `rhachet keyrack get` via `run_watch_rhachet` (`git.pull.watch.operations.sh:1108`). `as_watch_token_state` reads `.status` and `.grant.key.secret` (`git.pull.watch.token.sh:36`)
- keyrack: `get` reads only keyrack's daemon cache, never the vault (`rhachet` `getKeyrackKeyGrant.js:20`–`21`). the cache purges a grant at its `expiresAt` (`daemonKeyStore.js:49`–`56`), which the github-app mech stamps at now + 55 min (`mechAdapterGithubApp.js:202`). so the seaturtle key reads `locked` about an hour after each unlock, and the grove key serves from then on
- a 401: `get_watch_github_resource` returns 3 (`git.pull.watch.github.sh:175`); the tick pauses at once with cause `expired` (`git.pull.watch.daemon.sh:929`)
- a 404: `get_watch_github_resource` returns 1 for any non-200 that is not 304/401/rate/5xx (`git.pull.watch.github.sh:194`). the tick logs it as a read fault and holds (`git.pull.watch.daemon.sh:949`). the daemon's own note says a 404 shows in `get` alone (`git.pull.watch.daemon.sh:522`)
- idle and cadence: `is_watch_pr_idle` reads `poll.changed`, which only `set_watch_pr_cadence` writes, after a good read (`git.pull.watch.operations.sh:1034`, `:1044`); `set` resets the cadence via `del_watch_pr_cadence` (`git.pull.watch.set.sh:184`)
- the respawn: the SessionStart hook counts every record of the clone under every older key (`sessionstart.git-pull-watch.sh:88`). the steal skips ended records, gone roots, and roots on another key (`git.pull.watch.daemon.sh:853`–`856`). a daemon with zero records exits before any token read (`git.pull.watch.daemon.sh:872`)
- the test stubs: the scene stubs `gh` and `rhachet` on PATH and logs each keyrack call (`genWatchTestScene.ts:15`, `:219`, `:609`), stubs the grove key apart from the seaturtle key (`keyrackAmbient`, `:103`), and stubs a 404 per pr (`faultByPr: 'notfound'`, `:72`)
- vocab to reuse: `ended`, `steal`, `held`, `paused`, `idle`, the closure note shape `as_watch_closure_text`
- stdout to match: the closure note tree of `as_watch_closure_text` (`git.pull.watch.alert.sh:217`), header `print_watch_alert_header` (`:52`); the `token:` log line of `set_watch_token_source_logged`

## what is awkward

- a held grove token outlives the keyrack unlock that a human may believe bounds it (F1)
- a 404 from a token that cannot see the pr ends the watch the same as a gone pr; the note names the token and both readings, and the clone must judge which (F2)
- a paused daemon whose human unlocks with no push waits up to the 30 min cap to resume (F4)
- the clone probe stays per tick, now the largest idle-tick birth by far (F6)
