# case=4 · a live daemon reads its token once, and holds it until github refuses it

covers: E4, E5, E6, E20, E28. happy · critipath.

## .narrative

a human unlocks keyrack at 09:00 and a clone pushes. the daemon boots for two watches. its first due read needs a token: today the seaturtle token is granted, so the daemon holds that secret in memory.

each tick after, it reads github with the held token. a quiet pr waits out its 30-minute gap; on those ticks no pr is due, so the daemon reads neither keyrack nor github.

the seaturtle token is a github app installation token, valid for one hour. near 10:00 github answers 401. the daemon drops it, re-reads keyrack, and retries the read (case=5). keyrack's own cache purged the seaturtle grant at 55 minutes, so the re-read finds it `locked` and falls back to the grove token, `@all.prep.GITHUB_TOKEN`. that read is granted; the retry gets 200, and no clone hears a word. the daemon holds the grove token from then on.

the grove token carries no expiry of its own, so the daemon reads keyrack again only if github refuses it. today the same daemon makes two keyrack reads every minute after 10:00 (the seaturtle key, refused, then the grove key), 120 an hour; with the fix it made two reads all day.

`daemon.log` names each read once:

```
<boot> token: ehmpathy.prep.EHMPATHY_SEATURTLE_GITHUB_TOKEN (held until github refuses it)
<boot + 1h> token: @all.prep.GITHUB_TOKEN, the grove token (the seaturtle token is not granted), held until github refuses it
```
