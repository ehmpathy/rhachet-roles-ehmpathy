# case=3 · a watch that never reads ok ends at the idle ttl

covers: E3. sharp · critipath.

## .narrative

clone @:mechanic watches a pr whose every read faults: a 403 or a malformed reply (dark), or no reply at all (an outage). without the fix, the idle clock (`poll.changed`) starts only at the first good read, so a watch with none never reaches the ttl. it also never gets a poll gap, since the cadence is set only after a good read; it reads each tick, forever.

with the fix, a pr with no good read starts its idle clock at its first failed read, one tick after the watch is set; a fresh `set` restarts it. a dark pr earns the poll gap: each failed read doubles it, as a quiet read does. an outage read holds its gap instead, yet still starts the idle clock.

in the meantime `get` names the fault on the row. at the ttl the clone hears one note that says the pr went unread, never quiet, and names the last fault and the rewatch:

```
🐢 heads up dude...

🐚 git.pull.watch — #1222 unreadable for 7 days; watch ended
   ├─ last fault: github read failed: repos/ehmpathy/surf-demo/pulls/1222 (status: 403) Resource not accessible by integration
   └─ rewatch: rhx git.pull.watch set --which 1222 --mode apply
```

(`as_watch_closure_text … dark`, `git.pull.watch.alert.sh`)

so a watch that fails each read neither lives forever nor dies in silence.
