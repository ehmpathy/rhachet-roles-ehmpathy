# case=6 · records no daemon will serve never spawn one

covers: E8, E9, E10, E19. sharp · critipath. this is the respawn loop.

## .narrative

clone @:mechanic was upgraded from v1.42.0 to v1.43.0. under `v=1.42.0+…/watches/` three of its records remain:

- #1201: ended (merged), its closure note held when the old daemon died
- #1202: its repo root was a worktree, since removed
- #1203: its root runs v1.43.1 in another worktree

no v1.42.0 daemon lives. today the SessionStart hook counts all three as "watches under an older key", spawns a v1.43.0 daemon, and prints `pr watch: daemon … spawned, for 3 watch(es)`. the daemon's first tick steals none of them: the steal skips an ended record, a gone root, and a root on another key. it holds zero watches and exits. the next session repeats the whole birth, for every clone of the box, forever.

with the fix, one predicate answers "would a daemon of this key serve this record?", and the hook and the steal both read it:

- #1201 (ended, root runs this key) → served: the steal takes it with its end mark and held note; the note goes out; the record leaves
- #1202 (root gone) → reaped by the steal pass, as a root gone under this key is today
- #1203 (root runs another key) → not this key's: the hook counts it zero; the v1.43.1 daemon steals it when its own hook runs

once those three are settled, a session start spawns naught.

the hook stays loud where it spawns: its extant line names the count it serves (`for 1 watch(es), 1 under an older key, taken at its first tick`). it stays silent where it spawns naught, as it is today for a clone with no watch. a record left inert (E21) still shows in `get`.
