# 1.vision.experience.dimensions — fix-pull-watch-daemon-respawn-loop

actor = the pr-watch daemon, as one clone (and the director who counts births) lives with it.

## .dimensions

| id | dimension | values |
|---|---|---|
| D1 | pr state, as github answers it | `open` (reads 200/304) · `merged` · `closed` (without merge) · `gone` (404) · `dark` (a fault with no path of its own, each read: a 403 that is not a rate limit, a 422, a reply that will not parse) |
| D2 | token state, as keyrack and github answer it | `granted` at boot · `locked` at boot · `locked` mid-life (keyrack's unlock lapsed; the held token still serves) · `refused` by github (401), healed by one fresh read · `refused` again with a fresh token (pause cause `expired`) · none granted on the fresh read (pause cause `locked`) · keyrack faults (no reply in 30s, or a reply that will not parse) |
| D2s | which token serves | `seaturtle` (`ehmpathy.prep.EHMPATHY_SEATURTLE_GITHUB_TOKEN`) · `grove` (`@all.prep.GITHUB_TOKEN`, where the seaturtle key is absent, locked, or blocked) |
| D3 | pr due this tick? | `due` · `not due` (a quiet pr waits its gap) |
| D4 | where the record sits | this key · an older key, root runs this key · an older key, root runs another key · an older key, root gone · an older key, record unreadable or rootless (no proof of any root) |
| D5 | record end mark | `live` · `ended` (closure note held or sent) |
| D6 | who calls the findsert | `set` (or `git.commit.push`) · SessionStart hook |
| D7 | when, against its peers | `alone` · `concurrent` with a peer findsert · `concurrent` with the daemon's own exit · `concurrent` with a steal or a tick |

`dark` is closed by exclusion. every other fault class already has its own extant path, which this work leaves as is: a 401 pauses (`git.pull.watch.github.sh:175`), a rate limit or a quota below the floor backs off (`:162`, `:181`), a stall or a 5xx is an outage with its own clock and note (`:155`, `:188`). what is left returns 1 from `get_watch_github_resource` (`:194`), and `dark` names exactly that set. an outage read and a dark read share one cadence rule: each holds the pr's gap and starts its idle clock, so a pr that never answers ends at the idle ttl like a dark one.

## .the walked product

D1 × D2 × D2s × D3 drives the tick. D4 × D5 × D6 × D7 drives the spawn. the two halves meet at one point only: a daemon that lives reads its token; a daemon that boots to naught reads none. so the product walks as two sub-products plus their seam.

### tick half: D1 × D2 × D2s × D3 (5 × 6 × 2 × 2 = 120 cells)

- D3 = `not due` → no github read, so D1 is moot and D2 must not be read: every such cell collapses to one rule (**no token read on a tick with no due pr**)
- D2 = `locked` at boot → no github read; D1 moot: the pause with cause `locked`, re-read on the poll gap
- D2 = `granted`, or `locked` mid-life with a held token, × D3 = `due` → D1 decides 5 outcomes: `open` (case=8), `merged` and `closed` (case=1), `gone` (case=2), `dark` (case=3)
- D2 = `refused`, healed → as `granted` after one retry; D1 decides
- D2 = `refused` again → the pause with cause `expired` (the fix: refresh the key)
- D2 = none granted on the fresh read → the pause with cause `locked` (the fix: unlock)
- D2 = keyrack faults → not a token state, so never a pause and never an `unlock` note: the extant `tokenfault` path holds the tick, logs keyrack's own cause, and past 30 min sends one note per clone with that cause and the check to run (`git.pull.watch.daemon.sh:886`–`891`, `as_watch_fault_cause`). a held token is not dropped on a keyrack fault, since only github's 401 drops it; a fault on the fresh read after a 401 takes the same `tokenfault` path
- D2s changes D1 at one cell only: `gone` × `grove` names the grove token and the seaturtle fix (E31). every other outcome reads the same under either token. D2s also orders the fresh read: seaturtle first, grove where seaturtle is not granted

### spawn half: D4 × D5 × D6 × D7 (4 × 2 × 2 × 4 = 64 cells)

- D4 = this key → the record is served; D5 decides read vs drain-only. × `live` × SessionStart is the extant findsert: `found` and silent where the daemon lives, spawned with one line where it died (E36)
- D4 = older key, root runs this key → stolen; D5 = `ended` rides the steal with its mark kept
- D4 = older key, root runs another key → not this key's to serve; the hook must not count it
- D4 = older key, root gone → no clone can live there; reaped
- D6 only changes who asks; the predicate of "would a daemon of this key serve it?" must be one, read by both
- D7 = `alone` → as above
- D7 = `concurrent` with a peer findsert (two session starts, or a session start and a `set`) → serialized by the key lock: `gen_watch_daemon` takes it before it judges the daemon (`operations.sh:764`), and a daemon that boots claims `daemon.pid` under it and exits if a live twin holds it (`daemon.sh:105`–`114`). one daemon lives; the second findsert reads `found`. at worst one extra bash birth that exits at boot, never a second live daemon
- D7 = `concurrent` with the daemon's own exit → `exit_watch_daemon_if_idle` re-checks the records under the lock (`daemon.sh:272`–`287`), and `set` writes its record before it takes the lock, so a record that lands as the daemon leaves is seen, or spawns a fresh daemon. extant, unchanged
- D7 = `concurrent` with a steal or a tick → the hook's count reads records while a live daemon may steal or end them. the count can be stale by one record: the hook may spawn into a live daemon (`found`, no birth past the findsert), or a daemon may exit idle one tick later. at worst one daemon life, never a loop: a stale count cannot recur, since the record it counted has moved or left

### seam

- a daemon that boots, steals naught, and holds zero records exits before any token read. a hook that counts only servable records never spawns that daemon at all.
