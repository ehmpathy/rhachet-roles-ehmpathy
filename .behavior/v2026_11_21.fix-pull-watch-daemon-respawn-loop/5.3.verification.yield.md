### the 404 contract on real github

the daemon reads a 404 from the first line of `gh api -i` and from gh's exit code. both, observed on the real service with the human's gh login (read-only, this public repo):

```
$ gh api --method GET -i repos/ehmpathy/rhachet-roles-ehmpathy/pulls/999999; echo "exit=$?"
HTTP/2.0 404 Not Found
...
{"message":"Not Found","documentation_url":"https://docs.github.com/rest/pulls/pulls#get-a-pull-request","status":"404"}gh: Not Found (HTTP 404)
exit=1
```

the stub gh (`genWatchTestScene.ts:131`) serves this exact shape: `HTTP/2.0 404 Not Found` first, stderr `gh: Not Found (HTTP 404)`, exit 1. so every stubbed 404 case reads the reply github sends.
