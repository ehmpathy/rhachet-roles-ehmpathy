## the clean-rhx-sink fulcrum (SETTLED — the seam honors the human's own deny-list)

reviewers blocked on: `is_sink_safe` accepts a clean-rhx call as a sink, so
`echo hi | rhx git.commit.uses set …` auto-approves. a later reviewer (i007 r010) sharpened
this into a live security regression: `rhx git.commit.bind set` is ALSO deny-listed, but —
unlike `git.commit.uses` — `git.commit.bind.sh` has NO execution self-guard (it writes
`.branch/.bind` directly). its ONLY protection is the deny-list text match, which the piped
form evades. so the widened seam would silently auto-approve a mechanic's self-set of a
human-owned commit-level constraint.

decision: **the seam now HONORS the human's own `permissions.deny`.** this is the correct
root fix, and it settles the whole fulcrum uniformly:

- **PRIMARY — the deny-honor** (`command_is_denied`): the seam reads the human's OWN
  `permissions.deny` (the same authority gate 2 is built from), symmetric to the allow set
  it already read. a denied segment fails its producer/sink bar, so the compound LIFTS (a
  chain with a denied segment DENYS). this is NOT a seam-minted denylist
  (`define.why-permission-guards-allowlist-all-rhx` forbids only a SELF-MINTED rhx
  blocklist; it does not forbid honor of the human's own). the deny matcher is GLOB-aware
  (unquoted prefix) so `--org * del` catches any org — for a deny, an under-match is a HOLE,
  so it errs wide; for the allow matcher, an under-match only LIFTS (fail-safe), so it stays
  literal. this closes the hole for EVERY deny-listed skill, self-guarded or not.
- **BACKSTOP — the execution self-guard**: a non-denied sensitive rhx skill can still refuse
  a piped call at run time (git.commit.uses.local.sh: `[[ ! -t 0 ]] → exit 2 "only humans"`;
  a PIPE removes the TTY). this is the repo's documented division of responsibility: the
  seam asks "clean rhx or a chain?"; the skill asks "is this allowed for this caller?".
- **the WISH BODY is honored**: "every segment {clean-rhx OR allowlisted}, wherever it
  sits" — a NON-denied clean-rhx sink still auto-approves (the four wish cases are
  untouched: git.repo.test/get, npm run, tail, jq are not deny-listed). the deny-honor only
  ever NARROWS approve, never widens it.
- **invariant #5 = shell escalation OR a human-denied grant**: `echo hi | sudo rhx …` LIFTS
  (sudo is a shell token, no self-guard) and `echo hi | rhx git.commit.uses set …` LIFTS
  (human-denied). both refuse; neither auto-approves.

## update (i008) — the loose-recognizer-vs-literal-veto bypass class: closed

i008 r010/r011 (both) surfaced a real class the deny-honor left open: `is_clean_rhx_call`
is a LOOSE shape recognizer (4 leads, whitespace-loose, quote-loose) while the deny veto
was a STRICT literal-text match. wherever they disagreed, the loose side won and the deny
was bypassed — so `npx rhx git.commit.bind set`, `rhx  git.commit.bind set` (two spaces),
and a quoted skill token each evaded the deny and auto-approved the exact skill the deny
protects. git.commit.bind has NO execution self-guard, so the deny was its only protection.

**the fix — `canonicalize_rhx_command` (decompose-for-recompose, not a patch).** one
transformer folds all recognized rhx-family leads to a single canonical `rhx <tail>`, strips
quote delimiters, collapses whitespace runs to one space. applied BOTH at the deny match and
to each deny pattern at load — so veto ⊇ recognizer by construction, and a deny written ONCE
covers every form. quoted-token, alt-lead (`npx rhx`), whitespace, line-continuation, and
quote-split-verb/skill evasions all close uniformly. honors the vision one-parser
constraint: a pure string fold over the already-extracted atom, not a second quote parser.

**clamp extended + proven to bite**: `case13` gained the alt-lead, whitespace, and quoted
rows; the compose corpus quote-split / npx / line-continuation rows flipped to LIFT.
dogfooded: canonicalizer neutered → case13 4/7 red + compose quote-split 0/2 red; restored
→ 219 passed, 0 failed; types+lint+format green.

**cheap nitpicks cleared**: the case2 newline comment now attributes the strip to `$(...)`
CMD-extraction (not a residue-scan trim); the stale `rhx foo | jq .` AUTO_APPROVE row moved
out of the LIFT section into the AUTO_APPROVE pipe section.
