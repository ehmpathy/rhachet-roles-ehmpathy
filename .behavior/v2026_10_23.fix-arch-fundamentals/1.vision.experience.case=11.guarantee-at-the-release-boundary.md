# case 11 — guarantee-at-the-release-boundary · happy critipath (densest new walk: 5 boundaries)

cell: family E · `guarantee × release-boundary × declarative`, and `assumption × release-boundary` in the consumer · lessons I25, I24, I27

## .narrative

an architect ships `svc-lessons` v2.0.0. consumers build against `getLessonReservation`, so the architect writes `g001 — a reservation's id is stable`: surface, promise, since v2.0.0, relies on `i001`, and an unpromised list — the order of a list response, the id format, error message text. a blackbox acceptance test calls the published contract and proves the id holds across a re-read.

inside the service, no other surface gets a guarantee. `setLessonSlot` and the dao are internal contracts; they change freely.

a voucher service in another repo redeems a gift voucher against a reservation. its architect writes `a002 — a reservation's id stays stable`, evidence tier "an upstream guarantee (`ehmpathy/svc-lessons g001`)". a second assumption, that reservations list in creation order, has no upstream guarantee behind it; its evidence tier says so, and its required response on break is "surfaced": the voucher list sorts by `createdAt` itself.

a month later, `svc-lessons` moves to a keyed store, and list order changes. `g001`'s acceptance test stays green, so the change ships as a minor. the voucher service sees no break: it never leaned on order without a sort of its own.

## .bdd `[tn]` timeline

```
given svc-lessons v2.0.0 publishes getLessonReservation
  when [t0] the architect inventories the release boundary
    then inventory.of=guarantee holds g001 a reservation's id is stable: since v2.0.0, relies on i001
    and  g001 lists unpromised: list order, id format, error message text
    and  a blackbox acceptance test proves g001 through the published contract
    and  no internal contract gets a guarantee
  when [t1] the voucher service inventories what it leans on
    then a002 cites ehmpathy/svc-lessons g001 as its evidence tier
    and  the creation-order assumption cites no upstream guarantee; its response is surfaced: sort locally
  when [t2] svc-lessons changes list order in a refactor
    then g001's acceptance test passes; the release is a minor
    and  the voucher service sees no break
```

## .why critipath

every repo with a consumer meets this boundary (freq: each release). a guarantee left implicit gets replaced by whatever consumers observe (hyrum's law); a break then ships as a minor and pages another team (cost: behavioral, reputation). the unpromised list and the blackbox test keep the declared and the observed surface close.
