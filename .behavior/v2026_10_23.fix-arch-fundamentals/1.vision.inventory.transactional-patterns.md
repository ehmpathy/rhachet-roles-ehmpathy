# inventory: transactional patterns

## .the ask

the wisher: *"please itemize fundamental transactional architectural patterns too for us to review whether to adopt or reject too"*. on review: *"some of them look like overkill"*.

## .the lens

our repos are information logistics: postgres or dynamodb, queues, and third-party apis, behind serverless handlers. each pattern below is judged by one question: **does a common invariant in those repos break without it?**

- yes, often → **core**: taught in the brief
- yes, but only in one kind of repo or one kind of load → **situational**: one line in the brief, with the case that calls for it
- rarely, or it is infra config, or it repeats a core row → **drop**

each pattern names the invariant it keeps, since the brief teaches patterns as enforcements of invariants (`1.vision.inventory.lessons.md`, I01).

## .columns

- **keeps** — the invariant the pattern holds
- **extant** — the brief that already holds part of it
- **proposed** — `core` · `situational` · `covered` · `drop`
- **ruled** — blank, for the wisher

**blanket ruled**: _(blank)_ — write `agree unless ruled` to accept every proposed call you leave blank

sources are standard texts, not fetched this round (🟡 → `[research]` before a brief cites them): Gray & Reuter, *Transaction Processing* (1992); Garcia-Molina & Salem, *Sagas* (1987); Kung & Robinson, optimistic concurrency (1981); Helland, *Life beyond Distributed Transactions* (2007); Vernon, *Effective Aggregate Design* (2011); Fowler, *Patterns of Enterprise Application Architecture* (2002); Kleppmann, *Designing Data-Intensive Applications* (2017).

## .core (8)

| id | pattern | keeps | extant | proposed | why | ruled |
|---|---|---|---|---|---|---|
| T01 | **one-store transaction** — a multi-row write commits or rolls back as one | no half-written state in one store | none | **core** | the base tool; most of our writes need no more | |
| T02 | **unique constraint on the natural key** | no duplicate entity under a concurrent findsert | mechanic `rule.forbid.race-conditions` (ref) names it as one cure; `rule.forbid.nonidempotent-mutations` names the verbs, not the constraint | **core** | a findsert with no constraint races: two callers find none, both insert. the constraint makes the verb safe | |
| T03 | **check constraints + foreign keys** | a value stays in range; a ref resolves | none | **core** | the store refuses an illegal row when code forgets | |
| T04 | **version check** (optimistic concurrency) — write only if the version still matches | no lost update between two writers | none | **core** | cheap, no held lock; a conflict fails loud and the caller retries | |
| T05 | **guarded state transitions** — a status moves only along declared edges | no skip, no backward move, no double move | dispatcher `radio.task.push` enforces `QUEUED → CLAIMED → DELIVERED` | **core** | most of our entities have a status; most status defects are an illegal edge | |
| T06 | **idempotent consumer** — record each handled message id; skip a repeat | a redelivered message acts once | none | **core** | sqs and its kin deliver at least once; the handler must absorb a repeat | |
| T07 | **caller-supplied id** on create | a retried create lands on one row | domain objects `uuid?` metadata | **core** | turns a create into a findsert by id | |
| T08 | **aggregate = transaction boundary** — one transaction changes one aggregate | the aggregate's own invariants; it names where a transaction ends | domain objects; abstraction A14 | **core** | without it, one transaction grows to span whatever the code happens to touch | |

## .situational (5)

| id | pattern | keeps | the case that calls for it | proposed | ruled |
|---|---|---|---|---|---|
| T09 | **row lock** (`select … for update`) for a short critical section | no interleave in a read-modify-write | a hot row under real contention (the last board in stock), where T04 retries would thrash | **situational** | |
| T10 | **orchestrated saga + compensation** — one coordinator drives each step and its undo | a multi-service change ends whole or undone | a change spans services that cannot share a transaction (charge, then reserve) | **situational** | |
| T11 | **transactional outbox** — the event row commits with the state; a relay publishes it | no state change without its event, no event without its state | a write must emit an event other services act on | **situational** | |
| T12 | **double-entry ledger** for money | every balance equals the sum of its entries | a repo that moves or holds money | **situational** | |
| T13 | **read-your-writes** | a caller sees its own write | a read replica, or an eventually consistent index | **situational** | |

## .drop (14)

| id | pattern | why drop | ruled |
|---|---|---|---|
| T19 | at-least-once + idempotent handlers | the same lesson as T06; merged there | |
| T20 | lease + fence token (distributed lock) | rare in our repos; look it up when it comes | |
| T21 | change data capture | infra choice, not a code lesson | |
| T22 | dead-letter queue | queue config, not a code lesson | |
| T23 | order by sequence, not wall clock | rare; at most one line in `time-assumptions` | |
| T24 | serializable isolation as default | forces a retry loop on every write; T04 and T09 cover the real cases | |
| T25 | advisory lock | ties correctness to one engine's feature | |
| T26 | event-sourced state | high cost to read, migrate, fix; T11 buys most of its value | |
| T27 | soft delete vs tombstone | shape varies by domain; no measured need | |
| T28 | unit of work | hides writes behind a tracker; our daos write explicitly | |
| T29 | two-phase commit | blocks on a slow participant; few of our apis support it | |
| T30 | choreographed saga | the flow lives nowhere; hard to read and to test as a whole | |
| T31 | separate read and write models (cqrs) | only where an analytical load meets a live store (lessons I06) | |
| T32 | rich domain model (behavior as entity methods) | fights `rule.require.immutable-vars`; our objects hold shape, operations hold behavior | |

saga and compensation share one row (T10): neither stands alone.
