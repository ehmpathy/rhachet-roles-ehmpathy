# case 2 — double-click-double-book · happy critipath (the densest walk)

cell: family A · `design × cross × again × held` and `design × cross × together × held` · lessons I01, I02, I04, I05 · patterns T02, T04, T05, T06, T11

## .narrative

the surf school wants online lesson reservations, with a board reserved per surfer. the wish's own example (lines 230–233) names the trap: payment charges once, inventory guards one board per surfer, and a fast double click still hands one board to two surfers. each part kept its invariant; the composition broke.

an architect clone designs `setLessonReservation`. I02 asks it to state the invariant before the operation, so it writes one line first:

> **for every lesson slot, the count of reserved boards never exceeds the count of boards in stock, and each surfer reserves at most one board per slot.**

then it picks the enforcements from the transactional inventory, one per way the invariant could break:

| how it could break | enforcement |
|---|---|
| two reservations race for the last board | T04 — a version on the slot row; the second write fails and retries |
| one surfer double-clicks | T02 — a unique constraint on `(slotUuid, surferUuid)` |
| the reservation commits but the "reservation placed" event never reaches the payment service | T11 — the outbox row commits in the same transaction |
| the payment service receives the event twice | T06 — it records the event id and skips a repeat |
| a reservation moves from `RESERVED` straight to `REFUNDED` | T05 — `RESERVED → PAID → ATTENDED`, or `RESERVED → CANCELLED`; any other edge throws |

last, I05: it names the seam tests. a parts test proves each enforcement; one composer test fires two reservations at once for the last board and asserts exactly one wins.

kai and jo click "reserve" on the last foamboard at 6am within the same 300ms. kai gets the board. jo sees *"the last foamboard just went — 2 longboards remain"*. no surfer is left on the sand with a paid lesson and no board.

## .bdd `[tn]` timeline

```
given a slot "trestles, sat 6am" with 1 foamboard in stock, and surfers kai and jo
  when [t0] the architect clone designs setLessonReservation
    then its design states the invariant in one line before any enforcement
    and  each way to break it maps to one named enforcement (T02, T04, T05, T06, T11)
    and  it names one composer test: two concurrent reservations on the last board
  when [t1] kai and jo reserve the last foamboard within 300ms (concurrent: both in flight)
    then exactly one reservation commits (kai)
    and  jo's reservation fails the version check, retries, reads zero stock, and returns a constraint: "no foamboard left at this slot" with the open alternatives
  when [t2] kai clicks "reserve" again after the first reservation returns (a sequential repeat)
    then the second call returns kai's prior reservation — the unique key absorbs it (idempotent)
  when [t3] the relay publishes kai's "reservation placed" event twice
    then the payment service charges once — the event id is already recorded
```

## .why critipath, and why densest

every school that takes money online walks this path daily (freq high). a double-book costs a refund, a surfer on the sand, and a review (cost high: monetary, reputation). it crosses six boundaries in one walk: ui, api, payment, inventory, queue, store. it exercises four lessons and five patterns at once. two of those patterns (T06, T11) sit only because two services meet here; in a one-store repo, T02 and T04 alone keep the same invariant.
