# case 6 — row-left-unruled · sharp critipath (fails safe)

cell: family B · `any item × any proposed × blank`, with no blanket · forbidden invariant: execution builds only ruled rows

## .narrative

the wisher rules forty rows, leaves the inventory's blanket line blank (case 8 shows the blanket), and misses T20 (lease + fence token). the execution clone reaches T20 and finds both the `ruled` cell and the blanket blank.

the easy move is to follow the proposed verdict: `drop` sits right there. but a proposed verdict is a guess the wisher reserved the right to overturn. a skip on a guess settles, by side effect, a call the wisher kept, as surely as a build would.

so the clone halts that row, and only that row. it builds every ruled row, then stops at the stone with one ask: *"T20 has no ruled verdict. proposed: drop — rare in our repos. rule it, then re-run the stone."* the ask names the file, the row id, the proposed call, and its reason.

## .bdd `[tn]` timeline

```
given the inventories with every row ruled except T20, and no blanket line set
  when [t0] the execution clone walks the rows
    then it builds every ruled row
    and  it neither builds nor skips T20 on its own call; T20 stays open
  when [t1] it reaches the end of the walk
    then it halts with one ask that names: the file, row T20, the proposed call, its reason
    and  the ask holds the exact edit the wisher must make: fill the ruled cell, or set the blanket to "agree unless ruled"
  when [t2] the wisher rules T20 and the clone re-runs
    then T20 is built per its ruled verdict, and no other row changes
```

## .why critipath

forty-odd rows guarantee a miss (freq: once per review, near certain). a build on the proposed verdict would ship an unreviewed call into every repo that boots the role (cost: reputation of the review itself). no fallback catches it after release.
