## .quotes

> "The HTTP Idempotency-Key request header field can be used to make non-idempotent HTTP methods such as POST or PATCH fault-tolerant."

> "Consider a scenario where the client sent a POST request to the server, but the request timed out. The client is left uncertain about the status of the resource. It doesn't know if the resource was created or updated, or if the server even completed processing the request. Furthermore, the client does not know if it can safely retry the request."

> "An idempotency key is a unique value generated by the client which the resource uses to recognize subsequent retries of the same request."

> "Concurrent Request The request was retried before the original request completed. The resource SHOULD respond with a resource conflict error."
