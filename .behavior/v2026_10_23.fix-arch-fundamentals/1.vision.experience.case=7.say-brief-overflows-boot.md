# case 7 — say-brief-overflows-boot · sharp critipath (fails loud)

cell: family C · `say × overflows` · forbidden invariant: a role boots within its declared `budget.tokens`

## .narrative

the wisher rules I04 (`define.enforcement`) as `adopt, boot as say` — a flip from the proposed `ref`. the execution clone adds it to the architect `boot.yml` under `say`. the brief runs ~1,800 tokens; the architect boot has 1,479 spare (13,521 of 15,000, measured 2026-10-23).

the build does not let it through. `boot.budget.integration.test.ts` fails red: the architect boot now exceeds its cap. `repo introspect` halts the build on the same check (per the note atop `src/domain.roles/architect/boot.yml`).

today the red test prints the token count and the budget, but the fix lives only in a code comment (`// on red: trim the boot, or raise budget.tokens deliberately`). the clone must read the test source to learn its moves. so this vision asks execution to lift that comment into the failure message (scouts honor: small, safe, in a file this route touches). then the red names its three cures: write a `.min` twin, demote another say brief to ref, or ask the wisher to raise the cap.

the clone writes `define.enforcement.md.min` (~250 tokens) beside the full brief. the `say` entry still lists `define.enforcement.md`; the boot renders the `.min` twin in its place, as it already does for the lang.prose briefs (`define.wick-dense.md` listed, `define.wick-dense.md.min` rendered). the full text stays on disk for a deeper read, and the test goes green.
