# experience dimensions

the behavior: architects and mechanics know what an invariant is and why it matters, and pick an enforcement for each one — a type, an abstraction, a store constraint, a transactional pattern, a test. the wisher curates which lessons, tactics, and patterns ship.

## .the latent axis: subject

a first pass used one axis `actor` = {architect, mechanic, reviewer, wisher}. it failed the orthogonality test: the wisher never edits code, and a clone never rules an inventory row. `actor` implied `subject`. so the latent dimension **subject** splits the space into three families, each walked on its own axes:

| family | subject | who meets it |
|---|---|---|
| **A — apply** | a code change, shaped by the new briefs | architect, mechanic, reviewer clones |
| **B — curate** | one inventory row (`I*`, `O*`, `A*`, `T*`) or one fulcrum (`F*`) | the wisher |
| **C — boot** | a brief entry in a `boot.yml` | the clone that executes this route |
| **D — arbitrate** | a test gone red after a change | the robot mechanic at build; the reviewer lane |
| **E — inventory** | one entry in a repo's `inventory.of=invariant` / `=assumption` / `=guarantee` | the architect who writes it; a consumer who cites it |
| **F — write** | one file write that holds a form of the overloaded noun the blocklist bans (I31) | any clone that writes a brief, a comment, or code; a consumer repo's clone too |
| **G — copy** | one brief text that lives in two files: a `say` brief and the `.min` twin the boot renders, or one brief in two roles | the author who amends one copy; the clone that boots the other |

families D and E surfaced after the first walk, with I27, I28, and the F15 verdict (`rule.require.experience-catalog-evolution`). D splits from A because its subject is a test, not a change to state: the same red test reads two ways, and the fork is what the test proves. E splits from B because its subject is an entry in a consumer repo's inventory, not a row of this route's inventories.

## .family A — apply

| axis | values (closed) | why orthogonal |
|---|---|---|
| **A1 seat** | `design` (architect, before code) · `build` (mechanic, in code) · `review` (reviewer lane, after code) | each seat meets every scope, drive, and spec state below: the design seat holds a planned set of enforcements, the other two hold code |
| **A2 scope** | `value` (one value or object: a price, a surfer, a count) · `store` (one aggregate in one store) · `compose` (an orchestrator over parts) · `cross` (a flow across stores or services) | scope = how far the invariant reaches, set by the subject. each scope has its cheapest enforcement: a type or abstraction for `value`, a constraint or transaction for `store`, a seam test for `compose`, a transactional pattern for `cross` |
| **A3 drive** | `once` (one caller, one run) · `again` (a sequential repeat: a retry, a redelivery, a second click after the first returns) · `together` (concurrent callers: two clicks in flight, two workers on one job) | any scope can be driven each way. `again` and `together` stay apart because their enforcements differ: an idempotency key absorbs `again`; a version check or lock settles `together`. at `scope = value`, a held value is immutable (A13), so a repeat or a race meets the `once` boundary — a coverage subsumption, not a lost axis: drive still bites at `value × together × broken`, where the break *is* the lost immutability. mutability is therefore no hidden axis; a mutable shared value is a value of A4 (`broken`) |
| **A4 spec** | `held` (stated, and its enforcement holds it) · `unstated` (no invariant named) · `broken` (stated, and the enforcement — designed or written — fails to hold it) · `unstatable` (no single invariant fits the subject as one whole; it must split) | the state of the spec, at any seat and scope. `broken` at `design` = an enforcement set that misses a break path. `unstatable` at `value` = one type that means two concepts, cured by a split |

product: 3 × 4 × 3 × 4 = **144 cells**, walked in `1.vision.experience.case=_.md`. no cell is impossible: each value of each axis meets each value of the others.

## .family B — curate

| axis | values (closed) | why orthogonal |
|---|---|---|
| **B1 item** | `lesson` (I01–I29) · `tactic` (O01–O14, A01–A23) · `transact` (T01–T33) · `fulcrum` (F01–F15) | the three inventories share one row shape: a proposed call, a `ruled` cell, a blanket. a fulcrum shares the first two — a taken fork, a `verdict` cell — and the wisher rules it the same way (case 5) |
| **B2 proposed** | `adopt` · `reject` · `defer` · `covered` | each inventory uses all four, in its own words. `amend` (I10, I11, O13, A18, A20) folds into `adopt`; the transactional `core` and `situational` fold into `adopt` (two depths of one brief), and `drop` into `reject`. each fold differs only in the edit execution makes, not in how a ruled, disagreed, or blank verdict is read, so every family B cell handles them as their fold. the edit difference lives in 5.1's blueprint |
| **B3 ruled** | `agree` (wisher keeps the call) · `disagree` (wisher flips it) · `blank` (wisher has not ruled the row) | the wisher's answer is independent of the call proposed |
| **B4 blanket** | `unset` · `agree unless ruled` (one line atop each inventory) | set per inventory, independent of any one row; it decides only what a `blank` row means |

product: 4 × 4 × 3 × 2 = **96 cells**. the `fulcrum` slice holds 24; 21 are impossible by nature (X): a fulcrum's taken fork is always a call to adopt that fork, so B2 is `adopt` alone, and the fulcrum summary carries no blanket line, so B4 is `unset` alone. 3 fulcrum cells are reachable (ruled `agree` · `disagree` · `blank`).

## .family C — boot

| axis | values (closed) | why orthogonal |
|---|---|---|
| **C1 reach** | `say` (booted text) · `ref` (booted pointer, read on demand) | a ruled lesson takes either reach |
| **C2 budget** | `fits` · `near` (fits, within 2% of the cap) · `overflows` | the role's cap, measured by `rhachet roles cost`. `near` splits from `fits` because the author meets a different render: a warn with the headroom left and the cure, before any red |
| **C3 plan** | `matches` (the brief boots at the reach its row planned) · `drifts` (it boots at another reach — a forbid pole slipped to `ref`, a catalog member booted at all) | a spec edit can move any brief to any reach at any budget; the plan is the inventory's verdict, the reach is what `boot.yml` says |

product: 2 × 3 × 2 = **12 cells**.

## .family D — arbitrate

| axis | values (closed) | why orthogonal |
|---|---|---|
| **D1 proves** | `invariant-kept` · `invariant-amended` (the change amends the entry on record) · `contract-replaced` (an implementation contract the change replaced) · `contract-kept` · `unnamed` (the test asserts a domain rule no entry names; glue never lands here — it is `contract-kept` or `contract-replaced`) | the five verdicts of the arbiter (`philosophy.invariants-are-the-source`); any red test sits in exactly one |

## .family F — write

family F surfaced at `5.1`, with I31 (the wisher asked for the ban in chat). its subject is a write, not a change to an invariant, so it sits apart from A.

| axis | values (closed) | why orthogonal |
|---|---|---|
| **F1 form** | `noun` · `plural` · `react-hook` · `external-key` (stripe `address.state`, the oauth param) · `compound` (`orderState`, `stateMachine`, `app_state`) · `near-word` (`statement`, `getState`, `stateful`, `restate`, `setState`) | the regex record must catch the first four and pass the last two; each form crosses a different word boundary. `external-key` is banned in sense and exempt in name; `compound` is banned in sense and invisible to the hook |
| **F2 attempt** | `first` · `retry` (inside the nudge window) | the HARDNUDGE fork: any form can be written first or retried |
product: 6 × 2 = **12 cells**.

## .family G — copy

family G surfaced at `5.3`, with the tests that pin the boot (`boot.lessons`, `briefs.twins`). its subject is a text held in two files, not a reach or a budget, so it sits apart from C.

| axis | values (closed) | why orthogonal |
|---|---|---|
| **G1 copy** | `min-twin` (a `say` brief and the `.min` the boot renders in its place) · `role-twin` (one brief shipped in two roles, e.g. `define.invariant`) | a brief can carry either copy, or both; each copy has its own file to drift |
| **G2 sync** | `equal` (both copies hold the amend) · `drifts` (one copy holds a line the other lacks) | any copy can drift; an amend lands in one file at a time |

product: 2 × 2 = **4 cells**.

## .axes considered and set aside

| candidate axis | why not an axis |
|---|---|
| language (typescript, bash, sql) | the lessons are language-neutral; a type in ts and a check constraint in sql keep the same invariant |
| failure cost (web app vs pacemaker) | it selects the enforcement (I04), not the experience; every cell below already assumes our cost tier (information logistics) |
| enforcement (type, constraint, transaction, test, solver) | an output of the experience, chosen inside a cell, not a precondition of it |
| repo (this repo vs a consumer repo) | the briefs ship identically to both; only family C differs, and C1/C2 hold it |
| actor = `system` (a cron, a queue worker) | a system actor is the *caller* of a change, not a reader of a brief. it meets no brief and has no felt experience. its effect, a repeat drive, is already A3: a queue that redelivers is `again`, a worker pool is `together` |
| statement form (`declarative` · `names-mechanism`) for family E | `names-mechanism` is barred in every kind and place (`define.invariant`: an entry never names its enforcement), so the axis would hold one live value. the enforcement lives in code, cited at most by an optional `.enforcement=` zoom-in — not a state of the entry. the bar stays on record as a forbidden invariant in the catalog |
| resource state (fresh · corrupt · absent) | for family A, an absent or corrupt resource is one more break path of the subject, so it sits under A4 `broken` (an enforcement set that misses "the payment api times out mid-charge"). for family B, the absent verdict is B3 `blank`. for family C, the absent headroom is C2 `overflows`. a separate axis would duplicate those three values |
