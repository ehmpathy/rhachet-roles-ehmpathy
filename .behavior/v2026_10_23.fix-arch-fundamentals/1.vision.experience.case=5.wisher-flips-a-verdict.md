# case 5 — wisher-flips-a-verdict · happy critipath

cell: family B · `any item × any proposed × disagree`

## .narrative

the wisher said up front: *"i expect to disagree with some of the choices, so lets plan to review them."* so every call this vision makes sits in a row with two columns: `proposed` (the vision's call and why) and `ruled` (blank).

the wisher opens `1.vision.inventory.transactional-patterns.md` and reads T26: event-sourced state, proposed `drop`. the wisher disagrees. one surf school client needs full audit replay. the wisher types `situational — audit replay is required for the school client` into the `ruled` cell. on T28 (unit of work, proposed `drop`), the wisher agrees and types `agree`.

the larger calls also sit in the fulcrum inventory (`.fulcrums/`), one entry per call, each with its reason at the time and its rework cost. the wisher rules those the same way.

at execution, the clone reads only the `ruled` column. it builds T26 into `ref.transactional-patterns.md` as adopted, and leaves T28 out. the yield of execution lists every row it built, each tied to its ruled verdict.

## .bdd `[tn]` timeline

```
given the three inventories, each row with a proposed verdict and an empty ruled cell
  when [t0] the wisher writes "situational — audit replay required" in T26's ruled cell (proposed: drop)
    then the inventory now holds the wisher's call beside the vision's — both visible
  when [t1] the wisher writes "agree" in T28's ruled cell (proposed: drop)
    then T28 stays out of every brief
  when [t2] the execution clone builds ref.transactional-patterns.md
    then T26 appears as adopted, with the wisher's reason
    and  T28 does not appear
    and  the 5.1 yield cites, per row, the ruled verdict it followed
```

## .why critipath

the wisher named this path before the vision existed (freq: every review of this route; the wisher expects to disagree with *some* calls).

a hand rewrite of the vision is a lever, but not a workable route to the goal. the goal is that execution builds the wisher's call. execution reads each row's `ruled` cell (case 6 `[t0]`), not the prose around it. so a prose edit leaves the row's proposed call in force, and execution builds the call the wisher rejected. to make a hand edit land, the wisher would have to find and rewrite the proposed cell, the read across, and every fulcrum that cites it, for each disagreement. that is the review rebuilt by hand, with no record of which call was the vision's and which the wisher's (cost: a silent build of a rejected call, or a lost audit trail). so the care is critipath.
