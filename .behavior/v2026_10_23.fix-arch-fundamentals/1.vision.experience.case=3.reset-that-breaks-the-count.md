# case 3 — reset-that-breaks-the-count · sharp critipath (fails loud)

cell: family A · `review × value × once × broken` · lessons I01, I10

## .narrative

a mechanic writes `getBeginnerCount` to size the soft-top rental. the code is the wish's anti-example (lines 75–85): it adds one per beginner, and on any other level it resets the count to zero. on `[Beginner, Advanced, Beginner, Intermediate, Beginner]` it returns 1. the school orders one soft-top for three beginners.

the reviewer lane reads the change with I01 and the amended `rule.require.clamp-edge-cases` (I10) on hand. it asks for the invariant and gets one from the header: *the count equals the number of beginners in the roster*. then it checks that the tests clamp the invariant at its break case — a beginner, then a non-beginner, then a beginner. that case is absent; the tests cover only `[]` and `[Beginner]`. the reviewer raises a blocker that names the invariant, the absent clamp, and the input that breaks it.

the mechanic adds the clamp. it goes red at once: expected 2 for `[Beginner, Advanced, Beginner]`, got 1. the reset line is deleted; the clamp goes green; reverted, it goes red again (the clamp bites).

## .why critipath

every transformer that sums, counts, or totals domain records holds an invariant of this shape (freq high). a wrong count under-orders boards and leaves surfers on the sand (cost: behavioral, monetary). the tests the mechanic first wrote pass, so no fallback catches it; only a clamp on the break case does.
