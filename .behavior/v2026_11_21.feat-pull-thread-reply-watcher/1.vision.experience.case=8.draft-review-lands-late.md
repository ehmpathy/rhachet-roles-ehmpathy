# case=8 · a draft review lands after newer comments

covers: C18r, C18f, C18p (arrival = `via-draft-review`). sharp · critipath.

## .narrative

on #1143 the commander read the whole diff before he said a word. he drafted 8 inline comments over 12 minutes in one draft review, and submitted it 6 minutes after the last, with an approval. until that submit, the 8 comments did not exist to anyone else. but github stamped each with its id and its `created_at` at the moment he drafted it.

here, on `#7`, the commander drafts three comments the same way. midway, while he still drafts, the crew replies to an older thread, and the daemon reads the pr: the crew's reply has the newest id the daemon has seen.

minutes later the review is submitted. the next read sees three comments whose ids sit below the crew's mid-draft reply. a cursor that keeps only the largest id seen would call them old, and the crew would never hear of them — a silent drop of a whole review.

the daemon keeps the set of review comment ids it has seen, as it already does for check runs. the three ids are not in the set, so they are new. the reply task lists all three threads. the approval in the same review rides the same alert, after the replies.

## .why it fails safe

- the seen-id set cannot be passed by a newer id, so no comment is dropped by its order of arrival
- at the prime tick, freshness reads the review's `submitted_at`, so a watch set mid-draft still raises the drafts once they are submitted
- a re-read of a seen id raises naught, so the set never doubles a task

## .bdd sketch

```ts
given('[case8] #7 under watch; the commander drafts a review', () => {
  when('[t0] a newer crew reply is read while the review is still a draft', () => {
    then('the drafts are not visible yet; naught for them', ...);
  });
  when('[t1] the review is submitted; its comment ids sit below the crew reply', () => {
    then('each draft comment raises once, in the reply task', ...);    // C18
    then('the approval of that review follows the replies', ...);
  });
  when('[t2] a watch was set mid-draft, so the prime tick sees the review', () => {
    then('freshness reads the review submitted_at; the drafts raise', ...);
  });
  when('[t3] the next read sees the same ids', () => {
    then('naught raises again', ...);
  });
});
```
