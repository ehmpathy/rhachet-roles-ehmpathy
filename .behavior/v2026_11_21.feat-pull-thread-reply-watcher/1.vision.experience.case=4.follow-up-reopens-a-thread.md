# case=4 · the commander replies inside a thread the crew answered

covers: C5, T1, S1. happy · critipath.

## .narrative

on #1222, the crew answered "they ttl after 1w idle?" with a list of what the pr held. the commander came back in the same thread: "so why not fix these now?". that follow-up owed a reply as much as the root did; it waited 37 minutes for one.

here, the crew sits idle at its prompt on `#7`. the commander replies in thread `4601230000`. the daemon reads it on the next tick: a human comment after the crew's last answer. the thread awaits again. the alert carries the new comment whole, plus the root's first line, so the crew knows which conversation this is without a read:

```
🐢 heads up dude...

🐚 git.pull.watch — reply task on #7
   ├─ pr: ehmpathy/surf-demo#7
   ├─ thread 4601230000 · follow-up · by @uladkasach
   │  ├─ re: they ttl after 1w idle? or after all clones disconnect?
   │  ├─ url: https://github.com/ehmpathy/surf-demo/pull/7#discussion_r4601239999
   │  └─ says
   │     └─ so why not fix these now?
   └─ next: reply first, then resume: rhx git.pull.comment set --which 7 --in ehmpathy/surf-demo --reply-to 4601230000 --key answer-4601239999-c<clone> --from <file|@stdin> --mode apply
```

`--reply-to` names the root, since github threads every reply under it. the key names the comment answered, so a second answer to this follow-up edits the first.
