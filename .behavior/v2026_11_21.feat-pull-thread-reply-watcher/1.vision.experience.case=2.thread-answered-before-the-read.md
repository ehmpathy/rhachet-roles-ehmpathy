# case=2 · the crew answered before the daemon read

covers: C2, C8, C11. happy · critipath.

## .narrative

`#7` has been quiet for an hour, so the daemon reads it every 30 min. the commander opens a thread: "isnt it `git.pull.watch set`, not .set?". the director sees it first and relays it into the crew's session. the crew answers at once, through `rhx git.pull.comment set --reply-to …`, under the app login `ehm-a-seaturtle[bot]`. the set writes the reply's id into the crew's ledger.

twenty minutes later the daemon reads `#7`. the thread is new since its cursor. but its last comment is the crew's: the id sits in the crew's ledger. the thread awaits naught. no alert goes out.

the crew is never told twice of a thread it already answered, so it never sends a second, late answer.

## .narrative — the crew's own reply (C8)

the crew replies to a thread the daemon already raised. the next read sees one new comment: the crew's own, ledgered. it opens no wait, and it is no `comment.new` either. silence.
