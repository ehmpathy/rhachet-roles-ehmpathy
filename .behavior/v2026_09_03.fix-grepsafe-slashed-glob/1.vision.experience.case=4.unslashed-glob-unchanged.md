# case=4 · an unslashed glob is untouched

> cells B1–B2 · `unslashed × rg × pattern-hits` · **happy** · **critipath**

## .why a critipath

acceptance 2. every documented example of `grepsafe --glob` is unslashed (`*.ts`, `*.md`), and so
was every prior test. that is why the defect survived: it cannot fire on any example the docs show.

it cuts both ways. the unslashed shape was the only covered one, so a regression shows there first,
and the repair touches exactly the code that inspects the glob.

## .the narrative

a dev greps markdown the way the help text taught:

```
rhx grepsafe --pattern 'seaturtle' --glob '*.md' --files-only
```

before the repair: works. after: works identically. the caller never learns the glob now splits
into legs.

## .the aha

the repair must be invisible to everyone whose glob already worked. a fix that trades a false zero
for a new one on the one covered shape is a net loss.

## .the bdd sketch

```gherkin
given [case4] a repo with 'src/foo.ts', 'src/foo.md', 'src/foo.json', each holds 'target'

  when [t0] an unslashed glob is used
    rhx grepsafe --pattern 'target' --glob '*.ts'
  then only 'foo.ts' is returned
    and 'foo.md' and 'foo.json' are absent

  when [t1] the prior snapshots are re-run
  then only the 'engine:' line differs       # its shape is F1 (open, best-guessed A)
```

## .the snapshot note

the `engine:` line shifts the prior snapshots. review that shift by eye, never blind-resnap: a
snapshot update that also swallows a result change is how a regression ships. keep the explicit
assertions beside it (`rule.require.snapshots`).

the lifts (`--hidden`, `-L`, `--no-ignore`) apply to named legs only. an unslashed glob names no
root, so its walk keeps the default skips (case=9 `[t3]`); a match it skips behind a dot dir is
named by the pruned zero (case=12 `[t4]`).
