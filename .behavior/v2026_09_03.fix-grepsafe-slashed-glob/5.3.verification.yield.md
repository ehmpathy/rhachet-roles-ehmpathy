## `--head` exited 141 on large results

`--head` exited 141 (SIGPIPE) with no output on any result past 64 KiB. found byhand at the
ergonomics review.

```
$ rhx grepsafe --pattern 'local' --glob 'src/**/*.sh' --head 3     # before
   └─ 💥 failed with an error                          (exit 141)

$ rhx grepsafe --pattern 'local' --glob 'src/**/*.sh' --head 3     # after
   ├─ lines: 1480 (first 3)                            (exit 0)
```

| isolation | result |
|-----------|--------|
| same scope, `--head 99999` | ✅ exit 0 |
| 89-line scope, `--head 3` | ✅ `lines: 89 (first 3)` |

it is a false failure: the search succeeded and the tool reported a crash, on exactly the large
results a caller most wants cut. pre-existent (`git log -S` → #344); the stone admits no prior
failures.

### `git.repo.test` — five sanitizers

each of five suites scrubs a spinner tick's duration to `(Xs)` and none scrubs the tick count:

```
- Snapshot  - 3                       ← idle box
+ Received  + 1                       ← busy box, same command
        ├─ 💤 inflight (Xs)
-       ├─ 💤 inflight (Xs)
-       ├─ 💤 inflight (Xs)
```

the count is `host speed ÷ emit threshold`: a clock value that looks like a property of the command.

measured 2026-09-25, 4 CPUs:

| 1-min load | peers active | reds |
|---|---|---|
| ~16 | 2 peer worktrees' jest runs | 8 of 448 |

| idle, 3 prior days | none | 0, three runs |

repair — each sanitizer gained one line:

```ts

```

`[case19][t1]` now pins the mechanism: the claim is "it refuses before the run starts", and the
spinner ticks only once a run is underway.


## defects found in grepsafe at this gate

### a glob read from the wrong root

rg anchors `--glob` to its cwd, not to the search root. grepsafe ran every search from the caller's
cwd, so a glob split into root + tail read the tail from the wrong place:

| # | glob | before | cause |
|---|------|--------|-------|
| D1 | `docs/*.md` | also `docs/sub/b.md` | tail `*.md` unanchored — any depth |
| D2 | `p/*/a.md`, `p/{docs,.hid}/*.md` | `0` | tail with a slash, read from cwd |
| D3 | `{docs/*.md,.hid/*.md}` | `.hid/c.md` absent | a brace group has no literal prefix, so no root is named and the dot dir is skipped |
| #780 | `*.md`, match only in `.behavior/` | `no line matched the pattern` | a skipped dot dir wears a true zero's words |

repair:

- **legs** — each brace alternative names its own root. one rg run per root, from that root, so the
  tail reads where the caller meant it. `/` anchors the tail
- **`-e`** — the pattern rides behind `-e`, so `-v marks` is a pattern, not a flag
- **the pruned zero** — on a clean zero from an unnamed walk, a `--hidden` probe. a hit renders
  `none in the walked trees, but N hidden file(s) hold a match` and a 🥥 with the `--path` that
  reaches it. the probe also runs beside results — see the radio section below

**clamp** `[case41]`, teeth by three disjoint reverts:

| revert | red |
|--------|-----|
| drop the `/` anchor · drop `-e` · skip the pruned probe | `[t0]` D1 · `[t3]` dash · `[t4]` #780 |
| no brace expansion | `[t2]` D3 + D2 brace (3 tests) |
| every leg from the caller's cwd | `[t0]` D1 · `[t1]` D2 · `[t2]` |
| restored | ✅ green |

`[t5]` is the control: no match anywhere ⇒ a plain zero, no 🥥.

`[case33][t2]` flipped: `--path src --glob 'src/nested/**'` found its file only through the cwd read
that caused D1 and D2. it now reads `no file matched the glob`, as case34 pins. F28 holds the call.

### `--head` cut an unordered set

`[case8][t2]` snapshotted `b.txt`, then read `c.txt` on the next run, same code and fixture. `rg`
walks in parallel, so `head -n "$HEAD_LIMIT"` kept whichever files landed first, under a tally that

with the sort disabled, `--head 3` over 12 equal files, two runs in one test:

```

```

`sanitizeOutput` sorts the body it is given, but the cut already discarded the rest upstream. a
filename mask would green the suite and leave `--head` nondeterministic for every caller.

```bash

if [[ -n "$HEAD_LIMIT" ]]; then
```
