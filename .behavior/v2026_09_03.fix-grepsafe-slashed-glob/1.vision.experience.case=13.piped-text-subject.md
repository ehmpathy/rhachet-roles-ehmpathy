# case=13 · piped text is the subject

> outside the product · **sharp** · **critipath** · radio #598, #622

the subject is piped text, not a tree, so no D1–D8 coordinate varies. it is a demo, not an
itemization, because the defect was a false answer — the harm class the wish names.

## .the narrative

a clone wants to know whether a command's output names a stone. it pipes the output in:

```
rhx route.drive | rhx grepsafe --pattern '5.3.verification'
   └─ files: 9
```

grepsafe ignored stdin and searched the repo. the nine hits were real files that hold the string, so
the clone read "the output names it" — whatever the piped text held. no error, no hint: the answer
to a different question, in the frame of a right one.

## .the contract

| stdin | grepsafe does |
|-------|---------------|
| a pipe or a file, with text | searches the text; `input: stdin (piped text)`; rows read `N:line` |
| a pipe, empty | the file search stands |
| a socket (what node hands a child) | waits up to 1s for a first byte; text ⇒ searches it, idle ⇒ the file search stands |
| `/dev/null` or a tty | never read; the file search stands |
| any, with `--from @stdin` | read to EOF; no text ⇒ a zero on the pipe, never a file search |
| text beside `--path`, `--glob`, or `--type` | refused: two subjects named |

## .the bdd

```gherkin
given [case42] a repo whose files hold 'paddleOut'
  when [t2] text that holds it once is piped in
  then the match is its line in the pipe, under 'input: stdin (piped text)'
  when [t3] piped text holds no match
  then a zero on the pipe, not the repo's hits
  when [t4] piped text rides beside --path, --glob, or --type
  then refused, exit 2
  when [t5] --from @stdin meets an empty pipe, or stdin that cannot be read
  then a zero on the pipe, or a refusal — never a silent file search
  when [t6] the pipe is empty (control)
  then the files are searched
  when [t13] the text arrives through a shell pipe, or [t14] a `<` redirect
  then the same answer as [t2] — the FIFO and file arms, not node's socket
```
