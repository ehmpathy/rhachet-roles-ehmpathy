## .the narrative

a clone needs the shape of an installed package:

```
rhx grepsafe --pattern 'domain-objects' --glob 'node_modules/domain-objects/package.json' --files-only
   └─ matches: 0
```

the file is there. the same tool finds it once the path is named another way:

```
rhx grepsafe --pattern 'domain-objects' --path node_modules/domain-objects --files-only
   └─ 2 files
```

the clone concludes the package is absent. the tool argued for a false fact, and the caller has no
signal that a rule was applied on their behalf.

## .the measurement — a control isolates gitignore

`dist/` is visible, real, and gitignored (`.gitignore:25:dist`). the same string lives in `src/` and
`dist/`, byte-identical.

| # | probe | gitignored? | result |
|---|-------|-------------|--------|
| control | `--glob 'src/**/*.sh'` | no | ✔ 1 file |
| 15 | `--glob 'dist/**/*.sh'` | yes | ❌ `matches: 0` |
| 16 | `--glob 'node_modules/domain-objects/package.json'` | yes | ❌ `matches: 0` |
| 17 | `--path node_modules/domain-objects` | yes | ✔ 2 files |

same pattern, glob shape, engine, and depth; the only variable is `.gitignore`. this is case=5's
divergence 2, measured as a defect.

## .the two-lift narrative — `[t5]`

`[t1]` renders one lift and `[t4]` three; neither renders two, so the four two-lift cells owe their
own story.

### arm a — `hidden × real × ignored`: a reviewer cannot read its own review dir

`.reviews/peer/` carries exactly two barriers: reached through a dot path (`.behavior/…/.reviews`),
a real directory, and its contents ignored by a nested rule (`.reviews/peer/.gitignore:2:*`).

```
rhx grepsafe --pattern 'needs your talons' --glob '.behavior/…/.reviews/peer/*.md'
   └─ matches: 0                                          # probe 18

rhx grepsafe --pattern 'needs your talons' --path .behavior/…/.reviews/peer
   └─ matches: 0                                          # probe 18b — the workaround also fails

rhx globsafe --pattern '.behavior/…/.reviews/peer/*.report.md'
   └─ 6 files                                             # probe 18c — the bash arm sees them
```

### arm b — `visible × linked × ignored`: a built fixture

`armbfixture → dist/domain.roles/mechanic/skills/claude.tools`: visible, a symlink, target
gitignored, link itself not (`git check-ignore armbfixture` exits 1).

| # | call | result |
|---|------|--------|
| control | `--glob 'src/domain.roles/mechanic/skills/claude.tools/*.sh'` — the tracked twin | ✔ 1 file |
| 19 | `--glob 'armbfixture/*.sh'` | ❌ 0 |
| 19b | `--path armbfixture` | ✔ 1 file |
| 19c | `globsafe --pattern 'armbfixture/*.sh'` | ✔ 4 files |

### the arms split on the escape

| arm | the ignore rule sits | `--path` |
|-----|----------------------|----------|
| probe 17 — `node_modules/domain-objects` | on the root itself | ✔ 2 files |
| b — `armbfixture` | on the target root the link resolves to | ✔ 1 file |
| a — `.reviews/peer` | on the contents, a nested `*` | ❌ 0 |

`rg`'s explicit-root override covers the root, never the contents beneath it. `realpath` resolves
`armbfixture` under `dist/`, and `rg` treats that root as an override, but no override reaches a rule
nested beneath it. so the unified rule — a named path is searched as named — must reach the files
under the named path, not merely the directory entry.

both arms are critipath: arm b on freq × cost, arm a because its escape is shut. a repair that keys
`--no-ignore` to a `check-ignore` hit on the typed path passes arm b and can still fail arm a — the
reason the step has two arms.

## .the `--path` narrative — `[t6]`

a clone audits the round's peer reviews and names the directory outright:

```
rhx grepsafe --pattern 'blocker' --path .reviews/peer
   └─ matches: 0
```

no glob was written, so none could be malformed. the clone concludes the reviews hold no blocker and
writes that down. bash lists six files there, and they hold the word; the cause is a `.gitignore` of
`*` inside `peer/`. this false zero has no glob in it: the defect is whether the tool searches what
the caller named.

### `[t6]` and `[t3]` demand opposite outcomes on the same cells

| invocation | the tree is | required |
|---|---|---|
| `--path .reviews/peer` | named | search it — `[t6]` |
| `--pattern x` with no glob, walk meets `peer/` | merely met | skip it — `[t3]` |

a repair must read the invocation, never the tree. a filter keyed on the tree ("is it ignored?")
answers both alike and breaks one. build both.

`[t6]` is easy to build wrong: `rg`'s override already lifts a rule on the named root (probe 17), so a
fixture with a root rule goes green before any repair. `[t6]`'s rule must sit beneath the named root.

## .why critipath

| the caller wants | `--path` alone |
|---|---|
| `node_modules/**/*.md` — a filter inside an ignored tree | `--path node_modules --glob '*.md'` works only because the glob is unslashed; a slashed filter re-enters the defect |
| a glob that spans two ignored roots | `--path` takes one root; no composition |

the alternative covers the simplest shape and fails the general one.

## .`[t3]` keeps the repair from a defect of its own

> *"it's an automatic opt-into gitignore-**ignore**"* — triggered by the path the caller typed.

| the caller | the walk |
|---|---|
| types `node_modules/**` | ignore rules do not apply — search it |
| runs `--pattern x` with no glob, and the walk meets `node_modules/` | ignore rules apply — skip it |

the opt-in is scoped to what was typed, never to the process. a bare `--no-ignore` satisfies `[t1]`
and `[t2]`, breaks `[t3]`, and turns every ordinary search into a `node_modules` crawl — case=2's
shape: a wrong answer traded for an unusable one.

F3 option D follows: a named ignored tree is searched by design.

## .the triple stack — `[t4]`, the wish's own headline

measured 2026-09-04: `.agent/repo=ehmpathy/role=mechanic/briefs` is hidden (`.agent`), linked
(→ `dist/…`), and ignored twice — `.agent/repo=ehmpathy/.gitignore:6:*` at the link and
`.gitignore:25:dist` at its target.

| call | result |
|------|--------|

| `--glob '.agent/repo=ehmpathy/role=mechanic/briefs/**/*.md'` | ❌ `matches: 0` |

```
when grepsafe is invoked with a glob whose path is hidden AND linked AND gitignored
  [t4] then it finds the file
       and a --path call on the same directory agrees    # both forms, one answer
       # passes only when all three lifts land: hidden (case=8), link
```

each barrier alone yields a false zero (the isolation table: `1.vision.yield.md`), so a repair that
clears two still returns `matches: 0` here. the rule is nested, so a repair that reads only the root
`.gitignore` fails it. the one rule for all three lifts: `case=_`, "one rule for all three lifts".

## .the fixture

hermetic: `dist/` and `node_modules/` belong to this checkout, not the test. the control is required:
without it, a green `[t1]` cannot be told from a repair that disabled the walk's filters. each row
carries exactly its own barriers, and the same string sits in every one, so a zero is never a
fixture defect.

| for | the dir | dot? | link? | ignored? | where the rule sits |
|-----|---------|------|-------|----------|---------------------|
| `[t1]`/`[t2]` — one lift | `ignored/` | no | no | yes | the root `.gitignore` |
| `[t5]` arm a — two lifts | `.hidden-ignored/` | yes | no | yes | the root `.gitignore` |
| `[t5]` arm b — two lifts | `linked-ignored/` → a real target | no | yes | yes | the root `.gitignore` |
| `[t4]` — three lifts | `.hidden-linked-ignored/` → a real target | yes | yes | yes | the root `.gitignore` |
| `[t6]` — nested rule | `nested-ignored/` | no | no | yes | a `.gitignore` of `*` inside it |
| control | `tracked/` | no | no | no | — |

the `[t6]` row cannot merge into another: every other rule sits on the root, where `rg`'s override
already lifts it under `--path`, so a `[t6]` built on any of them goes green before the repair.
`[t3]` further needs that no `--path` names the ignored tree.

probe 18b (`.reviews/peer`) is `[t6]`'s evidence, not its fixture: it is also hidden, and its
contents change every round. the clamp uses the hermetic `nested-ignored/`.
