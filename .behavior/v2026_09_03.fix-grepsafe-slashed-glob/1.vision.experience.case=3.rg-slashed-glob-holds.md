# case=3 · the rg arm holds a slashed glob — measured, not assumed

> cell A4 · `slashed × rg × pattern-hits` · **happy** after the repair · **critipath**. A4 splits by
> tail shape T; case=12 holds the two sub-shapes that failed

## .why this case exists

the wish flags an unverified suspicion: the `rg` arm passes an absolute search root, which the
reporter suspected also breaks relative globs. their patch showed no change, which proved naught,
since `rg` never ran on their box.

> *"someone with `rg` truly on PATH should check it, and this round is that party"*

this box has `rg` at `/usr/bin/rg`, so the check ran.

## .the measurement — 2026-09-03, this repo, before the repair

| # | command | result |
|---|---------|--------|
| 1 | `--glob 'src/**/*.sh'` | ✔ finds `…/claude.tools/grepsafe.sh` |
| 2 | `--glob '*.sh'` | ✔ the same file (baseline) |
| 3 | `--glob 'domain.roles/**/*.sh'` | ✔ none — a mid-path segment is not a prefix |
| 4 | `--glob 'nosuchdir/**/*.sh'` | ✔ 0 at once, no hang |
| 5 | `--path src --glob 'src/**/*.sh'` | finds the file |
| 6 | `--path src --glob 'domain.roles/**/*.sh'` | finds none |

the suspicion is disproven: the absolute root never touched the glob. runs 5 and 6 show why — rg
reads `--glob` from its **cwd**, not from the search root. run 1 held only because the cwd was the
repo root and its tail `**/*.sh` holds no slash to misread.

that cwd read is the cause case=12 names. grepsafe now runs rg from each leg's root, so runs 5 and 6
flip: `--path src --glob 'domain.roles/**/*.sh'` finds the file, and `src/**` names `src/src/`, an
honest zero (F28).

## .the bound — visible paths only

## .the narrative

a dev hunts a helper they half-remember under `src/`:

```
rhx grepsafe --pattern 'safe content search' --glob 'src/**/*.sh' --files-only
   └─ the file, first try
```

a question, an answer, move on. that unremarkable moment is what this case protects: a repair aimed
at the other causes must not disturb it.

## .the bdd sketch

```gherkin
given [case3] a repo with 'src/deep/file.sh' that holds 'safe content search'

  when [t0] a slashed glob is used
    rhx grepsafe --pattern 'safe content search' --glob 'src/**/*.sh' --files-only
  then the file is returned
    and the engine reads 'rg'

  when [t1] a mid-path segment glob is used
    rhx grepsafe --pattern 'safe content search' --glob 'deep/**/*.sh' --files-only
  then no file is returned                  # a glob names a path from its root
```

## .the bound on this evidence

one box, one `rg` version. rg's glob semantics are stable and documented; the `engine:` line is the
hedge if a future box disagrees.
