# 5.1.execution.from_vision.yield — grepsafe answers, or refuses; never false-zeros

**grepsafe searches with one engine (`rg`), from the root each glob names. it lifts every skip on a
path the caller NAMES, keeps the skip on a path it merely MEETS, names its engine and the kind of
every zero, and refuses when `rg` is absent or the search cannot run.**

the false zero is cured at its causes — hidden, ignored, linked, and a glob read from the wrong
root — not masked at one.

## what grepsafe does

### the engine

- `command -v rg && rg --version` proves the binary runs, so an aliased or broken `rg` counts as
  absent. this alone cures the reporter's box, where a zsh alias was invisible to bash
- no grep arm (F9). no `rg` ⇒ exit 2 with a fix hint, never a `0`
- the probe keeps `rg`'s stderr, so the refusal parts *"was not found"* from *"is on PATH but could
  not run … rg said: <reason>"*, on both streams
- every vibes frame names `engine: rg`

### the legs — which roots, and how each glob reads

- `expand_glob_braces` splits a glob into its brace alternatives, a string walk with no `eval`.
  each alternative names its own root: `{src/**,.behavior/**}` walks both
- an alternative whose literal prefix expands to an in-repo dir makes that dir its leg's root, with
  the tail as the filter. alternatives with one root and one named-ness share a leg
- each leg runs rg **from its root**: rg reads `--glob` from its cwd. the tail is `/`-anchored, so
  `docs/*.md` skips `docs/sub/` (D1) and `p/*/a.md` finds `p/docs/a.md` (D2)
- a glob under `--path` reads from `--path`, never from cwd (case33, case34, F28)
- overlapped legs report a file once; `--context` blocks stay apart across legs
- the pattern rides behind `-e`, so one that opens with `-` is never a flag
- the header names every root: `path:` for one, `paths:` for more

### the scope

- a `--path` other than `.`, or a glob alternative whose prefix is a real in-repo dir, sets
  `--hidden --no-ignore -g '!.git'` on that leg alone. a slash alone names no path: `**/*.md` lifts
  no skip (case30)
- the prefix expands via `realpath`, not `-L`: a NAMED symlink is followed, a MET one is not
  (case26). `.git` stays excluded (case25)
- each root passes `validate_root_within_repo_or_fail` as it becomes a root, so a refusal names the
  flag that crossed (`named by: --path` or `--glob`)
- an absolute prefix stays absolute: `/etc/*.conf` is refused, never re-read as `./etc`
- a root that will not expand states why (EACCES, ELOOP, ENOTDIR); the `--path` refusal splits on
  visibility (`could not be opened` vs `does not exist`)
- every `--path` is searched, one leg per root. a bare positional root stands alone: beside another
  root it is refused in either order, and the refusal names both
- piped text is the subject when present (case=13); beside `--path`, `--glob`, or `--type` it is
  refused as a second subject

### the zeros and the tally

- each zero names its kind: `no line matched the pattern` · `no file matched the glob` (or `the
  type`, `the glob and type`) · `no readable file matched` · `the path named by --glob could not be
  read` · `could not tell which zero — the file probe failed`
- a match in a skipped hidden path is never a plain zero (#780): `none in the walked trees, but N
  hidden file(s) hold a match`, plus a 🥥 with the `--path` that reaches it. beside results, the
  same skip reads `skipped: N hidden file(s) also hold a match` — a partial answer says so
- a fatal engine error is never a zero. an empty-dir probe re-runs a failed leg; what still fails is
  the input, refused with no count, exit 2 (case35)
- rg's stderr is captured apart from stdout; diagnostics ride an `unread` branch with a `fix:` line,
  on both streams (case31). the fix follows the reason: a denial, another cause, or both
- an `unread` line names only a path the caller typed, never a join artifact (case33)
- every rg stderr capture is sorted with `LC_ALL=C`
- the tally label follows the mode: `files` (`--files-only`, `--count`), `rows` (`--context`),
  `lines` otherwise
- `--head N` cuts with `--sort path`, counts before the cut, and says `(first N)`. the cut uses `<<<`,
  so a large result cannot die on SIGPIPE
- `--head` accepts `^0*[1-9][0-9]{0,17}$`, recast base-10 once
- `--files-only` wins over `--count` from either position

### the refusals

- every refusal renders through `emit_refusal`: 🐢 frame, 🐚 tree, 🥥 hint, on both streams in vibes
  mode; one glyph-free `grepsafe: …` line on stderr alone under `--output pipeable` (F20)
- every refusal names a next move; `[case40]` walks the set, `[case37][t7]` the pipeable prefix
- the retired `--output direct` exits 2 and names `pipeable`
- an unknown flag is refused after the parse loop, so its stream never depends on argv order

### globsafe, the peer

- the `--head` gate, digit cap, base-10 recast, and one-root rule, each with a fix
- every refusal in the house frame, on both streams; stderr alone under pipeable (F16)
- `--help` gained `notes:`, the retired-value entry, and the `--output MODE` metavar

### structure

- `build_leg_scope_flags` is the one scope producer; `build_leg_cmd` builds each leg's command
- `print_tree_block` renders a sub-bucket; an empty body renders no row
- `is_tree_node_last` reads `DIAGNOSTICS` live, so `└─ results` never sits above `unread`
- `count_lines` owns its empty-input guard and strips BSD `wc` pad
- the repo-root strip is a bash substitution, never a regex
- both probes declare their TOCTOU window at the site
- no `2>/dev/null` on an error path; a failed `cd` exits 2, never a clean zero's 1
