## .narrative

beaver's pr #1021 reads CONFLICTING. it runs the plan: 4 behind, 6 ahead, meter 5 → 4. it applies. git stops on `pnpm-lock.yaml` and on
`src/domain.roles/boot.budget.integration.test.ts`. exit 2, both files named, the merge in flight.

beaver edits the test file, keeps both hunks, stages it. then it runs `continue` too soon. the verb
refuses and names only `pnpm-lock.yaml`. beaver takes main's lock whole; the verb nudges a refresh.
`lock refresh` reinstalls against the merged `package.json`, which restores beaver's own dep bump,
and stages the lock. `continue` lands the merge commit: seaturtle author, sponsor trailer, meter 4.

`git.commit.push --mode apply` fast-forwards the remote branch. the pr turns MERGEABLE, ci runs on
the merged tree. an hour later beaver runs `begin --mode apply` again before review: `already level`,
no spend. no human saw a prompt.
