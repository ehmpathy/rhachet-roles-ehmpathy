### snapshot change rationalization

every snap change is an addition against `origin/main`, plus one new case in the hook suite (`[case30b]`: `git merge` offers `begin`, `git merge --abort` offers `abort`, `git merge --continue` offers `continue`): no shipped output changed. within this route, the renders were reworded on purpose (F34):
- begin, take, continue, and lock name each next move as a label and a paste-ready command; a placeholder sits in angle brackets (`<main|branch>`), and a lockfile on screen is named, never `<lock>`
- a grant only a human runs sits on its own leaf, `a human runs: …`, under the move it unblocks
- a plan that flags a refusal ends `clear each ⚠️ apply will refuse above, then run with --mode apply`
- abort reads `HEAD: … (as before the merge)`: true for a merge begin never started
- lock names `package manager:`; ops leaves quote `'infinite'` and list `corrupt, absent, spent`
- the temp-path mask keeps the subpath after the temp dir (`/TEMP/absent.git`)
