# case=2.catchup-with-conflict

cells: #6 · #29 · #30 · #34e · #34f · feel sharp → happy · care critipath

the #1021 shape: a pr CONFLICTING for want of one merge commit.

## .narrative

beaver applies the merge. main edited `src/domain.roles/boot.budget.integration.test.ts` and
`src/domain.roles/mechanic/readme.md`; so did the branch. git stops. the verb does not pretend: it
prints both conflicted files, says the merge is in flight, and names the two exits — settle and
`continue`, or `abort`. exit 2: the caller must act. beaver opens the test file, keeps both hunks,
stages it with `rhx git.stage.add`, and runs `continue` too early, before it settles the readme.
the verb refuses again and names only the file still in conflict. beaver edits the readme in a
hurry and stages it with one `=======` line left behind. git would commit that file as is; the
verb reads each staged file the merge touched, finds the marker, and refuses: exit 2, the file
named, the marker lines named. beaver removes the line, stages it, runs `continue`, and the merge
commit lands with the same author, trailer, and meter spend as case=1.

the spotlight `[case2c]`: the same settled merge, in a repo whose commit-msg hook refuses the
header. git fails the commit. the verb fails loud with the hook's own words as the cause, and the
merge stays in flight with every settlement kept. exit 1: a malfunction, not the caller's input.
beaver fixes the hook's cause and runs `continue` again, or backs out with `abort`. no settled work
is lost and no meter use is spent.
