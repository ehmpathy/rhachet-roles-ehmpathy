# 1.vision.experience.dimensions

the experience space of `rhx git.branch.catchup`: a mechanic brings its feature branch level with
`origin/main` by one merge commit, then pushes plain.

## .actor

one actor **runs** the verb, so actor is not an axis of the walk. three other candidates were
weighed:

| candidate | runs the verb? | verdict |
|---|---|---|
| mechanic (a clone, no human at its prompt) | yes | **the actor**. the wish names it; a human at a terminal runs raw `git merge`, so the verb exists for the actor who cannot |
| human lever owner (grants quota, binds sponsor, grants stage) | no — meets its refusals | beside the walk, inventory #39. its whole encounter is one printed command; it varies on no axis of the verb |
| human reviewer (reads the pr) | no — meets its output | beside the walk, inventory #40. it sees one merge commit row; it varies on no axis of the verb |
| system / cron (a scheduled catch-up, no clone) | could, in principle | inventory #41, itemized: the wish asks for no scheduled catch-up and none exists. the verb's plan default, exit codes, and no-prompt design already suit one, so no axis value changes |

## .the axes

| # | axis | values | relation to the others |
|---|---|---|---|
| A | **step** (the act the mechanic runs) | `begin plan` · `begin apply` · `take` · `lock refresh` · hand-settle + `git.stage.add` · `continue` · `abort` | the mechanic's choice. **conditional**: A constrains E — each step is legal only on certain merge states (collapse rule 2). hand-settle is no subcommand of the verb, but the conflict path cannot finish without it, so it is walked |
| B | **divergence** (branch vs `origin/main`) | `level` (0 behind) · `behind-only` (≥ 1 behind, 0 ahead: no own commits, so it cannot conflict) · `behind-clean` (≥ 1 behind, ≥ 1 ahead, no conflict) · `behind-conflict` (≥ 1 behind, ≥ 1 ahead, one or more files conflict) | a property of the two histories. the four values partition it: ahead-count and conflict-state are folded in where they can co-occur, and `behind-only` cannot conflict by nature |
| C | **conflict kind** | `text` · `lockfile` · `delete-vs-modify` | **conditional**: refines B's `behind-conflict` value only; elsewhere C does not exist (collapse rule 1) |
| D | **gate** (the first precondition that fails, else `open` — commit gates, ref and tree guards, the fetch, and the stage grant alike; collapse rule 4 records which flow step reads each) | `open` · `on-main` · `dirty-tree` · `rebase-in-flight` · `blocked-global-or-org` · `no-quota` · `no-sponsor` · `fetch-fails` · `stage-blocked` | each guard reads its own state source (ref, index, git dir, global/org blocker files, local meter `.uses`, bind, network, local meter `.stage`). independent of A–C |
| D′ | **quota kind** (only where D = `open`) | `finite` (`uses` ≥ 1) · `infinite` | **conditional**: refines D's `open`. decides whether the meter spends `−1` or stays `infinite` |
| E | **merge state** (git dir, at the moment the step runs) | `idle` · `merge-in-flight-unsettled` · `merge-in-flight-settled` | the residue of a prior `begin apply`; A constrains which E a step may meet |
| F | **time** (what moved while the mechanic worked) | `still` · `branch-moved` (someone pushed to the branch since fetch) · `main-moved` (origin/main advanced after `begin`'s fetch) | a property of the two remotes; independent of every local axis |

`lock refresh` adds one sub-state: whether every manifest (`package.json`) is settled. it varies
only under `lock refresh`, so it is walked there, not raised to an axis.

## .the walked product

the full box is 7 × 4 × 3 × 9 × 2 × 3 × 3 = 13 608 cells. most collapse, by five structural facts:

1. **C exists only where B = `behind-conflict`.** elsewhere C = n/a
2. **A constrains E.** `begin` needs E = `idle`; `take`, `lock refresh`, `continue`, `abort` need
   E in flight; hand-settle needs E = `merge-in-flight-unsettled`. a subcommand on the wrong E is a
   sharp rejection, one cell per (step, wrong E). hand-settle on the wrong E is impossible: with no
   file in conflict, an edit is ordinary work, not a settle
3. **D is checked first and short-circuits.** a closed gate makes B, C, F moot for that run, so
   each gate is one cell per step (and mode) that reads it
4. **each gate binds only the steps that read it** — the latent `stage-of-flow` dimension, made
   explicit here rather than raised to an axis, since it is fully set by A:

   | flow stage | step (A) | gates it reads |
   |---|---|---|
   | preflight | `begin` | on-main, dirty-tree, rebase-in-flight, blocked-global-or-org, no-quota, no-sponsor |
   | fetch | `begin` | fetch-fails |
   | settle | hand-settle | stage-blocked (`take` and `lock refresh` stage inside the verb) |
   | commit | `continue` | blocked-global-or-org, no-quota, no-sponsor |
5. **D′ and F matter only where they change the outcome.** quota kind changes only the meter line
   of a commit; time changes only what the push meets and whether the pr is still behind

## .the hidden axis the grid surfaced

the gate axis D splits by **who holds the lever**: `on-main`, `dirty-tree`, `rebase-in-flight`,
`fetch-fails` the mechanic can clear alone; `blocked-global-or-org`, `no-quota`, `no-sponsor`, and
`stage-blocked` only a human can clear. so D hides a `lever-owner` axis (mechanic · human). it
changes the output each refusal owes: a mechanic lever prints the command to run; a human lever
prints the command the human runs, and says so.

it also splits by **what plan owes**. plan mutates naught, so a gate that guards only the mutation
(`dirty-tree`, `rebase-in-flight`, `no-quota`) lets plan preview and flag what apply will refuse.
a gate that guards the whole intent (`on-main`: never merge into main) or a human's deliberate
halt (`blocked-global-or-org`, `no-sponsor`, as `git.commit.set` refuses them in plan too) refuses
in both modes.

a third latent axis: **side name**. in a rebase, `ours` = main and `theirs` = the branch. in a
merge, `ours` = the branch and `theirs` = main. the same word flips sense across two verbs a
mechanic runs in one week. the `take` cell must name sides by what they are (`main` · `branch`),
not by git's pronoun. see `1.vision.yield.md` § awkward.
