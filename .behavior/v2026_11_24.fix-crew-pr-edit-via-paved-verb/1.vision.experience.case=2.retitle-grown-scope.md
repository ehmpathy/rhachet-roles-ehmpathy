# case=2: a driver retitles a pr whose scope outgrew its title

feel: happy · care: critipath · cell c2

## .narrative

the pr opened as `fix(reef): bound the kelp scan`. the route then also mapped the kelp beds. the title now undersells the work. the driver opens `rhx git.commit.push --help`; the section names `git.pull.title set` "when the scope outgrew the title". it pipes the new title in and reads the plan. a piped title is spent once read, so it pipes it again with `--mode apply`. had it rerun with `--mode apply` alone, the verb would refuse the empty title before any write, and the refusal would hand it the exact command with the pipe in front (c18).

## .bdd sketch

```
given a seaturtle-opened pr whose title names only the first commit
  when [t0] the driver runs `rhx git.commit.push --help`
    then stdout names `rhx git.pull.title set` and "when the scope outgrew the title"
  when [t1] the driver runs `echo 'feat(reef): map the kelp beds' | rhx git.pull.title set --from @stdin`
    then the plan shows old → new title; no write
  when [t2] the driver pipes the same title in again, with `--mode apply`
    then the title is written, read back, and matches
  when [t2'] the driver reruns with `--mode apply` but pipes no title
    then the verb refuses the empty title before any write, and its hint names the pipe
```
