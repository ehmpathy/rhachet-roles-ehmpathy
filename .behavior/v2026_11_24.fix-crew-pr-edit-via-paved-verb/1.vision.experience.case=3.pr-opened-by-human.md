# case=3: the pr was opened under another login

feel: sharp · care: critipath for c3 (other-auth) · alterpath for c4 (foreign), which rides this case since it shares the refusal path

## .narrative

keyrack was down at push time, so the pr opened `--auth as-human`, under the human's gh login. the driver follows the help to `git.pull.description set` and runs it with the default `--auth as-ehmpath`. the verb refuses before any write: the pr was opened by the human's login, not by seaturtle. the hint names the exact command under `--auth as-human`, in plan, and says: if the author is that login, plan, then add `--mode apply`; else ask the author.

fails safe: fast (before any gh write), loud (ConstraintError, exit 2), teaches the fix (the exact rerun). no edit lands under the wrong identity.

for c4 (a pr a stranger opened), the same refusal fires; the rerun under the other `--auth` refuses too, and the second hint line — ask the author — is the fix.

## .bdd sketch

```
given a pr opened under the human's login (--auth as-human)
  when [t0] the driver runs `rhx git.pull.description set --from ./.temp/body.md`
    then exit 2, `✋ ConstraintError: <repo>#<n> was opened by <human>, not by ehm-seaturtle (as-ehmpath)`
    then the hint names `rhx git.pull.description set --from ./.temp/body.md --auth as-human`
    then no write reached github
  when [t1] the driver reruns with `--auth as-human`, then `--mode apply`
    then the body is written under the human's login, signed with the seaturtle footer

given a pr a foreign login opened
  when [t0] the driver runs the verb under either --auth
    then exit 2 each time; the hint says ask <author> to set it
```
