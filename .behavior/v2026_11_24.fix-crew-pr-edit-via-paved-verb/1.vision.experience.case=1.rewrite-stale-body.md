# case=1: a driver rewrites the stale body of its own pr

feel: happy · care: critipath · cell c1 (the pre-fix walk is case=6)

## .narrative

the driver's route on svc-protools grew three commits past the first. the pr body still tells only the first. it pushes the new commit; the tree reads `pr #128 (found)`. the body has not moved.

this is the #128 walk, on an install that holds the verbs (`≥ v1.41.0`; #128's own install predates them, see c16). before this fix, `--help` ended at `--help, -h`, and the header never named the verbs. the driver reached for raw `gh`. the footer vanished.

now the driver runs `rhx git.commit.push --help`. the last section says push never rewrites an extant pr, and names `git.pull.description set` for a body that no longer tells the work. it writes the new body to `./.temp/body.md`, runs the verb in plan, sees the diff and the footer append, then adds `--mode apply`. the read-back sha matches. the body lands under seaturtle.

## .bdd sketch

```
given a seaturtle-opened pr #128 whose body is stale
  when [t0] the driver runs `rhx git.commit.push --mode apply`
    then the tree reads `pr #128 (found)` and the body is unchanged
  when [t1] the driver runs `rhx git.commit.push --help`
    then stdout holds "to edit the pr after it is open"
    then stdout names `rhx git.pull.description set` and "when the body no longer tells the work"
    then stdout says "never raw `gh` to edit a pr"
  when [t2] the driver runs `rhx git.pull.description set --from ./.temp/body.md`
    then the plan shows the new body and the seaturtle footer append; no write
  when [t3] the driver adds `--mode apply`
    then the body is written as seaturtle, read back, sha matches
```
