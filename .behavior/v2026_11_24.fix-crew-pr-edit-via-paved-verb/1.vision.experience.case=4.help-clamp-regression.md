# case=4: a maintainer drops the pointer from the help

feel: sharp · care: critipath · cell c5 (c13 as the green twin)

## .narrative

months later, a maintainer trims `git.commit.push --help` and cuts the edit section as noise. they run the push suite before they push. `[case31]` goes red: its `toContain` on `git.pull.description set` and `git.pull.title set` fail, and the snapshot diff shows the lost lines. the maintainer reads why the lines exist, and restores them — or argues the cut in review, in the open. the pointer cannot vanish silently.

## .bdd sketch

```
given a maintainer with the edit section cut from `git.commit.push --help`
  when [t0] the maintainer runs `rhx git.repo.test --what integration --scope git.commit.push --mode apply`
    then the maintainer sees `[case31]` fail: stdout lacks `git.pull.description set`
    then the maintainer sees `[case31]` fail: stdout lacks `git.pull.title set`
    then the maintainer sees the snapshot diff name the lost lines
  when [t1] the maintainer restores the section and reruns
    then the maintainer sees `[case31]` pass and the snapshot match
```
