# case=6: a driver on a pre-fix install meets the deny, and recovers

feel: sharp · care: critipath · cell c6

## .narrative

the driver's repo pins a release that holds the edit verbs (`≥ v1.41.0`) but not this pointer. its pr body is stale. `rhx git.commit.push --help` ends at `--help, -h`; the booted header names no edit verb. so the driver reaches for `gh pr edit 128 --body-file ./.temp/body.md`.

the mechanic permission hook blocks it before it runs: `gh pr edit` sits in the deny list (`init.claude.permissions.jsonc:199`). the block is a `✋ ConstraintError` that names both paved alternatives (`commands.alternatives.jsonc:129`). the driver runs the one for the body, in plan, then applies. no raw edit lands.

fails safe: fast (blocked before the call), loud (a qualified ConstraintError), teaches the fix (the exact paved commands). the cost of the pre-fix state is one wasted attempt, which the pointer this work adds removes. the clamp in case=4 keeps a post-fix install from a slide back into this cell.

## .bdd sketch

```
given a driver on an install with the edit verbs but no pointer, and a stale body on its own pr
  when [t0] the driver runs `rhx git.commit.push --help`
    then stdout ends at `--help, -h`; no edit verb named
  when [t1] the driver runs `gh pr edit 128 --body-file ./.temp/body.md`
    then the hook blocks it before any call: `✋ ConstraintError: this command is not paved`
    then the block lists paved alternatives for `gh pr edit`:
      `rhx git.pull.title set --from ./.temp/title.md`
      `rhx git.pull.description set --from ./.temp/body.md`
    then the pr body is unchanged
  when [t2] the driver runs `rhx git.pull.description set --from ./.temp/body.md`, then adds `--mode apply`
    then the walk proceeds as case=1 [t2]-[t3]
```

source of `[t1]`'s text: `rhx permissions.get --for 'gh pr edit 128 --body-file ./.temp/body.md'`, run on this repo.
