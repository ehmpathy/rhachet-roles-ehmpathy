# case=5 — main changed a path that was set aside

sharp · critipath

## .narrative

the clone's tree holds an unstaged `package.json` (an upgrade it has not committed) beside the ambient files. main shipped a release and bumped `package.json` too. the rebase takes main's version; then the put-back writes the clone's set-aside bytes over it, as the wish demands (byte for byte). the unstaged diff now also reverts main's bump at that path. the skill does not hide this: it flags the path as `main also changed this path`, and names the two next moves — inspect the diff, then either take main's version or re-apply the clone's edit atop it. so the clone never folds a silent revert into a later commit. for the ambient files the same overlap is benign — they regenerate on the next session; for `package.json` the flag and its fix are what stand between the clone and a revert of main's release.

## .timeline

```
given('[case5] main changed a path that also holds an unstaged edit')
  when('[t0] begin --unstaged ignore --mode apply')
    then('the rebase completes')
    then('the path reads back byte for byte as the set-aside copy')
    then('the output flags the path: main also changed it')
    then('the output names the fix: git diff <path> to inspect; git checkout HEAD -- <path> to take main version; or re-apply the edit atop it')
```
