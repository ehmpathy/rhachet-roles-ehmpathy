# 1.vision.experience.case=_ — the inventory

care = freq × cost, and only that. boundary density sets the order of the rows (densest first), never the care.

"stop" = any pause that leaves a rebase in progress: a conflict, or a non-conflict stop mid-replay (see dimensions).

## .actors

- clone (mechanic) in a worktree — every row above
- human who runs the skill by hand — same rows; no distinct experience, since the skill reads no actor
- pr reviewer — experiences E15's invariant only: the pr diff holds no ambient file edit. covered by the E1 and E3 `then` on commit contents

## .rejection invariants

- no path set aside through `git stash` (E14)
- no set-aside edit ever enters a commit (E15)
- the set-aside never touches the index (E29)
- every set-aside path reads back byte for byte, link for link, and mode for mode once the rebase ends, by any exit (E1, E3, E4, E20, E23, E28)
- the store is deleted only after every held path reads back, and never while a rebase is in progress (E22, E34)
