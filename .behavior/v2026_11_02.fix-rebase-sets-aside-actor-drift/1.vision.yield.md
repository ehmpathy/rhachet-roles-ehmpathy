# 1.vision — a clone rebases a tree that holds ambient drift

## the outcome world

### day in the life
a clone's pr conflicts with main. it runs `rhx git.branch.rebase begin --unstaged ignore --mode apply`. the skill sets the regenerated ambient settings aside, rebases, puts them back exactly. the clone pushes. the human learns of it from a green pr, not from a page.

### before / after
| | before | after |
|---|---|---|
| clone tree holds ambient drift | `begin` refuses: "commit or stash your changes first" | `begin --unstaged ignore` rebases; drift reads back identical |
| the refusal | names neither the paths nor a safe cure; suggests a stash, which is shared across worktrees | lists each path; names `--unstaged ignore` |
| conflict mid-rebase | n/a (never got this far) | drift stays aside; `continue` or `abort` puts it back |
| who unblocks | a human | the clone |

### the aha
the refusal itself teaches the cure. a clone that hits it once reruns with the flag and never needs a human for this again.

## the contract

```
rhx git.branch.rebase begin [--mode plan|apply] [--unstaged ignore|include]
rhx git.branch.rebase continue [--unstaged ignore]
rhx git.branch.rebase abort [--unstaged ignore]
```

- no flag + unstaged edits → exit 2, `✋ ConstraintError`, paths listed, cure named (stdout + stderr)
- `ignore` → each unstaged path copied (link as link — a broken link too, whose target is absent — bytes as bytes, absence as absence) into a per-worktree store in the git dir, reset to HEAD, rebase runs, each path put back
- conflict → paths stay aside; `continue` (on completion) and `abort` put them back
- drift returns at a held path mid-conflict → `continue` resets it to HEAD; the held copy supersedes it at put-back, named in output with the recovery hint (fulcrum F4)
- a fresh edit at a path NOT held, mid-conflict → `continue` and `abort` refuse before git acts, exit 2, and name `--unstaged ignore` on the same command, which adds the edit to the store (fulcrum F5)
- the rebase fails to start (no replay, no rebase in progress) → `begin` puts every held path back at once, deletes the store, prints git's output, exit 1
- any stop that leaves a rebase in progress (a conflict, or a non-conflict stop mid-replay) → the store stays; `continue` / `abort` put back
- `abort` with no rebase in progress but a store present → recovery: puts back every held path (the cure for a crash or a partial put-back). `begin`, plan included, and `continue` refuse in that state and name `abort`
- staged content in the index → `begin` refuses before any set-aside; the set-aside never touches the index
- `include` with unstaged edits → refused, with the cure `git.commit.set --unstaged include` (fulcrum F1). with no unstaged edits, every flag is a no-op
- never `git stash`; never a set-aside edit in a commit

## done

a pr against main, ci green, watched via `rhx git.release --watch`. automerge stays off: no `git.release --mode apply`, since the release waits on the commander's review. this overrides the habit to enable automerge after a green watch.

## mental model

- a clone would say: "rebase, but leave my settings alone"
- metaphor: a surfer sets a board on the sand before a duck dive under the wave, then picks it back up. the board never rides the wave
- our term: **set aside** (verb), **put back** (verb). not "stash" — that names the git stash stack this feature exists to avoid

## evaluation

- goals: the clone unblocks itself on a conflicted pr (met); the ambient files stay out of commits (met by construction: they are reset to HEAD before the rebase replays commits)
- pros: same flag shape as `git.commit.set`; no shared state across worktrees; the refusal teaches the cure
- cons: a second store to reason about mid-conflict; `include` is a refusal, not a behavior
- edgecases + pit of success:
  - main changed a set-aside path → put back as-is, flagged (case=5, fulcrum F3)
  - a prior run died with paths aside → `begin` refuses and names `abort` as the cure; `abort` with a held store and no rebase puts the copies back (E7)
  - up to date → exits before any set-aside; tree untouched (E10)
  - plan mode → lists what it would set aside; touches naught (E8)

## open questions & assumptions

- [research] Q1: does `git rebase --continue` refuse on an unstaged edit at an unrelated path? case=6's end state holds either way. if no, `continue` needs no reset branch: the put-back alone supersedes the drift, and only the output note remains. execution confirms by test first, and builds the reset only if git refuses
- [answered] root cause of the drift: the ambient dir tracks generated files with per-machine content (a home-dir symlink target; home paths and version-bound hooks in `settings.of.repo.json`). the source cure belongs to rhachet, caught as a reseed dream: `dreams/v2026_11_02.reseed.ambient-settings-carry-per-machine-content.md`. this route still stands: any unstaged edit blocks a rebase today, not only ambient drift
- [answered] assumption: the scope is unstaged edits to tracked paths (`git diff`), which is exactly what `begin` refuses on today. untracked files and staged edits are out of scope
- [answered] concurrency: git serializes the rebase itself, but not the set-aside before it nor the put-back after. the store is created by an atomic `mkdir`, so a second `begin` in the same worktree finds it present and refuses (E21); `abort` recovery and `begin` cannot both own it
- [answered] not an assumption: that unstaged edits are only ambient drift. this route's own tree also holds unstaged `package.json` and `pnpm-lock.yaml`. `ignore` sets aside every unstaged path, so case=5 (main changed a held path) is frequent: main bumps `package.json` each release. hence case=5 is a critipath, and its output flag carries real weight
- [answered] assumption: the grove link's target exists. false on a fresh machine; the contract covers a broken link explicitly, and the clamp's symlink should be broken so the test bites
- [answered] the dirty-tree refusal moves from exit 1 to exit 2, and its text changes. the extant `begin` test `[case6] dirty work tree` pins exit 1 and the old text, so execution changes an extant test. that change is owed, not drift: the refusal is a caller-must-fix constraint (`rule.require.exit-code-semantics`), and the wish asks the text to name paths and cure. the other `begin` guards that exit 1 on a constraint stay as-is: out of scope
- [answered] a put-back that fails partway (a write error; a path now blocked by a dir): `💥 MalfunctionError`, exit 1, each path not yet put back named, the store kept whole and deleted only once every path reads back. the cure is the recovery: `rhx git.branch.rebase abort` with a held store puts back what is left (inventory rows E22, E27)
- [wisher] F1: what should `--unstaged include` do on a rebase? best guess: refuse, name `git.commit.set --unstaged include` as the cure (60%). alternatives: commit the edits atop the branch first, or carry them forward as a 3-way patch. the drive proceeds on the guess; the rework is clean
- [wisher] F3: when main changed a held path, put back byte for byte and flag it (best guess, 65%), or leave main's version and keep the held copy? the wish's byte-for-byte wording favors the guess; `package.json` is the case that argues against it
- [research] does `git rebase --abort` discard an unrelated unstaged tracked edit? F5's guard makes the answer moot (abort refuses before git acts on a not-held edit); execution records the answer in the test for the guard
- [answered] F5 (`continue` and `abort` take `--unstaged ignore`, 80%) follows from the wish's demand that they put back: they cannot put back a path they never held
- [answered] F2 (store in the worktree's git dir, 90%) and F4 (held copy supersedes mid-conflict drift, 75%) follow from the wish's own promises; recorded in `.fulcrums/`, no wisher input needed

## what is awkward

- `include` accepted by the parser only to refuse. it keeps the shape the wish named, at the cost of a flag value with no behavior (F1)
- the put-back can silently revert main's change at a shared path; a flag in the output is the only guard (F3)
- set-aside state spans two commands (`begin` → `continue`/`abort`); a crash between them leaves a store a human must understand. E7's refusal is the mitigation
