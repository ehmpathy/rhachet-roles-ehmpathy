actor: a clone (mechanic) in a worktree, with a pr that conflicts with main. a human seldom runs this skill by hand; when one does, the same paths hold.

### .the terms

- **fails to start**: git exits before it replays any commit, and leaves no rebase in progress (fetch error; git refuses, e.g. an untracked file in the way)
- **stop**: any pause that leaves a rebase in progress — a conflict, or a non-conflict stop mid-replay. both resume through the same `continue` / `abort`, so they share one value. the skill keeps the store on any stop; it never asserts the tree reads as before `begin` while a rebase is in progress

## .orthogonality

- D1 × D2: the flag only matters when the unstaged set is non-empty
- D3 × D4: plan never rebases, so D4..D8 apply to apply mode only
- D2 × D4: orthogonal by construction across the D4 values that put back (clean, fails to start, continue, abort). one put-back operation serves all of them, so each D2 kind round-trips the same way under each. under `up to date` no set-aside occurs at all (E10). the clamp proves the hardest kinds (content edit + broken symlink); each other kind has its own row
- D6a and D6b are per-path facts, independent of each other: each rule applies to its own path. both are **conditional on D4 = stop**: under up to date, clean, or fails to start there is no pause, so no window (E24)
- D7 = yes halts `begin` before D4 is reached, and plan too (E31). its cure is `abort` with no rebase in progress (E27); `continue` in that state refuses and names `abort` (E32)
- D8 meets every D4 value that puts back; one put-back operation, so one behavior
- D9 = staged halts `begin` before any set-aside (E29), so D9 meets no downstream axis
- D10 = claim or set-aside halts `begin` before D4 (E38, E39); D10 = git's abort meets only D4 = stop → abort (E44); D10 = a fresh-edit step meets only D4 = stop, at `continue` or `abort`, and halts before git acts (E50)
- D14 meets only D4 = stop → continue, after git has picked; the store stays held for a retry (E49)
- D11 × all: the store lives in each worktree's own git dir, so a second worktree meets every axis as if alone (E41)
- D12 × D2: orthogonal; each path shape round-trips under each kind through the same copy operation (E42)
- D13 is `begin`-only and meets D4 as if the edit had been there at the first read (E43)
