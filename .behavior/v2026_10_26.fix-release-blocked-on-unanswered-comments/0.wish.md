# wish: git.release refuses a release while a review comment has no reply

task: ehmpathy/rhachet-roles-ehmpathy#1171 (read it first; its words govern this wish)

## .what
`rhx git.release --into main|prod --apply` refuses, exit 2, while any review thread on the pr has no reply. the refusal names each thread (file, line, the reviewer's first words) and the verb that answers it: `rhx git.pull.comment`, released in #1143.

`--watch` and plan mode still run, and show the same count, so a driver sees the gate before it applies.

## .why
the commander approves pull requests on condition: "approved, as long as the comments are addressed before release". tonight, two prs (#693, then nearly #1143) reached the merge with that condition read by hand or not at all. the gate belongs in the release verb, where every driver passes it.

## .the done
- a thread whose only comment is the reviewer's own is unanswered; a reply in the thread, or a resolved thread, answers it
- the refusal is clamped: a fake pr with one unanswered thread refuses red without the fix, green with it; a pr whose threads all have replies passes
- the count rides in the plan output beside the ci tally
- no bypass flag
