# case=5 — automerge already on; apply refuses and disables it

feel: sharp · care: critipath · boundaries: refusal, automerge disable

## narrative

the clone enabled automerge on pr #700 yesterday; checks are still inflight today. overnight the commander left a review comment. the clone runs `rhx git.release --apply`. it sees `🌴 automerge disabled [removed] — comments unanswered`, the commander's row, and a ConstraintError with the answer verbs; exit 2. a few minutes later ci goes green — and the pr stays open, since no automerge is left to merge it. the clone answers the comment, reruns `--apply`, and automerge goes back on.

## timeline

```
given a feat pr with automerge found, checks inflight
  and one unanswered review thread

when [t0] rhx git.release --apply
  then `gh pr merge --disable-auto` is called
   and stdout shows `🌴 automerge disabled [removed] — comments unanswered`
   and ✋ ConstraintError + the answer verbs
   and exit 2

when [t1] the clone answers the thread and reruns `rhx git.release --apply`
  then `💬 all comments answered`, automerge enabled [added], watch — as today
```

## fail-safe proven
fast: automerge is disabled before ci lands, so no merge can follow · loud: exit 2, ConstraintError · teaches: the row and the answer verbs. the gate holds even after checks pass, since no automerge remains to merge past it.
