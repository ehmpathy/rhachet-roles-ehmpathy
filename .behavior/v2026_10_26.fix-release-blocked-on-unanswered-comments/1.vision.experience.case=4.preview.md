# case=4 — plan and watch preview the gate

feel: happy · care: alterpath (chosen — the wish names it) · boundaries: preview

care: apply still refuses, so a missed preview has a workable fallback → alterpath. demoed since the wish asks for it verbatim ("`--watch` and plan mode still run, and show the same count").

## narrative

the clone runs bare `rhx git.release` after a push, as `rule.require.watch-release-after-push` asks. it sees the rows now, not at apply.

## timeline

```
given a feat pr with checks passed, one unanswered review thread

when [t0] rhx git.release
  then `💬 1 comment(s) unanswered` + the row
   and hint: `--apply will refuse until each comment has an answer`
   and exit 0 (unchanged from today)

when [t1] rhx git.release --watch   (automerge unfound)
  then the same `💬` line + row, then the watch section as today; each poll re-reads comments
   and watch never enables automerge
   and exit per checks (unchanged)
```

the one exception (F11): if automerge is already on — set by an earlier apply — and a poll finds an unanswered row, watch turns automerge off and exits 2. that is the safe direction, and the only mutation watch ever makes (see case=9).

## why it is worth a demo
the driver learns of the gate one step before it bites: the rows and the hint arrive on the run it already makes after every push (`rule.require.watch-release-after-push`), so apply's refusal is never a surprise.
