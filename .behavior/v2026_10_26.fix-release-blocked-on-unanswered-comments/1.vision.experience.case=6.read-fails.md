# case=6 — the comment read fails

feel: sharp · care: critipath · boundaries: malfunction

## narrative

the clone has run a dozen releases this hour across repos, and github's rate limit runs out. it runs `--apply` on the next pr. the verb cannot read the pr's comments — and it says so, loud: a MalfunctionError with github's own words, and the next move (wait for the reset, then rerun; or check the token scope). it does not see `💬 all comments answered`, and no merge happens. it waits for the reset and reruns.

## timeline

```
given gh fails on the comment read (exit nonzero, stderr "API rate limit exceeded")

when [t0] rhx git.release --apply
  then 💥 MalfunctionError: could not read pr comments
   and the gh stderr is shown
   and the fix is named: `rerun once the rate limit resets (gh api rate_limit shows when)`; on a 401/403 scope error, `check the token scope`
   and exit 1
   and no automerge call; no `💬 all comments answered` line

when [t1] rhx git.release   (plan)
  then the same malfunction, exit 1
```

## fail-safe proven
fast (with automerge off, the read fails before any automerge call or merge; with automerge on, the gate first turns it off — that path is case=13) · loud (exit 1, qualified header) · teaches (names the rerun or scope fix — the extant rate-limit hint at `git.pull.comment.operations.sh:524` is the model) · never a false green — `rule.forbid.failhide`.
