# case=12 — a comment waits, and github refuses to turn automerge off

feel: sharp · care: critipath · boundaries: refusal, automerge disable, mutation fails

found at 5.3.verification (`rule.require.experience-catalog-evolution`). the read succeeds and the comment state is known; what fails is the mutation the refusal depends on.

## narrative

the clone enabled automerge on pr #42 yesterday; checks still run. the commander left a review comment overnight. the clone runs `rhx git.release --apply`. the gate reads the comment and tries `gh pr merge 42 --disable-auto`, but the token lacks the scope, and github answers `HTTP 403`. the skill does not claim a refusal it could not enforce. it prints the row, then `💥 MalfunctionError: could not disable automerge while 1 comment(s) wait on an answer`, states that automerge is still on and github will merge once checks pass, and prints the one command that closes the hole: `gh pr merge 42 --disable-auto`. exit 1. the clone, or a human with the scope, runs that command; then the clone answers the comment and reruns `--apply` as in case=5.

a near variant: the disable fails because automerge is already off (`not set to auto-merge`), and a re-read confirms it reads off. the goal holds, so the skill converges: the ordinary refusal at exit 2, never a false malfunction.

```
  and a re-read shows automerge off

   and exit 2
```
