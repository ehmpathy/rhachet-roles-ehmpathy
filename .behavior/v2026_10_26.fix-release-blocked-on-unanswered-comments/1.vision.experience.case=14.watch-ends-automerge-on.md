# case=14 — the watch ends before the merge while automerge is on

feel: sharp · care: critipath · boundaries: watch exit, residual race (F6)

found at 5.3.verification (`rule.require.experience-catalog-evolution`). the dimensions doc names the residual window after a watch ends; this is what the driver sees at that moment, so a comment that lands later is not shipped in silence.

## narrative

every comment on pr #42 has an answer, automerge is on, and checks are slow. the clone runs `rhx git.release --watch`. fifteen minutes pass, or the clone hits ctrl-c, or its runner sends SIGTERM. the watch ends before github merges. the skill does not exit quietly: it says the watch stopped, that automerge is still on and github will merge once checks pass, and that no gate reads a comment that lands after this exit. it names both cures: rerun `rhx git.release --watch` to keep the gate, or `gh pr merge 42 --disable-auto` to turn it off.

if automerge is off, the stop line stands alone: no window is open. if the signal lands before the first poll read the pr, the state is unknown, and the skill says so (`automerge: unread`) rather than guess.

```
when [t3] the stop prints
  then `automerge: unread — this watch stopped before its first poll`
```

## fail-safe proven
loud: every exit path that leaves automerge on says so · teaches: names the rerun that keeps the gate and the command that closes the window · honest: an unknown state reads `unread`, never a guess. the window itself stays an accepted residual (F6): no process reads after the exit.
