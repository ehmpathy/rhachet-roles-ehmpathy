## .notes on itemized cells

- **#4 unknown on a shared box** — the lookup (`jest --showConfig`) fails when `node_modules/.bin/jest` is absent or jest cannot load the config. the skill adds naught (invariant 1); the run behaves as today. the care is alterpath by `freq × cost`: cost is today's load, but freq ≈ 0. npm and pnpm both link `node_modules/.bin/jest`, and a repo without it already breaks the skill's scope preview (`git.repo.test.sh:1586`: "cannot verify scope - jest --listTests failed", exit 1). a broken config fails the real run loud too, and jest's own error names the fix
- **#6 and #10 caller count vs the command's `--runInBand`** — a crew passes `-- --maxWorkers=16` to an acceptance run and still gets 1 worker. that is jest's precedence today, not a change the cap makes. sharp, but the cap neither causes nor worsens it; alterpath
- **#7, #9, #11** — the caller's own flag reaches jest alone, as today
- **multi-mode** (`--what all`, `--what unit,integration`) — each child invocation walks the cells above on its own, with the same args. one `--what all` run in `sql-schema-control` crosses #12, #1, #3, and #2 at once: case=5

## .invariants (forbidden outcomes)

each is a checkable rule the execution must hold:

1. **the skill never raises jest's worker count.** it only lowers it, to 4. a config of `maxWorkers: 1` (`declastruct-squarespace`, `sql-schema-control` integration configs) stays at 1
2. **the skill never adds a second worker flag.** when the caller passes `--maxWorkers`, `-w`, `--runInBand`, or `-i`, the skill adds none, so jest never receives two counts from the skill and the caller
3. **the skill never caps on ci.** `CI` set and not `false` → no worker flag, no lookup
4. **the skill never caps a non-jest kind.** `types`, `format`, `lint` run as today

## .density

case=5 crosses the most decision boundaries in one walk: four suites, four answers (no flag for lint, cap to 4 for unit, leave at 1 for integration, jest ignores the flag for acceptance). it is centered. case=1 crosses the most system boundaries for one suite: skill → jest config lookup → jest worker pool → the box's cores → the neighbor crew. case=2 is the sharpest: it spotlights the one regression a naive cap would ship, so its fail-safe stays legible apart from case=5.
