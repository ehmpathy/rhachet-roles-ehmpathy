# case=3: an explicit count stands

cell #5 · shared × explicit-count × command none · happy · critipath

## .narrative

late at night the grove is idle. a human wants the full unit suite fast and knows nobody else is on the box. they run:

```
rhx git.repo.test --what unit --mode apply --thorough -- --maxWorkers=16
```

the skill sees `--maxWorkers` after `--`. the caller already chose, so the skill adds no flag and skips the lookup. jest receives one count, `16`, and the suite runs on 16 workers.

if the skill had appended its own `--maxWorkers=4` too, jest would receive two counts. which one wins would depend on how jest parses a repeated flag, and the human could not predict it. the skill avoids the question: one flag, the caller's.

the same holds for `-w 16`, `--max-workers=16`, `--runInBand`, and `-i`.

## .bdd sketch

```
given a shared box (CI unset)
  and a jest config with maxWorkers: '50%'  (jest derives 18)
  when [t0] a crew runs `rhx git.repo.test --what unit --mode apply -- --maxWorkers=16`
    then jest receives `--maxWorkers=16`
    then jest receives no other worker flag
    then the suite runs on 16 workers
  when [t1] a crew runs `rhx git.repo.test --what unit --mode apply -- --runInBand`
    then jest receives `--runInBand`
    then jest receives no `--maxWorkers`
    then the suite runs on 1 worker
```
