# case=5: `--what all` crosses every boundary in one run

cells #12 (lint), #1 (unit), #3 (integration), #2 (acceptance), in one invocation · happy · critipath · densest by decision boundaries (case=1 is densest by system boundaries)

## .narrative — the clone

i am a clone on a 36-core grove, in `sql-schema-control`, about to push. i run the full gate:

```
rhx git.repo.test --what all --against local --env test --mode apply
```

four trees scroll past, one per suite, the same shape as before the cap:

1. **lint** passes as it always does
2. **unit** passes. its config says `'50%'`, so before the cap it took 18 workers; now the skill sends `--maxWorkers=4` and it runs on 4. on a busy grove its time holds steady, since no other crew's pool crowds it
3. **integration** passes, serial, as its config demands (`maxWorkers: 1`, `// run in series: tests share database state`). the skill sends naught, so the cap cannot make my suites race on the test database. no flake i would have to chase
4. **acceptance** passes on 1 worker. its npm command carries `--runInBand`; the skill reads that, sends no flag, and skips the lookup. same as today

my gate's result is the same as before the cap. i read no new line and pass no new flag. the two other crews on the grove never feel my run, because my one wide suite (unit) holds at 4.

a free-list of "cap or no cap" would miss that my one command needs four answers: no flag, cap to 4, leave at 1, and a flag jest ignores.
