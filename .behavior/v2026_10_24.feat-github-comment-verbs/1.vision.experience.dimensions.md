# 1.vision.experience.dimensions

the experience space of `git.pull.comment.get | set | del`, factored into orthogonal axes.

## .the axes

| # | axis | values |
|---|---|---|
| A | actor | `clone` (runs the verbs) · `sponsor` (the human whose gh login backs `as-human`) · `reviewer` (reads the pr in browser or email) · `maintainer` (runs the suite, by hand or in ci) |
| D1 | verb | `get` · `set` · `del` |
| D2 | kind | `body` (the pr description) · `issue` (a top-level pr comment) · `review` (an inline review-thread comment) |
| D3 | address | `all` (`--pr` alone) · `id` (`--id`) · `key` (`--key`) · `thread` (`--reply-to` + `--key`) · `self` (the kind names one target: `--kind body`) |
| D4 | remote state | `absent` · `same` (present, body equal) · `differs` (present, body unequal) · `foreign` (present, other author) · `twin` (two own comments, one key). own = the current login, or that login with or without a `[bot]` suffix (an app token reads both ways) |
| D5 | mode | `plan` · `apply` |
| D6 | credential | `as-ehmpath` · `as-human` |
| D7 | credential state | `present · keyrack` · `present · env` (as-ehmpath only: `EHMPATHY_SEATURTLE_GITHUB_TOKEN`) · `absent` |
| D8 | input | `valid` · `malformed` (a flag shape the contract refuses, or a body over github's 65536-character cap) |
| D9 | write outcome | `lands` (read-back hash equal) · `rewritten` (read-back hash differs) · `refused` (gh errors) |
| D10 | concurrency | `solo` · `racer` (a second writer on the same key between read and write) |
| D11 | output shape | `tree` (default) · `json` |

## .why each axis is orthogonal

- **A actor** — who encounters the behavior. every actor meets a different face of one write: the clone runs it, the sponsor's name signs it, the reviewer reads it, the maintainer proves it. no other axis value implies an actor
- **D1 verb × D2 kind** — any verb applies to any kind; `del · body` is a forbidden cell, not a dependency
- **D3 address vs D2 kind** — address says *how* the target is named, kind says *what* it is. `self` is the address of a kind that has exactly one instance per pr. the dependency that remains is real and is stated as impossible cells: `body` takes only `self` or `all`; `issue` takes `all`, `id`, or `key`; `review` takes `all`, `id`, or `thread`. `all` is a read address only — `set` and `del` need one target
- **D4 remote state** — what github holds now; independent of what the caller asks
- **D5 mode** — plan vs apply; independent of target and state: plan computes the same verdict apply would act on
- **D6 credential × D7 credential state** — whose token, and whether it is reachable. `as-human` + `absent` is real (`gh auth login` lapsed); `as-ehmpath` + `absent` is real (keyrack locked)
- **D8 input** — caller syntax, checked before any gh call, so it never meets D4 or D9
- **D9 write outcome** — what github did with an apply; independent of whether the verdict was POST or PATCH
- **D10 concurrency** — time; the `twin` state of D4 is the *result* of a race, D10 is the race itself
- **D11 output shape** — how the result renders; the verdict and the rows are computed before the render, so no other axis depends on it

## .the walk

### the target product — A=clone · D1 × D2 × D3 × D4

`—` = a pair the contract cannot express (impossible; its why in the inventory).

#### get

| D3 \ D2 | body | issue | review |
|---|---|---|---|
| all | one row (empty body → `bytes: 0`) | every row; none → `(no comments)`, exit 0 | every row; none → `(no comments)`, exit 0 |
| id | — | present → row · absent → 2 | present → row · absent → 2 |
| key | — | present → row · absent → 2 | — (a review key needs a thread) |
| thread | — | — | present → row · absent → 2 |
| self | the body | — | — |

a keyed read crosses D4 too, since `--key` names the current login's comment. `id` and `all` do not: an id names one comment of any author, and `all` reads every row.

| D3 · D2 \ D4 | absent | present (own) | foreign | twin |
|---|---|---|---|---|
| key · issue / thread · review | refuse 2, list hint | row | refuse 2, names the holder, never "absent" | refuse 2, both ids |

#### set

| D3 · D2 \ D4 | absent | same | differs | foreign | twin |
|---|---|---|---|---|---|
| key · issue | POST | no-op | PATCH | refuse 2 | refuse 2 |
| thread · review | POST reply | no-op | PATCH | refuse 2 | refuse 2 |
| id · issue \| review | refuse 2 | no-op | PATCH | gh 403 → refuse 2 | — |
| self · body | — | no-op | PATCH | — (gh decides access) | — |
| all · any | — (a write needs one target) | | | | |

#### del

| D3 · D2 \ D4 | absent | present (own) | foreign | twin |
|---|---|---|---|---|
| id · issue \| review | no-op 0 | DELETE | gh 403 → refuse 2 | — |
| key · issue / thread · review | no-op 0 | DELETE | refuse 2 | refuse 2 |
| self · body | forbidden — no delete exists for a pr description | | | |
| all · any | forbidden — a write needs one target | | | |

### the run product — D5 × D6 × D7, on every write cell

these three axes act the same on every target cell above. the claim is checkable: each value changes *only* the credential handed to gh or *whether* the write call fires, never the verdict computed. so the product is walked once here, and each row holds for every write cell:

| D5 mode | D6 credential | D7 state | outcome |
|---|---|---|---|
| plan | as-ehmpath | present | reads under bot token; prints verdict; no write |
| plan | as-ehmpath | absent | exit 2 before any gh call; fixes: keyrack unlock, or `--auth as-human` |
| plan | as-human | present | reads under gh login, `GH_TOKEN`/`GITHUB_TOKEN` unset; prints verdict; no write |
| plan | as-human | absent | gh reports not logged in → exit 2, fix `gh auth login` (via `is_gh_auth_failure`) |
| apply | as-ehmpath | present | writes as the bot; read-back |
| apply | as-ehmpath | absent | exit 2 before any gh call; same fixes |
| apply | as-human | present | writes as the sponsor; read-back |
| apply | as-human | absent | exit 2, fix `gh auth login` |

plan reads under the credential too, because the verdict needs the current login (key author check). so D7 `absent` refuses in plan as well — the caller learns early.

### the outcome product — D9 × D10, on every apply that writes

| D10 \ D9 | lands | rewritten | refused |
|---|---|---|---|
| solo | exit 0, `posted` / `edited` / `deleted` | exit 1, both hashes | exit 1 (malfunction) or exit 2 (403 / 404 → constraint), gh stderr shown |
| racer | both writers read `absent`, both POST → a twin forms; each exits 0 | as solo | as solo |

the race has no in-contract cure: github offers no lock or conditional write on comments. the next `set` on that key meets D4 `twin` and refuses with both ids, so the twin is caught on the first re-run, never silently grown.

### the output product — D11, on every verb

uniform by construction: both shapes render the same computed rows or verdict. walked once — `tree` → treestruct with 🐢 header and 🐚 verb line; `json` → one json value, no tree, the error still on both streams with a non-zero exit. inventory rows 49–50.

### the actor product — A × the one write each actor meets

| actor | encounter |
|---|---|
| clone | every cell above |
| sponsor | `as-human` writes: author = sponsor, body still opens with 🐢 |
| reviewer | reads a keyed comment: browser (marker hidden) · email (plain text may show marker) · after an edit by the reviewer (marker kept → next `set` overwrites; marker dropped → next `set` posts fresh) |
| maintainer | runs the suite: before the verbs (red) · after, token present (green) · after, token absent (real-api case fails loud) |

## .what the walk surfaced

- `foreign` is a real state, absent from the draft: a key written `--auth as-human` and re-run `--auth as-ehmpath` finds a comment the bot cannot edit. the draft would POST a twin
- `twin` is the state a non-idempotent post leaves, and the state a race leaves; the verbs refuse it, never pick one
- `set --id` on `absent` refuses, where `set --key` on `absent` posts — the id says "this one", so its absence is a caller error
- `del --kind body` has no remote act; github offers no delete for a pr description
- plan must read under the credential, so an absent credential refuses even in plan
- the reviewer and maintainer meet the behavior through other doors than the cli, and each has its own sharp path
