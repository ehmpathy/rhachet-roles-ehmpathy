## .decisions

- **refusal under `--output json`** — stdout holds one `{ error: { class, message, details, fixes } }` object, stderr the tree; one leaf (`emit_comment_refusal`) renders every refusal
- **thread scope** — a reply key is scoped to the thread root; github threads a reply to a reply under the root
- **unseen pr** — every 404 that could mean "the credential cannot see the pr" proves the pr first (`check_pr_visible`), so it reads as a constraint, never "absent" or a malfunction
- **stderr write** — `tee /dev/stderr` fails with ENXIO when stderr is a socket (node's spawn pipes). refusals call the shared `emit_both` (`git.commit/output.sh`) with its stdout on fd 3, so a refusal inside `$(...)` still reaches the terminal
- **reuse** — the auth vocab (`AUTH_DEFAULT`, `AUTH_VALID_VALUES`, `get_auth_who_label`) comes from `git.commit.operations.sh`; output leaves from `git.commit/output.sh`; function names are verb-first, like every extant operations file
- **del on a foreign-held key** refuses (exit 2), the same as set, so a crew never reads "absent" for a comment someone else holds
- **real-case target** — a closed pr in this repo (`#1039`), pinned. no new pr elsewhere: the wish bounds the drive to one pr. each run owns a unique key, deletes what it posts, and sweeps keys an hour stale
- **auth token order** — as-ehmpath reads `EHMPATHY_SEATURTLE_GITHUB_TOKEN` from the env first, then the keyrack; so a ci secret in the env works with no keyrack unlock. the tree labels it `as-ehmpath (env EHMPATHY_SEATURTLE_GITHUB_TOKEN)` (case15 [t5])
- **flag parse** — a `--flag` with no value, or followed by another `--flag`, refuses with "needs a value"; `--flag=value` parses as `--flag value` (case11 [t5], [t6])
- **no false absence** — an `--id` absent under its `--kind` but present under the other kind refuses with "pass --kind <other>"; a `--reply-to` thread that does not exist refuses on set, get, and del (case9 [t7])
- **twin on every verb** — get, set, and del each refuse a key the current login holds twice, through one leaf (`check_key_has_no_twin`) (case7)
- **claim grammar** — only a marker on a comment's own last line claims a key; a marker typed or quoted mid-body claims none. set still strips every marker from the text it posts (case7 [t3])
- **env token refused** — the fix names `refresh or unset EHMPATHY_SEATURTLE_GITHUB_TOKEN`, never a keyrack unlock that could not change it (case15 [t5])
- **as-human writes** — a thread reply posts under the human's gh login with the 🐢 and the key, and re-runs as a no-op; a bot-held key refuses the human and names `--auth as-ehmpath`; a human-held thread key refuses the bot; logged out names `gh auth login` (case15 [t8])
- **unknown flag** — a flag the verb does not know reads "unknown arg", never "needs a value" (case11 [t6])
- **body cap** — set refuses a body over 65536 characters in plan and apply, before any write (case15 [t7])
- **write failures** — a 422 points at gh's detail; a 404 on PATCH names the target; a 404 on DELETE converges to a no-op (case15 [t6])
- **mode bit** — the four `.sh` files carry `+x` (the build refuses non-executable skills)
