# case=11 · two writers race on one key

feel: sharp · care: alterpath (two clones on one pr) · second-densest boundary

## .narrative

two clones work pr #69 at once. both run `set --key round-2-status`. both read the pr, both see the key absent, both POST. github holds no lock and no conditional write for comments, so a twin forms. each clone exits 0: from where it stood, it posted.

the next `set` on that key, by either clone, reads two own comments with one key. it does not guess which is the real one. it refuses, lists both ids with their created times, and names the fix. one `del --id` later, the key is whole again and `set` converges as normal.

the race is caught on the first re-run, never silently grown into three, four, five.

## .timeline

```
given pr #69 with no comment that carries key `round-2-status`
  and clone A and clone B each hold ./status.md

when [t0] A and B run `set --pr 69 --key round-2-status --from ./status.md --mode apply` at once
  then each reads `absent`, each POSTs, each exits 0
  then #69 holds two comments by the same login with key `round-2-status`

when [t1] either clone runs the same command again
  then exit 2, no POST, no PATCH
  then stdout and stderr both carry:

✋ ConstraintError: key `round-2-status` matches 2 comments on #69
   ├─ 4410000001  created 2026-10-24T02:10Z
   ├─ 4410000002  created 2026-10-24T02:11Z
   └─ fix: rhx git.pull.comment.del --pr 69 --id 4410000002 --kind issue --mode apply

when [t2] the clone runs the named del, then `set` again
  then del exits 0, `deleted, confirmed absent`
  then set reads one match and converges: no-op or PATCH
```
