# case=9 · the reviewer reads what the clone wrote

feel: happy at [t0], sharp at [t1..t3] · care: critipath at [t0], alterpath after

actor: the reviewer — a human who opens pr #69 in the browser, or reads its notification email.

## .narrative

the reviewer opens #69. one "round 2 status" comment sits in the conversation, current, with github's own "edited" tag. no stack of stale versions. the key marker is an html comment, so the browser shows naught of it.

the reviewer reads the same comment in a notification email. the html part hides the marker; the plain-text part may show `<!-- rhx:git.pull.comment key=round-2-status -->` as a raw line. it is noise, not harm, and execution checks one real email to learn which.

the reviewer edits the clone's comment to fix a typo. the next `set` sees the body differs. the plan shows the current sha256 beside the new one, so the clone sees a remote edit before it applies. apply converges to the clone's file: the reviewer's typo fix is overwritten. this is what an upsert means; the plan makes it visible.

another time the reviewer edits the comment and deletes the marker line. the comment is now unkeyed. the next `set` finds no key and posts a fresh one. `get --pr` shows both, and `del --id` removes the stale one.

## .timeline

```
given pr #69 holds the clone's comment with key `round-2-status`, edited twice by `set`

when [t0] the reviewer opens #69 in the browser
  then one comment shows, current, with github's "edited" tag
  then the marker does not render

when [t1] the reviewer reads the notification email
  then the html part hides the marker
  then the plain-text part may show the raw marker line   # verified at execution (F1)

when [t2] the reviewer edits the text, keeps the marker; the clone runs set --key round-2-status (plan)
  then exit 0; no PATCH
  then the verdict reads `would edit`
  then the plan shows `current sha256` ≠ the clone's last-posted sha256

when [t2.1] the clone runs the same command with --mode apply
  then one PATCH; the reviewer's edit is overwritten
  then read-back sha256 matches; exit 0

when [t3] the reviewer deletes the marker line; the clone runs set --key round-2-status --mode apply
  then the verb finds no key; one POST
  then `get --pr 69` lists both comments
  then `del --pr 69 --id <old id> --kind issue --mode apply` removes the stale one
```
