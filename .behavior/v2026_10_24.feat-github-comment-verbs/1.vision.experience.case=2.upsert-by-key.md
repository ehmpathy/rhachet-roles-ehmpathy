# case=2 · upsert a top-level comment by key

feel: happy · care: critipath · densest boundary

## .narrative

a crew posts a "round 2 status" comment on pr #69. it names the comment `round-2-status`. the verb finds no comment with that key, so it posts one, with a hidden marker at the tail.

an hour later the crew fixes two more points and edits its local file. it runs the same command. the verb finds its own comment by key, sees the body differs, and PATCHes it in place. the reviewer sees one comment, current, not three stale ones.

the crew's session compacts and a fresh clone re-runs the step from its notes. the body is the same. the verb prints `no-op`. no comment doubles.

## .timeline

```
given a pr #69 with no comment that carries key `round-2-status`
  and ./status.md holds the status text

when [t0] rhx git.pull.comment.set --pr 69 --key round-2-status --from ./status.md --mode apply
  then exit 0
  then one POST to repos/<in>/issues/69/comments
  then the posted body = '🐢 ' + the text + '\n\n<!-- rhx:git.pull.comment key=round-2-status -->'
  then the verb reads back by id; sha256 matches
  then the verdict reads `posted` with the id and url

when [t1] ./status.md changes, then the same command runs
  then exit 0
  then no POST; one PATCH to repos/<in>/issues/comments/<id>
  then the verdict reads `edited` with the same id

when [t2] the same command runs, ./status.md unchanged
  then exit 0
  then no POST, no PATCH
  then the verdict reads `already there — no-op`
```
