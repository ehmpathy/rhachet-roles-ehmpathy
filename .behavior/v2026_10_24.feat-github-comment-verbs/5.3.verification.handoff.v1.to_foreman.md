## .what is blocked

one test file: `src/domain.roles/mechanic/skills/git.pull.comment/git.pull.comment.real.integration.test.ts` (case1, the live lifecycle on ehmpathy/rhachet-roles-ehmpathy#1039). it fails loud, by design (F6):

```
✋ ConstraintError: github token required for the real-api case
   hint: rhx keyrack unlock --owner ehmpath --env test --key EHMPATHY_SEATURTLE_GITHUB_TOKEN
```

every other suite is green (see `5.3.verification.yield.md`).

## .what i tried

1. `rhx git.repo.test --what integration --scope path://git.pull.comment.real --mode apply` (env test) → the key is declared in `env.test` but holds no value → the ConstraintError above
2. the same with `--env prep`, since the verbs' own default reads keyrack prep → keyrack unlocked `ehmpath/prep`, yet no value reached the env; same ConstraintError (log `.log/role=mechanic/skill=git.repo.test/what=integration/2026-10-24T06-44-42Z.stderr.log`)
3. `rhx keyrack unlock --owner ehmpath --env prep --key EHMPATHY_SEATURTLE_GITHUB_TOKEN` → `status: absent 🫧`, tip `rhx keyrack set ... --vault <vault>`
4. `rhx keyrack status --owner ehmpath` → no `EHMPATHY_SEATURTLE_GITHUB_TOKEN` under any env
5. a token lifted from `gh auth token` into the env: not done. it would put a secret into a shell expression, and this session never prints or moves secrets

## .why it is fundamentally the wisher's

the value is absent from the vault, not locked. only a human with the token can `rhx keyrack set` it, and only a repo admin can add the ci secret. F6 ruled exactly this: one real case, keyrack `ehmpath`/`test`, fail loud, the ci grant filed later by the wisher. the director's instruction repeats it: "the real-api case fails in ci until its token lands, so name that one check in the pr and report it."

## .what the grant needs

- a `ghs_` github app installation token. the keyrack firewall in ci grants `ghs_` and blocks `ghp_` (probed: `npx rhachet keyrack firewall --env test --from 'json(stdin://*)' --into json`)
- scope: pull_requests + issues write on ehmpathy/rhachet-roles-ehmpathy is enough for the case
- reach: under `env.test`, the token enters every integration process's env, not only this case's
- local: `rhx keyrack set --owner ehmpath --key EHMPATHY_SEATURTLE_GITHUB_TOKEN --env test --vault <vault>`; ci: the repo secret of the same name
