## .rejection invariants

each is a checkable rule the execution must hold:

- no write without `--mode apply`
- no POST without `--key` — a POST that a re-run would repeat is the defect these verbs exist to remove
- no write on a comment whose author is not the current credential's login — refused before gh refuses
- no write at a key with two own matches
- no write to a comment on a pr other than `--pr`
- no write while the credential is absent — refused before any gh call, in plan too
- no gh call of any kind on a repo outside the home orgs — refused, exit 2, allowlist named
- no `del --kind body` — refused, exit 2, with the `set --kind body` fix
- no write without one target — `--pr` alone on `set` or `del` refuses, exit 2
