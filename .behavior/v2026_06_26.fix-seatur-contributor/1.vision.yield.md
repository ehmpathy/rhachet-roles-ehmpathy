# 1.vision — consistent squash contributors via token-derived author

> the prior draft (with the full investigation trail and refuted hypotheses) is archived at
> `refs/1.vision.yield.v1-with-investigation-trail.md`. this is the coherent rewrite.

## the wish

when a seaturtle PR squash-merges, the merged commit should credit **exactly two** identities:

1. the **seaturtle** that did the work (author)
2. the **human** co-author

today the app shows up as a 3rd contributor.

## the root cause (confirmed)

github squash sets the **squash commit author = the PR opener**, and demotes every original commit author to a `Co-authored-by:` trailer. this is github's documented, non-configurable behavior.

evidence — declapract-typescript-ehmpathy PR #509 (opened by the app, single commit authored by the turtle):

```
squash author    = seaturtle-by-ehmpathy[bot]                     ← the app (it opened the PR)
squash committer = GitHub <noreply@github.com>                    ← web-flow, not a contributor avatar
Co-authored-by:    seaturtle[bot] <seaturtle@ehmpath.com>         ← real commit author, demoted
Co-authored-by:    Ulad Kasach <uladkasach@gmail.com>             ← human
```

so the 3 contributors = app (squash author) + turtle (co-author) + human (co-author).

the bug exists because the **PR opener** (the app) and the **commit author** (hardcoded `seaturtle[bot] <seaturtle@ehmpath.com>` in `git.commit.set`) are two different identities. github keeps the opener as author and adds the commit author as an extra trailer → 3.

## the decision

make the **commit author identity follow the active token's kind**, so the commit author always equals the PR opener. then the squash has one seaturtle identity to credit → **2 contributors**, consistently, with no per-repo config.

| token kind | label | commit author identity |
|---|---|---|
| **PAT** (`ghp_` / `github_pat_`) | **standard** | `seaturtle[bot] <seaturtle@ehmpath.com>` |
| **app installation** (`ghs_`) | **alternative** | `seaturtle-by-ehmpathy[bot]` (derived from the token) |

the two seaturtle identities are **peers chosen by token kind** — not legacy-vs-new. a PAT-opened PR squashes to the standard turtle; an app-opened PR squashes to the alternative bot. either way author == opener → 2 contributors.

the **human `Co-authored-by:` trailer stays** — the human remains credited. so the 2 are: the token-derived seaturtle (author) + the human (co-author).

## the outcome world

### day-in-the-life

a mechanic commits via `git.commit.set` → the skill detects the token kind and stamps the matching seaturtle author → `git.commit.push` opens the PR under that same token → on squash-merge the commit author already equals the opener, so github has one seaturtle + the human → **2 avatars** on the merged PR. the mechanic's workflow is unchanged.

### before / after

| | commit author | PR opener | squash author | contributors |
|---|---|---|---|---|
| **before (bug)** | `seaturtle[bot]` (hardcoded) | the app | the app | **3** |
| **after (app token)** | `seaturtle-by-ehmpathy[bot]` (derived) | the app | the app | **2** ✅ |
| **after (PAT)** | `seaturtle[bot]` | the turtle user | the turtle user | **2** ✅ |

### the aha

the fix is not "stop the app opening PRs" and not "swap the merge identity" — it is "make the commit author match whoever opens the PR." align opener and author and the squash naturally collapses to 2.

## user experience

- **usecase**: a mechanic commits + pushes as usual; their workflow stays the same.
- **contract**: `git.commit.set` reads the token (already fetched for push), classifies it by prefix, and selects the author name/email. no new flags.
- **outcome**: clean 2-contributor squash commits regardless of which token (app or PAT) is configured.

## mental model

> "whoever opens the PR is who github credits as the squash author. so we make our commits authored by that same identity — derived from the token — and the human stays as co-author. one turtle + one human = two."

analogy: sign the letter (commit) with the same name that mails it (opens the PR). if the signature and the return address match, there's one sender, not two.

## evaluation

### pros

- **consistent** — author always tracks the opener; auto-adapts to app or PAT, no per-repo config.
- **keeps the app card** — the app can still open PRs.
- **human stays credited** — co-author preserved.
- **small change** — localized to `git.commit.set`'s author selection.

### cons / costs

- **which seaturtle is credited now depends on the token** (app bot vs turtle user). accepted — they are declared peers.
- **token introspection** adds a small step to `git.commit.set` (classify by prefix; for app tokens, derive the bot identity).
- **human email on the squash commit** — retention of the co-author trailer puts the human email on the commit (the push skill strips it only from PR *bodies*, `git.commit.push.sh:370-372`). accepted by the wisher.

### edgecases / pit-of-success

- **app bot identity derivation**: for an app installation token, the bot identity is deterministic — name `seaturtle-by-ehmpathy[bot]`, email `<bot-id>+seaturtle-by-ehmpathy[bot]@users.noreply.github.com`. verified: `gh api users/seaturtle-by-ehmpathy[bot]` → id `295111357`, type `Bot`; matches #509's squash author email. cache it.
- **unknown token shape**: if a token matches neither prefix, fail loud rather than guess an identity.
- **multi-commit PRs**: each commit authored by the same token-derived identity, so no extra distinct authors slip in.

## groundwork

### external research

- github squash sets author = PR opener and adds other commit authors as co-author trailers; not separately configurable. confirmed via github changelog + community discussions (see archived ref for links) and directly via PR #509.

### internal research (verified against this repo)

- **author identity** — `git.commit.set.sh:38` `ROBOT_EMAIL="seaturtle@ehmpath.com"`, `:677` `git commit --author="$ROBOT_NAME <$ROBOT_EMAIL>"`; co-author trailer at `:671-673` from `git config user.name/email`. ← this hardcode is what the decision replaces with token-kind selection.
- **PR open token** — `git.commit.push.sh:380` `gh pr create` under `GH_TOKEN=$EHMPATHY_SEATURTLE_GITHUB_TOKEN`, fetched from keyrack `--env prep` (`:275-279`). this is the (now app) token whose kind we will classify.
- **co-author privacy** — `git.commit.push.sh:370-372` strips `Co-authored-by:` from PR bodies for email privacy; the squash commit trailer is a separate surface and is retained per the decision.

## what is awkward?

- **the credited turtle depends on the token kind** — slightly surprising that two distinct bot identities both mean "seaturtle." mitigated by the explicit standard/alternative framing.
- **token introspection inside a commit skill** — `git.commit.set` gains awareness of token shape, which couples it a little more to the auth layer; worth a clean transformer (e.g. `getOneSeaturtleIdentityFromToken`) so the commit logic stays narrative.
- **human email on the commit** — a conscious privacy tradeoff to keep the human credited; named so it stays a deliberate choice.
