# experience case 4: multi-mode carries the bound to each child

cells c5 (default, past, multi) and c6 (explicit, past, multi). feel = sharp · care = critipath. densest walk.

## .narrative

before a push, a driver runs `--what all`. the parent spawns one child per type: lint, unit, integration, acceptance. lint and unit pass in seconds. integration drifts past 5 minutes. the integration child halts with "woah, too slow"; the parent stops on that first failure, as it does today for any failure, and returns the child's exit 2. acceptance never starts, so no second seat is held.

a second driver runs `--what all --timeout 600`. today that flag is silently dropped — the parent never passes it to its children (`git.repo.test.sh:1445-1461`). with the fix, each child gets `--timeout 600`. the bound is per type: each child gets its own 600s, the same as a single-type call would.

## .timeline

```
given('[c5, c6] a repo whose integration suite runs past 300s; lint + unit are fast', () => {
  when('[t0] (c5) rhx git.repo.test --what all --against local --env test --mode apply  (no --timeout)', () => {
    then('lint passes; unit passes');
    then('integration halts at 300s with "woah, too slow"');
    then('the integration child renders the full [c2] halt: bound: 300s (default), "this speed defect is yours to root cause", find the slow suite, a wider --timeout only for a suite long by nature');
    then('acceptance does not run');
    then('exit 2');
  });

  when('[t1] (c6) same call with --timeout 600', () => {
    then('each child runs under a 600s bound');
    then('integration halts at 600s, not 300s; names bound: 600s (--timeout)');
    then('exit 2');
  });
});
```

## .fails safe

- teaches the fix: the halted child is a single-type run, so it renders the same owner line and next moves as case 2
- the parent's stop-on-first-failure means one slow type costs one bound, not four
- the explicit bound reaches every child, so the caller's number is never silently swapped for the default
