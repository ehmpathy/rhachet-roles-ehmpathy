# case=2 — a typo of a paved command

demos inventory #2 (`single · {typo}`).

## .narrative

a mechanic types `gti status` (or `npm run biuld`). today it sees the 200-line dump and must spot
its own typo inside it.

with the nudge, the hook ranks the allowlist by closeness to the blocked part and leads with the
near-miss: *"did you mean `git status`?"*. the fix is one glance.

a terser slip works too: `grpsf wave` holds the letters of `grepsafe` in order, so the fzf tier
ranks `rhx grepsafe` — the match a human expects from fzf.

## .the render (a pre-implementation sketch; the hook snapshots pin the shipped render, incl. its 🥥 retry hint)

```
✋ ConstraintError: this command is not paved

   ├─ blocked part
   │  └─ gti status
   │
   ├─ did you mean? (nearest paved patterns, 3 of 21 max)
   │  ├─ [p] git status        ← 2 edits away (a swap)
   │  ├─ [p] gh pr status
   │  └─ [p] gh issue status
   │
   ├─ 🐚 a need that recurs deserves a paved rhx skill.
   │
   └─ still need this exact command? retry it once; the human will be asked.
```

## .timeline

```
given('[case2] a typo of a paved head')
  when('[t0] the bot runs `gti status`')
    then('exit 2')
    then('the first candidate is `[p] git status` (edit-distance tier)')
    then('the ledger row records { kind: typo }')
  when('[t1] the bot runs `grpsf wave` (letters of `grepsafe`, in order)')
    then('exit 2')
    then('the fzf tier ranks `[p] rhx grepsafe` among the candidates')
  when('[t2] the bot runs `rhx grepsaf --pattern wave`')
    then('exit 0 — `rhx` is a paved prefix, so the hook never sees the typo')
    then('the skill-name typo is caught by rhx itself, not by this hook')
```

⚠️ `[t2]` is a boundary, not a feature: `rhx:*` is paved, so a typo'd skill name reaches rhx. the
vision does not widen this hook to rank rhx skill names (F5).
