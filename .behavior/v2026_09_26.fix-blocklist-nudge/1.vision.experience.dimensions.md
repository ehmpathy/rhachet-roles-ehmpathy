# 1.vision.experience.dimensions

the experience space of the `check-permissions` nudge, factored into orthogonal axes.

## .the part kind — defined once

each un-paved part of a command has exactly one **kind**:

- `alt` — its head has an inventory entry (grep, ls, sed, rm, cd …). a known head is never a slip, so
  the fzf tier skips it: its letters in order inside an unrelated name (`grep` in `git.repo.test`)
  are a coincidence, not intent (case=10, catalog #62)
- `typo` — no inventory entry, but a fuzzy tier matches above the score floor (`gti status`, `grpsf`)
- `novel` — no inventory entry, and no tier matches above the floor. a match **below** the floor
  (e.g. `du` near `diff`, where short heads skip the typo and fzf tiers) is withheld, so the part is
  still `novel`

## .the axes

| # | axis | values |
|---|---|---|
| P | **actor** | `bot` (mechanic, any clone) · `sponsor` (the human who answers prompts and reads the ledger) · `author` (the human who keeps the inventory) · `system` (a headless run with no human to answer a prompt) |
| B | **command shape** | `single` · `compound-1` (a compound where exactly one part fails) · `compound-n` (a compound where ≥ 2 parts fail) |
| A | **kinds present** — the set of part kinds among the failed parts | for `single` and `compound-1`: one of `{alt}` · `{typo}` · `{novel}`. for `compound-n`: any non-empty subset of `{alt, typo, novel}` — `{alt}` · `{typo}` · `{novel}` · `{alt,typo}` · `{alt,novel}` · `{typo,novel}` · `{alt,typo,novel}` |
| C | **attempt** | `first` · `retry-in-window` (the bust-through) · `retry-after-window` · `retry-clock-stepped-back` (the record holds a future stamp; added at 5.3) — inventory #40 |
| D | **mode** | `HARDNUDGE` (default, blocks) · `SOFTNUDGE` (advises, exit 0) |
| K | **concurrency** | `solo` · `parallel` (≥ 2 clones append to the same ledger at once) |
| H | **host** (added at 5.1) | `idle` · `saturated` (the allow check runs slow; the failfast budget is in play) — inventory #30 |
| F | **offer fit** (added at 5.3) | `serves` (the offered paved form does the job the part attempted) · `resolves-not-serves` (the offer is a valid paved pattern that cannot do the job — `[e] jq` for a filter, an edit tool for a line-range read) — inventory #34, #35. and on the source side: `source-readable` · `source-unreadable` (the inventory or allowlist could not be read, so the part cannot be graded) — #37 |
| S | **part shape** (added at 5.1) | `plain` · `global-flag` (a flag between head and subcommand, `git -C . log`) — inventory #29 · `sentinel-text` (the part is a sentinel word) — #32 · `shell-loop` (a `for … do … done` split into keyword parts, added at 5.3) — #36 · `bare-assignment` (a part that is only `VAR=value`, added at 5.3) — #41. and on the allowlist side: patterns with argument values, against which the rank must not match — #28 |

**why A is a set, not a count or a sequence.** the render gives each failed part its own block,
keyed on that part's kind. so two `alt` parts render the same way as three; what changes the
experience is **which kinds appear**, because each kind brings its own section (alternatives,
did-you-mean, or pave-a-skill). the set is closed: 3 values for one failed part, 7 for several.

**candidate count is not an axis.** it is an output of A and the allowlist. the only independent
fact is the cap: > 21 candidates → show 21 plus a count. that is an itemized render rule
(inventory row #19), not a dimension.

## .the walked product

B × A on its own is 3 + 3 + 7 = **13** shape-kind cells. with P (4), C (3), D (2), K (2), the nominal
space is 13 × 4 × 3 × 2 × 2 = 624 cells. five collapse rules, each a stated fact about the hook:

1. **P splits the space into disjoint encounters.** the bot meets the render; the sponsor meets the
   prompt (only on `retry-in-window`) and the ledger; the author meets the inventory file; the system
   meets the retry with no one to answer. B × A reaches the others only through the prompt reason
   and the ledger rows. ⇒ the bot owns the 13 shape-kind cells; each other actor owns a few rows.
2. **C `retry-after-window` ≡ `first`.** the window expired, so the hook treats it as a fresh
   attempt. ⇒ C has two live values.
3. **C `retry-in-window` flattens B × A for the bot.** the hook hands off without a render; B and A
   survive only as ledger fields and as the prompt reason. ⇒ one bot cell, one sponsor cell, one
   system cell.
4. **D `SOFTNUDGE` changes only the header, the tail, and the exit.** it renders the same per-part blocks for every B × A; its tail is an advisory line in place of the retry hint.
   ⇒ one SOFTNUDGE cell.
5. **K reaches only the ledger append.** the render and the gate are per-process; only the shared
   jsonl sees two writers. ⇒ one `parallel` cell.

⇒ the live space: the bot's 13 shape-kind cells on `first` / HARD, plus the bust-through (bot,
sponsor, system), plus SOFTNUDGE, plus the concurrency cell, plus limits, failures, and the
sponsor's and author's own rows. `1.vision.experience.case=_.md` walks every one.

## .the boundary-dense center

**B = `compound-n` × A = `{alt,novel}` × C = `first`** — `cd src && ls && python3 -c "…"`. it crosses
the split, every-failed-part, per-part lookup, a pave headline, and the shared cap in one walk.
its neighbors: `compound-n · {alt}` (`cd src && ls && grep …`, the commonest multi-block) and
`compound-1 · {alt}` (the wish's own incident). case=1 demos all three.
