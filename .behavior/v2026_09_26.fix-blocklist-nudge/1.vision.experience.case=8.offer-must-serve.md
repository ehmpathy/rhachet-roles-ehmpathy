# case=8 — an offer must serve the need, not merely match the head

demos inventory #34 and #35 (`F = resolves-not-serves`), found live at 5.3: the nudge named a
real paved pattern that could not do the job the bot attempted.

## .narrative

a mechanic wants the `scripts` block of `package.json` and types `jq .scripts package.json`. the
allowlist paves `jq` as an **exact** entry — a bare `jq`, the tail of a pipe — so this part blocks.
the old nudge answered *"did you mean? `[e] jq`"*. the mechanic read that as "jq is paved", retried
with `cat package.json | jq .scripts`, and was blocked again with the same offer. two turns spent,
no closer to the data: the exact failure the wish names ("retries blind").

a second mechanic wants lines 150–320 of a file and types `sed -n 150,320p notes.txt`. the old
nudge offered only `rhx sedreplace` — an edit tool, for a read.

now the inventory carries a paved form that serves each need, and the render explains its own
markers. the jq mechanic sees `cat <file> | jq` (the whole document, pretty-printed) first, and
the `[e]`/`[p]` key tells it a bare `jq` is all the exact entry paves. the sed mechanic sees
`head -n <last> <file> | tail -n <count>` beside sedreplace. each runs the first offer and gets
its data on the next turn.
