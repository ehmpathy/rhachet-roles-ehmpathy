# case=9 — see all, on demand

**cell:** bot · any blocked part · the session-start notice is out of context · the bot looks up
its options before it paves or retries
**feel × care:** happy × high (critipath) — every block now names this lookup as move 1; if it
fails or disagrees with the hook, the nudge sends the bot down a dead end

## .the narrative

a bot is hours into a session. the session-start notice — the one place every pre-approved command
was listed — scrolled out of context long ago. it runs `sort -u names.txt`, and the hook blocks it.

the block names the nearest candidates, and its hint opens with move 1:

```
🥥 did you know?
   ├─ 1. see all pre-approved commands: rhx permissions.get --for 'sort -u names.txt'
   ├─ 2. a need that recurs deserves a paved rhx skill — pave it
   └─ 3. need this exact command once? retry it unchanged — that interrupts the human to ask
```

the bot copies move 1 as-is. the command is shell-quoted, so even a part with inner `'` pastes and
runs. the lookup is itself pre-approved, so it never blocks. it answers with the hook's own verdict
and every candidate, ranked, with no cap:

```
🐢 heres the wave...

🐚 permissions.get --for 'grep -rn reef src/'
   ├─ verdict: not pre-approved — it would block; each blocked part and its options follow
   │
   ├─ blocked: grep -rn reef src/
   └─ paved alternatives for `grep`
      ├─ rhx grepsafe --pattern '<regex>' --path <dir>
      └─ rhx git.repo.get lines --in <org/repo> --words '<text>'
```

it picks a paved form and moves on — no retry, no human interrupted, no duplicate skill paved. the
lookup left no trace: no nudge record (so a later real attempt is still a first attempt), no ledger
row (so the demand ledger counts blocks, not lookups).

later the bot wonders what it may do with git. `rhx permissions.get --head git` lists every git
pattern in full. before it improvises a whole new flow, plain `rhx permissions.get` shows the map,
grouped by head, long heads folded with a pointer to `--head`.
