# 1.vision — a nudge that names the command you meant

## .the outcome world

### before

a bot runs `git diff --stat && grep -rln 'blocklist' src/`. `pretooluse.check-permissions.sh`
blocks it and prints **every** allowlist pattern — ~200 lines, sorted alphabetically, with the
`grep` alternatives buried among `gh search prs` and `rhx git.branch.rebase take --whos theirs .`.
the bot cannot find the fit, so it delegates to a subagent or retries blind. a retry passes to a
human prompt, and no record remains.

measured live, while this vision was written: `cd <worktree>; ls …` and `ls … && grep …` each drew
the full dump. the fit (`tree`, `rhx grepsafe`) was in the list both times; the list did not say so.

### after

the same command draws a short, ranked answer:

1. **the blocked parts** — only the parts that failed (here, `grep -rln 'blocklist' src/`), never
   the whole compound, and never only the first of several
2. **paved alternatives** — from a curated inventory: `grep` → `rhx grepsafe`,
   `rhx git.repo.get lines --words`
3. **nearest paved patterns** — an fzf-style fuzzy rank of the allowlist against the blocked part,
   capped so the total list holds **at most 21 candidates**
4. **pave what recurs** — a 🐚 tree on every nudge: use it again, a future traveler needs it, or a
   repo beyond this one needs it → pave it (and dispatch a task upstream); where → always start in
   `.agent/repo=.this/role=any/skills/`
5. **three moves** — a 🥥 hint closes every block: (1) see all pre-approved commands with
   `rhx permissions.get --for '<command>'`, (2) pave a reusable rhx skill, (3) retry the exact
   command once, which interrupts the human to ask

each block and each bust-through appends one row to a local ledger, so demand for paved paths
accrues instead of evaporates.

### on demand, any time

the session-start notice scrolls out of context; the lookup does not. `rhx permissions.get` shows
the pre-approved commands whenever a bot asks — the whole map grouped by head, one head in full
(`--head git`), or one command's verdict with every candidate ranked and no cap
(`--for 'sort -u names.txt'`). `--for` asks the hook itself, read-only, so the two never disagree.
the session-start notice shrinks to the heads with a count each, plus a pointer to the lookup.

### the aha

the dump answered *"what may I run?"*. the nudge answers *"what did you mean?"* — the question the
bot actually has at the moment of the block.

## .the contract (sketch)

| piece | shape |
|---|---|
| inventory | `claude.hooks/commands.alternatives.jsonc` — `{ entries: [ { heads: ['grep', 'rg'], alternatives: ['rhx grepsafe …', 'rhx git.repo.get lines --words …'] }, { heads: ['cd'], alternatives: [], advice: '…' } ] }`. one entry lists every head it answers; `advice` is prose for a head with no command answer. keyed on the head of the blocked part, longest first (three words, two, one: `git commit`, `npm test`, `grep`). comments are whole lines only |
| head | the first word of a blocked part, once any `VAR=value` prefix is skipped (`SURF=1 npm test` → `npm test`). the longest inventory head matches first: three words, then two, then one. a part of only `VAR=value` has no head and renders as novel |
| blocked parts | **every** un-paved part is named, not only the first — `cd x && ls && grep y` names three, so the bot fixes all in one pass instead of three blocks in a row. candidates for all parts share the one cap |
| rank | inventory hits first, in inventory order; then allowlist patterns by fuzzy score; dedupe; cap at 21; `… and N more (see all: rhx permissions.get, below)` past the cap — it names the lookup, which the 🥥 hint spells out in every mode |
| render | a treestruct: the header owns its trunk (no blank line); each part's `blocked:` line and its groups (advice, `paved alternatives for`, `did you mean?`, `nearest paved patterns`) are peers at one depth; only a group's items nest; a `│` spacer separates parts. then the 🐚 pave tree, then the 🥥 three-move hint. per ergonomist `rule.forbid.treestruct-header-gap` + `rule.forbid.treestruct-indented-text-as-children` |
| lookup | `rhx permissions.get` (mechanic skill): bare = every pre-approved command grouped by head, a head past 5 folds with a pointer; `--head <h>` = that head's patterns plus its inventory alternatives or advice; `--for '<cmd>'` = the hook's own answer via `--mode LOOKUP`: verdict, every candidate, no cap, no pave tree, no hint, no nudge record, no ledger row. pre-approved itself (`Bash(rhx permissions.get:*)`) so the lookup never blocks |
| session-start notice | the heads with a count each, then the three `rhx permissions.get` forms — never the full list |
| fuzzy score | pure bash, no forks, five tiers: (1) shared lead words — a fit only with a near-miss next word, ≥ 2 shared, or the whole pattern, (2) head word within its edit budget (optimal-string-alignment distance; 1 edit for ≤ 4 letters, else 2, taken from the shorter of the two heads — so `chmod` is never "2 edits" from `cmd`; typos: `gti` → `git`), (3) head letters in order within a pattern word, fzf-style, for heads of ≥ 4 letters (`grpsf` → `grepsafe`), (4) ≥ 2 part words among a pattern's dot-segments (`git commit` → `git.commit.set`), (5) ≥ 2 shared tokens. the typo tier needs heads of ≥ 3 letters. no tier = no fit. ties sort by pattern. runs **only on the block path** — the allow path stays as fast as today. edit distance runs per pattern, behind a length pre-check (a length gap past the edit budget skips it), which keeps the extant case23 bound (block in < 3s with 500 rules) |
| header | `✋ ConstraintError: this command is not paved` (per `rule.require.qualified-error-headers`); exit 2 |
| SOFTNUDGE | the same per-part tree and pave tree, header `🐚 advisory: this command is not paved (SOFTNUDGE — the command still runs)`, exit 0. the tree ends with an advisory line (no retry, no ledger); the 🥥 hint holds only the see-all move |
| ledger | `.agent/.cache/repo=ehmpathy/role=mechanic/skill=check-permissions/nudges.jsonl`, one row `{ at, part, head, kind: alt\|typo\|novel\|unranked, verdict: nudged\|retried }` — `unranked` = the search budget ran out before the part; a grammar part (`fi`, `done`) is no command, so it writes no row. append-only jsonl: each event is one line appended, never a read-modify-write, so concurrent clones cannot clobber each other. `.agent/.cache/` is already gitignored |
| pave nudge | the 🐚 `pave what recurs` tree on every nudge (four branches: use again · future traveler · beyond this repo → dispatch upstream · where → `.agent/repo=.this/role=any/skills/`), plus move 2 of the 🥥 hint |
| bust-through | a retry in the window returns `permissionDecision: "ask"` with a reason: *"retried after a nudge"* plus the alternatives offered or *"no paved path fits"*. R3, checked live (F18): claude code shows a bare prompt and does not surface the reason, so the context lives in the ledger's `retried` rows — the ruled fallback |

seed inventory (each target must match a paved pattern — see inventory cell #27):

| head | alternatives |
|---|---|
| `grep`, `rg` | `rhx grepsafe`, `rhx git.repo.get lines --words` |
| `ls`, `find` | `tree`, `rhx globsafe` |
| `cd` | advice only: run from the cwd; pass paths instead |
| `sed` | `rhx sedreplace` |
| `rm` / `mv` / `cp` / `mkdir` / `ln` | `rhx rmsafe` / `mvsafe` / `cpsafe` / `mkdirsafe` / `symlink` |
| `tee`, `>` | `rhx teesafe` |
| `git add` / `git commit` / `git push` | `rhx git.stage.add` / `git.commit.set` / `git.commit.push` |
| `git rebase` | `rhx git.branch.rebase` |
| `npm test`, `jest`, `npx jest` | `rhx git.repo.test` |
| `npm install`, `pnpm add` | `rhx set.package.install` |
| `gh pr merge` | `rhx git.release` |
| `cat` of another repo | `rhx git.repo.get lines --paths` |

🟡 inventory targets are **bash** commands only. native tools (Grep, Glob, Edit, Write) vary per
harness — this session exposes Edit/Write but not Grep/Glob — and the hook cannot verify them
against the allowlist. so the inventory never names a tool. a head with no paved target (e.g. `jq`
with args, see §awkward) gets no entry; it falls to the fuzzy rank or to `novel`.

## .mental model

- **bot's words:** "the hook told me what i meant." / "the hook said no paved path fits, so pave one."
- **human's words:** "it's autocorrect for the allowlist." / "the ledger is the wishlist for new skills."
- **analogy:** a shell's `command not found — did you mean 'git status'?`, plus a librarian who
  says *"we don't carry that; request it"* instead of a printout of the whole catalog.
- **our terms:** nudge, paved path, inventory, ledger, bust-through. "ledger" and "inventory" are new
  here; both are plain words with one sense each (see fulcrum F3).

## .evaluation

| goal (from the wish) | met by |
|---|---|
| nudge toward the most likely command | blocked-part focus + inventory + fuzzy rank |
| inventory of known alternatives | `commands.alternatives.jsonc` |
| fzf-style typo search | five-tier rank (see `.contract` fuzzy score): shared lead words → typo within the edit budget → head letters in order (fzf) → dot-segments → shared tokens |
| list up to 21 candidates | hard cap, with an overflow count |
| accrue nudges without a good alternative, esp. bust-throughs | ledger rows `kind: novel`, `verdict: retried` |
| report upstream | `rhx permissions.nudges` reads the ledger (pulled in at 5.1); its hint names the `radio.task.push` — an automatic push stays out (F1) |
| push them to pave a skill | pave footer on every block; headline on `novel` |

**pros:** shorter output (~200 lines → ≤ ~30); the fit is first, not buried; demand becomes data;
no change to the allow path; the retry still reaches the human, now with the reason attached.

**cons:** a curated inventory can rot (mitigated by the paved-target test, cell #27); fuzzy rank in
bash is heuristic — a wrong top hit is possible; one more file under `.agent/.cache/` that only grows.

**pit of success:**
- the dump is gone, so the answer cannot hide in noise
- an inventory entry that names an unpaved target fails a test, never a bot
- the ledger write fails open on the retry path (the gate already chose "ask the human"); the
  prompt's reason text notes the lost row, so the human sees it
- the gate itself still fails **closed**: a malfunction in rank or ledger on the block path exits 2

## .what is awkward

- **fuzzy rank in bash** — pure bash, no forks, over ~200 patterns. fine on the block path, but it is
  heuristic code in a language that fights it. a wrong-but-confident top hit is worse than none; so
  `novel` must be declared when the best score is weak, rather than show a poor fit first.
- **the inventory duplicates knowledge** already in briefs (`rule.prefer.sedreplace-for-renames`,
  etc.). a second source can drift from the first; the paved-target test catches only half of it.
- **exact entries are examples, not fits** — `[e] jq` matches only the bare word `jq`, so every real
  `jq '.x' file` blocks (measured live). the rank must score an exact entry's head, not require the
  whole string, or it will call a `jq` call `novel` when the paved answer is `cat <file> | jq`… which
  also blocks. that is an allowlist gap the ledger will surface, not one this wish closes.
- **`cd` is the commonest block** and has no skill alternative — the right answer is "don't". the
  inventory must carry advice, not only commands.
- **the bust-through still prompts the human** — the wish implies adhoc commands should almost never
  be needed; this vision records the demand but does not raise the bar to bust through. the wisher
  ruled it so (2026-09-27): *"for now, just the nudge is fine."* a required `--why` is caught as a
  dream (`dreams/v2026_09_27.feat.require-a-why-to-bust-through-a-permission-nudge.md`), to escalate
  if the ledger shows bust-throughs too often.
