# wish: grepsafe accepts a --path through a role symlink into the main checkout of a worktree

## .the defect

in a worktree, a role dir (`.agent/repo=.this/role=*`) is often a symlink into the MAIN checkout.
`rhx grepsafe --path <that dir>` refuses it: `REPO_ROOT` comes from `git rev-parse --show-toplevel`
(the worktree), so `validate_root_within_repo_or_fail` rejects the resolved path (the main checkout)
as outside the repo. measured on rhachet-roles-ehmpathy 1.39.7. a clone then has no sanctioned way to
search its own role's briefs.

this is distinct from #864 (grepsafe and stdin). do not fold the two.

## .the want

1. a `--path` that resolves, through a symlink, into the main checkout of the CURRENT worktree's repo
   is accepted, and searched as any in-repo path is
2. a path that resolves anywhere else outside the repo is still refused — the guard keeps its teeth
3. **clamped**: a test that builds a worktree whose `--path` runs through a role symlink into the main
   checkout. it is RED before the fix and GREEN after. the outside-the-repo refusal stays covered too

## .a lead (from the commander)

`cicd.action.act.sh` in this same repo already detects a worktree via its gitdir. that logic is the
likely candidate to lift and share, rather than a second detector.

## .bounds

- open a PR and watch it with `rhx git.release --watch`. never `--apply`, never merge. the commander
  reviews and releases
- size: nano
- the local grove is tight: run the route's own review lanes only, no extra fan-out
