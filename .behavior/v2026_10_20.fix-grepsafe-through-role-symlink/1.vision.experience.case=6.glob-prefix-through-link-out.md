# case=6 — a `--glob` prefix through a link out of both trees (g3, sharp × critipath)

## narrative

the clone filters with a glob instead of a path: `--glob 'escape/**/*.md'`. it never typed
`--path`, so it may expect the glob to slip past the boundary. it does not: the glob's literal
prefix `escape` faces the same gate, before any file is read. the link leads to a tmp dir, so
grepsafe refuses at once — no partial results, no silent zero — and the refusal says
`named by: --glob` so the clone knows which flag tripped it. the 🥥 hint gives the in-repo search
to run instead.

## timeline

```
[t0] given a linked worktree with dir `escape` -> /tmp/<elsewhere>
[t1] when  grepsafe --pattern 'wave' --glob 'escape/**/*.md'
[t2] then  exit 2, on both streams
[t3]   and the refusal reads "search path must be within the git repository"
[t4]   and it reads "named by: --glob"
[t5]   and no result row prints
[t6]   and the 🥥 hint names `--path <repo root>`
```
