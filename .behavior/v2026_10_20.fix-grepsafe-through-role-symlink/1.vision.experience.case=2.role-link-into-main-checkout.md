# case=2 — a role link into the main checkout (c2, happy × critipath)

## narrative

the clone wants a rule from its own briefs. in its worktree, `.agent/repo=.this/role=any` is a
symlink into the main checkout. it types the path it sees. before the fix grepsafe refused it as
outside the repo; the clone had no sanctioned way to search its own briefs. after the fix the
search runs, as for any in-repo dir. the result rows print the main-checkout file by its
ABSOLUTE path — unlike case=1's repo-relative rows — so the clone sees the hit lives in the main
checkout, not in its worktree. legible, if not pretty.

## timeline

```
[t0] given a main checkout with .agent/repo=.this/role=any/briefs/b.md that holds 'wave'
[t1]   and a linked worktree whose .agent/repo=.this/role=any links to the main checkout's
[t2] when  grepsafe --pattern 'wave' --path .agent/repo=.this/role=any/briefs   (cwd = worktree)
[t3] then  exit 0
[t4]   and `<main checkout abs>/.agent/repo=.this/role=any/briefs/b.md:1:…wave…` prints, absolute
[t5]   and no "must be within the git repository" refusal renders
```
