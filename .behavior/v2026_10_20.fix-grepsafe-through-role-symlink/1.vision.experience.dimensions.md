# experience dimensions — grepsafe through a role symlink

actor: a clone (or a human) at a shell. the gate under test is `validate_root_within_repo_or_fail`
(`grepsafe.sh:613`), reached from `derive_path_root` (`--path`) and from `derive_alternative_leg`
(a `--glob` literal prefix).

precondition, verdicted: a cwd outside any git tree never reaches the gate. grepsafe refuses first,
`error: not in a git repository` (`grepsafe.sh:424`), exit 2 — unchanged by this fix, since
`REPO_ROOT` and `MAIN_ROOT` are both read after that check. catalog row r0.

## the axes

| axis | values | what it measures |
|---|---|---|
| A. lexical position | in · out | the typed path, joined to the physical cwd (`pwd -P`) if relative, its `.`/`..` collapsed, NO link resolved — under the worktree root, or not |
| B. resolved root | wt · main · else | the same path after `realpath` — under the worktree, under the main checkout, or under neither |
| C. named via | --path · --glob · both | which flag carried the root to the gate. `both` = a `--path` root plus a dir-prefixed `--glob`: the prefix joins the `--path` root |
| D. distinct main checkout | yes · no | does this repo have a main checkout apart from the cwd's tree? yes = the cwd is a linked worktree of a non-bare repo. no = the cwd IS the main checkout, or the repo is bare |
| E. target state | present · absent | does the resolved root exist on disk |

## why each is orthogonal

- **A vs B** — A reads the path as typed; B reads where its links lead. a link can sit anywhere
  in the typed path, so every A value meets every B value:
  in×wt (no link), in×main (a role link), in×else (a link out), out×wt (an absolute path through an
  outside link back into the worktree), out×main (a typed `..`, or an absolute path through a
  linked prefix), out×else (`../..`, `/etc`). no cell is void by construction
- **C vs A, B** — both flags hand a root to the same gate; any root either flag can name, the
  other can too. on a refusal C changes only the `named by:` line. C does change CARE: `--path` is
  how a clone names a dir, so its cells are critipaths; a glob through a role link is the rarer
  move, so the happy `--glob` cells are alterpaths. and under E = absent C changes the outcome,
  since the two flags test existence at different lines (see the catalog's a1 / a2).
  `both` adds no new admit: the `--path` root faces the gate first, then the joined
  `<path>/<prefix>` faces it again as its own typed path — and that joined root is the one the
  leg searches (`add_search_leg "$prefix_abs"`), so the gated root and the searched root are one
- **D vs A, C** — D is a fact about the repo, not the path. it does NOT stay orthogonal to B:
  under D = no, the `main` value of B does not exist apart from `wt` (main checkout itself) or at
  all (bare). that correlation is the point of D — it is the hidden axis "is there a distinct main
  checkout?" surfaced, so the B = main column is walked only where it can occur
- **E vs A–D** — orthogonal in what can be typed. for `--path`, absence is checked before the
  gate (`grepsafe.sh:705-718`) and refuses; for a `--glob` prefix, absence drops the lift
  (`:776`) and the glob runs inside the `--path` root. either way the gate is never reached

## values deliberately left off

- a peer linked worktree is not a tree kind of the cwd; it is a target. it lands in B = else
- a file (not a dir) as the root — the gate does not care; covered by extant tests
