# vision: pressViaPipeline runs no live model on ci

## .the outcome world

ci runs the pressViaPipeline contract against a fake compressor: fast, free, deterministic. the live check of a real brain stays, gated behind `BRAIN_LIVE_SCOPE=all`. a human runs it on demand.

| | before | after |
|---|---|---|
| ci shard | asks `openrouter/deepseek/flash` 3×; red 4 runs on 2026-11-02/03, once on the v1.41.0 publish, once on #1225 | asks no brain; green unless the pipeline code breaks |
| cost per ci run | 3 paid asks | 0 |
| strict-compression contract | proven only by a live model, flaky | proven by a fake compressor on every run; a real-brain proof on demand |
| live check | always on, ungated | `BRAIN_LIVE_SCOPE=all`, named in a todo row on every run |

aha: the flake was never in `pressViaPipeline`. the test asked a model to prove an orchestrator's contract. the orchestrator threads steps, counts tokens, and passes kernels. a fake proves that exactly. the model's compression skill is a separate question, asked on demand.

## .the contract we propose

```ts
// pressViaPipeline takes its compressor from the caller
pressViaPipeline(
  { content, brainSlug, pipeline, kernels, force },
  context: { compressor: typeof compressViaBhrain },   // required; no default
)

// brief.condense.ts:129, the sole prod caller, injects the real one
await pressViaPipeline({ ... }, { compressor: compressViaBhrain });
```

- `pressViaPipeline.ts` imports `compress.via.bhrain` as `import type` only. that module mkdirs a cache dir at load (`createCache`, `compress.via.bhrain.ts:57`; `simple-on-disk-cache/dist/cache.js:92-95`). so a unit test of pressViaPipeline loads no fs side effect

- `pressViaPipeline.test.ts` (new, unit): a fake compressor that halves its input and records each call. it covers single-step, multi-step (threaded output), req-kernels (kernel strings reach the step), empty content, and empty pipeline
- `pressViaPipeline.integration.test.ts`: the three live cases sit in `describeBrainLiveOnDemand('pressViaPipeline (live)', …)`. the empty-content and empty-pipeline cases move to the unit test, since they never ask a brain
- `src/.test/isBrainLiveScopeAll.ts` + `src/.test/describeBrainLiveOnDemand.ts`: the gate. it mirrors the rhachet kin fix, with the same flag, closed set, and todo row

## .mental model

"the ci test no longer phones the model. a fake stands in. if you want to know the real model still squeezes, set `BRAIN_LIVE_SCOPE=all`." analogy: a unit test with a stub engine on the bench, and a road test on demand.

## .evaluation

- pros: no flake class left on ci · zero brain spend per run · the contract clamp is now exact (thread, order, kernels), where before it was only "the output got smaller" · one flag name across the org
- cons: ci no longer notices a brain that no longer compresses. accepted: that is the brain's quality, not this code's contract, and the live suite checks it on demand
- edge cases: a typo in the flag fails loud (case=4). the gated describe body does no i/o at collection; it reads the fixture in `useBeforeAll`, which never runs when skipped

## .what is awkward

- `rule.forbid.failhide` names `runIf` skips as no alternative to an absent resource. this gate is not an absent-resource skip. it is a cost opt-in, off by design, and named on every run by a todo row. the gate reads no credential: `isBrainLiveScopeAll` reads only `BRAIN_LIVE_SCOPE`, so with the flag on, the ask's own credential path (`compress.via.bhrain.ts:364-373`, rhachet `genContextBrain` via keyrack) runs unchanged. a test that proves that path fails loud on an absent key belongs to the compressor's contract (fulcrum F5)
- the context arg is required, so the one prod caller changes by one line. a default would be smaller, but it would force an eager value import of `compress.via.bhrain`, whose load-time mkdir would leak into the unit test. outer layers inject (`rule.require.dependency-injection`)
