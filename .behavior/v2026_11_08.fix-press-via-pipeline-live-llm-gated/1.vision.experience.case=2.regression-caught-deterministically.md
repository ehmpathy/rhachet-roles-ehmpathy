# case=2: a pipeline regression goes red on ci, with no brain

## .narrative

a mechanic edits `pressViaPipeline` and, by mistake, feeds each step the original content instead of the prior step's output. they push. the pr shard goes red within seconds, on the multi-step case alone. the failure says that step 1 got the original text where it expected step 0's output, and it shows both. the mechanic knows at once which line broke. no brain mood muddies the signal: if ci is red, the code is wrong.

the same suite also guards the kernels. had the edit dropped the kernels instead, the req-kernels case would go red. it hands two kernels in and expects both concept strings at the step, so the mechanic would see exactly which strings never arrived.

## .bdd sketch

```
given('[case2] a fake compressor that halves its input and records each call')
  when('[t0] pressViaPipeline runs a two-step pipeline [[sitrep-aggressive], [telegraphic]]')
    then('step 1 receives the output of step 0')        # red if the thread breaks
    then('steps record the mechanisms in pipeline order')
    then('tokens.after < tokens.before')
  when('[t1] pressViaPipeline runs [[req-kernels, sitrep-aggressive]] with kernels k1, k2')
    then('the step receives the kernel concept strings of k1 and k2')   # red if kernels drop
    then('the step mechanisms contain req-kernels')
    then('tokens.after < tokens.before')
```
