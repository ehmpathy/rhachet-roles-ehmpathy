# case=13 · an alert reaches a clone in another repo

covers: A32 (other-repo × idle), A33 (other-repo × dead), D9. happy · critipath, with one sharp edge.

the daemon is per machine, not per repo (Q6 lean). `clone say` addresses a clone through the repo's own `.agent/.actors/` (verified: `clone list` lists only this repo's actors). so the watch must carry where its clone lives.

## .narrative

the v1.41.0 daemon was spawned by clone A in `rhachet-roles-ehmpathy`. clone C, also on v1.41.0, works in `ehmpathy/domain-objects` and pushes pr #312. its findsert joins the same daemon, and its watch record holds `repoRoot: …/domain-objects/_worktrees/beav.fix-x`.

`test-unit` fails on #312. the daemon runs `rhx clone say @:mechanic` with cwd at that repo root, so `@:mechanic` matches clone C — not clone A, who shares the slug in another repo:

```
🐢 pr watch — ci failed on #312
   ├─ pr: ehmpathy/domain-objects#312
   ├─ check: test-unit (failure)
   └─ next: rhx show.gh.test.errors
```

the sharp edge: the alert addresses by serial, not slug, so two clones named `@:mechanic` in two repos can never cross.

clone C's session ends. the next tick's probe reads `domain-objects`' actors, finds clone C gone, and drops its watch.

whether `clone say` honors the cwd this way is research R1; if it does not, the fallback is to run the call through that repo's own `node_modules/.bin/rhx`.
