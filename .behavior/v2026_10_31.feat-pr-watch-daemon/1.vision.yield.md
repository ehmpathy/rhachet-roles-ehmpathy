# 1.vision — a pr-watch daemon for mechanics

## .the outcome world

### before

a mechanic pushes, opens pr #1220, and idles. ci fails at minute seven. nobody tells it. a director notices an hour later, types "your ci is red" into its pane, and the mechanic fixes a one-line snapshot. a review comment waits a day the same way. an approval waits until a director says "ship it". every signal github already holds travels through a human relay.

### after

the mechanic pushes. `git.commit.push` findserts the pr, then findserts a watch: pr #1220 → this clone. if no pr-watch daemon lives on the box for this rhachet-roles-ehmpathy version, the push spawns one; else it joins the one alive.

```
🐢 shell yeah, pushed
   ├─ pr: #1220 (created)
   └─ watch: set → @:mechanic (daemon v1.41.0 pid 48122, spawned)
```

at minute seven, the clone receives, on its own:

```
🐢 pr watch — ci failed on #1220
   ├─ pr: ehmpathy/rhachet-roles-ehmpathy#1220
   ├─ check: test-unit (failure)
   └─ next: rhx show.gh.test.errors
```

it fixes and pushes. a comment arrives the same way, then the approval, then `#1220 merged; watch ended`. when the box's last watch ends, the daemon exits.

### a day in the life

five mechanics on one box, three worktrees on v1.41.0 and two on v1.40.0. two daemons run — one per version. each polls its prs once per tick and speaks into the clone that watches. directors read the prs for judgment, never to relay ci state.

### the aha

the mechanic that went idle after a push wakes to `ci failed … next: rhx show.gh.test.errors`, and the fix ships before any human looks. the pr becomes a conversation between github and the clone; the director drops out of the loop.

## .the contract we propose (sketch)

| surface | shape |
|---|---|
| auto subscribe | `git.commit.push` findserts a watch right after it findserts the pr |
| `rhx git.pull.watch get` | the daemons on the box (per version: pid, last tick) and their watches |
| `rhx git.pull.watch set --pr N` | watch a pr by hand (e.g. a pr this clone reviews) |
| `rhx git.pull.watch del --pr N` | stop a watch; a no-op if absent |
| the daemon | `git.pull.watch.daemon`, spawned detached; never run by hand |
| state | `~/.rhachet/storage/repo=ehmpathy/role=mechanic/skill=git.pull.watch/v=$version/` — `daemon.pid`, `daemon.lock`, `heartbeat`, `watches/*.json` (pr, clone serial, repo root, cursors), `outbox/*.json` |
| delivery | `rhx clone say @:$serial --what @stdin`, run with cwd at the watch's repo root; never `--force` |
| github read | rest `gh api` with etag (`if-none-match`) per pr; one poll per pr per tick, shared by every watcher |

the three wish events map to rest reads, each etag-able:

| event | endpoint | today |
|---|---|---|
| ci.failed | `repos/$R/commits/$head_sha/check-runs` | `git.release` reads the same data via `gh pr view --json statusCheckRollup` (graphql, no etag) |
| comment.new | `repos/$R/issues/$N/comments` + `repos/$R/pulls/$N/comments` | `git.pull.comment get` reads these |
| review.approved, review body | `repos/$R/pulls/$N/reviews` | read nowhere |
| pr state, head sha | `repos/$R/pulls/$N` | — |

two facts the daemon must honor, verified by hand (see groundwork): a 304 costs no rate limit, and `gh api` exits 1 on a 304 — so "exit 1 + `HTTP 304`" reads as unchanged, never as a fault.

## .mental model

- a mechanic tells a friend: "once i open a pr, it pings me when ci breaks, when someone comments, and when it's approved."
- analogy: a **pager** for the pr. one pager base station per version on the box; each clone clips its pager to the prs it owns.
- their words vs ours:

| they say | we say |
|---|---|
| "it pings me" | the daemon delivers an alert |
| "i'm subscribed to my pr" | a watch (pr → clone) |
| "the watcher" | the pr-watch daemon |
| "ci went red" | `ci.failed` |

`watch` reuses the vocabulary `git.release --watch` already holds: an eye on a pr's state.

## .evaluation

### how well it meets the wish

| done means | how |
|---|---|
| alert per ci failure, comment, approval, no director relay | cases 1, 2, 3; auto subscribe at pr findsert |
| two clones, one version → one daemon | case 4; findsert under a per-version lock (case 6) |
| a second version gets its own daemon | case 5; state dir keyed by `v=$version`; an upgrade moves the watch (case 14) |
| a restart never leaves a second daemon | case 6; caller lock + daemon self-check at boot |

### pros

- the relay disappears for the three most common pr signals
- one poll per pr serves every watcher; etag 304s cost no rate limit
- the daemon cannot orphan: it exits at zero watches (the keyrack lesson, rhachet#489)
- alerts carry the next command, so a woken clone acts at once

### cons

- poll lag: an alert lands up to one tick late (lean: 60s)
- a token for the whole box: one keyrack grant serves every watch; expiry pauses all (case 8)
- `clone say` reaches only enrolled LIVE clones; a plain `claude` session cannot be alerted
- a version bump leaves the old daemon alive until its last watch ends

### edge cases and the pit of success

| edge | pit of success |
|---|---|
| clone busy, at a modal, or the human typed | if `clone say` refuses, the alert is held in the outbox and retried each tick; never forced (case 7) |
| clone dead | each tick probes each watch's clone; a dead one drops its watch; the last exits the daemon (case 10) |
| own 🐢 comment | never alerted (F5) |
| burst of events | one grouped alert per pr per tick |
| daemon crashed or wedged | the next findsert replaces it; cursors on disk catch up (case 9) |
| pid reused by another program | probe checks the command line; never kills a stranger |
| rate limit / network down | back off; cursors hold; no event lost |
| token expired | one loud alert with the unlock command; resume on return (case 8) |

## .open questions and assumptions

### assumptions

- A1. `rhx clone say` is the delivery channel for now; bhuild's `phone` does not exist yet
- A2. the version is the `package.json` version of the rhachet-roles-ehmpathy install that holds the skill; where that version does not pin the code (dev worktrees of this repo), see Q8
- A3. a watch begins at pr findsert; events before it are not alerted
- A4. `ci.passed` raises no alert; silence is the default
- A5. delivery is to enrolled clones only (they carry `RHACHET_CLONE_SERIAL`); a push from any other session prints `watch: skipped (not an enrolled clone)`
- A6. a pr opened before this feature ships gets a watch on its next push: `git.commit.push` reaches the findsert block for a found pr too (`git.commit.push.sh:651-674`)
- A7. comment edits are not alerted; the cursor keys on comment id

## .groundwork

### external

- github rest best practices — "subscribe to webhook events instead of polling"; if you poll, a conditional request "does not count against your primary rate limit if a `304` response is returned". webhooks need a public endpoint, which a dev box lacks, so etag polls fit. https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api
- rate limits — 5,000 requests/hour per token, shared across all requests of that identity. https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api
- verified by hand, 2026-10-31, on `repos/ehmpathy/rhachet-roles-ehmpathy/pulls/1180/reviews`:
  - first call → `200`, `Etag: "3769…6ffd"`, `X-Ratelimit-Remaining: 4960`, `Cache-Control: private, max-age=60`
  - repeat with `If-None-Match` → `304 Not Modified`, `X-Ratelimit-Remaining: 4960` (unspent); `gh` printed `gh: HTTP 304` and exited 1
  - `max-age=60` means a poll faster than 60s gains no fresher data — it backs the Q3 lean
- `gh pr view --json reviewDecision,latestReviews` returns both fields (checked on #1180), but `gh pr view` is graphql, which has no conditional requests; the daemon uses the rest twins
- ehmpathy/rhachet#489 — keyrack daemons orphan (~230/hour into swap). its fixes, in order: tie lifetime to the spawner, idle timeout, reuse before spawn. a shared daemon cannot tie to one spawner, so this vision takes reuse-before-spawn (findsert) plus exit-at-zero-watches
- ehmpathy/rhachet-roles-bhuild#491 — phone: directed texts between known clones, delivered by a daemon over `clone say`, durable files on disk. not shipped; a future delivery channel (Q1)

## .what is awkward

- **a shared daemon has no home.** it is spawned from one worktree, yet must outlive that worktree's delete or upgrade. Q7 leans to a per-version copy of its code in the state dir; that is a second install the box must keep, keyed by version
- **a shared daemon has no owner.** the keyrack lesson says tie the daemon to its spawner; a shared daemon outlives any one spawner by design. exit-at-zero-watches is the stand-in, and it rests on correct dead-clone detection
- **the version axis fights the box.** two daemons poll the same github for two versions; a pr watched from both versions is polled twice (inventory L13). the wish asks for this split, and it is cheap under etag. an upgrade mid-pr must move the watch between keys, or every alert doubles (case=14)
- **`clone say` reach is per repo.** a machine-wide daemon talks to clones in many repos, each through that repo's `.agent/.actors/`. the watch must carry the repo root, and that couples the daemon to the clone's worktree path
- **a box-wide token.** one keyrack grant now serves prs across repos and orgs; whose identity reads a given repo is no longer per call
- **held alerts can pile up** behind a clone that sits at a modal for hours; delivery then lands as one tall alert
