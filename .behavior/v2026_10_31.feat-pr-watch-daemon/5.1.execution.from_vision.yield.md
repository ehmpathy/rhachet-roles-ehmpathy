## .contract

| surface | shape |
|---|---|
| `rhx git.pull.watch get` | daemons per key (pid, live, last tick) and every watch; read-only |
| `rhx git.pull.watch set --pr N [--mode apply]` | findsert a watch for this clone, then the daemon of this clone's key; plan by default |
| `rhx git.pull.watch del --pr N [--mode apply]` | delete this clone's watch, under every key; a no-op if absent; plan by default |
| `git.commit.push` | after its pr findsert, findserts the watch in apply mode; prints one `watch:` line |
| `git.pull.comment set` | appends each comment id it posts to this clone's ledger |

## .findsert (set, git.commit.push, boot)

1. take the lock (`mkdir`, wait 10s by the clock; reap a lock whose owner pid is dead, or that is older than 20s; reapers serialize on a `.reap` guard and re-judge the lock inside it)
2. read `daemon.pid`; live (pid alive, its args name this key's daemon) and fresh (heartbeat within 3 ticks + 60s) → found
3. stale (dead or foreign pid) → clear the record; wedged (own pid, old heartbeat) → `kill` that verified pid, clear
4. absent → copy the skill `*.sh` into `bin/` if `bin/` is incomplete, spawn `nohup bash bin/git.pull.watch.daemon.sh $key &`, cwd at the state dir; drop the lock
5. the daemon claims `daemon.pid` under the lock at boot, or exits if a live daemon of its key holds it (F1); a source it cannot load exits it before the claim
6. the findsert waits for the pid record; a child that died first is a boot failure, named with the last line of `daemon.log`. it prints `daemon v<key> pid <n>, spawned|found|replaced <prior>`

`set` writes the watch record before step 1, and deletes this clone's watch on the same pr under every other key (F9, case=14). `set` refuses a clone that is absent, `DEAD`, or unreadable in its repo root's registry (F19).

## .tick (every 60s; env `GIT_PULL_WATCH_TICK_SECONDS` for tests)

1. touch the heartbeat; every bounded call that returns touches it too, through one hook in the bound, so no call site can leave a live daemon to read `wedged`
2. zero watches → remove `daemon.pid`, exit (F3)
3. per watch: a `repoRoot` that is no longer a dir → delete every watch at it, with its outbox. else `rhachet clone list --output json`, cwd at its `repoRoot`, bounded at 30s; serial absent or `DEAD` → delete the watch and its outbox (A17). `DEAF`, a fault, a stall, or a list of a shape not known (no `.actors` array) holds. each daemon delete runs under the key lock, and only if the record still holds the `watchId` the tick judged
4. token: `rhachet keyrack get --key ehmpathy.prep.EHMPATHY_SEATURTLE_GITHUB_TOKEN --env prep --owner ehmpath --json`, cwd at each watch `repoRoot` that still stands, in turn, until one grants (R3); where none grants, the status a human can act on (`locked` > `blocked` > `absent`) outranks a fault. not granted → write `daemon.paused` with the cause, send one paused alert per watcher per cause (unlock fix for `locked`, human fill fix for `absent`), skip github, next tick. `daemon.paused.told` names the clones told of the cause, so a clone that sets its first watch mid-pause is told on the next tick; the outage and fault notes keep a `.told` list the same way
5. per distinct pr: etag reads, each gh call bounded at 60s (a stall reads as no reply), of `pulls/$n`, `commits/$head/check-runs`, `issues/$n/comments`, `pulls/$n/comments`, `pulls/$n/reviews`. a list of a full page or more (a bare array, or `check_runs`) is read whole each tick with no etag, since page one's etag never sees a later page. a 401 → as step 4, cause `expired`. a rate limit (403 / 429 with a zero quota left or a `retry-after`) → write `daemon.backoff` with the lift epoch; each tick before it skips github and only drains the outbox (A29). no reply or a 5xx → mark `daemon.unreachable`; cursors hold; past 30 min (env `GIT_PULL_WATCH_UNREACHABLE_NOTE_SECONDS`) one outage note per watcher; the next read that succeeds clears it (A30). other faults → skip this pr this tick; cursors hold. a pause lifts only once github accepts the token; a granted keyrack read alone would lift a 401 pause each tick and re-alert it
6. per watch: diff against its cursors → events. the first tick after set primes the cursors and alerts only what happened at or after `setAt`; older events stay quiet (A3). every github string is stripped of control bytes before render
   - `ci.failed` — a check run with conclusion `failure | cancelled | timed_out | action_required`, its id unseen for this head; a new head resets the seen set (A5); the alert names the head's short sha
   - `comment.new` — an issue or review comment id above its cursor, not in this clone's ledger (F5); author marked `bot` where its login ends `[bot]` (Q4), or `clone` on proof only (A20): its id sits in some clone's ledger on this box, or its body opens with 🐢 and its author is a bot or a login a ledgered comment proves. a stranger who types 🐢 reads as human
   - `review.approved` — a review in state `APPROVED` above its cursor; `changes_requested` and commented reviews with a body ride as `comment.new` (Q5)
   - `pr.merged` / `pr.closed` — one closure note, then the watch ends
7. per watch: one grouped alert; queue it, then advance cursors. the alert sits in the outbox first, so a crash between the two repeats it, never drops it; a queue write that does not land holds the cursors too; a write-back that does not land repeats it each such tick, its cause in the log
8. retry the outbox: each held alert per tick, the heartbeat touched after each send; a clone that holds one alert holds the rest of its alerts that tick, untried; a log line each 10th try (F18)
9. zero watches → the daemon also clears its pause and outage marks, so none outlives its life

boot: `umask 077`; exit 1 with the tool named if `gh` or `jq` is absent from PATH; spawned under `setsid` where present, so a kill of the spawner's process group leaves it; the spawner's `RHACHET_CLONE_SERIAL` is dropped, since one daemon serves every clone. a pid that lives but that `ps` cannot name reads as held: no twin, no kill.

delivery: `rhachet clone say @:<serial> --what @stdin --output json`, cwd at `repoRoot`, never `--force`, bounded at 60s (env `GIT_PULL_WATCH_SAY_MAX_SECONDS`); no answer in the bound holds the alert. every rhachet call (token, clone list, say) runs through one communicator that enters the root, picks the binary, and applies the bound. exit 0 (`released`, `enqueued`, `exited`) → done. a failure with `reachState: DEAD` → drop the watch; every other failure (`withheld`, `buffered`, `absent`, `unreadable`, `DEAF`, wedged) → hold (F16).

rhachet binary: `$repoRoot/node_modules/.bin/rhachet` where present, else `rhachet` on PATH.

## .alerts

```
🐢 pr watch — ci failed on #1220
   ├─ pr: ehmpathy/rhachet-roles-ehmpathy#1220
   ├─ check: test-unit (failure)
   ├─ head: 4c127b2
   └─ next: rhx show.gh.test.errors
```

one alert per watch per tick; several events stack as peer sections. comment events name author, kind, url, the file and line of an inline comment, and the first line of the body, cut at 120 chars and marked `…` where more follows; a proven peer reads `(clone)`; a review names `read: gh api --method GET repos/<repo>/pulls/<n>/reviews/<id> --jq .body`, since `git.pull.comment get` reads no review body; approval names the reviewer and the head's ci (`passed`, `failed`, `in progress`, `no checks`), with `next:` from it — `rhx git.release --mode apply` on green, `rhx show.gh.test.errors` on red, `rhx git.release --watch` else (F23); a changes-requested review reads `review: changes requested`; closure notes are one line (`#N merged; watch ended`, `#N closed without merge; watch ended` + `by:`).

## .probes

read from the rhachet@1.50.1 dist, 2026-10-31.
