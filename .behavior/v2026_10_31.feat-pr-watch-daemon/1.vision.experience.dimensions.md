# 1.vision.experience.dimensions — pr-watch daemon

the experience space of "a mechanic opens a pr; the daemon alerts it". nine axes, in two boxes.

## .actors (who lives each cell)

| actor | role in the experience |
|---|---|
| `mechanic` | the clone that watches a pr; the one alerted |
| `system` (the daemon) | polls github, delivers alerts; no human, no prompt |
| `reviewer` | the human or clone who comments on or approves the pr — walked as D5 |
| `peer-clone` | a second clone on the box — walked as D4 |

`system` is a real value, not a stand-in for a felt actor. its sharp edges (a dead clone, a rate limit) have no human to prompt.

## .lifecycle box — who starts, finds, or reaps the daemon

### D2 · daemon state — at the moment a clone needs it

`absent` · `live` (a daemon of the caller's key) · `stale` (pid on record, process dead) · `wedged` (process alive, no tick in 3 intervals)

"other version only" is not a D2 value: from the caller's key, another version's daemon is `absent`. D4's version values carry that case.

### D4 · population — who shares the box

| value | sense |
|---|---|
| `solo` | one clone, one key |
| `two-clones.one-key.distinct-prs` | two clones, one version |
| `two-clones.one-key.same-pr` | two clones, one version, one pr |
| `two-keys.distinct-prs` | two clones on two versions |
| `two-keys.same-pr` | two clones on two versions, one pr — two daemons each poll it |
| `one-clone.key-change` | one clone upgrades while its watch lives |

### D7 · tempo — how the findsert calls meet

`steady` (calls far apart) · `race` (two findserts in one instant) · `restart` (one clone calls the findsert again)

### D8 · spawner home — the fate of the worktree that spawned the daemon

`intact` · `deleted` · `upgraded` (its install moved to another version)

## .alert box — what reaches the mechanic, and when

### D1 · event — what happened on the pr

| value | wish? | note |
|---|---|---|
| `ci.failed` | yes (a) | a check run concludes failure / timed_out / cancelled |
| `comment.new` | yes (b) | an issue comment, a review comment, or a review body |
| `review.approved` | yes (c) | a review with state APPROVED |
| `review.changes-requested` | implied | carries a body, so it is a comment by content (Q5) |
| `push.new` | implied | a new head sha; resets the check cursor |
| `ci.passed` | no | silence by design |
| `pr.merged` | no | ends the watch; a closure note |
| `pr.closed` | no | closed without merge; ends the watch; a closure note that says so |

### D3 · clone state — at the moment an alert is due

`idle` (at the prompt) · `busy` (mid-turn, no prompt up) · `at-modal` (mid-turn, paused on a permission prompt) · `dirty-input` (idle, but a human typed into the box) · `dead` (session gone)

exclusive by definition: `busy` means no modal is up; `at-modal` means one is; `dirty-input` means idle with text in the box.

### D5 · author — who caused the event (for `comment.new`, `review.*`)

`human` · `peer-clone` (another clone, same bot login) · `self` (this clone) · `bot` (a ci or app bot)

D5 applies to every authored event, not only comments. it is undefined for `ci.*`, `push.new`, `pr.*` — those cells are walked once without it.

### D6 · github reach — the channel the daemon reads

`ok` · `rate-limited` · `auth-expired` (a token was granted and lapsed) · `auth-absent` (no token was ever filled) · `network-down`

### D9 · repo scope — where the watched clone lives relative to the daemon

`same-repo` (the clone's repo is the one the daemon was spawned from) · `other-repo` (another repo on the box)

## .why these are orthogonal

- D4 is the population; D7 is how their calls meet in time; D8 is the spawner's worktree fate. a race can meet any population; a delete can meet any race
- D1 is what github says; D3 is what the clone can take; D9 is where the clone lives. a `ci.failed` can meet any clone state in any repo
- D5 is defined only for authored events; the collapse rule below names this, rather than claim D1 × D5 is full
- D6 is the upstream channel, independent of who watches and who is alerted

## .the hidden dimensions the walk surfaced

**delivery outcome** — D3 × `system` forced it: `delivered` · `held` (retry next tick) · `abandoned` (clone dead → watch ends). every non-idle clone state lands in one of these three, never in a silent drop. this axis is the outbox.

**daemon key** — D4 = `two-keys.*` forced it. a daemon's key is the version of the code it runs (plus a code hash where the version does not pin the code — Q8). a clone joins the daemon of its own key, never another.

**key change** — D4 = `one-clone.key-change` forced a rule: a clone's watch lives under one key at a time. a findsert under a new key moves the watch and deletes it under the old one, or every alert arrives twice.

## .the walk

the two boxes are near-independent: the lifecycle box sets which daemon serves a watch; the alert box sets what it delivers.

- **lifecycle box** = D2 × D4 × D7 × D8. walked as D2 × D4 under `steady` + `intact` (every cell), then D7 × D2 and D8 × D2 against any population (every cell)
- **alert box** = D1 × D3 × D5 × D6 × D9. walked as slices, not cell by cell, under these collapse rules:
  - D6 ≠ `ok` stalls every D1 alike → walk D6 once per value
  - D3 acts the same on every alert event → walk D3 once
  - D5 is defined only for authored events → walk D5 × {comment.new, review.approved}
  - D9 changes only the delivery path, not the alert → walk D9 × D3 = {idle, dead}
  - `ci.passed`, `pr.merged`, `pr.closed`, `push.new` are not alerts → walk once each

a cross-slice cell (e.g. `ci.failed × dirty-input × rate-limited`) takes the verdict of its slices: held (A16), and the tick backs off (A29). the inventory names each slice, not each of the hundreds of composed cells.

see `1.vision.experience.case=_.md` for every slice and its verdict.
