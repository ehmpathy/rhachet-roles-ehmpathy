# case=12 · the spawner's worktree goes away

covers: L25 (spawner deleted × live), L26 (spawner upgraded × live), F10. sharp · critipath.

freq: high — `_worktrees/` here are created and deleted per branch, and the first clone to push is the spawner. cost: high — if the daemon lived in that worktree, every other clone's alerts would stop with no word.

## .narrative

09:00 — clone A in `_worktrees/…beav.feat-a` pushes first and spawns the v1.41.0 daemon. at spawn, the findsert copies the daemon's code into the per-key state dir (`…/skill=git.pull.watch/v=1.41.0/bin/`), and starts it there, cwd there. the daemon reads no file under `beav.feat-a` after boot.

09:30 — clone B in `beav.feat-b` joins (case=4).

12:00 — #1220 merges. the human deletes the `beav.feat-a` worktree, `node_modules` and all.

12:01 — the daemon's next tick runs as before. its code, its pid record, and its cwd sit in the state dir, which no worktree owns. clone B's #1221 watch never notices:

```
🐢 pr watch
   └─ daemon v1.41.0 · pid 48122 · last tick 12s ago · home: ~/.rhachet/storage/…/v=1.41.0/bin
      └─ #1221 → @:mechanic (beav.feat-b)
```

the upgrade variant: clone B's worktree moves to v1.42.0 mid-day. the v1.41.0 daemon keeps its own copy, so it does not break when the v1.41.0 files leave `beav.feat-b/node_modules`. clone B's next push is a key change (case=14).

the fail-safe, if the copy were absent or corrupt: the daemon cannot boot, the spawn's boot-survival check sees it die, and the push prints it loud:

```
🐢 bummer dude — pushed, but no watch
   ├─ pr: #1221 (found)
   └─ 💥 MalfunctionError: pr-watch daemon v1.41.0 died at boot
      └─ see: ~/.rhachet/storage/…/v=1.41.0/daemon.log
```
