# case=8 · auth fails loud — expired or absent

covers: A27 (auth-expired), A28 (auth-absent), A10 (catch-up on resume), F7 (one paused alert, not one per tick). sharp · critipath.

freq: high — keyrack credentials expire ~9h, and a daemon outlives a work day. cost: high — a silent daemon is worse than none; the mechanic believes it is watched.

## .narrative — expired

the daemon has run since 09:00. at 18:10 the github token it reads expires. the next tick gets a 401.

the daemon does not retry blind and does not go quiet. it pauses its ticks and alerts every watcher once:

```
🐢 bummer dude — pr watch is paused
   ├─ ✋ ConstraintError: github token expired
   ├─ watches paused: #1220, #1221
   └─ fix: rhx keyrack unlock --owner ehmpath --env prep --key EHMPATHY_SEATURTLE_GITHUB_TOKEN
```

the mechanic runs the unlock. the daemon's next probe reads a valid token, resumes, and catches up from each watch's cursor. any failure that landed while paused is alerted then, once.

## .narrative — absent (case8b)

a fresh box. the keyrack was never filled with the github key. the first push spawns the daemon; its first token read finds no key at all. an unlock cannot help — there is no grant to unlock — so the alert names the human's step:

```
🐢 bummer dude — pr watch is paused
   ├─ ✋ ConstraintError: github token not filled
   ├─ watches paused: #1220
   └─ fix: a human runs `rhx keyrack fill --owner ehmpath`, then
      └─ rhx keyrack unlock --owner ehmpath --env prep --key EHMPATHY_SEATURTLE_GITHUB_TOKEN
```

the mechanic cannot fill it itself; it tells its human, and carries on. once filled and unlocked, the daemon resumes as above.

the two fixes come from the extant keyrack errors (`howto.keyrack`): `credential is locked` → unlock; `credential not filled` → a human fills.
