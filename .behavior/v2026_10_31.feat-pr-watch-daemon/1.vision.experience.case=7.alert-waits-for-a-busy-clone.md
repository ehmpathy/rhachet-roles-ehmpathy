# case=7 · an alert waits for a busy clone

covers: A14 (busy), A15 (at-modal), A16 (dirty-input), F6, F7, F8. sharp · critipath.

## .the rule this case proves

the daemon hands every alert to `rhx clone say`. `clone say` either takes it (it reaches enqueue) or refuses it. an alert that is taken is done. an alert that is refused goes to the outbox and is retried each tick. no alert is dropped, and `--force` is never passed.

what `clone say` takes vs refuses per clone state is `clone say`'s contract, not this daemon's. the verified part, from `rhachet clone say --help`: it refuses a dirty input box unless `--force`, and never forces a modal. whether a mid-turn clone enqueues or refuses is open research (see the yield). the outbox covers both answers.

## .narrative

`test-integration` fails on #1220 while the mechanic is deep in a turn. the daemon calls `clone say`.

- if `clone say` enqueues it, claude code holds the message until the turn ends, and the mechanic reads it then. done.
- if `clone say` refuses it, the daemon writes the alert to the outbox for that watch, keyed by the check run id, and retries next tick.

the next tick, the clone sits at a permission prompt. a retry is refused again — a modal answer is the human's call. still held.

the human answers the prompt; the clone idles. the next retry is taken:

```
🐢 pr watch — ci failed on #1220 (held 2 ticks; you were busy)
   ├─ pr: ehmpathy/rhachet-roles-ehmpathy#1220
   ├─ check: test-integration (failure)
   └─ next: rhx show.gh.test.errors
```

if the human had typed half a message into the box, `clone say` would refuse too, and the alert would wait. the daemon never passes `--force`.
