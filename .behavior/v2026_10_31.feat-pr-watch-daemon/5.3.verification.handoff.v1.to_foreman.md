# 5.3.verification — handoff v1 to the foreman

## .the wall

`git.pull.watch.github.real` case1 (an etag 200, then a 304, on the real github api) needs
`EHMPATHY_SEATURTLE_GITHUB_TOKEN`. that key is `absent` in this box's ehmpath keyrack, for both
env test and env prep. case2 (a 401 pauses the watch) needs no token and passes. every other suite
passes; see `5.3.verification.yield.md`.

## .what i tried

1. `rhx keyrack unlock --owner ehmpath --env test --key EHMPATHY_SEATURTLE_GITHUB_TOKEN` → `status: absent`
2. `rhx keyrack unlock --owner ehmpath --env prep --key EHMPATHY_SEATURTLE_GITHUB_TOKEN` → `status: absent`
3. `rhx keyrack status --owner ehmpath`: the other test keys (openai, xai, anthropic) are unlocked, so
   the keyrack itself works; only this key was never filled
4. a fake or a mock for this case: refused. the case exists to prove the etag contract against real
   github; the stub `gh` already covers the logic. a mock here would be a fake test
5. the human's gh cli login: refused. the watch reads github only with the ehmpath token (F11), and
   a test under a different identity proves a different claim

## .why it needs you

a keyrack fill needs the vault secret, which only a human holds. no command the clone may run puts
a value into the key.

## .the ask (either one closes it)

- fill the key, then the clone reruns the suite:
  ```sh
  rhx keyrack set --owner ehmpath --key EHMPATHY_SEATURTLE_GITHUB_TOKEN --env test --vault <vault>
  rhx git.repo.test --what integration --mode apply --scope 'path://git.pull.watch.github.real'
  ```
- or rule that ci is the proof: the ci keyrack firewall fills the key, and the done-gate push runs
  case1 in ci on #1222
