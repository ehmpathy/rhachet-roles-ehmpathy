# case=9 · a stale or wedged daemon is replaced

covers: L3 (stale), L4 (wedged), A10 (events while down), F11 (pid-reuse guard). sharp · alterpath.

care = freq × cost = low × medium → alterpath.
- freq low: a reboot, an oom kill, a hang — rare against the many pushes of a day
- cost medium, not high: the harm is **delay, not loss**. cursors sit on disk, so the next findsert catches up every event once (A10). contrast case=8, where the daemon lives but reads naught — no findsert would ever fix that, so it must alert
- the residual gap: a mechanic that never pushes again (it waits on a review) never re-findserts, so its delay has no bound. lean for the blueprint: also findsert at clone boot (Q12), which bounds the delay to the next session start

## .narrative

the box rebooted overnight. the pid record for v1.41.0 still names 48122, and the watch records for #1220 and #1221 are still on disk.

at 08:02 the mechanic pushes. the findsert takes the lock, reads 48122, and probes it: no such process. it clears the record and spawns pid 61004. the new daemon reads the watch records and their cursors. a comment that landed at 06:30 is alerted once.

```
🐢 shell yeah, pushed
   ├─ pr: #1220 (findserted)
   └─ watch: set → @:mechanic (daemon v1.41.0 pid 61004, replaced stale pid 48122)
```

the wedged variant: pid 48122 is alive, but its heartbeat file is 40 minutes old (three intervals missed). the findsert kills 48122 and spawns fresh, with the same output line ("replaced wedged pid 48122").

pid reuse guard: the probe checks that the live pid's command line is a pr-watch daemon of this version, so a reused pid that now belongs to another process is read as stale, never killed.
