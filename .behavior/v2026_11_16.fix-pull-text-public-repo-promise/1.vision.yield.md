# vision: pr text into a public repo needs an anonymized promise

## .the outcome world

every mechanic skill that sends pr text to github reads the target repo's visibility first. a public repo, with no promise, gets no write: the skill prints a soft nudge and exits 2. the caller checks the text, then reruns the exact command with `--promise text-to-public-repo-is-anonymized`. a private or internal repo writes as today.

### before / after

| | before | after |
|---|---|---|
| comment into a public repo | posted at once | held; one rerun with the promise posts it |
| a private route path pasted in a pr body | public forever, edit history included | caught at the nudge, cut before the send |
| a private repo | posted at once | posted at once |
| the caller's cost | none | one rerun per public write; zero per private write |

### the aha
a clone pastes `see reefco/svc-tides#412` into a status comment for a public repo. the nudge names "a private org, repo ... or pr / issue numbers". the clone reads its own text once more, cuts the line, and reruns. the leak never left the machine.

## .the contract

| skill | gated when | owes |
|---|---|---|
| `git.pull.comment.set` (new, edit, reply) | verdict writes text | `--promise` on a public repo |
| `git.pull.title.set` | verdict writes text | same |
| `git.pull.description.set` | verdict writes text | same |
| `git.commit.push` | every apply, before `git push` (F1) | same |
| `git.commit.set --push` | before the commit (F6); passes `--promise` to push | same |
| `*.get`, `comment.del` | never | naught: no text sent |

the gate, in order:
1. `--promise` given, with any other value → refuse, exit 2 (F7)
2. `--promise text-to-public-repo-is-anonymized` given → write as today; no visibility read (F5)
3. a no-op verdict → pass, no read (F4)
4. read visibility under the skill's own credential: `private` or `internal` → write as today
5. `public`, or the read fails → the nudge, exit 2, on stdout and stderr; plan too (F3)

the nudge is the issue's text (F2), with one change: its check line names the text this skill sends, so the caller checks the right words.

| skill | check line |
|---|---|
| comment.set | `check the comment holds none of` |
| title.set | `check the title holds none of` |
| description.set | `check the description holds none of` |
| commit.push, commit.set --push | `check the commit messages, which become the pr title and description, hold none of` |

its rerun line is the caller's exact command plus the promise; a caller who piped the text (`--from @stdin`, or set's `-m @stdin`) sees the pipe named again. an unreadable visibility reads `(visibility unreadable, held as public)` on the repo line. under `--output json`, stdout carries the family's refusal object.

each skill's `--help` names `--promise text-to-public-repo-is-anonymized` and when it is owed: a write of text into a public repo.

## .mental model

to a friend: "before the turtle posts on a public pr, it makes you pinky-swear the text names naught private. one extra flag, once you have looked."

analogy: the "reply all" confirm on an email to an external list. it fires only where the audience is the world.

| caller says | we say |
|---|---|
| "public pr" | a write of pr text into a repo whose visibility is `public` |
| "the check" | the nudge |
| "the pinky-swear" | `--promise text-to-public-repo-is-anonymized` |

## .evaluation

pros:
- the one safe moment, before the send, now holds a check
- zero cost on private repos
- the rerun line is the caller's own argv plus the promise, so the check costs one read and one paste. a piped text is the one exception: stdin is spent once read, so the line pipes from the paved `./.temp/` file and says to pipe the same text again (case=5, case=7)
- fails safe: an unreadable visibility holds, never writes unchecked

cons:
- a promise is a self-attest; a careless caller can pass it unread. the nudge's list makes the check concrete, not enforced
- every push into a public repo owes the promise (F1), also a push onto a pr that already exists

edges held in the pit of success:
- wrong promise value refused before any gh call (case=8)
- a piped body is not lost on the rerun (case=7)
- the composed set halts before the commit, so its exact rerun works (case=5)
- reads and deletes stay ungated

## .open questions & assumptions

- **[answered]** does the bhuild companion's nudge match? its code is not on bhuild's main (`rhx git.repo.get lines --in ehmpathy/rhachet-roles-bhuild --words 'public-repo-is-anonymized'` → 0 matches), but its spec is ehmpathy/rhachet-roles-bhuild#675. that nudge opens with its own role glyph (🦫), names the text it sends (`check the title and body hold none of`), and exempts a status-only update that carries no text. so this vision's per-skill check line and the 🐢 header are parity, and F4 has a precedent
- **[answered]** does "one request" in the clamp mean one gh call of any kind? no: every set also reads (viewer, the pull, the read-back), so a literal count could never pass. it means one write request (one POST, PATCH, or push), as the `[tn]` sketches assert
- **[answered]** is any other skill a writer of pr text? no: `rhx grepsafe --pattern 'gh pr (create|edit|comment|review)|git push|--method (POST|PATCH)' --path src/domain.roles --glob '*.sh'` finds only the five in scope; raw `gh` writes are not pre-approved (`rhx permissions.get --head gh`)
- **[wisher]** F1: gate the whole push (commit text included), or only the pr create? the one fork with a real cost: a rerun per push (case=9), and a keyrack outage that holds even a private repo's push (`.what is awkward`). best guess taken: the whole push
- **[wisher]** F2: the 🐢 nudge header, or `✋ ConstraintError:`? best guess taken: 🐢, now backed by #675's parity

- `git.commit.push.sh`: pr title and body come from the first behavioral commit (:437-441); push runs before the token fetch (:490-516) so a keyrack outage cannot strand a commit; pr create at :696
- `git.commit.set.sh` composes push in plan (:1151) and apply (:1276); the commit lands at :1223, before the push
- tests stub gh on PATH and log each call: `FAKE_GH_LOG` in `git.pull.comment.integration.test.ts:54`, `gh.calls.log` in `git.commit.push.integration.test.ts:3140`. the clamp asserts on those logs; each stub must learn to answer `GET repos/<owner>/<name>` with a visibility

## .what is awkward

- the nudge's labels end in a colon over child branches (`rule.forbid.treestruct-indented-text-as-children`, nitpick). kept for parity with the bhuild gate (#675)
- the check line departs from #1365's text: its shared "the title, description or comment" would send a push caller to check fields the push never writes (case=9). #675 already names its own sent text, so the departure matches the companion
- push gates on commit text the issue does not name (F1)
- plan exits 2 (F3): a caller that chains plan then apply now halts at plan, by design
- push today runs before any token fetch, so a keyrack outage never strands a commit (push :490-516). under F1, an unpromised push reads visibility first, and under `as-ehmpath` that read needs the token. so in a keyrack outage, even a **private** repo's push is held: the read fails, and a failed read holds as public. the escape is one rerun with the promise, which a private repo accepts and which skips the read (F5); the nudge's repo line says `visibility unreadable`, so the caller knows why. the same holds for a bare push plan, which today fetches no token
- the cure, if the commander rules F1 the other way: gate only `pr create`, after the push, and the invariant holds untouched
