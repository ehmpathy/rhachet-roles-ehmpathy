# case=10: a private repo's push, held in a keyrack outage

## .narrative
a clone pushes in a private reefco repo. its keyrack token is locked. today that push goes through (push runs before any token fetch) and only the pr open waits on the keyrack. under F1, an unpromised push reads visibility first, and under `as-ehmpath` that read needs the token. the read fails, so the skill cannot tell private from public, and it holds the push as public.

the nudge says why on the repo line, so the clone is not misled into a belief that the repo is public. it offers two ways on: rerun with the promise (a private repo accepts it, and it skips the read), or unlock the keyrack and rerun bare.

```
$ rhx git.commit.push --mode apply
🐢 hold up — this text goes to a public repo
   ├─ repo: reefco/svc-tides (visibility unreadable, held as public)
   ├─ check the commit messages, which become the pr title and description, hold none of
   │  ...
   └─ once checked, rerun with
      └─ rhx git.commit.push --mode apply --promise text-to-public-repo-is-anonymized
```

this is F1's second cost. under F1's other branch (gate only `pr create`), the push lands as today and only the pr open waits.

## .[tn]
```
given('[case10] a private repo, a seaturtle commit, the keyrack token locked')
  when('[t0] commit.push --mode apply, no --promise')
    then('exit 2; the repo line reads "visibility unreadable, held as public"')
    then('no git push ran')
  when('[t1] the same command plus --promise')
    then('no visibility read; one git push')
    then('the pr open meets the locked keyrack as today: the extant guide names the unlock')
```
