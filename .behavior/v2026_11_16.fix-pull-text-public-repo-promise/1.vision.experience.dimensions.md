# experience dimensions: pr text into a public repo

actor: a caller that writes pr text via a mechanic skill. who the caller acts as is axis D8.

## .dimensions

| dim | values | why it varies the experience |
|---|---|---|
| D1 skill | comment.set · title.set · description.set · commit.push · commit.set --push | each holds its own exact command, stdin shape, and write step |
| D2 visibility | public · private · internal | the repo's true visibility; decides gate or pass |
| D3 promise | absent · given · wrong value | decides halt or write |
| D4 mode | plan · apply | plan previews; apply writes |
| D5 verdict | write · no-op | a no-op sends no text (F4) |
| D6 output | tree · json | json callers parse one object |
| D7 input | file · @stdin | a piped text is spent once read; the rerun line must pipe it again |
| D8 auth | as-ehmpath · as-human | the credential the skill writes with, so the credential the visibility read rides on (F5) |
| D9 credential state | usable · unusable (keyrack locked or absent; gh logged out) · github unreachable | decides whether the visibility read can answer |

## .orthogonality

each axis varies alone: a caller picks D1, D3, D4, D6, D7, D8 by flag; D2 is a fact of the repo; D5 is a fact of the pull's current text; D9 is a fact of the machine and the network. no axis fixes another's value.

## .folded, with reason

- **pr authorship** (by self · by another login): every set refuses a foreign pull (`check_pull_by_self`) or a foreign comment key before its verdict (title.set: ownership check precedes the verdict). the gate sits after the verdict (F4), so a foreign target is refused by the extant ownership refusal and never reaches the gate. push opens or finds its own branch's pr only. so authorship adds no cell to this behavior.
- **time** (a visibility flip between the read and the write): an admin act inside a sub-second window; folded as residual risk, inventory row 25
- **plain `commit.set`** (no `--push`): not a D1 value, since it sends no text; inventory row 21 keeps its demo as proof the gate stays off a local commit
- **"unreadable"** is not a value of D2: it is what D9 ≠ usable produces. a read that cannot answer holds as public (issue row 5).

## .the walked product

5 × 3 × 3 × 2 × 2 × 2 × 2 × 2 × 3 = 4,320 cells. they collapse:

- D2 private ≡ internal: both pass, with or without a promise (issue row 4)
- D3 wrong value: refused at arg parse, before any credential or gh call. one cell for every D1, D2, D4, D5, D7, D8, D9; D6 picks tree or json of the same refusal
- D3 given: the read is skipped (F5), so D2 and D9 collapse to "writes as today" — a D9 unusable then fails at the write as today, which this behavior does not change
- D5 no-op: passes ungated for every D2 × D3 × D9 (F4); commit.push has no no-op verdict
- D7 applies only to title.set, description.set, comment.set (`--from @stdin`) and commit.set (`-m @stdin`); push reads text from git. commit.set keeps a held `-m '<literal>'` too, so its rerun is `-m @stdin` either way (inventory row 30)
- D3 given, on commit.set: `--promise` repeats, so `is-netnew-behavior` and the text promise can both be given; each is checked where it is owed (inventory row 29)
- D8 changes the rerun line (it keeps `--auth as-human`) and which D9 state can fail; it does not change the verdict
- D9 unusable or unreachable × D3 absent: held as public, whatever D2 is — the sharp cell for a private repo (case=10)

what stays distinct is walked in the inventory, `1.vision.experience.case=_.md`.
