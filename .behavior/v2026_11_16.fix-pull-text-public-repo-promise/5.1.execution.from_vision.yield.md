# execution: pr text into a public repo needs an anonymized promise

## .blueprint

one leaf file holds the promise; one gate per skill family reads visibility under that family's own credential.

```
skills/git/git.promise.operations.sh          # leaf: the value, the visibility rule, the nudge, the rerun line, the keep path
  ├─ git.pull.comment.operations.sh            # comment family gate: set_repo_visibility + check_text_promise
  │    └─ comment.set · title.set · description.set
  └─ git.commit.operations.sh                  # push family gate: set_pr_repo_visibility + guard_push_text_promised
       └─ git.commit.push · git.commit.set --push
```

| skill | gate sits | read via | held text named |
|---|---|---|---|
| comment.set (new, edit, reply) | after the no-op verdict, before plan | `gh api repos/<o>/<n> --jq .visibility`, under `--auth` | the comment |
| title.set | same | same | the title |
| description.set | same | same | the description |
| git.commit.push | after the guards, before plan and before `git push` (F1) | `gh repo view --json nameWithOwner,visibility`, under `--auth` | the commit messages, which become the pr title and description |
| git.commit.set --push | before stage, commit, and quota spend (F6) | same as push; the push it composes gets the promise | same |

rules the gate holds:

- the promise skips the read (F5)
- private or internal passes; public or unreadable holds, exit 2, nudge on both streams (json: one object on stdout, nudge on stderr)
- unreadable names its cause; as-ehmpath with no keyrack token cannot read, so it holds (case=10)
- plan holds too (F3); a no-op passes (F4); reads and deletes are never gated
- one promise value only (F7); git.commit.set `--promise` repeats, so `is-netnew-behavior` and the text promise coexist
- every printed rerun keeps the promise: the nudge's own line, and push's keyrack and auth guides once a promise was given
