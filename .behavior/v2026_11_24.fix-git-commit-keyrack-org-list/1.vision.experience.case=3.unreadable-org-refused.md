# case=3 — an unreadable `org:` is refused with the shape it read

feel: sharp · care: critipath · cells: A.8, A.9, A.10

## narrative

a human hand-edits `.agent/keyrack.yml` and leaves `org: []`. a clone runs `git.commit.set`.

before: an empty value refused with `.agent/keyrack.yml#org required`, then told the human to run `git.commit.uses allow --org <org>`. that writes to the meter, not the keyrack file, so the remedy never helped.

after: the gate refuses, shows what it read, and points at the file:

```
🐢 bummer dude...

🐚 git.commit.set
   └─ ✋ ConstraintError: .agent/keyrack.yml org: lists no org
      ├─ read: org: []
      └─ org: must be one org, or a list of orgs

ask your human to name the org in .agent/keyrack.yml, e.g.:
  org: ehmpathy
  org: [ahbode, bhanya]
```

exit 2. no meter remedy prints, because the meter is not at fault.

a shape the gate cannot read (a nested map, a flow list across lines) refuses the same way; its `read:` line holds the raw lines. a list keyrack itself refuses (`[ahbode, @all]`, `[ahbode, ahbode]`) refuses here too, with keyrack's own words, so the gate and keyrack never disagree on one file. the gate never guesses an org from a shape it cannot read, so an odd shape never grants a run.

## bdd sketch

```
given a repo whose .agent/keyrack.yml declares org: []
  when [t0] git.commit.set --mode apply
    then exit 2
    then output names the shape read: org: []
    then output names the keyrack.yml remedy
    then output does not name git.commit.uses allow --org
given a repo whose .agent/keyrack.yml holds no org: key
  when [t1] git.commit.set --mode apply
    then exit 2, output: .agent/keyrack.yml org: absent, keyrack.yml remedy
given a repo whose .agent/keyrack.yml declares org: as a map ({ name: ahbode })
  when [t2] git.commit.set --mode apply
    then exit 2, output holds the raw lines read, no commit lands
    then output names the keyrack.yml remedy
    then output does not name git.commit.uses allow --org
given the repo from [t0], after the human writes org: ahbode, with ahbode allowed
  when [t3] git.commit.set --mode apply
    then the commit lands, exit 0 (the taught fix works)
```
