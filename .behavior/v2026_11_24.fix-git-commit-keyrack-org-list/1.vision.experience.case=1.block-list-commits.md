# case=1 — a block-list repo commits

feel: happy · care: critipath · cells: A.1, A.2

## narrative

a clone works in `ahbode/svc-quotes`. its keyrack reaches two orgs:

```yaml
org:
  - ahbode
  - bhanya
```

the human allowed both: `git.commit.uses allow --org ahbode`, `--org bhanya`. the clone runs `git.commit.set`.

before: the gate read `org:` as one line, found naught after the colon, and refused with `.agent/keyrack.yml#org required`. it told the clone to ask for `git.commit.uses allow --org <org>`. the human ran it; the next commit refused the same way.

after: the gate reads two members, checks each against the meter, and the commit lands. the clone never learns the gate exists.

## bdd sketch

```
given a repo whose .agent/keyrack.yml declares org as a block list [ahbode, bhanya]
  and the org meter allows ahbode and bhanya
  when [t0] git.commit.set --mode apply
    then the commit lands
    then exit 0
  when [t1] the same list is written in flow form: org: [ahbode, bhanya]
    then the commit lands, exit 0
```
