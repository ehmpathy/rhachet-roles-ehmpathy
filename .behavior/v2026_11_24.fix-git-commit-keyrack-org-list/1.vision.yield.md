# 1.vision — git.commit reads keyrack `org:` as a scalar or a list

## what this builds

one reader, `get_org_from_keyrack`, learns the three `org:` shapes keyrack accepts: a scalar, a block list, a one-line flow list. it returns every member. `check_org_blocker` gates on every member: each must allow. the first refusal stops the run and names its org. any other shape refuses with the lines it read, and never grants a run.

`git.commit.set`, `git.commit.push`, and `git.branch.uses` all call `check_org_blocker`, so one change fixes all three.

a keyrack-read refusal gets its own remedy, keyed off a named flag (`ORG_KEYRACK_FAULT`, a fault kind beside `ORG_BLOCK_CORRUPT`, so each kind takes its own note): fix `.agent/keyrack.yml`. the meter remedy (`git.commit.uses allow --org`) prints only when the meter refused. all three surfaces read the flag. `git.commit.set` (`:760`) and `git.branch.uses` (`git.branch.uses.operations.sh:380`) today print `allow --org <org>` for any org refusal. push (`git.commit.push.sh:321`) drops its string match on the reason.

a pack test asserts the published files carry 0644, or 0755 for skills. the 0555 seen at install comes from `rhachet roles link`; that fix goes to `ehmpathy/rhachet` (F2).

## why it works

- **one grammar, keyrack's.** keyrack casts `org:` to an allowlist; member 0 is the default (`asKeyrackManifestOrgs.js`, `loadManifestExplicit.js:38-43`). the gate reads the same list, so the gate and keyrack agree on one file.
- **every member gates (F1).** the list names every org whose keys the repo may reach. a human who blocks bhanya has blocked work that touches bhanya. any looser rule fails open.
- **closed grammar, fail closed (F3).** a shape outside scalar / block / flow refuses and prints the raw lines. keyrack's member rules (no sigil member, no repeat) refuse too. no guess ever becomes a grant.
- **the remedy matches the fault.** a keyrack fault names the file; a meter fault names the org to allow.

## the outcome world

before:

- block form `org:\n  - ahbode` reads as an empty org → `.agent/keyrack.yml#org required` → remedy `git.commit.uses allow --org <org>`, which writes the meter and changes naught. the clone loops.
- flow form `org: [ahbode, bhanya]` reads as one org named `[ahbode,bhanya]` (`git.commit.operations.sh:1976` strips spaces). no meter key matches, so the gate falls to `@all`. with `@all: allowed`, **a repo that lists a blocked org commits anyway**: a silent fail-open, worse than the wish's "reads as no org".
  - measured: a probe sourced `git.commit.operations.sh` against a meter of `ahbode: allowed, bhanya: blocked, @all: allowed`. flow form → `ORG_VALUE=[ahbode,bhanya]`, `check_org_blocker` returned allowed. block form → `.agent/keyrack.yml#org required`.

- a decorated scalar `org: 'ahbode'  # main` reads as `'ahbode'#main` (the same whitespace strip) and takes the same `@all` path. the wish does not name this shape; the new grammar fixes it too.

after:

- both list forms commit when every member allows (case 1)
- a blocked member refuses, exit 2, named, with its own allow command (case 2)
- empty, absent, or odd `org:` refuses, exit 2, shows the shape, names the file fix (case 3)
- all 72 local repos (every one scalar on origin/main) behave as before (case 4)

aha: the human blocks bhanya once, and every repo that touches bhanya stops, whatever form its keyrack takes.

## mental model

a human would say: "the commit gate reads the org list the way keyrack does, and every org on it must say yes."

analogy: a door with several locks. one key per lock, and any lock left shut keeps the door shut.

terms: humans say "org list"; the code says allowlist / members. the help text uses "org list" and "every listed org".

## evaluation

- goals: all six done-means items covered. the 0555 item lands as a clamp here and a fix upstream (F2).
- pros: one reader, three surfaces. closes a real fail-open. remedies now match the fault.
- cons: under F1 a list repo needs an allow per member, or `@all`. a valid yaml shape outside the grammar refuses (F3), though the refusal shows the fix.
- pit of success: unknown shape → refuse, never grant. blocked member → named, with a copy-paste allow. absent meter key → `@all` fallback per member, as today.

## open questions & assumptions

- [answered] F1: every listed org gates, or only the default org? every. the wish delegates the choice ("the gate rule … is chosen"), and safe-by-default decides it: a looser rule fails open on a blocked member. the wisher may overrule at approval; the rework is clean.
- [wisher] F2: is an upstream fix in `ehmpathy/rhachet` plus a pack clamp here enough for the 0555 item, or does the wisher want a local stopgap too?
- [answered] does keyrack accept both list forms? yes: zod `org: string | unknown[]`, cast by `asKeyrackManifestOrgs` (`rhachet/dist/access/daos/daoKeyrackRepoManifest/schema.js:21-24`).
- [answered] which order sets the default? member 0 (`loadManifestExplicit.js:43`). F1 checks every member, so order affects only which refusal shows first.
- [answered] other readers of `org:` in this repo? none; `grepsafe '\^org:' src` finds one, `git.commit.operations.sh:1976`.
- [answered] does the tarball ship 0555? no: non-role files install 0664, role files 0555, plain `.md` included (see F2).
- [answered] keyrack's member rules (`asKeyrackManifestOrgs.js:25-49`: no empty list, no `@all`/`@this` member, no repeats, scalar `@all` = grove scope) are mirrored in the gate. keyrack is not always there to enforce them: `--auth as-human` never unlocks keyrack, so a file keyrack refuses could reach the gate unchecked. read of `git.commit.uses.org.sh`: such members never grant beyond `@all` (`@this` reads unset → `@all`). safe either way, but a mirror keeps the gate and keyrack in agreement on every file.
- [answered] F3: parse in bash, or load a yaml lib? bash. `yaml` is a devDependency here (`package.json`), so a consumer install cannot load it, and no keyrack command emits the list (`invokeKeyrack.js` searched).
- [answered] F4: what does a scalar `org: '@all'` do? keyrack reads it as grove scope, a legal file (`asKeyrackManifestOrgs.js:19-21`). the gate keeps its extant read: the meter's `@all` verdict.
- [answered] does the upstream rhachet task go out now? it waits on F2's verdict. the dream holds the shape of the fix meanwhile.
- [research] does the 0555 persist via a pnpm store hardlink? a link-count read in verification confirms or drops the claim. the cause (rhachet's chmod) stands either way.

## what is awkward

- the remedy fix touches three callers beyond the reader (set, push, branch.uses), each with its own print. a fourth gated surface would have to learn the flag too.
- the wish's 0555 item reads as this package's fix, but the cause lives one repo over. this pr can only prove its own half.
- F1 makes a list repo strictly harder to enable than a scalar one. correct for a permission gate, but a first-time human may be surprised.
