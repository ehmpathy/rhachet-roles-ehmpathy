## 🔴 ✅ RULED — this case was REWRITTEN by the second council, 2026-09-09

## .the narrative

ulad is on his laptop. `git config` holds his own name and email — it has for years, and every
commit from this tree already names him correctly.

the wish keeps that ergonomic and changes exactly one point: it is now an **act**, not an
assumption. he runs one command, once per tree, and the value moves from a place the code merely
hopes is a human into a place a human deliberately put it.

⇒ **the whole delta is the explicitness.** the value can be identical. what changes is that a
record exists of a human's decision to use it — and that record is what a cloud grove cannot forge.

🔴 **and the source of that value is now his github session, never his git config.** the two hold
the same person on his laptop, so the ergonomic is unchanged — but only one of them is tied to an
act he performed (`gh auth login`) rather than to a file a provisioner could have written.

## .what makes it an alterpath

| term | value |
|---|---|
| frequency | every local tree — common |
| cost if it breaks | the human types `--who "Name <email>"` instead. **≈ 0** |
| workable fallback | ✅ `--who` reaches the identical outcome |

⇒ `freq × cost` ≈ 0 despite the high frequency. **alterpath** — demo is a bonus, not a debt
(`define.experience._.axis=care.path=criti-vs-alter`: *convenient ≠ criti*).

demoed anyway because it is the **local half of the grove split**, and a reviewer must be able to
read it beside `case=1` to see that the split is real.

## 🔴 .the pair this case forms with `case=1`

the two cases differ on **exactly one axis value** — `local` vs `cloud` — and that one difference
changes the command:

| | `case=6` (cell 3, local) | `case=1` (cell 4, cloud) |
|---|---|---|
| the bind | `--who @me` | `--who @stdin` |
| `--who @me` here | ✅ binds | 🔴 **refuses** — `case=1` `[t3]` |
| why | the host's github session **is** the human's | the host's github session is the **clone's** |
| measured | `F6`, `gh api user` under `as-human` | `F6`, `Q2′` — `{"login":"ehm-seaturtle"}` on this very host |

⇒ 🎯 **that is what makes axis D carry real weight.** it does not decide whether a commit names a
human (the bound sponsor decides that, on both groves). it decides **which value form resolves**.

⚠️ **the flag is the same on both rows** — one flag, `F10`. what the grove changes is the answer
`@me` gets, and it changes it as a matter of **fact** about how cloud groves are provisioned, never
as a rule the skill enforces.

## 🔴 the line this case must not cross

the wish's bound survives the seed's removal, and gets **stricter** rather than looser:

> ⛔ **no silent fallback to `git config`** — that fallback **is** the defect

| the bind IS | the bind IS NOT |
|---|---|
| a **command** a human types (`--who @me`) | a default the skill reaches for |
| run **once**, at bind | re-read at every commit |
| **guarded** by the robot check | trusted because the host looks local |
| a **snapshot** | a live pointer |
| ⛔ **never `git config`, on any grove** | ~~an explicit seed, on a local grove~~ — struck |

⇒ each row is one way the ergonomic could rot back into the defect. the fourth is the subtle one: a
bind that tracked its source would be the implicit fallback, merely renamed.

⚠️ **there is no grove-detect in the skill.** this case is titled "a local grove" for the narrative,
and the code never asks which grove it is on. what differs is the **answer** `gh api user` returns
— a human's login here, the clone's there — and `case=5`'s guard is what makes the cloud outcome
refuse. ⇒ the safety comes from the value check, never from a host guess.
