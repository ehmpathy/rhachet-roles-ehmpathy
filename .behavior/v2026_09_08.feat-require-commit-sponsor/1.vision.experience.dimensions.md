# 1.vision.experience.dimensions

## .what

the orthogonal axes the sponsor experience varies over, and their product.

the inventory walks this product: `1.vision.experience.case=_.md`.

## .the axes

### A. actor — who runs the command

| value | who | may bind? |
|---|---|---|
| `human` | a person at a tty | ✅ yes — is the authorization |
| `mechanic` | a clone at work on a tree, no tty | 🔴 never. must not sponsor itself |
| 🔴 `dispatcher` | a clone that **provisions** a tree, no tty | ⚠️ undecided — holds a human's **delegated** authority, granted before the tree existed |

🔴 **`dispatcher` was promoted to a value at peer review r1**, where it had been folded into a
single `clone` value and named only as a "latent axis". the reviewer's charge was exact: *"a real
path off an absent axis is a blocker."* ⇒ folded, the dispatcher's cells were mis-verdicted as
mechanic refusals, and **the box's coverage claim was contingent on a question it had deferred.**

**why a value on A, and not a fifth axis.** the natural instinct is a 5th axis
`has-delegated-authority? {yes, no}` — but `human × delegated=yes` and `human × delegated=no` are
the same experience, so that axis would be **non-orthogonal**, meaningful only for one value of A.
⇒ per `howto.dimensional-decomposition`, a value that only makes sense inside another axis
**belongs to that axis.** A grows to three values; the box stays a clean product.

**why closed at three.** the extant guards sort on a tty
(`git.commit.uses.global.sh:98`) plus a permission denylist
(`init.claude.permissions.jsonc:41-75`) — a two-way sort. 🔴 **`dispatcher` is the party those
guards cannot see:** it has no tty and holds permissions a mechanic lacks, so to every mechanism
this design uses it **is** a mechanic. ⇒ that invisibility is the whole of `F5`, and it is why the
value must be walked rather than assumed away.

### B. act — what the actor came to do

| value | command |
|---|---|
| `bind` | bind the sponsor |
| `read` | read the bound sponsor |
| `clear` | clear the bound sponsor |
| `commit` | `git.commit.set` — the consumer that reads the sponsor |

**why `commit` sits on this axis.** the sponsor is not a standalone feature. its whole point is
what `commit` does with it, so the consumer is an act of the same space.

### C. identity — the identity in play

| value | at `bind` | at `read` / `clear` / `commit` |
|---|---|---|
| `none` | no value offered | nothing bound |
| `human` | a real human offered | a real human bound |
| `robot` | 🔴 **any value that cannot answer for a change** — a bot (`seaturtle[bot]`, the clone's github session) **or a placeholder** (`Test User <test@example.com>`) | such a value bound |

one axis, one sense: **the identity in play at this act**. at `bind` it is the value offered; at
every other act it is the value on record.

### ⚠️ `robot` is the CLASS, and a placeholder is inside it — flagged at peer review r5

the reviewer's point was fair: `case=5` `[t2]` refuses a **placeholder**, which reads as a fourth
value with no cell of its own. ⇒ the axis is not incomplete; the **label was too narrow**.

⇒ 🎯 **the class this axis splits on is `F3`'s: *can this value answer for a change?*** a bot cannot
and a placeholder cannot, so both sit at `robot` and both are refused by the same guard, at the same
act, with the same exit code. ⇒ to give a placeholder its own value would split one guard across two
cells and claim a distinction the design does not make.

⚠️ **the honest cost of the label:** `robot` names one *instance* of the class where it should name
the class. a better word would be `unanswerable`, and the reason to keep `robot` is that it is the
word the wish, both seed issues, and every case file already use
(`rule.forbid.term.addition.synonym`). ⇒ the row above states the class explicitly so the narrow
name cannot mislead — and the wider label is a `2.1.criteria` rename candidate, not a vision-stage
churn.

### 🔴 `unreadable` — a FOURTH value on C, found at peer review i002

three lanes (`mech-failhides`, `arch-hazards-maintenance`, `arch-hazards-behavior`) raised one
defect this axis could not name: a sponsor state file that is **present and will not parse**.

| value | at `bind` | at `read` / `clear` / `commit` |
|---|---|---|
| 🔴 `unreadable` | ⚪ **not applicable** — a bind overwrites the file whole; no prior state is read | a value IS on record and cannot be recovered from it |

⚠️ **the axis was not merely incomplete; the gap PRODUCED the defect.** with only three values the
code had two branches, so a corrupt file fell into the `none` branch and the commit refused with
*"no sponsor is bound to this tree"* — a diagnosis that is false, and a remedy (bind one) that
loops forever on a file already bound. ⇒ the missed cell and the shipped failhide are one omission
seen twice.

**why a value on C, and not a fifth axis.** it varies exactly where C varies — it is a state of
*the identity in play* — and `human × unreadable` is not a state that can exist. ⇒ per
`howto.dimensional-decomposition`, a value that only makes sense inside another axis belongs to
that axis.

🟡 **it is PARTIALLY orthogonal, and that is stated rather than hidden.** `bind` has no prior state
to read, so `unreadable × bind` is ⚪ **impossible** across every A and D — 6 cells, closed by
construction. the value is live only at `read`, `clear`, and `commit`.

⇒ the cells and their verdicts are itemized in `case=_`; the two that are demoed are `[case45]`
(`commit`) and `[case11]` (`read`) in the integration suites.

### D. grove — where the tree lives

| value | what `git config` holds | what `gh api user` returns |
|---|---|---|
| `local` | the human's own identity | ✅ the human — their own `gh auth login` session |
| `cloud` | the clone's identity | 🔴 the clone — **no human session exists** (`Q2′`) |

**this axis carries the defect.** `git.commit.set.sh:586` reads `git config` and calls it a human.
that read is true on `local` and false on `cloud` — one line, two opposite meanings, decided by an
axis the code never names.

🔴 **the second column was added after the second council, and it is what keeps this axis alive.**
the design removes the `git config` read entirely (`F9`), so column 1 describes only the **defect**.
column 2 describes the **fix**, and it splits the same way — which is why `D` still governs the
`bind` act (`--who @me` vs `--who @stdin`) even after it goes inert at `commit`.

⚠️ **`D` decides a VALUE FORM, never a flag.** there is one flag (`F10`), and the skill runs no
grove-detect — what the grove changes is the answer `gh api user` gives, and `case=5`'s guard is
what turns a clone's answer into a refusal.

⇒ measured on this host, under the session a cloud tree actually carries:

```sh
$ gh api -X GET user --jq '{login, name}'
{"login":"ehm-seaturtle","name":"Seaturtle of'Ehmpathy"}
```

⚠️ **and note this is a second, independent n = 1** — the same limitation as the `git config`
measurement below, and the wisher's answer is what generalizes it, not the measurement.

✅ **the `cloud` value is derived, not assumed.** the code writes
`Co-authored-by: $HUMAN_NAME <$HUMAN_EMAIL>` straight from `git config` (`:586-587`, `:749`), and
the verified commit `ahbode/svc-jobs@a1635ea` carries
`Co-authored-by: Seaturtle of'Ehmpathy <259600029+ehm-seaturtle@users.noreply.github.com>`.
⇒ `git config` on that host **held a clone identity**. the axis is a measurement, not a premise
borrowed from the seed issue.

### 🔴 ⚠️ but the measurement is **n = 1**, and the design must not rest on it

one commit, on one host, at one time. it proves `git config` **can** hold a clone identity on a
cloud grove. it does **not** prove that every cloud grove does, nor that the cause is inherent to
cloud groves rather than one mis-provisioned host.

⇒ **the honest counter-hypothesis:** if that host's `git config` was simply set wrong, the cheaper
repair is to fix the provisioner so it writes the human who dispatched — and this whole feature is
unnecessary.

🔴 **the design does not depend on the answer, and that is the point.**

| premise | needed for the design? |
|---|---|
| a cloud grove's `git config` holds a clone | **no** — it establishes *urgency*, never the requirement |
| `git config` is not a record of authorization | ✅ **yes** — and this is true on **every** grove |

⇒ `case=6` already carries the claim that holds the weight: *"the whole delta is the
explicitness… a record exists of a human's decision"*. a `git config` a provisioner sets is **still
a guess** — correct by luck, silent when the provisioner is skipped, and indistinguishable from a
wrong one at read time.

⇒ so the counter-hypothesis, even if true, produces a **fix that fails the wish's own bound**
(*"⛔ no silent fallback to `git config`"*). the axis stays as **evidence of frequency**, and the
requirement stands without it.

⚠️ **what the n = 1 DOES bound:** any claim about *how often* this fires. `#645` reports six such
commits; the branch is deleted and unverifiable. ⇒ do not let a frequency estimate lean on this
axis — that is `F4`'s question, and it belongs to the wisher (`Q3`).

## .orthogonality

| pair | independent? | why |
|---|---|---|
| A × B | ✅ | **any** of the three actors may attempt any act; the guard decides the outcome, not the attempt |
| A × C | ✅ | a human may offer a robot identity; either clone may offer a human one |
| A × D | ✅ | **a human can sit on a cloud grove** — over ssh. that is how a cloud grove gets bound at all. ⚠️ and a `dispatcher` on a **local** grove is rare but real — a local task runner |
| B × C | ✅ | C reads as "the identity in play", one sense across every act |
| B × D | ✅ | every act runs on either grove |
| C × D | ✅ | either identity can be in play on either grove |

⚠️ **the A × D cell that tempts a forbidden-combination call:** `dispatcher × local`. it is thin,
not empty — a local cron or a task runner provisions trees on a laptop. ⇒ **kept live**, because a
forbidden combination must be an invariant the design *enforces*, never a case we find unlikely.

### ⚠️ the axis deliberately NOT walked — concurrency / time

`rule.require.dimensional-decomposition` names *"concurrency / time"* among the usual omissions,
so its absence is a declared call rather than an oversight. **raised at peer review r1.**

the sponsor's own writers are benign, and each for a stated reason:

| the race | outcome | why benign |
|---|---|---|
| two `bind`s | last writer wins | both writers are **humans at a tty** — the design's own authorization. either value is truthful |
| `bind` ‖ `commit` read | the commit reads the old or the new sponsor | both are validly-bound humans. the record is true either way |
| `clear` ‖ `commit` read | the commit may read a sponsor mid-removal | the sponsor **was** bound at read time. the record is true for that instant |

⇒ the sponsor state is **written only by a human, at a tty, one tree at a time.** that is not a
concurrent workload, and the axis would walk 3 values that all read "benign".

🔴 **but the walk found a real race one axis over, and it is EXTANT, not ours.** the quota meter
`git.commit.set` reads at `:511` and unconditionally overwrites at `:849-866` — a **read-modify-write
across 338 lines**, including a network push, with no lock:

```sh
USES=$(jq -r '.uses' "$STATE_FILE")     # :511
…                                        # ~338 lines, incl. `git push`
cat > "$STATE_FILE" << EOF               # :849 — unconditional overwrite
{ "uses": $NEW_USES, … }
```

⇒ two concurrent commits on one tree both read `uses: 2`, both write `uses: 1` — **two commits
spent, one decrement.** this design **inherits** that window (the sponsor guard sits at `:586`,
inside it) and does not widen it.

⇒ ⚠️ **out of scope, and caught rather than fixed.** the repair is a lock in `git.commit.set`, which
is neither safe nor clean to ride along in a vision stone that writes no code
(`rule.always.fix-forward-under-scouts-honor`). ⇒ dreamed at
`.dream/v2026_09_08.fix.git-commit-quota-read-modify-write-race.md`.

## .the product

🔴 `3 × 4 × 3 × 2` = **72 cells** — up from 48 when `dispatcher` joined axis A at peer review r1.
every one verdicted in `1.vision.experience.case=_.md`.

## 🔴 .what the walk surfaced

three findings a free-list would not have produced.

### 1. the refusal hands the clone the loaded gun

cell `clone × commit × none × cloud` refuses and prints the fix. cell `clone × bind × * × *` is the
clone running that exact fix on itself.

⇒ **the two cells are adjacent, and the first one's error text is the second one's recipe.** a
refusal that says *"run: `git.commit.sponsor set --who ...`"* invites the clone to self-sponsor —
the original defect, wearing the new skill's coat and looking fully authorized.

⇒ the refusal must address the **human**, not the reader: *"ask your human to run"*. that is a
pit-of-success demand the grid produced, not the wish.

### 2. the `robot` column propagates from forbidden to impossible

| act | verdict at `identity=robot` |
|---|---|
| `bind` | **forbidden** by nurture — attemptable, the bind refuses |
| `commit` | **unreachable by construction** — the state cannot exist, because bind refused it |

⇒ the bind guard carries the whole column. drop it and every cell flips from unreachable back to
reachable, which is exactly the defect restored.

⚠️ **this row read *"impossible by NATURE"* until peer review r4 caught it.** the inventory had
already been corrected to *"unreachable by construction"* and this file was not — the same
summary-drifts-from-body defect three earlier rounds caught, in the opposite direction.

⇒ 🔴 **and the word matters here more than most.** *by nature* claims the state cannot exist at all;
*by construction* says **this design's guard** is what prevents it. the second is true and the first
is false — a robot sponsor is perfectly possible in a world without the bind guard, which is
precisely the world the defect lives in.

### 3. the fix COLLAPSES the grove axis for `commit` — and CONCENTRATES it at `bind`

today `D` decides whether a commit names a human. under a bound sponsor it decides nothing —
`commit` reads the sponsor, and the sponsor is grove-agnostic.

⇒ **the grove axis is an artifact of the defect, at `commit`.** the measure of the fix is that `D`
stops mattering there.

🔴 **but it does not vanish — the wisher's `Q2′` decision moved its whole weight onto `bind`.** a
cloud grove as provisioned today carries no human `gh auth login` session, so the `@me` value form
does not hold there:

| grove | the bind form | `commit` |
|---|---|---|
| `local` | ✅ `--who @me` (or a supplied form) | 🟰 identical — reads the bound sponsor |
| `cloud` | 🔴 `--who @stdin` / `--who "…"` — the **supplied** forms | 🟰 identical — reads the bound sponsor |

⇒ ⚠️ **an earlier draft of this section confined `D`'s remaining weight to the one-time bind seed,
and a later council dropped that seed.** had `Q2′` not landed in the same round, the axis would have
collapsed entirely and this walk would have carried a dimension that decided naught.

⇒ 🎯 **the axis now carries load for a stronger reason than the seed ever gave it.** the seed made
grove decide whether a route was *advisable*; `Q2′` makes grove decide which form **holds**. that is
the difference between a preference and an invariant, and it is what `case=6` (local) and `case=1`
(cloud) now demonstrate as a matched pair.

⚠️ **and the split survived `F10` unchanged**, which is the check that it is real. the drive folded
two flags into one and the two rows above still differ — because what differs is the **supply**
(read from the host vs handed in), and a flag rename cannot touch that.

## 🔴 .the third actor — one who encounters the behavior and runs no command

⚠️ **axis A is derived from the GUARD's sort, not from `howto.experience.enumerate`'s question.**
the guard asks *"who ran this command?"* and answers `{human, clone}`. the method asks a wider
question — *"who **encounters** this behavior?"* — and that admits a party who runs no command in
this skill at all:

> **the trail reader** — whoever later opens the history and asks *"who authorized this change?"*

they never invoke `git.commit.sponsor`. they run `git log`, or open a pr, or audit a release. and
they are **the party the whole wish exists to serve** — a commit that names a human is worth
exactly what a later reader can learn from it.

⇒ they are not a value on axis A, because A is the actor **at the command**. they are a separate
row, enumerated here so the omission is a declared choice rather than an oversight.

| feel | the experience | care | where |
|---|---|---|---|
| happy | reads a commit, sees a human in the trailer — the question is answered | **criti** | ✅ demoed — `case=2` `[t2]` reads the trail back with `git log` |
| sharp | audits **across the cutover**: a pre-fix and a post-fix commit both carry a `Co-authored-by` trailer, and the trailer alone cannot tell a **bound sponsor** from an old **`git config` guess** | alter | 🟡 itemized — see below |

### 🟡 the sharp row, and why it is an alterpath

`ahbode/svc-jobs@a1635ea` carries `Co-authored-by: Seaturtle of'Ehmpathy <…>`. a post-fix commit
carries `Co-authored-by: Ulad Kasach <…>`. **same trailer key, same shape** — the record does not
say which one was authorized.

- **fallback:** the commit date against the cutover date. workable, if clumsy ⇒ **alterpath**, and
  an absent demo here is a **nitpick** (`rule.require.experience-coverage`).
- **why we do not add a marker:** a `Sponsored-by:` trailer or a signature would distinguish them,
  and it would also change the commit format for every downstream reader and tool. that is a far
  larger blast radius than the wish asks for, and the wish's bound is *"a rename with no repair is
  wrong"* — not *"add a new trailer"*.
- 🔴 **and the robot guard already bounds the damage forward:** after the cutover no robot can be
  bound, so every *new* commit's trailer is a human by construction. the ambiguity is confined to
  history, and history is exactly what a date can partition.

⇒ recorded rather than repaired. it is a genuine limit of a hard cutover (`F4`), and it belongs in
front of the wisher.

## 🔴 .the dispatcher row, WALKED

⚠️ this section previously said *"a fifth axis hides here … this vision does not resolve it"* and
stopped. **that was the blocker at peer review r1.** to *name* an axis is not to *walk* it, and the
box's "every cell verdicted" claim covered only the two actors it had enumerated.

⇒ walked now. 24 cells, `dispatcher × act × identity × grove`.

### what the design does today — and it is not "undecided"

🔴 **the design has no way to tell a dispatcher from a mechanic.** both lack a tty; the denylist is
harness config. ⇒ **every dispatcher cell resolves exactly as the mechanic's**, and that is a
verdict, not a deferral:

| act | cells | dispatcher's verdict | same as mechanic? |
|---|---|---|---|
| `bind` | 49–54 | **forbidden** — no tty, denylisted | ✅ identical |
| `read` | 55–58 | **allowed** · 59–60 impossible by construction | ✅ identical |
| `clear` | 61–64 | **forbidden** · 65–66 impossible by construction | ✅ identical |
| `commit` | 69–70 | **allowed** — a sponsor is bound · 71–72 impossible | ✅ identical |

⇒ **22 of the 24 cells are behaviorally identical to the mechanic's** and inherit their verdicts.
what is *not* identical is the **consequence** of cells **67–68**.

### 🔴 the two cells where the consequence diverges — `dispatcher × commit × none × {local,cloud}`

> cells **67, 68**. ⚠️ the prose once said *"the last four"*; the divergence is in **two** cells
> (`identity = none`), and cells 51–52 (`bind × human`) are demonstrated by the same case for a
> different reason — a dispatcher that offers a real human's name. corrected at peer review r2.

a mechanic refused at `commit` is the design at work: a human is nearby, reads the refusal, binds,
and the tree proceeds. **that is `case=3`, and it is correct.**

a **dispatcher** refused at `commit` meets a refusal whose remedy it cannot reach:

```
   ⛔ you cannot fix this yourself. a sponsor is bound by a human, at a tty.
   ask your human to run, in this tree:
     printf 'Name <email>' | rhx git.commit.sponsor set --who @stdin
```

⇒ 🔴 **there is no human at that tty, and there may be no human watching at all.** the tree was
provisioned by automation, for automation. the refusal is *correct*, *well-worded*, and **useless**
— it names a remedy no party present can perform.

| term | value |
|---|---|
| frequency | **every automated dispatch, from the cutover onward** |
| cost | the pipeline stalls at its first commit, and the message addresses an absent party |
| workable fallback | 🔴 **none** — that is what makes it a critipath, not an alterpath |

⇒ **critipath, and it owes a demo.** ✅ demonstrated at
[`case=8`](1.vision.experience.case=8.a-dispatcher-provisioned-tree-stalls.md).

### ⚠️ what the walk does NOT decide

**whether a dispatcher SHOULD be able to bind** stays the wisher's call — `F5`, `Q1`. the walk
changes what the wisher is asked to rule on:

| before the walk | after the walk |
|---|---|
| *"should we support dispatchers?"* — an abstract feature question | 🔴 *"automated dispatch stalls at its first commit. is that acceptable, or must it be bought back?"* |

⇒ **a cost, demonstrated, beats a question, deferred.** the ruling is still the wisher's; the
consequence of each answer is now on the table rather than behind it.

⇒ and `F3` inherits the same dependency: the human predicate is an **act** check (a tty), and a
dispatcher has no tty. ⇒ if a dispatcher may bind, the act check needs a second route.
