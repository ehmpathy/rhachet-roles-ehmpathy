## the diagnosis

this is NOT context overflow. after guard edits the scope sits at ~133k tokens (34% of the
1M window) — the reviews still crash blank, before scope computes. no
`.log/bhrain/review/` directory holds an entry since 2026-09-15, though 7 review rounds ran
since (i048 through i054). the process dies before it reaches its own log write.

`node_modules/rhachet-roles-bhrain/dist/contract/cli/review.js:380-386` catches only
`helpful_errors_1.BadRequestError` and rethrows all else, so an uncaught exception from a
dependency crashes node at exit 1 with no captured stdout — exactly the shape observed.

package.json on this branch carries an unreviewed dependency bump alongside the sponsor
feature work: `rhachet-roles-bhrain` 0.32.1 to 0.37.0, `rhachet-brains-fireworksai` 0.1.6
to 0.1.7 (both dated 2026-09-17, the same day this malfunction first appeared). all 4 broken
lanes use the DEFAULT_BRAIN `fireworks/deepseek/v4-flash` (no `--brain` override in the
guard). the 5 lanes that read as healthy (r3-r7) are `cached` from i047 — **they never
re-run under the new package versions**, so they are not proof the fireworks path still
works; they are simply untested against the regression.

`node_modules/rhachet-brains-fireworksai` genBrainAtom.js calls
`openai.chat.completions.create(...)` direct; any error the openai sdk throws there is not
a `helpful-errors` `BadRequestError`, so it propagates uncaught through the exact path
above.
