## .progress

### 🔴 what the build found that the vision could not

**1. the extant tty guard would REFUSE the paved cloud form.**

`git.commit.uses.local.sh:135` and `git.commit.uses.org.sh:131` both guard with:

```sh
if [[ ! -t 0 && "${__I_AM_HUMAN:-}" != "true" ]]; then   # stdin is a tty?
```

⇒ that is correct for `git.commit.uses`, which takes no piped input. it is **wrong here**: the
design's paved form for a dispatch is `printf 'Name <email>' | rhx git.commit.sponsor set --who
@stdin`, which makes stdin a **pipe** for the legitimate human case. a copied `-t 0` guard would
refuse `case=1` `[t0]` — the highest-care cell in the box.

⚠️ **and it would have looked correct**, because it is the extant pattern and every other value form
(`@me`, the literal) passes it. only the piped form fails, and only on the grove where it is the
**only** form that works.

⇒ **taken:** the guard reads **stderr, stdout, then stdin** — a human is present when *any* stream
is attached to a terminal. a clone under a tool harness has none of the three. the pipe consumes
stdin alone, so the other two still carry the signal.

⇒ 🎯 **this is the same defect class the wish exists to remove**: a check that reads a proxy which
happens to hold on the author's own grove. it is worth the record that the *fix* very nearly
re-committed it.

**2. `case=5` `[t0]` is not catchable by any identity predicate — `Q10` already proved it.**

the demo has a human, at a tty, on a cloud grove, run `--who @me`; the session resolves to
`Seaturtle of'Ehmpathy <259600029+ehm-seaturtle@users.noreply.github.com>` and the bind must refuse.

⇒ `Q10` measured three candidate predicates against **that exact account** and refuted all three —
the email domain (shared with a human), the derived noreply address (identical shape), and
`gh api user --jq .type` (reads `"User"`). **the clone owns an ordinary, human-shaped account.**

⇒ so the backstop as built catches two classes it genuinely *can* establish:

| class | what it reads | why it is a class, not a roster |
|---|---|---|
| robot | `[bot]` in the name/email · the clone identities `keyrack.operations.sh` already declares | `[bot]` is a marker **github mints**; the clone list is declared elsewhere and maintained there |
| placeholder | `test user` · `test human` · `your name` · `john/jane doe` · `@example.com`/`.org` | generalizes the two literals at `git.commit.set.sh:600` |

⇒ ⚠️ **neither catches `[t0]`.** the residual is real and it is **`F3`'s deferred predicate**, which
the vision routed to `2.1.criteria` and which no measurement has yet closed.

⇒ **what carries it in practice is the ACT guard**, exactly as `Q10` concluded: a clone cannot reach
a terminal, so it cannot bind itself. the uncaught case needs a **human** who runs `@me` on a cloud
grove — and that human sees the resolved name echoed in the success tree, so a wrong bind is
**visible and `del`-able** rather than silent.

⇒ 🔴 **itemized as a fulcrum, not halted on** — the rework is a predicate swap inside one function
(`is_identity_robot`), so it is **clean**. see `F11`.

**4. 🔴 two defects a self-review caught that the green suite did not.**

both were in the `--who @me` / `@stdin` paths, which the suite exercises least — `@me` needs a real
`gh` session, so no test drives it end to end.

| # | the defect | why the suite missed it |
|---|---|---|
| **a** | the `@me` resolver called `exit 2` and `emit_both` **inside `$( )`**. the `exit` ends the SUBSHELL, and the stdout half of the error is **captured into the variable** rather than shown ⇒ the human sees the failure on **stderr only** | no test drives `@me`; and the exit code stays 2 either way, so a coarse assert would pass |
| **b** | `--who @stdin` at a terminal with no pipe runs `cat` on a tty ⇒ **hangs forever** | the harness always pipes stdin, so the tty branch is unreachable in test |

⇒ **(a) is a silent `rule.require.skill-output-streams` breach**, and the shape is worth the record:
**an error emitted inside a command substitution is half-swallowed by construction.** the repair is
structural rather than a patch — the gh calls and their refusals moved into the main flow, and what
stays inside `$( )` is a **pure transformer** that emits only the identity and never an error.

⇒ **(b) is worse than an error**, because a hang reports naught at all. guarded with `[[ -t 0 ]]`.

⚠️ 🔴 **note the symmetry with finding #1, and it is not a coincidence: this skill's hardest edges
are all about WHICH STREAM IS A TTY.** #1 was a guard that read the wrong stream; (b) is a value form
that assumes the right one. ⇒ a candidate invariant for `2.1.criteria`: **every path that reads or
guards a std stream states which stream and why.**

### the trap that ate the exit code

r006's repair for `get_gh_user_session` added `trap 'rm -f "$err_file"' EXIT` to close a
SIGINT/SIGTERM leak window the plain `rm -f` at the end of the function cannot reach. landing it
alone broke 9 of `[case9]`'s tests: every `expect(result.exitCode).toBe(2)` received `1`.

root cause: this file runs under `set -u`. `err_file` is `local` to `get_gh_user_session` — once
the function returns, that binding is gone. the trap string is single-quoted, so `$err_file`
expands at fire time, not at `trap` time. when `refuse_set` later calls `exit 2`, the EXIT trap
fires with `err_file` unbound; under `set -u` that read aborts the trap's `rm -f` command before
it runs, and bash reports the true exit code as the trap's own (nonzero) status rather than the
`2` that `exit` had set — silently rewriting a constraint refusal into a malfunction code.

fix: `trap 'rm -f "${err_file:-}"' EXIT` — the `:-` default makes a late, out-of-scope read expand
to an empty string instead of erroring, so `rm -f ""` runs as a no-op and the true exit code
survives. mid-flight (a signal while still inside the function) still expands `$err_file`
correctly, since the local binding is live on the call stack at that point — only the deferred,
post-return fire path needed the guard.

no new test was written: `[case9][t0]`'s prior `expect(result.exitCode).toBe(2)` already fails
under the bug and passes under the fix — it clamped the defect it was written for, and this defect
too, with no modification. re-ran the sponsor suite (111/111), the full `git.commit` suite
(440/440), types, format, and lint — all green.
