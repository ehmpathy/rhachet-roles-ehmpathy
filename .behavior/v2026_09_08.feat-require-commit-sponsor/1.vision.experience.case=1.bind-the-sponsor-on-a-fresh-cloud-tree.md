# case=1 — bind the sponsor on a fresh cloud tree

> cell **4** · `human × bind × human × cloud` · feel **happy** · care **critipath**

🔴 **the `[tn]` renders below are the SHIPPED renders, copied from the pinned snapshots**
(`git.commit.sponsor.integration.test.ts.snap`, `git.commit.uses.integration.test.ts.snap`). they
were sketches at vision time; verification re-rendered them so the contract and the code teach one
mental model rather than two (`rule.forbid.snapshot-visual-blemishes`).

## .the narrative

ulad opens a cloud grove and dispatches a tree for a fix in `svc-jobs`. he already grants the
commit quota there — that is the moment he authorizes the work. one more line in the same breath
names the human who answers for the change.

he does not type an email and he does not look up a format. he reads the requester's identity on
the machine he dispatched from and **pipes it in** — `--who @stdin`, which matches the extant
`-m @stdin` pattern (`git.commit.set.sh`) and keeps a person's name out of shell history.

the tree comes up. the mechanic commits. the trailer names the human who asked.

🔴 **and `--who @me` does not resolve here.** ⇒ see the ruled section below: a cloud grove as
provisioned today carries no human `gh auth login` session, so the value form that reads one would
name the **clone**.

⇒ **the sponsor rides beside the quota, in the same breath.** that placement is the whole
ergonomic: authorization already happens here, so the sponsor costs no new *moment* — only a new
*line*.

🔴 **and that sentence is a correction.** this case read *"the human owes one line and no more"*
until self-review r2 caught that the contract costs **two commands** — `uses set`, then
`sponsor set`. one breath, two lines.

⇒ the claim is now stated honestly rather than aspirationally, and the gap was a fulcrum: **`F8`** —
deliver the one-line act with a `--sponsor` flag on `git.commit.uses`, or keep the separate skill
and its two lines?

✅ **the wisher ruled `Q6` on 2026-09-09: one MOMENT is enough.** ⇒ the separate skill stands, no
`--sponsor` flag is added, and the nudge at `[t0]` is promoted from a nicety to a **required
behavior** — it is the whole reason two lines are acceptable. `F8`.

## .the bdd sketch

**[t0] the supervisor grants the quota — and the grant NUDGES**

```sh
$ rhx git.commit.uses set --quant 5 --push allow
🐢 radical! let's ride!

🐚 git.commit.uses set
   ├─ granted: 5
   ├─ push: allowed
   └─ stage: blocked

🥥 did you know?
   ├─ no sponsor is bound to this tree, so commits will refuse
   ├─ printf 'Name <email>' | rhx git.commit.sponsor set --who @stdin
   ├─ rhx git.commit.sponsor set --who "Name <email>"
   └─ rhx git.commit.sponsor set --who @me   # reserve for YOUR OWN work
```

then: 🔴 **the nudge fires only when no sponsor is bound** — it is discoverability at the one
moment a human is provably present and already in the act of authorization
(`rule.require.discoverability`: *"a step a human cannot find is a step a human cannot take"*)

then: ✅ it is a **coconut, not an error** — the grant still succeeds, exit **0**. the sponsor is

then: ⚠️ the nudge is a **prompt, never a guarantee** — a human may ignore it, and then `case=3`'s
refusal is the backstop. that ordering is deliberate: nudge at the human's moment, refuse at the
clone's

**[t1] the supervisor binds the sponsor — piped from the machine they dispatched from**

```sh
🐚 git.commit.sponsor set
```

then: the sponsor is on record, and it is a human

**[t3] the supervisor reaches for `--who @me`, and the bind REFUSES**

```sh
$ rhx git.commit.sponsor set --who @me
🐢 bummer dude...

     Seaturtle of'Ehmpathy <259600029+ehm-seaturtle@users.noreply.github.com>

  $ printf 'Name <email>' | rhx git.commit.sponsor set --who @stdin
```

then: exit code **2** — a constraint, and the human can fix it

then: ⚠️ it prints **what it found**, so the human can tell "no session at all" from "the wrong

then: 🎯 **and note WHICH guard fires.** a real human is at a real tty here, so `F3`'s **act check

### ✅ RULED — `@me` resolves only where YOUR OWN session is

**the wisher ruled `Q2′` on 2026-09-09: a cloud grove as provisioned today carries no human
`gh auth login` session.**

⇒ measured on this very host, under the session a cloud tree actually has:

```sh
$ gh api -X GET user --jq '{login, name}'
{"login":"ehm-seaturtle","name":"Seaturtle of'Ehmpathy"}
```

🔴 **the clone.** so `[t1]` previously named that session and was **wrong on the critipath** — this
case is cell 4, the highest-care happy cell in the box, and its paved command named a robot.

⇒ `[t1]` now pipes; `[t3]` demos the refusal that keeps the wrong path shut. **`F6`.**

⚠️ **and the claim is about the VALUE, never the grove.** *"`@me` is local-only"* over-claims: the
skill runs no grove-detect (`[t4]`, `case=5`), so a human who ssh'd in **with their own
`gh auth login`** would pass. `Q2′` is a fact about how cloud groves are provisioned today, not a
rule the skill enforces. ⇒ the same error class as *"impossible by nature"*, caught at `F10`.

### ✅ RULED — the sponsor is the REQUESTER, not the supervisor

**the wisher ruled `Q8` on 2026-09-09.** this `[tn]` previously read *"a supervisor can sponsor on
behalf of the human who actually asked for the work"* — which **implied** the requester and decided
none of it. self-review r3 caught that (assumption **H2**) and escalated it, because `case=1`'s
cast had one person in both roles, so a question about two people had nowhere to appear.

⇒ the decision, and the term's own evidence is what settles it: **a sponsor answers for the
change.** that is the requester's relation to it. the supervisor's relation is to the **budget** —
which the quota meter already records, in a different mechanism, for a different question.

🔴 **so `--who @me` is NOT the paved value form for a dispatch.** the moment a supervisor acts for
someone else, `@me` names the wrong human — **truthfully**, which is exactly what makes the error
hard to see. a reader of that trailer learns who paid, where the record should say who asked.

⚠️ **and the three value forms are not interchangeable defaults.** the choice among them is a domain
call rather than an ergonomic one:

| the binder is | the value form | names |
|---|---|---|
| a human who sponsors **their own** work | `--who @me` | themself. the common case |
| a supervisor who dispatches **someone else's** ask | `--who @stdin` / `--who "…"` | 🔴 the **requester** |

⇒ 🎯 **one flag, and the VALUE carries the domain call** (`F10`). two flags asserted a distinction
that is not there — both answer *who is the requester?*, and only their supply route differs.

### 🔴 the mechanism the wisher named — and why it makes `@stdin` a requirement

> *"the supervisor should know to grab it from the machine they dispatched from and pipe it in"*

⇒ the requester's identity is **already on the supervisor's own machine** at dispatch time. so the
supervisor reads it there and pipes it into the bind — no hand-typed email, and the `@me` ergonomic
survives for the case it actually fits.

⇒ ⚠️ **`@stdin` is a contract requirement rather than a convenience**: a human's name and email in
`--who "…"` lands in shell history and in the process arg list, which is the same PII the push
skill already strips from pr bodies (`get_clean_pr_body in git.commit.push.sh`). ⇒ raised for `2.1.criteria`.

## .what makes it a critipath

| term | value |
|---|---|
| frequency | every cloud tree dispatch |
| cost if it breaks | the tree cannot commit at all; the work stalls until a human intervenes |
| workable fallback | **none** — no other act binds a sponsor, and no commit proceeds without one |

⇒ `freq × cost` intolerable. **critipath.**

## .the pit of success it must build

- **`--who @stdin` is the paved default HERE.** if the cloud case needs a hand-typed email,
  supervisors will skip the step or paste the wrong address — so the pipe must be the form the
  nudge prints and the form `--help` leads with.
- **the source is named in the output.** `source: supplied` tells the human the value was handed
  in rather than read off this host, so a wrong value is visible at bind time, not at commit time.
- 🔴 **a wrong-session `--who @me` refuses; it never degrades.** `[t3]`. a fallback is the defect.
- 🔴 **the refusal names the other two forms**, so `--who "literal"` is reachable from an error a
  human actually meets — `--help` is not the only place the set is enumerated.
- ⛔ **the source is never the tree's `git config`** — on any grove. `F9` struck the seed outright.
- ⛔ **and never the keyrack owner** — see below.

## 🔴 .the source, and the one that was refuted

an earlier draft read the `@me` form from the **keyrack owner**. self-review checked it and
**refuted** it:

```
$ rhx keyrack --help
  --owner <owner>     owner identity (e.g., mechanic, foreman)
```

⇒ `--owner` names a **role**, not a human, and `.agent/keyrack.yml` holds only `org` + `env` +
credential key names. a sponsor read from there would be `mechanic` — **the clone**. the defect,
from a third direction.

⇒ the source is `gh api user` under `--auth as-human`, which is tied to a human's own login and
already reachable here (the `as-human` branch in `git.commit.push.sh`, which strips any ambient
`GH_TOKEN` so gh uses the human's own session). fulcrum `F6`.

### ✅ and the `null` email is settled too — the address is DERIVED

an earlier draft flagged this as unverified: github returns `.email: null` for a private-email
account, which this org uses. **measured at self-review r4:**

```sh
$ gh api -X GET user --jq '(.id|tostring) + "+" + .login + "@users.noreply.github.com"'
"259600029+ehm-seaturtle@users.noreply.github.com"
```

⇒ 🎯 **byte-for-byte the co-author trailer on the defective commit `a1635ea`.** so `@me` reads
`.name` plus a **derived** noreply address, never `.email`, and the predicted degradation to a
supplied value was not needed.

⚠️ **it refuses for a different reason instead** — the session is the clone's on a cloud grove
(`Q2′`, `[t3]`). ⇒ the form survives; **where it resolves** narrowed, never its field access.
