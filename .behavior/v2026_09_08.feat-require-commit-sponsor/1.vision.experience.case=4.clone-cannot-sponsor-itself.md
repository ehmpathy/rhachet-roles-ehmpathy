# case=4 — a clone cannot bind a sponsor, for itself or for anyone

> cells **9, 10** · `clone × bind × human × {local, cloud}` · feel **sharp** · care **critipath**
> **forbidden** by nurture — the clone may attempt it; the behavior must refuse

🔴 **the `[tn]` renders below are the SHIPPED renders**, copied from
`git.commit.sponsor.integration.test.ts.snap`. they were sketches at vision time; verification
re-rendered them so the contract and the code teach one mental model
(`rule.forbid.snapshot-visual-blemishes`).

## .the narrative

the mechanic hits `case=3`. the refusal names a command. the mechanic is a competent agent that
runs commands, and it wants to unblock itself.

so it runs the command.

⇒ 🔴 **this is the cell the free-list misses.** the sponsor skill's own error message is a recipe,
and the reader of that message is the exact party who must not follow it. a design that ships the
skill without this guard has moved the defect one hop, into a mechanism that *reads* as an
authorization.

and there are two shapes of the attempt, both refused:

| the clone offers | what it is |
|---|---|
| its own identity | **self-sponsorship** — the original defect, with a new name |
| a human's identity it read from a file | 🔴 **fabrication** — worse, because it produces a plausible record |

the second is the one `#646` documents: a human, asked to let a clone write their name into a
co-author line, **refused, correctly**. a clone that supplies a human's attribution on their behalf
is exactly the invention the co-author guard exists to stop. the sponsor skill must not become the
loophole that guard closed.

## .the bdd sketch

```
given [case4] a tree with no sponsor bound
  and the actor is a mechanic (no tty, permission-denied)
```

**[t0] the clone offers a human identity it read somewhere**

```sh
$ rhx git.commit.sponsor set --who "Ada Lovelace <ada@example.com>"
🐢 bummer dude...

🐚 git.commit.sponsor set
   └─ error: only humans can run this command

   a sponsor answers for a change in the real world, so only a
   human can bind or clear one.

   this holds even for a real human's name. to name a human who
   did not act is a fabrication, and it reads as authorized.

ask your human to run, in this tree:
  $ printf 'Name <email>' | rhx git.commit.sponsor set --who @stdin
  $ rhx git.commit.sponsor set --who "Name <email>"
```

then: exit code **2**
then: no value was written to the sponsor state
then: 🔴 the refusal explains **why a value that reads correct is still wrong** — else the clone
concludes it merely used the wrong name and retries with a better one
then: ✅ the printed commands are the **supplied** value forms, which hold on every grove — the rule
`case=3` states, and this refusal is read by the same audience under the same uncertainty

**[t1] the clone offers the identity the host carries**

```sh
$ rhx git.commit.sponsor set --who @me
🐢 bummer dude...

🐚 git.commit.sponsor set
   └─ error: only humans can run this command
   ... (the same body and remedy as [t0] — ONE headline serves both value forms)
```

then: refused at the **actor** guard, before the identity is even inspected
then: were the actor guard absent, the **identity** guard would catch it — `case=5`
then: two nets, and cell 12 is why both exist
then: ⚠️ **this `[tn]` used to run `--from git-config`, which `F9` struck.** the substitution is
exact rather than cosmetic: on a cloud grove `--who @me` reads the clone's own github session, so
this is still *"the clone offers itself"* — the same act, through the form that survived
then: 🔴 **and the actor guard fires whatever the value form.** `@me`, `@stdin`, and a literal all
land at one guard, so `F10`'s single flag removed a surface and left this cell's outcome intact

**[t2] the clone tries to clear an extant sponsor, then rebind**

```sh
$ rhx git.commit.sponsor del
🐢 bummer dude...

🐚 git.commit.sponsor del
   └─ error: only humans can run this command

   a sponsor answers for a change in the real world, so only a
   human can bind or clear one.

ask your human to run, in this tree:
  $ rhx git.commit.sponsor del
```

then: 🔴 `clear` carries the identical guard. a permissive clear is a permissive bind with one
extra step (inventory rows 33–34)

then: 🔴 **ONE headline serves both verbs** — `only humans can run this command`. an earlier draft
here rendered a per-verb headline (`only a human can bind a sponsor` / `... mutate the sponsor`),
which taught two error copies where the skill ships one

then: ⚠️ **the REMEDY branches, though.** a refused `del` prints `del`, never the bind commands — a
refusal whose fix does the opposite of the act it refused is worse than no fix
(`rule.require.errors-name-the-fix`)

then: 🔴 **and the fabrication paragraph is ABSENT here**, on purpose. it answers *"why is a better
name still wrong?"*, and a refused `del` offered no name to better. clamped by an explicit
`not.toContain` on this arm

**[t3] the clone reads the sponsor**

```sh
$ rhx git.commit.sponsor get
🐢 lets check the sponsor...

🐚 git.commit.sponsor
   └─ sponsor: (none)

🥥 did you know?
   ├─ a human binds this tree's sponsor
   ├─ printf 'Name <email>' | rhx git.commit.sponsor set --who @stdin
   └─ rhx git.commit.sponsor set --who "Name <email>"
```

then: **allowed.** read is not a mutation, and the clone needs it to explain its own state
then: `get` is the one act on this skill with no actor guard
then: ✅ the `(none)` form follows the extant absent-value render —
`"   └─ level: (none — will nudge on feat commits)"` (`git.commit.bind.sh:192`)

then: 🔴 **the next move rides a 🥥, never a mandatory block** — a read that found no sponsor is not
a refusal, and `rule.require.coconut-hints` grades a coconut with mandatory load a blocker. the
mark is the one cue that parts this OPTIONAL list from the near-identical MANDATORY list `[t0]`
prints

then: ⚠️ **and it reads `a human binds this tree's sponsor`, not `ask your human to…`** — `get`
carries no actor guard, so a **human** reads this line as often as a clone does, and an imperative
addressed to "your human" would command the very reader it names

## .what makes it a critipath

| term | value |
|---|---|
| frequency | 🔴 **every time a clone reads the `case=3` refusal** — the message invites the attempt |
| cost | a self-bound sponsor is the defect restored, now with a mechanism that vouches for it |
| workable fallback | **none** — if this guard leaks, every other guard in the design is decoration |

⇒ **critipath.** the frequency term is the surprise: this is not a rare adversarial poke, it is the
natural next move of a competent agent that just read an error.

## .the sharp-path bar — fail fast, fail loud, teach the fix

| the bar | this refusal |
|---|---|
| **fast** | refused at the **actor** guard, before the identity is read and before any write. ⇒ the refused bind leaves no state — `case=7` `[t3]` depends on it |
| **loud** | exit **2**, a `print_tree_error` line, never a silent no-op |
| **teaches the fix** | *"ask your human to run, in this tree:"* + both grove-agnostic commands |
| 🔴 **teaches the WHY** | ✅ **shipped** — *"this holds even for a real human's name. to name a human who did not act is a fabrication, and it reads as authorized."* without it the clone concludes it merely picked a bad value and retries with a better one, so a refusal that teaches the wrong lesson fails **open** on the second attempt |

⇒ the fourth row is the one a generic error would miss. the other three are the standard bar; this
one is specific to a reader that can reason about its own rejection.

## .the two guards, and why both

| guard | mechanism | already paved at |
|---|---|---|
| **permission denylist** | the clone's harness refuses to dispatch `sponsor set` / `del` | `init.claude.permissions.jsonc:41-75` (`git.commit.uses set`, `git.commit.bind set`) |
| **tty check** | the skill itself refuses without a tty | `git.commit.uses.global.sh:98` |

neither alone suffices:

- the denylist is **harness config** — a tree with a stale or absent permission file has no guard
- the tty check is **in the skill** — it travels with the code, but a tty can exist in odd contexts
  (a pty-wrapped agent)

⇒ defense in depth, and both are extant patterns rather than new invention.

## 🔴 .the THIRD guard — the state file, not the command

⚠️ **surfaced at self-review r4.** the two guards above both sit on the **command**. a clone that
never runs the command can still reach the state:

```
Write(.meter/git.commit.sponsor.jsonc)   ← a plain file write. no skill invoked, no tty consulted
```

✅ **the pattern already exists and already covers it** — `init.claude.permissions.jsonc:15-18`
denies `Edit(.meter/*)` and `Write(.meter/*)`, with a comment that states the exact rule this
design needs, one concept over: **the meter state must be modified by humans only**, so the
mechanic cannot widen its own quota.

⇒ the sponsor is that same class of state, and it earns the same treatment.

🔴 **but the protection is LOCATION-BOUND, and the glob is a single star.**

| state path | covered by an extant deny? |
|---|---|
| `.meter/git.commit.sponsor.jsonc` | ✅ yes — `Write(.meter/*)` |
| `.branch/.bind/git.commit.sponsor` | ✅ yes — `Write(.branch/.bind/*)` |
| 🔴 `.meter/sponsor/state.jsonc` | **no** — `*` does not cross a `/` |
| 🔴 `.branch/.sponsor/…` | **no** — only `.bind` is named |

⇒ **a design that picks a "tidier" nested path silently loses the guard.** the file would be
untracked, human-only by intent, and writable by the clone — and no test would catch it, because
the skill's own guards all still pass.

⇒ **invariant for `2.1.criteria`: the sponsor state lives FLAT inside an extant denied
directory** — `.meter/` — or the deny list gains an entry in the same change. this is not a free
choice of file layout; it is the third guard.

## ⚠️ the latent axis this case exposes

a **dispatcher** that provisions cloud trees is not a human and has no tty — so this guard refuses
it, and automated dispatch stalls at the first commit.

that party holds **delegated authority**, granted by a human before the tree existed. it is neither
the mechanic this case forbids nor the human `case=1` assumes.

✅ **RULED — `Q1`, 2026-09-09: no automated dispatch exists, so a dispatcher cannot bind** (`F5`).
⇒ the guard stands as written, and `case=8` prices the stall at frequency **zero today**. the
re-open trigger is the first party with no tty that needs to commit.
