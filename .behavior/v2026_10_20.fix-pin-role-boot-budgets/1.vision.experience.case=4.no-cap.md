# case 4 — `c4` + `c5`: two doors to an uncapped boot

## narrative — door `c4`
an author, annoyed by a red build, deletes the `budget:` block from mechanic's boot.yml. they
run `npm run build` and it goes green — `repo introspect` skips a role with no declared budget
(`assertRegistryWithinBudget.js:64`). that green is the trap. then the budget test runs, locally
or on the pr, and `it declares a budget` fails for both views
(`expect(cost.budget).not.toBeNull()`). the pr reads red; the merge is refused; no consumer
boots `unlimited budget`.

## narrative — door `c5`
an author registers ecologist in `getRoleRegistry.ts` and never writes it a boot.yml, so it
would boot every brief it holds. the build goes green — introspect finds no spec to cap. the
budget test's `[case0]` fails and names the slug: `Expected: [] · Received: ["ecologist"]`. the
author writes a boot.yml with a pin; until then, the pr reads red.

## bdd
- given a registered role whose boot.yml declares no `budget:` (`c4`)
  - `[t0]` local, when `npm run build` runs → then introspect passes (blind by design)
  - `[t1]` local, when the budget test runs → then `it declares a budget` fails
  - `[t1b]` local, when the author runs `roles boot` → then the stats block carries no budget line
  - `[t2]` pr, when ci runs → then step `repo introspect` passes and the integration job reads red
  - `[t3]` published → forbidden; the red pr never merges
- given a role registered with no boot spec (`c5`)
  - `[t4]` local, when `npm run build` runs → then introspect passes (no spec to cap)
  - `[t5]` local, when the budget test runs → then `[case0]` fails and names the slug
  - `[t6]` pr, when ci runs → then step `repo introspect` passes and the integration job reads red
  - `[t7]` published → forbidden; the red pr never merges
