# experience dimensions

## the axes

| axis | values |
|---|---|
| **change** — what a diff does to a role's boot cap, or to the report that measures it | `c1` hold (edit within pin) · `c2` grow past pin · `c3` grow past pin + raise pin in the same diff · `c4` remove `budget:` · `c5` register a role with no boot spec · `c6` bump rhachet so the `roles cost` report shape drifts |
| **checkpoint** — where, and by whom, the cap is met | `local·test` · `local·introspect` · `local·boot` (author, in their tree) · `pr·test` · `pr·introspect` (ci; a reviewer reads the diff) · `published·boot` (a consumer) |

## the latent dimension, surfaced

stage (local, pr, published) and gate (test, introspect, boot) are not orthogonal: consumers
run no test, ci runs no boot. the dimension under that correlation is **side**:

- **source side** (author + ci) *grades* the cap — `test`, `introspect` can go red — and an
  author can also *display* it via a local `roles boot`
- **consumer side** only *displays* it — `roles boot` shows the stats block and warns on a linked
  spec over budget; it never refuses

each real (stage, check) pair is now one value of `checkpoint`, so the grid holds no impossible
cell. `local·boot` — an author who boots their own role and reads `budget = N / pin` — joins the
walk; it was the cell the split hid.

## orthogonality

- **change ⟂ checkpoint**: every change reaches every checkpoint; the verdict varies per pair
  (e.g. `c4` is red at `local·test`, green at `local·introspect`, and shows no budget line at
  `local·boot`), which is why all six are walked.
- **actor folds into checkpoint**: author ↔ `local·*`, ci + reviewer ↔ `pr·*`, consumer ↔
  `published·boot`. one-to-one, so not a separate axis.
- **role is not an axis; headroom is a coordinate of the change.** the same diff is `c1` for
  mechanic (662 tokens of room) and `c2` for ergonomist (157). recorded as an itemized `c2`
  instance in the inventory, not a seventh column.

## the walk

6 changes × 6 checkpoints = 36 cells, every one verdicted in `1.vision.experience.case=_.md`.
