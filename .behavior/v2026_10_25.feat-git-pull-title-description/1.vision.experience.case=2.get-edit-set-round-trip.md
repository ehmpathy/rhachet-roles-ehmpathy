# case 2 — get-edit-set-round-trip · happy · critipath

**narrative**

a reviewer asks the driver to note a known limit in the pull body. the driver reads the
current body with `rhx git.pull.description get`, appends a `## .limits` section, and sets it
back. the body it read already ends in the seaturtle line — `git.commit.push` put it there. the
set strips the old attribution and appends one fresh. after each such edit, the pull still
ends in exactly one seaturtle line, never a stack of them.

critipath: get → edit → set is how a driver updates a pull it already opened. if the round trip
stacked attributions, every edit would scar the body, and the only cure would be a human edit.

**bdd `[tn]` timeline**

```
given pull #812 whose body ends in "---\n🐢🌊 surfed in by seaturtle[bot]"
  when [t0] the driver runs `rhx git.pull.description get`
    then it sees the body of #812, attribution included, on stdout
  when [t1] the driver appends a "## .limits" section and runs
           `cat body.md | rhx git.pull.description set --from @stdin --mode apply`
    then pull #812's body holds the new section
    and  the body ends in exactly one seaturtle attribution
  when [t2] the driver re-runs [t1] unchanged
    then the output reports the body as unchanged
    and  the body still ends in exactly one seaturtle attribution
```
