# case 2 — get-edit-set-round-trip · happy · critipath

**narrative**

a reviewer asks the driver to note a known limit in the pull body. the driver writes the
current body to a file with `rhx git.pull.description get --to ./.temp/body.md`, appends a
`## .limits` section, and sets it back with `--from ./.temp/body.md`. the body rides a file, never
stdout: through `rhx`, stdout opens with rhachet's own header, so a redirect would publish that
header into the pull. the body it read already ends in the seaturtle line — `git.commit.push` put
it there. the set strips the old attribution and appends one fresh. after each such edit, the pull
still ends in exactly one seaturtle line, never a stack of them.

critipath: get → edit → set is how a driver updates a pull it already opened. if the round trip
stacked attributions, every edit would scar the body, and the only cure would be a human edit.

**bdd `[tn]` timeline**

```
given pull #812 whose body ends in "---\n🐢🌊 surfed in by seaturtle[bot]"
  when [t0] the driver runs `rhx git.pull.description get --to ./.temp/body.md`
    then ./.temp/body.md holds the bare body of #812, attribution included, and no rhachet header
    and  the tree names the file and the two steps left: edit it, then set --from it
  when [t1] the driver appends a "## .limits" section to ./.temp/body.md and runs
           `rhx git.pull.description set --from ./.temp/body.md --mode apply`
    then pull #812's body holds the new section
    and  the body ends in exactly one seaturtle attribution
  when [t2] the driver re-runs [t0] and [t1] unchanged
    then the set reports the body as unchanged — the round trip converges, no write
    and  the body still ends in exactly one seaturtle attribution
  when [t3] the driver runs `get --to ../outside.md`, or `get --to ./.temp` (a directory)
    then it exits 2 before any call to github, names the fix `--to ./.temp/body.md`, writes no file
  when [t4] the driver runs `get --to README.md` (a tracked file)
    then it exits 2 before any call to github: --to never overwrites a file git tracks
```
