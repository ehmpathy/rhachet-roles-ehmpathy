# case 1 — set-description-repairs-attribution · happy · critipath

**narrative**

the driver finished its route. it drafts a pull body from its session, and the draft ends the
way its harness taught it: `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
it pipes the draft to `rhx git.pull.description set`. the plan shows the body as it will land:
the claude line gone, the seaturtle line in its place. the driver applies. a human who opens the
pull sees one attribution, the one this repo declares — the same line `git.commit.push` wrote
when it opened the pull.

critipath: the repair is the reason this verb owns attribution. if it broke, every driver-set
body would ship the harness line, and no other paved path sets a body (`gh pr edit` is not
allowlisted).

**bdd `[tn]` timeline**

```
given a branch with an open pull #812
  and a draft body that ends in "🤖 Generated with [Claude Code](https://claude.com/claude-code)"
  when [t0] the driver runs `cat draft.md | rhx git.pull.description set --from @stdin`
    then it sees a plan: the body as it would land, the claude line absent, the seaturtle line at the end
    and  pull #812 is unchanged on github
  when [t1] the driver runs `cat draft.md | rhx git.pull.description set --from @stdin --mode apply`
    then pull #812's body ends in "---\n🐢🌊 surfed in by seaturtle[bot]"
    and  the body holds no line "Generated with Claude Code"
    and  the output names what changed: the pull, and that the attribution was repaired
```
