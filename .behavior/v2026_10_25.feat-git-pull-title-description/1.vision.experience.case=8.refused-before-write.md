# case 8 — refused-before-write · sharp · critipath (fails safe)

**narrative**

the driver pipes a body it meant to build from a file, but the file was never written: stdin is
empty. a naive set would PATCH an empty body and wipe the pull's description — the summary, the
test list, the attribution, gone. the skill stops before any call to github, says the body is
empty, and names the fix. the pull is untouched.

the same guard catches the other two writes that must never reach github: an empty title (github
rejects it, but only after a round trip, with a raw 422), and a body past github's cap.

critipath: an empty-body write destroys the pull's text — cost ∞, at any frequency. the guard is
all that stands between a dropped file and a wiped pull.

```
✋ ConstraintError: the body from '@stdin' is empty
   ├─ why: an empty set would wipe the description of pull #812
   └─ fix: pipe the body in again
      └─ cat body.md | rhx git.pull.description set --from @stdin --mode apply
```

**bdd `[tn]` timeline**

```
given pull #812 with a full body
  when [t0] the driver runs `printf '' | rhx git.pull.description set --from @stdin --mode apply`
    then it exits 2 with "✋ ConstraintError: the body from '@stdin' is empty", on stdout and stderr
    and  the message names the fix: pipe the body in again
    and  pull #812's body is unchanged — no call to github was made
  when [t1] the driver runs `rhx git.pull.title set --title '' --mode apply`
    then it exits 2 with "✋ ConstraintError: the title is empty", and pull #812's title is unchanged
  when [t2] the driver pipes a body of 70,000 chars
    then it exits 2 with "✋ ConstraintError: the body is 70000 chars; github caps a description at 65536"
    and  pull #812's body is unchanged
  when [t3] the driver sets a title of 300 chars
    then it exits 2 with "✋ ConstraintError: the title is 300 chars; github caps a title at 256"
  when [t4] the driver sets a body that lands at exactly 65536 chars with its footer, and a title of 256
    then both are set — the cap holds at its edge, the last valid input still succeeds
```
