# 1.vision — git.pull.title and git.pull.description, with the attribution repair

## the outcome world

### before

a driver opens its pull through `rhx git.commit.push`. the title is whatever `--pr-title-fallback`
or the first commit said; the body is the commit body plus the seaturtle line. after that, the
pull is frozen to the driver:

- `gh pr edit` is not allowlisted, so a driver cannot retitle or rewrite its own pull
- the human edits it by hand, or the pull ships with a stale title that becomes the squash header
- a body a driver drafts from its harness ends in `🤖 Generated with [Claude Code](...)` — the
  wrong attribution for this repo, and no skill strips it

### after

```
rhx git.pull.title get                                   # print this branch's pull title
rhx git.pull.title set --title '<title>' [--mode apply]  # retitle it
rhx git.pull.description get                             # print its body
cat body.md | rhx git.pull.description set --from @stdin [--mode apply]   # rewrite it
```

the driver owns its pull's words end to end. a review asks for a limits note: `get`, edit, `set`.
the route grew past its first commit: `title set`. every body it sets ends in exactly one
attribution — `🐢🌊 surfed in by seaturtle[bot]` — whatever it passed in.

### the aha

the driver reads its body back, edits one line, sets it — and the pull still ends in one
seaturtle line, no claude line, no stacked duplicate. no one polices the attribution any more.

## mental model

- a driver would say: *"i can fix my own pr title and description now, and it always signs it right."*
- analogy: `git commit --amend` for the pull's cover page — the words change, the signature holds.
- their terms vs ours: they say "pr", "description", "edit". we say "pull", "description",
  `set`. `pull` and `description` match the tree `git.pull.comment` plants (#1143); `set`
  follows `rule.require.get-set-gen-verbs` (overwrite, idempotent).

## evaluation

| goal (wish) | how the vision meets it |
|---|---|
| title + description get/set ship in the git.<noun>.<verb> tree, beside git.pull.comment | `skills/git.pull.title/` and `skills/git.pull.description/` (prior art: `git.pull.comment/`), a dispatcher + one file per verb each |
| driver sets its own title + body; no human edit, no raw `gh pr edit` | cases 2, 3, 6 |
| body keeps the seaturtle attribution | cases 1, 2; one declared source for the line |
| `Generated with Claude Code` never ships; replaced by the declared attribution | case 1 |
| a test red without the repair, green with it | the case 1 `[t1]` assertion is the clamp; it feeds the harness form verbatim (link markdown), not the wish's paraphrase |
| no struck alias ships | only `git.pull.title` and `git.pull.description` dispatch |

pros:
- closes the last gap where a driver depends on a human for its own pull
- one source of truth for the attribution: `git.commit.push` and `git.pull.description set` read
  the same declaration, so they cannot drift
- strip-then-append makes the body converge; set is idempotent

cons:
- a second writer of pull bodies; the attribution line must lift out of `git.commit.push.sh:685`
  into a shared declaration, which touches `git.commit.push`
- `set` overwrites whole fields; a concurrent human edit between `get` and `set` is lost
  (last writer wins, same as github's own form)

edgecases → pit of success:
- empty input → refused (an empty body would wipe the pull)
- closed or merged pull → set works, as github allows (open question 9, answered)
- body with `Co-authored-by:` trailers, any case → stripped (no email leak); the shared strip
  goes case-insensitive, which also closes push's extant miss of `Co-Authored-By:`
- body with the attribution already → stripped and re-appended once
- credential expired → refused before any write; never a silent fall back to the host's gh login
  (`--auth as-human` stays an explicit choice, as in prior art)

## open questions & assumptions

the wish routes blueprint questions to the commander, never best-guessed. each question is tagged:
`[wisher]` = the commander's call (the demos hold a sketch, not a decision) · `[answered]` = settled
now by logic or code, with the reason · `[research]` = for the research phase.

1. `[wisher]` **target**: `git.pull.comment` requires `--pr <n>`; #996 said "the pr for the
   current branch, never another". demos sketch current branch by default, `--pr <n>` to override
   (the director's #1143 order needs `--pr`). or `--pr` required, to match the comment verbs?
2. `[wisher]` **title input**: inline `--title '<text>'` (demos), or `--from <path|@stdin>` like a body?
3. `[wisher]` **quota gate**: should `set` require the `git.commit.uses` push permission, or no
   gate (the comment verbs have none; push has one)?
4. `[wisher]` **secret-shaped body refusal**: #996 drafted it; #1165 does not ask. in or out?
5. `[wisher]` **the director's drafts**: `.temp/prior-art.1165/` and `.temp/pr1143.body.md` sit in
   another tree's gitignored scratch; `pretooluse.forbid-cross-repo-access` bars the read ("ask the
   human"). copy them into this tree, or lift the hook for them? the #1143 step of the order cannot
   run without the body file.
6. `[answered]` **shared leaf code — copy or source?** #1143 is unmerged, so this pull cannot
   source its ops; the wish forbids a shared pull. so this pull carries its own thin ops file. a
   later dedupe, once both merge, is a follow-up, not a blocker.
7. `[answered]` **attribution source**: the wish requires the body keep "the attribution
   `git.commit.push` declares". the only form that cannot drift is one named declaration both read,
   so the touch on `git.commit.push` is implied by the wish. it also carries the case-insensitive
   co-authored-by fix (see assumptions).
8. `[answered]` **"replaced" — strip-and-append, or swap in place?** strip-and-append. the round
   trip (case 2) feeds back a body that already ends in the footer; only strip-every-footer +
   strip-claude-line + append-one converges. a swap in place leaves the old footer and stacks.
9. `[answered]` **closed/merged — refuse set?** no. no one asked (wish, #1165, #1035, prior art),
   github allows it, and a fix to a merged pull's stale text is legit. a guard no one asked for is a
   path to maintain for no harm prevented. set works on any state; the inventory reflects it.
10. `[answered]` **the description cap**: 65536 chars, from prior art's `COMMENT_BODY_CHARS_MAX`
    and its 422 map. no further research owed.

settled by prior art, not open: plan by default with `--mode apply`; `--auth as-ehmpath|as-human`
(as-ehmpath default); `--from <path|@stdin>` for the body; `--output tree|json`; read-back + sha256
no-op; one skill file per verb.

assumptions:
- the declared attribution is the literal at `git.commit.push.sh:682-685`: a `---` rule, then
  `🐢🌊 surfed in by seaturtle[bot]`.
- "replaced" means: the claude line (and its `🤖` prefix form) is removed, and the body ends in
  the declared attribution — not a substitution in place mid-body.
- the match is on the line as the harness writes it: `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
  a literal match on the wish's words `Generated with Claude Code` would miss it — the link
  markdown sits between "with" and "Claude". the strip matches a line with `Generated with`,
  then `Claude Code` (bare or in a link), and the test feeds the real harness form.
- the harness's `Co-Authored-By: Claude …` trailer must be stripped too. the extant strip does
  **not** catch it: `get_clean_pr_body` (`git.commit.push.sh:622`) runs `grep -v '^Co-authored-by:'`,
  case-sensitive, and the harness writes `Co-Authored-By:`. so push leaks that trailer into a pull
  body today. the shared strip owes a case-insensitive match (`grep -vi`), which repairs push in
  the same move — small, clean, inside the attribution touch of open question 7.

## groundwork

### external research

- `gh pr view [--json title,body]` reads a pull by current branch (verified: `gh pr view --help`;
  json fields include `title`, `body`, `state`, `number`).
- `gh pr edit --title/--body-file` writes them; the github rest equivalent is
  `PATCH /repos/{owner}/{repo}/pulls/{pull_number}` with `title`, `body`. `gh pr edit` is blocked
  for the clone by `pretooluse.check-permissions` (verified this session), which is why a paved
  verb is owed.

## what is awkward?

- the attribution lives in two skills that do different jobs; one must own the declaration and
  the other import it. today it is a literal inside `git.commit.push`.
- `description set` silently edits what the caller passed (removes a line, appends one). the
  plan output must show this, or it surprises.
- `set` is whole-field overwrite. a driver who wants to append one section must `get` first;
  there is no `--append`. kept out on purpose (wet over dry) — flagged.
