# 1.vision.experience.dimensions

the experience space of `rhx git.pull.title get|set` and `rhx git.pull.description get|set`.

## .the dimensions

| # | dimension | values | why orthogonal |
|---|---|---|---|
| D1 | noun | `title` · `description` | each noun holds one pull field; no value of another axis implies which |
| D2 | verb | `get` · `set` | read vs write; independent of the field |
| D3 | pull state | `open` · `absent` (the lookup finds no pull for the target) · `closed/merged` | a fact of github. `absent` is read against D9: own-absent and by-number-absent are distinct cells with distinct fixes, walked apart in the inventory |
| D4 | credential | `usable` · `keyrack-locked` (under `--auth as-ehmpath`; fix `rhx keyrack unlock`) · `gh-logged-out` (under `--auth as-human`; fix `gh auth login`) · `write-forbidden` (the token reads but github answers 403 at the write) | a fact of the host, independent of the pull; each failure value has its own fix |
| D5 | mode (set only) | `plan` (default) · `apply` | the caller's choice |
| D6 | input (set only) | `non-empty` · `empty` · `multi-line` (title only: a newline in `--title`) · `padded` (title only: blanks around the words, trimmed before compare and write; a quote in the title rides the hint shell-escaped) — by content, whatever the channel (`@stdin`, a path, a literal) | what the caller supplies; the channel does not change the verdict |
| D7 | body content (description set only) | a **set** of markers, each present or absent: `claude-line` (`Generated with [Claude Code](…)`, any form) · `prior-footer` (a seaturtle line already present — left by a prior set, surfaced by a `get`, or pasted by a human) · `co-authored-by` (any case; a line that holds an email, bracketed or bare, lf or crlf — a line with no email is prose, kept). `clean` = the empty set | the content of the caller's text; markers combine freely, so the axis is 2³ = 8 values, a true partition |
| D8 | repeat | `first` · `again` (same input re-set) | the idempotency axis. apart from D7: a first set can carry `prior-footer` (a human pasted one), and an `again` can carry none (a title, or a clean body re-set) |
| D9 | target | `own` (the pull for the current branch) · `own-ambiguous` (no `--pr`, the branch has two or more open pulls) · `own-detached` (no `--pr`, the cwd sits on a detached HEAD, so no branch names a pull) · `by-number` (`--pr <n>`, e.g. a peer tree's pull) | how the caller names the pull; whether the lookup finds one is D3's job. the two `own-*` failure values each refuse with their own fix: name one pull by `--pr` |
| D17 | input form (all verbs) | `well-formed` · `malformed` (an unknown arg, a flag with no value, a non-numeric `--pr`, an `--auth` / `--mode` / `--output` outside its set) — in the spaced or the `--flag=value` form alike | the shape of the argv, apart from what it names; every malformed value refuses before any gh call, so D17 folds against every axis that needs github |
| D10 | size (set only) | `under-cap` · `over-cap` — per noun: description 65536 chars (prior art's `COMMENT_BODY_CHARS_MAX`), checked before the write; title — github's own cap, enforced by its 422 (fulcrum F8) | a property of the input, apart from its content |
| D11 | concurrency (set only) | `alone` · `concurrent-edit` (a human edits the same field while the driver's write is in flight — after a prior get, or with none) | a fact of who else touches the pull, independent of the caller's input |
| D12 | pull author | `self` (the login of the chosen `--auth` opened the pull) · `foreign` (another login opened it) | a fact of who opened the pull, apart from how the caller names it (D9) and which credential it holds (D4): a by-number pull can be self, and an own-branch pull can be foreign |
| D13 | file sink (description get only) | `none` (stdout alone) · `in-repo` (`--to` an untracked path inside the repo) · `outside` (`--to` a path past the repo root) · `directory` (`--to` a directory) · `tracked` (`--to` a file git tracks) | where the bare body lands for an edit; through `rhx`, stdout opens with rhachet's header, so `in-repo` is the round-trip sink |
| D14 | repo owner | `home-org` · `foreign-org` (`--in` names an owner outside the home orgs) | where the pull lives, apart from which pull (D9) and who opened it (D12); one shared fence for all four verbs |
| D15 | read-back (set apply only) | `matches` · `altered` (github stores text other than what was sent) | a fact of github after the write, apart from the input and the credential |
| D16 | output shape | `tree` (default) · `json` · `text` (get only: the bare field; refused on set) | the caller's choice of render, apart from every fact above; every verdict and refusal speaks the chosen shape, so D16 folds against all other axes — walked per verb (tree, json, text on get; tree, json, and the `text` refusal on set), never crossed |

## .the actor — single-valued, on purpose

actor is not an axis here: one value, **the driver**. a human may type the same command, but meets
the same experience through the same flags (`--auth as-human` is covered by D4). no cron or system
caller of these verbs exists; one that did could not run an interactive unlock, and would earn an
axis then. the human who reads the pull is an observer of the result, not a caller.

## .the walked product

full product over the set path: D1 × D3 × D4 × D5 × D6 × D8 × D9 × D10 × D11 × D12 = 2 × 3 × 3 × 2⁷ =
2,304 tuples before content, × 8 D7 values on the description side.
the get path: D1 × D3 × D4 × D9 = 36; D12 folds on get (see below). D13 adds 4 cells on the
description get: `none` and `in-repo` are the two live sinks; `outside`, `directory`, and `tracked`
are refused before any call to github, so they fold to one verdict each and do not multiply D3 × D4.
D14 `foreign-org` and D6 `multi-line` refuse before any call, and D4 `write-forbidden` and D15
`altered` act only at an apply write, so each adds one class rather than a factor (see the folds).

- **get** = 2 nouns × 3 pull states × 3 credentials × 2 targets = 36 cells
- **title set** = 3 × 3 credentials × 2 modes × 2 inputs × 2 repeats × 2 targets × 2 sizes × 2 concurrency × 2 authors = 1,152 cells
- **description set** = the title-set product × 8 content values = 9,216 cells
- **get × any set-only axis (D5, D6, D7, D8, D10, D11)** = impossible by nature: a get takes no
  mode, input, content, size, and makes no write for a human edit to race. verdicted once in the
  inventory, as a class

the cells group into classes whose verdict does not change across the folded axes. the
inventory (`1.vision.experience.case=_.md`) walks each class.

### .the folds, and why each holds

- **credential `keyrack-locked`** → one sharp experience for every noun × verb: refused before any
  call; the fix is `rhx keyrack unlock --owner ehmpath --env prep`.
- **credential `gh-logged-out`** → a distinct sharp experience under `--auth as-human`: refused
  before any call; the fix is `gh auth login`. never a silent swap to the other auth.
- **pull `absent`, target `own`** → one sharp experience for every noun × verb: no pull to read or
  write. the fix is `rhx git.commit.push` (which opens it). this covers main with no `--pr`.
- **pull `absent`, target `by-number`** → a distinct sharp experience: the number names no
  pull. `git.commit.push` cannot open a peer's pull, so the fix differs — check the number, or
  drop `--pr` to address the own pull.
- **pull `closed/merged`** → get and set both work, as github allows; no one asked for a guard
  (vision open question 9). the set plan names the state (`open`, `closed`, `merged`), so a
  driver sees that a merged title is already the squash header before it applies.
- **author `foreign` × set** → one sharp experience for both nouns, every mode: refused before
  any write. a driver sets only a pull its own credential opened (fulcrum F17); the refusal names
  the `--auth` twin, for the case where the other login is the caller's own.
- **author × get** → a get reads any pull it can see and names its author, so a driver learns the
  pull is foreign before it edits, never at the set. D12 changes no get verdict, so it folds.
- **input `empty`** → set refused for both nouns: an empty title is invalid on github; an empty
  body would wipe the description, a destructive act on the bare path.
- **mode `plan`** → every set cell in plan renders the before/after and writes naught; the
  content axis still applies (the plan shows the repaired body).
- **repeat `again`** → the set converges: same input → same stored text, reported as unchanged.
- **target `by-number`, pull `open`** → same verdicts as `own` on every other axis; it adds one
  experience: a driver edits a pull it does not stand on (the director's #1143 order).
- **size `over-cap`** → the pull is never changed: a description is refused before any write; a
  title is refused by github's 422, mapped to a ConstraintError that names the fix.
- **concurrency `concurrent-edit` × `plan`** → the plan reads the current text fresh and shows it
  beside the new, so the driver sees an edit it did not make before it applies.
- **concurrency `concurrent-edit` × `apply`** → last writer wins: the driver's write overwrites
  the human's edit silently, same as github's own edit form. no lock is offered.
- **credential `write-forbidden`** → one sharp experience for both set verbs under apply: github's
  403 surfaces loud on both streams, the pull is untouched. a get and a plan read only, so they fold
  into `usable`.
- **input `multi-line` × title set** → refused before any call: a title is one line on github.
  description input folds it away (a body holds lines by nature).
- **repo `foreign-org`** → one sharp experience for all four verbs, every other axis: refused at the
  fence before the credential is read or github is called. no other axis reaches past it, so it
  does not multiply.
- **read-back `altered`** → one sharp experience for both set verbs: a MalfunctionError that names
  both texts (title) or both hashes (body); a rerun is the fix, and a second mismatch means github
  rewrites the field. plan and no-op make no write, so they fold into `matches`.
- **line ends on a description set** → github may hold `\r\n`; the compare reads text, not line
  ends, so a body that differs only in line ends folds into `again` (a no-op, no write).
- **content on get** → a get returns what github holds, claude line included. content does not
  change the get, so it folds into the plain get class.
- **D7 content values** → every value converges to one shape: strip each marker present, append
  one footer. so the 8 values fold to three demoed walks: `clean` (append only), single markers
  (cases 1, 2), and all markers at once (case 7).

### .the hidden axis the walk surfaced

the round trip: a driver reads its body with `get`, edits it, and sets it back. the body it read
already ends in the seaturtle line. that composition is formalized as D7's `prior-footer` marker —
it is how a prior get shows up on the set side, so the round-trip cells are generated by the
table, not narrated. without a strip of every prior footer, the round trip would stack a second
attribution each time. the repair is not "replace the claude line" alone — it is "the body ends
in exactly one attribution, whatever came in".
