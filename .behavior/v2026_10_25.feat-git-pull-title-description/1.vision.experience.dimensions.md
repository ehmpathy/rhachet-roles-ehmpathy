# 1.vision.experience.dimensions

the experience space of `rhx git.pull.title get|set` and `rhx git.pull.description get|set`.

## .the dimensions

| # | dimension | values | why orthogonal |
|---|---|---|---|
| D1 | noun | `title` · `description` | each noun holds one pull field; no value of another axis implies which |
| D2 | verb | `get` · `set` | read vs write; independent of the field |
| D3 | pull state | `open` · `absent` (the lookup finds no pull for the target) · `closed/merged` | a fact of github. `absent` is read against D9: own-absent and by-number-absent are distinct cells with distinct fixes, walked apart in the inventory |
| D4 | credential | `usable` · `keyrack-locked` (under `--auth as-ehmpath`; fix `rhx keyrack unlock`) · `gh-logged-out` (under `--auth as-human`; fix `gh auth login`) | a fact of the host, independent of the pull; each failure value has its own fix |
| D5 | mode (set only) | `plan` (default) · `apply` | the caller's choice |
| D6 | input (set only) | `non-empty` · `empty` — by content, whatever the channel (`@stdin`, a path, a literal) | what the caller supplies; the channel does not change the verdict |
| D7 | body content (description set only) | a **set** of markers, each present or absent: `claude-line` (`Generated with [Claude Code](…)`, any form) · `prior-footer` (a seaturtle line already present — left by a prior set, surfaced by a `get`, or pasted by a human) · `co-authored-by` (any case). `clean` = the empty set | the content of the caller's text; markers combine freely, so the axis is 2³ = 8 values, a true partition |
| D8 | repeat | `first` · `again` (same input re-set) | the idempotency axis. apart from D7: a first set can carry `prior-footer` (a human pasted one), and an `again` can carry none (a title, or a clean body re-set) |
| D9 | target | `own` (the pull for the current branch) · `by-number` (`--pr <n>`, e.g. a peer tree's pull) | how the caller names the pull; whether the lookup finds one is D3's job |
| D10 | size (set only) | `under-cap` · `over-cap` — per noun: description 65536 chars (prior art's `COMMENT_BODY_CHARS_MAX`); title 256 chars (github; `[research]` — confirm at blueprint) | a property of the input, apart from its content |
| D11 | concurrency (set only) | `alone` · `concurrent-edit` (a human edits the same field while the driver's write is in flight — after a prior get, or with none) | a fact of who else touches the pull, independent of the caller's input |

## .the actor — single-valued, on purpose

actor is not an axis here: one value, **the driver**. a human may type the same command, but meets
the same experience through the same flags (`--auth as-human` is covered by D4). no cron or system
caller of these verbs exists; one that did could not run an interactive unlock, and would earn an
axis then. the human who reads the pull is an observer of the result, not a caller.

## .the walked product

full product over the set path: D1 × D3 × D4 × D5 × D6 × D8 × D9 × D10 × D11 = 2 × 3 × 3 × 2⁶ =
1,152 tuples before content, × 8 D7 values on the description side.
the get path: D1 × D3 × D4 × D9 = 36.

- **get** = 2 nouns × 3 pull states × 3 credentials × 2 targets = 36 cells
- **title set** = 3 × 3 credentials × 2 modes × 2 inputs × 2 repeats × 2 targets × 2 sizes × 2 concurrency = 576 cells
- **description set** = the title-set product × 8 content values = 4,608 cells
- **get × any set-only axis (D5, D6, D7, D8, D10, D11)** = impossible by nature: a get takes no
  mode, input, content, size, and makes no write for a human edit to race. verdicted once in the
  inventory, as a class

the cells group into classes whose verdict does not change across the folded axes. the
inventory (`1.vision.experience.case=_.md`) walks each class.

### .the folds, and why each holds

- **credential `keyrack-locked`** → one sharp experience for every noun × verb: refused before any
  call; the fix is `rhx keyrack unlock --owner ehmpath --env prep`.
- **credential `gh-logged-out`** → a distinct sharp experience under `--auth as-human`: refused
  before any call; the fix is `gh auth login`. never a silent swap to the other auth.
- **pull `absent`, target `own`** → one sharp experience for every noun × verb: no pull to read or
  write. the fix is `rhx git.commit.push` (which opens it). this covers main with no `--pr`.
- **pull `absent`, target `by-number`** → a distinct sharp experience: the number names no
  pull. `git.commit.push` cannot open a peer's pull, so the fix differs — check the number, or
  drop `--pr` to address the own pull.
- **pull `closed/merged`** → get and set both work, as github allows; no one asked for a guard
  (vision open question 9).
- **input `empty`** → set refused for both nouns: an empty title is invalid on github; an empty
  body would wipe the description, a destructive act on the bare path.
- **mode `plan`** → every set cell in plan renders the before/after and writes naught; the
  content axis still applies (the plan shows the repaired body).
- **repeat `again`** → the set converges: same input → same stored text, reported as unchanged.
- **target `by-number`, pull `open`** → same verdicts as `own` on every other axis; it adds one
  experience: a driver edits a pull it does not stand on (the director's #1143 order).
- **size `over-cap`** → refused before any write, against that noun's own cap.
- **concurrency `concurrent-edit` × `plan`** → the plan reads the current text fresh and shows it
  beside the new, so the driver sees an edit it did not make before it applies.
- **concurrency `concurrent-edit` × `apply`** → last writer wins: the driver's write overwrites
  the human's edit silently, same as github's own edit form. no lock is offered.
- **content on get** → a get returns what github holds, claude line included. content does not
  change the get, so it folds into the plain get class.
- **D7 content values** → every value converges to one shape: strip each marker present, append
  one footer. so the 8 values fold to three demoed walks: `clean` (append only), single markers
  (cases 1, 2), and all markers at once (case 7).

### .the hidden axis the walk surfaced

the round trip: a driver reads its body with `get`, edits it, and sets it back. the body it read
already ends in the seaturtle line. that composition is formalized as D7's `prior-footer` marker —
it is how a prior get shows up on the set side, so the round-trip cells are generated by the
table, not narrated. without a strip of every prior footer, the round trip would stack a second
attribution each time. the repair is not "replace the claude line" alone — it is "the body ends
in exactly one attribution, whatever came in".
