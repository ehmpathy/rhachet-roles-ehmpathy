# case 11 — secret-refused-before-write · sharp · critipath (fails safe)

**narrative**

the driver drafts a body from its notes, and one note holds a deploy token it pasted while it
debugged. a set would put the token on the pull, where every reader of the repo sees it and the
edit history keeps it after a fix. the skill reads the body before any call to github, finds a value
in the shape of a github token on line 3, and stops. it names the shape and the line, never the
value, so the refusal itself leaks naught. the pull is untouched.

the same guard reads a title, since a title is as public as a body. a body that names a key kind in
prose ("rotate the github token") holds no value, and passes.

critipath: a leaked credential is cost ∞ at any frequency (commander, #1173 review: in). the guard is
all that stands between a pasted note and a public secret.

```

🥥 did you know?
   └─ to fix it
      └─ remove the value from the body, then rerun; a credential belongs in the keyrack, never in a pull
```
