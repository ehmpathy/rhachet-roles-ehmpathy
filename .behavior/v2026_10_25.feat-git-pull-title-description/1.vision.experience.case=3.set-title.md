# case 3 — set-title · happy · critipath

**narrative**

the driver opened its pull with the title of its first commit: `feat(git.pull): add title get`.
the route then grew to four verbs and an attribution repair. the title now undersells the pull.
the driver runs `rhx git.pull.title set`, sees the before and after, applies. the pull list now
reads true, and the squash commit at merge will carry the right header.

critipath: the title becomes the squash commit header on main and the changelog line. the
driver has no other paved way to fix it.

**bdd `[tn]` timeline**

```
given pull #812 titled "feat(git.pull): add title get"
  when [t0] the driver runs `rhx git.pull.title get`
    then it sees "feat(git.pull): add title get"
  when [t1] the driver runs `rhx git.pull.title set --title 'feat(git.pull): title and description get|set, with attribution repair'`
    then it sees a plan: before → after
    and  pull #812's title is unchanged
  when [t2] the driver re-runs [t1] with `--mode apply`
    then pull #812's title is the new one
    and  the output names the pull and the new title
  when [t3] the driver re-runs [t2] unchanged
    then the output reports the title as unchanged — no write
```
