# case 4 — no-pull-for-branch · sharp · critipath (fails safe)

**narrative**

a fresh driver wants to stage a good body before it pushes. it runs
`rhx git.pull.description set` on a branch no pull exists for yet. the skill does not create a
pull (that is `git.commit.push`'s job) and does not fail with a raw gh error. it stops at once,
says no pull exists for this branch, and names the fix. it then tries the other three verbs out
of habit; each stops the same way, through the one lookup.

later, asked to touch a peer's pull, it fat-fingers the number. the lookup finds no pull #9999.
this fix differs: `git.commit.push` cannot open a peer's pull, so the skill says to check the
number, or drop `--pr` to address its own pull.

critipath: every new branch starts here. a raw `no pull requests found` or, worse, a silent
exit 0 would leave the driver to believe its body landed.

```
✋ ConstraintError: no pull found for branch feat-git-pull-title-description
   ├─ why: a pull opens on the first push
   └─ fix: push, which opens the pull
      └─ rhx git.commit.push --mode apply
```

**bdd `[tn]` timeline**

```
given a branch with no pull on github
  when [t0] the driver runs `echo body | rhx git.pull.description set --from @stdin --mode apply`
    then it exits 2 with "✋ ConstraintError: no pull found for branch <branch>", on stdout and stderr
    and  the message names `rhx git.commit.push` as the fix
    and  no pull is created
  when [t1] the driver runs `rhx git.pull.title get`
    then it exits 2 with the same error
  when [t2] the driver runs `rhx git.pull.title set --title 'x' --mode apply`
    then it exits 2 with the same error
  when [t2b] the driver runs `rhx git.pull.description get`
    then it exits 2 with the same error — all four verbs refuse through the one lookup
given the driver passes `--pr 9999`, a number no pull holds
  when [t3] the driver runs each verb with `--pr 9999`:
           `rhx git.pull.title get --pr 9999` · `rhx git.pull.title set --pr 9999 --title 'x' --mode apply` ·
           `rhx git.pull.description get --pr 9999` · `echo b | rhx git.pull.description set --pr 9999 --from @stdin --mode apply`
    then each exits 2 with "✋ ConstraintError: no pull #9999 in <owner/repo>"
    and  each fix names a check of the number, or the same verb with no `--pr` (own pull) —
         not `git.commit.push`, which cannot open a peer's pull
    and  no write reaches github
```
