# case 6 — set-a-peer-pull-by-number · happy · critipath

**narrative**

the director wants pull #1143 — another clone's pull, in another tree — to read true before the
commander reviews it. its body was drafted in that tree; its title still says
`github.comment` after the rename to `git.pull.comment`. the driver of this tree does not stand
on #1143's branch, so it names the pull by number. it sets the title, pipes the body in, applies
both, and reads each back: the title it asked for, a body that ends in the seaturtle line.

critipath: the director's order is exactly this walk, and `gh pr edit` is denied, so no other
paved path reaches a pull the driver does not stand on.

**bdd `[tn]` timeline**

```
given pull #1143 titled "feat(github.comment): add get, set, and del verbs for pr comments"
  and a body file that ends in "🤖 Generated with [Claude Code](https://claude.com/claude-code)"
  and the driver stands on another branch
  when [t0] the driver runs
           `rhx git.pull.title set --pr 1143 --title 'feat(git.pull.comment): add get, set, and del verbs for pr comments' --mode apply`
    then pull #1143's title is the new one, read back
    and  the driver's own pull is untouched
  when [t1] the driver runs `cat pr1143.body.md | rhx git.pull.description set --pr 1143 --from @stdin --mode apply`
    then pull #1143's body ends in "---\n🐢🌊 surfed in by seaturtle[bot]", read back, hash matches
    and  holds no line "Generated with Claude Code"
  when [t2] the driver runs `rhx git.pull.title get --pr 1143` and `rhx git.pull.description get --pr 1143`
    then it sees the new title, and a body whose last line is the seaturtle line
```
