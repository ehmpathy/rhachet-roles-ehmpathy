# case=14 — a robot cannot forge a grant file through the file tools

cells: 4.10. feel 🔪. care 🔴.

## .narrative

`case=7` closes the front door: a robot cannot run `git.release.uses set`. the stamp is still a
file, `.meter/git.release.uses.jsonc`, and a crew holds paved file tools that write inside the
repo. a crew that cannot run the grant verb could write the file the verb writes, and mint its own
release.

the third lock lives in the file tools. `teesafe`, `cpsafe`, `mvsafe`, `symlink`, and `sedreplace`
each refuse a write whose destination — or whose link target — lands in `.meter/` or
`.branch/.bind/`. the check runs before any write; a glob copy checks every destination first, so
not one file lands. the match is on the directory, not the word: `src/meter-notes.md` writes fine.

## .timeline

```
given a tree with a live release stamp, and a crew session
  when [t0] crew runs `echo '{"uses":99}' | rhx teesafe --into .meter/git.release.uses.jsonc`
    then exit 2, `✋ ConstraintError:`, and the stamp is unchanged

  when [t1] crew runs `rhx cpsafe --from forged.jsonc --into .meter/git.release.uses.jsonc`
    then exit 2, the stamp is unchanged

  when [t2] crew points a symlink at the stamp, or moves the stamp out of `.meter/`
    then exit 2, no link is created, the stamp stays in place

  when [t3] crew runs `rhx teesafe --into .branch/.bind/git.commit.level`
    then exit 2, no bind is written

  when [t4] crew runs `rhx teesafe --into src/meter-notes.md`
    then exit 0 — the guard matches the `.meter` dir, not the word
```
