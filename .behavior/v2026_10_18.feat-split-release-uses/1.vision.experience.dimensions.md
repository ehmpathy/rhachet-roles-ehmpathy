# 1.vision.experience.dimensions

the experience space of three independent allowances: commit ⟂ push ⟂ release.

## .the dimensions

| # | dimension | values |
|---|---|---|
| A | allowance | `commit` · `push` · `release` |
| B | act the crew attempts | `commit` · `push` · `rebase` · `release` · `get` |
| C | state of the allowance that act needs | `unset` · `granted` · `depleted` · `blocked` · `corrupt` |
| D | meter level that decides | `local` · `org` · `global` |
| E | actor | `human` (tty) · `robot` (crew) |
| F | tree history | `fresh` (no meter) · `legacy` (old `"push"` field inside `git.commit.uses.jsonc`) · `current` |
| G | rebase shape (only when B = rebase) | `0 ahead` (fast-forward) · `N ahead, clean` · `N ahead, conflict` |

## .the act → allowance map (the core invariant)

| act | needs | never needs |
|---|---|---|
| commit (`git.commit.set`) | commit | push, release |
| rebase (`git.branch.rebase begin/continue`) | commit | push, release |
| push (`git.commit.push`, `git.commit.set --push`) | push | release · and NOT commit quota — a push spends no commit |
| release (`git.release --mode apply`) | release | commit, push |
| read (`get` on any meter) | none | — |
| grant / block / revoke (`set`, `allow`, `block`, `del`) | human at tty | — |

⇒ B × A collapses to this one map. each act reads exactly one meter. a cell where an act reads a
second meter is the defect this behavior removes.

## .the walked product

the full product is 3 × 5 × 5 × 3 × 2 × 3 × 3. most axes do not interact, so the walk factors into
four planes. each plane is walked as a matrix below; its rows live in `1.vision.experience.case=_.md`.

| plane | axes walked | why this cut |
|---|---|---|
| P1 — independence | A × (grant one, then each act) | the done test: each grant moves exactly one act |
| P2 — gate states | B × C × D | every act refuses or proceeds the same way on each state, at each level |
| P3 — rebase | G × (commit state) × (push state) | the measured incident lives here |
| P4 — authority + migration | E × (grant verbs) · F × B | who may grant; what an upgraded tree sees |

## .the planes, as checkable products

the 7 axes are NOT all crossed. the act → allowance map above is the latent dimension: an act's
outcome depends only on the state of the ONE meter it reads, so A and B fold into "the needed
meter", and the full 7-way box collapses to four sub-products. each is walked in full below;
each cell maps to an inventory row, or is folded / impossible with its reason.

### P1 — independence: grant set × gated act

grant set = which of the 3 meters are granted (2³ = 8). gated act = commit · push · release (3).
8 × 3 = 24 cells. by the map, a cell's outcome = "is the act's own meter granted?" — so 24 fold
to 3 acts × 2 = 6 outcomes, plus the cross-meter effects the fold hides (depletion, revoke,
read-back, a two-meter command).

| grant set ↓ · act → | commit | push | release |
|---|---|---|---|
| none | refuse (2.1) | refuse (2.1) | refuse (2.1) |
| commit | 1.1 | 1.2 | 1.3 |
| push | 1.7 | 1.8 | refuse (fold of 1.3) |
| release | refuse (fold of 1.7) | refuse (fold of 1.2) | 1.6 |
| commit + push | proceed (fold of 1.1) | 1.4 | 1.5 |
| commit + release | proceed (fold of 1.1) | refuse (fold of 1.2) | proceed (fold of 1.6) |
| push + release | refuse (fold of 1.7) | proceed (fold of 1.8) | proceed (fold of 1.6) |
| all three | proceed | proceed | proceed — `case=9` |

cross-meter rows outside the grid: 1.9 (revoke one), 1.10 (depletion), 1.11 (read-back),
1.12 (`git.commit.set --push`, two meters in one command), 1.13 (combined read).

### P2 — gate state × level, for the needed meter

C (5) × D (3) = 15 cells. B folds: every gated act reads its own meter through one shared reader.

| state ↓ · level → | local | org / `@all` | global |
|---|---|---|---|
| unset | 2.1 | 2.6 | proceed — a global entry is a blocker only; absence = not blocked |
| granted | 2.2 | proceed (org allowed is the AND's org term) | impossible — global holds no grant, only a block |
| depleted | 2.3 | impossible — org has no quota | impossible — global has no quota |
| blocked | fold of 2.3 (`block` = quant 0) | 2.5 | 2.4 |
| corrupt | 2.7 | 2.7 | 2.7 · 2.8 (release, today fails open) |

plus 2.9 (release gains the org gate) and 2.10 (a commit global block no longer halts release) —
both cross a meter boundary the single-meter grid cannot show.

### P3 — rebase shape × commit × push

G (3) × commit (granted · not) × push (granted · not) = 12 cells.

| shape ↓ · (commit, push) → | (✓, ✗) | (✓, ✓) | (✗, any) |
|---|---|---|---|
| 0 ahead | 3.1 | fold of 3.1 — push never read | 3.2 |
| N ahead, clean | 3.3 | 3.4 | fold of 3.2 |
| N ahead, conflict | 3.5 | fold of 3.5 | fold of 3.2 |

push folds to "any" in the ✗-commit column: commit refuses first. extra rows on the 0-ahead
shape: 3.7 (remote ahead), 3.8 (untracked path clash). 3.6 is the invariant over all 12.

the stage act (F12): rebase state (in progress · not) × commit (live · not) = 4 cells. stage reads
the commit meter alone, so neither rebase state nor path ever changes the outcome — they fold. the
retired `--stage` field is never read.

| rebase ↓ · commit → | live | not live (unset · depleted · blocked) |
|---|---|---|
| in progress | 3.9 (a hand-merged conflict; any other path folds here) | 3.12 |
| not | 3.11 | fold of 3.12 |

3.10 is the `continue` refusal that names the step. 3.13 is a legacy tree whose `stage` field
disagrees with its commit grant. P3 total: 12 + 4 = 16 cells.

### P4 — actor × write verb · tree history × act

E (2) × write verb (`set` · `allow` · `block` · `del`, at 3 levels) → robot: every write refused
(4.1, 4.2, 4.3); human: every write proceeds (4.4). F (3) × act (4): only `legacy` changes an
outcome — 4.5 push, 4.6 release, 4.7 commit, 4.8 old flag, 4.9 `set` over a legacy file; `fresh`
= P2 unset row; `current` = P1. P4 total: E (2) × verb (4) × level (3) = 24, plus F (3) × act (4)
= 12 → 36 cells.

## .orthogonality notes

- **D is AND, not precedence.** an act proceeds only when global is not blocked AND org (or `@all`) is
  allowed AND local is granted — the composition `git.commit.uses` uses today
  (`git.commit.set.sh:709-805`). so D multiplies only the *refusal* cells, never the *proceed* cells.
- **E only meets the grant verbs.** a robot reads every meter freely; it may grant none.
- **F only meets push and release.** a legacy tree's commit quota keeps its sense; only the
  retired `"push"` field and the implicit release (commit quota > 0) change.
