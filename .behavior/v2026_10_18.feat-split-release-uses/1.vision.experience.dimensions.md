# 1.vision.experience.dimensions

the experience space of two independent meters: `git.commit.uses` (commit + stage + rebase + push)
⟂ `git.release.uses` (release).

## .the dimensions

| # | dimension | values |
|---|---|---|
| A | meter | `commit` · `release` |
| B | act the crew attempts | `stage` · `commit` · `push` · `rebase` · `release` · `get` · `write a grant file` (via a paved file tool) |
| C | state of the meter that act needs | `unset` · `live` (uses left / `allow`) · `held at 0` (depleted) · `blocked` · `corrupt` · `spent, arm failed` (release only: between the spend and the refund) |
| D | meter level that decides | `local` · `org` · `global` |
| E | actor | `human` (tty) · `robot` (crew) |
| F | tree history | `fresh` (no meter) · `legacy` (old `"push"` / `"stage"` fields; release via commit quota) · `current` |
| G | rebase shape (only when B = rebase) | `0 ahead` (fast-forward) · `N ahead, clean` · `N ahead, conflict` |
| H | branch vs its pr (only when B = release) | `no pr` (never pushed) · `in sync` · `ahead of pr` (unpushed commits) |

## .the act → meter map (the core invariant)

| act | needs | never needs |
|---|---|---|
| stage, no rebase in progress (`git.stage.add`) | commit — live | release |
| stage, rebase in progress | none, as `continue` | — |
| commit (`git.commit.set`) | commit — live; spends one use | release |
| push (`git.commit.push`, `git.commit.set --push`) | commit — held (live or at 0); spends no use | release |
| rebase begin (`git.branch.rebase begin`) | commit — live; spends no use | release |
| rebase continue / abort / take | none | — |
| release (`git.release --mode apply`) | release — live; spends one use; branch in sync with its pr | commit |
| release arm fails after the spend | release — refunds the one use it spent, only to the stamp the spend left | commit |
| read (`get` on either meter) | none | — |
| grant / block / revoke (`set`, `allow`, `block`, `del`) | human at tty | — |
| write into `.meter/` or `.branch/.bind/` via a file tool | refused for every actor; the grant verbs are the only writers | — |

⇒ A × B collapses to this one map. each act reads at most one meter. a cell where an act reads the
other meter is the defect this behavior removes.

## .the walked product

the full product is 2 × 6 × 5 × 3 × 2 × 3 × 3 × 3. most axes do not interact, so the walk factors
into five planes. each is walked as a matrix below; its rows live in `1.vision.experience.case=_.md`.

| plane | axes walked | why this cut |
|---|---|---|
| P1 — independence | grant set × gated act | the done test: each grant moves only its own acts |
| P2 — gate states | C × D, for the needed meter | every act refuses or proceeds the same way on each state, at each level |
| P3 — rebase + stage | G × commit state · rebase-in-progress × commit state | the measured incident lives here |
| P4 — authority + migration | E × verb × level · F × act | who may grant; what an upgraded tree sees |
| P5 — push ⟂ release | commit (held · revoked) × release (live · not) × H | the boundary the commander ranks first |

## .the planes, as checkable products

### P1 — independence: grant set × gated act

grant set = which of the 2 meters are live (2² = 4). gated act = commit · push · release (3).
4 × 3 = 12 cells. stage and rebase fold into the commit column (same meter, same live test).

| grant set ↓ · act → | commit | push | release |
|---|---|---|---|
| none | refuse (2.1) | refuse (2.1) | refuse (2.1) |
| commit | 1.1 | 1.4 | 1.3 — refused by meter |
| release | 1.7 — refused | 1.8 — refused | 1.6 |
| both | proceed (fold of 1.1) | proceed (fold of 1.4) | proceed — `case=13` |

cross-meter rows outside the grid: 1.9 (revoke one), 1.10 (depletion keeps push), 1.11 (read-back),
1.12 (`git.commit.set --push`, one meter, two acts), 1.13 (combined read).

### P2 — gate state × level, for the needed meter

C (5) × D (3) = 15 cells. B folds: every gated act reads its meter through one shared reader.

| state ↓ · level → | local | org / `@all` | global |
|---|---|---|---|
| unset | 2.1 | 2.6 | proceed — a global entry is a blocker only; absence = not blocked |
| live | 2.2 | proceed (org allowed is the AND's org term) | impossible — global holds no grant, only a block |
| held at 0 | 2.3 (commit and release refuse; push proceeds, 1.10) | impossible — org has no quota | impossible — global has no quota |
| blocked | 2.11 (`block` revokes push too) | 2.5 | 2.4 |
| corrupt | 2.7 | 2.7 | 2.7 · 2.8 (release, today fails open) |

plus 2.9 (release gains the org gate) and 2.10 (a commit global block no longer halts release) —
both cross a meter boundary the single-meter grid cannot show. the `spent, arm failed` state adds
2.12 (the refund returns the use) and 2.13 (a revoke or a damage mid-apply: the refund mints naught
or fails loud) — local only, since only the local stamp holds a quota.

### P3 — rebase + stage

rebase: G (3) × commit (live · held at 0 · revoked or unset) = 9 cells.

| shape ↓ · commit → | live | held at 0 | revoked / unset |
|---|---|---|---|
| 0 ahead | 3.1 | 3.15 — proceeds; a held grant suffices (F9) | 3.2 |
| N ahead, clean | 3.3 | fold of 3.15 | fold of 3.2 |
| N ahead, conflict | 3.5 | fold of 3.15 | fold of 3.2 |

extra rows on the 0-ahead shape: 3.7 (remote ahead), 3.8 (untracked path clash). 3.6 is the
invariant over all 9: rebase never reads release. 3.4 is the push of a rebased branch (rides P5).

stage: rebase in progress (yes · no) × commit (live · not live) = 4 cells.

| rebase ↓ · commit → | live | not live (unset · held at 0 · revoked) |
|---|---|---|
| in progress | 3.9 | 3.14 — proceeds; mid-rebase stage reads no meter |
| not | 3.11 | 3.12 — refused |

3.10 is the `continue` refusal that names the step. 3.13 is a legacy `stage` field that disagrees
with the commit grant. P3 total: 9 + 4 = 13 cells.

### P4 — actor × write verb · tree history × act

E (2) × verb (`set` · `allow` · `block` · `del`) × level (3) = 24 → robot: every write refused (4.1,
4.2, 4.3); human: every write proceeds (4.4). the verb axis also holds a write that bypasses the
verbs: a paved file tool into `.meter/` or `.branch/.bind/` — refused for every actor (4.10). F (3) × act (`stage` · `commit` · `push` · `release`)
= 12: only `legacy` changes an outcome — 4.5 push, 4.6 release, 4.7 commit, 4.8 old `--push` flag,
4.9 `set` over a legacy file, 3.13 stage. `fresh` = P2 unset row; `current` = P1. P4 total: 36 cells.

### P5 — push ⟂ release

commit (held · revoked) × release (live · not) × H (no pr · in sync · ahead) = 12 cells. the push
column reads H only as "is there a commit to push"; the release column reads H as a gate (F14).

| (commit, release) ↓ · branch → | no pr (never pushed) | in sync with pr | ahead of pr |
|---|---|---|---|
| (held, not) — push without release | 5.1 push proceeds, opens the pr; release refused | 5.2 release refused by meter | fold of 5.1 |
| (held, live) | 5.3 release refused, names push | proceed (fold of 5.5) | 5.4 release refused, names `N unpushed`; push then release proceeds |
| (revoked, live) — release without push | 5.6 refused; names `git.commit.uses` to push first | 5.5 release proceeds; no push needed | 5.7 refused; names the unpushed commits + the commit grant |
| (revoked, not) | fold of 2.1 | fold of 2.1 | fold of 2.1 |

5.8 is the invariant over all 12: release never pushes, and push never merges.

## .orthogonality notes

- **D is AND, not precedence.** an act proceeds only when global is not blocked AND org (or `@all`) is
  allowed AND local is granted — the composition `git.commit.uses` uses today
  (`git.commit.set.sh:709-805`). so D multiplies only the *refusal* cells, never the *proceed* cells.
- **E only meets the grant verbs.** a robot reads both meters freely; it may grant neither.
- **F only meets push, release, and stage.** a legacy tree's commit quota keeps its sense; the
  retired `"push"` and `"stage"` fields and the implicit release (commit quota > 0) change.
- **H only meets release.** push writes the pr; release reads whether the pr holds the branch.
