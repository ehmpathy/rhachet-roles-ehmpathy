# case=8 — an upgraded tree, and an old habit

cells: 4.5 · 4.6 · 4.8. feel 🔪. care 🔴.

## .narrative

a tree upgrades. its `.meter/git.commit.uses.jsonc` reads `{ "uses": 5, "push": "allow" }`. under
the old contract that one file let the crew commit, push, and release. under the new contract it
grants commits only. the tree must neither gain nor lose a grant *silently* — so the first refused
push and the first refused release each say why, name the split, and print the exact command that
restores what the human used to grant. no grant is carried over in silence; none is lost in silence.

a human with the old habit types `git.commit.uses set --quant 3 --push allow`. it refuses and names
the two commands that replace it.

## .timeline

```
given a legacy `git.commit.uses.jsonc` with `"push": "allow"` and no push or release meter
  when [t0] crew runs `rhx git.commit.push --mode apply`
    then it exits 2 with `✋ ConstraintError: push not allowed`
    then a note reads `push moved to its own meter; the "push" field in git.commit.uses is retired`
    then it names `rhx git.push.uses allow   # ask your human`

  when [t1] crew runs `rhx git.release --mode apply`
    then it exits 2; the note reads `release moved to its own meter; a commit quota no longer grants it`
    then it names `rhx git.release.uses set --quant N   # ask your human`

  when [t2] crew runs `rhx git.commit.set -m @stdin --mode apply`
    then it proceeds; the retired field is ignored on read

given a human at a tty
  when [t3] human runs `rhx git.commit.uses set --quant 3 --push allow`
    then it exits 2 with `✋ ConstraintError: --push moved to its own meter`
    then it names `rhx git.commit.uses set --quant 3` and `rhx git.push.uses allow`
```
