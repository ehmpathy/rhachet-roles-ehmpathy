# case=8 — an upgraded tree, and an old habit

cells: 4.5 · 4.6 · 4.8. feel 🔪. care 🔴.

## .narrative

a tree upgrades. its `.meter/git.commit.uses.jsonc` reads `{ "uses": 5, "push": "block" }`. under
the old contract that file let the crew commit and — since `git.release` read the commit quota —
release, but not push. under the new contract it grants commit + push and never release. the tree
must neither gain nor lose a grant *silently*: the first push says it now rides the commit grant,
and the first refused release names the split and the exact command that restores it.

a human with the old habit types `git.commit.uses set --quant 3 --push allow`. it refuses and names
the one command that replaces it.

## .timeline

```
given a legacy `git.commit.uses.jsonc` = { "uses": 5, "push": "block" } and no release meter
  when [t0] crew runs `rhx git.commit.push --mode apply`
    then it proceeds; a 🥥 note reads `the "push" field retired — push rides the commit grant`
    then it names `rhx git.commit.uses block   # ask your human, to stop push`

  when [t1] crew runs `rhx git.release --mode apply`
    then it exits 2; the note reads `release moved to its own meter; a commit grant no longer grants it`
    then it names `rhx git.release.uses set --quant N   # ask your human`

  when [t2] crew runs `rhx git.commit.set -m @stdin --mode apply`
    then it proceeds; the retired fields are ignored on read

given a human at a tty
  when [t3] human runs `rhx git.commit.uses set --quant 3 --push allow`
    then it exits 2 with `✋ ConstraintError: --push retired; push rides the commit grant`
    then it names `rhx git.commit.uses set --quant 3`
```
