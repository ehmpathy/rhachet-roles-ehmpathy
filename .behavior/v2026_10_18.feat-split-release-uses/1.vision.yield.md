# 1.vision — three allowances: commit ⟂ push ⟂ release

source: the canonical wish, `refs/2026-10-18.wish.canonical.md` (verbatim, with the human's
stage-in-rebase addendum). it supersedes `0.wish.md` and the earlier relay
(`refs/2026-10-18.wish-amendment.via-director.md`): **three** independent allowances, not two.

## the contract

| meter | governs | grant shape | who grants |
|---|---|---|---|
| `git.commit.uses` | local commits, a local rebase, and the stage that feeds them | `--quant N` · `allow` = unlimited | a human at a tty — granted freely, the moment a crew needs it |
| `git.push.uses` | a push to the tree's own feature branch (incl. a rebase's force-with-lease) | `allow` · `block` | a human at a tty — granted freely |
| `git.release.uses` | a release: a merge to main, a publish, a tag that ships | `--quant N` · `allow` = unlimited | a human at a tty — the release stamp |

each meter:

- has three levels — `local` · `--org <org>` / `--org @all` · `--global` — that compose by AND (F3)
- reads `unset` as blocked and a damaged file as blocked (`💥`, exit 1)
- is read by exactly one act, written by exactly one grant verb
- is human-only to write — `set` · `allow` · `block` · `del` all pass the tty guard, as `git.commit.uses`
  does today (`git.commit.uses.local.sh` `set|del|block|allow` → `guard_actor_is_human_via_stdin`);
  any actor may `get`

"freely" vs "stamp" is a difference of human ceremony, never of mechanism: all three grants need a
human at a terminal. a director that grants is a human-driven session; a charter that grants by
itself is out of scope here (open question).

| act | reads | never reads |
|---|---|---|
| `git.commit.set` | commit | push, release |
| `git.branch.rebase begin` | commit | push, release |
| `git.branch.rebase continue` / `abort` / `take` | none, as today — covered by the commit grant that began the rebase | — |
| `git.stage.add` — in a rebase or out (e.g. mark a hand-merged conflict done) | commit (live grant; spends no use) | push, release; the retired `--stage` field |
| `git.commit.push`, `git.commit.set --push` | push | commit quota, release |
| `git.release --mode apply` | release | commit, push |
| `git.release` plan / `--watch` | none | — |

## the outcome world

### a day in the life

a director spins up three crews. each gets `git.commit.uses set --quant 5` and
`git.push.uses allow` — two commands, granted freely, no human stamp. the crews commit, rebase onto
fresh main, and push their branches all day. no crew waits on a human for a push.

at 4pm one crew's pr is ready. the human reads it, runs `git.release.uses set --quant 1` on that
tree, and the crew runs `git.release --into prod --mode apply`. the stamp spends itself. the other
two crews still cannot ship — their commit and push grants carry no release.

### before / after

| moment | before | after |
|---|---|---|
| a director lets a crew push | `--push allow` — and since `git.release` reads the commit quota (`git.release.sh:292-303`), the crew can now also ship | `git.push.uses allow` — ship stays refused |
| a crew with zero commits rebases | refused: *"rebase requires push permission"*; two grants, two round trips | fast-forward on a commit grant alone; naught to push |
| a crew with a commit grant stages its files | `git.stage.add` refused: *"stage not allowed"* — a second grant (`--stage allow`) owed before the commit grant is usable | `git.stage.add` reads the commit meter; one grant |
| a crew hand-merges a rebase conflict and marks it done | `git.stage.add` refused: *"stage not allowed"* — a third grant for a rebase that only moves commits; and `continue`'s conflict refusal never names the mark-done step (`git.branch.rebase.continue.sh:74-76`) | `git.stage.add` reads the commit meter; `continue`'s refusal names `rhx git.stage.add <files>` |
| a commit quota depletes | `git.commit.push.sh:722` silently flips push to block | push stays as granted |
| the global release blocker file is damaged | `jq ... \|\| echo "false"` reads it as not blocked — fails open | `💥` malfunction; fails closed |
| a tree has a local grant but its org is unset | release proceeds (release skips the org gate) | release refuses, names `--org <org> allow` |

### the aha

the old `--push` bit stood for two acts with opposite stakes. once each act reads its own meter,
the cheap acts get cheap and the costly act gets strict — at once, with no trade. a director can
hand out commit and push like water because neither can ship.

## mental model

- **to a friend**: "three keys. the commit key and the push key a lead hands out. the ship key only
  the owner holds. no key opens another's lock."
- **analogy**: a kitchen. cooks (commit) and the plate on your own station's tray (push) are the
  sous-chef's to grant. only the head chef sends a plate out to the guests (release).
- **their terms vs ours**: humans say "let it push" and "let it ship". ours match: `git.push.uses`,
  `git.release.uses`. we avoid "deploy" — a release here is a merge to main / a publish / a tag.

## evaluation

| goal (wish + amendment) | met by |
|---|---|
| commit ⟂ push ⟂ release | one meter per allowance, one reader per act (forbidden cells X1–X3, X7) |
| release fails closed | unset + damage both block; the hardened shared reader replaces the raw `jq` read |
| no widen of release auth | release gains the org gate and loses the fail-open read; AND composition (F3) |
| no default-allow | every meter unset = blocked |
| rebase needs commit, push only to push | `case=3`, `case=4` |
| every caller that read `--push` as "may release" moves | `git.release.sh:254-304` → release meter; `git.commit.push.sh:353-366`, `git.commit.set.sh:784-808`, `git.branch.rebase.begin.sh:84-95`, `git.branch.rebase.operations.sh:189` → push meter or removed; hook test fixtures that type `--push` (Q4) |
| migration note, no silent gain or loss | `case=8` + F6 |

**pros**: the measured incident vanishes; release is stricter than today on two axes; every grant
reads back alone; one hardened reader per meter.

**cons**: three meters to learn where there was one; every extant `--push` habit breaks (loudly,
F8); every tree mid-flight loses push and release on upgrade and must be regranted (F6). the
regrant has two layers: per machine, once per org — `git.push.uses --org <org> allow` and
`git.release.uses --org <org> allow` (today one `git.commit.uses --org <org> allow` covers commit,
push, and release); per tree — the local grants. the migration note must list both, and must name
the retired `--stage` field: a tree that held `stage allow` with no commit quota loses stage.

**edge cases kept in the pit of success**: a damaged meter → `💥` + the path + the fix; a push
to `main` stays refused by `git.commit.push` (forbidden X6); a 0-ahead fast-forward over a remote
branch that holds unfetched commits refuses (F7); a robot that tries any write on any meter meets
the same tty refusal it meets on `git.commit.uses` today.

## what is awkward?

- **the push skill is named `git.commit.push`** but reads `git.push.uses`. the name says "commit"
  while the meter says it needs no commit. tolerable; a rename is out of scope.
- **`git.commit.set --push` reads two meters** — commit to commit, push to push. it is two acts in
  one command, so two reads is honest, but it is the one place the "one act, one meter" table bends.
- **a rebase asks for a commit grant even on a fast-forward that writes no commit** (F9). one rule
  beats a special case, but it can read as fussy.
- **the upgrade is loud by design**: every live tree loses push and release at once. correct for
  safety; a real chore for a human with a fleet. a one-shot migrate could follow (F6).
- **"release" spans merge to main, publish, and tag**, yet this repo's local release act is only
  `git.release --mode apply`; publish and tag happen in ci after the merge. the meter guards the
  merge, which is the gate to the rest.
