# 1.vision — two meters: commit + push ⟂ release

source: the commander's order of 2026-10-20, verbatim: *"rank the git.release.uses tree to the top
of your premises. the goal: a crew can be granted commit + push quota while any release (merge,
git.release --apply) stays refused, by meter, not by habit."* it matches `0.wish.md` (two meters,
two gates) and supersedes the three-meter draft drawn from `refs/2026-10-18.wish.canonical.md` (F15).

## the contract

| meter | governs | grant shape | who grants |
|---|---|---|---|
| `git.commit.uses` | commit · stage · rebase · push to the tree's own feature branch (incl. a rebase's force-with-lease) | `--quant N` · `allow` = unlimited · `block` · `del` | a human at a tty — granted freely, the moment a crew needs it |
| `git.release.uses` | a release: a merge to main, a publish, a tag that ships | `--quant N` · `allow` = unlimited · `block` · `del` | a human at a tty — the release stamp |

the one sentence a human needs:

```sh
rhx git.commit.uses allow && rhx git.release.uses block   # push the pr all day; never ship
```

each meter:

- has three levels — `local` · `--org <org>` / `--org @all` · `--global` — that compose by AND (F3)
- reads `unset` as blocked and a damaged file as blocked (`💥`, exit 1)
- is written only by its own grant verbs; no verb writes both
- is human-only to write — `set` · `allow` · `block` · `del` all pass the tty guard, as `git.commit.uses`
  does today (`git.commit.uses.local.sh` `set|del|block|allow` → `guard_actor_is_human_via_stdin`);
  any actor may `get`

there is no push meter, no stage meter, no rebase meter. each of those acts rides the commit grant.

| act | reads | never reads |
|---|---|---|
| `git.commit.set` | commit (spends one use) | release |
| `git.commit.set --push` · `git.commit.push` | commit (held grant; a push spends no use, F16) | release |
| `git.branch.rebase begin` | commit (held grant; spends no use, F9) | release |
| `git.branch.rebase continue` / `abort` / `take` | none — covered by the grant that began the rebase | — |
| `git.stage.add`, no rebase in progress | commit (live grant; spends no use) | release; the retired `--stage` field |
| `git.stage.add`, rebase in progress | none — as `continue`; a revoke mid-rebase never strands the crew (F12) | — |
| `git.release --mode apply` | release (spends one use) | commit |
| `git.release` plan / `--watch` / `--retry` | none | — |

two words carry the commit meter's states:

- **live** = granted with uses left (or `allow`) — needed to commit and stage
- **held** = granted, even at 0 left — needed to push and to begin a rebase, since neither spends a use. `block` and `del` revoke; depletion does not (F9, F16)

so a crew pushes the commit that spent its last use, and a human who wants push gone types `block`.

## the outcome world

### a day in the life

a director spins up three crews. each gets `git.commit.uses set --quant 5` — one command, granted
freely, no human stamp. the crews stage, commit, rebase onto fresh main, and push their branches all
day. no crew waits on a human for a push.

at 4pm one crew's pr is ready. the human reads it, runs `git.release.uses set --quant 1` on that
tree, and the crew runs `git.release --into prod --mode apply`. the stamp spends itself. the other
two crews still cannot ship — their commit grants carry no release, by meter.

### before / after

| moment | before | after |
|---|---|---|
| a director lets a crew push | `--push allow` — and since `git.release` reads the commit quota (`git.release.sh:292-303`), the crew can now also ship | `git.commit.uses set --quant N` — push rides it; ship stays refused until `git.release.uses` |
| a director wants push but never ship | no way to say it: push allow + quota > 0 = release | `git.commit.uses allow && git.release.uses block` |
| a crew with zero commits rebases | refused: *"rebase requires push permission"*; two grants, two round trips | fast-forward on the commit grant alone |
| a crew with a commit grant stages its files | refused: *"stage not allowed"* — `--stage allow` owed | stage rides the commit grant |
| a crew hand-merges a rebase conflict | refused: *"stage not allowed"*; `continue` never names the mark-done step (`git.branch.rebase.continue.sh:74-76`) | stage reads no meter mid-rebase; `continue`'s refusal names `rhx git.stage.add <files>` |
| a commit quota depletes | `git.commit.push.sh:722` silently flips push to block | push stays held; only `block` / `del` revoke it |
| a crew with only a release grant ships | refused unless commit quota > 0 | proceeds — release needs no commit grant |
| a branch holds commits its pr lacks | release ships the pr without them, silently | release refuses, names the unpushed count + the push (F14) |
| the global release blocker file is damaged | `jq ... \|\| echo "false"` reads it as not blocked — fails open | `💥` malfunction; fails closed |
| a tree has a local grant but its org is unset | release proceeds (release skips the org gate) | release refuses, names `--org <org> allow` |

### the aha

the old `--push` bit stood for two acts with opposite stakes. now the cheap acts (stage, commit,
rebase, push to a feature branch) share one cheap meter, and the costly act (release) owns a strict
one. a director hands out commit grants like water because no commit grant can ship.

## mental model

- **to a friend**: "two keys. the work key — stage, commit, rebase, push your own branch — a lead
  hands out. the ship key only the owner holds. the work key never opens the ship lock."
- **analogy**: a kitchen. cook and plate up on your own station (commit, push) — the sous-chef's to
  grant. only the head chef sends a plate to the guests (release).
- **their terms vs ours**: humans say "let it work" and "let it ship". ours: `git.commit.uses`,
  `git.release.uses`. we avoid "deploy" — a release here is a merge to main / a publish / a tag.

## evaluation

| goal | met by |
|---|---|
| commit + push quota while release stays refused, by meter | push rides `git.commit.uses`; release reads only `git.release.uses` (X1–X3) |
| release fails closed | unset + damage both block; the hardened shared reader replaces the raw `jq` read |
| no widen of release auth | release gains the org gate, loses the fail-open read, refuses unpushed commits; AND composition (F3) |
| no default-allow | both meters unset = blocked |
| rebase needs commit only | `case=3`, `case=11` |
| every caller that read `--push` as "may release" moves | `git.release.sh:254-304` → release meter; `git.commit.push.sh:353-366`, `git.commit.set.sh:784-808`, `git.branch.rebase.begin.sh:84-95`, `git.branch.rebase.operations.sh:189` → commit grant held; hook test fixtures that type `--push` (Q4) |
| migration note, no silent gain or loss | `case=8` + F6 |

**pros**: one meter fewer than the three-meter draft; the measured incident vanishes; release is
stricter than today on three axes; `allow && block` says the whole policy in one line.

**cons**: a commit-but-never-push grant no longer exists (F17); every extant `--push` habit breaks
(loudly, F8); every tree mid-flight loses release on upgrade and must be restamped (F6). the
migration note names the regrant per machine (`git.release.uses --org <org> allow`) and per tree,
and names the retired `--push` and `--stage` fields.

**edge cases kept in the pit of success**: a damaged meter → `💥` + the path + the fix; a push to
`main` stays refused (X6); a 0-ahead fast-forward over a remote branch that holds unfetched commits
refuses (F7); a robot that tries any write on either meter meets the tty refusal it meets today.

## what is awkward?

- **a push spends no use but needs a held grant** — two words, live vs held, where one would be
  simpler. the alternative strands a crew with a commit it cannot push (F16).
- **`block` revokes push too.** a human who blocks commits to pause a crew also stops its push.
  correct for a pause; surprise for a human who wanted "push what you have, commit no more" —
  that human types `set --quant 0`.
- **a rebase asks for a commit grant even on a fast-forward that writes no commit** (F9).
- **the upgrade is loud by design**: every live tree loses release at once (F6).
- **"release" spans merge, publish, and tag**, yet the local act is only `git.release --mode apply`;
  publish and tag run in ci after the merge. the meter guards the merge, the gate to the rest.
