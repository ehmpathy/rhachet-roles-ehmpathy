# wish — split `git.release.uses` from `git.commit.uses`

## .the outcome

two meters, two gates, two owners:

| meter | governs | who grants |
|---|---|---|
| `git.commit.uses` | commits, and pushes **to the tree's own feature branch** (incl. a rebase's force-push) | a director, freely, the moment a crew needs it |
| `git.release.uses` | a **release**: a merge to main, a publish, a tag that ships | the human's release stamp (or a charter that grants release auth) |

a commit grant never carries release auth, and a release grant never needs a commit quota.

## .why

today `git.commit.uses --push allow|block` is ONE bit for two acts with opposite stakes: a push to a
feature branch (cheap, reversible) and a ship (a release). so a push is held as tightly as a release,
and every branch push waits on the same human the release does.

measured 2026-10-18, `rhachet-roles-bhuild.beav.feat-behavior-route-upgrades`: to retire fireworks
the crew had to rebase onto main. its branch held **zero commits**, yet the paved `git.branch.rebase`
refused with *"rebase requires push permission"*. a director granted 1 commit with push blocked; the
rebase still refused; a second grant with push allowed was owed before the crew could move. two
grants, two round trips, for a rebase that shipped naught.

the commander, verbatim: *"seems like we should entool a skill into rhachet-roles-ehmpathy to enable
rebase without commit-quota … or, maybe this is just solved by the git.release.uses separate to
git.commit.uses"*.

## .what must be true after

- `git.commit.uses` governs commits and feature-branch pushes (and so a rebase). its push no longer
  implies any release
- `git.release.uses` (global · org · local, the same shape as `radio.uses` and `git.commit.uses`) gates
  every release act. it **fails closed**: unset = blocked, so a defect blocks a ship rather than
  permits one
- `git.branch.rebase` needs no push permission when the branch has nothing to push (no commits ahead
  of its base), and otherwise needs only `git.commit.uses` push, never `git.release.uses`
- every extant caller that read `--push` as "may release" is moved to `git.release.uses`
- a migration note for extant meter state, so no tree silently gains or loses a grant

## .what must NOT be in it

- any widening of release auth. the release gate must be at least as strict after as before
- a default-allow on either meter

## .how you know it is done

a director grants `git.commit.uses set --quant 1 --push allow` on a tree, the crew rebases and pushes
its branch, and a release from that tree is still refused until `git.release.uses` is granted.
