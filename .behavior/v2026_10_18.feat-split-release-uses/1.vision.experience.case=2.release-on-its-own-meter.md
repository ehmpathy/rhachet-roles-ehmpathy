# case=2 — release reads only its own meter, and fails closed

cells: 1.6 · 5.5 · 2.1 · 2.9. feel 😊 / 🔪. care 🔴.

the release journey without a commit grant.

## .narrative

a human wants a crew to ship a branch another crew already pushed. this crew holds no commit grant —
it has no reason to write code. the human grants one release. the release proceeds; it never looks
at the commit meter, and it pushes naught (the pr already holds the branch). on a second tree with
no release grant, or with a local grant but no org allowance, the release refuses — the gate is at
least as strict as today, and stricter on the org axis.

## .timeline

```
given a tree with no `git.commit.uses` grant, a pr in sync with the branch
  when [t0] human runs `rhx git.release.uses set --quant 1`
    then `rhx git.release --into prod --mode apply` proceeds through feat → main → prod
    then `git.release.uses get` reads `left: 0`
    then `git.commit.uses get` still reads `└─ no grant set` — release needed none and spent none

given a tree with no `git.release.uses` file
  when [t1] crew runs `rhx git.release --mode apply`
    then it exits 2 with `✋ ConstraintError: release not allowed`
    then it names `rhx git.release.uses set --quant N   # ask your human`

given a tree with a local release grant, and the org meter holds no entry and no `@all`
  when [t2] crew runs `rhx git.release --mode apply`
    then it exits 2, names `rhx git.release.uses --org <org> allow   # ask your human`

given any tree
  when [t3] crew runs `rhx git.release` (plan) or `rhx git.release --watch`
    then it proceeds with no grant — plan and watch ship naught
```
