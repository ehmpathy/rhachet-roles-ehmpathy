# case=10 — hand-merge a rebase conflict and mark it done, on the commit grant alone

cells: 3.9 · 3.10. feel 🔪 → 😊. care 🔴.

## .narrative

measured 2026-10-18 on `rhachet-roles-bhuild.beav.feat-behavior-route-upgrades` (the human's
addendum): a rebase stopped on a conflict in a file neither "ours" nor "theirs" could settle. the
crew merged it by hand. to mark it done it needed `git add` — and `git.stage.add` refused, since
the tree held a commit grant but no `--stage allow`. a rebase that only moves commits needed a
third grant.

after: `git.stage.add` rides the commit grant — in a rebase or out — so the mark-done needs no
stage grant; there is no stage grant any more. and `continue`, if run too soon, names the
mark-done step instead of a bare "settle conflicts".

## .timeline

```
given `feat/tide-chart` 3 ahead, 5 behind; `git.commit.uses` quant 1; `git.push.uses` unset
  when [t0] crew runs `rhx git.branch.rebase begin --mode apply`
    then it halts: `status: conflict`, files `src/tide/getTideChart.ts`

  when [t1] crew hand-merges the file, then runs `rhx git.branch.rebase continue`
    then it exits 1 with the file still listed as unmerged
    then next steps read `├─ rhx git.stage.add src/tide/getTideChart.ts   # mark it done`
                         `└─ rhx git.branch.rebase continue`

  when [t2] crew runs `rhx git.stage.add src/tide/getTideChart.ts`
    then it proceeds on the commit grant: `└─ staged: src/tide/getTideChart.ts (commit grant)`
    then the stage spent no use; `git.commit.uses get` still reads `left: 1`

  when [t3] crew runs `rhx git.branch.rebase continue`
    then the rebase completes; the tail names `rhx git.commit.push (needs git.push.uses)`
```
