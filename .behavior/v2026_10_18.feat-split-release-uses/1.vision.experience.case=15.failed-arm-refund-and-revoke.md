# case=15 — a failed arm refunds its own use, and never undoes a human's revoke

cells: 2.12 · 2.13. feel 😊 → 🔪. care 🔴.

## .narrative

an apply spends one release use at the arm of the merge (F19). if the arm fails — gh refuses the
merge, the network drops — naught shipped, so the use returns. the refund is keyed to the spend:
it returns the one use this apply took, and only if the stamp still reads as the spend left it.

if a human revoked the stamp between the spend and the failure, the stamp no longer reads as the
spend left it. the refund then mints naught, and the revoke stands. a blind read-then-increment
would undo the revoke, and the crew would hold a use its human just took away.

if the stamp turns damaged between the spend and the refund, the refund fails loud as a
malfunction. it never reads a damaged file as "a human changed it".

## .timeline

```
given a release grant of 1 use, no commit grant, a feature branch in sync with its pr
  when [t0] crew runs `rhx git.release --into main --mode apply` and the merge arm fails
    then exit non-zero, and the stamp reads 1 left — the failed arm refunded its use

  when [t1] a human runs `rhx git.release.uses block` while the apply is in flight, then the arm fails
    then the stamp reads revoked, and the output names `a human changed it` — the refund mints naught

  when [t2] the stamp file turns damaged mid-apply, then the arm fails
    then `💥 MalfunctionError: could not refund the release use` on both streams,
         and the output never says `a human changed it`
```
