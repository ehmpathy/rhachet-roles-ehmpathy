# case=7 — a robot cannot grant push or release

cells: 4.1 · 4.2. feel 🔪. care 🔴.

## .narrative

a crew blocked on a release is tempted to grant itself. two locks stop it, the same two that guard
`git.commit.uses` today: the claude permission deny-list (`init.claude.permissions.jsonc:30-67`)
and the tty guard (`guard_actor_is_human_via_stdin`, `git.commit.operations.sh:1007`). both new
meters inherit both locks, on every grant form — local `set`/`allow`, `--org * allow`,
`--global allow`, `--org * del` (which can lift an org block).

## .timeline

```
given a crew session with no tty
  when [t0] crew runs `rhx git.release.uses set --quant 1`
    then the PreToolUse permission check denies it before it runs

  when [t1] the deny-list is bypassed (e.g., a bare form the list misses)
    then the skill exits 2 with `✋ ConstraintError: git.release.uses set is human-only`

  when [t2] crew runs `rhx git.release.uses get`
    then it proceeds — a read needs no authority

  when [t3] crew runs `rhx git.release.uses block`
    then it exits 2 at the tty guard — every write is human-only, as on `git.commit.uses` today
```
