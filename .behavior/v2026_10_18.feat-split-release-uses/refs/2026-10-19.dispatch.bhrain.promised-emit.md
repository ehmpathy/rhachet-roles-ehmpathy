## defect: `route.stone.set --as promised` renders a self review guide with no ask behind it

`rhachet-roles-bhrain@0.42.1`, `dist/domain.operations/route/formatRouteStoneEmit.js:280-297`.

- the `promised` emit renders `formatLetsReflect` for `nextReview` — the full guide plus the articulate-into path
- `stepRouteStoneSet.js:235-270` builds `nextReview` via `getOneNextUnpromisedReview` and mints NO ask
- the only ask mint is `setSelfReviewTriggeredReport` inside `setStoneAsPassed.js:234-258`
- so a driver writes the next review from the rendered guide, promises, and is refused `challenge:unasked` ("no ask on record"). it also forfeits the per-ask haste clock

## measured

rhachet-roles-ehmpathy @ beav/feat-split-release-uses, stone 1.vision, 2026-10-18: hit twice in five self reviews.

## fix (applied downstream as a pnpm patch)

for `promised` with `nextReview`, render a pointer, never the guide:

```
   ├─ passage = progressed (review.self 2/5 promised)
   └─ next = review.self 3/5
      └─ to be handed it, run: rhx route.stone.set --stone 1.vision --as passed
```

the alternative — mint the ask at promise time — moves the haste clock, a design call for this repo. the render fix is the minimal safe cure.

downstream clamp: `src/infra/patches/rhachet-roles-bhrain.patch.integration.test.ts` (teeth proven). please ship the fix with a clamp in the `formatRouteStoneEmit` tests, so the downstream patch can drop.
