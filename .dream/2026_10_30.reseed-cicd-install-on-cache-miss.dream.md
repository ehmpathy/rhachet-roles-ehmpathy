## .the gap, precisely

no job ever installs once the install job has reported a hit, and a consumer job's restore miss is
only a warning. so any miss or failure on the consumer side runs the job with no `node_modules`.

1. `.github/workflows/.install.yml:29-35` — the "node-modules cache check" is an
   `actions/cache/restore` with `lookup-only: true`. it asks "does the key exist", downloads naught.
2. `.github/workflows/.install.yml:38,44,48,52` — setup node, setup pnpm, `pnpm install
   --frozen-lockfile`, and the cache save are all gated `if: steps.cache.outputs.cache-hit != 'true'`.
   a lookup hit skips the install. attempt 1's install log: `Cache hit for:
   Linux-node-v22.21.0-pnpm-4bde0194aa6f42adcb1e0c7456a3d963` / `Lookup only - skipping download`.
3. `.github/workflows/.declastruct.yml:48-52` — plan's "get node-modules from cache" is a plain
   `actions/cache/restore` on `needs.install.outputs.node-modules-cache-key`, with no
   `fail-on-cache-miss` and no install step behind it. a miss (or a restore timeout) is a warning.
   the apply job repeats it at `:110-114`.
4. `.github/workflows/.declastruct.yml:68` (plan) and `:139` (apply) — `npx declastruct …`. with no
   local `node_modules`, npx resolves the registry's latest (1.9.2), not the pinned 1.7.3, and that
   copy has no `declastruct-github` beside it.
5. a `rerun --failed` makes it certain: the green install job is reused as is (its log keeps the
   2026-10-21 timestamps), so its 9-day-old key is handed to plan with no fresh lookup. that key is
   gone: `gh cache list --key Linux-node-v22.21.0-pnpm-4bde0194` returns no entry (github evicts a
   cache unused for 7 days).
6. not our code: `package.json` and `pnpm-lock.yaml` are identical at 7deacc9 and origin/main
   (`declastruct 1.7.3`, `declastruct-github 1.3.0`), and `git log 7deacc9..origin/main --
   package.json pnpm-lock.yaml .github` holds only release bumps. the same workflow ran green on two
   other branches 7 minutes before and 12 minutes after attempt 1.

provenance: `declapract.use.yml:2` declares `npm:declapract-typescript-ehmpathy` (0.47.35, from
`package.json:94`). the repo's `.install.yml` and `.declastruct.yml` match
`node_modules/declapract-typescript-ehmpathy/dist/practices/cicd-common/best-practice/.github/workflows/`
line for line, apart from action sha pins. the same restore-with-no-install shape repeats in
`.test.yml` (`:41`, `:62`, `:92`, `:113`, `:134`, `:202`, `:288`) and `.publish-npm.yml:27`.

## .the shape of the fix

in the template's `cicd-common` best-practice:

- every consumer job that restores `node_modules` installs on its own miss. gate on that restore's
  own output, not on the install job's lookup:
  ```yaml
  - name: get node-modules from cache
    id: node-modules
    uses: actions/cache/restore@v4
    with:
      path: ./node_modules
      key: ${{ needs.install.outputs.node-modules-cache-key }}
  - name: install on cache miss
    if: steps.node-modules.outputs.cache-hit != 'true'
    run: pnpm install --frozen-lockfile   # (+ setup pnpm, as .install.yml does)
  ```
  a miss, an eviction, or a restore timeout then costs an install, never a broken job.
- plan and apply resolve the pinned local copy: `pnpm exec declastruct …` (or `npx --no-install`),
  so an absent `node_modules` fails loud as "not installed" and never pulls an unpinned registry
  release.
- optional: drop `lookup-only` in `.install.yml`, or keep it and accept that the consumer-side
  install is the real guarantee.
- clamp in the template repo: a declapract test that asserts each consumer restore is followed by a
  miss-gated install, and that no workflow step calls bare `npx <pinned dep>`.

## .why it is not done in this round

- SAFE: yes. CLEAN: no. the files are stamped by another repo's template; a hand edit here is
  overwritten by the next `declapract apply`, and every other ehmpathy repo keeps the gap. the fix
  belongs in `ehmpathy/declapract-typescript-ehmpathy`, outside this diff and this route's scope.
- the PR's red heals on its own: the next push runs the install job fresh, with a live key.
