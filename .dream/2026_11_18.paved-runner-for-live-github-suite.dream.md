# 🌙 dream: a paved runner for the live github suite

kind = followup · owner = mechanic · caught 2026-11-18

## .the cue that fired
5.3 verification on fix-pull-text-public-repo-promise: the zero-skips scan found three `given.runIf(isLiveTargeted(...))` blocks in `git.pull.watch.github.real.integration.test.ts`, and no paved way to run them.

## .the gap, precisely
the suite runs only under `TEST_LIVE=github`. no npm command or `rhx git.repo.test` flag sets it, and an env prefix on a bash call is not paved. so a clone cannot prove the suite green, and a default run reports no skip count for it.

## .the shape of the fix
- `rhx git.repo.test --what integration --live github` sets `TEST_LIVE=github` and unlocks keyrack env test
- or a `test:integration:live` npm command in package.json
- a ci job (nightly, or on a label) that runs it, so the gate is exercised somewhere on a schedule

## .the wider set (same scan, same shape of fix)
the scan also found, in files this pr does not touch: ten `describe.skip` llm eval and compression suites (librarian `cluster`, `brief.condense`, `brief.compress`, `kernelize/clusterKernels`, `.evals`), `git.repo.test.play` two `skipIf(CI)` real-npm cases, and `cicd.deflake/detect` `runIf(isGhAuthenticated)`. each wants an owner call: delete as dead, move behind a paved opt-in runner, or fix and enable. full list in route fulcrum F10.

## .why it is not done in this round
the file is untouched by this pr. to delete the gate would put live github calls and the test key into every integration run, a ci policy change outside this behavior.
