# 🌙 dream: `--thorough` reports ~120 failures that no change caused

**kind:** fix · **owner:** mechanic · **caught:** 2026-09-09

## .the cue that fired

a route ran `rhx git.repo.test --what integration --mode apply --thorough` to answer one question —
*"did my change break aught outside its own scope?"*

it came back **2514 passed / 120 failed** across **19 suites**, in 4638s.

⇒ **not one of the 120 implicated the change.** the diff touched `git.commit/*`,
`init.claude.permissions.jsonc`, and one new test helper. zero of the 19 suites read any of them.

## .the gap, precisely

🔴 **the instrument answers a different question than the one a driver asks it.** at a ~4.5% failure
floor with no change at all, `--thorough` cannot separate a regression from its own noise — which is
the one job it exists to do.

three distinct causes, none a product defect:

| cause | suites | evidence |
|---|---|---|
| **wall-clock exhaustion under parallel load** | `git.release` ×8 (~100 tests) | every failure sits at 10–14s; the snapshots show watch-loops truncated mid-poll — `... (Nx more)` where `✨ done!` was owed |
| **perf assertions as stopwatches** | `git.repo.test` ×3, `check-permissions` | `expect(elapsed).toBeLessThan(5000)`, `…under 3s with 500 rules` → 5151ms. 88 suites in parallel saturate the box |
| 🔴 **host toolchain drift** | `git.branch.rebase` ×5, `decide-permissions`, `forbid-cross-repo-access` | **re-ran alone, unloaded — identical failures.** not load at all |

### the drift cases are the sharpest, because they are permanent

- **git**: a snapshot pins `error: invalid onto: 'abc123def456'`; this host's git emits
  `error: could not get 'onto': 'abc123def456'`
- **jq**: a mask regex is `/jq: parse error:.*/g`, but this build emits `parse error: …` with **no
  `jq: ` prefix** — so the mask never fires and the snapshot diffs on an unmasked cause string
- **jq, again**: `forbid-cross-repo-access` expects exit `0` on malformed stdin and gets **4** — a
  jq exit code the hook does not absorb

⇒ these **never pass on this host**, at any load. they are a permanent red that trains the reader to
skip the whole report.

## 🔴 .why it matters more than the count suggests

the easy read of a 120-failure report is *"it's all noise"* — and **that read is how a real
regression ships.** the noise floor does not merely waste time; it *teaches* a driver to disbelieve
the one signal they ran the suite to get.

⚠️ what made the answer legible in this round was **not the thorough run**. it was:

1. the **diff** — which files can this change even reach?
2. two **re-runs alone, unloaded** — which failures are load, and which are drift?

⇒ **a suite that needs two out-of-band steps to interpret is not yet an instrument.** and both steps
were the driver's own initiative — no rule required them, so the next traveler may skip them.

## .the shape of the fix

three repairs, cheapest first:

1. **pin the drift** — mask the version-variable text rather than the whole line:
   - the jq mask should tolerate an absent `jq: ` prefix (`/(jq: )?parse error:.*/`)
   - the git snapshot should mask the `onto` error text, or assert the shape rather than the phrase
   - `forbid-cross-repo-access` should absorb a non-zero jq exit and still fail OPEN + loud (its own
     stated contract — the test is right and the hook does not honor it on this jq)
2. **make the stopwatches load-aware** — a perf assertion that shares a box with 87 other suites
   measures the box. either give them a **serial lane**, or scale the budget by observed
   parallelism, or mark them so a loaded run reports them apart from real failures.
3. 🔴 **separate the report** — the highest-value change is not any single fix: it is that
   `--thorough` should distinguish **"failed"** from **"failed for a reason the suite already knows
   about"**. a known-drift lane would have let this round read its answer in one glance.

⚠️ **and `rmsafe` is a genuine, prior defect** found en route — 3 tests in `[case11]`/`[case15]`
where a glob-matched file survives a delete that should have removed it. it fails **alone**, so it
is not load, and it sits outside this route's diff entirely. ⇒ worth its own diagnosis; it is the
one item here that is a real product defect.

## .why it is not done in this round

**SAFE: no. CLEAN: no.**

- **safe** — it edits assertions and snapshots across **7 suites this route never opened**, plus a
  hook's error path. a wrong mask here hides a real defect later, which is strictly worse than the
  noise it removes
- **clean** — it ripples into `git.repo.test`'s own reporter, three snapshot files, and a hook

⇒ **and one bound matters: do NOT reach for `--resnap`.** a re-record of these baselines would pin
*this host's* git and jq text as the truth and move the breakage to every other host. the repair is
a **mask**, never a re-record (and `rmsafe` is a defect that a resnap would bless outright).

⇒ 🟡 no fulcrum is owed — a noisy suite found en route is not a fork in the sponsor contract.
