# 🌙 dream: rebase and stage honor an org block, without a refusal on unconfigured trees

kind: reseed · owner: mechanic (rhachet-roles-ehmpathy) · caught 2026-10-21

## .the cue that fired

r11 i006 blocker.2 on `v2026_10_18.feat-split-release-uses`: `git.commit.uses block --org X`
stops commit and push, yet `git.branch.rebase begin --mode apply` and `git.stage.add` proceed.

## .the gap, precisely

- `git.branch.rebase.begin.sh` reads `check_global_blocker` (added in this route), never
  `check_org_blocker`
- `git.stage.add.sh:113` reads `check_global_blocker` only
- `check_org_blocker` (`git.commit.operations.sh:2140`) returns 2 on an UNSET org (no keyrack.yml,
  no org entry), so a drop-in call refuses every unconfigured tree

## .the shape of the fix

1. split the org read three ways: blocked · allowed · unset. rebase and stage refuse on `blocked`
   (and on damage), proceed on `unset`; commit and push keep fail-closed on `unset`
2. fold the four hand-written gates into one `assure_commit_meter act=commit|stage|push|rebase`
   leaf that holds the act → (live|held, levels) table
3. clamp: an org-blocked tree refuses rebase and stage (exit 2); an unconfigured tree still
   rebases on a held grant

## .why it is not done in this round

dirty: it changes what an unconfigured tree may do and reshapes ~100 fixtures. fulcrum F28.
