# 🌙 dream: continue reads git's exit code, never prints success over a git error

kind: fix · owner: ehmpathy/rhachet-roles-ehmpathy (`src/domain.roles/mechanic/skills/git.branch.rebase/git.branch.rebase.continue.sh`) · caught 2026-11-02

## .the cue that fired
a peer review on the `--unstaged` route found `GIT_OUTPUT=$(git rebase --continue 2>&1) || true`: when git refuses a pick with no conflict and no unstaged edit (a hook fails, the index is dirty), continue prints `righteous!` and `status: in progress`, exit 0.

## .the gap, precisely
the exit code is dropped. the fall-through branch reads "in progress" as success. four extant tests in `git.branch.rebase.continue.integration.test.ts` (case2 to case5) simulate a rebase that git rejects and pin the `righteous!` render, so they pin the defect. `git.branch.rebase.unstaged.integration.test.ts` case12 t1 pins it a fifth time, with held paths named; its snapshot also shows `commits: 1 ✓` beside git's `Rebasing (2/2)` in case12 t0.

## .the shape of the fix
capture `GIT_EXIT_CODE`; ahead of the progress render, a nonzero exit renders `hang tight...`, `status: stopped (no conflict)`, the held branch, and `print_rebase_next_steps settle_step="clear what stopped it, per git.output below"`, exit 1. rebuild case2 to case5 on a real rebase (the journey test's setup) so each pins a true state, and add a clamp: a `pre-commit` or index-lock stop mid-continue goes red without the fix.

## .why it is not done in this round
the defect predates this route, and its fix flips four extant tests outside the `--unstaged` wish (`rule.require.review-test-changes`). it earns its own pr.
