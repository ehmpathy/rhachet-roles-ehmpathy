# 🌙 dream: lifecycle case9b [t2] reads `live` where it asks for `wedged`, under load

- kind: deflake
- owner: mechanic (git.pull.watch tests)
- caught 2026-11-21

## .the cue that fired

one full run of the 13 pull-watch suites (2026-11-21, on the fix-pull-watch-daemon-respawn-loop branch) failed `git.pull.watch.lifecycle` `[case9b][t2]`: `expected " · wedged · "`, the daemon read `live`. the same case passed alone twice in a row right after, and passed in three prior full runs.

## .the gap, precisely

`getKeyDirWithWatch` runs `set`, which respawns a real daemon, then `scene.stopAllDaemons()` SIGKILLs it by its pid record. the test then writes an hour-old `daemon.heartbeat`. a child of the killed daemon still mid-tick (a heartbeat write inside a `$( )` subshell, or a bound's done hook) can land its write after the kill, so the heartbeat reads fresh and the state `live`.

## .the shape of the fix

after `stopAllDaemons`, await every process of the key gone (the daemon and its process group), or kill the group (`process.kill(-pid)`, the daemon is a `setsid` leader), before the test writes the heartbeat. a clamp: run the case under load, many times, red before and green after.

## .resolved

landed in the same route, at `5.3.verification`: the whole-repo run hit the flake again, with the heartbeat at `0s`. `stopAllDaemons` in `genWatchTestScene.ts` now kills the daemon's group (`process.kill(-pid, 'SIGKILL')`), with the bare pid as the fallback where no group of that id stands. the lifecycle suite passed after it (`103 passed, 0 failed`). an under-load repeat clamp stays owed; the next whole-repo runs are its evidence.
