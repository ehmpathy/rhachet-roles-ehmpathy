- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-ehmpathy`
- **caught** = 2026-09-11

## .the cue that fired

peer review `i008` `enroll-impl-behavior-intent`, nitpick A:

> *"`git.commit.bind.sh` sources only `output.sh` — it calls **neither** guard. It relies *solely*
> on the permission denylist (confirmed: no `-t`/`__I_AM_HUMAN` reference anywhere in the file). …
> `git.commit.bind.integration.test.ts` has zero tty/actor-guard tests — so this asymmetry isn't
> just undocumented, it's also unclamped by any test."*

## .the gap, precisely

three skills in this family answer *"is a human at this terminal?"*. one does not ask.

| skill | actor guard | lines of defense |
|---|---|---|
| `git.commit.sponsor` | all 3 streams, emits on both | **2** — the skill AND the manifest |
| `git.commit.uses.{local,org,global}` | `guard_actor_is_human_via_stdin` | **2** |
| 🔴 `git.commit.bind` | **none** | **1** — the manifest alone |

verified: no `-t`, no `__I_AM_HUMAN`, and no `source` of `git.commit.operations.sh` in
`git.commit.bind.sh`.

⇒ 🔴 **a denylist is a property of THIS role's config.** `git.commit.sponsor.sh` says so in its own
header — *"a clone that never runs the skill could still reach the state file … the tty guard
travels with the code; this entry stops the invocation."* ⚠️ **that argument applies verbatim to
`bind`, and `bind` has only the half that does not travel.**

## ✅ .the half that LANDED 2026-09-11

the `--` passthrough route was denied for the sponsor and left open for bind. closed:

```jsonc
"Bash(npx rhachet run --skill git.commit.bind -- set:*)",
"Bash(npx rhachet run --skill git.commit.bind -- del:*)",
"Bash(rhx git.commit.bind -- set:*)",
"Bash(rhx git.commit.bind -- del:*)",
```

clamped by `init.claude.permissions` `[case6][t0]`, which reads the **shipped** manifest.

⇒ SAFE ✅ (a deny entry only tightens) · CLEAN ✅ (the manifest was already open in this diff).

## .the shape of the fix — what is still owed

1. `source "$SCRIPT_DIR/git.commit.operations.sh"` in `git.commit.bind.sh`
2. call `guard_actor_is_human_via_stdin "git.commit.bind $COMMAND"` on `set` and `del`, never `get`
3. add the non-tty spawn tests `git.commit.bind.integration.test.ts` has none of — the three `uses`
   suites already carry the exact pattern to copy (`// no __I_AM_HUMAN`)

## .why it is not done in this round

the SAFE/CLEAN test — **SAFE refuses it**, and for the same reason `F12` ask 4(b) is deferred:

- it **changes the behavior of an extant skill**. a caller that binds a commit level today with
  stdin piped would begin to be refused
- ⇒ a real tighten, and surely the right one — but *"who may bind a commit level"* is a policy
  call, not a tidy-up beside a sponsor guard

🟡 **and it is the SAME question F12 ask 4(b) already holds**: *may this family's guard surfaces be
tightened to refuse callers they accept today?* ⇒ so it belongs to that council rather than to a
new one — **one verdict settles `bind` and the three `uses` skills together.**

⚠️ **what is NOT a reason: "bind came first."** it did, and the sponsor's guard beside it is what
made the absence legible — this change surfaced the gap, so it owes the record even where it does
not owe the fix.
