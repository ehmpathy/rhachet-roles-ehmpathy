# 🌙 dream: one front-half resolver and a crash-safe seal for git.package.patch

- kind: refactor
- owner: ehmpathy/rhachet-roles-ehmpathy, role=mechanic, skill git.package.patch

## .the cue that fired

the l3 peer lanes on route `v2026_10_20.feat-git-package-patch` (i008–i009) each named the same
shape: begin and commit carry two copies of the front half, and the seal leaves a window where the
tracked patch is set aside.

## .the gap, precisely

- the repo shape, `--edit-dir` bound, installed versions and edit-dir state run in both
  `git.package.patch.begin.sh` and `git.package.patch.commit.sh`; the in-tree bound has four
  `is_inside_tree` call sites
- `commit.sh` reassigns `PACKAGE_VERSION` three times through the version ladder
- `operations.sh` sources all of `claude.tools/output.sh` for `is_path_within_repo_root`, which
  redefines five `print_*` names; only source order keeps this skill's renders in force
- `set_patch_aside` moves `patches/x.patch` to `x.patch.aside` for the length of `pnpm
  patch-commit`; a SIGTERM there leaves the tracked file absent and its manifest entry live
- `as_patch_note` renders the note fields and `is_note_of` matches the same literals; two owners of
  one format

## .the shape of the fix

- `set_call_target` (main shell, namerefs — a `refuse_*` inside `$(...)` exits only the subshell)
  resolves name, version, edit dir and state once; each phase passes its own fix command
- `get_one_version_to_seal --asked --dir-given --installed --open` returns a version or a named
  refusal; `VERSION_ASKED` and `VERSION_TARGET` replace the reassigned variable
- move `is_path_within_repo_root` into `claude.tools/path.sh`; `claude.tools/output.sh` sources it,
  so no other caller changes
- extract the front half gate by gate, one move at a time: `refuse_unless_pnpm_tree`,
  `refuse_unless_edit_dir_allowed`, `refuse_unless_dir_holds`. each block is a sequential
  `X || refuse_*` in the main shell, so a lift keeps the gate order and the refusal text; only the fix
  command becomes a parameter, and the snapshots stay put
- replace the set-aside move with a copy into the verb's own temp dir, outside `patches/`: compare
  the patch content before and after the seal (unchanged = naught sealed), copy it back on a pnpm
  failure. that deletes `set_patch_aside`, `set_patch_restored`, `del_patch_aside`,
  `set_patch_reverted`, the three revert branches and the SIGTERM window; lift the rest into one
  `set_patch_sealed` that returns `sealed | empty | failed`
- `get_patch_note_field` reads what `as_patch_note` writes; a round-trip test pins the format, and
  a future `retire` subcommand reads the note through it
- `begin` names a leftover `patches/x.patch.aside` (a seal killed mid-install) and says "rerun commit"
- refusal hints carry the `--why` and `--upstream` the crew typed, not the `'<why>'` placeholder
- case=6: the several-versions refusal gives one command per installed version, not one for the latest
- the seal backs up every file it touches — patch, manifest, `pnpm-lock.yaml`, note — via one owner
  `get_all_seal_files`, and the success output prints that same list
- `is_hoisted_repo` asks pnpm (`pnpm config get node-linker`) rather than regex two files, so a
  user-level rc or an env override is read too
- one `refuse_unless_edit_dir_allowed` runs at gate 7 on the resolved dir for both the default and
  the given dir; `del_edit_dir` takes `--within` and checks the bound before its `rm -rf`
- the pure bound primitives (`is_inside_tree`, `is_edit_dir_allowed`, `is_package_name`,
  `is_path_with_parent_segment`, `as_package_*`, `is_upstream_link`, `is_note_of`) move to one file
  with a data-driven table test, so path shapes stop to pay a real pnpm install each
- the seal tests run `pnpm install --frozen-lockfile` after the seal, and one real amend journey
  (reopen over a prior patch, add a second edit, seal with a new why) asserts both edits live
- the seal deletes only what the verb owns: `rm -rf` only under `$root/node_modules/.pnpm_patches/`;
  a custom in-tree `--edit-dir` stays, with a "remove it" line in place of `removed`. that one
  predicate replaces the delete half of the `--edit-dir` denylist (r011 i015 #2; vision case 3
  `[t2]` does not say whether a custom dir is removed, so it is a design call — fulcrum F12)
- pure transformers: `as_install_cmd` takes `declared` as an input (the caller asks
  `is_dependency_declared`); `is_edit_dir_allowed` drops its `-L`/`-e` probe and its
  `--given`/`--from` params, now that `realpath -m` resolves a broken link (r011 i015 #3)
- one `get_edit_dir_identity --dir` owns the edit dir's `package.json` read + shape check, in place
  of the twin reads at begin and commit (r011 i015 #4)
- one `run_pnpm --root -- <args>` owns cwd, closed stdin, stderr merge, and
  `--config.confirmModulesPurge=false` for all three pnpm calls, `patch-commit` included; it is
  also the one place to read or gate `pnpm --version` (r011 i015 #5)
- one `get_local_patch_state` (`none | open | sealed | entry-lost | note-differs`) that begin,
  commit, and a future `retire` read, in place of today's `get_sealed_patch_gap` beside a file check
- refuse a blank or one-character `--why`; `begin` on an open dir hints "to start fresh, remove the
  dir"; redirect raw `pnpm patch-remove` in `commands.alternatives.jsonc`; the plan warns the seal
  install may take minutes; a custom `--edit-dir` gets an ignore hint so `git add -A` skips it
- one `get_package_manager` lifted to `skills/` for git.package.patch, set.package and
  git.branch.rebase, which today give three answers for one question (a seed for the org, too)

## .why it is not done in this round

safe, and per gate clean, but the sum is a review round of its own: the seal rework changes the
crash path every revert test pins, and the path move touches `claude.tools/output.sh`, which other
skills source. the one security invariant here — the edit-dir bound — already has one producer
(`is_edit_dir_allowed`) and one clamp per phase (`[t22]`, `[t23]`), so no behavior waits on the
extract. fulcrum F12 records the call.
