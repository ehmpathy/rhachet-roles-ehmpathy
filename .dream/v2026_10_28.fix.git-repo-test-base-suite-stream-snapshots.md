# 🌙 dream: git.repo.test base suite snaps both streams, under their names

kind: fix · owner: repo=ehmpathy mechanic · caught 2026-10-28

## .the cue that fired

5.3 peer review (`ergo-contract-snapshots` i002 blocker.1, `ergo-snapshot-visual-blemishes`
blocker.1) on `fix-repo-test-grove-suite-bound` read the base suite's failure snapshots as stdout
renders with a broken tree.

## .the gap, precisely

`git.repo.test.integration.test.ts` titles every snapshot `output matches snapshot`. success cases
snap `result.stdout`; failure cases snap `result.stderr`, which holds only the tail the skill tees
(see `fix.git-repo-test-headless-stderr-tree`). a reader cannot tell which stream a snapshot holds,
and no case snaps both. both streams are asserted by `toContain`, so no behavior is unproven; the
render of the other stream is.

## .the shape of the fix

per case, two thens: `stdout matches snapshot` and `stderr matches snapshot`. success → stderr
`""`; failure → the full stdout tree plus the stderr tail. do it after the headless-stderr fix,
so the stderr snapshots are written once, in their final shape.

## .why it is not done in this round

safe, not clean: ~17 cases and their snapshots, in a suite the grove touched for six lines, and
its stderr half is better written after the headless-stderr fix. fulcrum F27 records the call.
