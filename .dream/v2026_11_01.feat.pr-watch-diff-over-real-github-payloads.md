# 🌙 dream: feed real github payloads through the watch diff

kind: feat (test) · owner: repo=ehmpathy role=mechanic (git.pull.watch) · caught 2026-11-01

## .the cue that fired

5.1 i005 r010 test realism: only `pulls/N` is read from real github. the fields `WATCH_DIFF_JQ`
reads from check-runs, comments, and reviews come only from the stub. the shared clone login
proved the gap: real clone comments come from a `User`, not a `Bot`, and the fixtures said `Bot`.

## .the gap, precisely

- no test runs the diff over a real check-runs, issue-comments, review-comments, or reviews body
- the review shape is unconfirmed against real data; no recent pr in the org holds one

## .the shape of the fix

- in `github.real`, read the five endpoints of one public, merged ehmpathy pr that holds a
  review, an inline comment, and a failed run
- pipe them through `WATCH_DIFF_JQ` with a cursor at zero; assert each event kind and each
  field the render reads (`path`, `line`, `user.type`, `submitted_at`, `completed_at`)
- a clock-skew case beside it (r010 lower): `fresh()` compares github time to the local
  `setAt`; a slack of a minute, or the pr's own `updated_at` as the floor, keeps a laptop
  clock that runs ahead from a swallowed prime event
- an absent timestamp (5.1 i006 r007 nitpick.1): `fresh()` reads a null `completed_at` as
  older than the watch, and the run's id still joins `checkRunIdsSeen`, so it never alerts.
  once real payloads prove which fields github always sends, a failed run with no
  `completed_at` reads fresh on the prime tick (its id cursor then quiets repeats); the stub
  fixtures that omit the field gain it first, so no prime-tick alert changes by accident
