# 🌙 dream: the tty-guard branches have no pty harness, so they are dead under test

- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-ehmpathy`
- **caught** = 2026-09-10

## .the cue that fired

peer review `i004` `behavior-intent-coverage` nitpick.1:

> *"no test reaches this branch: every spawn in `git.commit.sponsor.integration.test.ts` pipes
> stdin (`stdio: ['pipe','pipe','pipe']` and `input: args.stdin ?? ''`), so `-t 0` is always
> false and the branch is dead under test. … A refactor that deleted the `-t 0` check would ship
> green and a human would meet a hang."*

correct, and the consequence is the sharpest kind: **a hang**. an error is legible; a hang
reports naught at all (`rule.require.status-feedback`).

## .the gap, precisely

the guard, in `git.commit.sponsor.sh`:

```bash
if [[ -t 0 ]]; then
  … print_tree_error "--who @stdin expects a pipe, and none is piped" …
  exit 2
fi
SPONSOR_RAW=$(cat)
```

⇒ `cat` on a terminal blocks forever. the guard exists precisely to turn that into a message.

🟡 **and it is not the only `-t 0` in the family** — the human-tty actor guard in the same skill
(and its twins in `git.commit.uses.*`) is reached under test only via the `__I_AM_HUMAN` escape
hatch, never via a real tty. ⇒ **the escape hatch itself is unclamped**: an edit that made
`__I_AM_HUMAN` the *only* accepted signal would ship green.

## .the shape of the fix

a pty seam in the harness, then one test per `-t 0` branch:

1. add a `runInPty(cmd, args)` helper — either the `node-pty` package, or the unix `script(1)`
   executable via `script -qec <cmd> /dev/null`
2. `[case7]` gains a `--who @stdin` at a real tty ⇒ assert exit 2 and the curated message,
   **with a timeout** so a regression fails fast rather than hangs the suite
3. the actor guard gains a real-tty pass, so `__I_AM_HUMAN` stops being the only route in

🔴 **the timeout carries the weight here.** a test for a hang-prevention guard that itself hangs
on regression converts one defect into a stuck CI run.

## 🔴 .the price, MEASURED — and it is far lower than this dream first claimed

**re-measured 2026-09-12, at i015, after six review lanes had each been told the cost was "a new
native dependency".** that answer was wrong, and the correction is the most useful thing in this
file.

```
pnpm-lock.yaml:9324   optionalDependencies:
pnpm-lock.yaml:9325     node-pty: 1.2.0-beta.15      ← ALREADY IN THE LOCK (transitive, via rhachet)
```

it ships **prebuilds**, so there is no native compile at all:

```
node_modules/.pnpm/node-pty@1.2.0-beta.15/node_modules/node-pty/prebuilds/
  ├─ linux-x64/pty.node        ├─ darwin-x64/pty.node
  └─ linux-arm64/pty.node      └─ darwin-arm64/pty.node
```

and it **works on this host today**. a throwaway probe loaded it from the store and ran a bash
child under a real pty:

```
PTY_PROBE_REPORT { "loaded": true, "observed": "T0_TRUE\nT1_TRUE\nT2_TRUE" }
```

⇒ 🎯 **all three `-t` tests read TRUE.** the harness this dream calls expensive is a solved
problem sat in the lock file.

### what actually remains

**exactly one gap: pnpm is strict, so an undeclared transitive is NOT resolvable.**
`node_modules/node-pty` does not exist at top level. the ask is therefore a **one-line
devDependency promotion** at the version already locked — never an install of anything new.

| the old claim | the measured truth |
|---|---|
| "a new dependency" | already in `pnpm-lock.yaml`, via `rhachet` |
| "with a native build step" | prebuilt for linux-x64/arm64 and darwin-x64/arm64 |
| "needs a security audit of a new package" | the package is already installed and loaded by the toolchain |

## .why it is STILL not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`) — **CLEAN still refuses it, but
for a DIFFERENT and much narrower reason than the one above.**

| route | why not now |
|---|---|
| the unix `script(1)` executable | a bare host dep, and its flags DIFFER between the linux (util-linux) and macos (bsd) builds. `rule.forbid.bare-host-deps` names this class outright. **unchanged** |
| `node-pty` | 🔴 **cost was overstated.** what remains is a HERMETICITY call: it is `optional` upstream, so a host whose install skips it would meet a **broken suite** rather than a skip — and a skip would be `failhide` (`rule.forbid.failhide`). a devDependency every test file inherits is a repo-wide portability decision |

⇒ the route is a **harness** change that outlives this feature and serves several skills, so it
wants a deliberate choice rather than a smuggled one beside a sponsor guard. ⚠️ and this org has
history here — `ehmpathy/rhachet @ beav/fix-node-pty-install` is a whole branch about this
package's install.

⚠️ **what is NOT a reason:** "the branch is small". it is small and it prevents the worst
failure mode the skill has. the deferral is about the COST OF THE HARNESS, never the value of
the clamp.

✅ **corroborated by an independent second opinion**, sought before any escalation
(`rule.always.get-a-second-opinion-before-foreman`). it searched the lock, the store, and every
test harness, and returned the same verdict in its own words:

> *"the claim's premise ('no pty library is present') is **false** … [the] library is already
> reachable … which **shifts the question from discovery to policy**."*

⇒ two independent measurements, one conclusion: **the blocker was never the build.**

🔴 **and the lesson this dream now carries for its next reader: a deferral is only as honest as
its price tag.** six lanes accepted "a new native dependency" without a challenge, because it
sounded expensive and nobody re-measured it — myself least of all. **an estimate repeated across
rounds hardens into a fact.**

`@stdin` empty-pipe path is covered by `[case7][t2]`. ⇒ the tty branch is the one hole left, and
this dream is what keeps it visible.
