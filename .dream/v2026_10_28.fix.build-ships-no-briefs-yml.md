# 🌙 dream: the build must ship briefs/**/*.yml so review.by works from a published package

kind: fix · owner: repo=ehmpathy mechanic · caught 2026-10-28

## .the cue that fired

5.3 verification on `fix-repo-test-grove-suite-bound`: a fresh `npm run build` left no
`dist/domain.roles/*/briefs/reviews/rubrics.yml`. the published 1.39.9 lacks `briefs/reviews/` too.

## .the gap, precisely

`build:complete:dist` in `package.json` uses an rsync allowlist. it includes `briefs/**/*.md` and
`briefs/**/*.min`, but no `*.yml` under briefs. `review.by.sh` reads
`$ROLE_DIR/briefs/reviews/rubrics.yml` and exits 2 with `rubrics.yml not found` when it is absent.
so `rhx review.by` fails in every repo that installs this package.

the test suite cannot see it: `review.by.integration.test.ts` runs the skill from `src/`.
with the include reverted and a fresh build, `[case5]` still passes (4 passed, 0 failed).

## .the shape of the fix

1. add `--include='**/briefs/**/*.yml'` after `--include='**/briefs/**/*.min'` in `build:complete:dist`
2. clamp: an acceptance test that runs `review.by` from the built `dist` (or asserts
   `dist/domain.roles/mechanic/briefs/reviews/rubrics.yml` exists after a build). red before, green after

## .why it is not done in this round

the director's rule for this PR: the include rides only if the suite fails without it. it does not,
since no test reads `dist` for review.by. the fix needs its own clamp at the acceptance grain.
