## .the cue that fired

`pretooluse.forbid-shouted-readme [case6][t2]` and `pretooluse.forbid-cross-repo-access [case12][t0]`
went red together: malformed stdin exited **4**, where the contract is exit 0 with a loud warn.

## .the gap, as caught

both hooks allowlisted jq's parse-error exit by a version table (`2` for jq <=1.6, `5` for >=1.7).
the host's jq returns `4`, so the hooks took the rethrow arm and exited 4. a PreToolUse hook that
exits nonzero blocks the tool call, so the declared fail-open shipped as fail-closed.

the table keyed on evidence for a fact (an exit code) rather than the fact (the input did not parse)
— the defect class this route repairs in `grepsafe.sh`.

## .the repair, as landed

both hooks now probe the fact:

```sh
if ! echo "$STDIN_INPUT" | jq . >/dev/null 2>&1; then
  emit_both "WARN: PreToolUse hook could not parse stdin as JSON; allow tool call"
  exit 0
fi
```

- `jq .` is the identity program. it always compiles and applies to any value, so its only failure
  is unparseable input. the version table and its comment are deleted.
- the rethrow arm stays on the extraction call, where parseability is settled, so a nonzero there is
  a genuine jq malfunction (`rule.forbid.failhide`).
- clamps assert `status === 0` and the warn text, never a jq exit number.
- measured: 2 reds → green. revert-checked: disable the probe in one hook ⇒ exactly that hook reds.

`permissionrequest.decide-permissions [case10][t5]` failed in the same run from an unrelated cause —
a snapshot mask that required a `jq: ` lead this host's jq does not emit. it is repaired in its own
test.

## .what is still owed

the two hooks carry the probe block verbatim, so a future change to it must land twice. lift it to
one shared place (`rule.prefer.most-common-denominator`).

## .why the lift is not done in this round

- **SAFE?** no. these hooks gate every tool call in a live session.
- **CLEAN?** no. a shared hook lib is a new structure across hook files and their tests.
