## .the gap, precisely

- **position predicates are scattered.** `phase × halt × from_kind` is read at five sites:
  `is_park_expected`, `guard_head_at_cutover_position`, abort's undo branch, abort's quota line,
  and the report. each site hand-derives what a phase implies (park made? cut made? unit spent?)
- **the pid-lock primitive lives in the meter's file.** `git.branch.uses.operations.sh` holds about
  150 lines of pid lock (`set_pid_lock`, `is_pid_lock_held_by_self`, the exit-release registry);
  the cutover worktree lock imports it from there. a third consumer pays for that home
- **the stage-grant read has four by-path copies**: `git.commit.set`, `git.stage.add`,
  `git.commit.uses.local`, and the cutover halt render (`get_halt_stage_block`). the halt mirrors
  stage.add's two gates (global blocker, then `.stage`) in the same order, by hand

## .the shape of the fix

1. a `get_cutover_position_facts` leaf: one table, keyed by phase, that answers `park_made`,
   `cut_made`, `switched`, `unit_spent`. every site above reads the table, none derives
2. lift the pid lock to `git.pid.lock.operations.sh` (or the shared `git.meter.operations.sh` the
   meter dream proposes); the meter and the cutover both source it
3. an `is_stage_granted` leaf in the commit domain that holds both gates; the four sites call it,
   and the halt render can then never say "ok" where stage.add refuses
4. the extant suites cover each: cutover cases 20, 36–43, 57, 61; `git.stage.add`; `git.commit.set`
5. a push-allowed probe in the commit domain (i008 r011 n3). the report's push hint mirrors
   `git.commit.push.sh`'s author test by hand; it should call the owner's predicate, as the plan's
   quota line already calls the real gate
6. one op-in-flight leaf (i008 r011 n4): `get_op_in_flight` + `get_op_settle_lines`, backed by a
   table of rebase, cutover, merge, cherry-pick, revert, bisect. rebase stops to hardcode cutover's
   state path; cutover stops to re-derive rebase detection and to source all of rebase operations
7. split `git.branch.cutover.operations.sh` by grain (i008 r011 n6): `.git.sh`, `.state.sh`,
   `.park.sh`, `.picks.sh`, `.preflight.sh`, a thin `.sh`. the park is the atom #531 cutback needs.
   split the test file per verb, with shared fixtures out of `describe`, and renumber cases
8. one errexit convention (i008 r011 n5): `park_tracked_edits` returns a `PARK_OUTCOME` as the pick
   loop does; add `shellcheck --enable=check-set-e-suppressed` (SC2310, SC2311) scoped to
   `skills/git.branch.*`
9. a cutover `take --whos ours|theirs` peer of rebase's take (i008 r010 b1). a delete-settle is
   paved now (git.stage.add stages a delete, case65); a side-take for many conflicts is not
10. a multi-commit squash note (i008 r010 n2). case 4 marks a one-commit squash "already on base";
    a squash of N commits matches none by patch-id, so the left-behind list carries no mark. the fix
    is a tree-equal probe of the base range, which `git cherry` cannot do
11. the spend and its phase write are two steps (i008 r011 n9); a kill between them makes abort say
    "no unit was spent". item 1's `unit_spent` fact, written with the spend, closes it. the
    i010 r011 shape: record `quota_before` in the claim state; the spend converges to
    `quota_before - 1`, and abort derives "spent" from the meter, not from the phase
12. pick-conflict foresight in the plan (i010 r010 n3). the plan foresees drops and carry halts, not
    pick conflicts. a full probe needs `merge-tree --write-tree` (git 2.38+), so it owes a version
    gate; a cheap first cut warns where a pick touches a file a left-behind commit changed
13. the report names the subject that landed (i010 r010 n4). a pick a human commits by hand, then
    `continue`, reports the pick's own subject; record the landed commit's subject instead
14. narrate `begin.sh` (i010 r011 #4): extract `get_base_branch_name`, `get_into_beside_name`,
    `guard_into_free`, and `drive_begin_apply` (claim, meter, park, cut, spend)
15. phase and halt literals as named predicates (i010 r011 #6): `get_cutover_phase`,
    `is_cutover_halted_on_pick`; the literals live in one place, so a misspelled phase fails loud
16. one `get_named_arg` transformer (i010 r011 #7) for the seven `key=value` loops, and
    `get_index_tree` joins the convention
17. begin and continue converge by step, as abort does (i011 r011 #1, fulcrum F20 option b). abort
    now marks `.aborting`, and skips each step already done. begin and continue still drive a
    phase machine whose resume rests on the position table (item 1). shape: each step guarded by
    the git fact it produces (branch at base, HEAD on <into>, pick sha landed), so a rerun from
    any kill point converges, and the phase becomes a hint, not a gate
18. the error detail keeps git's path lines, and the untracked scan covers directory-vs-file overlap
    (i011 r010 n4). `as_git_error_detail` keeps only the first `error:` line, so "would lose
    untracked files in them:" names no path; and a source that turned file `foo` into dir `foo/`
    with an untracked `foo/note.txt` passes preflight, then fails post-cut (no loss, no spend)
19. an empty pick says "holds no change", not "already on origin/main" (i011 r010 n5): probe the
    commit's tree against its parent's; the plan lists it under "will drop"
20. clamps for the probed-sound edges (i011 r010 n6): a submodule pointer carry, and a run from a
    subdirectory, so items 7 and 14's refactors turn red if they break them
