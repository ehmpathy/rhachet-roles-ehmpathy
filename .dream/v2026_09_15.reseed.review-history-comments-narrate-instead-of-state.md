# 🌙 dream: comment condense pass on the sponsor family

- **kind** = reseed
- **owner** = ehmpathy/rhachet-roles-ehmpathy

## .the cue that fired

`enroll-impl-arch-defects` (i038, stone `5.1.execution.from_vision`) found `git.commit.sponsor.sh`
and `git.commit.operations.sh` saturated with comments that narrate the review history itself —
e.g. "a prior form... MEASURED, by removal of this gate...", "this was BELOW, and that left a
hole...". this is the exact shape `rule.forbid.chronological-accretion` forbids (blocker-severity
under the mechanic's own rules): these read as a decision log, not a statement of current truth.

## .the gap, precisely

a comment should state what IS and its durable why, per `rule.require.timeless-comments`. a
comment that narrates a round-by-round revision history rots the moment the round is forgotten,
and it costs every future reader a re-derivation of "which of these layers is still true."

## .the shape of the fix

the repo already has a `condense` skill built for precisely this: run it over
`git.commit.sponsor.sh` and `git.commit.operations.sh` before this wish lands on `main`, and
confirm each comment left after the pass states current truth rather than the argument that
produced it.

## .why it is not done in this round

**SAFE: yes — text-only, no behavior change.**

**CLEAN: no.** both files are large (`sponsor.sh` 1276 lines, `operations.sh` 1753 lines, measured
2026-09-15) and mid-convergence on eleven review lanes whose `.taken` files cite specific line
numbers and comment text. a full condense pass now risks drift in exactly the citations this
round's own `.taken` files depend on — safer to run it once the stone is past review convergence,
right before the release.
