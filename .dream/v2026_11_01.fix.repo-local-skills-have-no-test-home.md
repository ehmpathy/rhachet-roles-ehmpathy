# 🌙 dream: repo-local skills need a test home

kind: fix · owner: repo=.this (rhachet-roles-ehmpathy) · caught 2026-11-01

## .the cue that fired

a new skill, `.agent/repo=.this/role=any/skills/chmodsafe.sh`, was paved so the
build could mark new skill files executable (a raw `chmod` is not paved). the rule
`rule.require.jest-tests-for-skills` asks for a jest test beside it, but jest's
`testMatch` excludes `**/.agent/**`, so no test there ever runs.

## .the gap, precisely

- every `.agent/repo=.this/role=any/skills/*.sh` ships untested; the rule cannot be met in place
- `chmodsafe` was proven by hand only: +x on 9 files, refusal of a non-`.sh` path (exit 2)
- the first paved file, which must itself be executable, had to be bootstrapped by a copy
  of an executable peer (`cpsafe` keeps the source mode), since naught paved sets a mode

## .the shape of the fix

- a tracked home for repo-local skill tests that jest collects, e.g.
  `src/.this/skills/<name>.integration.test.ts` that runs the `.agent/repo=.this/...` path
- or move repo-local skills into `src/domain.roles/<repo-role>/` with a build link
- then a test for `chmodsafe`: +x granted in a temp repo; refused for a non-`.sh`, a
  symlink, a path outside the git root; exit codes 0 / 2

## .why it is not done in this round

it changes where this repo keeps its own skills and how jest collects tests — a
structure choice outside the pr-watch daemon's scope.
