# 🌙 dream: route guard templates name a retired brain slug

- kind: reseed
- owner: the repo that ships the `1.vision.guard` template (bhuild behaver routes)
- caught 2026-09-26

## .the cue that fired

both l1 peer reviewers on `v2026_09_26.fix-git-sponsor` stone `1.vision` malfunctioned at brain
selection before they read a single artifact.

## .the gap, precisely

```
BrainChoiceNotFoundError: brain not found: fireworks/deepseek/v4-flash
```

rhachet 1.48.0 lists `fireworks/deepseek/flash/v4.1` and `fireworks/deepseek/pro/v4`. a guard
stamped from the template carries the old slug, so every new route's l1 reviewers break.
`rhx route.guard.upgrade --stone 1.vision` also fails to plan here: `unknown var: $slug`.

## .the shape of the fix

1. in the template repo, swap `fireworks/deepseek/v4-flash` → `fireworks/deepseek/flash/v4.1`
   across every `*.guard` template.
2. make `route.guard.upgrade` expand `$slug` (or name which template var it lacks), so extant
   routes can re-sync instead of a hand edit.
3. optional: a test that every brain slug in a shipped template exists in the installed registry.

## .why it is not done in this round

not SAFE, not CLEAN: the template lives in another repo, and this route's guard is sealed to the
driver (`route.mutate.guard` emits no output; the file stays blocked to Read/Edit).
