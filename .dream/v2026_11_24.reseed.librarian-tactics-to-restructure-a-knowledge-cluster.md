## .the shape of the fix

### the principle: a cluster is disjoint and exhaustive over its subject

three properties, each with its own test:

| property | applies to | the test | its failure |
|---|---|---|---|
| **disjoint** | claims, and the values of one axis | each claim lives in exactly one file, under one value | one claim in two places |
| **exhaustive** | the values of each axis | each value has a home; a forbidden cell still gets its file | a gap |
| **independent** | a pair of axes | a value on one axis does not limit the values the other can take | a fake hierarchy, or a flat product with dead cells |

disjoint and exhaustive grade the values within an axis. independent grades two axes against each other. the brief keeps the three words apart.

🟡 the name, vetted: **"partition"** is the math word, but the reviewer's `--partition` permits overlap, the opposite sense. **"MECE"** is an acronym. so the principle names its two halves in plain words.

precedent to fetch from primary sources: aristotle's division of a genus into species by differentia, via porphyry's tree · the set partition (blocks pairwise disjoint, none empty, union the whole) · minto's "mutually exclusive, collectively exhaustive".

### a howto: `howto.restructure-a-cluster._.md`

the moves, sorted by the property each one tests. each move cites the case that taught it.

| # | property | move | the test | the case |
|---|---|---|---|---|
| 1 | disjoint + exhaustive | **find the generic** | for each sibling: "what is this a kind of?" siblings of one generic → `$generic.kind=$value`; every member falls under exactly one kind | invariant, assumption, guarantee were kinds of constraint, filed as its peers |
| 2 | independent | **find every axis; test each pair** | independent → two flat coordinates, and the root holds the dimensions table. dependent → nest | kind × grain: every kind has both grains, so `constraint.grain=declaration.kind=…` would fake a hierarchy |
| 3 | exhaustive | **give every axis value a home** | each value has its own `define.*` before a catalog sorts by it | the declaration grain had no file; contract and construct had no definition |
| 4 | disjoint | **mark the generic value with `_`** | a member that applies to every value takes `$axis=_`, and no specific value repeats it | `kind=_.verb=set.tactic=separate` versus `kind=contract.verb=set.tactic=narrow`. `_` sorts first, and a `kind=*` glob still matches it. where a cell holds several members, the member name is its own coordinate (`tactic=`), never a bare slug |
| 5 | disjoint (of words) | **vet each axis word against the glossary** | taken here? overloaded? only the canon's word? → replace before it spreads | `grain` was taken; `yield` collided; `owner` and `boundary` read two ways; `module` appears in the canon, not our code; `act` collided with `rhx act`, so the key became `verb`; `partition` above |
| 6 | disjoint | **prune the members** | see the prune questions below | 14 tactics → 8 |
| 7 | disjoint | **one home per claim; symlink each peer** | a claim held in two files? the owner role keeps it; every other directory symlinks | `domain.terms/` copies → relative symlinks to the role briefs |
| 8 | disjoint | **strip overfit from examples** | does the example demonstrate a claim another brief owns? → cite that brief and cut the demo | an abstraction example taught a privacy rule |
| 9 | — | **sweep the rename in one pass** | old names in briefs, boot specs, test paths, snapshots: zero hits | 47 refs across 27 files, one sedreplace |

### the prune questions (move 6)

| the member | then |
|---|---|
| repeats a claim another brief owns | drop it; cite the owner from the root |
| differs from a peer only by the object it acts on | one move over a pair (separate · gather), or one member |
| is the use-half of a peer's set-half | split by a `verb=set|use` axis, not by topic |
| shares one smell with two peers | merge them; keep the strongest source, cite the rest |
| shows a smell no other member names | keep it |

| rule | property | severity | says | the cure it names |
|---|---|---|---|---|
| `rule.forbid.overlapped-claims` | disjoint | blocker | one claim in two places, at any of three scales: across directories (a definition copied into a shared terms directory), within a catalog (a member whose claim another brief owns), within a brief (an example that demonstrates another brief's concern) | the owner keeps it. a peer directory symlinks (`rhx symlink --mode relative --idem findsert`); a catalog root cites; an example cites and cuts the demo |
