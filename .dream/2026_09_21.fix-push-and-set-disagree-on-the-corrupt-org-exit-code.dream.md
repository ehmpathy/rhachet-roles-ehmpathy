# 🌙 dream: push and set disagree on the corrupt-org exit code

- kind: fix
- owner: repo=ehmpathy/role=mechanic
- caught: 2026-09-21

## .the cue that fired

a peer reviewer (`enroll-verif-snapshot-blemishes`, i005) raised a blocker that the SAME
"org meter file corrupt" state renders two different headlines, decided by which command
surfaces it. the repair unified the headline across all three surfaces — and while i read
the three arms side by side to make that change, a second divergence on the same state
surfaced that no reviewer had named.

## .the gap, precisely

one state — the org meter file cannot be parsed — exits two different codes:

| surface | file:line | exit | comment on record |
|---|---|---|---|
| `git.commit.set` | `git.commit.set.sh:761-763` | **1** | "malfunction — the file is damaged, not the caller's input" |
| `git.commit.push` | `git.commit.push.sh` (org blocker arm) | **2** | none |

`rule.require.exit-code-semantics` is explicit: exit 1 = malfunction (external error,
unexpected state), exit 2 = constraint (the caller must fix a thing they control). an
unparseable file on disk is not the caller's input, so `set`'s 1 is the correct grade and
`push`'s 2 is the drift.

checkable: `rhx grepsafe --pattern 'ORG_BLOCK_CORRUPT' --glob '*.sh'` shows the set arm
branches on it for the exit code and the push arm does not.

⚠️ **no test pins either value.** a grep of `git.commit.push.integration.test.ts` for
`orgStateRaw` / `org meter file corrupt` returns zero matches — the corrupt-org push path
has no coverage at all, which is why the divergence survived.

## .the shape of the fix

1. in `git.commit.push.sh`, at the org-blocker arm, mirror the set arm:
   ```sh
   if [[ "$ORG_BLOCK_CORRUPT" == "true" ]]; then
     exit 1  # malfunction — the file is damaged, not the caller's input
   fi
   exit 2
   ```
2. add the absent coverage to `git.commit.push.integration.test.ts` — a `[case]` that seeds
   `orgStateRaw: '{ this is not json'` and asserts exit 1, the shared headline, and the
   corrupt body. the `git.commit.uses.integration.test.ts` `[case37]` blocks are the model.
3. while there, check the other two guards in the push arm (global blocker, sponsor) for the
   same constraint-vs-malfunction question — the org arm is unlikely to be the only one.

## .why it is not done in this round

**SAFE: no. CLEAN: yes.** it lands in the diff already open, so it is clean — but it is an
exit-code change on a path with zero test coverage, which makes it a behavior change rather
than a repair. `rule.require.review-test-changes` is direct about this: do not degrade or
alter prior behavior that was not asked about, and prefer to surface the choice. the round's
blocker was the *render*, and the render fix stands on its own without this.

⇒ the divergence is now named in a comment at the site (`git.commit.push.sh`, the org arm)
so the next reader meets it with this dream cited, rather than re-derived.
