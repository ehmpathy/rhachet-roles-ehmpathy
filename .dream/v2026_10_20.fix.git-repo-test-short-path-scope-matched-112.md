# 🌙 dream: `git.repo.test --scope path://boot.budget` matched 112 files, not 1

- kind: fix
- owner: ehmpathy/mechanic (`git.repo.test`)
- caught: 2026-10-20

## .the cue that fired
`rhx git.repo.test --what integration --scope 'path://boot.budget' --mode apply` reported
`matched: 112 files` and ran the whole integration suite, LLM evals included, for 10+ minutes.
the full path `path://src/domain.roles/boot.budget.integration.test.ts` matched 1.

## .the gap, precisely
a path scope that names one file by stem fans out to the whole suite. the plan-mode preview
shows the count, but apply mode does not stop on a fan-out, so a cheap probe becomes an
expensive run.

## .the shape of the fix
1. find why `boot.budget` matches 112 (likely the `.` treated as regex wildcard plus a
   changed-file union, or a fallback to all on a parse miss)
2. clamp: a hermetic test where `path://boot.budget` must match only `*boot.budget*` files
3. consider: refuse apply when a scope matches > N files with no `--thorough`

## .why it is not done in this round
not safe+clean here: a scope-parse change in a shared skill ripples to every caller, and this
pr's mandate is boot budgets.
