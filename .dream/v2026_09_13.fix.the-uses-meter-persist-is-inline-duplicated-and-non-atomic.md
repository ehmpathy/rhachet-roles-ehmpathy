- **kind** = fix
- **owner** = `ehmpathy/rhachet-roles-ehmpathy`
- **caught** = 2026-09-13

## .the cue that fired

peer review `i026` `arch-opport-decomposition` nitpick.2:

> *"`git.commit.set.sh` apply mode writes the local uses-meter with a heredoc straight to the
> final path, in two near-identical copies (the normal write and the auto-revoke write). The
> change introduced `set_sponsor_state` (temp-file + mv, inner-directory) as the communicator for
> the sponsor file's persist boundary and made `write_org_file` atomic too, so the local meter is
> the one persist boundary in the family left inline and non-atomic in an orchestrator."*

🔴 **this is the WRITE-side twin of a dream already caught for the READ side**
(`v2026_09_10.fix.the-uses-meter-has-no-shared-reader-and-four-bare-jq-callers.md`). the reader
dream closed half of one boundary and left the other half unnamed, which is how a half-extracted
boundary reads as finished.

## .the gap, precisely

every other state file in this family now persists through a named atomic leaf. the uses meter
does not:

| state file | persist | atomic |
|---|---|---|
| sponsor | `set_sponsor_state` — temp + `mv` | ✅ |
| org meter | `write_org_file` — temp + `mv` | ✅ |
| 🔴 **uses meter** | **two inline heredocs** straight to the final path | 🔴 **no** |

the two copies, in one file:

```bash
# git.commit.set.sh — the normal decrement
cat > "$STATE_FILE" << EOF
{ "uses": $NEW_USES, "push": "$PUSH_ALLOWED", "stage": "$STAGE_ALLOWED" }
EOF

# … and again, ~20 lines on, for the auto-revoke
```

plus a third shape in `git.commit.uses.local.sh`'s `set` arm.

⇒ **two harms, and they are separable:**

1. **duplication** — the meter's JSON shape lives in three places. a new field lands in two of
   them and the third writes a meter that lacks it, which the bare-jq readers then read as absent
2. 🔴 **non-atomic** — a `cat >` truncates first. a crash, a full disk, or a kill between the
   truncate and the write leaves a **0-byte meter**, and the readers have no shape gate
   (the reader dream), so the tree is left in a state no code classifies

⚠️ **harm 2 is what makes this more than tidiness.** the sponsor and org files were made atomic
*this drive* on exactly that ground; the meter that gates every commit was left behind.

## .the shape of the fix

1. add `write_uses_state` to `git.commit.operations.sh`, as a mirror of `write_org_file`: render
   to a temp file **in the same directory**, `jq`-validate, then `mv -f`
2. route all three write sites through it — the two in `git.commit.set.sh` and the one in
   `git.commit.uses.local.sh`
3. pair it with `read_uses_state` from the reader dream; **they are one boundary** and should land
   together, so the shape gate and the write shape cannot disagree
4. a clamp per `rule.require.clamp-edge-cases`: a 0-byte meter mid-write must be unreachable —
   assert the final path is either the old content or the new, never empty. it must go **red**
   against the inline heredoc

⚠️ **it does NOT close the race** — `v2026_09_08.fix.git-commit-quota-read-modify-write-race.md`
still owes a lock. an atomic write makes each write whole; it does not make the read-modify-write
pair exclusive. two clones would still lose one decrement, just without a torn file.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`), and it fails **both** — for
the same reasons its read-side twin does:

| question | verdict |
|---|---|
| **SAFE?** | 🔴 **no.** this is the write that records a spent commit. a wrong edit either double-spends the quota or refuses a human's grant |
| **CLEAN?** | 🔴 **no.** three sites across two files, one of which (`uses.local.sh`) this change opened only for the sponsor nudge. it owes a clamp per site, and it should land with `read_uses_state` rather than ahead of it |

⇒ and the bound `arch-hazards-behavior` drew at `i003` and graded correct still holds: **the
sponsor state file is new, so its persist was this change's to get right. the uses meter is prior
art.**

⇒ itemized under fulcrum `F12` (ask 1's write-side half), per
`rule.always.catch-dreams-for-followups`: a deferral for DIRT owes both a dream and a fulcrum.
