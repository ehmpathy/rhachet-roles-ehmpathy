# 🌙 dream: qualify error headers in the skills beyond git.commit

kind: fix · owner: mechanic · caught 2026-09-27

## .the cue that fired

`fix-git-sponsor` migrated every git.commit refusal to `✋ ConstraintError:` / `💥 MalfunctionError:`
(the wisher ruled F12 = B). the unqualified `print_tree_error` in `git.commit/output.sh` had to
stay, since two other skills source that file and call it.

## .the gap, precisely

- `git.stage/git.stage.add.sh` — six `print_tree_error` sites, via `git.commit/output.sh`
- `git.repo.get/git.repo.get.operations.sh` — ~15 `print_tree_error` sites, via the same file
- `git.branch.rebase/git.branch.rebase.lock.sh` — its own local `print_tree_error`
- `librarian/skills/{brief.compress,brief.condense,kernelize}/output.sh` — each its own copy, plus
  raw `echo "error: …" >&2` lines (stderr only, which also breaks
  `rule.require.skill-output-streams`)

## .the shape of the fix

1. per skill, swap each `print_tree_error` for `print_tree_constraint` / `print_tree_malfunction`
   by the exit code beside it (2 → constraint, 1 → malfunction), as git.commit did
2. once `git.stage.add` and `git.repo.get` are migrated, delete `print_tree_error` from
   `git.commit/output.sh` so no unqualified leaf remains to call
3. the local copies (rebase lock, librarian) either source a shared leaf or define the two
   qualified leaves themselves
4. resnap each suite and read the diffs — the header line is the only expected change

## .why it is not done in this round

out of the wish: the wisher ruled the git.commit family, and each of these is its own skill with
its own suite. to pull them in would balloon one sponsor fix into a repo-wide render migration.
