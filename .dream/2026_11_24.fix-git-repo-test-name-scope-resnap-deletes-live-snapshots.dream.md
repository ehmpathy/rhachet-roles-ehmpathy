# 🌙 dream: git.repo.test name-scoped runs mistreat live snapshots

- kind: fix · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic · `git.repo.test`) · caught 2026-11-24, on route `v2026_11_24.fix-crew-pr-edit-via-paved-verb` stone 5.1

## .the cue that fired
a scoped resnap, `rhx git.repo.test --what integration --scope git.commit.push.integration --scope 'name://case31' --mode apply --resnap`, deleted three snapshots in `git.commit.push.integration.test.ts.snap` whose tests still exist (`[case14c]`, `[case14d]`). a full-file resnap restored them.

## .the gap, precisely
- with a `name://` scope, jest reports the snapshots of `[case14c]` / `[case14d]` as obsolete (`Snapshots: 3 obsolete`)
- `--resnap` then deletes them, silently, on a live test
- the plain scoped run exits non-zero (`✋ failed`) while it reports `1 passed, 0 failed`, because of the same obsolete count
- the skill's own `--help` names `name://` + `path://` as "the fastest feedback loop", so the pit leads straight here

## .the shape of the fix
- under any `name://` scope, pass jest `--ci=false` without `-u` semantics that remove obsolete, or refuse `--resnap` with a `name://` scope and name the file-scope rerun as the fix
- do not count obsolete snapshots as a failure when the run is name-filtered
- clamp: a temp suite with two tests, a `name://` resnap of one must leave the other's snapshot intact; red before, green after

## .why it is not done in this round
another skill's contract and tests; outside the wish's scope (push help). a fix here would widen the pr past the commander's review bound.
