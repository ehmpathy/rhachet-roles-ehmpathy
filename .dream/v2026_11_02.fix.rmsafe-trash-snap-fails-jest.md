# 🌙 dream: a snap that rmsafe trashed fails the next jest run

- kind: fix
- owner: mechanic (rhachet-roles-ehmpathy, rmsafe)
- caught 2026-11-02

## .the cue that fired

`rhx rmsafe blackbox/__snapshots__/git.pull.watch.acceptance.test.ts.snap`, then the suite: 9 of 9
tests passed, yet the run failed on `1 snapshot file obsolete`, named at
`.agent/.cache/repo=ehmpathy/role=mechanic/skill=rmsafe/trash/blackbox/__snapshots__/…snap`.

## .the gap, precisely

rmsafe keeps its trash inside the repo, under `.agent/.cache/`, with the same relative path. jest
scans that dir, finds a `.snap` with no test beside it, and fails the run as obsolete. a delete
that a human may undo turns into a red suite.

## .the shape of the fix

- either jest ignores `.agent/.cache/` (`testPathIgnorePatterns` + `modulePathIgnorePatterns` in
  each jest config), or rmsafe trash sits outside the repo (`~/.rhachet/storage/…/trash/<repo>/`)
- a clamp: rmsafe a `.snap`, run its suite, expect no obsolete file

## .why it is not done in this round

a change to rmsafe or to the jest configs, which this route does not touch; outside the pr-watch
scope.
