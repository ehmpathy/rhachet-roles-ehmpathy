# 🌙 dream: `--paths-wout` matcher has no brace support, and fails silently

- **kind** = fix
- **owner** = ehmpathy/rhachet-roles-ehmpathy
- **caught** = 2026-09-15

## .the cue that fired

stone `5.1.execution.from_vision` set `--paths-wout '**/{__snapshots__/**,*.test.ts}'` on 5 l1
review lanes to fit a context window. the debug logs
(`.log/bhrain/review/*/input.scope.debug.json` + `tokens.expected.md`) showed no files excluded —
every snapshot and test file the pattern was meant to drop still landed in the target set, with no
error and no warning.

## .the gap, precisely

`isPathMatchedByGlob` (`rhachet-roles-bhrain/dist/domain.operations/review/isPathMatchedByGlob.js`)
is the function `stepReview.js` calls to apply `--paths-wout` (and the `!`-prefixed half of
`--paths`). it is not a real glob matcher — it supports only three modes: exact match, a suffix
match on the final path segment, and a naive `*`/`?` → `.*`/`.` regex substitution. any other glob
metacharacter (`{}`, `[]`, `!` inside a pattern, extglob) is left as a literal regex character. a
brace pattern like `{a,b}` becomes the literal regex text `{a,b}`, which no real file path
contains — so the pattern compiles, runs, and matches no file, with no error surfaced anywhere.

this is a silent-failure class: the flag is accepted, the log shows the pattern as given, and the
absent exclusion looks identical to "the pattern legitimately matched zero files."

a second, adjacent find: the docstring above `isPathMatchedByGlob` calls its input a "negative
glob pattern" and the cli help calls `--paths-wout` a glob flag — both overstate what the function
actually supports.

## .the shape of the fix

swap the hand-rolled matcher for the same `globby`/`fast-glob`-backed matcher `enumFilesFromGlob`
already uses for positive patterns (see `enumFilesForReviewSubjects`), so `--paths-wout` gets real
brace/extglob support and the two matchers do not silently diverge in what "glob" means. short of
that, `isPathMatchedByGlob` should throw or warn on an unrecognized metacharacter rather than
compile it as a literal and match no file.

## .why it is not done in this round

**SAFE: yes — the fix is isolated to one matcher function's implementation.**

**CLEAN: no.** the fix lives in the `rhachet-roles-bhrain` package (a dependency), not in this
wish's own diff — out of this stone's bound scope. the workaround this round used instead:
`--paths '!**/*.test.ts' --paths-wout '**/__snapshots__/**'` (two single-metacharacter-free
patterns, each routed through the same limited matcher, which handles bare `*` correctly).

⇒ recorded here rather than worked around silently — the workaround is real, but it does not
repair the matcher's own unadvertised limit.
