## .the gap, precisely

1. `check.timestamps.lock.sh`: `TIMESTAMPS_LOCK_DISK=$(git hash-object -- "$TIMESTAMPS_LOCK_HOOK")` has no `|| timestamps_lock_malfunction`. a failed hash renders as a changed-hook ConstraintError, exit 2, where the truth is a malfunction, exit 1.
2. `check.timestamps.lock.sh`: the hook path comes from `$0`. an absolute `$0` makes `git ls-files -s` match naught, exit 0, so a staged edit passes the index check (fail open).
3. `check.timestamps.lock.sh`: no `set -eu`, unlike its two peers.
4. `check.secrets.sh`: `openai-style key` (`sk-(proj-)?…`) precedes `anthropic key` (`sk-ant-…`) and matches it first, so an anthropic key is labeled openai and the anthropic row never fires.
5. `check.secrets.sh`: the `set -eu` comment says the scan pipelines end in `head`; they end in `cut`.
6. no test pins any of the three hooks' refusals.

## .the shape of the fix

- `|| timestamps_lock_malfunction` on the hash read; anchor the hook path at `git rev-parse --show-toplevel`, repo-relative; treat an empty index read of a tracked hook as a malfunction; `set -eu`
- move `anthropic key` above `openai-style key`, or exclude `sk-ant-` from the openai pattern
- fix the comment to name `cut`
- a jest `.integration.test.ts` per hook, in a hermetic temp repo, snapshot + asserts on each refusal
