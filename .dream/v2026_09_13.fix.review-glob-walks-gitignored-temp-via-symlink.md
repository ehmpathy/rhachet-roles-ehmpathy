# 🌙 dream: the reviewer's glob walks gitignored dirs, and a symlink takes it out of the repo

- **kind** = reseed (the fix lives in `rhachet-roles-bhrain`, not here)
- **owner** = the bhrain reviewer maintainer
- **caught** = 2026-09-13

---

## .the cue that fired

nine of eleven peer-review lanes died with `FATAL ERROR: Ineffective mark-compacts near heap limit
Allocation failed - JavaScript heap out of memory` at the 2GB node cap, after 13–15 minutes. i014 and
i015, every l1 lane, every round. **the stone could not pass because no cheap reviewer could run.**

the log dir was **empty** for every dead lane, which is the tell: `stepReview.js:314` writes
`input.scope.debug.json` *before* validation — a write its own comment describes as *"enables debug
even on failure."* ⇒ the process dies upstream of every artifact it would leave behind.

## 🔴 .the gap, precisely — measured, with a control

`enumFilesFromGlob.js` walks with `followSymbolicLinks: true` (line 149) and prunes only two paths:

```js
const filesFromGlob = await globby(positivePatterns, {
  ignore: ['**/node_modules/**', '**/.git/**', ...negativePatterns],
  followSymbolicLinks: true,     // ← "supplies live behind .agent symlinks"
  ...
});
if (!input.gitignore) return filesFromGlob.slice().sort();
const allowed = getGitFilesNotIgnored({ cwd });   // ← the git filter runs AFTER the walk
return filesFromGlob.filter((file) => allowed.has(file)).sort();
```

🔴 **the gitignore filter is applied to the RESULT, never to the traversal.** so a gitignored
directory is still fully walked, every entry materialized into a JS array, and only then discarded.

and this repo has:

```
.temp/genTempDir.symlink -> /tmp/test-fns/<branch>/.temp
```

⇒ `.temp` is gitignored, is **not** in the ignore list, and is a **symlink out of the repo**. with
`followSymbolicLinks: true` the reviewer walks the shared test-fixture store. measured today:

```
tree .temp/genTempDir.symlink/   →   10,172 directories, 12,918 files
```

every integration test run adds fixture dirs (`<timestamp>.<slug>.<hash>/.claude/`) and **none are
ever removed**, so the cost grows monotonically with test activity. that is why i013 ran and i014 did
not: the suite was exercised heavily between them.

### the control that proves it

the reviewer's exact subject glob, same tree, same options — one variable:

| ignore list | result |
|---|---|
| `['**/node_modules/**', '**/.git/**']` — what the reviewer uses | 🔴 **TIMEOUT >60s** (→ 2GB / ~13min) |
| the same, plus `'.temp/**'` | ✅ **4,975 files in 2.6s** |

and the isolation walk that named the subtree:

```
.agent → 744 files 0.5s   .behavior → 4155 0.4s   .claude → 7    dist → 722
src → 1020                .log → 1165             node_modules → 0 (ignore works)
.temp → 🔴 TIMEOUT (>25s)          . → 🔴 TIMEOUT (>25s)
```

⇒ **every other subtree in this repo walks in under a second. `.temp` alone is unbounded.**

## .the shape of the fix

three levers, in the order they should be reached for:

1. 🔴 **prune gitignored dirs from the WALK, not the result.** ask git for the ignore set first and
   pass it to globby's `ignore`, or use globby's own `gitignore: true`. this is the root fix, and it
   also removes the post-filter allocation entirely.
2. **add `.temp/**` and the other well-known junk roots to the default ignore list.** cheap, partial,
   and it does not generalize to the next gitignored dir someone adds.
3. ⚠️ **reconsider `followSymbolicLinks: true`.** its stated reason is *"supplies live behind .agent
   symlinks into node_modules"* — a real need for the **supplies** globs (`--rules`, `--refs`). it is
   not obviously needed for the **subjects** glob, which walks the repo's own work. a per-call option
   would keep the supplies functional while it holds the subjects walk inside the repo.

⚠️ **lever 3 is the one that makes the defect dangerous rather than merely slow**: a symlink lets the
subjects walk leave the repository entirely. `.radio -> /home/vlad/git/...` (a *different user's*
home) sits at this repo's root too — it happens to be broken here, so it cost 0 files. **if it
resolved, the reviewer would have read another user's files.**

## .why it is not done in this round

**SAFE 🔴 CLEAN 🔴.**

- **SAFE fails** — the change alters what every reviewer in every repo can see. a wrong ignore rule
  silently shrinks review scope, which is the one defect class a reviewer cannot self-detect.
- **CLEAN fails** — the file is `rhachet-roles-bhrain/dist/domain.operations/review/enumFilesFromGlob.js`,
  a published package this wish does not own. the wish's subject is two hook scripts.

⇒ reseed, never a local patch. a `node_modules` edit would be erased by the next install and would
mask the defect for exactly one machine.

## ✅ .the local relief, which is NOT the fix

**taken 2026-09-13 as F14: narrow the guard's own subjects glob off the repo root**, so the walk
never enters `.temp` at all.

```
- --paths-with '**/*.{ts,sh,md,snap}'                              → 🔴 TIMEOUT at 30s
+ --paths-with '{src,.behavior,.dream,.claude}/**/*.{ts,sh,md,snap}' → ✅ 3,572 files in 596ms
```

⇒ **driver-owned, in-guard, zero scope delta** — the 5 diff files the narrow misses are the 5 ` D`
deletions, which are not on disk, so the root-anchored glob missed them too.

✅ **proven end-to-end at i017**, from the lanes' own artifacts:

| | before (i014→i016) | after (i017) |
|---|---|---|
| `.log/bhrain/review/<ts>/` | 🔴 **0 files** — dead upstream of `stepReview.js:314` | ✅ **10 files**, incl. `input.scope.debug.json` and `output.review.md` |
| per-lane wall time | ~13–19 min, then a V8 heap fatal | ✅ **~2 min**, complete |
| `targetFiles` | never reached | ✅ **93** — the full diff |
| `contextWindowPercent` | never reached | ✅ **66.9%**, under the 75% bar |

⚠️ **it is relief, never a repair.** it works because *this* guard's diff happens to live under four
roots. the next guard, the next repo, and the next diff root each hit the same wall, and the walk
still follows `.temp` for any lane that must scan the repo root. **the fix is upstream.**

### the other relief, and why it was not taken

the fixture store can be emptied — it regrows with every test run, so it buys time rather than a
repair. ⚠️ **it is 10k+ directories outside the repo**, so it is a human's call to make, never a
driver's unilateral act.

## .the lesson worth more than the repair

🔴 **I diagnosed this wrong twice before I measured it, and both wrong answers were reasoned, cited,
and confidently written.**

| the claim | how it fell |
|---|---|
| *"the yield's 1762 lines OOM'd the reviewer"* — i014 | the restructure moved 1245 lines into `appendix/peer-rounds.md`, which is **untracked** and therefore still in `--diffs since-main`. **the corpus never shrank.** I measured one file's line count: real, precise, and an answer to a question nobody asked |
| *"the 977KB `--conversation` corpus is the input that grew"* — F13 | correlated and wrong. spent a guard edit that cost every l1 reviewer its memory of fifteen rounds, and fixed naught. **reverted once measured** |

⇒ **the first instrument I reached for twice was a plausible number rather than a controlled
experiment.** what settled it in under ten minutes was a control: *run the same glob with one variable
changed.* it was available from the first round.

⚠️ and the tell was on the page each time — F13 was itemized at **70% confidence** with *"I never
measured the OOM's source"* written into it. **a flagged low confidence is a prompt to measure, never
a licence to proceed.**
