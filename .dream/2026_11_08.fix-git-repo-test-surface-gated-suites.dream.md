- kind: fix

- caught 2026-11-08

## .the cue that fired

the enroll-impl-behavior-intent lane on the pressViaPipeline route found two gaps on the paved crew path.

## .the gap, precisely

1. `rhx git.repo.test --what integration --scope path://pressViaPipeline --mode apply` prints `🎉 passed … 0 passed, 13 skipped`. jest's `✎ todo [gated: live brain] … run with BRAIN_LIVE_SCOPE=all` row lands only in the raw log, which is omitted on success. a crew member reads green as proof the live check ran
2. the on-demand form `BRAIN_LIVE_SCOPE=all rhx git.repo.test …` is an env prefix, which the permission hook does not pave. `git.repo.test` has no flag to pass the scope through, so a clone cannot run a gated suite

## .the shape of the fix

1. in the stats branch, add `todo: N` when jest reports todos, and list each todo name below it
2. add `--live-brain all` to `git.repo.test`. it sets `BRAIN_LIVE_SCOPE=all` for the jest child, and validates the value against the same closed set
3. snapshot both outputs in `git.repo.test`'s integration tests

## .why it is not done in this round

both are skill changes to `git.repo.test`, with their own snapshots and permission surface. the pressViaPipeline wish is a ci gate on one suite.
