# 🌙 dream: the hardnudge lock must never prove a holder dead by elapsed time

kind: fix · owner: repo=ehmpathy mechanic · caught 2026-10-27

## .the cue that fired

5.3 verification on `fix-repo-test-grove-suite-bound`: a full `--thorough` integration run on a
loaded 4-core box lost nudge stamps in `_hardnudge.lib.integration.test.ts [case2]` (twelve writers
race on one nudge file). the wait cap was one cause, fixed and clamped there (`[case3]`, ~2s → ~6s).
this is the other path that can lose a stamp, and its failure never got proven or ruled out.

## .the gap, precisely

`_hardnudge.lib.sh` `set_hardnudge_lock`: a lock dir with no `pid` file for
`HARDNUDGE_NOPID_TRIES` (20 × 0.05s ≈ 1s) is taken over as "the holder died between mkdir and its
pid write". a LIVE holder descheduled for >1s in that gap loses its lock; two writers then
read-modify-write the nudge file at once, and the later `mv` erases the earlier record. the lib's
own header says "a wait time alone never proves a holder dead", and this path does exactly that.

in the failed run `wave-0` (likely the first holder) lost its record, which fits this path better
than the wait cap. the `[case2]` failure message now carries each absent path's hook stderr, so the
next red run names which path fired.

## .the shape of the fix

make the pid-less lock unreachable, so no timer is needed:
1. holder: `mkdir lock.$$`, write `lock.$$/pid`, then `mv -T lock.$$ lock` (atomic; fails while
   `lock` exists with content)
2. release: `mv lock lock.dead.$$` then `rm -r lock.dead.$$`, so `lock` is never seen empty
3. delete the nopid branch; a lock dir always holds a pid, and only `kill -0` proves death
4. clamp: a holder that stalls 2s between its claim and its pid write keeps the lock
5. check-permissions' `set_attempt_record` has the same shape; fix both

## .why it is not done in this round

safe, not clean: a lock protocol change in a hook every clone runs on every write, outside this
branch's wish. the wait-cap fix rode along because it was one constant with a red-green clamp.
