# 🌙 dream: git.commit.set cannot commit in a tree whose ambient drift rewrites the hooks

- kind: fix
- owner: mechanic, `git.commit.set` (rhachet-roles-ehmpathy)
- caught 2026-11-14, by .behavior/v2026_11_14.feat-pull-comment-hints-unanswered

## .the cue that fired
a commit of staged work refused: `.husky/check.timestamps.sh was changed … expected afea02d … found 151bc07 (in the index)`. the index held main's committed hook. the worktree held an uncommitted husky practice upgrade (modified `.husky/pre-commit` and `check.timestamps.sh`, untracked `check.secrets.sh`, `check.timestamps.lock.sh`) from before the session. git runs the worktree's hooks, so the new hook demanded its own upgrade be committed.

## .the gap, precisely
`--unstaged ignore` commits staged paths only, yet the hooks still run from the drifted worktree. the clone has no paved way to commit against the committed hooks: `git stash` is not paved, and `--no-verify` is no answer.

## .the shape of the fix
mirror `git.branch.rebase --unstaged ignore` (c4488aa, `git.branch.rebase.aside.operations.sh`): set aside unstaged paths under `.husky/` (or all unstaged paths) before `git commit`, then put them back, with the same lock and restore guarantees. clamp: a temp repo with a drifted `.husky/pre-commit` commits staged work green, and its drift is intact after.

## .why it is not done in this round
another skill's contract, outside this nano tree. this round needs the commit now, so a human approves a one-time set-aside.
