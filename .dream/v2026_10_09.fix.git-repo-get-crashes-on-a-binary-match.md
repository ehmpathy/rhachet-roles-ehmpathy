# 🌙 dream: git.repo.get lines crashes on a binary-file match

- kind: fix
- owner: ehmpathy/rhachet-roles-ehmpathy (mechanic `git.repo.get`)
- caught 2026-10-09

## .the cue that fired

`rhx git.repo.get lines --repos 'ehmpathy/*' --words 'fireworks'` printed 23 matches from
`declapract-typescript-ehmpathy`, then died:

```
├─ Binary file origin/main
│  >    0: pnpm-lock.yaml matches
💥 failed with an error
git.repo.get.operations.sh: line 1593: printf: pnpm-lock.yaml matches: invalid number
```

## .the gap, precisely

`git grep` emits `Binary file origin/main:pnpm-lock.yaml matches` for a binary hit. the parser
splits that line on `:` as if it were `<ref>:<path>:<lineno>:<text>`, so the path becomes
`origin/main` and the line number becomes `pnpm-lock.yaml matches`; `printf %d` at
`git.repo.get.operations.sh:1593` rejects it, and the whole multi-repo search aborts with exit 1.
every repo after the first binary hit goes unsearched.

## .the shape of the fix

- pass `-I` (`--no-binary` semantics: skip binary files) to the `git grep` call, or drop
  `Binary file ... matches` lines before the parse
- clamp: a temp repo with a binary file that contains the search word; assert exit 0, the text
  hits listed, and no binary row. revert → red with the printf crash

## .why it is not done in this round

- SAFE? yes. CLEAN? no — `git.repo.get` is outside the permission-hook subsystem this route
  touches, and the clamp needs its own fixture repo.
