dream =

give `rule.prefer.lowercase` teeth: a pretooluse hook that flags capitalized sentence-starts
and lone `I` in robot prose output, the same way the gerund + blocklist hooks give their
rules enforcement.

## .the problem

`lang.tones/rule.prefer.lowercase` is a good rule with NO enforcement path. it is a `prefer`
(nitpick), so no hook fires when a robot shouts a sentence-start. that leaves the rule to
lean on memory — and base-model capitalization gravity (capital sentence-starts, lone `I`)
overrides it under load, especially mid-task when attention sits on the work.

the rules that DO hold — gerunds, the term blocklist — hold because a pretooluse hook stops
the write cold. lowercase has no such teeth, so it drifts. the fix is enforcement, not a
clearer rule.

## .the shape

a pretooluse hook, kin to `pretooluse.forbid-terms.gerunds`, that scans robot prose in a
file write and flags:

- a capitalized sentence-start (first letter of a sentence is upper-case)
- a lone `I` used as a pronoun

on a flag: block + name the fix (lowercase it), same UX as the gerund hook, same
retry-same-operation override for the legitimate exceptions.

## .the hard part — the exemptions

lowercase is scoped tighter than gerunds, so the hook must exempt more. it must NOT flag:

- **code constructs** — class/type/constant refs (`DomainEntity`, `IsoPriceWords`, `BootYml`)
- **proper nouns / brands** — `openai`, `github`, `aws`, `ASD-STE100`, `Claude`
- **declared technical names** — domain ubiqlang terms
- **code blocks + inline code** — fenced ``` and `backtick` spans
- **verbatim quotes** — a cited quote keeps its original case
- **acronyms already governed by `forbid.shouts`** — do not double-grade

the risk: a naive "first letter of sentence is upper-case" check drowns in false positives
from the above. so the hook needs the same care the gerund hook took — a curated skip-set +
context awareness (skip code fences, skip inline-code, skip known proper nouns). worth a
plan/diagnose pass before a build, to bound the false-positive rate.

## .scope of application

the hook governs ROBOT prose output — the same surfaces the other lang hooks watch: file
writes of comments, briefs, docs, plans, commit bodies. it does NOT govern human-chat tone
in the terminal (no hook reaches that), so lowercase in live chat still leans on memory — but
the written artifacts, at least, gain a gate.

## .relation to telepath

this pairs with the telepath-role dream (`2026_08_26.telepath-role-for-bhrains`). there the
concern is: generic communication rules must migrate WITHOUT loss of mascot flavor like
lowercase. an enforcement hook here proves the mascot rule can hold its own teeth after the
generic rules leave — the seam works only if the mascot side is enforceable too.

## .provenance

surfaced 2026-08-26 when a human asked why the robot keeps its slips out of lowercase. the
honest answer: the rule is unenforced. this dream is that fix.
