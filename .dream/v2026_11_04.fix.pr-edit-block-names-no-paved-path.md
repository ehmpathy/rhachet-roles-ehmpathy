# 🌙 dream: the `gh pr edit` refusal names git.pull.description

kind: fix · owner: ehmpathy/rhachet-roles-ehmpathy (`src/domain.roles/mechanic/inits/claude.hooks/pretooluse.check-permissions.sh` + the mechanic boot) · caught 2026-11-04

## .the cue that fired
to set the pr #1263 body, `gh pr edit 1263 --body-file …` was blocked as unpaved. the refusal named no paved twin. the body shipped without its attribution line, and the gap was reported as "no paved pr body edit".

## .the gap, precisely
- a paved path exists: `rhx git.pull.description get|set` (since v1.41.0)
- the hook's paved-alternatives list for `gh pr edit` does not name it
- the mechanic boot lists `git.pull.title` and `git.pull.description` only as `ref`, so their purpose never reaches a clone's view
- so a clone that needs the body falls back to the raw command, meets the block, and stops

## .the shape of the fix
- map `gh pr edit --body*` → `rhx git.pull.description set --from <path|@stdin> --mode apply`, and `gh pr edit --title` → `rhx git.pull.title set`, in the hook's paved alternatives
- clamp: a hook integration test that runs `gh pr edit 1 --body-file x` and asserts the refusal names `rhx git.pull.description set`

## .why it is not done in this round
a hook outside this route's files; it would ride a pr about rebase.
