## .the shape of the fix

mechanical, one opener at a time:

| today | tomorrow |
|---|---|
| `🛑 BLOCKED: forbidden term(s) detected` | `✋ ConstraintError: forbidden term(s) detected` |
| `ERROR: hook received no input via stdin` | `✋ ConstraintError: hook received no input via stdin` |
| `⚠️  record NOT saved` | `💥 MalfunctionError: record NOT saved — could not update the file` |

### 🔴 the exit code does NOT move with the glyph

every one of these is a PreToolUse hook, where claude code reads exit 2 as **blocked** and any other
code as **permitted**. so a malfunction that gets "corrected" to `exit 1` opens the gate it guards:

```bash
echo "💥 MalfunctionError: the blocklist holds a term that is not a valid regex" >&2
exit 2    # ← NOT 1. exit 1 would permit the write.
```

⇒ the rule's own `🔴 .the PreToolUse exception` section carries this. read it before the sweep.

### ⚠️ each hook drags its snapshots

every converted hook owns an `.integration.test.ts` whose snapshots pin the stderr verbatim, plus
`toContain('BLOCKED')`-shaped assertions that `--resnap` will not touch. so the per-hook cost is:

1. swap the openers in the `.sh`
2. swap the string-literal assertions by hand — the suite goes red and names each one
3. `--resnap`, then read the diff line-by-line to prove it is **header-only**

## .why it is not done in this round

- **SAFE ✅** — a header string carries no control flow. no verdict, exit code, or term set moves.
- **CLEAN 🔴** — it ripples into 9 hook files, 9 test suites, and their snapshot sets, none of which
  this PR opens. that is a diff several times the size of its own subject, in files whose behavior
  this branch never touched.

⇒ deferred for dirt, so it carries a fulcrum beside it, per
`rule.always.fix-forward-under-scouts-honor`.
