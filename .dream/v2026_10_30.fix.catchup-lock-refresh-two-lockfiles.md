- kind: fix

## .the cue that fired
peer `enroll-verif-snapshot-coverage` read `lock.sh`: the package manager is picked from the first
lockfile found, pnpm, then npm, then yarn.

## .the gap, precisely
a repo that holds two lockfiles (a stray `package-lock.json` beside `pnpm-lock.yaml`) gets one
refreshed and staged; the other stays as it was, and the render says naught of it. `continue`
then commits a merge whose second lockfile is main's or the branch's, unrefreshed.

## .the shape of the fix
read every lockfile present. one → refresh it, as today. more than one → refuse, exit 2, name
each file and the `packageManager` field (when set) as the tiebreak, or refresh each with its own
manager. which of the two is a product call; the refusal is the safe default. a lock case for
each, snapped.

## .why it is not done in this round
it adds a new refusal path to `lock refresh` with its own render and tests, and asks a product
question (refuse vs refresh all) the wish did not settle. the one-lockfile journey, the #1021
case, is whole.
