## .the gap, precisely

- the repair is a behavior change in `git.commit.set`'s gate, found while the cutover meter was built
- it has its own test in `git.commit.set.integration.test.ts`, but no commit of its own
- this route holds one commit unit, and the route lands as one commit

## .the shape of the fix

1. after the cutover lands, cut a branch from main: `rhx git.branch.cutover begin --from @main --into fix/commit-gate-zero-byte-meter`
2. if the cutover ever reverts, re-apply the `[[ -s ]]` hunk and its test there, as `fix(commit): ...`
3. if it never reverts, close this dream: the fix shipped, only its history is shared

## .why it is not done in this round

safe, not clean: a separate commit needs a second commit unit and a second branch, and the route
asks for one commit at its end. the repair is tested where it lives, so the only cost of the shared
commit is that one revert would undo both.
