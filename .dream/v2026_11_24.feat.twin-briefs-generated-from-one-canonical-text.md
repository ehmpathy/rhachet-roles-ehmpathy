## .the cue that fired

route `v2026_10_23.fix-arch-fundamentals`, stone `5.1`, peer review i005 (`enroll-impl-arch-defects`, nitpick.1): the `define.invariant` twins, shipped in architect and mechanic, stay equal only because `briefs.twins.integration.test.ts` fails on drift. a test is the weaker rung of the enforcement ladder this same route teaches (`define.enforcement`): it catches a drift after an author writes it; structure would make the drift unwritable.

## .the gap, precisely

- `src/domain.roles/architect/briefs/practices/domain.constraints/define.invariant.md` (+ `.md.min`) and `src/domain.roles/mechanic/briefs/practices/lang.terms/define.invariant.md` (+ `.md.min`) hold one shared text, typed twice
- a role boots only its own briefs, so the mechanic cannot boot the architect copy; that is why two copies exist
- each copy owns its `## .see also` (`.md`) or `see also:` line (`.min`), so its citations reach briefs its own role ships, with `(role)` marks on the cross-role ones

## .the shape of the fix

1. keep one canonical body per twin, e.g. `src/domain.roles/.twins/define.invariant.body.md` (and `.body.md.min`)
2. keep each role's see-also as its own small file beside where the brief ships
3. a build step (in `npm run build`, beside the brief copy to `dist/`) composes body + see-also + twin marker into each role's brief
4. the twins test then shrinks to a check that the built copies match their sources, or retires
5. the same mechanism serves any later twin with no new test code

## .why it is not done in this round

**SAFE: yes. CLEAN: no.** it adds a build step and a new source layout under `src/domain.roles/`, and changes where an author edits a twin. the test already fails on the first drift, each see-also is shape-checked (only citations, each reachable), so the harm a drift could ship is held today. fulcrum: `F26`.
