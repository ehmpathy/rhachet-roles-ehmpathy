# 🌙 dream: `git.repo.test` shows `inflight` forever, so slow reads as hung

- **kind** = fix
- **owner** = repo=ehmpathy (this repo)
- **caught** = 2026-09-11

## .the cue that fired

a 13-file integration scope was run under `git.repo.test`. it printed `💤 inflight (Ns)` every 15
seconds for 19 minutes and was killed as a hang.

**it was not hung.** a 3-file scope of the same suites finishes green in **109s** — about 36s per
file — so a 13-file scope legitimately needs ~8 minutes, and the poll line looks identical the
whole way.

🔴 **that ambiguity cost three wrong diagnoses in a row**, each written down before it was tested:
runqueue contention, then a specific suite blamed, then the truth. the full sequence is in
`.behavior/v2026_09_09.fix-hook-fork-storm/5.1.execution.from_vision.yield.md`.

## .the gap, precisely

`💤 inflight (405s)` carries exactly one fact: elapsed time. it does not say:

- how many of the N suites have finished
- which suite is live right now
- whether any assertion has run at all
- what a normal duration for this scope would be

⇒ so the human (or clone) cannot tell **slow** from **stuck**, which is precisely the gulf of
evaluation `rule.require.status-feedback` names:

> *"silence is ambiguous: the human cannot tell 'at work' from 'hung' from 'done'."*

a timer is not status. it is the **absence** of status with a clock attached.

## .the shape of the fix

jest already emits per-suite completion on stderr as it goes. the skill buffers it to a log and
shows only the timer. two moves, either of which closes the gap:

1. **report progress, not elapsed** — `💤 inflight (405s) · 7/13 suites · now: forbid-tmp-writes`.
   a count that advances is unambiguous: if it moves, it is slow; if it stalls, it is stuck.
2. **name the expectation** — on a scope of N files, print the prior run's per-file median so the
   reader knows ~8 minutes is normal before the wait begins, never after.

a third, cheaper and weaker: after some threshold, print the hint that already exists at the end —
`tip: use --log always to persist` — so a reader knows where to look mid-run rather than post-mortem.

⚠️ the slowness itself is real too (~36s per hook suite, since each spawns dozens of bash
processes), and it is a **separate** concern. this dream is about legibility: a slow run that
announces itself as slow costs patience; a slow run that looks hung costs a misdiagnosis.

## .why it is not done in this round

**SAFE: yes. CLEAN: no.**

- the fix lands in `git.repo.test.sh`'s output layer — a skill this wish never opens, whose whole
  subject is unrelated to the two forbid-terms hooks.
- it needs a read of how jest's per-suite events are captured and buffered today, plus a decision
  about output shape that belongs with the ergonomist's `rule.require.status-feedback` /
  `rule.require.treestruct-output`.
- ⇒ it ripples into files this change never intended to open, so it fails the CLEAN test
  (`rule.always.fix-forward-under-scouts-honor`).

⇒ the deferral is for **dirt**, so it owes a fulcrum as well as this dream. recorded as **F10** in
`.behavior/v2026_09_09.fix-hook-fork-storm/.fulcrums/`.
