# 🌙 dream: lift the fuzzy rank into a sourced lib

- **kind** = feat
- **owner** = repo=ehmpathy (mechanic role, `claude.hooks/`)
- **caught** = 2026-09-27

## .the cue that fired

a level-3 reviewer on route `v2026_09_26.fix-blocklist-nudge`: the "nearest paved command"
matcher (`get_osa_distance`, `is_subsequence`, `get_max_edits`, the five-tier scorer in
`get_ranked_hits`) has no tie to the permission domain, yet it lives private to one hook.

## .the gap, precisely

- two places already want it: rhx skill-name typo help (F5 of the source route: "rhx owns it"),
  and typo tolerance in `permissionrequest.decide-permissions.sh`
- today the only way to reuse it is a copy, and copies drift
- unlike the allow-matcher (F15's subject), the rank decides no allow vs deny, so a shared lib's
  worst case is a worse suggestion, never a gate that fails open

## .the shape of the fix

1. move the four procedures to `claude.hooks/lib.fuzzy-rank.sh`, sourced by the hook with a
   fail-closed guard (an absent lib → the block still holds, named as a malfunction)
2. keep the globals contract (`PART_WORDS` in, `RANK_HITS` out) or pass explicit inputs
3. re-measure case23 (block in < 3s with 500 rules) before and after — `source` adds a file read
4. wait for the second real consumer before the move (`rule.prefer.wet-over-dry`)

## .why it is not done in this round

safe: yes. clean: no — no second consumer exists yet, so the lift is speculative, and it adds a
sourced-file seam to a gate whose fail-closed contract this route just hardened.
