# 🌙 dream: a run with no changed test files should not claim a grove slot

- kind: fix
- owner: ehmpathy/rhachet-roles-ehmpathy, `git.repo.test`
- caught 2026-10-28, route `v2026_10_25.fix-repo-test-grove-suite-bound`, 5.3 peer i005

## .the cue that fired

`enroll-verif-snapshot-blemishes` nitpick.2: play `[case14]` and `[case21] [t0]` snapshots print
`🎫 slot.0 claimed`, then `files: 0 (no test files changed since origin/main)`.

## .the gap, precisely

an unscoped, non-thorough jest run (`--what unit --mode apply`) learns its file set from
`jest --changedSince origin/main` inside the run, after `set_grove_slot`
(`git.repo.test.sh`, the claim at "claim a grove slot before the suite runs"). on a busy grove such
a run waits behind real suites, claims, and does no work.

## .the shape of the fix

before `set_grove_slot`, for an unscoped non-thorough jest run, list the changed test files
(`jest --listTests --changedSince origin/main`, as `get_scope_file_count` does for a scope). zero
files → `grove: bypass (no test files)` and the extant `skipped` render, exit 0. the list costs one
jest start per run; weigh that against the wait it saves, and reuse the list for the run if jest
accepts a file list.

## .why it is not done in this round

dirty: it adds a jest list to every unscoped run, which adds load to the box the grove guards, and
it touches the run path shared by every jest type and its snapshots. F30.
