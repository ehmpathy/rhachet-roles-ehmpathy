# 🌙 dream: carry a watch's queued alerts inside its record

kind: refactor · owner: repo=ehmpathy role=mechanic (git.pull.watch) · caught 2026-11-01

## .the cue that fired

r011 nitpick.3 (5.1 i004): queue-then-advance re-queues an alert on every tick a cursor
write fails, and the outbox entry is a foreign key held in a filename (`${stem%.*.*.*}`).

## .the gap, precisely

- the alert lands in `outbox/` and the cursors land in `watches/` as two writes; a tick
  whose second write fails queues the same alert again next tick (a repeat, never a drop)
- the outbox name format and its stem parse must stay in step forever
- two deleters (the daemon and the verbs) must each find the outbox of a record

## .the shape of the fix

- the record holds `alerts: [{ text, tries, heldAt }]`; one atomic write commits alert and
  cursors together, so the repeat window closes
- the drain reads and rewrites the record under the key lock; the outbox dir, the stem
  parse, and the second deleter go
- decide it before the live-delivery tier lands (`v2026_11_01.feat.pr-watch-live-delivery-tier`),
  since that tier reads the queue
- the clone-scoped notes get a lane of their own (5.1 i006 r011 nitpick.5): paused, outage,
  and token-fault notes speak to a clone, yet ride the outbox of that clone's first watch, and
  die with it on a `del`; a clone-keyed lane (`notes/clone=<serial>.*`, root read from any live
  record of that clone) keeps the note while any watch of the clone stands. decide both
  addressees in one layout

## .why it is not done in this round

it changes the on-disk layout every suite reads; no install holds the layout yet, so the
rework stays clean until ship (fulcrum F27).
