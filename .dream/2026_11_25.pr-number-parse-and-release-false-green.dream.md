# 🌙 dream: git.commit.push reads a two-line pr number; git.release --watch reports green on unresolved checks

- kind: fix
- owner: rhachet-roles-ehmpathy (role=mechanic)
- caught 2026-11-25

## .the cue that fired

pr #1486 (`rhx git.commit.push --mode apply --auth as-human`), then `rhx git.release --watch`, twice.

## .the gap, precisely

1. `git.commit.push` on the as-human fallback rendered `pr: pr #1486` then a bare `1 (created)` line. its own watch step then refused: `--which must be a pr number; got '1486\n1'`. the pr number capture takes a second line from the gh output, so the auto watch never arms on this path.
2. `git.release --watch` on the feature branch, seconds after the push, rendered `👌 all checks passed` and `🫧 no runs inflight`. at the same moment `gh pr checks 1486` listed 18 checks not yet resolved and 6 passed. a rerun minutes later rendered the same false green. a false green on a watch is the defect a watch exists to prevent.

## .the shape of the fix

- (1) take the pr number from `gh pr view --json number -q .number` (or the first line, validated `^[0-9]+$`); a clamp feeds the two-line form and asserts one number
- (2) find why the status read sees zero runs on an as-human-opened pr (auth of the read, head sha vs pr ref, or a check-suite filter); an unresolved check must render as inflight, never as passed. a clamp: a fake gh that lists one unresolved check → the watch waits

## .why it is not done in this round

both live in other skills; this pr fixes the keyrack org reader.
