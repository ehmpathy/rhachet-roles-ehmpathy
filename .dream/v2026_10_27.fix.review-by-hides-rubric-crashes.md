# 🌙 dream: review.by must fail loud when a rubric run crashes

kind: fix · owner: repo=ehmpathy mechanic · caught 2026-10-27

## .the cue that fired

5.3 verification on `fix-repo-test-grove-suite-bound`: `review.by.integration.test.ts [case5]` went
red. a direct `rhx review.by --role mechanic --paths <clean fixture>` printed `🐢 cowabunga!`,
`r1 mech-failhides ✗`, `r2 mech-decode-friction ✗`, `0 blockers`, `0 nitpicks`, and exited 0.

## .the gap, precisely

`review.by.sh` runs each rubric in the background, writes its output to a temp file, and records its
exit code. a rubric that crashes (here: `rhx review` died with `Cannot find module
'../../domain.operations/review/getOneReviewBindRebound'` inside the installed
`rhachet-roles-bhrain@0.42.1`) gets status ✗, but:
- its output is never shown (the temp dir is removed on exit)
- the header stays `cowabunga!` and the exit stays 0, since only blocker/nitpick counts set them
- `0 blockers` reads as a clean review, when no review ran

a crashed reviewer reads as a pass: a failhide (`rule.forbid.failhide`), and the review contract
says an unreadable review is a malfunction (`contract.reviewer-output`).

## .the shape of the fix

1. any rubric with a nonzero exit and no parsed counts → `💥 MalfunctionError`, exit 1
2. show that rubric's last lines of output under its ✗ branch
3. clamp: a fake rubric that exits 1 → review.by exits 1 and names it

## .why it is not done in this round

safe, not clean: a behavior change in a skill outside this wish, with its own snapshot set; the
round's hour is set. the absent `briefs/**/*.yml` in the build is its own dream:
`v2026_10_28.fix.build-ships-no-briefs-yml`.
