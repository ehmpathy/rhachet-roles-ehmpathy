# 🌙 dream: 31 arg-parse errors in `git.commit/` speak to stdout only

**kind:** fix · **owner:** mechanic · **caught:** 2026-09-09

## .the cue that fired

a self-review of a new skill (`git.commit.sponsor.sh`) found **three** error paths that used a bare
`echo` and exited 2 — stdout only, no stderr.

`rule.require.skill-output-streams` is a table, and it is unambiguous:

| case | stdout | stderr |
|---|---|---|
| validation error | yes | **yes** |

⇒ it grades the violation a **blocker**. the three were repaired with `emit_both` and
`validate_enum_arg`, the two extant helpers that already live in that dir.

🔴 **then the sweep widened, and the find inverted.**

```sh
$ grep -rn '^\s*echo "error' src/domain.roles/mechanic/skills/git.commit/*.sh
```

**31 instances, across 7 files:**

| file | count |
|---|---|
| `git.commit.uses.local.sh` | 9 |
| `git.commit.uses.org.sh` | 8 |
| `git.commit.bind.sh` | 5 |
| `git.commit.set.sh` | 4 |
| `git.commit.uses.global.sh` | 4 |
| `git.commit.push.sh` | 2 |
| `keyrack.operations.sh` | 1 |

## .the gap, precisely

🔴 **the practice and the rule disagree, and the practice prevails by weight of instances.**

- the repo **declares** the rule
- the repo **ships the helpers** — `emit_both` (`output.sh:50`) and `validate_enum_arg`
  (`output.sh:218`), which emits to both streams and exits 2
- the repo **uses them correctly** on its error-rich paths — `emit_error`, `emit_gh_auth_guide`,
  every guard in `git.commit.sponsor.sh`
- ⇒ and then 31 arg-parse errors do it the other way

⚠️ **the residue has a shape: it is all in the arg-parse block.** every instance is an
unknown-option, absent-command, or absent-flag error near the top of a file. that is the region
written **first**, before a skill's own vocabulary is established — and then never re-read, because
a reviewer's eye goes to the logic and treats the parse block as boilerplate.

### .why it matters — the failure is invisible to a human and total for a machine

a caller that captures only stderr (a log aggregator, a CI step, a `2>` redirect, a wrapper that
reports the error stream) sees **an empty error** for a skill that exited 2. ⇒ the exit code says
"constraint" and the diagnosis is absent — which is `rule.forbid.failhide`'s shape: a real failure
that reports naught where it is read.

🟡 **a human at a terminal never notices**, because stdout and stderr both land on the same screen.
⇒ that is exactly why it survived 31 times: **the defect is invisible in the one context where it
is always tested by hand.**

## .the shape of the fix

mechanical, and the helpers already exist:

1. **unknown-option paths** (7 instances, one per file) →
   ```bash
   emit_both "error: unknown option: $1
   $USAGE"
   exit 2
   ```
2. 🔴 **absent/invalid enum paths** (the majority) → `validate_enum_arg`, which absorbs the absent
   case and the wrong-value case into one call and emits the repo's standard message:
   ```bash
   validate_enum_arg "$COMMAND" "command" "$USAGE" set get del
   ```
   ⇒ this is the better repair: it removes a hand-rolled message rather than merely re-aims it
3. **`not in a git repository`** (5 instances, one per file) → `emit_both`

⚠️ **and each repair needs its test assertion strengthened, never merely re-pointed.** the worked
example from the sponsor skill: the old test asserted a hand-rolled `'command required'`; the new
one asserts exit 2, the standard message, the **stderr half** that was never checked, and the usage
line — plus a brand-new case for the unknown-option path, which had no test at all.

⇒ ✅ **`git.commit.sponsor.sh` is the reference implementation**: 0 instances, and 29 green tests
that clamp both streams on both paths.

## .why it is not done in this round

**SAFE: no. CLEAN: no.**

- **safe** — it edits the error paths of 7 skills, among them `git.commit.set` and
  `git.commit.push`, which this route depends on. an arg-parse edit that slips changes what a guard
  refuses
- **clean** — 31 sites across 7 files, plus the snapshot and assertion updates each one drags with
  it. that is a change several times the size of the route that found it

⇒ **and one bound matters most: do NOT do it as a blind sed.** `validate_enum_arg` is the right
repair for the enum cases and the wrong one for the free-text cases, so each site needs a read. a
mass rewrite would produce 31 mechanical `emit_both`s and miss the better fix on the majority.

⇒ 🟡 no fulcrum is owed — a drifted practice found en route is a defect with many instances, not a
fork in the sponsor contract.

## .the lesson worth more than the fix

🎯 **a drifted practice is not a convention; it is a defect with many instances.**

a self-review that asks *"am I consistent with my neighbors?"* would have flagged the **repaired**
file as the outlier and "corrected" it back into the defect. the question that gets it right is
*"which does the RULE say, and do the helpers exist?"* — and here the answer was yes on both counts,
with 31 sites that simply came first.
