# 🌙 dream: one hermetic journey from push to alert

kind: feat (test) · owner: repo=ehmpathy role=mechanic (git.commit.push + git.pull.watch) · caught 2026-11-01

## .the cue that fired

r010 nitpick.4 (5.1 i004): no test proves the chain `git.commit.push` → the real `set` →
the daemon → an alert in a clone.

## .the gap, precisely

- the push suite stubs `set` with a hand-written `{"line":…}` (`WATCH_SET_LINE`); only
  the lifecycle json snapshot guards that contract
- the watch suites start at `set`, never at a push

## .the shape of the fix

- one acceptance-shaped test: a temp repo with a github origin, the stub `gh` and stub
  `rhachet` of `__test_utils__/genWatchTestScene`, a real `git.commit.push --mode apply`
- the push's own `set` call runs for real; the daemon spawns; a check fails in the store
- assert: the push prints `watch: set → @:<slug> (daemon v<key>, spawned …)`, and one
  `clone say` lands in the clone with `check: <name> (failure)`
- the journey runs as `.acceptance.test.ts` through the built `rhx` contract (5.1 i006 r010
  nitpick.10), so the shipped dist, not the src scripts, carries it

## .why it is not done in this round

the push suite and the watch scene each stub a different `gh`; one journey needs one
shared stub, a test-scaffold change of its own. the live-brain seam stays with F15.
