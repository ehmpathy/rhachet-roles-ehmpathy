## .the gap, precisely
four skill families reach into git.commit's folder for shared leaves:
- `git.release/git.release.operations.sh:620` → `../git.commit/keyrack.operations.sh`
- `git.release/output.sh:21` → `../git.commit/output.sh`

## .the shape of the fix
1. new neutral folder, e.g. `src/domain.roles/mechanic/skills/_shared/` (check the build copies it and `rhx list` skips it)
2. move `output.sh` leaves (emit_both, print_turtle_header, print_tree_start, print_coconut_hint, is_arg_in_enum, get_enum_choice_list) and `keyrack.operations.sh` there; move the `--auth` vocab (AUTH_DEFAULT, AUTH_VALID_VALUES, get_auth_who_label) out of `git.commit.operations.sh` into `_shared/auth.operations.sh`
   also lift the generic github leaves that `github.comment.operations.sh` holds today: `run_gh_as_auth` (a twin of `git.commit.push.sh run_gh`), `get_one_gh_viewer_login` (a twin of the graphql whoami at `keyrack.operations.sh:344`), `as_repo_slug_from_remote_url`, `is_gh_not_found`, `fail_gh_call`, and the `ORGS_HOME` fence — a fleet write policy, not a comment policy, so the next github writer reuses it rather than copies the org list
3. lift the fake `gh` into one shared, state-backed stub under `.test/` (today: inline in `github.comment.integration.test.ts`, plus heredocs in the `git.commit.set` and `git.commit.push` suites); it encodes github semantics (thread root, 404 on an unseen pr, page size) that one real conformance case keeps honest
4. repoint the five `source` lines; keep a one-line forwarder in git.commit only if an external repo sources it
5. rerun every suite of the four families; snapshots must not move

## .also caught here (github.comment polish, from the 5.1 peer rounds)
- `get_all_gh_resources`: append `?per_page=100`; ~3x fewer calls on a busy pr. the stub's page-size case and endpoint asserts move with it
- set: after a POST, re-list own matches once; a twin found there refuses at once (exit 2, "posted; a twin stands", names `del --id <newest>`). no delete, one list call
- get: an index view (`--bodies none`) that lists id, kind, author, key, bytes per row, without every body
- set plan: show the current comment's `updated_at` and first line beside its hash, so "a reviewer edited it" reads apart from "my text changed"
- set plan: list own unkeyed comments in the same scope (thread or issue list), and offer `--id <id> --key <k>` to adopt one, so a first keyed run never doubles a thread of unkeyed replies (#69's shape)
- twin refusal and del plan: one line per comment with bytes and the first body line, so a human picks the fuller twin, not merely the newest
- get: `--into <file>` for raw text, and a header note that pr review summaries (`pulls/N/reviews`) are not read
- the suite runs ~280s, from process spawns per scene; fewer scenes or a shared scene per given would cut it
- identity: read self once as `(type, login)` via `viewer { __typename login }`, and drop the reverse `[bot]` clause
- `set --kind body`: name the pr author in the plan, and refuse a body another author opened unless overridden
- the home-org fence: enforce it in the two write leaves (`set_one_gh_resource`, `del_one_gh_resource`), not where the repo is derived, so reads reach any repo and no write skips it
- one claim grammar reader: `as_key_from_body` calls the jq `key_of`; `get --key` lists one endpoint and shapes only its matches
