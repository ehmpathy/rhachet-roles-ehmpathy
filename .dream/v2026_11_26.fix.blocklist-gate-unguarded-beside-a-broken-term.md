# 🌙 dream: a broken blocklist term must not unguard its valid neighbours at the gate

kind: fix · owner: ehmpathy/mechanic · caught 2026-11-26

## .the cue that fired

the detection walk in `pretooluse.forbid-terms.blocklist.sh` moved to in-shell `[[ =~ ]]` matches (zero
execs per record). the same move makes a per-term compile check free, and `[case23] [t0]` pins a hole
whose only stated reason to stay open was that cost.

## .the gap, precisely

- the gate is one grep over `\b(t1|t2|…)\b`, joined from every term
- a term with an unbalanced group (`)swell(`) re-parses the joined pattern: `deploy|)swell(` reads
  "deploy or empty, then swell"
- the pattern compiles, so the exit-2 guard never fires
- ⇒ a write that holds only `deploy` passes the gate, exit 0, silent
- evidence: `[case23] [t0]` asserts `exitCode 0` and `stderr ''`, with the comment "the only cheap
  detection is a compile-check per term, which costs N execs on the CLEAN path"
- that premise no longer holds: `[[ "" =~ $term ]]` exits 2 on a broken term, in-shell, at zero forks

## .the shape of the fix

1. build the gate alternation in-shell from terms that compile alone (`[[ "" =~ $term ]]` ≤ 1)
2. warn on each broken term at the gate, as the walk already does (SKIPPED, blast radius, fix)
3. flip `[case23] [t0]` to expect exit 2 with `deploy` named, plus the SKIPPED warn
4. confirm `[case1]`'s clean-path ratchet stays green: the check adds no exec, but a clean write
   now pays one loop over the records

## .why it is not done in this round

safe, but not clean: it flips a pinned verdict (`[t0]` exit 0 → exit 2) that an earlier route
reserved under its acceptance #2, "no policy move in either direction". that call belongs to whoever
owns that acceptance, never to a ride-along.
