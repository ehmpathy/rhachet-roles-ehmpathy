# 🌙 dream: the rhachet practice writes `@declapract{check.minVersion(...)}` as a dep version

kind: reseed · owner: ehmpathy/declapract-typescript-ehmpathy (or ehmpathy/declapract) · caught 2026-11-08

## .the cue that fired
`npx declapract apply --practice rhachet` (declapract 0.13.27, declapract-typescript-ehmpathy 0.50.0) wrote these into this repo's devDependencies:
`"rhachet-brains-fireworksai": "@declapract{check.minVersion('0.2.3')}"`, and the same for `rhachet-roles-bhrowser` and `rhachet-roles-ghlitch`. the next `pnpm add` failed with `ERR_PNPM_SPEC_NOT_SUPPORTED_BY_ANY_RESOLVER`.

## .the gap, precisely
- the fix for an absent dep writes the raw check expression, not a version, so every apply on a repo that lacks those deps breaks install
- the same apply also moved `rhachet-artifact-git` from dependencies to devDependencies, in a package whose prod code imports it
- it also dropped `npm run build &&` from `prepare:rhachet`, in a roles repo whose roles link from `dist/`

## .the shape of the fix
render `check.minVersion('x')` to `x` (or to the latest that satisfies it) when the fix adds an absent key. add a clamp: apply on a package.json with no such dep → the written value is a semver. review whether the prod-deps practice should exempt deps that `src/` imports at runtime.

## .why it is not done in this round
the defect is in another repo. here, package.json was repaired by hand (fulcrum F3), and the repair lands with the practice upgrade, apart from the fix.
