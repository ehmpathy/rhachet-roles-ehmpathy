# 🌙 dream: a clone can open a stack of prs, each on the slice below

- kind: followup
- owner: mechanic (git.commit.push, git.branch.cutover)
- caught 2026-11-15

## .the cue that fired

a commander asked for #1345 (~117 min of review) as a stack of prs under 30 min each. no paved skill
could cut the slice branches or open a pr on a base other than main.

## .the gap, precisely

- `git.commit.push --base <branch>` (shipped in #1345) opens a pr on the slice below, or moves a
  found pr onto it; the base must be on origin and below HEAD
- `git.branch.cutover` cuts a branch, but its apply refuses while the org gate is unset
- no skill cuts the slice branches of a stack, nor rewrites a pr's branch to its top slice
- raw `git switch -c` and `git push <sha>:refs/heads/<b>` are unpaved, so each one interrupts a human

## .the shape of the fix

- a `git.branch.stack` skill: given ordered path sets, cut one branch per slice from main, one commit
  each, push each via `git.commit.push --base <slice below>`, and write `stack: k of n` into each body

## .why it is not done in this round

it is new skill work, beyond the release gate this pr ships
