# 🌙 dream: a paved way to mark a new skill executable

kind: skill · owner: ehmpathy/mechanic · caught 2026-11-01

## .the cue that fired

`npm run build` (`rhachet repo introspect`) refused the new `git.pull.title/*.sh` and `git.pull.description/*.sh` because they were not executable. `chmod` is not paved, so the clone had to take a detour: `rhx cpsafe` an extant executable file to a tmp path, `cat new.sh | rhx teesafe tmp`, then `rhx mvsafe tmp new.sh`.

## .the gap, precisely

- no `rhx` skill sets the execute bit, and `chmod +x` prompts.
- every new shell skill hits this at its first build.
- the detour relies on teesafe to preserve the target's mode, which no contract promises.

## .the shape of the fix

- add `rhx chmodsafe --path <glob> --mode +x`, fenced to repo-tracked `*.sh` files under `src/**/skills/**` or `src/**/inits/**`.
- or have `teesafe` take `--exec` to write the file as executable.
- clamp: an integration test that writes a new skill file, makes it executable, and checks that `rhachet repo introspect` passes.

## .why it is not done in this round

- it is not clean: a new skill plus a permission-allowlist change sit outside this pull's scope (#1165, title and description verbs).
- it is safe, but it touches the permission surface, which deserves its own review.
