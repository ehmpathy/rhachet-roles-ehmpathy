# 🌙 dream: git.release --watch reports green before any check registers

kind · fix · owner · mechanic (`src/domain.roles/mechanic/skills/git.release/`) · caught 2026-11-22

## .the cue that fired
seconds after `git.commit.push --auth as-human` opened pr #1463, `rhx git.release --watch` printed `👌 all checks passed`, `0s watched`, under a blank `🌊 release:` title; `gh pr checks 1463` listed the runs as queued. a second call, minutes later, said the same while 15 checks were still in flight.

## .the gap, precisely
a watch that finds no checks (or no pr) reads as a pass. the blank title suggests the pr lookup came back empty for a pr opened as the human, and an empty check list then folds to "all passed".

## .the shape of the fix
an empty check list is "no checks yet", never a pass: wait for the first registration (bounded), then watch. a pr lookup that finds naught fails loud with the branch name. clamp: a stub gh with a pr whose checks are queued → the watch must not print `all checks passed`.

## .why it is not done in this round
it is a mechanic skill fix outside this upgrade's scope; `gh pr checks --watch` served this round.
