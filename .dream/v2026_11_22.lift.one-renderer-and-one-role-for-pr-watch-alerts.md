- kind: lift
- owner: mechanic role, this repo
- caught 2026-11-22, on route `.behavior/v2026_11_21.feat-pull-thread-reply-watcher` (fulcrum F17)

## .the cue that fired

the l3 arch-defects review of the reply-task pr found one alert drawn by two renderers (bash for the extant layouts, jq `render` for the reply layout), and a 150-line `WATCH_DIFF_JQ` whose `is_own`, `is_peer`, `is_answerer`, `is_human`, and `who` encode one truth table.

## .the gap, precisely

- a ci burst renders capped and collapsed beside a reply task, uncapped and per-check in the extant mixed layout
- the reply header strips ` on #N` / ` #N` off the rest phrase and compares the vibe to a literal
- the text cap is applied in the diff (`task_comment`) with a second default (`// 2000`) beside the shell default; the checks cap lives in the alert file
- only 2 of 16 `GIT_PULL_WATCH_*` knobs are validated, by an ad hoc regex each
- the pure rules of the diff have no unit test: each is reached only through a daemon tick and a fake `gh`

## .the shape of the fix

1. per-kind node transformers (`ci_node`, `comment_node`, `approved_node`, `thread_node`) all drawn by `render`; reply-first becomes an order over nodes
2. `as_watch_alert_phrase` and `as_watch_alert_vibe` learn `reply.task` as a kind; the phrase composes from kinds, never parsed back
3. one total `def role` → `own | clone | bot | human`; `who`, the filters, and the thread-answer test read it. it is also the `answered=` input the F3 lift (#1340) wants
4. split `WATCH_DIFF_JQ` by concern into peer `.sh` files of jq defs (the bin copy already takes `git.pull.watch/*.sh`), with data-driven unit tests for the pure rules
5. one `as_watch_whole_number` for every knob that reaches `jq --argjson`; both text caps move to the alert file; drop the jq default so a missed injection fails loud
6. persist each outbox entry with its event kinds beside its text, so the held mark (both routes: `as_watch_alert_text_held` and the prompt hook) and `get` read data, never a regex over the rendered header
7. bound the total text of one alert, or name every thread past the bound with its read command; a plain "+N more threads" is unsafe, since the seen state has already moved past them
8. one `as_watch_reply_key` transformer beside `reply_cmd`, unit-tested against `COMMENT_KEY_PATTERN`, and one test that runs a printed reply command through `git.pull.comment set --mode plan`
9. membership by an id-keyed object, not an array scan, with the ledger read once per tick; a one-line verdict log per read ("raised 2 threads", "#5301 answered", "untrusted, kept as comment.new")
10. a reminder for a reply task the crew dropped: `raisedAt` per thread root, re-raised once as `still unanswered` after a bound
11. every extant pr-watch snapshot stays green through the migration

## .why it is not done in this round

it rewrites every extant alert layout; the done-means of the reply-task pr is its own behavior, ci green. a migration behind 500+ assertions rides its own pr.
