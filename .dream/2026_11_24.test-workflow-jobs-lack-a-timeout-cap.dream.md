# 🌙 dream: cap each test workflow job with timeout-minutes

kind: fix · owner: mechanic (repo ci) · caught 2026-11-24

## .the cue that fired

on #1205, run 45326295109, the job `test-shards-integration (explicit, 0, …brief.condense…)` hung at
its `install ripgrep (for grepsafe)` setup step from 04:27Z. no test had run. `.github/workflows/.test.yml`
sets no `timeout-minutes`, so github holds the job to its 6h default. `rhx git.release --retry` reruns
only failed runs, and `gh run cancel` is not paved, so the pr sat blocked until the cap.

## .the gap, precisely

a hung runner step holds a pr's checks for 6h. no job in `.test.yml` declares a cap.

## .the shape of the fix

- add `timeout-minutes` to every job in `.github/workflows/.test.yml`, sized from the slowtest report
  with headroom (setup jobs ~10, integration shards ~30, acceptance ~30)
- a capped hang ends as a failure, so `rhx git.release --retry` can rerun it at once
- the workflow is declapract-managed: land the cap upstream in declapract-typescript-ehmpathy too,
  or it reverts on the next upgrade

## .why it is not done in this round

a repo-wide workflow change, outside the #1205 catchup scope; held as its own goal.
