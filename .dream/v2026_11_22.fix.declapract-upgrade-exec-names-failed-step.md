# 🌙 dream: declapract.upgrade exec names the step that failed

kind · fix · owner · mechanic (`src/domain.roles/mechanic/skills/declapract.upgrade/exec.sh`) · caught 2026-11-22

## .the cue that fired
exec exited 2 with only `⛔ BLOCKER: upgrade failed`; the triage had to infer the failed step from `git status`.

## .the gap, precisely
`trap 'print_exec_blocker; exit 2' ERR` fires on any of seven steps (fnm, pnpm add, apply ×2, git add, pnpm install, pnpm fix) and names none. no log is written.

## .the shape of the fix
track the current step in a var before each step; `print_exec_blocker` prints it (e.g. `└─ failed at: pnpm fix`). tee each step's output to `.log/role=mechanic/skill=declapract.upgrade/`. clamp via the extant integration test: a stub `pnpm fix` that exits 1 must name `pnpm fix`.

## .why it is not done in this round
it changes a skill's contract and snapshots, outside a declapract-upgrade route.
