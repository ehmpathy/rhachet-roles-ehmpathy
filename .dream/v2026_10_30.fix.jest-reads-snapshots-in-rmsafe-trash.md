# 🌙 dream: jest reads a snapshot in rmsafe's trash as obsolete

- kind: fix
- owner: mechanic
- caught 2026-10-30

## .the cue that fired
in the catchup build, `rhx rmsafe` of a stale `__snapshots__/*.snap` moved it to
`.agent/.cache/repo=ehmpathy/role=mechanic/skill=rmsafe/trash/src/…/__snapshots__/`. the next
`rhx git.repo.test --what integration` run failed on an obsolete snapshot there, though every test
passed. `rhx rmsafe --recursive` on the trash dir cleared it.

## .the gap, precisely
`jest.integration.config.ts:44` (and the unit and acceptance twins) keep `.agent/**` out of
`testMatch`, so no test there runs. but jest's obsolete-snapshot check walks the haste map, which
still holds `.agent/`, so a `.snap` file with no test beside it reads as obsolete and fails the run
under `--ci`. so the safe-delete tool, used as paved, breaks the next test run.

## .the shape of the fix
1. keep `.agent/` out of the haste map: `modulePathIgnorePatterns: ['<rootDir>/.agent/']` (or
   `haste.retainAllFiles: false` plus an ignore), in all three jest configs
2. first confirm no test resolves a module through `.agent/` (its role dirs symlink into `dist/`)
3. clamp: a fixture `.snap` under `.agent/.cache/` with no test; the run must stay green

## .why it is not done in this round
a jest config change across three configs reaches module resolution for every suite. that is not
the clean, in-diff fix scouts honor allows in the catchup wish scope.
