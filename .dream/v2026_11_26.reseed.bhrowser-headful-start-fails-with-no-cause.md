## .the cue that fired

route `v2026_10_23.fix-arch-fundamentals` started a headful session so the wisher could solve a captcha, as the wisher asked. `rhx browser.start --session default --mode HEADFUL` exited 1 inside `wait_for_cdp_ready` (`browser.start.sh`, line 237) and printed no cause. `--mode HEADLESS` on the same machine started at once.

## .the gap, precisely

- the start fails, and the human sees an exit code with no `💥 MalfunctionError:` header, no cause, no fix (`rule.require.errors-name-the-fix`, `rule.require.qualified-error-headers`)
- a headful session is the one path a human needs to clear a botwall, so the failure lands where a human is waited on

## .the shape of the fix

1. on a cdp-ready timeout, print the browser's own stderr tail and the port it waited on, behind `💥 MalfunctionError: the browser never opened its debug port`
2. probe the likely cause for headful: no `DISPLAY` / `WAYLAND_DISPLAY` in the env → name it, with the fix (`export DISPLAY=:0`, or run from the desktop session)
3. a clamp: start headful with `DISPLAY` unset; assert the error names the display, exit 1
