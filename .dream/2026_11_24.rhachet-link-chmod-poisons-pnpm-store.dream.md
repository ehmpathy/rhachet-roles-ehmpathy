# 🌙 dream: rhachet roles link must not chmod package files to 0555

kind: reseed · owner: ehmpathy/rhachet · caught 2026-11-24

## .the cue that fired
wish `fix-git-commit-keyrack-org-list` names `ERR_PNPM_PATCH_FAILED` on this package's 0555 files. the read traced the 0555 to rhachet, not to the tarball.

## .the gap, precisely
`rhachet/dist/domain.operations/invoke/link/symlinkResourceDirectories.js:31-53` (`setDirectoryReadonlyExecutable`) chmods every file in each linked role dir to 0o555, `.md` included. pnpm hardlinks package files to its content store, so the chmod lands on the store inode. every later install of that version, and `pnpm patch`'s copy, inherits 0555. evidence: in `rhachet-roles-ehmpathy` and `rhachet-roles-bhuild` installs, role files are `r-xr-xr-x` while `boot.yml` / `*.js` are `rw-rw-r--`.

## .the shape of the fix
- protect the link, not the package: guard writes via the extant hooks, or chmod only the symlink target's copy, never a store hardlink
- or keep each file's x-bit and drop only w: `mode & ~0o222` (md → 0444, sh → 0555), then document that `pnpm patch` needs `chmod -R u+w`
- clamp: an integration test that links a pnpm-installed role, then asserts the store file mode is unchanged

## .why it is not done in this round
the cause lives in another repo; this route ships only this package's half (a pack-mode clamp).
