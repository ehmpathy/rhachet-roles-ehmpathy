# 🌙 dream: bhrowser needs playwright as a direct dependency

- **kind** = reseed
- **owner** = ehmpathy/rhachet-roles-bhrowser
- **caught** = 2026-11-23

## .the cue that fired

route `v2026_10_23.fix-arch-fundamentals`: the wisher asked for citations fetched via the bhrowser. `rhx browser.start` failed in this repo right after `rhachet-roles-bhrowser@0.1.0` was installed.

## .the gap, precisely

- pnpm does not hoist a transitive dependency into the consumer's `node_modules`, so the role could not load `playwright`
- the start worked only after two manual steps: `pnpm add -D playwright@1.60.0` in the consumer repo, then `npx playwright install chromium`
- this repo's `package.json` now carries `"playwright": "1.60.0"` only as a workaround (see `git diff package.json` on this branch)

## .the shape of the fix

1. in `rhachet-roles-bhrowser`, load playwright from the role's own install path: either a `dependencies` entry plus a `require.resolve` call from the role dir, or a `peerDependencies` entry with an init that fails fast and names the install command
2. `browser.start` prints `✋ ConstraintError: chromium not installed` with the exact fix (`npx playwright install chromium`) instead of a stack trace
3. add an acceptance test that installs the role into a temp pnpm repo and runs `browser.start`; red before the fix, green after (`rule.require.clamp-edge-cases`)
4. once that ships, drop the direct `playwright` devDependency from this repo

## .why it is not done in this round

**SAFE: yes. CLEAN: no.** the defect lives in `rhachet-roles-bhrowser`, and a tree adopts only what is scoped to itself.
