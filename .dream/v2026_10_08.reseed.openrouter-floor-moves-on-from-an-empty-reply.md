# 🌙 dream: the openrouter floor walk moves on from an empty reply, as its readme promises

kind: reseed · owner: ehmpathy/rhachet-brains-openrouter · caught 2026-10-08

## .the cue that fired

the full integration run (2026-10-08 06:20) failed four `checkRetention` cases on one ask:

> `💥 MalfunctionError: openrouter returned no usable reply (finish_reason=stop, 0 chars). the host
> replied empty where a json schema was owed.` — provider `DekaLLM`, generation
> `gen-1791441176-u3hIiYCtTueyp8Os2iHQ`

the same suites pass alone (`checkRetention` + `clusterKernels`: 18/18), so the host answered
empty once, and the atom gave up rather than ask the next host.

## .the gap, precisely

the readme's `floor` row: *"one endpoint per attempt; a throttle, refusal, or bad reply moves on
to the next cheapest"*. in `rhachet-brains-openrouter@0.1.3` (the latest),
`getOneSuppliedCompletion` runs `getOneReplyDefectError` AFTER `getOneFloorCompletion` returns —
the floor walk hops only on transport throttles and refusals, so a 200 reply that is empty, cut
off, or prose-where-json-was-owed throws for the whole ask while cheaper-next endpoints sit unused.

## .the shape of the fix

move the reply-defect check inside the floor walk: a defective reply records an attempt
(`{ tag, verdict: 'defect', cause }`), marks a prose-where-json host into the 7-day ignore list it
already keeps, and hops to the next qualified endpoint; only an exhausted queue throws, with every
attempt listed. clamp: a stubbed endpoint list whose cheapest host answers empty, the next answers
json — the ask returns the second host's answer, and `supply.attempts` names both.

## .why it is not done in this round

it is another repo's code (`rhachet-brains-openrouter`). this repo pins 0.1.3; a local retry wrapper
in the librarian callers would mask the defect rather than fix it. the radio is blocked globally,
so the reseed waits held until a human lifts it.
