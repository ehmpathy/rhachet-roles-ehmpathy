# 🌙 dream: the pr-watch skill's bash functions take named args

- kind: refactor
- owner: mechanic (git.pull.watch)
- caught 2026-11-21

## .the cue that fired

a peer review of fix-pull-watch-daemon-respawn-loop flagged three new `as_`/`is_` functions with two positional args (`rule.forbid.positional-args.md.pt2`). every function in `git.pull.watch.*.sh` takes positional args, so the new ones followed the skill (F8).

## .the gap, precisely

calls like `is_watch_pr_due "$KEY_DIR" "$repo" "$pr"` and `set_watch_records_of_pr_ended "$repo" "$pr" gone "$text"` cannot show which string is which, and a transposed pair of same-shape args fails in silence.

## .the shape of the fix

one skill-wide pass: each function parses `key=value` args (the bash form in `rule.forbid.positional-args.md.pt1`), every call site names its args, and a lint or test asserts no positional call remains. one pr, no behavior change, the full pull-watch suite as its guard.

## .why it is not done in this round

a rewrite of every function signature and call site in the skill is a refactor far wider than this fix. three named-arg functions beside a hundred positional ones would leave two conventions in one file.
