# 🌙 dream: git.stage.add stages a tracked deletion, and the paved hint names only real flags

kind: fix · owner: ehmpathy/mechanic (git.stage) · caught 2026-11-05

## .the cue that fired

the #1022 done gate drops three tracked `.foreman/*` notes. after `rhx rmsafe --path .foreman --recursive`,
`rhx git.stage.add .foreman/forks.5.1.i011.md …` refused `error: path must be within repo`, and the
check-permissions hint for `git add -u .foreman` offered `rhx git.stage.add --glob 'src/**/*.ts'`, which
refuses `unknown option: --glob`. `git rm` and `git add -u` are not paved, so a mechanic cannot stage a
deletion by name at all.

## .the gap, precisely

- `git.stage.add` requires each path to exist on disk; a tracked path deleted from the worktree is
  refused, though `git add -- <path>` stages its deletion
- the paved-alternatives list for `git add` names a `--glob` form the skill never parses
- the only paved route to stage a deletion is `git.commit.set --unstaged include`, which stages every
  change — the actor settings files a done gate must leave out among them

## .the shape of the fix

- accept a path that is absent on disk when `git ls-files --error-unmatch -- <path>` finds it tracked;
  stage it via `git add -- <path>` and report `staged (deleted): <path>`
- either add `--glob` to `git.stage.add`, or drop that pattern from the check-permissions alternatives;
  a snap of the hint pins whichever lands
- clamp: a temp repo with one tracked file deleted; `git.stage.add <path>` stages the deletion

## .why it is not done in this round

the route is complete and its commit is gated by the global switch; a change to git.stage now would
land unreviewed in the done-gate commit.
