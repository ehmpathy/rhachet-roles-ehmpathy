# 🌙 dream: close two behavior hazards in git.commit.push.sh

kind: fix · owner: mechanic · caught 2026-10-30

## .the cue that fired
review i003 of #1206 graded all of `git.commit.push.sh` and raised two blockers on code that ships on
main, outside the quota-refusal diff.

## .the gap, precisely
- failhide: the pr title and body reads (`git log -1 --format=%s|%B "$BEHAVIORAL_COMMIT_HASH"`, and
  the HEAD fallback) end in `2>/dev/null || echo ""`. a git failure on a valid hash (corrupt object,
  permission) becomes an empty title, and the pr opens with the fallback title, silently
- race: the author guard (`git log -1 --format='%an'`) and the main/master guard
  (`git rev-parse --abbrev-ref HEAD`) read HEAD once; `git push origin HEAD --force-with-lease`
  re-reads it. a HEAD that moves between the two pushes a commit the guards never saw

## .the shape of the fix
- failhide: `git rev-parse --verify` the hash first; then read with no stderr discard, and let a
  failure surface as a MalfunctionError
- race: capture `HEAD_SHA` and `TARGET_BRANCH` at guard time; check that sha's author; push
  `"$HEAD_SHA:refs/heads/$TARGET_BRANCH"`. clamp: a temp repo whose HEAD moves between guard and push

## .why it is not done in this round
both change push behavior on a real repo and need their own clamp; neither touches the quota
refusal. fulcrum F9 in `v2026_10_27.fix-quota-refusal-names-director-grant`.
