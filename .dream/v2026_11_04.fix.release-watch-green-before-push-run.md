# 🌙 dream: git.release --watch waits for the push-triggered test run

kind: fix · owner: ehmpathy/rhachet-roles-ehmpathy (`src/domain.roles/mechanic/skills/git.release/`) · caught 2026-11-04

## .the cue that fired
right after a push to pr #1263, `rhx git.release --watch` reported `all checks passed` / `no runs inflight`. the `test` workflow (on: push) for that head had not yet queued. a few seconds later it queued, and then it failed. the green came early.

## .the gap, precisely
- watch reads the pr's check rollup at call time
- a workflow on `push` registers its checks some seconds after the push lands
- so "no checks inflight" reads the same as "all done", and watch exits green on a head that has not run its tests
- the cure was hand-run: `gh run list --branch <b>` until the run showed, then `gh run watch <id> --exit-status`

## .the shape of the fix
- key the verdict to the head sha: list the workflow runs for `headSha`, and treat a workflow expected on push (one the repo declares `on: push` for this branch) but absent as inflight, with a bounded grace wait
- or require at least one check for the head sha that is not from the prior head before green
- clamp: a fake `gh` whose first poll returns no runs for the head, then a queued run, then a failure; assert watch reports the failure, not green

## .why it is not done in this round
another skill, outside this route's files; it would ride a pr about rebase.
