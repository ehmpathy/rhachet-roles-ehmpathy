# 🌙 dream: home-org repos require conversation resolution before merge

kind: reseed · owner: the repo declarations (declapract / declastruct-github) · caught 2026-10-30

## .the cue that fired
peer review r011 (enroll-impl-arch-defects), i015, open items, on route `.behavior/v2026_10_26.fix-release-blocked-on-unanswered-comments/`.

## .the gap, precisely
`rhx git.release` refuses while a comment waits, but it is a client-side gate. between its last read and the moment automerge arms, a comment can land; github then merges at arm time if checks are already green. a manual merge click bypasses the gate entirely. `git.release.spec.md` usecase 8 names the server-side cure; no repo turns it on.

## .the shape of the fix
set branch protection `required_conversation_resolution: true` on `main` for each home-org repo, through the declared repo config (declastruct-github resources, or the declapract practice that owns branch protection), not by hand. with it on, github itself refuses the merge while any review thread is unresolved, for every merge path.

## .why it is not done in this round
it belongs to another repo's declarations, and it changes merge policy org-wide: a call for the wisher, not a ride-along on the release gate.
