# 🌙 dream: check-permissions case58 asserts a wall-clock bound that host load breaks

kind: flake · owner: mechanic (claude.hooks) · caught 2026-11-11

## .the cue that fired

`rhx git.repo.test --what integration --scope 'path://check-permissions' --mode apply`: 372 passed,
1 failed. `[case58][t0]` ("it blocks well inside its 10s registered timeout") expected `< 9500` ms
and received `10406`; alone (`--scope 'name://case58'`) it received `11531`. the host read
`/proc/loadavg` 40.33 on 12 cpus at the time.

its peer `[case62][t1]` had the same defect (`< 1500` ms, received `3135`). that one is fixed on
`beav/feat-git-package-patch`: it now asserts the deadline branch by its message and the absence of
the live-holder message, and it goes red when the deadline check is disabled.

## .the gap, precisely

case58 lifts `FAILFAST_TIMEOUT` to 60, so the allow check of 150 parts against 200 allows runs with
no bound, then times the whole spawn. on a loaded host the allow check alone can pass 9.5s before the
search budget it means to clamp is reached. the assertion then grades the host, not the search bound.

## .the shape of the fix

time only the phase under test. have the hook print the epoch ms at which the search began and at
which it gave up, and assert the gap between the two against the search budget. keep the
`not searched — the candidate search ran out of time` assertion, which already proves the bound fired.

## .why it is not done in this round

safe, but not clean: the hook executable sits on main three releases ahead of this branch's base,
the fix adds output to the hook itself, and the `git.package.patch` pr does not otherwise touch it.
