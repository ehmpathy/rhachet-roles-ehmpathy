# 🌙 dream: clamp the daemon's hold on an alert render fault

- kind: test
- owner: mechanic role, this repo
- caught 2026-11-22, on route `.behavior/v2026_11_21.feat-pull-thread-reply-watcher` (5.3 peer lane `enroll-verif-snapshot-coverage`; fulcrum F25)

## .the cue that fired

a reviewer named a guard with no clamp: when `as_watch_alert_text` returns nonzero, the daemon logs `alert render failed` and holds its cursors, so the next tick tries again. remove that guard and a render fault would drop the reply task for good, and every suite would stay green.

## .the gap, precisely

- the guard lives in `git.pull.watch.daemon.sh` (the tick's alert step), new in this route
- every fault path in the renderer is jq over data the daemon built itself; no realistic input trips it
- so no test can reach the guard without a fault seam, and the scene has none

## .the shape of the fix

1. a jq shim in the scene's stub dir that delegates to the real jq, and fails only for the renderer's final call (match on `render("   ")` in its args) while a marker file exists
2. a faults case: plant the marker, open a thread, assert the log holds `alert render failed` and naught raises; drop the marker, assert the task raises on the next tick, once
3. prove it bites: delete the guard's `|| { … return 0; }`, the case goes red (the cursors advance, the task never raises)

## .why it is not done in this round

the seam is new test infra the whole scene shares (a jq on PATH for every suite); it ripples past this diff, so it fails the clean test. the guard itself is two lines and reads plainly.
