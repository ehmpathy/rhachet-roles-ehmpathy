# 🌙 dream: git.commit.push reads the pr number as two lines

kind: fix · owner: mechanic (git.commit.push) · caught 2026-11-24

## .the cue that fired
`rhx git.commit.push --mode apply --auth as-human` opened pr #1481, then printed `pr: pr #1481\n1 (created)` and its watch step refused: `--which must be a pr number; got '1481\n1'`.

## .the gap, precisely
the as-human fallback path captures the pr number with a second line (`1`) appended, likely an exit code or a count echoed into the same capture. the push and the pr both landed; only the watch set failed, so the crew sat unwatched until a hand `rhx git.pull.watch set --which 1481 --mode apply`.

## .the shape of the fix
take the first line of the captured number (or capture the number alone), and assert it matches `^[0-9]+$` before it reaches the render or the watch. clamp: an integration case on the as-human fallback that asserts the render reads `pr #<n> (created)` and the watch is set.

## .why it is not done in this round
the done gate grants two commits and covers this pr; the fix is a separate defect in another skill, with its own clamp.
