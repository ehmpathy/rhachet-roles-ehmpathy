# 🌙 dream: read `browser.action --play` relative to the caller's cwd

- **kind** = reseed
- **owner** = ehmpathy/rhachet-roles-bhrowser
- **caught** = 2026-11-24

## .the cue that fired

route `v2026_10_23.fix-arch-fundamentals`, a citation fetch round. two calls failed before an absolute path worked.

## .the gap, precisely

`rhx browser.action --play <path>` imports the playbook relative to the skill's own file, not the caller's cwd (rhachet-roles-bhrowser@0.1.0, `dist/domain.roles/playwright/skills/browser.action.ts`):

| `--play` | result |
|---|---|
| `.behavior/…/fetch-sources.play.ts` | `ERR_INVALID_MODULE_SPECIFIER`: "is not a valid package name" |
| `./.behavior/…/fetch-sources.play.ts` | `ERR_MODULE_NOT_FOUND`: looked under `node_modules/…/playwright/skills/.behavior/…` |
| `/home/…/.behavior/…/fetch-sources.play.ts` | runs |

both failures surface as `UnexpectedCodePathError` with a raw node stack and the hint "this should not happen". an absent file, by contrast, gets a clean `ConstraintError: playbook not found`, since that check reads the path relative to the cwd.

## .the shape of the fix

- in `browser.action.ts`, make the `--play` path absolute against `process.cwd()` before the existence check and the import; import via `pathToFileURL(absolute).href`
- a clamp test: run a playbook by a bare relative path and a `./` path from a temp cwd; both must run
- `--help`: say that `--play` is read relative to the cwd

## .why it is not done in this round

**SAFE: yes. CLEAN: no.** the fix lives in another repo (rhachet-roles-bhrowser). the absolute path works in the meantime.
