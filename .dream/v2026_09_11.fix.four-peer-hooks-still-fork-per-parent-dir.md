# 🌙 dream: four peer hooks still fork one `dirname` per parent dir

- **kind**: fix
- **owner**: ehmpathy/rhachet-roles-ehmpathy
- **caught**: 2026-09-11

## .the cue that fired

a `has-consistent-mechanisms` self review on `v2026_09_09.fix-hook-fork-storm`. the two
forbid-terms hooks got a `${dir%/*}` swap in `find_claude_dir` and a one-pass `jq … | @tsv`
stdin read. a grep to check whether the change was **consistent** with the peers answered the
opposite: the peers never got either, so the two hooks now differ from the other six.

⇒ **the inconsistency is real, and the repair is to lift the win, never to revert it.**

## .the gap, precisely

### the `dirname` walk — 4 hooks

`find_claude_dir` walks `$PWD` upward to find a `.claude` dir. the extant form calls
`dirname` once **per parent dir**, so a deep worktree pays ~7 execs per invocation:

| hook | still forks | fires on |
|---|---|---|
| `pretooluse.check-permissions.sh` | yes | 🔴 **every `Bash` call** |
| `permissionrequest.decide-permissions.sh` | yes | every permission prompt |
| `pretooluse.forbid-cross-repo-access.sh` | yes | every `Read` |
| `sessionstart.notify-permissions.sh` | yes | each boot |

the two forbid-terms hooks now use `${dir%/*}`, a bash expansion at **zero** forks:

```bash
dir="${dir%/*}"
[[ -z "$dir" ]] && dir="/"   # ${x%/*} yields "" at the root where dirname yields "/"
```

### the 3-jq stdin read — 6 hooks

each reads `.tool_name` in its own `jq` exec, then `.tool_input.file_path` in another. one
`jq -rj '[…] | @tsv'` emits both in a single exec:

```bash
IFS=$'\t' read -r TOOL_NAME FILE_PATH < <(
  echo "$STDIN_INPUT" | jq -rj '[(.tool_name // ""), (.tool_input.file_path // "")] | @tsv' 2>/dev/null || echo ""
) || true
```

🔴 **`check-permissions` is the one that pays most.** it gates `Bash`, so it fires on every
shell call rather than every file write — the highest-frequency hook in the set.

## .the shape of the fix

1. lift `find_claude_dir`'s `${dir%/*}` form into the 4 hooks, verbatim. the `-z` guard is
   required, never optional — absent it the loop spins forever at the root
2. lift the `@tsv` one-pass read into the 6 hooks that read two fields
3. extend `pretooluse.forbid-terms.forkbudget.integration.test.ts`'s PATH-shim tally to cover
   each hook touched. **the clamp is the deliverable, never the count** — a fork budget
   recorded only in prose drifts back on the next edit
4. prove each clamp bites: revert the swap, watch it go red, restore, watch it go green
   (`rule.require.clamp-edge-cases`)

⚠️ **`check-permissions` and `decide-permissions` are large and carry their own audit trail.**
they are not a copy-paste target — read each `find_claude_dir` before the swap, since one may
lean on `dirname`'s exact root answer.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

| | verdict |
|---|---|
| **safe?** | ⚠️ **no.** `check-permissions` gates every `Bash` call and `decide-permissions` auto-decides permission prompts. a defect in either fails **open**, silently, in every consumer repo |
| **clean?** | 🔴 **no.** it opens 4 hook files this wish never touched, each with its own test suite, plus a clamp per hook |

and the wish's boundary names this case directly:

> *"do not touch the other PreToolUse hooks unless a shared-cost fix genuinely lands there
> too — and if it does, say so plainly rather than expand the diff quietly."*

⇒ the fix **does** genuinely land there, so the clause invites it. it is declined here because
the blast radius reaches the two hooks that gate shell calls and permission prompts, and this
round's own clamps are the only proof that shape of change is safe. ⇒ **said plainly, per the
clause, rather than expanded quietly.**
