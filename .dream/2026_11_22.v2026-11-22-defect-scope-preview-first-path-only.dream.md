# 🌙 dream: the scope preview lists files of every stacked path scope

- kind: defect
- owner: ehmpathy/rhachet-roles-ehmpathy, `git.repo.test`
- caught 2026-11-22

## .the cue that fired

`rhx git.repo.test --what integration --scope path://hooks-reachable --scope path://imagineIsContentAdmissible --scope path://pressViaPipeline --mode apply` printed `matched: 1 files` and listed one file, then jest ran 3 suites.

## .the gap, precisely

the preview (`get_scope_file_count`, `get_scope_files`) receives one `local_scope`, set from `PATH_PATTERNS[0]` (`git.repo.test.sh`, the "use first path pattern" comment in both the plan and apply branches). the real run passes every path pattern. a stacked `--scope path://a --scope path://b` previews `a` only; a typo in `b` is never caught by the zero-match constraint.

## .the shape of the fix

pass every path pattern to both preview functions (`"$path_flag" "$p"` per pattern, as `run_single_test` does), so the count and list match the run. clamp: a stacked two-path scope case in `git.repo.test.scope.integration.test.ts` that asserts `matched: 2 files`, and a typo in the second scope that exits 2.

## .why it is not done in this round

outside the wish (the jest worker cap); it changes the zero-match constraint for stacked scopes, a behavior change that wants its own test and review.
