# 🌙 dream: `rhx enroll -p` drops the clone's answer from stdout

kind: reseed · owner: ehmpathy/rhachet (enroll) · caught 2026-10-07, in route `v2026_09_26.fix-blocklist-nudge`, stone 5.1 (peer i004, i005)

## .the cue that fired

a guard lane ran `$rhx enroll claude … -p '<review prompt>'` (default `--await`). twice, the
guard read only the enroll banner and permission notices and graded the lane `💥 malfunction:
reviewer output lacks a numeric blocker/nitpick count` — yet `rhx clone get @:e691813d --format
raw` showed the clone had finished a full review that ended `2 blockers, 4 nitpicks.`

## .the gap, precisely

`--await` is documented as "hold until the clone answers its prompt and exits, then forward its
exit code". it forwards the exit code but not the answer text, so any caller that reads stdout
(every guard lane) sees no review. a second clone spawned in the same cwd in the same instant
(i004) made it worse: `clone get` reported "history is empty because this clone shared a cwd
with another at spawn", and that clone stayed LIVE over an hour.

## .the shape of the fix

forward the clone's final reply on stdout under `--await` (the tree output's last block, or the
raw reply under `--output json`). clamp: enroll with `-p 'reply exactly: 0 blockers / 0
nitpicks'` and assert stdout holds both lines.

## .why it is not done in this round

it lives in another repo (rhachet). the route's guard works around it: each enroll lane has its
clone write the final list to `.temp/route.review/<slug>.md` and prints that file. the radio is
blocked globally, so a push would only be held.
