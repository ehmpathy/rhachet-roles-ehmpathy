# 🌙 dream: git.release --watch reports "all checks passed" while checks still queue

kind: fix · owner: mechanic (git.release) · caught 2026-11-24

## .the cue that fired
right after the push of pr #1481, `rhx git.release --watch` twice printed `👌 all checks passed` and `no runs inflight`, while `gh pr checks 1481` listed install, lint, types, unit, and every test shard as queued. one shard later failed.

## .the gap, precisely
the watch reads "no runs inflight" as "passed" before the workflows have queued their jobs. a crew that trusts it reports green on a pr that is red.

## .the shape of the fix
treat a queued or unstarted check as inflight; when the pr's head sha has no check runs yet, wait for them to appear (bounded) rather than report passed. clamp: a case where the check list holds only queued rows asserts the watch keeps a wait, never `all checks passed`.

## .why it is not done in this round
the done gate grants two commits and covers this pr; `gh pr checks --watch` stood in for the watch this round.
