# 🌙 dream: this repo adopts rhachet 1.54, whose init moves role hooks into a dispatch manifest

- kind: followup
- owner: mechanic (getMechanicRole hooks tests, package bump)
- caught 2026-11-24

## .the cue that fired

an upgrade bump to rhachet 1.54.0 (with rhachet-roles-bhrain 0.44.1, rhachet-roles-ehmpathy 1.43.0)
turned ci red on #1345, so it was reverted out of that pr.

## .the gap, precisely

- `rhachet init --hooks` 1.54 sets hook dispatchers: role hooks move from `.claude/settings.of.repo.json`
  into `.claude/hooks.dispatch.manifest` (ci log: "22 role hooks moved from the settings into the manifest")
- `getMechanicRole.hooks-reachable.integration.test.ts` [case1] reads hook commands from the settings
  file only, so under 1.54 it finds mechanic hooks at one event key and no `_hardnudge.lib.sh` source
- a box whose settings were generated before the dispatchers still passes locally; only a fresh init (ci) fails

## .the shape of the fix

- teach the hooks-reachable reader to read the dispatch manifest too: every role hook a dispatcher
  names counts as registered, at the event of its dispatcher
- then land the bump: rhachet 1.54.0, rhachet-roles-bhrain 0.44.1, rhachet-roles-ehmpathy 1.43.0

## .why it is not done in this round

it is an adaptation to a new rhachet hook layout, a different goal than the release gate #1345 ships
