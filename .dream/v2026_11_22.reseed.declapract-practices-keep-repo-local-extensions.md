# 🌙 dream: declapract practices keep a repo's local extensions across an apply

kind · reseed · owner · ehmpathy/declapract-typescript-ehmpathy · caught 2026-11-22

## .the cue that fired
the 0.50.0 apply rewrote three practice-owned files and silently dropped repo-local lines this repo kept on purpose; each had to be restored by hand, and the next apply drops them again.

## .the gap, precisely
- `jest.integration.config.ts` testMatch: the repo's hand-only excludes (live-pr suites, real-registry suites, brain-graded suites) vanish
- `jest.{integration,acceptance}.env.ts`: `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM`=/dev/null and `GIT_TERMINAL_PROMPT=0` vanish
- `.github/workflows/.test.yml` shards: repo runner tools (`ripgrep`, `pnpm`) vanish
- `provision-github` backfills `"private": true` on a published package whose key was absent (it provisioned public before)

## .the shape of the fix
a declared seam per file, read by the practice, never overwritten: e.g. `jest.integration.config.local.ts` (extra testMatch excludes), a `jest.env.local.ts` the env files import, a `.test.yml` `runner-tools` input. git isolation belongs in the template itself for every repo whose suites shell git. for privacy: refuse to backfill when the package has a publish workflow; ask for an explicit boolean instead.

## .why it is not done in this round
the fix lives in another repo; this round restores the lines locally. already filed upstream as ehmpathy/declapract-typescript-ehmpathy#829 (templates drop repo-local excludes and runner steps); this dream adds the git-isolation and `private` backfill cases to it.
