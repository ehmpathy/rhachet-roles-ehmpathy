# 🌙 dream: `git.repo.test --what acceptance` with no scope finds no file

- kind: fix
- owner: mechanic (rhachet-roles-ehmpathy, git.repo.test)
- caught 2026-11-02

## .the cue that fired

`rhx git.repo.test --what acceptance --against local --env test` printed `matched: 0 files` and
`error: no files matched`, while `blackbox/` holds 13 `*.acceptance.test.ts` files; the same call
with `--scope 'path://blackbox/git.pull.comment'` matched one.

## .the gap, precisely

the bare call (scope all) searches a set of paths that omits `blackbox/`, so the obvious
invocation reports "no acceptance tests" in a repo full of them.

## .the shape of the fix

- scope all resolves the files through the jest acceptance config (`jest --listTests -c
  ./jest.acceptance.config.ts`), the same source `npm run test:acceptance` reads
- a clamp: a temp repo with one `blackbox/x.acceptance.test.ts` matches 1 file with no scope

## .why it is not done in this round

a change to a skill this route does not touch, with its own suite; outside the pr-watch scope.
