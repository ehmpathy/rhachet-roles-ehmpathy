# 🌙 dream: peer reviewers report whole new files as truncated

kind: reseed · owner: rhachet-roles-bhrain (role=reviewer) · caught 2026-10-31

## .the cue that fired

three rounds of one vision stone. a peer lane reported a bdd `[tn]` block as truncated, with no `then` steps and an unclosed fence: case=6 (round 2), case=5 (round 2, other lane), case=9 (round 3). all three files were whole on disk. for case=9, the review's own `input.prompt.md` held the full sketch (target at line 1328, `given('[case9b] …'` at 1361).

## .the gap, precisely

the brain (`openrouter/deepseek/flash`, push mode, `diffs: since-main` ∩ paths) is fed `<target.diff kind="+">` blocks for many new files back to back. it attributes text from the next target to the current one, then reports the current one as cut short. it once quoted `### D9 · repo scope` (from `dimensions.md`) as the tail of a case file.

each misread costs a round of budget and a disputed concern.

## .the shape of the fix

- delimit each target with an explicit close tag and its path repeated (`</target.diff path="…">`), so a brain cannot run one file into the next
- or, for `kind="+"` (all-new files), send the file content as a target file, not a diff
- clamp: a fixture of 10+ new files with fenced code blocks; assert the review does not claim a truncation the file lacks

## .why it is not done in this round

the reviewer lives in rhachet-roles-bhrain; this route builds a pr-watch daemon in rhachet-roles-ehmpathy. disputed on record: fulcrums F9, F10.
