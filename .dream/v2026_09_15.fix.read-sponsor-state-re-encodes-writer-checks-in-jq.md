# 🌙 dream: `read_sponsor_state`'s jq gate re-encodes the writer's identity checks in a second engine

- **kind** = fix
- **owner** = ehmpathy/rhachet-roles-ehmpathy
- **caught** = 2026-09-15

## .the cue that fired

`arch-opport-decomposition` (i045, nitpick.2) found that `read_sponsor_state`
(`git.commit.operations.sh`) validates the sponsor state file with one 7-conjunct `jq` expression
that re-encodes checks the writer (`git.commit.sponsor.sh`) already expresses as named bash
predicates: `is_identity_unprintable` (control chars), `as_identity_part`/`SPONSOR_EMAIL_PATTERN`
(email shape), `as_identity_trimmed`.

## .the gap, precisely

only the email pattern (`SPONSOR_EMAIL_PATTERN`) is a shared named constant. the control-char
and shape checks live as duplicate logic written in a second regex engine (jq/Oniguruma vs bash
ERE), with no named leaf that holds them on the read side. a future change to what counts as "a
valid identity" has to land in two engines, and a miss between them stays invisible until a value
that one side accepts and the other rejects reaches the state file.

## .the shape of the fix

extract the control-char and shape checks the writer already names into a form both the bash
writer and the jq reader can call — either a small jq module the reader loads, or a switch of the
reader's validation to shell out to the same bash predicates the writer uses instead of a raw jq
expression.

## .why it is not done in this round

**SAFE: yes — the fix only touches validation logic already isolated to two functions.**

**CLEAN: no.** the sponsor state file is a wire-format contract both `sponsor.sh` (writer) and
`operations.sh` (reader) parse; a change to how it validates is exactly the class of edit this
drive's own invariants (`domain.terms/sponsor.md`) treat as sensitive, and it is minor (a nitpick,
scoped inside one leaf) rather than a live defect.
