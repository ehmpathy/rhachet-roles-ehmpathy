## .the gap, precisely

`git.release` reads GitHub only through the `gh` CLI, over four read-only json surfaces:

| call | fields read | site |
|------|-------------|------|
| `gh pr list` | `number`, `title`, `headRefOid`, `mergeCommit` | `operations.sh:72,95,777,795` |
| `gh pr view` | `statusCheckRollup`, `autoMergeRequest`, `mergeStateStatus`, `state`, `title`, `mergeCommit` | `operations.sh:193`, `git.release.sh:757,963` |
| `gh run list` | `name`, `conclusion`, `status`, `url`, `startedAt`, `updatedAt` | `operations.sh:466,866` |
| `gh run view` | `jobs`, `startedAt`, `updatedAt` | `operations.sh:540,558` |
| `gh api -X GET --paginate repos/{owner}/{repo}/pulls/{n}/reviews` | `user.login`, `user.type`, `author_association`, `state`, `submitted_at` | `get_pr_reviews` (the review gate) |

the reviews read carries the most weight of the five: a token that cannot read reviews, or a
renamed `author_association`, turns every `--apply` into a refusal (fail closed, but a release
outage). a draft suite for it is ready:
`.dream/2026_09_26.add-real-gh-contract-test-for-git-release.draft.p10.reviews.real_boundary.ts.txt`
— reads `ehmpathy/rhachet-roles-ehmpathy#1022` (merged; a human member APPROVED, `ehm-seaturtle`
COMMENTED) under `EHMPATHY_SEATURTLE_GITHUB_TOKEN`, asserts the five keys, the human approval's
authority, the clone's `type: User`, and that `is_pr_approved_by_human` decides it `true`. land it
as `src/domain.roles/mechanic/skills/git.release/git.release.p10.reviews.real_boundary.integration.test.ts`
once the token reaches ci.

a field rename upstream ships green. three mock surfaces serve the 17 suites:

| surface | suites |
|---------|--------|

a shape change must land in all three places. a repair to `mockGh.ts` alone leaves `p2` and `p4` green

## .the shape of the fix

one read-only contract suite — no write, no PR, no release:

1. call each surface against this repo with `--json <the exact fields above>`.
2. assert keys present, not values.
3. assert the nested shapes the skill reads: `mergeCommit.oid`, `jobs[].steps[].name`.
4. the write half of `git.release` stays mock-tested.

prerequisite: a read-only token in the `test` keyrack env and `GH_TOKEN` in
`.github/workflows/.test.yml`. today no token reaches the integration shards, so the suite would pass
locally and red in CI. do not substitute a stub: a stub cannot fail for the reason this test exists.

the key is already declared (`env.test: EHMPATHY_SEATURTLE_GITHUB_TOKEN` in `.agent/keyrack.yml`);
the ci keyrack firewall reports it `absent 🫧`, because no repo secret by that name holds a value.
a human adds the secret (and fills it in the local `ehmpath` `test` keyrack); the firewall then
grants it to the shards with no workflow edit.

## .the merge pin, a write contract (added 2026-11-15)

the review gate pins the merge: `gh pr merge --auto --squash --match-head-commit <sha>` (and the
direct `--squash` fallback). gh sends the sha as `expectedHeadOid` in
`EnablePullRequestAutoMergeInput` and `MergePullRequestInput`; the p9 clamp proves it only against
the mock. one live run on a throwaway pr in a sandbox repo, with the pinned sha stale, must show:

1. github accepts the field with `--auto` (else every approved apply exits 1)
2. a stale pin is refused, and the exact error text, which `_is_gh_output_head_moved` must match
   (today it matches `head branch was modified|expected head|head sha ... match`)

this needs a write grant, so it runs by hand or in a sandbox repo, never against this repo's prs.
