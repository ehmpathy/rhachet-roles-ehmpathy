# 🌙 dream: `rmsafe` expands globs with `compgen -G`, which ignores `globstar`

- **kind** = fix
- **owner** = `repo=ehmpathy/role=mechanic`
- **caught** = 2026-09-14, at stone `5.3.verification`, in the wide-run triage

## .the cue that fired

three `rmsafe` cases are red in **both** wide runs of the 78-file mechanic suite — the stably-red
set, never the flaky one. each asserts a file was deleted; each finds it still present:

```
● rmsafe.sh › [case11][t2] recursive glob **/*.bak › matches files in nested directories
    Expected: false     ← pathExists
    Received: true      …rmsafe.integration.test.ts:1671
```

## .the gap, precisely

**two cases pin the mechanism between them, because they fail at opposite depths:**

| case | glob | the file that SURVIVED | intermediate dirs |
|---|---|---|---|
| `[case11][t2]` | `src/**/*.bak` | `src/deep/nested/baz.bak` | **2** |
| `[case15][t5]` | `build/**/*.ts` | `build/output.ts` | **0** |

and in `[case11]` the two files with **exactly 1** intermediate dir — `src/utils/foo.bak`,
`src/core/bar.bak` — were deleted correctly (their assertions pass; jest reports the first failure
at `:1671`, the depth-2 file).

⇒ **zero segments fail · one segment passes · two segments fail.** that is `*`, not `**`. a true
`**` matches any depth, zero segments too; a plain `*` matches exactly one segment. so `**` is
degraded to `*`.

### the cause is one line, and it defeats the line 25 lines above it

```bash
rmsafe.sh:35    shopt -s globstar nullglob          # ← set, and inert for the glob below
…
rmsafe.sh:213   # .note = uses compgen -G for safe glob expansion (handles escape sequences, no eval)
rmsafe.sh:221   done < <(compgen -G "$pattern" 2>/dev/null | sort)
```

**`compgen -G` does not honor `globstar`.** it runs bash's completion-side pathname expansion, which
does not consult the `globstar` shopt of the shell that invoked it. so `shopt -s globstar` at `:35`
is dead code with respect to the only glob expansion `rmsafe` performs.

⚠️ **the `.note` at `:213` explains why `compgen -G` was chosen** — escape-sequence safety with no
`eval`. that is a good reason, and it is what makes this a design tension rather than a typo.

### blast radius — bounded to `rmsafe`

`compgen -G` appears at **exactly one site in the repo** (`rmsafe.sh:221`). the siblings
`mvsafe.sh:34`, `cpsafe.sh:34`, and `globsafe.sh:37` each set `shopt -s globstar nullglob` and expand
by native bash glob syntax, so their `**` works.

🟡 **`globsafe.sh:37` carries a different latent defect worth a look in the same pass**:
`shopt -s globstar nullglob 2>/dev/null || true` continues silently if the `shopt` fails, which is a
`rule.forbid.failhide` shape — a degraded glob that warns no one. `rmsafe.sh:35` has no `|| true`
and is correct on that count.

### ⚠️ it fails in the SAFE direction, which is why it has sat unnoticed

`rmsafe` under-deletes: files the caller asked to remove survive. for a **deletion** tool that is the
benign direction — a caller notices leftover files, never lost ones. ⇒ no data-loss hazard, and no
urgency; it is a correctness and contract gap.

## .the shape of the fix

1. **confirm the mechanism directly** — `shopt -s globstar; compgen -G 'a/**/c'` against a fixture
   tree, beside a native `for f in a/**/c`. this dream infers from two failure signatures that agree
   plus the source; a two-line probe settles it outright. **do this first** — if `compgen -G` turns
   out to honor globstar, the whole diagnosis is void and the real cause is elsewhere.
2. **swap the expansion for native bash glob syntax** with `nullglob` + `globstar` already set, and
   keep the no-`eval` property the `.note` protects. the extant `globsafe.sh` does exactly that and
   is a ready reference.
3. **keep the escape-sequence safety** the `.note` cites — whatever replaces `compgen -G` must still
   handle a literal `[` in a filename without `eval`. that is the actual constraint to design to.
4. the three red cases then pass with **no test edit**, which is the tell that the fix is at the
   right layer. ⚠️ **if a test needs an edit to go green, stop** — the tests encode the contract, and
   `[case11][t2]` is named *"matches files in nested directories"* outright.

## .why it is not done in this round

**SAFE 🔴 · CLEAN 🔴** — it fails both questions of `rule.always.fix-forward-under-scouts-honor`.

| question | verdict |
|---|---|
| **SAFE?** | 🔴 **no.** the fix makes a **deletion** tool match strictly more files. that is the one class of change where an error destroys work nobody can recover, and it lands nowhere near this wish's blast radius |
| **CLEAN?** | 🔴 **no.** `rmsafe.sh` is in no file this diff opens. this wish is two `pretooluse` hooks, and `git diff --stat main -- rmsafe*` is empty — the suite is byte-identical to `main`, so the failure is inherited, never authored here |

⚠️ **and the stone's buttonup mandate was weighed against this, rather than waved past.** it says
*"consider all failures as defects from this pr."* the honest answer is that the PERMITTED test of
`rule.always.raise-a-blocker-a-taken-cannot-close` is narrower than *possible*: a change to a
deletion tool's glob semantics, in a file this diff never opens, is not a change this stone is
permitted to make — so it is recorded with a runnable shape rather than attempted.

🔴 **what this round DID owe, and paid:** the failure moved from *"red, not ours, byte-identical to
main"* to a **named mechanism with a one-line cause and a bounded blast radius.** the wide-run
triage had listed these three as merely excluded; they are now diagnosed. ⇒ **the deferral is of the
repair, never of the diagnosis.**
