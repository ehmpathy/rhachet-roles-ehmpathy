the lane is right about the class, and it named **one** site. the grep found **four**.

## .the gap, precisely

`.meter/git.commit.uses.jsonc` is read by bare `jq -r` at four sites in three files, with no
shared reader and no shape gate at any of them:

| file | lines |
|---|---|
| `git.commit.uses.local.sh` | 376–378 |
| `git.commit.push.sh` | 268–269 |
| `git.commit.set.sh` | 531–533 |

checkable:

```sh
rhx grepsafe --pattern "jq -r '\\.uses'|jq -r '\\.push'|jq -r '\\.stage" \
  --glob 'src/domain.roles/mechanic/skills/git.commit/*.sh'
```

⇒ a corrupt or truncated meter file makes the first read exit non-zero under
`set -euo pipefail`, and the skill dies with jq's own parse text: no command named, no remedy,
no semantic exit code (`rule.forbid.failhide`, `rule.require.failloud`).

🔴 **and the sharper half, measured on the sponsor file this round**: a `// empty` or
`// "block"` default does not merely produce an ugly error — it lets the read **continue with a
fabricated value**. `.stage // "block"` on an unreadable file is the shape that would silently
deny a permission the human granted.

## .the shape of the fix

mirror `read_sponsor_state`, which this round built in `git.commit.operations.sh` and which now
serves three callers through one decision point:

```bash
# returns 0 = usable, 1 = present and unusable, 2 = absent
read_uses_state() { … }
```

1. add `read_uses_state` to `git.commit.operations.sh`, with the same two gates the sponsor
   reader carries — a `jq -e 'type == "object"'` shape gate, then a value gate
2. route all four call sites through it, and branch on its status rather than on a local
   `[[ -f … ]]` pre-check
3. one curated corrupt-meter render, shared — never one per caller
4. a clamp per caller shape, dogfooded red-green

⚠️ **the lesson this round already paid for, and it applies here directly**: when a fix applies
to one caller, enumerate the others before you call it done. a guard at
`git.commit.uses.local.sh` alone would leave `set` and `push` on the older model — the exact
drift `arch-opport-decomposition` predicted and `arch-hazards-maintenance` graded in `i003`.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`), and it fails **both**:

| question | verdict |
|---|---|
| **SAFE?** | 🔴 **no.** the read gates every commit and every push. a wrong edit here does not degrade a render — it stops the fleet from committing |
| **CLEAN?** | 🔴 **no.** four sites, three files, and two of them — `git.commit.push.sh` and `git.commit.set.sh` — are skills this change never opened. it also owes a curated render and a clamp per caller |

⇒ this is the **same scope bound** the `arch-hazards-behavior` lane drew for the atomic write in
`i003`, and it drew it in this exact direction:

> *"the lane notes `git.commit.set` and `git.commit.uses` write meter state the same way, and
> correctly marks that as prior art rather than this change's doing … it ripples into two skills
> this change never opened."*

🟡 the sponsor state file is **new**, so its reader was this change's to get right. the uses meter
is prior art, and a separate, larger question.
