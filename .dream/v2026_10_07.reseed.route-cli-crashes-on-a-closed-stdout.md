# 🌙 dream: the route cli crashes on a closed stdout

kind: reseed · owner: ehmpathy/rhachet-roles-bhrain (driver) · caught 2026-10-07, in route `v2026_09_26.fix-blocklist-nudge`, stone 5.1

## .the cue that fired

`rhx route.stone.set --stone <s> --as absorbed --that <slug> | head -n 1` printed a node stack
and `💥 failed with an error`, seven times in a row.

## .the gap, precisely

`head -n 1` closes the pipe after one line; the next `console.log` in
`rhachet-roles-bhrain/dist/contract/cli/route.js:1076` hits `write EPIPE`, which is an unhandled
`'error'` event on the stdout socket, so node exits nonzero. whether the absorb recorded before
the crash is not visible from the output — a re-run with `| tail -2` printed `🦉 absorbed:` for
each, so the act is idempotent, but the caller cannot tell a recorded act from a lost one.

## .the shape of the fix

in the cli entry, ignore EPIPE on stdout/stderr — `process.stdout.on('error', (e) => { if (e.code
=== 'EPIPE') process.exit(0); throw e; })` — the node equivalent of the `trap '' PIPE` the
ehmpathy hooks use. clamp: spawn the cli piped into a reader that closes after one line; assert
exit 0 and that the act recorded.

## .why it is not done in this round

it lives in another repo (rhachet-roles-bhrain). the radio is blocked globally, so a push would
only be held; this dream holds it until a human runs `rhx radio.uses --global allow`.
