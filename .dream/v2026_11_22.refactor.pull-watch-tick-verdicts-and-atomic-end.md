# 🌙 dream: the pull-watch tick reads as a dispatch, and a watch's end lands in one write

- kind: refactor
- owner: ehmpathy/rhachet-roles-ehmpathy, the git.pull.watch skill
- caught 2026-11-22

## .the cue that fired

peer review of `fix-pull-watch-daemon-respawn-loop` (5.1.execution, i004, enroll-impl-arch-defects) named four seams where convention or repetition stands in for structure. fulcrum F11 defers them from that change.

## .the gap, precisely

- `run_watch_tick` is one ~90-line loop: an 8-way rc ladder, a `token_absent` flag, a `token_fresh` flag, and several `held + continue` exits
- `set_watch_records_of_pr_ended` queues the note, then writes `.ended` under the lock. a mark that misses its lock, while the same tick's drain sends the note, lets the next tick queue it again: two notes
- token absence and keyrack faults are box-wide, yet each due pr gets its own cadence write and a bumped `poll.quiet`; after a one-tick keyrack blip, a hot pr waits a longer gap
- `is_watch_pr_unprimed_and_readable` guards an override that may only save one tick between a record's write and `set`'s cadence reset (`set.sh:184`)
- tests owed: the end-mark recovery path (a mark that misses its lock: one note, the gap held), and a `get` snapshot of an inert gone-root record (E21)

## .the shape of the fix

1. `run_watch_pr_read <repo> <pr>` sets a verdict (`read-ok` · `gone` · `dark` · `held` · `backoff`) and its cause; the loop dispatches on it. the 401 and grove-404 retries live in one `get_watch_pr_state_retried`
2. the end and its note ride one record write: `.ended` plus `.endedNote`; the drain builds the outbox entry from the record, then deletes it. the outbox scan (`is_watch_outbox_text_held`) and the "ends next tick" retry go away
3. one box-level `token.recheck.at` gate; per-pr cadence stays a measure of the pr's own quiet
4. measure the race the unprimed override covers; remove it if `set`'s cadence reset already makes a fresh watch due
5. `get` names the held token and since when (`token: seaturtle | grove | none`), so a grove token that outlives a keyrack lock is visible
6. a fork-budget clamp (reuse `pretooluse.check-permissions.forkbudget.integration.test.ts`'s shape) over one steal pass and one SessionStart run; the hook's count could then share one root memo across key dirs instead of one per `$( )`
7. the root memo held across ticks, cleared on a slow cadence (`WATCH_POLL_MAX_SECONDS`); `as_watch_key_of_record` as `${record%/watches/*}` with no fork; the hook's memo seeded with the session's own root and key
8. `del_watch_records_at_root` takes a `key_dir`, so the steal's gone-root reap shares its log text and lock path
9. the end reason stored once: `.ended = "dark"` for a dark end (today it stores `idle` and renders `dark`), with `set_watch_records_of_pr_ended <repo> <pr> <end> <detail>` that renders through `as_watch_closure_text` itself; the token source passed as its label (`grove`), so the text layer never sees the `ambient` enum
10. the SessionStart hook names an older-key record it cannot read, as it already does for its own key, instead of a silent skip in `get_watch_record_count_servable_of_clone`
11. the token read across N repo roots: with the seaturtle key locked at each, a fresh read costs N+1 keyrack reads; cut it to one per distinct keyrack, and clamp the count with a two-root scene
12. snaps of the production-scale texts (the `30 min` bound, not the test cap) and of the daemon.log lapse lines (`github answered 401 to the held … token`); a live check of whether a renamed repo answers 404 or redirects
13. clamps for each, red before and green after, plus the two owed tests above

## .why it is not done in this round

each rewrites a seam that every pull-watch suite leans on, and none fixes a defect the wish names. the respawn-loop change already holds the safe parts: the 404 branch holds its gap, a held note is not queued twice, and a token read fresh in a tick earns no second read.
