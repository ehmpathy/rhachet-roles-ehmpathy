# 🌙 dream: single-source the level-bind state contract across `bind` and `set`

- **kind**: fix
- **owner**: unclaimed
- **caught**: 2026-09-12

## .the cue that fired

a peer review lane (`enroll-impl-arch-defects`, i014 r011) named it as *"the
exact shape of the defect this drive already found and fixed for the sponsor
file"* — and it is right. `SPONSOR_STATE_FILENAME` was hoisted to
`git.commit.operations.sh` in this very drive, with this reason recorded at the
hoist:

> each built it from its own literal, so a rename applied to the writer and
> missed in a reader would leave that reader on a file nobody writes.

the level-bind pair carries that same risk, unfixed, one file over.

## .the gap, precisely

**two skills each declare the state contract from their own literals.**

the path, built independently:

```
git.commit.bind.sh:32   LEVEL_FILE="$BIND_DIR/git.commit.level"
git.commit.set.sh:287   LEVEL_FILE="$REPO_ROOT/.branch/.bind/git.commit.level"
```

the inference, declared twice (~25 lines, verbatim):

```
git.commit.bind.sh:37   infer_level_from_branch() { … }
git.commit.set.sh:54    infer_level_from_branch() { … }
```

`bind.sh` **writes** the file and `set.sh` **reads** it, so they are a
writer/reader pair on one contract — exactly the shape that makes a one-sided
rename silent. a rename in the writer leaves the reader on a path nobody
writes, and the reader's failure mode is *"no level is bound"*, which is a
legitimate state rather than an error. ⇒ **the drift would not announce
itself.**

no live defect today: the two literals resolve to the same path, and the two
function bodies agree.

## .the shape of the fix

1. lift `LEVEL_STATE_FILENAME="git.commit.level"` into
   `git.commit.operations.sh`, beside `SPONSOR_STATE_FILENAME`, which is the
   established home for exactly this cross-skill contract.
2. lift `infer_level_from_branch()` there too — it is a pure transformer over
   a branch name, with no dependency on either skill's state.
3. have both skills compose their path from the shared constant.
4. 🔴 **`git.commit.bind.sh` must first `source` `git.commit.operations.sh`** —
   it does not today. that is the whole cost of this fix; see below.
5. the twin test `git.commit.bind.integration.test.ts` clamps the bind
   behavior; the rename must leave it green with no resnap, which is the proof
   the lift preserved behavior.

## .why it is not done in this round

**SAFE: no. CLEAN: no.** (`rule.always.fix-forward-under-scouts-honor`)

- **not safe** — `git.commit.bind.sh` is untouched by this drive. the lift
  would add a `source` edge to a skill this wish never opened, and a sourced
  file runs its top level under `set -euo pipefail` in a script that has never
  run it.
- **not clean** — it ripples into a second skill plus its own test suite, for
  a contract this wish does not own.

🔴 **and this drive already paid for that exact mistake, one round earlier.**
at i012 I took a reviewer's ask to lift `EXTERNAL_CALL_TIMEOUT` out of
`keyrack.operations.sh` into the shared ancestor. it broke three tests:
`keyrack.operations.sh` is a **leaf** that sources no other file, and its test
sources it standalone. I had checked every *skill* consumer and never the
*test* harness.

⇒ **a `source` edge added to a file that has none is not a free move**, and
`git.commit.bind.sh` is in precisely that position. the fix is right; it wants
its own round, where the bind suite is the subject under test.

⚠️ the reviewer offered both outcomes — repair it before merge, **or at
minimum catch a dream** to match the one `bind` already carries. this is that
file, and it sits beside
`.dream/v2026_09_11.fix.git-commit-bind-has-no-actor-guard-of-its-own.md`,
which names the other half of the same skill's debt. **whoever picks up one
should take both** — they touch the same file for the same structural reason.
