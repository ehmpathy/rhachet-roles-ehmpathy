# 🌙 dream: git.release --watch reports a pass while the run is only queued

- kind: fix
- owner: mechanic, `git.release` (repo=ehmpathy/rhachet-roles-ehmpathy)
- caught 2026-11-25

## .the cue that fired
right after the push of #1487, `rhx git.release --watch` printed `👌 all checks passed` and `no runs inflight` in 0s, while `rhx show.gh.action.logs --flow test` showed run 45537999870 `status: queued`.

## .the gap, precisely
- the release watch reads a zero-check (or all-queued) state as a pass
- a driver that trusts it reports green before CI ran; the real verdict came from a separate watch of the run

## .the shape of the fix
- treat zero checks, or any queued check, as inflight: wait, never pass
- name the state in the tree (`⏳ queued: N`) so the wait is visible
- clamp: a fake gh with a queued run; red (passes at once) before the fix, green (waits, then reports the run's real verdict) after

## .why it is not done in this round
another skill's runtime; this pr is help text only.
