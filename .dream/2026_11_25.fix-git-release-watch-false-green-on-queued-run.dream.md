# 🌙 dream: git.release reads gh's stderr hint as part of the pr json, so it reports a false green and its retry never fires

- kind: fix
- owner: mechanic, `git.release` (repo=ehmpathy/rhachet-roles-ehmpathy)
- caught 2026-11-25

## .the cue that fired
on pr #1487, `rhx git.release --watch` printed `👌 all checks passed` while run 45537999870 sat queued, and again while run 45552238570 had 2 failed jobs (`gh pr checks 1487`: `suite / test-integration` fail, `suite / test-shards-integration (dynamic, 4, 5)` fail). `rhx git.release --retry --watch` then reran naught, since it saw no failure.

## .the gap, precisely
- `_gh_with_retry` (`src/domain.roles/mechanic/skills/git.release/git.release.operations.sh:31`) captures `output=$("$@" 2>&1)` and echoes it as the return value
- the installed gh prints a multi-line `hint: … gh event listen …` block on stderr for `gh pr view` (proven: `gh pr view 1487 --json number | <grep>` shows the hint outside the pipe, the json alone inside it)
- so `get_pr_status` returns hint text plus json; `jq '.statusCheckRollup[]?'` in `parse_check_counts` yields no rows; counts read `passed:0 failed:0 progress:0`, which renders as all passed
- every caller of `_gh_with_retry` that parses stdout is exposed: pr lookup, status, failed checks, tag runs. the retry path (`show_failed_checks` → `rerun_failed_workflows`) never runs because no check reads as failed
- the same fold may explain push's `pr #1487` / `1 (created)` line split (dream `2026_11_25.fix-push-pr-number-line-breaks-watch`); check whether push shares the capture

## .the shape of the fix
- in `_gh_with_retry`, capture stdout and stderr apart: return stdout only; use stderr for the transient match and the failloud report
- treat zero checks, or any check not COMPLETED, as inflight, never as passed; a jq parse failure on gh output must fail loud as `💥 MalfunctionError`, never read as an empty rollup
- clamp: a fake gh that writes a hint to stderr and a rollup with one FAILURE to stdout; red (reads all passed) before the fix, green (reads 1 failed, `--retry` calls `gh run rerun --failed`) after. a second clamp with a queued check: must wait, never pass

## .why it is not done in this round
another skill's runtime and its own clamp; this pr is push help text only.
