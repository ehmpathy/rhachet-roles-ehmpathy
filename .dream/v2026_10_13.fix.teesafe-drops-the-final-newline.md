# 🌙 dream: teesafe drops the final newline of what it writes

- kind: fix · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic/claude.tools/teesafe) · caught 2026-10-13

## .the cue that fired

`git show :<snap> | rhx teesafe --into <snap> --idem upsert` restored a snap byte-for-byte except
its final newline; `git diff` showed `\ No newline at end of file`. `printf '\n' | rhx teesafe
--idem append` added naught.

## .the gap, precisely

teesafe likely reads stdin via `$(cat)`, which strips final newlines. so it is not a faithful
`tee`: any file restored or written through it loses its last newline, and an append of a bare
newline is a no-op.

## .the shape of the fix

write stdin straight to the file (`cat > "$dest"` / `cat >> "$dest"`, then `cat "$dest"` for the
stdout echo), or capture with a sentinel (`content="$(cat; printf x)"; content="${content%x}"`).
a test that pipes `a\n` and asserts the file holds exactly 2 bytes.

## .why it is not done in this round

a skill fix outside this route's scope; worked around with Edit for the two snaps it touched.
