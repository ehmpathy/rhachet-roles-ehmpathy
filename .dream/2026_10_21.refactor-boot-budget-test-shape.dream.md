## .the cue that fired

5.1 i005, the two l3 lanes on `feat-mechanic-subject-101` raised six `[nitpick][better]` points

## .the gap, precisely

- `boot.budget.integration.test.ts` holds pure operations (`asBootCost`, `asBootSpecSlice`,
  `asSubjectCapBreach`, `asMessageWithCountsMasked`, `getOneCappedRoleSpecPath`) that only run in a
  suite that spawns `npx rhachet`; a rhachet outage hides their cases.
- the `union` cost (`--subject 101` = always ∪ 101, ~12k) is logged, never asserted.
- `boot.yml.integration.test.ts` pins subject.101 by exact path list; the contract lives twice.
- no test catches full-role or per-subject drift short of the 30k cap (the F7 +155 passed ci).
- the rendered `--subject 101` boot (`.min` swaps, roster) is never snapped.

## .the shape of the fix

1. `src/domain.roles/.test/rolesCost.testkit.ts` + `.test.ts`: move the pure operations; rename
   `asSubjectCapBreach` → `getOneSubjectCapBreach`.
2. tripwire: once rhachet ships the per-subject `always` opt-out, assert `union ≈ slice` and fail
   with "move the cap to `budget:` in boot.yml".
3. invariants for every row of `SUBJECT_BUDGETS`: no skills; each say row already `say` elsewhere;
   none `ref` elsewhere — then drop the exact list.
4. a drift band: snap each subject's cost rounded to the nearest 500, so +155 on a no-change wish
   reads in review.
5. snap `roles boot --subject 101` with counts masked.

## .why it is not done in this round

safe, not clean: (1) touches a testkit three suites import; (2)–(5) each pin numbers that move on
every brief edit, so each needs its own banded design; (3) replaces a pin the i003 lanes asked for.
