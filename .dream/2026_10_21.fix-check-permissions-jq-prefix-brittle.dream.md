# 🌙 dream: make the check-permissions malfunction tests independent of the jq version

kind: fix · owner: ehmpathy/rhachet-roles-ehmpathy · caught 2026-10-21

## .the cue that fired

`pretooluse.check-permissions.integration.test.ts` fails 5 cases on this host, none touched by the
change under way: case35 t1, case40 t15, case42 t0, case45 t0, case45 t1.

## .the gap, precisely

- the tests (and the case40 snapshot) expect jq's parse error to start with `jq: `
  (e.g. `/unparseable: commands\.alternatives\.jsonc \(jq: /`, snapshot `(jq: <error>)`)
- this host's jq prints `parse error: Unfinished JSON term at EOF at line 1, column 33` — no prefix
- the hook behavior is correct (the block holds, the malfunction is named); only the assertions pin
  the text of one jq release

## .the shape of the fix

- in the test's `asSnapshotSafe`, mask the parse error to one token whether or not it opens with `jq: `
  (e.g. replace `/\((?:jq: )?(?:parse )?error[^)]*\)/` with `(<jq parse error>)`)
- relax the `toMatch(/\(jq: /)` asserts to `/\((jq: )?parse error/`
- or pin jq in the test env, if the repo prefers one jq everywhere

## .why it is not done in this round

SAFE holds, CLEAN fails: it edits a 2600-line suite and a snapshot the cutover never touched; a reviewer
of the cutover should not have to judge it. small, but its own diff.
