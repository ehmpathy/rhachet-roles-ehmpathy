# 🌙 dream: drop the role hooks that boot their own role, so `npm run build` completes

kind: fix · owner: ehmpathy/rhachet-roles-ehmpathy · caught 2026-10-21

## .the cue that fired

`npm run build` on `beav/feat-git-branch-cutover` failed at its last step, `rhachet repo introspect`:

```
✋ ConstraintError: hooks that boot their own role
   ├─ architect  onBrain.onBoot[0]  rhachet roles boot --repo ehmpathy --role architect
   ├─ ergonomist onBrain.onBoot[0]  rhachet roles boot --repo ehmpathy --role ergonomist
   ├─ mechanic   onBrain.onBoot[1]  rhachet roles boot --repo .this --role any --if-present
   └─ mechanic   onBrain.onBoot[2]  rhachet roles boot --repo ehmpathy --role mechanic
```

## .the gap, precisely

- the tree carries a routine bump `rhachet 1.48.1 → 1.49.1` (package.json, uncommitted)
- 1.49.1 adds an introspect check: briefs now reach a session via the brain-dir `boot.md` render, so a
  `roles boot` onBoot hook is redundant and refused
- tsc + the dist rsync complete before introspect, so dist is whole; only `build:complete:repo` fails
- `prepare:rhachet` chains `npm run build && rhachet init`, so it fails too (init ran by hand)

## .the shape of the fix

- delete the four `roles boot` entries from the role definitions' `hooks.onBrain.onBoot`
  (architect, ergonomist, mechanic ×2) in `src/domain.roles/*/get*Role.ts`
- confirm `boot.md` renders `repo=.this/role=any` too, since mechanic onBoot[1] is the only path for it
  today — if it does not, that one needs a replacement, not a delete
- rerun `npm run build`; update any hook snapshot that lists the onBoot commands

## .why it is not done in this round

SAFE fails: the hooks decide what every session boots with, across three roles, and the
`.this/any` boot may have no replacement yet. CLEAN fails: it touches role definitions the cutover
never opened. a separate fix, with its own review.
