# 🌙 dream: git.repo.test's 0-match refusal prints a headless tree on stderr

kind: fix · owner: repo=ehmpathy mechanic · caught 2026-10-28

## .the cue that fired

5.3 self review `has-critical-paths-frictionless` on `fix-repo-test-grove-suite-bound`. a scope that
matched 0 files:

```
$ rhx git.repo.test --what unit --scope path://git.repo.test --mode apply
🐚 git.repo.test --what unit --scope path://git.repo.test --mode apply
   ├─ scope: path://git.repo.test
   │  └─ matched: 0 files
   ...
   ├─ status: constraint
   └─ error: no tests matched scope 'path://git.repo.test'
```

and the copy that reaches stderr (and so the terminal's second print):

```
├─ status: constraint
   └─ error: no tests matched scope 'path://git.repo.test'

hint: check the scope pattern or run without --scope to see all tests
```

## .the gap, precisely

the refusal prints the tree progressively on stdout, then tees only the tail (from `status` on) to
stderr. so stderr holds a branch with no root: no `🐚` header, a `├─` at column 0, and a `└─` that
hangs off it. a log aggregator or a caller that reads stderr alone sees a fragment. the hint also
breaks the `🥥 did you know?` shape the skill uses elsewhere (rule.require.treestruct-output).

## .the shape of the fix

1. emit the whole refusal (header, scope, status, error) to both streams, as the other refusals do
   (`emit_to_both` on a full block, not the tail)
2. render the hint as a `🥥 did you know?` branch
3. resnap the 0-match stderr snapshots in the play and scope suites; assert stderr starts with the
   `🐚 git.repo.test` header

## .why it is not done in this round

safe, not clean: the code predates this branch (no line of it is in `git diff origin/main`), and the
fix rewrites the stderr snapshot of every 0-match case in two suites.
