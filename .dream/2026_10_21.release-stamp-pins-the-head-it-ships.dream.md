# 🌙 dream: a release stamp pins the head it ships

kind: fix · owner: ehmpathy/mechanic · caught 2026-10-21

## .the cue that fired

peer review i004 (arch-defects 1, 2) on `v2026_10_18.feat-split-release-uses`: `--retry` reruns a
failed tag-run publish with no use spent, and an armed automerge ships commits pushed after the
stamp was spent.

## .the gap, precisely

- `git.release.sh`: the gate runs only on `MODE == apply`; `rerun_failed_workflows` runs on any
  `--retry` (`emit_transport_status.sh`)
- `git.release.operations.sh` `enable_automerge`: `gh pr merge --auto --squash`, no head pin
- `git.commit.push.sh`: push runs before any gh call, on the commit grant alone

## .the shape of the fix

1. the gate writes the pr head sha beside the spent use: `.meter/git.release.uses.jsonc` gains
   `stamped: { pr, head }`
2. `git.commit.push` reads the branch pr's `autoMergeRequest` after the push lands; if armed and
   the head moved past the stamp, it disarms (`gh pr merge --disable-auto`) and says a restamp is
   owed
3. `--retry` on a tag transport reads the stamp: a rerun of the stamped head is free, any other
   needs a use

## .why it is not done in this round

dirty: a new stamp contract (F26). the vision counts applies, and keeps push un-gated by gh.
