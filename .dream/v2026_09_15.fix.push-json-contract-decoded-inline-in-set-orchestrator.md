# 🌙 dream: the delegated push/pr-open json contract is decoded inline in `git.commit.set.sh`

- **kind** = fix
- **owner** = ehmpathy/rhachet-roles-ehmpathy
- **caught** = 2026-09-15

## .the cue that fired

`mech-decode-friction` (i046, nitpick.2) found that both the plan-mode and apply-mode arms of
`git.commit.set.sh` extract the delegated `git.commit.push.sh` call's raw json contract inline:
`PUSH_PLAN_STATUS=$(echo "$PUSH_PLAN_JSON" | jq -r '.status')` in plan mode, and
`PUSH_RESULT_STATUS`/`PUSH_TARGET`/`PUSH_AUTH_WHO`/etc in apply mode.

## .the gap, precisely

a reader must know the delegated call's json shape (a `.status` enum, an `.error` carried on the
failure path, an `.auth` label, the empty-json fallback) to know what each positional extraction
produces. the file already extracted the boolean half of this same boundary into named predicates
(`is_push_shipped`/`is_push_failed`); the field-extraction half of the identical boundary stays
raw inline decode-friction in the orchestrator.

## .the shape of the fix

a named communicator leaf (e.g. `asPushResultFromJson`) that takes the raw
`git.commit.push.sh --output json` stdout and returns the named fields the orchestrator reads —
the same shape the file's own `is_push_shipped`/`is_push_failed` predicates already set for the
boolean half of this boundary.

## .why it is not done in this round

**SAFE: yes — a pure extraction of an already-correct decode, no behavior change intended.**

**CLEAN: no.** the boundary spans two modes (plan and apply) and five-plus fields, and this
round already touched the same apply-mode block twice for real defects (the `--repo` shift guard,
the org-meter byte fix). a third edit to the identical block under this round's time budget risks
the push-flow tests this wish's own critipath (`case=44`, `case=7`) depends on — better done as
its own deliberate pass.
