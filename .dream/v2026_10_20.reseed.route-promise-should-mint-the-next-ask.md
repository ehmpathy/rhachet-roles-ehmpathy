# 🌙 dream: a self-review promise should mint the next review's ask

kind: reseed · owner: ehmpathy/rhachet-roles-bhrain (driver) · caught 2026-10-20

## .the cue that fired

on stone `1.vision` of this route, `rhx route.stone.set --as promised` for review N/5 printed the
full guide for review N+1 — slug, guide, `articulate into` path. a promise written against that
path was then refused: `🍃 no ask on record … rhx route.stone.set --stone 1.vision --as passed`.
three of five reviews hit it.

## .the gap, precisely

the promise output renders the next ask as if it were minted, but the ask only mints on the next
`--as passed|arrived`. a driver who follows the printed path writes the file before the ask, so
the freshness bar refuses it too, and the driver must ask, re-save, promise.

## .the shape of the fix

either mint the next ask when a promise succeeds (one step, as the render already implies), or
render the next guide only after an explicit `--as passed`, and say so in the promise output.

## .why it is not done in this round

it belongs to rhachet-roles-bhrain; this round is scoped to `git.package.patch`.
