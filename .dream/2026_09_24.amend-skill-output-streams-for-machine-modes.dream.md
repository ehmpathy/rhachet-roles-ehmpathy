# 🌙 dream: amend `rule.require.skill-output-streams` with a machine-mode carve-out

- **kind**: reseed (a house rule, not one skill)
- **owner**: the council — the rule governs every skill with a machine-faced output mode
- **caught**: 2026-09-24, from `v2026_09_03.fix-grepsafe-slashed-glob` @ F20

## .the cue that fired

the wisher ruled F20 option A: grepsafe's pipeable-mode refusals go to stderr only. the rule that
grades that a blocker is unchanged, so review lanes re-raise it — two lanes, six rounds.

## .the gap, precisely

the rule has one failure row, *"yes stdout, yes stderr"*, and *"error output without stdout =
blocker"*. it assumes stdout is a human's stream. under a machine-faced mode, stdout is data a caller
pipes, and an error there is consumed as a result.

`--output pipeable` exists in `grepsafe.sh` and `globsafe.sh`. every future pipe-faced mode meets the
same fork: obey the letter and corrupt a pipeline, or deviate and draw a permanent blocker.

## .the shape of the fix

split the failure row by mode:

```
| case                                           | stdout | stderr |
|------------------------------------------------|--------|--------|
| failure, human-faced output                    | yes    | yes    |
| failure, machine-faced output (stdout is DATA) | no     | yes    |
```

rationale: where a caller opted into a data-only mode, an error on stdout is a false result — the
harm the rule exists to prevent.

test: does a caller pipe this mode's stdout into another program? yes → stderr only. no → both.

## .why it is not done in this round

- **SAFE?** no. it rewrites a house rule that governs every skill and every rubric that cites it.
- **CLEAN?** no. it lands outside this route's declared `src/**`.

a driver should not amend the rule they are graded against. F20 blessed the conduct; only a council
can bless the rule.
