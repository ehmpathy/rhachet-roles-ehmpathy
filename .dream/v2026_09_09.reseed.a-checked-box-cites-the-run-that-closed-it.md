# 🌙 dream: a checked box must cite the run that closed it

**kind:** reseed · **owner:** driver (`bhrain/role=driver`) · **caught:** 2026-09-09

## .the cue that fired

a late task notification surfaced a stale failed run. the audit it forced found that **four**
`git.repo.test` integration logs sat on disk and **not one** recorded the green verdicts the drive
had been citing for hours.

| the claim in the yield | the newest log that exists |
|---|---|
| sponsor suite **28/28** | `20-26-16Z` — 26 tests, **1 failed** |
| `git.commit` scope **274/274** | `18-42-09Z` — 92 tests, **23 failed** (pre-repair) |

⇒ the repairs were real and each failure had been diagnosed. what was absent is the **re-run that
proves it** — and a `[x]` had been written as though that re-run had happened.

## .the gap, precisely

🔴 **the driver's own checklist is an unverified artifact that reads as a verified one.**

`philosophy.verification-strictness` already forbids *"unproven claims — cite command + output or
it's a guess."* it is written for **deliverables**. no rule points it at the **progress record**,
so a yield's checkboxes are exempt by omission.

⇒ and the exemption bites hardest exactly where it matters: a driver re-reads its own checklist to
decide whether a stone is ready to signal. **a pre-ticked box is how a stone arrives with unproven
work behind it.**

⚠️ the failure mode is `rule.require.snapshots`' twin, one level up:

| artifact | what the eye checks | what it skips |
|---|---|---|
| a snapshot | did it **change**? | is it **right**? |
| a checkbox | is it **ticked**? | does the tick have **evidence**? |

⇒ **a record that is easy to read is trusted in place of the thing it records.**

🟡 the mechanism that produced it is mundane and will recur: the box was ticked when the item was
**true** (8 cases, 25 tests, green), then the artifact grew (a 9th case), the suite went red, a
repair landed — and **no step in that sequence unticks the box.** a tick is monotonic; the truth it
asserts is not.

## .the shape of the fix

a `rule.always.*` in `bhrain/role=driver`, since the subject is a **verb phrase** — *cite the run,
each time you tick* (`rules101.structure`: an `always` grades the trail, not the state).

> **a checked box names the command that closed it and the run that proved it. a box with no
> citation is not checked.**

concretely, per item:

```md
- [x] **E1** the sponsor suite — `rhx git.repo.test --what integration --scope path://sponsor`
      ⇒ `.log/…/2026-09-09T20-26-16Z` — 28/28
- [~] **E1** written, NOT proven — the newest run on disk is red
```

⇒ three parts earn their keep:

1. **the citation** — a log path or a run id, never a remembered number
2. 🔴 **a third state, `[~]`** — *written but unproven*. today a driver has only done/not-done, so
   work that is complete-but-unverified gets rounded **up**, every time
3. **the untick trigger** — where an artifact changes after its box was ticked, the box drops to
   `[~]`. this is the step that was absent above

⚠️ **do not reach for a tool first.** the cheap version is a habit plus a symbol, and the expensive
version (a guard that greps yields for uncited ticks) should follow only if the habit fails.

## .why it is not done in this round

**SAFE: no. CLEAN: no.**

- **safe** — it is a rule for another repo's role. authored here, it would bind naught
- **clean** — it ripples into the driver's brief set and into every extant yield template

⇒ and this round's own remedy was applied where it lands: `E1` was demoted to `[~]`, the two
uncited claims were named, and `F4` was added as the run that settles them. **the local repair is
done; the generalization is what is deferred.**

⇒ 🟡 no fulcrum is owed — this is a process lesson caught in passing, not a fork in the sponsor
contract.
