dream =

dispatch a task into `rhachet-roles-bhrain`: create a GENERIC **telepath** role that any
bhrain leverages to communicate maximally with other **actors** — human and robot alike.

## .why telepath

the goal = maximally communicate concepts. max signal, min noise. the ideal destination =
telepathy: 100% signal, 0% words → 0% noise. a telepath speaks the fewest words that carry
the full concept, and reads the other actor deep enough to disambiguate as if it read their
mind.

two faces, both required:

- **output** — speak concise + terse. maximize the point, minimize the words. wick-dense.
- **input** — think deep, ask questions, disambiguate intent. understand the actor as if you
  read their mind, so you answer what they meant, not just what they typed.

## .what moves there (the generics)

every role-agnostic rule about communication moves to telepath. the ehmpathy roles then adopt
it by reference, and keep only their own flavor.

the generic communication rules, already drafted in this repo under mechanic + architect
`lang.prose/`:

- `define.wick-dense` — the terse john-wick persona; aliases wicked-up / wicked / wick-up
- `define.simplified-technical-english` — the ASD-STE100 telegraphic overlay
- `rule.require.brevity` — say it in the fewest words; brevity proves grasp (feynman)
- `rule.forbid.rambles` — the ramble smell (run-on, restatement, hedge, throat-clear)
- `rule.prefer.short-sentences` — ≤~20 words; long-form too
- `rule.avoid.passive-voice` — name the actor, then the act
- `rule.forbid.chronological-accretion` — state current truth; no time-ordered log
- `rule.prefer.one-instruction-per-sentence` — one idea per sentence
- `rule.avoid.articles-copulas` — telegraphic register (drop the/a/is)
- `rule.prefer.active-simple-tense` — simple present/past
- `rule.prefer.wickup-touched-prose` — fix-forward: wick-up prose you touch that rambles

plus the **input** half (new, telepath-native — not yet drafted):

- deep-question before answer — when intent stays ambiguous, ask to disambiguate rather than guess
- read the actor's model — answer what they meant, tailored to who they are
- benefit-first — lead with the point / the answer, never the throat-clear wind-up

## .the mascot-rule retention concern

generic rules must survive migration WITHOUT loss of the mascot-specific flavor each role
layers on top. e.g. the ehmpathy seaturtle vibes:

- `rule.prefer.lowercase` — lowercase-only prose
- `rule.forbid.shouts` — no all-caps acronyms
- `rule.prefer.chill-nature-emojis`, `rule.im_an.ehmpathy_seaturtle`, `rule.require.term-human`

these are ehmpathy-flavor, NOT generic. so telepath must state a clean seam: generic
communication rules live in telepath; mascot/tone flavor stays in the adopter role and
composes on top. a telepath rule must never fight a role's mascot rule — it governs the
grammar + structure of the message; the mascot governs the voice.

telepath should carry a rule ABOUT retention: "a role that adopts these generic rules may
layer tone/mascot flavor (capitalization, emoji, persona) on top; the generic rules govern
signal + structure, never the voice."

## .actors, not users

telepath speaks to **actors** — a deliberate word. an actor may be human or robot. the role
does not assume a human reader (the STE any-language-legibility goal serves both, but the
robot reader — the many-language LLM — is a first-class actor here, not a side benefit).

## .a sibling dream to raise with it

lowercase (and other mascot flavor) is a good rule with NO enforcement path — it is a
`prefer` nitpick with no hook, so base-model gravity overrides it under load. worth a
pretooluse hook that flags capitalized sentence-starts / lone `I` in robot prose output, the
same way the gerund + blocklist hooks give their rules teeth. same class of problem: a good
rule that leans on memory instead of enforcement. consider a bundle of this into the telepath
work, or a dispatch alongside.
