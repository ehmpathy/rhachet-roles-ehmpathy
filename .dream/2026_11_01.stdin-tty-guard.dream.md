# 🌙 dream: refuse `--from @stdin` when stdin is a terminal

kind: friction fix · owner: mechanic skills · caught 2026-11-01

## .the cue that fired
peer r010 on `feat-git-pull-title-description` 5.1: a human who runs
`rhx git.pull.description set --from @stdin` with no pipe sees naught — the read waits on the tty.

## .the gap, precisely
`git.pull.description.set.sh --from @stdin`, `git.pull.title.set.sh --title @stdin`, and
`git.pull.comment.set.sh --from @stdin` read fd 0 via `as_body_trimmed` with no check that fd 0 is
a pipe or file. silent wait = `rule.require.status-feedback` blocker.

## .the shape of the fix
one shared check in `git.pull.comment.operations.sh`, given the flag name that took `@stdin`:
`[[ "$value" != "@stdin" || ! -t 0 ]] || fail_comment_constraint "$flag @stdin reads a pipe, and stdin is a terminal" "pass a file: --from ./.temp/body.md"`
called by all three set verbs. clamp: run each verb with fd 0 on a pty (util-linux's pty wrapper).

## .why it is not done in this round
not CLEAN: it spans the shipped comment family (#1143) and needs a pty harness (fulcrum F14).
