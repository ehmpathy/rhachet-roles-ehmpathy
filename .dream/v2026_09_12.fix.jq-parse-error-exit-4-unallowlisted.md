# 🌙 dream: three hooks fail CLOSED on malformed json, because jq now exits 4

- **kind** = fix
- **owner** = ehmpathy/rhachet-roles-ehmpathy
- **caught** = 2026-09-12

## .the cue that fired

a full `--scope path://claude.hooks` run under `v2026_09_09.fix-hook-fork-storm` stone 5.1
returned **711 passed, 4 failed**. one failure was mine; the other three were not.

⇒ **the cue was a wide test run, never a hunt.** a narrower scope — the two hooks this wish
owns — would have reported 104/104 green and disclosed none of it.

## .the gap, precisely

three hooks allowlist jq's parse-error exit code by an explicit pair:

```bash
# pretooluse.forbid-cross-repo-access.sh:94-99
# jq reports an input/parse error as exit 2 (jq <=1.6) or 5 (jq >=1.7); allowlist both
JQ_STATUS=0
TOOL_NAME=$(echo "$STDIN_INPUT" | jq -r '.tool_name // empty') || JQ_STATUS=$?
if [[ $JQ_STATUS -eq 2 || $JQ_STATUS -eq 5 ]]; then
  emit_both "WARN: PreToolUse hook could not parse stdin as JSON; allow tool call"
  exit 0
fi
if [[ $JQ_STATUS -ne 0 ]]; then
  emit_both "ERROR: PreToolUse hook hit an unexpected jq failure (exit $JQ_STATUS)"
  exit "$JQ_STATUS"          # ← this branch is what fires now
fi
```

**the jq on this box exits 4**, which the pair does not hold. so the "unexpected failure" branch
is taken, and the hook exits 4.

### the consequence, and it is the worse direction

| | intended | actual |
|---|---|---|
| malformed stdin | **fail OPEN, loud** — exit 0, warn on both streams | **fail CLOSED** — exit 4 |

a PreToolUse hook that exits nonzero **refuses the tool call**. ⇒ a single malformed payload now
halts the caller at three separate gates, where the declared contract is *"a hook that cannot read
its input must not block every tool call in the session"* (the test's own comment).

### the three, and their failed assertions

| hook | the case | how it fails |
|---|---|---|
| `pretooluse.forbid-cross-repo-access.sh` | `[case12] [t0]` — *"fails OPEN, but loud on both streams"* | exit `4`, expected `0` |
| `pretooluse.forbid-shouted-readme.sh` | `[case6] [t2]` — *"malformed json exits 0 with a loud warn"* | exit `4`, expected `0` |
| 🔴 `permissionrequest.decide-permissions.sh` | `[case10] [t5]` — *"the settings json is malformed (allow-list degrades)"* | **a SNAPSHOT mismatch, never an exit code** |

### 🔴 the third one is a DIFFERENT failure mode of the same root cause, and shape 2 does not fix it

`decide-permissions` does not trip the exit-code table at all. it trips a **message mask**:

```ts
.replace(/jq: parse error:.*/g, 'jq: parse error: <JQ_CAUSE>');
```

| | the mask expects | this box's jq emits |
|---|---|---|
| prefix | `jq: parse error: …` | `parse error: Invalid literal at line 1, column 7` |

⇒ the mask never matches, so the **unmasked** cause leaks into the snapshot and the line diffs. the
hook's behavior is correct; the *test's* normalizer is keyed to a message format that moved.

🔴 **this matters for the fix, not merely for the record.** shape 2 below inverts the exit-code
test — and this site has no exit-code test to invert. ⇒ **a fix that closes the first two leaves the
third red**, and a driver who verifies by "the exit-4 cases are green now" would ship it that way.

⚠️ **and the deeper lesson is about the mask, not jq.** a normalizer that anchors on a vendor's
*prose* is a version table with no version in it — it degrades to a no-op silently, and a no-op mask
does not fail loudly, it merely stops to normalize. ⇒ the durable shape is to anchor on the part
that is ours (`could not parse <SETTINGS> as json; allow list degraded:`) and mask the whole
remainder of the line, whatever the vendor says.

### checkable evidence

```
git diff main --stat -- src/domain.roles/mechanic/inits/claude.hooks/
```

⇒ all three are **byte-identical to `main`**, so the defect predates the fork-storm diff and is

## .the shape of the fix

the pair is a hard-coded version table, and a version table drifts by construction. two shapes:

1. **widen the allowlist** — add `4`. cheapest, and it will drift again on the next jq release.
2. 🔴 **invert the test** — stop to enumerate jq's *parse-error* codes, and instead treat **every**
   nonzero jq status on a fixed-literal program as a parse error. the comment above the code
   already argues this is sound: *"jq is confirmed present above and the jq program is a fixed
   literal that always compiles — so the single expected failure is a malformed-JSON parse error."*
   ⇒ the code enumerates anyway, against its own stated reason.

shape 2 is the durable one. the `exit "$JQ_STATUS"` branch it removes has never fired for a real
cause — its only observed trip is this false positive.

⚠️ **and a clamp is owed that the extant tests do not give**: they assert the *outcome* (exit 0,
warn on both streams) for one malformed input. none asserts the *mechanism*, so the suite went red
on a jq upgrade rather than on a behavior change. a clamp that stubs `jq` on PATH to exit an
arbitrary nonzero code would hold shape 2 honest across every future jq.

## .why it is not done in this round

the SAFE/CLEAN test, run honestly:

| question | answer |
|---|---|
| **SAFE?** | 🔴 **no.** it changes the block/permit behavior of three hooks this wish does not own, on a path where "fail open" and "fail closed" are opposite security postures |
| **CLEAN?** | 🟡 **borderline.** the code edit is small, but the wish's boundary is explicit — *"do not touch the other PreToolUse hooks unless a shared-cost fix genuinely lands there too"*, and this is not a shared-cost fix. it is an unrelated defect |

⇒ **SAFE is a hard no**, so it defers. the wish's own words are the reason: *"a behavior change
smuggled into a cost change is unreviewable."* a security-posture flip for three hooks, ridden
along inside a fork-count diff, is the exact shape that clause forbids.

## .the note worth a keep beyond the fix

🔴 **a version-code allowlist is a failhide with a long fuse.** it reads as careful — it names two
versions, it cites them in a comment, it has an else branch that fails loud. and its failure mode
is that the loud branch takes the **benign** case while the tool's contract inverts silently.

> ⇒ where a comment can argue *"the single expected failure is X"*, the code should test for
> **not-success**, never enumerate the codes of X. the enumeration adds no safety and takes on a
> maintenance debt keyed to someone else's release schedule.

⚠️ and the second note, about the search rather than the defect: **this was found by a test run
whose scope was wider than the change.** a driver who scopes every run to the files they touched
never sees a repo-wide red, and these three hooks have been red here for as long as this box's jq
has been installed.
