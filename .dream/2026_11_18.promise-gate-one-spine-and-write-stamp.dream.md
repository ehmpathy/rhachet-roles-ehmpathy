## .the gap, precisely
- the writers `set_one_gh_resource` and `set_one_gh_pull_field` do not demand that the gate passed; a new caller can skip it
- `guard_push_text_promised` and `check_text_promise` share one spine (skip if promised, read, return if ungated, keep, nudge, refuse, exit 2) in two copies; the push json drops `cause`
- the three pull verbs each rebuild the pipe, note, keep path, keep text, and rerun before the gate call
- set forwards `--promise` to push after its own read found the repo private, so push's retry hints name a promise the caller never gave
- `set_push_pr_token` both fetches and exits (identity assert), so a push plan under as-ehmpath can unlock or exit 2
- no test drives the as-ehmpath path with a real token through either gate; set's keyrack-outage case is untested
- `git.promise.operations.sh` is sourced four times; the argv renderers sit in the promise leaf

## .the shape of the fix
1. `TEXT_PROMISE_PASSED_REPO` stamp, set on every pass by the gate; both writers fail as a malfunction without it
2. one `guard_text_promised` in `skills/git/` that takes a reader and a refuser, plus a `set_text_kept` leaf; one `check_pull_text_promised` for the three pull verbs
3. set exports a vetted flag (like `SEATURTLE_PR_TOKEN_*`) instead of `--promise` to push
4. `set_push_pr_token` only fetches; the identity assert runs once at the apply site
5. as-ehmpath gate cases for push and set, under a fake keyrack token; a set case=10 test
