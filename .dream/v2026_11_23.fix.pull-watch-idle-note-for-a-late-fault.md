# 🌙 dream: the pull-watch idle note names a fault that began after the last change

kind: fix · owner: mechanic (git.pull.watch) · caught 2026-11-23

## .the cue that fired

a peer review of 5.3 on `fix-pull-watch-daemon-respawn-loop` (r4, ergo-acceptance-journey-coverage, nitpick.1).

## .the gap, precisely

`set_watch_idle_ended` sends the `dark` note (`unreadable for <ttl>`) only when `read.fault.since` spans the whole idle ttl. a pr that changed at T, read fine, then faulted from T+δ keeps `poll.changed = T`, so at T+ttl it ends with the `quiet for <ttl>` note. for its last stretch it was unread, not quiet.

## .the shape of the fix

- `set_watch_idle_ended`: when a `read.fault` exists but spans less than the ttl, render `as_watch_closure_text <pr> idle <cause> <span>`
- `as_watch_closure_text … idle`: with a cause, the header reads `#N quiet for <ttl>, unread for its last <span>; watch ended`, then `├─ last fault: <cause>`, then the rewatch
- clamp: a health case that reads #N fine, flips it to 403, and waits out the ttl; assert the two-span header and snap it. revert the branch → the `quiet` note returns → red
- add the row to the route's experience inventory (D1 `open` → `dark` mid-life × idle ttl)

## .why it is not done in this round

it adds a header form to the closure note contract, a scene step, a snap, and a vision row: past this diff's scope (F14). the edge ends on time; only its label undersells the fault.
