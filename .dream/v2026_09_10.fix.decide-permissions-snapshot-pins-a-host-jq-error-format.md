# 🌙 dream: mask the jq error text so the decide-permissions snapshot stops pinned to a host jq build

- kind: fix
- owner: mechanic
- caught: 2026-09-10

## .the cue that fired

a coverage round widened the test scope past the changed files, and
`permissionrequest.decide-permissions.integration.test.ts` `[case10][t5]` failed on a host
that had never run it before. the diff was two lines, and both differed only by a prefix.

## .the gap, precisely

the test masks jq's error text before it snapshots:

```ts
// permissionrequest.decide-permissions.integration.test.ts:1454
.replace(/jq: parse error:.*/g, 'jq: parse error: <JQ_CAUSE>');
```

the mask requires a literal `jq: ` prefix. this host's jq emits the parse error with no
prefix at all, so the mask never applies and the raw text reaches the snapshot:

```
- └─ could not parse <SETTINGS> as json; allow list degraded: jq: parse error: <JQ_CAUSE>
+ └─ could not parse <SETTINGS> as json; allow list degraded: parse error: Invalid literal at line 1, column 7
```

⇒ the snapshot pins **one jq build's error string**, so the suite is red on any host whose
jq words a parse error differently. that is a `rule.require.hermetic-tests` defect: the
test depends on host state it never provisioned (`rule.forbid.bare-host-deps`).

⚠️ **the column number is host data too.** even with the prefix made optional, `at line 1,
column 7` is jq's own cursor and may move between builds — so a mask that only relaxes the
prefix leaves the same class of breakage in place.

## .the shape of the fix

make the mask match the whole jq diagnostic rather than one build's phrasing of it:

```ts
.replace(/(jq: )?parse error:.*/g, 'parse error: <JQ_CAUSE>');
```

then resnap `[case10][t5]`. ⇒ the assertion keeps its real subject — *the hook reports a
degraded list and names the settings file* — and drops the part that was never the point.

🟡 verify on both jq variants before you land it. a fix validated on one build only moves
the breakage to the other, which is the defect this dream describes.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **SAFE** — ✅ a mask widened in one test; no prod path moves
- **CLEAN** — 🔴 **no.** the whole `claude.hooks/` dir is untouched by this branch
  (`git status --porcelain src/domain.roles/mechanic/inits/claude.hooks` → empty), so the
  fix opens a file and a snapshot this change never intended to touch. and the snapshot was
  authored on a jq this host does not have, so **the fix cannot be validated here** — only
  its symptom on one side.

⇒ a repair I cannot verify against the other build is a guess with a resnap attached, and a
resnap of someone else's baseline is the one edit hardest to review. deferred.

## .the other failure in the same run, and why it is NOT here

`pretooluse.check-permissions` `[case23]` breached its 3s budget at 5181ms in a loaded
192s run, and **passed in 6s when run alone**. that is load-induced, not a defect — no
dream owed.
