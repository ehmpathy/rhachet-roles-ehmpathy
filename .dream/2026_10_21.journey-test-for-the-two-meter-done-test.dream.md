# 🌙 dream: one journey test for the two-meter done-test

kind: test · owner: mechanic (rhachet-roles-ehmpathy) · caught 2026-10-21

## .the cue that fired

peer review i003 on `5.1.execution.from_vision` (route `v2026_10_18.feat-split-release-uses`):
behavior-intent-coverage nitpick.2. the wish closes on one done-test — a commit grant lets a crew
rebase and push, and a release from that tree still refuses until `git.release.uses` is granted.

## .the gap, precisely

each meter is proven alone: commit + push suites, the release gate in p2, the 24-cell AND matrix.
no single test walks one tree through the seam the wish exists to prove. a regression where a
commit grant leaks release auth, or the gate reads the commit meter, would leave each piece green.

checkable: `rhx grepsafe --pattern 'git.release.uses' --path blackbox` shows two cases (a `get`
and a robot refusal), none that pairs a commit grant with a release refusal.

## .the shape of the fix

one `blackbox/git.meters.journey.acceptance.test.ts`, one temp repo with a mocked `gh`:

1. `[t0]` `git.commit.uses set --quant 1` → `git.commit.set --push` lands and pushes
2. `[t1]` `git.release --mode apply` → exit 2, "no release grant on this tree", commit grant untouched
3. `[t2]` `git.release.uses set --quant 1` → apply proceeds, release meter spends to 0
4. `[t3]` `git.commit.uses del` → push refuses; release meter still reads 0, untouched by the del

snap each step's stdout. the wish's literal command (`--push allow`) now refuses; the journey is
its current-idiom form.

## .why it is not done in this round

safe, not clean. it needs the gh mock and the commit identity fixtures lifted from the p-suites
into `blackbox/.test/`, a new acceptance harness edge. the per-meter suites cover each step.
