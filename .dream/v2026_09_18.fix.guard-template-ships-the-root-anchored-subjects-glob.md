# 🌙 dream: the bhuild guard template ships the root-anchored subjects glob, so every stone re-acquires the OOM

- **kind** = reseed
- **owner** = `repo=bhuild/role=behaver` (upstream: `ehmpathy/rhachet-roles-bhuild`)
- **caught** = 2026-09-18, at stone `5.3.verification`, after the third round of lane malfunctions

## .the cue that fired

`5.1.execution` was repaired at i017 by **F14** — narrow the l1 subjects glob off the repo root —
and the lanes went from *0 log files / OOM after ~15 min* to *10 log files / ~2 min*.

**then `5.3.verification` malfunctioned in exactly the same shape.** the obvious read is that the fix
was reverted. it was not: `5.3.verification.guard` never carried it.

## .the gap, precisely

the guard names its own provenance:

```yaml
provenance:
  uri: node_modules/rhachet-roles-bhuild/dist/domain.operations/behavior/init/templates/5.3.verification.guard
```

and the template ships the defect **at identical line numbers**:

```
template :234   --paths-with '**/*.{ts,sh,md,snap}'      ← root-anchored
   guard :234   --paths-with '**/*.{ts,sh,md,snap}'      ← byte-identical
   …
template :274   --paths-with '{src,blackbox}/**/*.test.ts'   ← the one anchored lane
   guard :274   --paths-with '{src,blackbox}/**/*.test.ts'
```

⇒ **8 of 9 l1 lanes ship root-anchored, in the template.** a root-anchored subjects glob walks the
repo root, and `enumFilesFromGlob.js` applies the gitignore filter **to the result, never to the
traversal**, with `followSymbolicLinks: true`. so the walk follows `.temp/genTempDir.symlink` out of
the repository — measured here today at **6,753 dirs / 6,722 files**, and growth is monotonic with
test activity.

### 🔴 why this compounds the walk defect it triggers

the walk defect beneath it is already dreamed
(`v2026_09_13.fix.review-glob-walks-gitignored-temp-via-symlink.md`) and it is a **reviewer**
problem. this is a separate one, stacked on top:

| | |
|---|---|
| **it re-arms per stone** | each stone generates a fresh guard from the template, so a repair on stone N does not reach stone N+1. the driver pays the full diagnosis again |
| **and it looks like a regression** | the second occurrence reads as *"the fix was reverted"*, which sends the next driver after a revert that never happened. **it cost me a full round to tell those two apart** |
| **it needs a human grant to repair** | `route.mutate.guard` seals guard files, and its grant is human-owned — so every re-acquisition also costs a human round-trip |
| **it is silent** | the lane returns `💥 malfunction` with an empty log dir and no count, which `asPeerGivenVerdict` scores as one blocker. no message names the glob |

⇒ **a defect that re-arms itself on a schedule, is human-gated to fix, and disguises itself as a
regression.** the local repair is a treadmill; the template is the brake.

## .the shape of the fix

1. 🔴 **anchor the template's 8 root-anchored lanes**, exactly as lane `:274` already is. the proven
   form, measured at i017: `'{src,.behavior,.dream,.claude}/**/*.{ts,sh,md,snap}'` → 3,572 files in
   596ms, against a TIMEOUT at 30s.
   ⚠️ **the root set is repo-specific**, which is the real design question — a template cannot know
   a consumer's top-level dirs. so prefer (2).
2. ✅ **better: fix it at the cause and leave the template alone.** if `enumFilesFromGlob` prunes
   gitignored paths from the **walk** rather than the result, the root-anchored glob becomes cheap
   again and no template needs per-repo knowledge. ⇒ that is lever 1 of the walk dream, and **this
   dream is a second, independent reason to take it.**
3. if neither lands soon: have `route.guard.upgrade` carry a repo's anchored root set forward, so a
   repair on one stone propagates to the next. **partial** — it fixes propagation, never the default.

⇒ **(2) is the root fix; (1) is relief with a known flaw; (3) addresses only the re-arm.**

## .why it is not done in this round

**SAFE 🔴 · CLEAN 🔴.**

| question | verdict |
|---|---|
| **SAFE?** | 🔴 **no.** the template governs the review scope of **every behavior route in every consumer repo**. a wrong root set silently shrinks what reviewers see — the one defect class a reviewer cannot self-detect. and the correct root set is repo-specific, which is the unsolved part |
| **CLEAN?** | 🔴 **no.** the file is `rhachet-roles-bhuild/dist/…/templates/5.3.verification.guard`, a published package this wish does not own. this route's subject is two bash hooks. a `node_modules` edit would be erased by the next install |

⇒ caught as a **reseed**.

🔴 **what this round DID owe, and paid:** this stone's own guard is narrowed (F15), with `.agent`
added to F14's four roots because re-verification found a `.md` file outside them — so the anchor
holds **zero scope delta today**, rather than inherit a zero-delta claim measured four days ago. the
privilege was granted, used for the bind only, and revoked. ⇒ **the deferral is of the upstream
repair, never of the local one.**
