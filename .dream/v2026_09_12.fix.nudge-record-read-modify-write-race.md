# 🌙 dream: the HARDNUDGE record is a read-modify-write with no lock

- **kind** = fix
- **owner** = ehmpathy/rhachet-roles-ehmpathy
- **caught** = 2026-09-12

## .the cue that fired

peer reviewer `arch-hazards-behavior` graded it a **blocker** on round 1 of
`v2026_09_09.fix-hook-fork-storm` stone 5.1. the lines are rewritten by that diff, so a
diff-scoped reviewer sees them; their concurrency semantics are untouched from `main`.

⇒ **the cue was a reviewer bound to a diff, never a hunt for this defect.** nobody had concurrency
in view — the wish is a fork-count fix.

## .the gap, precisely

both hooks persist HARDNUDGE state as an unlocked read-modify-write over a shared file:

```bash
# blocklist.sh · gerunds.sh — the stamp
TMP_FILE=$(mktemp)
jq --arg key "$NUDGE_KEY" … "$NUDGE_FILE" > "$TMP_FILE" && mv "$TMP_FILE" "$NUDGE_FILE"
```

and, separately and earlier, the read that decides the verdict:

```bash
LAST_ATTEMPT=$(jq -r --arg key "$NUDGE_KEY" '.[$key].time // 0' "$NUDGE_FILE")
```

two defects, one shape:

| # | the race | the consequence |
|---|---|---|
| 1 | two invocations both read before either `mv`s | the second **clobbers** the first ⇒ a block-stamp is lost ⇒ a legitimate in-window retry is refused **again** |
| 2 | the `LAST_ATTEMPT` read and the stamp write are not atomic | a TOCTOU window between "am I inside the window?" and "record that I blocked" |

⚠️ **the wish's own opening scenario is the trigger.** it starts from a grove of ~17 clones over 4
cores, so concurrent invocations of the same hook against the same repo are the **normal** case
here, not an edge.

### checkable evidence

```
git show main:…/pretooluse.forbid-terms.blocklist.sh   → same jq > TMP && mv, no lock
git show main:…/pretooluse.forbid-terms.gerunds.sh     → same
```

⇒ it predates the fork-storm wish. that is why it was deferred, and it is also why it has survived
unnoticed: no test exercises two concurrent invocations.

## .the shape of the fix

wrap both the read and the write in one critical section per nudge file:

```bash
exec {lock}>"$NUDGE_FILE.lock"
flock "$lock"
#   read LAST_ATTEMPT
#   decide the verdict
#   stamp, if a block
exec {lock}>&-
```

🟡 **two design points a later traveler will hit, so they are recorded now while the context is
held:**

1. **`flock` is not on macos by default.** it needs a fallback — a `mkdir` lock is portable and
   cheap, and `mkdir` is atomic on every posix fs. a hook that hard-requires `flock` breaks every
   mac contributor.
2. **the lock costs a fork**, and this wish exists to remove forks. ⇒ take the lock **only on the
   block path**, never on the clean path. the clean path never touches the nudge file at all
   (already true after the stale-sweep re-sequence), so the hot path pays zero.

⇒ and the clamp that proves it: spawn N concurrent hooks against one cwd and one file path, then
assert the record holds N stamps rather than one. it goes red under the current code.

## .why it is not done in this round

the SAFE/CLEAN test, run honestly:

| question | answer |
|---|---|
| **SAFE?** | 🔴 **no.** a lock changes HARDNUDGE behavior under contention — today one stamp is lost, under a lock the second waits. acceptance #3 says that behavior is **unchanged**, and contention is exactly the condition this wish's diff is judged on |
| **CLEAN?** | 🔴 **no.** it needs a portability fallback, a concurrency test harness this repo has none of, and it lands in the one code path the wish promised not to alter |

⇒ both no ⇒ defer, and record. ⚠️ **a fulcrum is owed beside this one**: the deferral rests on a
judgment that a race which predates the diff does not become this diff's to fix merely because the
diff rewrote its neighbourhood. a reviewer disputed that judgment, so it is a live call rather
than a settled one.

## .the note worth a keep beyond the fix

**a reviewer bound to a diff cannot tell which lines changed MEANING from which merely changed
SHAPE.** it reads rewritten lines as new code, correctly and unavoidably — the bind gives it no
access to `main`.

> ⇒ a refutation of the form *"this predates the diff"* owes the `git show main:` output, never the
> claim alone. the reviewer cannot run that command, so the driver holds evidence the reviewer
> structurally lacks — which makes a refusal to supply it a defect rather than an oversight.
