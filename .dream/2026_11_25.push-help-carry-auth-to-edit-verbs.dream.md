# 🌙 dream: push help names the `--auth` a later pr edit needs

- kind: fix
- owner: mechanic, `git.commit.push` (repo=ehmpathy/rhachet-roles-ehmpathy)
- caught 2026-11-25

## .the cue that fired
route `v2026_11_24.fix-crew-pr-edit-via-paved-verb` opened its pr `--auth as-human`, since the tree holds no seaturtle token. its own new help section then pointed at the edit verbs with no `--auth`, which refuses for that pr.

## .the gap, precisely
- `git.pull.title set` and `git.pull.description set` write only a pull their own credential opened (`check_pull_by_self`, `src/domain.roles/mechanic/skills/git.pull/git.pull.operations.sh:195`)
- `git.commit.push --help` shows `rhx git.pull.title set --from …` and `rhx git.pull.description set --from …` bare; the bare call defaults to `--auth as-ehmpath`
- a pr push opened `--auth as-human` is authored by the human's gh login, so the bare edit call refuses. the driver must know to repeat `--auth as-human`, and push's help is silent on it

## .the shape of the fix
- one help line under `to edit the pr after it is open`: `  pass the same --auth the push used; a pr opened as-human edits only as-human`
- optional: push's `pr #N (opened)` tree line names the credential (`as-human` / `as-ehmpath`), so the driver reads it at the moment it matters
- clamp: `[case31]` asserts the line; red without it, green with it

## .why it is not done in this round
the cost surfaced only at the done gate, after 5.3 verification passed. a new help line here reopens the clamp, the snaps, and both review stones for a case the wish did not name; it is its own small pr.
