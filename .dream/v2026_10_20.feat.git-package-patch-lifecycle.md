# 🌙 dream: git.package.patch get / check / del, and an upgrade-safe patch

kind: feat · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic) · caught 2026-10-20

## .the cue that fired

the `git.package.patch` wish was bounded to nano: `begin` + `commit` only. #926 asks for the whole lifecycle; #772 asks for a hoisted-linker fallback.

## .the gap, precisely

- no `get`: a crew cannot list patches with their why + upstream + apply state
- no `check`: an underapplied patch (target version moved) aborts `pnpm install`, which blocks `rhx upgrade` — the very path that would retire the patch (#926)
- no `del`: retire a patch + its `patchedDependencies` entry + its note by hand
- under `node-linker=hoisted`, pnpm leaves the package pristine while `package.json` reads patched (#772)

## .the shape of the fix

- `get` reads `patchedDependencies` + each `patches/*.patch.note.md`
- `check` dry-applies each patch: `applied` / `underapplied` / `obsolete` (upstream issue closed)
- `del --package X` removes patch, entry, note
- an onStop nudge runs `check`; set pnpm's patch-failure tolerance so an upgrade lands
- for hoisted repos, a `git apply --directory node_modules/<pkg>` applier (see #772)
- exempt vendor code from our term hooks: `pretooluse.forbid-terms.gerunds.sh` and
  `.blocklist.sh` grade writes under `node_modules/` (incl. `.pnpm_patches/`), so an edit of a
  third-party file that holds a blocklisted word is refused once. our prose rules should not
  grade code we do not own

## .why it is not done in this round

the wish bounds size to nano; the patch verb alone closes the classifier stall. the rest is real work that ripples into hooks and the upgrade path.
