## .the shape of the fix

2. `[case13]`'s snapshot moves with the text, and a clamp asserts the diagnostic line
3. every rebase failure names its next move, as the conflict frame does: `rebase failed` (`[case11]`,
   the tree is left as it was; fix the cause in `git.output`, then re-run `rhx git.branch.rebase

4. one label for the commit count across every begin frame, in words that count right: `ahead: N
   commits` in the preview, up-to-date (today `commits: N (ahead)` / `behind: 0`), apply
   (`commits: N ✓`), and conflict (`commits: N`) frames; `1 commit`, never `1 commits`
   (`as_commit_count_words`, drafted and reverted in pr #1206 since it moved the locked journey
   snapshot)
6. the preview's ahead list closes its last row on `└─`, as the behind list does (main leaves an open
   `├─`); the journey snapshot moves two lines with it, so it ships as its own reviewed change
5. the conflict frame names one next step: git's own `hint:` lines in `git.output` (`git rebase
   --continue` / `--skip` / `--abort`) are masked, or `next steps` says to use the rhx step above
