# 🌙 dream: one shared parser and ranker for the permission gates

kind: feat · owner: mechanic · caught 2026-10-07, in route `v2026_09_26.fix-blocklist-nudge`, stone 5.1 (peer i007, enroll-impl-arch-defects; fulcrums F36, F37)

## .the cue that fired

an architecture review found two independent quote-aware command parsers for the two permission
gates (`check-permissions`, `decide-permissions`), and the new rank/budget logic inline in a
~1700-line bash hook while the same folder already holds small unit-tested `.ts` transformers.

## .the gap, precisely

- `pretooluse.check-permissions.sh`: `split_compound_command`, `command_is_allowed`,
  `get_ranked_hits` (edit distance, fzf, dot-segment), `set_part_budgets`
- `permissionrequest.decide-permissions.sh`: `compute_command_scan`, `tokenize_argv`,
  `canonicalize_rhx_command`, its own allow/deny match, its own `.claude` walk and filter variant
  (see also `.dream/v2026_10_07.fix.one-name-for-the-claude-dir-walk.md`)

## .the shape of the fix

1. lift one parse lib (`_permissions.parse.lib.sh`): the quote-aware split and the allow match,
   with the decider's extras (deny, canonicalize) as callers of it, not forks
2. parity clamp: one table of commands run through both gates, the verdicts compared
3. the pure rank math — measure first: if a node call per BLOCKED command fits the block-path
   budget, move edit distance / fzf / dot-segment / budget into `.ts` transformers with unit
   tests; else keep bash and add a bash unit harness
4. split a case arm at its `)` in the shared parser: today `case w in tide) ls` renders whole as
   grammar, so the arm body (`ls`) gets no alternatives (it still blocks; acceptance `[case16]`
   pins the current render)

## .why it is not done in this round

dirty: both hooks' suites (~480 cases) pin each parser, and the decider predates this route.
fulcrums F36 (parser merge) and F37 (bash vs `.ts`) record the hold.
