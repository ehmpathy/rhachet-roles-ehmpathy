# 🌙 dream: the comment real-api snapshot nests its json outputs as objects

kind: followup · owner: ehmpathy/mechanic · caught 2026-11-02

## .the cue that fired

5.3 peer lane r6 (ergo-snapshot-visual-blemishes) blocker.1 on
`.behavior/v2026_10_25.feat-git-pull-title-description`.

## .the gap, precisely

`git.pull.comment.real.integration.test.ts.snap` stores `setFirst`, `getFirst`, `setEdit`, `setAgain`
as one json string each; the stub suite's snap nests the same outputs as objects. two shapes for one
contract, and the string form is harder to scan.

## .the shape of the fix

1. in `asStable`, split the id mask: `(issuecomment-|comments\/)\d+` → `$1<id>`, and
   `("id": )\d+` → `$1"<id>"`, so the masked json stays valid
2. add `asStableJson = (input) => JSON.parse(asStable(input))`; use it for the four json outputs
3. run the case by hand under a gh login (`npx jest -c jest.integration.config.ts --testMatch …`), with `-u`
4. apply the same to `git.pull/git.pull.real.integration.test.ts` if it ever snaps a string

## .why it is not done in this round

safe, not clean to land: the snapshot regenerates only from a live run that writes to pr #1039, and
that run was declined here. a hand-written snapshot would be forged. fulcrum F21.
