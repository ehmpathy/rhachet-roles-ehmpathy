# 🌙 dream: the permission matcher should understand claude's full pattern syntax

kind: fix · owner: ehmpathy/mechanic · caught 2026-10-08

## .the cue that fired

peer r010 (enroll-impl-behavior-intent), i005, item 6, on route
`.behavior/v2026_10_07.fix-check-permissions-reads-settings-repo`. the user layer
(`$HOME/.claude/settings.json`) now joins the read set, and a human's home file is where a bare
`Bash`, `Bash(*)`, or `Bash(npm run *)` is most likely to be.

## .the gap, precisely

`pretooluse.check-permissions.sh` and `permissionrequest.decide-permissions.sh` match only:
- exact `Bash(cmd)`
- prefix `Bash(cmd:*)`

claude also accepts a bare `Bash` (allow all), `Bash(*)`, and glob-star forms with a space
(`Bash(npm run *)`). the hooks skip these, so a command claude would allow gets one nudge block
before it passes on retry.

a related gap (peer r011 i005, item 6): decide reads `permissions.allow` and `permissions.deny`,
never `permissions.ask`. an `ask` rule that claude would honor with a prompt can be auto-approved
by decide when an allow also matches. both gaps predate the #895 route.

## .the shape of the fix

- in the shared matcher, map a bare `Bash` and `Bash(*)` to allow-all
- map a final ` *` to the same prefix rule `:*` uses
- research claude's current docs for any other forms first
- read `permissions.ask` in decide as a veto, beside deny
- add cases to both the check and decide suites
- keep the fork-budget ratchet (`pretooluse.check-permissions.forkbudget.integration.test.ts`)
  green; the matcher runs on every Bash call

## .why it is not done in this round

dirty. the matcher is shared by check and decide, each with a cost ratchet, and the change alters
the gate's semantics for every repo. #895 is about which files the hooks read, not how a pattern
matches. see fulcrum F19.
