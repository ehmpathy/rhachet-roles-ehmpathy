# 🌙 dream: the simple gh mock routes the release-pr number lookup to its title

kind: fix · owner: ehmpathy/rhachet-roles-ehmpathy (git.release test infra) · caught 2026-10-30

## .the cue that fired
p9 [case12] (release pr on main, `--into prod --apply`) printed `--pr chore(release): v1.3.0 🎉` where the pr number belongs. the code reads a number; the mock handed it a title.

## .the gap, precisely
`.test/infra/mockGh.ts:1360` — `writeSimpleGhMock` routes `gh pr list` to the `pr list title` key when the args contain `.title`. `get_release_pr` (`git.release.operations.sh:113,126`) queries `select(.title | startswith(...)) | .number` — it names `.title` too, so it receives the title. every simple-mock test that sets `pr list title` (e.g. p1 [case3a]) runs the release pr as `$release_pr = "chore(release): …"`: `gh pr view <title>`, `gh pr merge <title>`. the tests pass only because the mock ignores the pr argument. p9 [case12] omits the key to stay true.

## .the shape of the fix
route on the jq tail, not on any mention: `| .title'` (get_release_pr_title) vs `| .number'` (get_release_pr). the `"title=\(.title)"` query (`:189`) needs its own arm, or it falls through to `pr list`. then resnap the suites that set `pr list title` and read each diff: every `--pr`/`#` the release pr prints should become its number.

## .why it is not done in this round
safe, not clean: the narrowed match reroutes the `title=` query and moves snapshots across p1/p3 suites this change never opened. the comment gate's own test avoids the trap.
