# 🌙 dream: a mandatory remedy has no marker to wear

- **kind**: reseed
- **owner**: `repo=.this/role=any` — `rule.require.coconut-hints` + `git.commit/output.sh`
- **caught**: 2026-09-10

## .the cue that fired

the `repo-rules` peer reviewer flagged every sponsor refusal in this stone as a
`rule.require.coconut-hints` violation — the remedy renders as unmarked prose after
`print_instruction`, where the rule asks for a `🥥` block.

the point could not be taken, and that is the part worth the record. the same rule forbids what
it asks for here:

> *a coconut block that carries **load-bearing** information (not optional guidance) = **blocker***

⇒ 🔴 **so a mandatory remedy is caught in a gap.** the coconut is the only marked shape the house
vocabulary owns, and its declared sense is *optional*. a remedy that is the ONLY way forward
cannot wear it, so it wears no marker at all — and then reads as prose to every reviewer and every
human.

the reviewer even names the two facts side by side without a join: it calls these *"mandatory
refusals"* in the same sentence that asks them into an optional block.

## .the gap, precisely

| the render carries | the marker it wears today |
|---|---|
| optional guidance you MAY act on | `🥥 did you know?` ✅ |
| the result of a success | the result tree ✅ |
| the fault | the `error:` line ✅ |
| 🔴 **the one act that can clear a refusal** | **none** |

and a fourth case this stone surfaced, which is sharper still: **a remedy the reader is not
permitted to run.** the sponsor refusals are read mostly by clones, and the fix is a human's act
at a tty. the current render says so in plain words —

```
   ⛔ you cannot fix this yourself. a sponsor is bound by a human,
      at a tty.
```

— but `⛔` is used ad-hoc there, by one skill, with no rule behind it and no helper to keep the
shape consistent across the others.

## .the shape of the fix

a `⛔`-headed twin of `print_coconut_hint`, in `git.commit/output.sh`, plus the rule text that
declares its one sense:

```
                              <- blank line, as the coconut has
⛔ you must                   <- the header: mandatory, not optional
   ├─ <why it is not yours>   <- e.g. "a sponsor is bound by a human, at a tty"
   └─ <the exact command>     <- copy-pasteable, closes the block
```

then, in `rule.require.coconut-hints` (or a paired rule beside it):

- extend the `.when it applies` table with a **mandatory** row that points here
- state the pair plainly: `🥥` = *you may*, `⛔` = *you must* — one glyph, one sense
  (`rule.forbid.ambiguous-labels`)
- keep the caveat intact; it is what makes the split necessary rather than cosmetic

## .why it is not done in this round

**SAFE: yes. CLEAN: no.** ⇒ deferred per `rule.always.fix-forward-under-scouts-honor`.

- the marker belongs to the **house vocabulary**, so a half-migration is worse than none — two
  refusal shapes in one repo is the ambiguity the rule exists to remove
- the migration touches every refusal in every `git.commit` skill and re-snaps them all. the
  `git.commit` scope alone is 301 tests with locked stdout/stderr snapshots
- ⇒ it would balloon a sponsor change into a repo-wide render rewrite, which
  `rule.require.review-test-changes` names a blocker

⚠️ **and there is a real design question a rushed edit would settle by accident**: is `⛔ you must`
one block, or two senses (*"you must do X"* vs *"a human must do X"*)? this stone needs the
second, and it is not obvious the first is a special case of it. that call wants the ergonomist,
not a mid-review edit.
