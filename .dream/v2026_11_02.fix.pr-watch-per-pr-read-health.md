# 🌙 dream: per-pr read health, so one bad pr cannot hide behind a good one

- kind: fix
- owner: mechanic (rhachet-roles-ehmpathy, git.pull.watch)
- caught 2026-11-02

## .the cue that fired

5.1 i006 r011 nitpick.3: `daemon.unreachable` is one clock for the box; any good pr read clears it.

## .the gap, precisely

- pr A stalls or 5xx each tick while pr B reads fine: each tick starts the clock, then clears it.
  A's clone never gets the outage note, and its alerts hold in silence
- a persistent 404 or 403 on one pr only logs; no state, no note, no `get` row

## .the shape of the fix

- each pr cache dir holds `read.fault`: `{ since, rc, cause }`, cleared on a good read
- the outage note goes per watch, from its own pr's clock
- `get` shows a read fault per watch (the visibility half of F30 Q-b that waits on no answer)
- the box-wide marks then mean only token and github-wide faults

## .why it is not done in this round

the note text for a per-pr fault is the same what Q-b asks (what a persistent read fault must
say); the state can land first, but its render waits on that answer.
