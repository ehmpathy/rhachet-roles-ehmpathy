# 🌙 dream: `git.release --watch` and `git.commit.push` misread the pr they just made

- kind: fix
- owner: ehmpathy/rhachet-roles-ehmpathy, the git.release and git.commit skills
- caught 2026-11-22

## .the cue that fired

on pr #1456, `rhx git.commit.push --mode apply --auth as-human` printed `pr: pr #1456` then a stray `1` on the next line, and its auto-watch refused `--which '1456\n1'`. a minute later `rhx git.release --watch` printed `👌 all checks passed` and `0s watched`, while `gh pr checks 1456` showed 15 checks not yet run (every integration and acceptance shard).

## .the gap, precisely

- `git.commit.push`: the pr number it parses from the as-human `gh pr create` path carries a second line, so the number is not one integer; the watch that follows fails
- `git.release --watch`: just after a push, with check runs queued but not started, it reads the state as all passed and exits 0. a green that was never earned

## .the shape of the fix

- parse the pr number to `^[0-9]+$` (the last url segment of `gh pr create`'s output) and fail loud on any other shape
- in `git.release --watch`, count queued and unstarted checks as inflight; "all passed" only when every required check is in a terminal state and at least one ran
- a clamp each: a stub `gh` that prints an extra line; a stub checks list with all runs queued

## .why it is not done in this round

both are other skills' contracts with their own suites; the pull-watch pr does not touch them.
