# 🌙 dream: git.repo.get suite cleanup flakes on ENOTEMPTY

- kind: fix
- owner: mechanic
- caught 2026-10-30

## .the cue that fired
pr #1205 (markdown only) went red on one test: `git.repo.get.sh › [case24] GIT_REPO_ROOT env
override › uses custom root instead of ~/git`, ci run 41006003359, shard 2/5.

## .the gap, precisely
the assertions are not what fails. the `finally { cleanup() }` at
`src/domain.roles/mechanic/skills/git.repo.get/git.repo.get.integration.test.ts:1997` throws
`ENOTEMPTY: directory not empty, rmdir '/tmp/git-repo-get-test-…'` from
`fs.rmSync(tempDir, { recursive: true, force: true })` (:91). a recursive rm only reports ENOTEMPTY
when a file lands in the dir while the rm walks it, so some process still writes under
`HOME=tempDir` after the skill returns: a child the skill left behind (fetch, cache write) is the
first suspect. the fixture is also a hand-rolled `mkdtemp`, which `rule.forbid.adhoc-gentempdir-reimpl`
forbids.

## .the shape of the fix
1. find the writer: run case24 in a loop with `inotifywait -r` (or `lsof +D`) on the temp dir at
   cleanup time
2. if the skill leaves a child behind, the skill is the defect: wait on it, or detach it to a path
   outside `HOME`
3. move the fixture to `genTempDir` from `test-fns`
4. clamp: a test that fails while a child outlives the skill

## .why it is not done in this round
another skill's suite, out of the catchup wish scope, and the root cause needs a diagnosis, not a
one-line patch. a retry was run on this pr.
