# 🌙 dream: show.gh.test.errors prints the failed logs off a tty

kind: fix · owner: ehmpathy/rhachet-roles-ehmpathy (`src/domain.roles/mechanic/skills/show.gh.test.errors.sh` → `show.gh.action.logs.sh`) · caught 2026-11-04

## .the cue that fired
on pr #1263, test run 41789296473, `rhx show.gh.test.errors` printed one line per job: `the response contains terminal escape sequences; pass --allow-escape-sequences to output it anyway`. no job showed a log. it also listed all 22 jobs as failed, where only 3 integration shards and their rollup failed.

## .the gap, precisely
- off a tty, gh refuses to print a log that holds ansi escapes; jest logs always hold them
- the skill passes no `--allow-escape-sequences`, so a clone sees zero failure text
- the failed-job filter counts a job as failed when gh's log fetch fails, not by the job's conclusion
- the cure was hand-run: `gh run view <id> --log-failed | rhx teesafe <file>`, then `rhx grepsafe`

## .the shape of the fix
- pass `--allow-escape-sequences` to the log fetch, then strip ansi before print
- pick failed jobs by `conclusion == "failure"` from `gh run view --json jobs`
- clamp: an integration test with a fake `gh` on PATH that emits escapes off a tty; assert the log text prints and only failed jobs list

## .why it is not done in this round
another skill, outside this route's files; it would ride a pr about rebase.
