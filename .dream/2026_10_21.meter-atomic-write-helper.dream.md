# 🌙 dream: one atomic json writer for the meter files

kind: refactor · owner: ehmpathy/mechanic · caught 2026-10-21

## .the cue that fired

self review `has-consistent-mechanisms` on `5.1.execution.from_vision`
(`v2026_10_18.feat-split-release-uses`): the split added three more temp-then-`mv` writes.

## .the gap, precisely

seven sites hand-roll the same atomic write — `"${file}.tmp.$$"`, an EXIT trap, `mv -f`:

- `git.commit/git.commit.operations.sh` (sponsor bind)
- `git.commit/git.commit.uses.org.sh`
- `git.commit/git.commit.uses.global.sh`
- `git.commit/git.commit.uses.local.sh`
- `git.commit/git.commit.set.sh` (use spend)
- `git.release/git.release.uses.local.sh`
- `git.release/git.release._.guard_release_meter.sh` (use spend)

each carries its own trap, and only the sponsor writer guards a state path that is a directory
(the `mv` that succeeds into a dir). the other six lack that guard.

## .the shape of the fix

`set_json_file_atomic file=… content=…` in `git.commit.operations.sh`: refuse a non-file at the
path, write the temp, trap its removal, `mv -f`. swap each site to it. clamp: one test per meter
writer where the state path is a directory (red today on six of seven).

## .why it is not done in this round

safe, not clean: four of the seven writers predate this stone (sponsor, org, global, set) and
the swap ripples into suites this route never opened.
