# 🌙 dream: split the pr-watch operations by noun, behind one daemon manifest

kind: refactor · owner: repo=ehmpathy role=mechanic (git.pull.watch) · caught 2026-11-01

## .the cue that fired

the l3 arch review of the pr-watch daemon (5.1 i004 r011, nitpick.1, .2, .4) names
`git.pull.watch.operations.sh` as ~950 lines of nine nouns, with the layout facts still
written by hand at many sites.

## .the gap, precisely

- `git.pull.comment.set` sources the whole file to append one ledger id
- the daemon code hash and its bin copy glob every `*.sh`, so an edit to the read-only
  `get.sh` re-keys the daemon and respawns it
- the `daemon.*` file names appear in six files plus the tests; 21 inline
  `jq -r '.cloneSerial|.repoRoot|.ended|.watchId'` reads fork per record per tick
- `run_watch_tick` ends five branches with `set_watch_outbox_drained; return 0`;
  return codes `3/4/5` (github, daemon) and `3` (dead clone, alert) carry no name

## .the shape of the fix

- one file per noun: `git.pull.watch.<render|key|daemon|lock|record|outbox|ledger|clone|verb>.sh`
- one `WATCH_DAEMON_FILES` list that drives the code hash, the bin copy, and the daemon's
  `source` lines, so verb scripts stay out of the key
- `as_watch_daemon_file <key_dir> <name>`; one record reader that emits a tsv row
- `WATCH_DIFF_JQ` in its own sourced file, so a unit can read its branches
- one tick epilogue (the loop drains after the reads); named return codes
  (`WATCH_RC_AUTH_REFUSED`, `WATCH_RC_RATE_LIMITED`, `WATCH_RC_UNREACHABLE`, `WATCH_RC_CLONE_DEAD`)
- cut by grain as well as by noun (5.1 i005 r011 nitpick.1): `daemon.sh` holds only boot and
  the loop; a sourced `tick` library takes `key_dir` explicitly, not the global `$KEY_DIR`, so
  the tick, the diff, and the drain are callable once. communicators (`run_watch_rhachet`, the
  gh read, a dao each for record, outbox, ledger, and the `daemon.*` marks), transformers (the
  diff, the render, the name parsers), orchestrators (the tick, the drain, the verbs)
- before the first release (5.1 i005 r011 nitpick.2): every persisted record carries
  `schema: 1`, and `as_watch_record_moved` merges the old record onto a fresh-record template,
  so a cursor field added later (as Q-d's status cursor would be) reads its default, never
  `null`. release turns the layout into a contract that `moved` reads forever
- one event vocabulary (5.1 i006 r011 nitpick.4): the kind strings sit in the diff jq and four
  bash ladders in `alert.sh` (phrase, leaves, next, label). one pure render table beside the
  diff, `kind → { phrase, label, leaves, next }`, with repo and pr as `--arg`, pinned by a
  data-driven case list and a test that fails on a kind the table does not know
- the peer predicate has one owner (5.1 i006 r011 nitpick.7): the 🐢 mark is a convention of
  `git.pull.comment.set`; that skill exports `is_comment_by_clone` beside `set_watch_ledger_id`,
  so a change to its mark cannot relabel peers in silence. the ledger proof stays first
- the file split lands now that F27 no longer covers it (5.1 i006 r011 nitpick.10): it moves
  no on-disk layout, so it can ride ahead of the layout decision

## .why it is not done in this round

each move rewires files every suite reads, on a stone at its third review level; the
defects these shapes invite were fixed at cause with clamps this round (fulcrum F27).
