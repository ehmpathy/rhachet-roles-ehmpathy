# 🌙 dream: the boot hook revives a clone's watches under every key

kind: fix · owner: repo=ehmpathy role=mechanic (sessionstart.git-pull-watch) · caught 2026-11-01

## .the cue that fired

r010 lower-friction list (5.1 i004): the boot hook only revives the current key. after an
upgrade plus a reboot, an old-key watch stays unserved until the clone's next push.

## .the gap, precisely

- the hook counts this clone's records under the current key only, and findserts that key's
  daemon
- a watch left under an old key (set before the upgrade) has no daemon after a reboot;
  the next `set` or push moves it (case=14), but a clone that idles never pushes

## .the shape of the fix

- the hook scans every key dir for this clone's records
- for each record under an old key: move it to the current key with `as_watch_record_moved`
  (cursors ride along, as `set` does), under each key's lock
- then findsert the current key's daemon once; the hook's one line names the moves

## .why it is not done in this round

it gives the boot hook a write it does not have today (a move), with its own lock and
fault paths; that wants its own review.
