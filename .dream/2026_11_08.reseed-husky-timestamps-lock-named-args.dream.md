# 🌙 dream: the husky practice's lock hook takes named args

- kind: reseed
- owner: declapract-typescript-ehmpathy (practice `husky`)
- caught 2026-11-08

## .the cue that fired

three peer lanes on rhachet-roles-ehmpathy 5.1 (arch-opport-decomposition, arch-smell-scopeleaks, arch-hazards-behavior) flagged `.husky/check.timestamps.lock.sh`. the practice apply wrote that file at boot.

## .the gap, precisely

`timestamps_lock_halt` reads `$1` (the found value) and `$2` (where it was found), and every call site passes ordered literals: `'absent' 'on disk'`, `"$TIMESTAMPS_LOCK_DISK" 'on disk'`, `"$TIMESTAMPS_LOCK_INDEX" 'in the index'`. a reader at the call site cannot tell which is which (`rule.forbid.positional-args`, which names bash outright).

## .the shape of the fix

in the practice source, have the helper take `found=` / `where=` named args, and call it as `timestamps_lock_halt found='absent' where='on disk'`. bump the practice, so every repo gets it on its next `declapract apply --practice husky`. the lock hash (`TIMESTAMPS_LOCK_EXPECTED`) covers `check.timestamps.sh`, not this file, so the lock needs no restamp.

## .why it is not done in this round

the file is practice output, not this repo's code. a local edit would drift from the practice, and the next apply would overwrite it. the fix belongs in the practice repo. this route's fix pr no longer carries the file (the practice upgrade is split out).
