# 🌙 dream: a green git.release --apply names the approval it merged on

- kind: followup
- owner: mechanic (git.release skill)
- caught 2026-11-15

## .the cue that fired

an l3 reviewer on `fix-release-refuses-unreviewed-pr` 5.3 noted that a successful `--apply` prints the
same tree as an ungated merge: `👌 all checks passed`, `🌴 automerge enabled [added]`, `done! merged!`.

## .the gap, precisely

the review gate passes silently. a merge log cannot show that the gate ran, or on whose approval and
which head. after an incident where a merge went out with no review, that audit line is what a
human would look for.

## .the shape of the fix

- have `is_pr_approved_by_human` (or a peer `get_pr_approval`) also emit the login and commit of the
  approval that carried the verdict
- thread it to `emit_transport_status`, and print `├─ 👌 approved by @<login> on <sha7>` above the
  automerge line on the gated feature pr
- resnap every approved apply in p1, p2, p3, and p9

## .why it is not done in this round

it widens the visible contract of every green path and resnaps suites the gate does not own
(fulcrum F24). the wish is the refusal, and this pr is in its verification stone.
