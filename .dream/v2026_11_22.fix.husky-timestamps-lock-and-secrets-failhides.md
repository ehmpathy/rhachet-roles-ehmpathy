## .the cue that fired

peer review of `fix-pull-watch-daemon-respawn-loop` (5.1.execution, rounds i002 and i003) raised both files: the `since-main` scope lists untracked worktree files beside the branch diff. they are not part of that route's change and are not staged by it.

## .the gap, precisely

- `.husky/check.timestamps.lock.sh:44` — `TIMESTAMPS_LOCK_DISK=$(git hash-object -- "$TIMESTAMPS_LOCK_HOOK")` has no guard and the file sets no `set -e`. a git fault leaves the value empty, which then reads as a mismatch: `✋ ConstraintError: ... was changed. revert the hook`, exit 2. a malfunction is reported as a constraint with the wrong cure. the index read below it already guards with `|| timestamps_lock_malfunction`
- `.husky/check.secrets.sh:60` — `line=$(printf ... | grep -nIE -e "$regex" | head -n 1 | cut -d: -f1)` runs with no `pipefail`. a grep error (rc 2) reads as no match, so a scan fault passes the file as clean. in a secrets gate, that lets a key ship

## .the shape of the fix

- timestamps lock: `TIMESTAMPS_LOCK_DISK=$(git hash-object -- "$TIMESTAMPS_LOCK_HOOK") || timestamps_lock_malfunction`, or `set -euo pipefail` as the peer hooks do
- secrets: capture grep's own status (`grep ... > "$tmp"; rc=$?`), treat rc 1 as no match, and halt with `💥 MalfunctionError` (exit 1) on rc ≥ 2
- a clamp per file: a stub git or grep that faults, red before and green after
