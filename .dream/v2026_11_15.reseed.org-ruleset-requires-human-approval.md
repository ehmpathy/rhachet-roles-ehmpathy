# 🌙 dream: an org ruleset that requires one approval before merge

kind: reseed · owner: ehmpathy org admin · caught 2026-11-15

## .the cue that fired
the vision for "git.release refuses an unreviewed pr" asked *what is the root cause?*
(`rule.require.solve-at-cause`). the root is that the clone's token can merge a pr no human
reviewed; github allows it because sdk-aws-lambda carries no review rule (`reviewDecision: ""` on
#79). a client-side gate in git.release stops this skill, never a raw `gh pr merge`.

## .the gap, precisely
no org-level ruleset requires an approval on the default branch of ehmpathy repos. any caller with
write access, clone included, can merge unreviewed.

## .the shape of the fix
- an org ruleset on `~DEFAULT_BRANCH`: require a pull request, 1 approval, dismiss stale approvals
  on push
- bypass list: release-please's app, so release prs still merge (they carry no human review today,
  e.g. rhachet-roles-ehmpathy #1279)
- note: with the rule on, a robot account with write access could still approve; pair it with
  CODEOWNERS of human logins, or "require review from code owners"

## .why it is not done in this round
org settings sit outside this repo and need an admin. the client gate in git.release ships now as
defense in depth.
