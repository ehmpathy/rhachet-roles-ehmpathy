# 🌙 dream: genTestDir must link roles under a temp home, before the rhachet 1.51 bump lands

kind: fix · owner: rhachet-roles-ehmpathy (whoever lands the rhachet ≥1.51 bump) · caught 2026-11-15

## .the cue that fired

on `beav/feat-git-package-patch`, `rhx test.acceptance.prebuilt --scope
blackbox/pretooluse.check-permissions.acceptance.test.ts` failed every case with
`EACCES: permission denied, open '<tempDir>/.claude/settings.json'`.

## .the gap, precisely

- under rhachet 1.51.0, `npx rhachet roles link --role mechanic` (run by `genTestDir` in
  `blackbox/.test/invokeHook.ts`) leaves the fixture's `.claude/settings.json ->
  settings.of.grove.json -> /home/<human>/.claude/settings.json`
- `genHookRepo` then `fs.writeFileSync`s that path — a write aimed at the human's own global
  settings. only a read-only target stopped it
- with a writable home, the suite would overwrite the human's settings on every run
- even with a temp home, all 104 cases fail under 1.51: the hook no longer reads the allowlist the
  fixture writes, so the fixture layout itself must follow rhachet's new `.claude` layers

## .the shape of the fix

```ts
const homeDir = path.join(tempDir, '.home');
fs.mkdirSync(path.join(homeDir, '.claude'), { recursive: true });
await execAsync('npx rhachet roles link --role mechanic', {
  cwd: tempDir,
  env: { ...process.env, HOME: homeDir },
});
```

then write the fixture allowlist into the layer the hook reads under 1.51 (likely
`.claude/settings.of.repo.json`), and resnap the suite at 1.51.

## .why it is not done in this round

SAFE fails: it changes infra every blackbox suite shares, and this tree (rhachet 1.51 installed,
1.48.1 committed) can prove it under neither version. the hazard arrives with the bump, which F6
holds out of this PR; the fix belongs in the same PR as the bump.
