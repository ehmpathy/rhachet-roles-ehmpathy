## .the cue that fired

i007 r11 (`enroll-impl-arch-defects`) items 2 and 3: `git.pull.operations.sh` is a facade over
`git.pull.comment.operations.sh`, so the title and description verbs speak `COMMENT_REPO`,
`COMMENT_PR`, `set_comment_*`, `fail_comment_*` — "comment" now names a pull.

## .the gap, precisely

- `git.pull/git.pull.operations.sh` line 25 sources `../git.pull.comment/git.pull.comment.operations.sh`
  (987 lines), which sources `git.commit.operations.sh`, `output.sh`, `keyrack.operations.sh`
- ~40 of its 83 symbols are pull-generic: dispatch, refusal render, flag checks, repo fence, auth,
  gh communicators, pr lookup, hash ops, cap. `get_one_gh_pull`, `check_pr_visible`, and the
  `fix_split` arg of `check_body_under_cap` were added there to serve title and description
- `set_one_gh_pull_field` (pull ops) repeats `set_one_gh_resource` (comment ops): err file, gh call,
  classify. the title read-back compares text; the description compares sha256

## .the shape of the fix

1. move the pull-generic block into `git.pull/git.pull.operations.sh`; the comment ops source it
2. `rhx sedreplace` `COMMENT_REPO|COMMENT_PR|COMMENT_LOGIN|COMMENT_AUTH|COMMENT_OUTPUT` → `PULL_*`,
   `set_comment_{repo,auth,login,pr,output}` → `set_pull_*`, `fail_comment_*` → `fail_pull_*`
3. one communicator `set_one_gh_resource` with an optional payload field and 422 fix arg
4. compare both read-backs as `as_pull_field_from_json <f> | as_sha256`
5. one `set_body_file_from_source` op for the `--from` intake of comment.set and description.set
6. the `github.auth` lift (dream `2026_11_01.github-auth-ops-lift`) then lands below this layer

## .why it is not done in this round

SAFE: no — it rewrites the ops the merged #1143 comment verbs run on. CLEAN: no — it renames
symbols in every comment verb, past the wish's bound. fulcrum F18 records the call.
