# 🌙 dream: a hung apt install can hold a ci shard for six hours

kind = followup · owner = mechanic (ci) · caught 2026-11-20

## .the cue that fired
pr #1380 run 44665300620: `suite / test-shards-acceptance (dynamic, 1, 1)` sat in step `install ripgrep (for grepsafe)` for hours, with every later step queued. no test ran.

## .the gap, precisely
`.github/workflows/.test.yml` lines 231 and 322 run `sudo apt-get update && sudo apt-get install -y ripgrep` with no bound on time, and no job in the file sets `timeout-minutes`. a stalled apt mirror holds the job until github's 6h default, and the pr shows the check as unresolved the whole while. `git.release --retry` reruns only failed runs, so a driver has no paved lever to cut it short.

## .the shape of the fix
1. `timeout-minutes` on each test job (well above its normal runtime, e.g. 30)
2. bound the install: `timeout 120 sudo apt-get ...`, or fetch the ripgrep release binary, or cache it
3. optional: `git.release --retry` also cancels and reruns a run whose step has run past a bound

## .why it is not done in this round
the ci workflow is outside this pr's scope (pr text into a public repo).
