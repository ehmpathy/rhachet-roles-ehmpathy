# 🌙 dream: the pr-watch daemon's clone probe births one node process per repo root per tick

- kind: fix
- owner: mechanic (git.pull.watch)
- caught 2026-11-21

## .the cue that fired

the vision of fix-pull-watch-daemon-respawn-loop counted births per tick. the token read leaves the loop, but `rhachet clone list` stays at one read per watched repo root, every 60s.

## .the gap, precisely

`del_watch_records_of_dead_clones` in `git.pull.watch.daemon.sh` runs `get_watch_clone_list` for each root, each tick. that is a node process per root per minute for the whole life of a watch, a quiet one included.

## .the shape of the fix

read births first (the director's laptop count after this release). then probe each root on the same doubled gap as its quiet prs, and always before a delivery (`clone say` already reports a dead clone as rc 3).

## .why it is not done in this round

out of the wish's scope. the per-tick probe is a prior decision (feat-pr-watch-daemon fulcrum F5: a dead clone on a quiet pr must be found with no event). a change there wants its own read of births, not a guess.
