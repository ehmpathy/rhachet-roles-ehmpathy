## .the cue that fired

the ergo-acceptance-journey-coverage lane on the pressViaPipeline route (5.3) found that the `brief.condense` cli has no acceptance test, and that none of its output variants is snapped.

## .the gap, precisely

- `brief.condense.ts` prints a turtle tree (`🐢 lets see...` / `shell yeah!`, `🐚 condense`, the `dens.Δ` / `kern.Δ` / `tokens` branches, a `quality:` line), a `--json` form, a plan-mode note, and two error forms (`condense failed` json, and the `bummer dude...` tree)
- no test runs the cli as a human would. its one suite, `brief.condense.integration.test.ts`, is a `describe.skip` on main
- every run asks a live brain, so any end-to-end test spends money

## .the shape of the fix

1. add `brief.condense.acceptance.test.ts`: spawn the cli with args, capture stdout, stderr, exit code, and written files
2. put the cases that ask a brain inside `describeBrainLiveOnDemand` (`src/.test/describeBrainLiveOnDemand.ts`)
3. cases that never ask a brain run always: `--help`, a bad arg, an absent file, empty content
4. mask token counts and σ values, then snap the turtle and json outputs for plan, apply, and each error form

## .why it is not done in this round

this route changed one line of the cli (the injected compressor, same function as before), so no cli output changed. the live cases need spend, which is declined for this route. fulcrum F7.
