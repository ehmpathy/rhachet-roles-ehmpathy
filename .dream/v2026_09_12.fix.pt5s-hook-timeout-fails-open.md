# 🌙 dream: a PreToolUse hook that exceeds its PT5S timeout fails OPEN, silently

**kind** fix · **owner** repo=ehmpathy/role=mechanic · **caught** 2026-09-12

## 🔴 .OBSERVED LIVE — 2026-09-21, on a loaded box

this was caught from a **source read** and six converging rubrics. it has now been **watched
happen**, in a deliberate dogfood of the shipped hooks:

| probe | path | result |
|---|---|---|
| 1 | `.temp.dogfood.md`, content holds `script` | 🔴 **PERMITTED. no refusal, no diagnostic** |
| 2 | `.temp.dogfood2.md`, byte-identical content | ✅ blocked, correctly |
| 2 retry | same path, same content | ✅ permitted — HARDNUDGE, as designed |

⇒ **probe 1 is the fail-open, and the nudge file proves the hook was not merely absent.**
`.claude/terms.blocklist.nudges.local.json` held, immediately after:

```json
{ "69e8d605…": { "time": 1789960913,
                 "path": "…/.temp.dogfood.md",
                 "terms": ["script"] } }
```

**the hook ran, detected the term, swept, and wrote its block-branch state — then the refusal
never reached the caller.** the record is written at `blocklist.sh:434-438`, and `exit 2` is
~40 lines later. ⇒ it died in between.

⚠️ **the box was under heavy contention at the time**, measured in the same session: the
`types` gate went **46s → 175s** and `unit` went **14s → 94s** against identical inputs. a
5-second budget on a box that slowed ~4× is the whole mechanism.

🔴 **so the fork-storm fix REDUCES this defect's likelihood and does not remove it.** fewer
forks means less time blocked on the runqueue, which means fewer expiries — but the tripped
path still spends ~25 execs, and the gate still fails **open and silent** when it runs out of
clock. **a probability reduction is not a guard.**

⇒ **and it fails open exactly when the grove is busiest** — the same load-sensitivity the wish
was written about, now observed in the gate's correctness rather than its cost.

six peer lanes across two rounds — i007-r010, i007-r011, i008-r001 (n4), i008-r002 (n1),

## .the gap, precisely

`getMechanicRole.ts` registers every mechanic hook with a timeout.

⚠️ **the budget is now `PT10S`, raised from `PT5S` by the wisher on 2026-09-24.** that doubles
the headroom and **closes no part of this dream** — a killed hook still reads as a permit, at
whatever cap. every measurement below was taken against the 5s value, so read each margin as
twice what it states.

per claude code's hook contract, **a hook that exceeds its timeout is killed and treated as
NOT blocked** — the exit status is not 2, and a non-2 exit reads as a permit. so:

| the path | what happens on expiry |
|---|---|
| a clean write | no delta — it would have permitted regardless |
| 🔴 **a tripped write** | the forbidden term/gerund **lands**, unrefused, with **no diagnostic at all** |

the tripped path is the exposed one, and it is the expensive one:

| hook | clean path | tripped path |
|---|---|---|
| blocklist | ~5 execs | **~25 execs** |
| gerunds | ~4 execs | **~20 execs** |

⇒ **this is the same silent class `rule.forbid.failhide` bars everywhere else in both
files** — the alternation collapse, the nudge write, the `mv`-in-`if` guard were each
repaired in this very drive precisely because a non-2 exit reads as a permit. the timeout is
the one door of that shape nobody closed, because nobody could see it from the source.

### 🔴 the sharpest part — the wish's own premise IS the trigger

the wish exists because these hooks are **blocked on forks under runqueue contention**
(`pcpu 8%` = ~92% of wall time blocked, not busy). the fix trims the fork count, so the
clean path now holds three orders of headroom against 5s.

**the tripped path still forks ~25.** and vision assumption A1 records a measured ~40% trip
rate in the drove — the tripped path is not rare. ⇒ under exactly the contention this wish
was written to relieve, a tripped write is the one case that could approach 5s, and if it
does the term lands with zero signal.

⚠️ **the fork trim MOVED this hazard away. it did not remove it**, and a reader of the yield
could easily conclude otherwise.

## .the shape of the fix

three shapes, weighed:

| shape | verdict |
|---|---|
| **drop the timeout** | 🔴 **reject.** a hook with no cap hangs every tool call on a deadlock — a rare silent permit traded for a certain total stall. strictly worse |
| **raise the timeout** | ⚠️ **moves the bound, keeps the class.** a larger number is a larger stall on deadlock and still fails open past it. no better as a contract |
| ✅ **make expiry LOUD, not silent** | the real fix, and it needs a capability we do not hold — claude code must part "hook expired" from "hook permitted" at the contract level, so a killed gate reads as a refusal rather than a pass |

⇒ **the remedy is upstream of this repo.** the shape to pursue:

> **a PreToolUse timeout should fail CLOSED, or at minimum emit a visible diagnostic.**
> a gate that expires silently is indistinguishable from a gate that approved.

## 🔴 .the "partial local mitigation" this dream once named — WITHDRAWN, 2026-09-13

~~clamp the tripped path's wall latency in the fork-budget suite — a jest assertion that a tripped
write completes well under 5s on the test box.~~

**it was wrong, and it was measured wrong the same week it was written.** a wall-latency assertion
grades the **box**, never the code. this repo already carries one, and it is a proven flake:

> `[case23]` in `pretooluse.check-permissions.integration.test.ts` asserts *"under 3 seconds"* —
> **green at 548s, green at 753s, red at 1346s, same commit, monotone at n=3.**
> ⇒ `.dream/v2026_09_13.fix.check-permissions-perf-case-asserts-a-wall-clock.md`

⇒ to add a second wall-clock assertion would **author the exact defect that dream reports**, and the
cheap variant — raise the constant — is *"the defect restated with a larger constant."* the
fork-budget suite is built on **discrete event counts** precisely to avoid this:
*"it works because it counts discrete events, never elapsed time"*
(`pretooluse.forbid-terms.forkbudget.integration.test.ts:22`).

⚠️ **a peer reviewer at i016 graded the absence of this clamp a nitpick — the sharpest one — on this
dream's own authority.** ⇒ **a dream's recommended follow-through is evidence, never a mandate**, and
a recommendation written before the relevant measurement will be cited against you after it.

**what is actually in reach: no deterministic local proxy exists.** the hazard stays
documented-not-clamped, at both `.sh` headers and the registration. that is a worse answer than a
clamp and a truer one.

## .why it is not done in this round

**SAFE** 🔴 **no.** the only real fix changes the hook contract in claude code, which this
repo does not own. the two local shapes (drop / raise the timeout) each make the trade
worse, not better.

**CLEAN** 🔴 **no.** `timeout` is registered on **all 14** of this role's init hooks, so any
policy move ripples across every gate — among them seven this wish's boundary explicitly
fences off (*"do not touch the other PreToolUse hooks"*).

⇒ so it takes the **document-not-eliminate** treatment this drive already applies to its two
peer ambient hazards — the HARDNUDGE wall-clock window and the nudge-record race. a
`🟡 .note` now sits in **both** hooks and beside the registration in `getMechanicRole.ts`, so
the contract is visible from the three places a maintainer could meet it.

⚠️ **no fulcrum is owed.** a fulcrum records a *call reserved for the council*; this is not a
judgment about ripple cost but a capability we lack. there is no alternative for anyone to
overrule.
