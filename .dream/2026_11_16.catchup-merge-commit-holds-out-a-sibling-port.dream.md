# 🌙 dream: a catchup merge commit can carry the port a conflict needs

kind: fix · owner: mechanic (git.branch.catchup) · caught 2026-11-16

## .the cue that fired

#1205's catchup of main #1222 conflicted in `git.commit.set.sh`. main edited inline token code that
this branch had moved to `git.commit.operations.sh`. the right resolution ports main's change into
`git.commit.operations.sh`, a file main never touched. `catchup continue` unstages every file main
did not change, so the port cannot ride the merge commit, and the merge alone ships an unbound
`ROBOT_TOKEN_STATUS` under `set -u` on the `--push` as-ehmpath path.

## .the gap, precisely

the merge commit holds only main-touched files. a semantic conflict across a moved boundary needs
an edit in a sibling file. today that costs a second commit, and the merge commit between them is
a broken tree.

## .the shape of the fix

`continue` keeps a staged file main did not change when the human names it, e.g.
`rhx git.branch.catchup continue --carry <path>`. it lists carried files in the render and the
commit body. the default stays pure. clamp: a temp repo with a moved-function conflict, red
without `--carry`, green with it.

## .why it is not done in this round

the fix is a verb change on files main did not touch, so it needs its own commit and review.
the round had one commit.
