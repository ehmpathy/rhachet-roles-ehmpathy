# 🌙 dream: the pr-watch boot hook renders its faults in the family shape

kind: fix · owner: mechanic · caught 2026-11-02

## .the cue that fired

5.3 i003 peer lane r6 (ergo-snapshot-visual-blemishes) nitpick.1: `sessionstart.git-pull-watch`
faults open on a bare `💥 MalfunctionError:` line, with no `🐢 bummer dude...` header and no
`🐚 <skill>` root, where every `git.pull.watch` verb uses `print_watch_header`. its load-fault line
also prints a raw `dist/inits/claude.hooks/../../skills/...` path.

## .the gap, precisely

- one skill family renders its faults two ways: the verbs via `fail_watch_malfunction`, the hook
  via a hand-rolled `say_both`
- the load-fault path keeps its `../../` segments

## .the shape of the fix

- the hook prints a `🐢 bummer dude...` header and a `🐚 sessionstart.git-pull-watch` root, then
  nests the `💥 MalfunctionError:` line under it, as the verbs do; it keeps exit 0 and both streams
- compute the physical path of the sourced file with `cd -P` before it is named, so no `../../`
  segment prints
- resnap `sessionstart.git-pull-watch.integration.test.ts`; the hook must not load
  `git.pull.watch.operations.sh` to print a fault that says it could not load it, so the header
  print lives in the hook itself

## .why it is not done in this round

the hook prints at session start into every enrolled session; a new shape there touches boot
output read by every clone, and its header must be built without the operations file whose load
it reports. that is a design pass, not a nitpick fix.
