# 🌙 dream: git.branch.rebase begin refusals exit 2, not 1

kind: fix · owner: ehmpathy/mechanic · caught 2026-10-21

## .the cue that fired

self review `behavior-declaration-adherance` on `5.1.execution.from_vision`
(`v2026_10_18.feat-split-release-uses`): the new F7 refusal had to pick an exit code, and every
peer refusal in `git.branch.rebase.begin.sh` exits 1.

## .the gap, precisely

`rule.require.exit-code-semantics`: a caller-must-fix refusal exits 2; 1 means malfunction.
begin exits 1 for constraints — no commit grant, no uses left, on main, dirty tree, rebase in
progress, remote ahead (F7). only the damaged-meter arm is a true malfunction. the headers read
`error:`, not `✋ ConstraintError:` (`rule.require.qualified-error-headers`).

## .the shape of the fix

split begin's refusals: constraint arms → `✋ ConstraintError:` + exit 2; the damaged-meter arm
stays `💥 MalfunctionError:` + exit 1. update the begin, rebase, and journey suites' status
asserts and resnap. check `continue` / `abort` / `take` for the same split.

## .why it is not done in this round

safe, not clean: a contract change across one skill's whole refusal set, and five or more arms
predate this stone. a lone exit 2 on the new arm would split the file's contract.
