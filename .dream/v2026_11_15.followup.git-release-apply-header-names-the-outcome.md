# 🌙 dream: git.release apply header names the outcome, not the intent

- kind: followup
- owner: mechanic (git.release skill)
- caught 2026-11-15

## .the cue that fired

two l3 reviewers on `fix-release-refuses-unreviewed-pr` 5.3 flagged it: `🐢 cowabunga!` opens apply
runs that end in `✋ ConstraintError` or `💥 MalfunctionError`.

## .the gap, precisely

`git.release.sh` prints the apply-mode turtle header (`cowabunga!`) before the outcome is known, since
the tree streams. a refusal mid-apply (head moved, red checks, lost approval, rebase) therefore sits
under a celebratory header. a reader who skims only the top of an unattended log may think it shipped.
main has the same shape, so the p1 rebase-refusal snapshot already shows it.

## .the shape of the fix

either:
- print a neutral intent header for apply (e.g. `lets ride...`), and keep `cowabunga!` as the final
  line on a merge; or
- buffer the header until the first terminal state.

the first is cheaper; it resnaps every apply snapshot in p1, p3, p9.

## .why it is not done in this round

it predates this pr, it is not in the wish, and the fix resnaps every apply snapshot across the suite.
that ripple fails CLEAN for this diff.
