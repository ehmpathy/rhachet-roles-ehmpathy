# 🌙 dream: the blocklist gate opens silently when its config is malformed

- **kind** = fix
- **owner** = repo=ehmpathy / role=mechanic
- **caught** = 2026-09-09, on route `v2026_09_09.fix-hook-fork-storm`

## .the cue that fired

the experience walk for the fork-storm wish reached the cell
`editor × trips-blocklist × config malformed` and had to give it a verdict. the read of
`pretooluse.forbid-terms.blocklist.sh:72` showed the gate does not fail — it **opens**.

## .the gap, precisely

```bash
# src/domain.roles/mechanic/inits/claude.hooks/pretooluse.forbid-terms.blocklist.sh:72
TERMS_JSON=$(sed 's|//.*||' "$BLOCKLIST_FILE" | jq -c '.terms // []' 2>/dev/null || echo "[]")
```

then at `:75-77`:

```bash
if [[ "$TERMS_JSON" == "[]" ]]; then
  exit 0
fi
```

⇒ a `jq` parse failure — one stray comma in `terms.blocklist.jsonc` — is swallowed by
`2>/dev/null || echo "[]"`, collapses to the empty-list case, and **exits 0 for every content**.
the whole blocklist retires with no error, no log line, and no failed test.

**checkable evidence:** the extant `…blocklist.test.sh:197-205` `[case9]` asserts an *empty*
config permits all. there is no case for a *malformed* config, and the two are indistinguishable
to this code path.

that is `rule.forbid.failhide` — "allow trycatch only if catch allowlists errors and handles
carefully, throws others" — graded a mega blocker by the brief.

⚠️ **the same shape sits in `gerunds.sh:68-70`**, and there it fails the *other* way: a parse
failure empties `ALLOWLIST`, so the gate becomes **stricter** and the one allowlisted word starts
to block. one bug, two opposite silent outcomes.

## .the shape of the fix

distinguish "absent" from "corrupt", and fail loud only on corrupt:

1. keep the `[[ ! -f "$FILE" ]] → exit 0` guard as-is (an absent list is a legitimate state — a
   repo that has not linked the role)
2. split the parse so its failure is visible:
   ```bash
   TERMS_JSON=$(sed 's|//.*||' "$FILE" | jq -c '.terms // []') || {
     { echo "⛈️  forbid-terms: $FILE is malformed json — the gate cannot be trusted"
       echo "   fix: correct the syntax, or delete the file to disable the gate on purpose"
     } | tee /dev/stderr
     exit 2
   }
   ```
3. mirror it in `gerunds.sh`
4. clamp both directions, per `rule.require.clamp-edge-cases`: a malformed list must exit 2, and
   an **absent** list must still exit 0 — the two must not collapse again

⚠️ **exit 2 blocks the write.** that is the correct severity — a gate that cannot read its own
policy must not pretend to enforce it — but it means a corrupt list wedges every Write until
someone fixes the file. the error text must therefore name the file and the escape (delete it) in
the same breath, per `rule.require.errors-name-the-fix`.

## .why it is not done in this round

the SAFE/CLEAN test of `rule.always.fix-forward-under-scouts-honor`:

- **clean?** ✅ yes — one guarded block per hook, inside files the fork-storm route already opens
- **safe?** 🔴 **no** — it changes what the hook **permits**. content that lands today would be
  refused after

the wish that owns this round states the bound three ways: *"do not change what is blocked"* ·
*"do not weaken the checks"* · *"a behavior change smuggled into a cost change is unreviewable"*.
a repair here would be exactly that smuggle, however much better the behavior.

⇒ deferred, dreamed, and raised as fulcrum **F5** so the judgment itself is reviewable rather than
merely reported.
