## .the gap, precisely

`author: repo=ehmpathy/role=mechanic`, already `bash`-invoked:

```json

      "command": "bash .agent/repo=ehmpathy/role=mechanic/inits/claude.hooks/permissionrequest.decide-permissions.sh",
      "timeout": 5,
```

that entry was **hand-written** by #576 rather than generated from the role. so:

| guard | covers it? | why |
|---|---|---|
| `[case1]` — reads the generated `settings.json` | ✅ **yes** | it walks every event key, so a broken path or a restored wrapper here goes red |
| `[case2]` — reads `ROLE_MECHANIC.hooks` | 🔴 **no** | the hook is in no role file, so it is in no command list `[case2]` can build |

🔴 **the consequence is exactly the blind spot `[case2]` exists to close for every other mechanic
hook**: a stale committed `settings.json` can satisfy `[case1]` while the role source already
carries a defect. for this one hook there **is** no role source, so `[case1]`'s staleness is
unbacked — and a hook that never runs is a gate that never gates, **silently**, because claude code
reads a non-2 exit as *not blocked*.

⚠️ **the blast radius is real but bounded**: this is a PermissionRequest auto-decide seam, so a
silent retirement costs extra human prompts rather than a permitted-forbidden action. it fails
toward friction, never toward harm.

## ✅ .step 1 is ANSWERED — 2026-09-20. it is a TWO-REPO change

the rhachet brain-hook contract has **no** `PermissionRequest` event. read from
`ehmpathy/rhachet` @ `origin/main`,

```ts
onBrain?: {
```

| rhachet | claude code |
|---------|-------------|

⇒ **no role can declare a `PermissionRequest` hook today**, which is why #576 hand-wrote the
`settings.json` entry — it was the only shape available, not an oversight.

🔴 **so the fix is upstream-first**: rhachet must gain a `PermissionRequest` event (a peer of
`onTool`, or an `onTool` filter value) before step 2 below is expressible at all. ⇒ this is a
**dispatch**, never a local repair, and the local half stays blocked on it.
