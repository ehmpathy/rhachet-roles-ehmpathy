# 🌙 dream: the HARDNUDGE window is keyed to a wall clock, so a backwards jump holds the gate open

- **kind** = fix
- **owner** = ehmpathy/rhachet-roles-ehmpathy
- **caught** = 2026-09-12

## .the cue that fired

peer round 4, lane `arch-hazards-behavior` (r007), nitpick.1 — graded against
`rule.forbid.behavior-hazards`, whose "time assumptions / non-determinism" clause asks a
wall-clock dependence to be **documented or eliminated**.

⇒ the cue was a reviewer, and its sharpest half is *where* it looked: the defect predates this
diff, and it lives on lines the diff rewrote. **a rewritten line draws a fresh read of an old
hazard**, which is a reason to welcome the churn rather than defend it.

## .the gap, precisely

both hooks decide the retry verdict from `date +%s`:

```bash
# pretooluse.forbid-terms.blocklist.sh
NOW=$(date +%s)
LAST_ATTEMPT=$(jq -r --arg key "$NUDGE_KEY" '.[$key].time // 0' "$NUDGE_FILE" ...)
elapsed=$((NOW - LAST_ATTEMPT))
if [[ $elapsed -lt $HARDNUDGE_WINDOW_SECONDS ]]; then
  exit 0          # ← permit
fi
```

move the clock **backwards** — an ntp correction, a `date -s`, a container snapshot restore —
and `elapsed` goes negative. `-lt 300` stays true for as long as the clock trails the stamp, so
every retry on that path permits.

### and the sweep cannot clear it

the stale prune reads the same clock:

```bash
'to_entries | map(select(.value.time > ($now - $threshold))) | from_entries'
```

with `$now` behind the stamp, `.value.time > ($now - 3600)` holds, so the record survives. ⇒ **the
one mechanism that would otherwise expire a bad stamp is keyed to the same broken source.**

### what bounds it, and it does bound it

| | |
|---|---|
| the window | 300s |
| the key | `sha256(file_path)` — **one** path |
| so a jump of N seconds | opens exactly that one path, for at most N seconds |

⇒ not a global gate release. a clone that edits one file repeatedly through the jump window walks
past the gate on that file; every other path is untouched.

⚠️ **and the same clock read is what the block branch stamps**, so a forward jump has the mirror
effect: it expires a live window early and re-blocks a legitimate retry. that direction is a
friction, never a hole, which is why the backwards case is the one worth the note.

## .the shape of the fix

the window measures an **interval**, and an interval wants a monotonic source:

| # | shape | verdict |
|---|---|---|
| 1 | read `/proc/uptime` (linux) or `CLOCK_MONOTONIC` instead of `date +%s` | 🔴 a monotonic clock **resets on reboot**, so the stamp must carry both, and the record format changes |
| 2 | keep the wall stamp, and **clamp a negative elapsed to "outside the window"** — `elapsed < 0 ⇒ block` | ✅ one comparison, no format change, fails **closed** |
| 3 | store a boot id beside the stamp and invalidate the whole file when it changes | 🟡 correct, and it retires every live window on a reboot |

shape 2 is the one. it costs a single added condition, needs no new tool, keeps the nudge record
byte-compatible, and it errs toward **block** — the safe direction for a gate.

⚠️ **shape 1 reads as the principled answer and is the worst of the three here.** a monotonic
counter resets to zero at boot, so a record stamped before a reboot compares against a smaller
number and looks *future-dated* — the exact defect this dream describes, reintroduced by the fix
meant to remove it.

## .why it is not done in this round

the SAFE/CLEAN test, run honestly:

| question | answer |
|---|---|
| **SAFE?** | 🔴 **no.** it changes **when** the gate re-blocks. today a negative elapsed permits; after the fix it blocks |
| **CLEAN?** | ✅ yes — one condition, in a file this diff already opens |

⇒ **SAFE is the no, and it is a hard one.** acceptance #3 reads *"the HARDNUDGE behavior is
unchanged — first attempt blocks, a retry within the window passes, and the nudge record keeps its
shape."* a clamp on negative elapsed is a correctness repair **and** a verdict change, and
acceptance #2 bars a policy change *"either direction"* — the direction that makes the gate
stricter very much among them.

⚠️ **this is the uncomfortable half: the wish's freeze protects a defect.** that is what a freeze
does, and it is the right call for a cost change — *"a behavior change smuggled into a cost change
is unreviewable."* the repair belongs to a round whose subject is the gate, never to this one.

## .the note worth a keep beyond the fix

🔴 **an interval measured by two reads of a mutable clock is not an interval — it is a difference
of two opinions about the time.** it behaves like an interval for as long as the clock is
monotone, which is nearly always, which is why the defect survives every review that reasons about
the happy path.

> the tell is grammatical: `HARDNUDGE_WINDOW_SECONDS` names a **duration**, and the code derives
> it by subtraction of two **instants**. wherever a duration is computed rather than measured, ask
> what happens when the two instants come from a source that can move.

⚠️ and the second note, about the review: **the fix here is one line and it is still deferred.**
cheapness is not the SAFE/CLEAN test. a one-line change that flips a verdict is a policy change at
full price, and the smallness of the diff is exactly what makes it easy to ride along unnoticed.
