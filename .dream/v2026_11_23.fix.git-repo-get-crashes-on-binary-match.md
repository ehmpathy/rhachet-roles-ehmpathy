# 🌙 dream: git.repo.get lines crashes when a match is a binary file

kind: fix · owner: mechanic (this repo) · caught 2026-11-23

## .the cue that fired

an org-wide search for saga compensation, run to verify fulcrum F09 of `.behavior/v2026_10_23.fix-arch-fundamentals`, died mid-scan:

```
$ rhx git.repo.get lines --repos 'ehmpathy/*' --words 'compensat'
   ├─ ehmpathy/sdk-environment (local) — 1 matches
   │  └─ Binary file origin/main
   │  │  >    0: bin/run.bun.sdk-environment.bc matches
🪨 run solid skill repo=ehmpathy/role=mechanic/skill=git.repo.get
   └─ 💥 failed with an error
.../git.repo.get.operations.sh: line 1593: printf: bin/run.bun.sdk-environment.bc matches: invalid number
```

## .the gap, precisely

- `git grep` reports a binary hit as `Binary file <ref> matches` with no line number
- the renderer at `git.repo.get.operations.sh:1593` feeds the line-number field to a numeric `printf` slot, so the text `bin/run.bun.sdk-environment.bc matches` crashes it
- every repo after the first binary match goes unscanned, and the search exits 1 — the results so far are lost from the verdict

## .the shape of the fix

- pass `-I` (`--no-binary` semantics) to the `git grep` call, so binary files never match; or
- detect the `Binary file … matches` line before the render and print it as `(binary file, skipped)`
- clamp: a hermetic temp repo with one committed binary file that contains the search word; assert exit 0 and the text matches of the other files still render. revert the fix → red

## .why it is not done in this round

the route is a briefs route (F12). the fix is safe, but not clean here: it needs its own regression clamp in `git.repo.get` tests, a separate review surface from the briefs this route ships.
