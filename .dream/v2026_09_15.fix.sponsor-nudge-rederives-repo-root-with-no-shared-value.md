# 🌙 dream: `print_sponsor_bind_nudge_if_absent` re-derives repo root with no shared value to reuse

- **kind** = fix
- **owner** = ehmpathy/rhachet-roles-ehmpathy
- **caught** = 2026-09-15

## .the cue that fired

`arch-opport-decomposition` (i045/i046, nitpick.1) found that `print_sponsor_bind_nudge_if_absent`
(`git.commit.operations.sh`) computes `repo_root=$(git rev-parse --show-toplevel)` and
`meter_dir="$repo_root/.meter"` inline, duplicate of the same `git rev-parse` call
`uses.local.sh` already makes at its own top.

## .the gap, precisely

checked all 3 call sites (`uses.local.sh`, `uses.org.sh`, `uses.global.sh`): only `uses.local.sh`
precomputes `REPO_ROOT`/`METER_DIR`. `uses.org.sh` reads host-scoped org state, not tree-scoped
local state, so it holds no `REPO_ROOT` at all. `uses.global.sh` likewise holds none. a "pass what
you already hold" fix (the form i045's nitpick first proposed) does not clean up as claimed —
2 of 3 real callers would gain no benefit, since they have no precomputed value to pass.

## .the shape of the fix

either accept the duplicate `git rev-parse` call as the cost of a caller-agnostic shared leaf (it
is already isolated to one function, not spread across the 3 call sites), or restructure so
`uses.org.sh`/`uses.global.sh` also precompute `REPO_ROOT` at their own top for other future uses
— which is a broader change than this nitpick's own scope.

## .why it is not done in this round

**SAFE: yes — the current form works correctly; this is a pure duplication concern.**

**CLEAN: no.** any fix that removes the duplicate `git rev-parse` call changes the function's
call contract (from zero-arg to accepting/requiring a precomputed value), which ripples into all
3 call sites, 2 of which would need new code added purely to satisfy this refactor rather than
their own needs.
