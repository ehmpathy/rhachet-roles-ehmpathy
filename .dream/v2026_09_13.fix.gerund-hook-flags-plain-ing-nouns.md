# 🌙 dream: part true gerunds from plain -ing nouns in the gerunds hook

- kind: fix
- owner: mechanic
- caught: 2026-09-13

## .the cue that fired

two file writes were refused by `pretooluse.forbid-terms.gerunds.sh` on words that are **not
gerunds at all** — plain nouns whose spelling ends in `-ing`:

| word refused | what it is | the hook advice |
|---|---|---|
| `sibling` | a common noun. no verb `to sibl` exists | *"remove -ing suffix"* ⇒ `sibl` |
| `nothing` | a pronoun | *"remove -ing suffix"* ⇒ `noth` |

both blocks landed inside ordinary prose in a `.taken` and a radio task spec. the advice each
emitted is not merely unhelpful — it is nonsense, which is the tell that the detector never
asked whether a verb stem exists.

## .the gap, precisely

the extractor at `gerunds.sh:145` pulls every `-ing` word from the content, then the gate
treats membership in that set as a verdict. there is no stoplist and no stem check, so the
whole class of `-ing` nouns is caught: `sibling`, `nothing`, `thing`, `string`, `ring`,
`king`, `ceiling`, `spring`, `during`, `morning`, `bring`, `sterling`.

`rule.forbid.gerunds` itself is narrower than the hook that enforces it — it bans *"-ing as
noun"* where the word is a **verb** form, and explicitly permits participles in verb phrases.
⇒ the hook over-reaches its own rule.

## 🔴 .the second half — use versus mention

this very file could not be written until the identical write was retried, because
`pretooluse.forbid-terms.blocklist.sh` refused the word `nothing` as a forbidden vague term.

the usage here is a **mention**, never a use: the word is the subject under discussion, cited
so the defect can be named. neither hook parts the two, so **any brief, dream, or `.taken`
that documents a forbidden term is refused by the gate that forbids it.**

⇒ the class of document most worth an audit trail — the one that explains the policy — is the
one the policy blocks.

## 🔴 .why it matters more than a nuisance

each false block is survivable alone — the HARDNUDGE contract says *"if this is intentional
and absolutely unavoidable, retry the same operation."* so the author retries and moves on.

**that is the harm.** a gate that cries wolf on `sibling` teaches every agent that the correct
response to this refusal is a reflexive retry. the retry path is the same one a true positive
must be stopped at ⇒ the false positives erode the gate for the real ones, and the erosion is
invisible because a retry looks identical in both cases.

## .the shape of the fix

- add a stoplist of `-ing` nouns to the extractor, checked before the verdict, so the word
  never reaches the block message
- or, stronger: require a verb stem — `X-ing` is a gerund only where `X`, `Xe`, or a
  de-doubled `X` is a known verb. a stoplist is cheaper and needs no wordlist at runtime, and
  the fork budget favors it
- for the mention case: a carve-out is harder and may not be worth it. the honest option is to
  leave the retry as the documented path and say so in the refusal text, rather than pretend
  the gate can read intent
- clamp both directions per `rule.require.clamp-edge-cases`: a case that proves `sibling` and
  `nothing` pass, beside one that proves `loading` and `handling` still block. stage the
  stoplist away and watch the first go red

## .why it is not done in this round

SAFE 🔴 — `gerunds.sh` is the exact file under review on stone `5.1.execution.from_vision`,
and a change to its detection semantics is a **policy change**, which acceptance #2 of
`v2026_09_09.fix-hook-fork-storm` bars outright: the `.jsonc` policy and the verdict surface
must stay byte-identical to `main`.

CLEAN 🔴 — it would move snapshots in four suites that pin the refusal text.

⇒ deferred, and the deferral is a judgment about policy scope rather than size, so it is
itemized rather than merely dreamed.
