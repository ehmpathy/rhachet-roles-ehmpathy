# 🌙 dream: the review pipeline enlarges its own scope every round

- **kind** = reseed
- **owner** = ehmpathy/rhachet-roles-ehmpathy
- **caught** = 2026-09-15

## .the cue that fired

`enroll-impl-arch-defects` (i042, stone `5.1.execution.from_vision`) named a mechanism no prior
round had filed: this branch carries zero commits ahead of `main`, so `--diffs since-main` unions
the whole staged+untracked tree. every review round writes `.taken` files, dream files, and
fulcrum edits into that same untracked tree — so a round's own review enlarges the diff the next
round reads. this is the direct cause of the l1 lanes' context-overflow malfunction that has held
since i034.

## .the gap, precisely

the review tool's own scope computation has no floor separate from the code under test — its own
convergence artifacts count as scope. a review pipeline whose correctness-safe output (a `.taken`,
a fulcrum row) degrades its own future runs is a maintenance hazard in the tool itself, not in any
one feature branch.

## .the shape of the fix

exclude the route's own convergence artifacts (`.reviews/peer/**`, `.fulcrums/**`, and this
route's `dreams/` symlinks) from the diff scope `--diffs since-main` computes, or accept that
review-round-generated files sit outside `since-main`'s intended sense ("what did this feature
change") and should never have been in scope to start with.

## .why it is not done in this round

**SAFE: yes — a scope-computation change, no feature-code behavior change.**

**CLEAN: no.** the fix lives in the `bhrain`/`rhachet` review tool package, not in this wish's own
diff (`src/domain.roles/mechanic/skills/git.commit/**`) — out of this stone's bound scope, and a
change to a shared tool mid-convergence risks the exact citation drift `F12` ask 8 already warns
against for this same drive.

⇒ recorded here rather than worked around silently, per the reviewer's own recommendation.
