# 🌙 dream: push's pr number carries a stray line, so its auto-watch fails

- kind: fix
- owner: mechanic, `git.commit.push` (repo=ehmpathy/rhachet-roles-ehmpathy)
- caught 2026-11-25

## .the cue that fired
`rhx git.commit.push --mode apply --auth as-human` opened #1487 and printed `pr: pr #1487` then `1 (created)` on the next line; its watch step refused with `--which must be a pr number; got '1487\n1'`.

## .the gap, precisely
- on the `as-human` fallback path the pr number capture holds two lines: the number, plus a stray `1` (likely an exit status or a count echoed into the same capture)
- the tree line and the `git.pull.watch set --which` call both read the polluted value
- the push itself succeeds; only the tree and the auto-watch break, and the printed rerun command carries the same bad value

## .the shape of the fix
- capture the pr number alone on the as-human path (strip to the first line, or assert `^[0-9]+$` and fail loud if not)
- clamp: an integration case on the as-human create path asserts `pr #<n> (created)` on one line and a watch call with a numeric `--which`

## .why it is not done in this round
found at the done gate after the pr opened; it changes push's runtime on a path this pr does not touch.
