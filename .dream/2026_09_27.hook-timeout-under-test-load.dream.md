# 🌙 dream: PreToolUse hooks fail under test load

kind: fix · owner: ehmpathy/mechanic · caught 2026-09-27

> 🟡 **half discharged 2026-09-28.** symptom 1 was never load: three hook scripts shipped as `100644`,
> so rhachet's exec failed with exit 126, which claude code reports as a soft error with only the
> first stderr line — the `💪 init role` header. the chmod and a clamp
> (`getMechanicRole.integration.test.ts`) landed in this route; radio #810 tracks it. **symptom 2 is
> still owed**, and live: `pretooluse.check-permissions` stopped a tool call on 2026-09-28 with
> `permission check exceeded 4s timeout` while an integration run held the host.

## .the cue that fired

1. **live hook.** a human saw repeated `Failed with non-blocking status code: 💪 init role
   repo=ehmpathy/role=mechanic/init=claude.hooks/pretooluse.forbid-cross-repo-access` while
   `git.repo.test --what types|lint|format` ran in parallel, then `--what integration`.
2. **hook test.** `pretooluse.check-permissions.integration.test.ts` went 6 red in a 6-file parallel
   run: `[case4]` and `[case5]` allowed compound commands exited 2 (blocked), and `[case23]`'s scale
   ratio missed (7142ms vs a 5860ms bound). alone, the same file passes 73/73.

## .the gap, precisely

- the hook registers with `timeout: 'PT5S'` (`src/domain.roles/mechanic/getMechanicRole.ts:119`),
  rendered as `"timeout": 5`. it fires on Write|Edit|Read|NotebookEdit|Grep|Glob|Bash.
- symptom 1 held only the `💪 init role` header. every exit arm of the hook prints via `emit_both`
  first, so a header-only output suggests a kill mid-run, not a clean exit.
- `dist/` matched `src/`, so neither a stale build nor the jq-exit-4 defect explains it.
- unmeasured: the hook's wall time under load, and why an allowed compound command exits 2 under
  load. both diagnoses are inferred, not timed.

## .the shape of the fix

1. measure: time `rhachet run --init claude.hooks/pretooluse.forbid-cross-repo-access` idle and under
   a parallel `git.repo.test` load. node startup of `rhachet run` is most of the cost.
2. trace the `[case4]` exit 2 under load: find which part of `check-permissions.sh` returns a block
   when the host is slow.
3. if the budget is confirmed: raise it (e.g. PT15S) and audit the other PT5S hooks. a guard hook
   that times out fails open, silently.
4. longer term: cut node startup out of the hook path.

## .why it is not done in this round

the route is `fix-grepsafe-slashed-glob`. a hook-budget change touches every consumer's settings, and
its cause is not measured — not CLEAN, and not SAFE to change blind.
