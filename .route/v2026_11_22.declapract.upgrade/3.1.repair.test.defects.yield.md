## .defects

### D1 · test:types red in provision/github.apps
- **what**: TS2322 at `provision/github.apps/resources.ts:46`: `LogMethods` requires `_`
- **how**: `declastruct-github` 1.3.0 → 1.8.0. the file itself is unchanged vs HEAD and vs origin/main
- **why**: 1.6.0+ DAOs read `log._.level` through as-procedure, and a bare console object lacks `_`. the practice rewrote its own `github.repo` provider to `genLogMethods()`; `github.apps` is repo-owned, so the apply left it
- **fix**: `log: genLogMethods()` from `sdk-logs`

### D2 · test fixtures shipped in dist
- **what**: `dist/**/.test.assets/**` held 10 paths (a fixture `keyrack.yml`, fixture readmes)
- **how**: the apply renamed `__test_assets__/` → `.test.assets/`; `build:complete:dist` (unchanged vs HEAD and origin/main) excludes only `**/__test_assets__/**`
- **why**: the stale exclude no longer matched, so rsync's `**/readme.md` and `**/keyrack.yml` includes pulled the renamed fixtures in
- **fix**: `--exclude='**/.test*/**'`. rebuilt: gone
- **note**: `dist/.../brief.compress/.test/fixtures/briefs.js` remains: tsc emits it because `runPerfevals.evals.ts` (non-test) imports it. unchanged since HEAD; out of scope

### D3 · hand-only real-api suites back in the ci glob
- **what**: `git.pull.comment.real`, `git.pull.real` (write to a live pr), `set.package.{install,upgrade}.real` (live npm advisory api), and five brain-graded kernelize suites matched `test:integration`
- **how**: the apply replaced `jest.integration.config.ts` testMatch with the practice template. HEAD and origin/main both hold the exclusions
- **why**: the practice owns the file whole and offers no repo-local seam, so an apply erases any repo line it does not declare
- **fix**: exclusions restored in `testMatch` (not `testPathIgnorePatterns`: ci shards pass that flag on the cli, which replaces the config's list). upstream seam: dream `v2026_11_22.reseed.declapract-practices-keep-repo-local-extensions.md`

### D4 · git isolation lost in integration + acceptance env
- **what**: `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_SYSTEM=/dev/null`, `GIT_TERMINAL_PROMPT=0` gone from both env files; the 'Test User' guard gone from the integration env
- **how**: the apply replaced both env files with the practice template. HEAD and origin/main both hold the lines; origin/main also adds `delete process.env.RHACHET_CLONE_SERIAL`
- **why**: same as D3: the template carries no git isolation, and the apply erases repo lines. suites here shell git, so a human's global identity, sign, and hooks would leak in, and a stray remote would hang on a prompt
- **fix**: restored in both env files (the guard as a `ConstraintError` via `spawnSync`). `git.commit.set` integration 172/172. `RHACHET_CLONE_SERIAL` lands at the rebase onto origin/main

### D5 · live-brain suites read red on a keyless host
- **what**: `imagineIsContentAdmissible`, `pressViaPipeline` (integration) failed on a locked/absent `OPENROUTER_API_KEY`; the whole acceptance run stopped in globalSetup
- **how**: new `jest.acceptance.prepare.ts` (absent on HEAD and origin/main) passes `mode: 'strict'` to `useKeyrack`; `.agent/keyrack.yml` `env.test` (unchanged) declared `EHMPATHY_SEATURTLE_GITHUB_TOKEN`, which no suite reads (all pass fakes)
- **why**: `useKeyrack` defaults to `lenient` and forces `strict` only under declared aws auth; the template's explicit `strict` contradicted that for a repo with no aws account, and the live-brain suites sat in the default globs
- **fix** (fulcrum F4): live-brain suites gated off the default `testMatch`, each with its by-hand command (`imagineIsContentAdmissible`, `pressViaPipeline`, `guardBorder.onWebfetch*` ×4); `test:evaluation` runs exactly those six, so ci's `test-evaluation` job keeps them; acceptance keyrack in the org default mode; the unused github token dropped from `env.test`. two keyless cases ride along in a gated file → dream `v2026_11_22.fix.guardborder-acceptance-split-keyless-cases.md`
