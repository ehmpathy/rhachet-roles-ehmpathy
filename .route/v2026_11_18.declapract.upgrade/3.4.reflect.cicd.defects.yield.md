## C1 — repo quirk, on a practice bug

- the quirk: `ripgrep` and `pnpm` serve this repo's own skills (`grepsafe` is rg-only; `git.branch.rebase.lock` refreshes a real pnpm lock). another repo has no reason to install them, so the steps themselves stay repo-local
- the bug: the practice's `.test.yml` (`src/practices/cicd-common/best-practice/.github/workflows/.test.yml`) replaces the file whole and gives a repo no place to keep a runner step. its own seam shape already exists — `npm run prepare:rhachet --if-present` (lines 114, 211, 289, 377), `start:testdb --if-present` (231, 309, 394), `start:livedb:prep --if-present` (234, 312) — but no hook for runner setup
- cure upstream: an `npm run prepare:ci --if-present` (or similar) step after `prepare:rhachet` in each shard job, so a repo provisions its own tools without a hand-patch the next apply wipes

## C2 — practice bug

- `src/practices/tests-node/best-practice/jest.integration.config.ts` owns `testMatch` as one value
- the practice states it outright, in `src/practices/tests-any/jest-testmatch.declapract.test.ts:20-21`: "the configs are whole-file templates (EQUALS), so the next apply lands each line in an extant repo with no merge fix"
- so every repo-local `!**/…` exclude is wiped on each apply, and the suites they kept off ci (live-api, brain-graded) run and fail. same root as test defect D5
- cure upstream: a seam the template keeps — a repo-owned file of extra excludes the config spreads in, or a marked block the apply preserves. the clamp at `jest-testmatch.declapract.test.ts` would assert the seam survives an apply

## C3 — practice bug

- `src/practices/cicd-common/best-practice/.github/workflows/report-slow-tests.sh:24-41` (origin/main)
  - `:24` `total` counts every file in `testResults`
  - `:30` exempts only `total == 0`
  - `:38` exits 1 when no file has a nonzero span
- a file whose every test is skipped is listed in `testResults` with `endTime - startTime = 0` (the `// 0` defaults cover an absent key the same way), so a shard of only skipped files reads as schema drift
- already reported: `ehmpathy/declapract-typescript-ehmpathy#788` (open), item 1 — same mechanism, hit by bhuild's credential-gated acceptance shards. this repo is a second consumer
- cure upstream: #788's own proposal matches the repair here — count files where a test passed or failed, exit 0 when none ran, keep the drift check for files that ran (`.github/workflows/report-slow-tests.sh:28-43` here)
